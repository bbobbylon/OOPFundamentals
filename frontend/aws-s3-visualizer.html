S3 — Simple Storage Service

S3 is unlimited, durable object storage. Store application artifacts, user uploads, database backups, static websites, and logs. 11 nines of durability.

🪣 What is S3 — and how do you use it for user uploads, deployment artifacts, and backups?

S3 is object storage — unlimited, 11-nines durable (replicated across 3+ AZs), accessed by key (a path-like string, not a real filesystem; no in-place edit, treat as key-value). Buckets are globally-unique containers; versioning keeps every overwrite and soft-deletes. Storage classes trade cost for retrieval time (Standard → Intelligent-Tiering → Standard-IA → Glacier → Deep Archive), and lifecycle rules auto-transition or expire objects. The key backend pattern is presigned URLs: your app generates a short-lived signed URL so the client PUTs/GETs the object directly to S3 — the binary never flows through your backend.

  • Object storage by key — 11-nines durable; not a filesystem, no in-place edit.
  • Buckets + versioning — globally unique; overwrites keep all versions.
  • Storage classes + lifecycle — Standard→IA→Glacier auto-transition/expire.
  • Presigned URLs — client uploads/downloads directly; binary skips the backend.

Spring Boot + S3 upload

// Spring Boot: generate presigned upload URL // (Angular uploads directly to S3, not via backend) @Service public class S3UploadService { private final S3Presigner presigner; private final String bucket = "ciam-user-uploads"; public String generateUploadUrl(String userId, String filename) { String key = "avatars/" + userId + "/" + filename; PutObjectRequest objectRequest = PutObjectRequest.builder() .bucket(bucket).key(key) .contentType("image/jpeg") .build(); PutObjectPresignRequest presignRequest = PutObjectPresignRequest.builder() .signatureDuration(Duration.ofMinutes(15)) .putObjectRequest(objectRequest) .build(); return presigner .presignPutObject(presignRequest) .url().toString(); // Angular: fetch this URL, then: // fetch(url, {method: 'PUT', body: file}) } }

Lifecycle rules (cost control)

# S3 Lifecycle Rules for CIAM buckets: # Bucket: ciam-audit-logs # Rule: move old logs to cheaper storage { "Rules": [{ "Status": "Enabled", "Transitions": [ { "Days": 30, "StorageClass": "STANDARD_IA" // 60% cheaper }, { "Days": 90, "StorageClass": "GLACIER" // compliance archive } ], "Expiration": {"Days": 2555} // delete after 7 years }] } # Bucket: ciam-build-artifacts # Rule: delete old CI build JARs { "Rules": [{ "Filter": {"Prefix": "builds/"}, "Expiration": {"Days": 30} }] } # Keep only last 30 days of CI artifacts

CIAM S3 bucket strategy

# S3 buckets for a CIAM deployment: ciam-user-uploads-prod avatars/{userId}/{filename} # presigned URL upload # Versioning: ON (recover deleted photos) # IAM: ECS task role → s3:GetObject + s3:PutObject # Public: NO — serve via presigned GET URLs only ciam-audit-logs-prod logs/{year}/{month}/{day}/ # daily audit exports # Lifecycle: Standard → IA(30d) → Glacier(90d) # Versioning: OFF (append-only, immutable) ciam-static-frontend index.html # Angular app main-{hash}.js styles-{hash}.css # Static website hosting: ON # CloudFront origin: this bucket # Public: YES (Angular app is public) ciam-ci-artifacts builds/{version}/app.jar # CI pipeline artifacts # Lifecycle: expire after 30 days # Access: ADO pipeline IAM role only ciam-backups-prod rds/{timestamp}/backup.dump # pg_dump exports # Lifecycle: IA → Glacier (compliance)

In CIAM / Context: Profile photos: Angular requests a presigned PUT URL and uploads straight to S3 (binary never routes through the backend), then reads back via a presigned GET. Audit logs export nightly to S3 and lifecycle-archive to Glacier for 7-year compliance. The Angular app itself is served from an S3 bucket via CloudFront — fast, cheap, globally cached static hosting.

2 — Spring Boot + S3 Integration

<!-- pom.xml --> <dependency> <groupId>software.amazon.awssdk</groupId> <artifactId>s3</artifactId> </dependency> <!-- or: Spring Cloud AWS --> <dependency> <groupId>io.awspring.cloud</groupId> <artifactId>spring-cloud-aws-starter-s3</artifactId> </dependency> // FileStorageService.java — upload and download @Service public class FileStorageService { private final S3Client s3; private final String bucket = "my-company-app"; // Upload a file public String upload(MultipartFile file, String key) { s3.putObject(PutObjectRequest.builder() .bucket(bucket).key(key) .contentType(file.getContentType()) .build(), RequestBody.fromInputStream(file.getInputStream(), file.getSize())); return key; } // Generate a presigned URL (temporary download link) public String presignedUrl(String key) { S3Presigner presigner = S3Presigner.create(); GetObjectPresignRequest req = GetObjectPresignRequest.builder() .signatureDuration(Duration.ofHours(1)) .getObjectRequest(r -> r.bucket(bucket).key(key)) .build(); return presigner.presignGetObject(req).url().toString(); } }

3 — Storage Classes — Cost vs Access Speed

STANDARD
~$0.023/GB/month
Milliseconds retrieval
Default. Frequently accessed data — app files, active user uploads.
STANDARD_IA
~$0.0125/GB/month
Milliseconds retrieval
Infrequent Access. Cheaper storage, retrieval fee per GB. Good for database backups, older logs.
INTELLIGENT_TIERING
Varies by access
Milliseconds retrieval
Auto-moves objects between tiers based on access patterns. Best when you don't know access frequency.
GLACIER_IR
~$0.004/GB/month
Milliseconds retrieval
Archive, instant retrieval. For compliance archives accessed occasionally.
GLACIER
~$0.004/GB/month
Minutes–hours retrieval
Long-term archive. Retrieval takes minutes to hours. Very cheap. Good for legal hold, 7-year compliance.

4 — Key S3 Features

FeatureDescription
Bucket PolicyResource-based IAM policy on the bucket. Grants cross-account access or makes specific prefixes public.
VersioningKeep all versions of every object. Enables recovery from accidental deletes or overwrites. Costs more storage.
Server-Side EncryptionSSE-S3 (AWS manages keys), SSE-KMS (your own KMS key), SSE-C (customer-provided key). All data encrypted at rest.
Lifecycle RulesAutomatically transition objects to cheaper storage classes or delete them after N days.
Presigned URLsTemporary URLs that grant access to private objects. Your backend generates them — the user downloads directly from S3 without hitting your server.
S3 Event NotificationsTrigger Lambda functions when objects are created/deleted. Use for image processing, ETL pipelines.
Static Website HostingServe static files (Angular build output) directly from S3 + CloudFront for global distribution.
Transfer AccelerationSpeed up uploads from distant locations using CloudFront edge locations.
