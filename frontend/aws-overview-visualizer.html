AWS Overview & Global Infrastructure

AWS operates the world's largest cloud infrastructure across dozens of Regions and hundreds of Availability Zones. Understanding the geography is key to building resilient applications.

1 — Regions — Click to Explore

A Region is a separate geographic area. Each Region is completely independent — data doesn't leave a Region unless you explicitly replicate it:

us-east-1
US East (N. Virginia)
6 Availability Zones
The oldest and largest AWS Region. New services launch here first. Most tutorials assume us-east-1. Hosts the IAM global endpoint and Route 53.
us-west-2
US West (Oregon)
4 Availability Zones
Major Region for west-coast US. Often chosen for DR (disaster recovery) failover from us-east-1. Lower latency for Pacific-region users.
eu-west-1
EU (Ireland)
3 Availability Zones
Primary EU Region. GDPR-compliant — EU customer data stays in EU. Choose this (or eu-central-1) when your users or compliance requirements are in Europe.
ap-southeast-1
Asia Pacific (Singapore)
3 Availability Zones
Main APAC Region for Southeast Asia. Used for apps serving Singapore, Australia, and the broader Asia-Pacific region.

How to choose a Region: proximity to users (latency), compliance (data residency), available services (not all services exist in all regions), and cost (prices vary by region).

2 — Availability Zones — High Availability

Each Region has 2–6 Availability Zones. Each AZ is one or more physically separate data centers with independent power, cooling, and networking. They're close enough for low-latency replication but far enough apart to survive local disasters:

Deploy across ≥ 2 AZs for High Availability. An ALB (Application Load Balancer) distributes traffic across AZs. If one AZ fails, the others continue serving traffic.

3 — Shared Responsibility Model

Security is divided between AWS and you. Understanding the boundary is critical for compliance and security architecture:

AWS Responsibility — "Security OF the Cloud"
Your Responsibility — "Security IN the Cloud"
  • Physical data center security
  • Hardware (servers, networking)
  • Hypervisor / virtualization layer
  • Managed service software (RDS engine patches)
  • Global network infrastructure
  • Your application code
  • OS patches (for EC2 VMs you manage)
  • IAM permissions (who can do what)
  • Data encryption (at rest and in transit)
  • Security groups and NACLs (network rules)
  • Customer data classification
