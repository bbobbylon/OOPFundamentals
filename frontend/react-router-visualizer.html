React Router v6

URL matching, nested routes, data loaders (React Router 6.4+), auth guards, and the useNavigate / useParams / useLoaderData hooks.

🧭 What is React Router — and how do loaders and auth guards work in v6.4+?

React Router is the standard client-side router: JS intercepts URL changes, matches a route, and swaps components with no full-page reload. Routes form a tree and nested routes render into the parent's <Outlet />. The v6.4+ change is data loaders — each route can fetch data before its component renders, delivered via useLoaderData() (no useEffect+setState, no loading flag), with errors caught by error boundaries. A loader is also the auth guard: if (!auth.isAuthenticated()) return redirect('/login') runs before render. The Angular equivalent is a Resolver + canActivate guard combined into one loader.

  • Client-side routing — match URL → render component, no page reload.
  • Nested routes + <Outlet /> — children render into the parent layout.
  • Loaders fetch before render — useLoaderData(), no manual loading state.
  • Loader = auth guard — redirect('/login') before the component mounts.

Route structure

const router = createBrowserRouter([ { path: '/', element: <Layout />, children: [ { index: true, element: <Home /> }, { path: 'users', element: <UsersLayout />, loader: usersLoader, // fetch before render children: [ { index: true, element: <UserList /> }, { path: ':userId', element: <UserDetail />, loader: userDetailLoader, }, ], }, { path: 'login', element: <Login /> }, { path: '*', element: <NotFound /> }, ]} ]); // RouterProvider replaces BrowserRouter <RouterProvider router={router} />

Loaders + hooks

// Define loader (runs before component) export async function usersLoader() { const auth = getAuth(); // check auth if (!auth.isAuthenticated()) return redirect('/login'); return fetch('/api/users', { headers: { Authorization: \`Bearer ${auth.token}\` } }); } // Component receives data synchronously function UserList() { const users = useLoaderData() as UserDto[]; // No loading state needed — loader runs first return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>; } // Navigation hooks const navigate = useNavigate(); navigate('/users'); navigate(-1); // back const { userId } = useParams(); // /users/:userId const [searchParams] = useSearchParams(); // ?q=bob

Angular Router comparison

React Router concept → Angular Router equivalent. Route path="/users/:id" → { path: 'users/:id', component: UserDetailComponent }. loader: usersLoader → resolve: { users: UsersResolver } (pre-fetch). Auth redirect in loader → canActivate: [AuthGuard]. <Outlet /> → <router-outlet></router-outlet>. useNavigate() → inject Router, call router.navigate(['/users']). useParams() → inject ActivatedRoute, read route.snapshot.paramMap.get('id'). useSearchParams() → route.queryParams observable. React Router's data-fetching approach (loaders) is the newer pattern — Angular's resolve guards predate it but achieve the same goal.

CIAM React app: Every admin route gets a loader that checks the auth store — if (!user?.roles.includes('CIAM_ADMIN')) return redirect('/unauthorized') — and a detail route pre-fetches with fetch('/api/users/' + params.userId, { headers: authHeader() }) so the component renders with data and no skeleton. Programmatic navigation after login (login(creds).then(() => navigate('/dashboard'))) is exactly Angular's router.navigate(['/dashboard']).

1. Route Definition (v6 createBrowserRouter)

// v6.4+ recommended pattern
const router = createBrowserRouter([
  {
    path: "/",
    element: <Root />,
    loader: rootLoader,
    children: [
      { index: true, element: <Home /> },
      {
        path: "users/:userId",
        element: <UserProfile />,
        loader: userLoader, // fetch data before render
        errorElement: <UserError />,
      },
    ],
  },
]);
// Loader runs before the component renders
async function userLoader({ params }) {
  const res = await fetch(`/api/users/${params.userId}`);
  if (!res.ok) throw new Response("Not Found", { status: 404 });
  return res.json();
}

// Component reads loader data
function UserProfile() {
  const user = useLoaderData();
  return <h1>{user.name}</h1>;
}

Loaders eliminate the useEffect-to-fetch-on-mount pattern. The component is always rendered with the data already loaded — no loading spinner in the component code.

2. Auth Guard Pattern

// v5 style: custom Route component
// v6 recommended: loader redirect

function requireAuth({ request }) {
  const user = getUser(); // check store / cookie
  if (!user) {
    throw redirect("/login?next=" +
      new URL(request.url).pathname);
  }
  return user;
}
// Protect a subtree:
{
  path: "dashboard",
  loader: requireAuth, // runs before ANY child
  children: [
    { path: "settings", element: <Settings /> },
    { path: "billing", element: <Billing /> },
  ]
}
// redirect() is a Response with status 302
// React Router intercepts it, calls navigate()

Loader-based guards are cleaner than ProtectedRoute wrapper components — no render-time redirects, no flash of protected content.

Login flow with "next" redirect: Store the current path as ?next=/dashboard/settings. After login, read searchParams.get("next") and navigate there. The loader's request.url gives you the attempted URL before redirect.

3. Navigation Hooks

useNavigate

const navigate = useNavigate();
navigate("/users/42"); // push
navigate(-1); // back
navigate("/login", { replace: true }); // replace history

useParams + useSearchParams

const { userId } = useParams(); // :userId
const [params, setParams] = useSearchParams();
const tab = params.get("tab") ?? "overview";
setParams({ tab: "billing" }); // updates URL
