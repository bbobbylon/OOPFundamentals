Java Networking

HTTP Client, Sockets, URLs — from low-level TCP sockets to the modern Java 11+ HttpClient API.

🔌 What is a TCP socket — and why do most Spring Boot developers never use one directly?

A socket is a bidirectional channel between two endpoints — HTTP, WebSocket, and SMTP all sit on TCP sockets, and Java's Socket/ServerSocket give you the raw bytes. But in practice Spring Boot handles all of it: Tomcat opens the ServerSocket, accepts connections, and routes to your controllers. The networking class you'll actually touch is Java HttpClient (Java 11+) for calling external APIs — though Spring Boot 3's RestClient and @HttpExchange sit above even that and are what most CIAM work uses.

  • Sockets are the foundation — but Tomcat/Spring own them; you write controllers.
  • HttpClient (Java 11+) for outbound calls in plain Java — sync or async, HTTP/2.
  • Always encode user input in URLs — use UriComponentsBuilder or URLEncoder.
  • Prefer Spring's clients in Boot — pooling, timeouts, JSON for free.

Java HttpClient (Java 11+)

HttpClient client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build(); HttpRequest req = HttpRequest.newBuilder(URI.create("https://api.example.com/users")).header("Authorization","Bearer " + token).timeout(Duration.ofSeconds(10)).GET().build(); HttpResponse<String> resp = client.send(req, BodyHandlers.ofString()); int status = resp.statusCode(); String body = resp.body();. Async: client.sendAsync(req, BodyHandlers.ofString()).thenApply(HttpResponse::body).thenAccept(System.out::println). Supports HTTP/1.1 and HTTP/2 automatically.

URL and URI in Java

URL: older class, can connect directly (url.openConnection()) but limited. URI: newer, represents a URI string without network operations. Build safe URIs: URI.create("https://api.example.com/users/" + userId) — DANGER: if userId contains "/", this breaks the URL. Use UriComponentsBuilder.fromHttpUrl("https://api.example.com/users/{id}").build(userId) (Spring) or encode manually: URLEncoder.encode(param, "UTF-8"). URL parameters: URI.create("https://api.example.com/search?q=" + URLEncoder.encode(query, StandardCharsets.UTF_8)). Always encode user-supplied values in URLs.

Raw TCP sockets (when you need them)

Server: try (ServerSocket ss = new ServerSocket(8080)) { while (true) { Socket conn = ss.accept(); // blocks until client connects new Thread(() -> handleClient(conn)).start(); } }. Client: try (Socket s = new Socket("localhost", 8080); PrintWriter out = new PrintWriter(s.getOutputStream()); BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream()))) { out.println("HELLO"); String reply = in.readLine(); }. Use case: custom protocols, games, IoT sensors. Not needed for REST APIs — use HttpClient or Spring's RestClient.

CIAM / Spring Boot: Prefer RestClient/@HttpExchange over raw HttpClient — they add pooling, error handling, timeouts, and JSON; raw HttpClient is for utilities outside the Spring context. The Ping admin API and Microsoft Graph are both REST/HTTPS, cleanly handled by a RestClient with a Bearer interceptor. Debug with logging.level.org.springframework.web.client=DEBUG.

Java Networking API Evolution

Java's HTTP support has improved dramatically across versions. Understanding the history explains the code you'll encounter in legacy codebases.

Java 1.0 — URL (1996) — still works, but very limited
URL url = new URL("https://api.example.com/users"); InputStream in = url.openStream(); // GET only, no headers, no timeout config String body = new String(in.readAllBytes()); // Use case: reading a simple URL, nothing fancy
Java 1.1 — URLConnection / HttpURLConnection (1997) — still seen in older codebases
URL url = new URL("https://api.example.com/users"); HttpURLConnection conn = (HttpURLConnection) url.openConnection(); conn.setRequestMethod("POST"); conn.setRequestProperty("Content-Type", "application/json"); conn.setDoOutput(true); try (OutputStream os = conn.getOutputStream()) { os.write(body.getBytes(StandardCharsets.UTF_8)); } int code = conn.getResponseCode(); // 200, 404, etc. String resp = new String(conn.getInputStream().readAllBytes()); conn.disconnect(); // Verbose, no async, HTTP/1.1 only, bad error handling
Third-party libraries — Apache HttpClient, OkHttp (2000s-present)
// Apache HttpClient — still widely used CloseableHttpClient client = HttpClients.createDefault(); HttpGet get = new HttpGet("https://api.example.com/users"); CloseableHttpResponse resp = client.execute(get); // OkHttp — popular in Android/modern Java OkHttpClient client = new OkHttpClient(); Request req = new Request.Builder().url("https://...").build(); Response resp = client.newCall(req).execute();
Java 11 — java.net.http.HttpClient (2018) — the modern standard
HttpClient client = HttpClient.newHttpClient(); HttpRequest req = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users")) .GET() .build(); HttpResponse<String> resp = client.send(req, HttpResponse.BodyHandlers.ofString()); System.out.println(resp.body()); // Clean. Async-capable. HTTP/2. Fluent.

java.net.http.HttpClient — the builder pattern

The HttpClient is designed to be shared and reused — create one instance per application, not per request. It manages connection pooling, HTTP/2 multiplexing, and thread management internally.

// Minimal — uses all defaults HttpClient client = HttpClient.newHttpClient(); // Fully configured HttpClient client = HttpClient.newBuilder() .version(HttpClient.Version.HTTP_2) // HTTP/2 with HTTP/1.1 fallback .connectTimeout(Duration.ofSeconds(10)) // TCP connection timeout .followRedirects(HttpClient.Redirect.NORMAL) // follow 3xx (not to http://) .authenticator(myAuthenticator) // Basic/Digest auth .proxy(ProxySelector.of(new InetSocketAddress("proxy", 8080))) // proxy .sslContext(sslContext) // custom TLS .executor(Executors.newFixedThreadPool(4)) // custom thread pool .build(); // Build a request HttpRequest request = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users/42")) .header("Accept", "application/json") .header("Authorization", "Bearer " + token) .timeout(Duration.ofSeconds(30)) // per-request timeout .GET() .build();
BodyHandlers determine how the response body is consumed: ofString() reads into a String, ofBytes() into a byte[], ofFile(path) saves directly to disk, ofLines() gives a Stream<String> of lines, discarding() ignores the body, ofInputStream() gives raw streaming access.

Sync vs Async — send() vs sendAsync()

Synchronous — send()
// Blocks the calling thread until done HttpResponse<String> resp = client.send(request, BodyHandlers.ofString()); int status = resp.statusCode(); // 200 String body = resp.body(); HttpHeaders hdr = resp.headers(); String ct = hdr.firstValue("Content-Type") .orElse("unknown");
Asynchronous — sendAsync()
// Returns immediately with a CompletableFuture CompletableFuture<String> future = client.sendAsync(request, BodyHandlers.ofString()) .thenApply(HttpResponse::body) .thenApply(b -> parseJson(b)); // Non-blocking — combine multiple requests: CompletableFuture.allOf(req1, req2, req3) .thenRun(() -> mergeResults());

GET, POST, PUT, DELETE with HttpClient

// --- GET --- HttpRequest get = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users/1")) .header("Accept", "application/json") .GET() // .GET() is the default; can be omitted .build(); // --- POST with JSON body --- String json = """ {"name": "Alice", "age": 30} """; HttpRequest post = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users")) .header("Content-Type", "application/json") .POST(HttpRequest.BodyPublishers.ofString(json)) // BodyPublisher provides the body .build(); // --- PUT --- HttpRequest put = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users/1")) .header("Content-Type", "application/json") .PUT(HttpRequest.BodyPublishers.ofString(updatedJson)) .build(); // --- DELETE --- HttpRequest delete = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users/1")) .DELETE() .build(); // --- Custom method (PATCH) --- HttpRequest patch = HttpRequest.newBuilder() .uri(URI.create("https://api.example.com/users/1")) .method("PATCH", HttpRequest.BodyPublishers.ofString(patchJson)) .build();
BodyPublishers: ofString(s) — UTF-8 string body; ofBytes(bytes) — raw bytes; ofFile(path) — stream a file; ofInputStream(supplier) — stream from any InputStream; noBody() — for GET/DELETE with no body.

HTTP/2, timeouts, redirects, and authentication

// HTTP/2 — enabled by default, automatically negotiated via ALPN client.version().equals(HttpClient.Version.HTTP_2); // check resp.version(); // HttpClient.Version — what was actually used // HTTP/2 multiplexing — multiple requests on one TCP connection List<CompletableFuture<HttpResponse<String>>> futures = urls.stream() .map(url -> client.sendAsync( HttpRequest.newBuilder().uri(URI.create(url)).build(), BodyHandlers.ofString())) .collect(Collectors.toList()); // All requests fly in parallel on the same HTTP/2 connection
// Redirect behaviour HttpClient.Redirect.NEVER // never follow (default) HttpClient.Redirect.ALWAYS // always follow, including http: → https: HttpClient.Redirect.NORMAL // follow except downgrade from https: → http: // Authentication — built-in Authenticator Authenticator auth = new Authenticator() { @Override protected PasswordAuthentication getPasswordAuthentication() { return new PasswordAuthentication("user", "pass".toCharArray()); } }; // This handles HTTP Basic/Digest — for Bearer tokens, use .header() directly // Timeout handling try { client.send(request, BodyHandlers.ofString()); } catch (HttpTimeoutException e) { // per-request timeout exceeded } catch (ConnectException e) { // connect timeout exceeded (from client builder) }

URL and URI — parsing and building

URI (Uniform Resource Identifier) is the more correct, standards-based class. URL is older and performs a DNS lookup in equals() — avoid using URL for equality comparisons.

https://api.example.com:8443/v2/users/42?format=json&page=1#section
protocol host port path query fragment
// Parsing a URI URI uri = URI.create("https://api.example.com:8443/v2/users/42?format=json&page=1#section"); uri.getScheme() // "https" uri.getHost() // "api.example.com" uri.getPort() // 8443 uri.getPath() // "/v2/users/42" uri.getQuery() // "format=json&page=1" uri.getFragment() // "section" uri.getRawQuery() // URL-encoded version uri.toURL() // convert to URL (if absolute) // Building a URI programmatically URI uri = new URI( "https", // scheme "api.example.com", // host "/v2/users", // path "name=Alice&active=true", // query (auto-encoded) null // fragment );

InetAddress — hostname resolution

// Resolve a hostname to IP address(es) InetAddress addr = InetAddress.getByName("google.com"); addr.getHostAddress() // "142.250.80.46" — one IP addr.getHostName() // "google.com" addr.isReachable(3000) // boolean — ICMP ping or TCP echo, 3 sec timeout // Get ALL IP addresses for a host (round-robin DNS) InetAddress[] all = InetAddress.getAllByName("google.com"); // Localhost InetAddress.getLocalHost() // machine's hostname → IP InetAddress.getByName("localhost") // 127.0.0.1 InetAddress.getLoopbackAddress() // always 127.0.0.1 (Java 7+) // Creating from raw IP InetAddress ip = InetAddress.getByAddress(new byte[]{10,0,0,1}); ip.getHostAddress() // "10.0.0.1"

Socket and ServerSocket — TCP low-level communication

TCP sockets are the transport layer beneath HTTP. Knowing how they work helps you understand connection pooling, keep-alive, and timeouts in higher-level APIs.

Server side — waits for connections
// Echo server ServerSocket server = new ServerSocket(8080); while (true) { Socket client = server.accept(); // blocks Thread.ofVirtual().start(() -> handleClient(client)); } void handleClient(Socket s) { try (BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream())); PrintWriter out = new PrintWriter(s.getOutputStream(), true)) { String line; while ((line=in.readLine())!=null) out.println("Echo: " + line); } }
Client side — connects to server
// Connect to echo server try (Socket socket = new Socket("localhost", 8080)) { socket.setSoTimeout(5000); // read timeout PrintWriter out = new PrintWriter( socket.getOutputStream(), true); BufferedReader in = new BufferedReader( new InputStreamReader( socket.getInputStream())); out.println("Hello, server!"); String resp = in.readLine(); // resp = "Echo: Hello, server!" } // auto-closes socket
Virtual threads (Java 21): The server example uses Thread.ofVirtual() — each client gets its own virtual thread. This scales to millions of concurrent connections because virtual threads are cheap (stack managed by JVM, not OS). On Java 8-19, use a thread pool instead.

Socket options and configuration

Socket s = new Socket(); // Connect with explicit timeout (avoids hanging forever) s.connect(new InetSocketAddress("host", 8080), 5000); // 5 sec timeout s.setSoTimeout(10_000); // read timeout (SocketTimeoutException) s.setKeepAlive(true); // TCP keep-alive probes s.setTcpNoDelay(true); // disable Nagle's algorithm (latency-sensitive) s.setReceiveBufferSize(65536); // socket receive buffer s.setSendBufferSize(65536); // socket send buffer s.setReuseAddress(true); // allow bind to recently-used port (for ServerSocket) s.shutdownOutput(); // signal EOF without closing the read side // ServerSocket backlog — queue of pending connections ServerSocket server = new ServerSocket(8080, 128); // 128 pending connections queued

UDP — DatagramSocket and DatagramPacket

UDP is connectionless — packets are sent without establishing a connection first. No guarantee of delivery, order, or duplicate prevention. Used where low latency matters more than reliability: games, video streaming, DNS, SNMP.

UDP sender
DatagramSocket socket = new DatagramSocket(); // OS assigns port byte[] data = "ping".getBytes(); InetAddress dest = InetAddress.getByName("localhost"); DatagramPacket packet = new DatagramPacket( data, data.length, dest, 9090); socket.send(packet); socket.close();
UDP receiver
DatagramSocket socket = new DatagramSocket(9090); // bind to port byte[] buf = new byte[1024]; DatagramPacket packet = new DatagramPacket(buf, buf.length); socket.receive(packet); // blocks String msg = new String( packet.getData(), 0, packet.getLength()); // "ping" InetAddress sender = packet.getAddress(); int senderPort = packet.getPort();
TCP vs UDP: TCP guarantees delivery and order (handshake, retransmission, flow control). UDP is fire-and-forget. For most application-level networking, use TCP (and usually at a higher abstraction: HttpClient, WebSocket, gRPC). Only drop to UDP if you need sub-millisecond latency and can tolerate loss.

Common patterns — REST client, file download, retry with backoff

// --- Reusable REST client wrapper --- public class RestClient { private final HttpClient client; private final String baseUrl; private final ObjectMapper mapper = new ObjectMapper(); public RestClient(String baseUrl) { this.baseUrl = baseUrl; this.client = HttpClient.newBuilder() .connectTimeout(Duration.ofSeconds(10)) .followRedirects(HttpClient.Redirect.NORMAL) .build(); } public <T> T get(String path, Class<T> type) throws Exception { HttpRequest req = HttpRequest.newBuilder() .uri(URI.create(baseUrl + path)) .header("Accept", "application/json") .GET().build(); HttpResponse<String> resp = client.send(req, BodyHandlers.ofString()); if (resp.statusCode() >= 400) throw new HttpException(resp.statusCode()); return mapper.readValue(resp.body(), type); } }
// --- File download with progress --- HttpRequest req = HttpRequest.newBuilder() .uri(URI.create("https://example.com/large-file.zip")) .build(); Path dest = Path.of("downloads/file.zip"); HttpResponse<Path> resp = client.send(req, BodyHandlers.ofFile(dest)); // Body is streamed directly to disk — no heap pressure from large files System.out.println("Downloaded to: " + resp.body());
// --- Retry with exponential backoff --- public <T> T sendWithRetry(HttpRequest req, HttpResponse.BodyHandler<T> handler, int maxRetries) throws Exception { int attempt = 0; long delayMs = 500; while (true) { try { HttpResponse<T> resp = client.send(req, handler); if (resp.statusCode() == 429 || resp.statusCode() >= 500) { throw new RetryableException(resp.statusCode()); // server error or rate limit } return resp.body(); } catch (RetryableException | IOException e) { if (++attempt >= maxRetries) throw e; Thread.sleep(delayMs); delayMs = Math.min(delayMs * 2, 30_000); // cap at 30s } } }

SSL/TLS and HTTPS — security considerations

// HttpClient uses HTTPS by default for https:// URLs — no extra config needed // Java's default SSLContext uses the JVM's trusted certificate store // --- Custom SSLContext (for self-signed certs, mutual TLS) --- KeyStore trustStore = KeyStore.getInstance("PKCS12"); try (InputStream is = Files.newInputStream(Path.of("truststore.p12"))) { trustStore.load(is, "password".toCharArray()); } TrustManagerFactory tmf = TrustManagerFactory .getInstance(TrustManagerFactory.getDefaultAlgorithm()); tmf.init(trustStore); SSLContext sslCtx = SSLContext.getInstance("TLS"); sslCtx.init(null, tmf.getTrustManagers(), null); HttpClient client = HttpClient.newBuilder() .sslContext(sslCtx) .build();
Never do this in production:
// "Trust all certificates" — disables all cert validation
TrustManager[] trustAll = new TrustManager[]{ new X509TrustManager() {...} };
This is sometimes seen in tutorials and legacy code. It makes HTTPS useless — any attacker can perform a man-in-the-middle attack. Use proper certificates instead.
// --- Certificate pinning (verify the server's exact cert) --- SSLParameters params = new SSLParameters(); params.setEndpointIdentificationAlgorithm("HTTPS"); // hostname verification (default on) // For mutual TLS (mTLS) — client sends a certificate too KeyManagerFactory kmf = KeyManagerFactory.getInstance("SunX509"); kmf.init(clientKeyStore, keyPassword); sslCtx.init(kmf.getKeyManagers(), tmf.getTrustManagers(), null);
