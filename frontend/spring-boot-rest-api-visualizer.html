2 — Controller Anatomy — Click Any Annotation

@RestController

Marks class as HTTP handler + auto-serializes return values to JSON

@RequestMapping

Base URL prefix for all methods in the class

@GetMapping

Handles GET requests. Maps a URL to a method

@PostMapping

Handles POST requests. Used for creating resources

@PathVariable

Extracts a variable from the URL path

@RequestBody

Deserializes the JSON request body into a Java object

ResponseEntity

Wrapper that lets you control status code + headers

@RequestParam

Reads query string parameters like ?page=2&size=10

@RestController @RequestMapping("/api/users") public class UserController { private final UserService service; @GetMapping("/{id}") public ResponseEntity<User> getUser(@PathVariable Long id) { return service.findById(id) .map(ResponseEntity::ok) .orElse(ResponseEntity.notFound().build()); } @PostMapping public ResponseEntity<User> createUser(@RequestBody User user) { User saved = service.save(user); return ResponseEntity.status(201).body(saved); } @GetMapping public List<User> listUsers( @RequestParam(defaultValue = "0") int page, @RequestParam(defaultValue = "20") int size) { return service.findAll(page, size); } }

3 — HTTP Status Codes That Matter

Click a status code to see when to use it and the common mistake.

200
OK
Successful GET, PUT, DELETE. Return the resource or updated object. ⚠️ Don't use for resource creation — that's 201.
201
Created
Successful POST that created a new resource. Return the created object and set Location header to the new resource URL.
204
No Content
Successful DELETE (or PUT with no response body). No response body. ⚠️ Don't return 200 with an empty body — use 204.
400
Bad Request
The client sent malformed data (invalid JSON, missing required field). Return a body explaining what's wrong. Include validation errors.
401
Unauthorized
Not authenticated. Client must provide credentials (login first, get a token). ⚠️ Confusingly named — it means unauthenticated, not unauthorized.
403
Forbidden
Authenticated but not authorized. The user IS logged in but doesn't have permission for this action/resource. Don't expose why — just refuse.
404
Not Found
Resource doesn't exist. Return 404 (not 200 with null). ⚠️ Also use 404 instead of 403 when you want to hide a resource's existence from unauthorized users.
409
Conflict
Request conflicts with current state. Classic use: trying to create a user with an email that already exists. Return the conflicting resource info.
500
Internal Server Error
Something broke server-side. Log the full exception server-side but return a generic message to the client — never expose stack traces externally.

4 — Raw Servlet vs Spring MVC

The same GET /users/{id} endpoint — written the old way vs the Spring way:

❌ Raw HttpServlet
protected void doGet( HttpServletRequest req, HttpServletResponse res) throws IOException { String path = req.getPathInfo(); // Parse ID from "/42" manually Long id = Long.parseLong(path.substring(1)); User u = db.find(id); if (u == null) { res.setStatus(404); return; } res.setContentType("application/json"); // Serialize to JSON manually String json = "{\\"id\\":" + u.getId() +"}"; res.getWriter().write(json); }
✅ Spring @RestController
@GetMapping("/{id}") public ResponseEntity<User> getUser(@PathVariable Long id) { return service.findById(id) .map(ResponseEntity::ok) .orElse(ResponseEntity .notFound().build()); } // - No parsing URLs manually // - No JSON serialization (Jackson) // - No response headers // - No try/catch boilerplate // - Spring handles all of it
