Go HTTP Server & Middleware

net/http ServeMux, the Handler interface, middleware chains, request context, JWT Bearer token validation, and structured JSON responses — production-grade Go web server patterns.

🌐 What is Go's net/http package — and how does middleware work without a framework?

Go ships a production HTTP server in net/http — no framework. The core is the one-method Handler interface (ServeHTTP(w, r)); any type with it is a handler. ServeMux routes (Go 1.22+ method+path: mux.HandleFunc("GET /users/{id}", h)). Middleware is just func(Handler) Handler — wrap and chain: Logging(Auth(mux)) runs logging, then auth, then the mux, the same idea as a servlet filter chain or Angular interceptor. Every request carries a context; middleware adds values with r.WithContext() and the next handler reads them via r.Context().Value(key). JSON is json.NewEncoder(w).Encode(data) / Decode(&req) — set Content-Type and handle errors explicitly.

  • One-method Handler — ServeHTTP(w, r); no framework needed.
  • ServeMux routes — Go 1.22 method+path, r.PathValue("id").
  • Middleware = func(Handler) Handler — chain like a filter chain.
  • Context threads request data; Encode/Decode handle JSON.

ServeMux + handlers

type UserHandler struct { store UserStore } func (h *UserHandler) GetUser(w http.ResponseWriter, r *http.Request) { id := r.PathValue("id") // Go 1.22 user, err := h.store.Find(r.Context(), id) if errors.Is(err, ErrNotFound) { http.Error(w, "not found", 404); return } if err != nil { http.Error(w, "internal error", 500); return } w.Header().Set("Content-Type", "application/json") json.NewEncoder(w).Encode(user) } mux := http.NewServeMux() h := &UserHandler{store: db} mux.HandleFunc("GET /users/{id}", h.GetUser) mux.HandleFunc("POST /users", h.CreateUser) mux.HandleFunc("DELETE /users/{id}", h.DeleteUser) log.Fatal(http.ListenAndServe(":8080", mux))

Spring Boot comparison

Go HTTP → Spring Boot equivalent. http.Handler interface → Spring's HandlerInterceptor / Servlet Filter. func Auth(next Handler) Handler middleware → Spring Security filter chain / OncePerRequestFilter. context.WithValue(ctx, userKey, user) → Spring's SecurityContextHolder.setContext(). mux.HandleFunc("GET /users/{id}", h.GetUser) → @GetMapping("/users/{id}") ResponseEntity<User> getUser(@PathVariable String id). json.NewEncoder(w).Encode(user) → returning a POJO with @ResponseBody (Jackson serializes automatically). Angular's HTTP interceptors work identically to Go middleware: intercept a request, modify it (add auth header), call next, modify the response. Go's ServeMux → Angular's Router. r.PathValue("id") → Angular's route.paramMap.get('id').

CIAM Go service: A JWT middleware validates the RS256 token from Ping/Entra, extracts claims, and injects {sub, email, roles, idpType} into the request context; handlers read claims := r.Context().Value(userKey).(*Claims) and gate with if !contains(claims.Roles, "CIAM_ADMIN") { http.Error(w, "forbidden", 403) }. A logging middleware times each request, and server.Shutdown(ctx) drains in-flight requests on exit. Spring Boot auto-configures all this; Go makes every piece explicit but composable.

1. The Handler Interface

// net/http core interface
type Handler interface {
  ServeHTTP(w http.ResponseWriter, r *http.Request)
}

// HandlerFunc converts a function to Handler
mux.Handle("/users",
  http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
    json.NewEncoder(w).Encode(users)
  }))
// Go 1.22+: enhanced ServeMux with method + path params
mux := http.NewServeMux()
mux.HandleFunc("GET /users/{id}", getUser)
mux.HandleFunc("POST /users", createUser)
mux.HandleFunc("DELETE /users/{id}", deleteUser)

// Extract path param:
id := r.PathValue("id") // Go 1.22+ built-in

Go 1.22 added method-qualified patterns ("GET /path") and path parameters ({id}). Before 1.22, most projects used a third-party router (chi, gorilla/mux, httprouter).

2. Middleware Pattern

// Middleware: func(Handler) Handler — classic Go pattern
func WithLogging(next http.Handler) http.Handler {
  return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    start := time.Now()
    next.ServeHTTP(w, r) // call the next handler in chain
    log.Printf("%s %s %v", r.Method, r.URL.Path, time.Since(start))
  })
}

// Chain middleware (innermost applied last — reads left to right):
handler := WithLogging(WithAuth(WithCORS(mux)))
Middleware chains wrap handlers like onions. The outermost middleware runs first before next.ServeHTTP, and last after it returns. Logging wraps Auth wraps CORS wraps the mux: CORS runs first (allows browser preflight), then Auth (checks JWT), then the handler, then Auth post-processing, then Logging records the duration.

3. Request Context for Values

// Store values in request context (middleware → handler)
type contextKey string
const userKey contextKey = "user"

func WithAuth(next http.Handler) http.Handler {
  return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    user, err := validateJWT(r.Header.Get("Authorization"))
    if err != nil { http.Error(w, "Unauthorized", 401); return }
    ctx := context.WithValue(r.Context(), userKey, user)
    next.ServeHTTP(w, r.WithContext(ctx))
  })
}

func getUser(w http.ResponseWriter, r *http.Request) {
  user := r.Context().Value(userKey).(*User) // extract from context
}
