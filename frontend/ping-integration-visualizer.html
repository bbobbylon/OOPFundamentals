Spring Boot + Angular + Ping

Full-stack integration using PingFederate as the OAuth2/OIDC provider. Angular authenticates users through PingFederate; Spring Boot validates JWT access tokens issued by PingFederate.

@Configuration @EnableMethodSecurity public class SecurityConfig { @Bean public SecurityFilterChain filterChain(HttpSecurity http) throws Exception { http .cors(c -> c.configurationSource(corsSource())) .csrf(AbstractHttpConfigurer::disable) .authorizeHttpRequests(a -> a .requestMatchers("/actuator/health").permitAll() .anyRequest().authenticated() ) .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults())); return http.build(); } @Bean public CorsConfigurationSource corsSource() { var cfg = new CorsConfiguration(); cfg.setAllowedOrigins(List.of("http://localhost:4200", "https://app.company.com")); cfg.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS")); cfg.setAllowedHeaders(List.of("*")); cfg.setAllowCredentials(true); var src = new UrlBasedCorsConfigurationSource(); src.registerCorsConfiguration("/**", cfg); return src; } // Map PingFederate custom claims to Spring authorities @Bean public JwtAuthenticationConverter jwtConverter() { JwtGrantedAuthoritiesConverter conv = new JwtGrantedAuthoritiesConverter(); conv.setAuthoritiesClaimName("groups"); // PingFederate attribute conv.setAuthorityPrefix("ROLE_"); JwtAuthenticationConverter jwtConv = new JwtAuthenticationConverter(); jwtConv.setJwtGrantedAuthoritiesConverter(conv); return jwtConv; } }
// Using oidc-client-ts with PingFederate (vanilla OIDC — works without MSAL) // npm install oidc-client-ts import { UserManager, WebStorageStateStore } from 'oidc-client-ts'; export const userManager = new UserManager({ authority: 'https://pingfederate.company.com/ext/oauth/discovery', client_id: 'angular-spa-client-id', redirect_uri: 'http://localhost:4200/callback', post_logout_redirect_uri: 'http://localhost:4200', response_type: 'code', scope: 'openid profile email api:read', userStore: new WebStorageStateStore({ store: window.sessionStorage }), automaticSilentRenew: true, silent_redirect_uri: 'http://localhost:4200/silent-callback.html' }); // auth.service.ts @Injectable({ providedIn: 'root' }) export class AuthService { login = () => userManager.signinRedirect(); logout = () => userManager.signoutRedirect(); getUser = () => from(userManager.getUser()); }
// auth.interceptor.ts — attach PingFederate access token to API calls @Injectable() export class AuthInterceptor implements HttpInterceptor { intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> { return from(userManager.getUser()).pipe( switchMap(user => { if (user?.access_token && req.url.startsWith('http://localhost:8080')) { req = req.clone({ setHeaders: { Authorization: `Bearer ${user.access_token}` } }); } return next.handle(req); }) ); } } // app.config.ts — register the interceptor { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }

3 — Common Integration Problems

401 Unauthorized — even with a valid-looking token
Check 1 — Issuer mismatch: Spring's issuer-uri must exactly match the iss claim in the JWT (check with jwt.io). PingFederate may issue tokens with https://pingfederate.company.com but your config says https://pingfederate.company.com/ext/oauth/discovery. The OIDC discovery endpoint's issuer field is the ground truth.

Check 2 — Audience mismatch: If you configured audiences, the JWT's aud claim must match exactly.

Check 3 — Clock skew: If the server clock is > 5 minutes off, tokens will appear expired. Sync NTP.
CORS error in browser — "blocked by CORS policy"
Spring's CORS config must include the Angular origin. Also check that the OPTIONS preflight is handled — add "OPTIONS" to allowed methods and ensure Spring doesn't block OPTIONS requests with Spring Security before they hit the CORS filter.

Tip: disable Spring Security for OPTIONS: .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
PingFederate returns "invalid_client" on token request
Check 1: The client_id in Angular doesn't match the OAuth Client ID in PingFederate Admin.

Check 2: The redirect_uri sent in the auth request doesn't exactly match (case-sensitive, trailing slash matters) the redirect URI registered in PingFederate.

Check 3: The grant type authorization_code is not enabled for this client in PingFederate.
Token validated but @PreAuthorize always fails
Spring's default claim is scope or scp. PingFederate may put roles in a custom claim like groups or memberOf.

Configure a custom JwtAuthenticationConverter that reads the correct claim:
conv.setAuthoritiesClaimName("groups");

Then use @PreAuthorize("hasAuthority('ROLE_Engineering')") matching the prefix + claim value.
Angular redirect loop after login
The callback page (redirect_uri) must handle the auth code and exchange it for tokens before redirecting. If the OIDC library isn't processing the callback properly, the user gets redirected to login again.

Ensure: the callback route is excluded from the auth guard, the OIDC library's signinRedirectCallback() is called on the /callback route, and the auth state is properly stored before navigation.

4 — Key Endpoints Reference

EndpointPurpose
/ext/oauth/discoveryOIDC Discovery — JSON doc with all endpoints, supported scopes, algorithms
/ext/oauth/jwksJWKS — public keys for JWT signature verification (Spring Boot fetches this)
/as/authorization.oauth2Authorization endpoint — browser redirects here to start login
/as/token.oauth2Token endpoint — exchange auth code for tokens (POST from Angular/service)
/idp/userinfo.openidUserInfo endpoint — returns user claims for the current access token
/as/revoke_token.oauth2Token revocation — logout: invalidate access/refresh tokens at PingFederate
/idp/startSLO.pingSingle Logout — redirects to IdP to clear PingFederate session (for SAML/SSO logout)
