1 — The Big Picture




Kubernetes (K8s) is a container orchestrator. You describe the desired state ("run 3 copies of my Spring Boot container") and Kubernetes makes it so — scheduling containers onto nodes, restarting failed ones, and routing traffic.






Control Plane


    

  • API Server — the REST front door; every kubectl command hits it
    • 

  • etcd — distributed key-value store; the source of truth for all cluster state
    • 

  • Scheduler — watches for unbound pods, picks the best node
    • 

  • Controller Manager — runs controllers (ReplicaSet, Deployment, etc.)
    • 







Worker Nodes


    

  • kubelet — node agent; pulls images and runs containers
    • 

  • kube-proxy — manages iptables / eBPF rules for Service networking
    • 

  • Container Runtime — containerd or CRI-O actually runs containers
    • 

  • Pod — smallest deployable unit: one or more containers sharing network/storage
    • 














2 — Pods




A Pod wraps one or more containers that share the same network namespace (same IP) and can share volumes. Pods are ephemeral — they don't reschedule themselves. That's what Deployments are for.


# minimal pod manifest
apiVersion: v1
kind: Pod
metadata:
  name: demo
  labels:
    app: demo
spec:
  containers:
  - name: app
    image: myregistry/demo:1.0
    ports:
    - containerPort: 8080
    resources:
      requests: { cpu: "100m", memory: "256Mi" }
      limits:  { cpu: "500m", memory: "512Mi" }


100m CPU = 0.1 core. Always set both requests and limits — requests drive scheduling; limits prevent a bad pod from starving others.









3 — kubectl Essentials




# context & cluster
kubectl config get-contexts
kubectl config use-context my-cluster

# apply manifests (declarative)
kubectl apply -f deployment.yaml
kubectl apply -f ./k8s/          # whole directory

# inspect
kubectl get pods -n my-namespace
kubectl get pods -A              # all namespaces
kubectl describe pod demo-abc
kubectl logs demo-abc -f         # stream logs
kubectl exec -it demo-abc -- /bin/sh

# debug
kubectl get events --sort-by=.metadata.creationTimestamp
kubectl top pods                 # requires metrics-server









4 — Namespaces & Resource Quotas




Namespaces are virtual clusters within a physical cluster. They scope names, RBAC policies, and resource quotas. Use them to isolate environments (dev/staging) or teams.


# create a namespace
kubectl create namespace team-alpha

# ResourceQuota limits total consumption
apiVersion: v1
kind: ResourceQuota
metadata:
  name: team-alpha-quota
  namespace: team-alpha
spec:
  hard:
    pods: "20"
    requests.cpu: "4"
    requests.memory: 8Gi


Four built-in namespaces: default (your apps if unspecified), kube-system (K8s internals), kube-public (readable by all), kube-node-lease (node heartbeats).









5 — Pod Lifecycle






PhaseMeaning


PendingAccepted by API server; waiting for scheduler or image pull


RunningAt least one container running; others may still be starting


SucceededAll containers exited 0 (Job pods)


FailedAt least one container exited non-zero and won't restart


UnknownNode communication lost; pod state unreadable




Restart policies: Always (default, good for servers), OnFailure (Jobs), Never (run-once tasks). CrashLoopBackOff = container keeps crashing; K8s backs off exponentially (10s → 20s → 40s… max 5min).
