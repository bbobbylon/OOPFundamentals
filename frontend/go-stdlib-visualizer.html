Go: Standard Library Tour

The four packages you'll touch in almost every Go program: encoding/json, the io.Reader/Writer abstraction, time, and strings/strconv/fmt.

Why Go's standard library lets most services ship with almost no dependencies

Go's stdlib is unusually complete, so a production HTTP/JSON service often needs zero third-party libraries. Four packages do most of the work. encoding/json converts between Go values and JSON: json.Marshal(v) serializes (driven by json:"..." struct tags), json.Unmarshal(data, &v) deserializes, and only exported fields participate. io defines two tiny interfaces that the whole ecosystem composes around: io.Reader (one method, Read([]byte) (int, error)) and io.Writer (Write([]byte) (int, error)). Because files, network sockets, HTTP bodies, buffers, gzip streams, and crypto all implement these, you can wrap and chain them like Unix pipes — io.Copy(dst, src) streams any reader into any writer without loading it all into memory. time gives you time.Time, time.Duration (a typed nanosecond count, so 2 * time.Second is type-safe), timers/tickers, and a famously unusual formatting scheme: you spell out the reference date Mon Jan 2 15:04:05 MST 2006 (i.e. 01/02 03:04:05 PM '06) as the layout. And strings/bytes/strconv/fmt handle text: strings.Builder for efficient concatenation, strconv for number⇄string, and fmt's verbs (%v, %+v, %q, %T) for formatting and debugging. Master these four and you can build most backends without reaching for a framework.

1. encoding/json

type User struct {
  ID int `json:"id"`
  Email string `json:"email"`
  Roles []string `json:"roles,omitempty"`
  pw string // unexported → never marshaled
}
b, _ := json.Marshal(u) // struct → []byte
var u2 User
err := json.Unmarshal(b, &u2) // []byte → struct (pass &)

Marshal/Unmarshal are tag-driven. omitempty drops zero values; json:"-" excludes a field entirely; unexported fields are invisible to JSON. Unknown JSON keys are silently ignored on decode (use Decoder.DisallowUnknownFields() to reject them). For huge or streaming payloads, use json.NewDecoder(r).Decode(&v) / json.NewEncoder(w).Encode(v) on an io.Reader/Writer instead of buffering.

Decoding into any turns every number into float64. json.Unmarshal(b, &m) where m is map[string]any gives you float64 for 42 — so a JWT exp read this way needs int64(v.(float64)). Decode into a typed struct to avoid the surprise.

2. io.Reader / io.Writer — Compose Like Pipes

InterfaceMethodImplemented by
io.ReaderRead(p []byte) (n int, err error)files, net.Conn, http body, strings.Reader, bytes.Buffer, gzip.Reader…
io.WriterWrite(p []byte) (n int, err error)files, http.ResponseWriter, bytes.Buffer, gzip.Writer, hash.Hash…
io.Copy(dst, src) streams any Reader into any Writer in constant memory, and decorators wrap each other: gzip.NewReader(bufio.NewReader(file)), io.MultiWriter(w1, w2) (tee), io.TeeReader. Read returns io.EOF at the end — that's a normal signal, not a failure. This tiny-interface design is why the whole stdlib plugs together.

3. time — Time, Duration, and the Reference Layout

now := time.Now()
d := 2 * time.Second // Duration is typed ns
later := now.Add(d)
elapsed := time.Since(start) // uses monotonic clock

// format/parse by the reference date:
// Mon Jan 2 15:04:05 MST 2006
s := now.Format("2006-01-02T15:04:05Z07:00") // = time.RFC3339
t, err := time.Parse(time.RFC3339, s)

A Duration is a typed int64 of nanoseconds, so arithmetic is unit-safe (5 * time.Minute). Formatting uses the magic reference time 01/02 03:04:05PM '06 -0700 — you write the layout as if formatting that exact date. Prefer the predefined layouts (time.RFC3339). For timeouts pair with context.WithTimeout; for periodic work use time.NewTicker (and Stop() it).

Measure elapsed time with time.Since, not by subtracting wall clocks. time.Now() carries a monotonic reading that's immune to NTP adjustments and DST; time.Since(start) uses it, so a clock jump can't produce a negative or wrong duration.

strconv beats fmt for hot paths. strconv.Itoa(n) is far faster and allocates less than fmt.Sprintf("%d", n) because fmt uses reflection to inspect its arguments. Use fmt for readability and debugging (%+v is invaluable), strconv when converting numbers at volume.
