Fastify — Schemas, Hooks & Plugins

Express, but faster and schema-first. You declare a JSON Schema per route; Fastify uses it to validate the input and compile a blazing-fast serializer for the output. Lifecycle hooks and an encapsulated plugin system round it out.

⚡ What is Fastify — and how does a schema make it fast and safe?

Fastify is a modern Node web framework focused on low overhead and developer experience. Its headline idea is schema-based everything: each route can declare a JSON Schema for its params, query, body, headers, and response. Fastify uses that schema two ways — it validates incoming data (rejecting bad requests with a 400 before your handler runs) and it compiles a specialized serializer (via fast-json-stringify) that turns your response object into JSON far faster than generic JSON.stringify, because the shape is known ahead of time. Requests flow through an explicit lifecycle of hooks (onRequest → preValidation → preHandler → handler → preSerialization → onSend → onResponse), each a place to plug in auth, logging, or transforms. Code is organized as plugins — encapsulated, composable units registered with fastify.register(), each with its own scope. It is the framework you pick when Express feels too unstructured and too slow.

  • Schema-first — one JSON Schema validates input and compiles the output serializer.
  • Lifecycle hooks — named extension points around every request.
  • Plugins + encapsulation — register() scopes decorators/hooks to a subtree.
  • Fast by design — schema-compiled serialization, low per-request overhead.

A schema-validated route

fastify.post("/users", { schema: { body: { type: "object", required: ["email"], properties: { email: { type: "string", format: "email" }, age: { type: "integer", minimum: 0 }, }, }, response: { 201: { type: "object", properties: { id: { type: "integer" } } } }, }, }, async (req, reply) => { const id = await createUser(req.body); // body is valid reply.code(201).send({ id }); });

Hooks & a plugin

// a hook: runs for every request in this scope fastify.addHook("onRequest", async (req, reply) => { req.startTime = process.hrtime.bigint(); }); // a plugin: an encapsulated, composable unit async function authPlugin(fastify, opts) { fastify.decorateRequest("user", null); fastify.addHook("preHandler", verifyJwt); } fastify.register(authPlugin); // scoped to its subtree

Spring Boot comparison

Fastify's per-route schema ≈ a Spring DTO + @Valid Bean Validation, but it also covers the response shape (like declaring your serialization view). Its hooks ≈ Servlet filters / HandlerInterceptor at named points. Plugins + encapsulation ≈ Spring's modular configuration and bean scoping — a registered plugin's decorators/hooks are visible only to that subtree, like a child ApplicationContext. reply.code(201).send(obj) ≈ ResponseEntity.status(201).body(obj). The schema-compiled serializer has no Spring analogue — it is a Fastify performance trick that trades a little startup compilation for much faster JSON output.

CIAM Fastify gateway: Fastify's speed suits a high-throughput token-validating gateway. An authPlugin decorates the request with a user property and adds a preHandler hook that verifies the Ping/Entra RS256 JWT (via @fastify/jwt + a JWKS fetcher) — encapsulation means only the routes under that plugin require auth. Per-route response schemas guarantee the gateway never accidentally leaks an internal field, because the compiled serializer only emits the properties the schema declares. That schema-as-allowlist behavior is a genuine security win over hand-rolled res.json().

1. The request lifecycle (hook order)

onRequest // earliest — auth/rate-limit before parsing
preParsing
preValidation // before schema validation
[ schema validation runs here ]
preHandler // last gate before your handler
[ your handler runs ]
preSerialization // transform the payload before JSON
onSend // final tweak of the outgoing response
onResponse // after sent — logging/metrics
Hooks are the extension points. Put authentication in onRequest (cheapest, before body parsing); put authorization in preHandler (after validation, when you know the request shape is good); put metrics in onResponse. Each maps to a precise moment in the pipeline.

2. Encapsulation: the plugin tree

// decorators & hooks are scoped to where they're registered
fastify.register(async (api) => {
  api.addHook("preHandler", verifyJwt); // only inside this scope
  api.get("/me", meHandler); // protected
}, { prefix: "/api" });

fastify.get("/health", healthHandler); // NOT protected (outside scope)

A plugin gets its own encapsulated context — hooks and decorate() additions are visible only to it and its children, not siblings. Use fastify-plugin to deliberately break encapsulation and share globally.

3. Why the response schema matters

// Without a response schema: generic JSON.stringify, leaks everything
reply.send(user); // { id, email, passwordHash, internalFlags } 😱

// With a response schema: compiled serializer emits ONLY declared props
schema: { response: { 200: { type: "object",
  properties: { id: { type: "integer" }, email: { type: "string" } } } }
reply.send(user); // → { id, email } — passwordHash never serialized
