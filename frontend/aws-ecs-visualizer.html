ECS — Elastic Container Service

ECS runs Docker containers on AWS. With Fargate, AWS manages the underlying servers — you define your container (CPU, memory, image) and ECS runs it. No EC2 instances to patch. See Deployment Strategies for blue-green/canary alternatives to ECS's default rolling deployment.

📦 What is ECS — and why is Fargate the preferred way to run Spring Boot containers in production without managing servers?

ECS is AWS's managed container orchestrator — the AWS-native alternative to Kubernetes. Two launch types: EC2 (you manage the instances) and Fargate (serverless — you only specify CPU/memory per task), and Fargate is almost always right for CIAM: no fleet to patch, pay only for what tasks use. The hierarchy is Cluster → Service → Task Definition → Task: the Service keeps N tasks running, does rolling zero-downtime deploys (start new, pass ALB health check, drain old), and registers with an ALB target group. A Task IAM Role means no credentials in code — the SDK reads temp creds from the task metadata endpoint. Service Auto Scaling target-tracks CPU ("keep avg at 60%") to add/remove tasks with load.

  • ECS = AWS container orchestrator — Fargate (serverless) beats EC2 launch type for CIAM.
  • Cluster → Service → Task Def → Task — Service keeps desired count + wires the ALB.
  • Rolling deploys — new tasks pass health check, old tasks drain → zero downtime.
  • Task IAM role + auto scaling — no creds in code; target-track CPU to scale.

The ALB registers each running task as a target. ECS handles rolling deploys (starts new tasks before draining old ones), health checks, and auto-scaling. Fargate runs tasks in private subnets; the ALB in public subnets routes traffic inward.

Fargate vs EC2

A Cluster is the logical grouping of tasks and services. Think of it as the namespace. You can run multiple services in one cluster (e.g., api-service, worker-service, scheduler-service).

  • Clusters are free — you pay for the tasks (Fargate CPU/memory) that run in them
  • One cluster per environment is typical: prod-cluster, staging-cluster
  • CloudWatch Container Insights can be enabled per cluster for metrics and logging

A Task Definition is a blueprint for your container (like a Docker Compose file, but for ECS). It defines the container image, CPU, memory, environment variables, and IAM role:

{ "family": "spring-boot-api", "networkMode": "awsvpc", // required for Fargate "requiresCompatibilities": ["FARGATE"], "cpu": "512", // 0.5 vCPU "memory": "1024", // 1 GB "taskRoleArn": "arn:aws:iam::123:role/spring-boot-task-role", "executionRoleArn": "arn:aws:iam::123:role/ecsTaskExecutionRole", "containerDefinitions": [{ "name": "myapp", "image": "123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:1.2.0", "portMappings": [{ "containerPort": 8080 }], "environment": [ { "name": "SPRING_PROFILES_ACTIVE", "value": "prod" } ], "secrets": [ { "name": "DB_PASSWORD", "valueFrom": "arn:aws:secretsmanager:..." } ], "logConfiguration": { "logDriver": "awslogs", "options": { "awslogs-group": "/ecs/spring-boot-api", "awslogs-region": "us-east-1", "awslogs-stream-prefix": "ecs" } }, "healthCheck": { "command": ["CMD-SHELL", "curl -f http://localhost:8080/actuator/health || exit 1"], "interval": 30, "timeout": 5, "retries": 3 } }] }

An ECS Service keeps a desired number of tasks running and integrates with the ALB. It handles rolling deployments and auto-scaling:

  • Desired count — the number of tasks to keep running (e.g., 2 for HA)
  • Rolling update — minimum healthy percent (e.g., 50%) and maximum percent (e.g., 200%) control how many tasks are replaced at once
  • ALB integration — service registers tasks in a Target Group; ALB health check drives task deregistration on failure
  • Auto Scaling — scale based on CPU%, memory%, or custom CloudWatch metrics (requests per task)
  • Circuit breaker — ECS can automatically rollback a deployment if health checks fail

Fargate — Serverless containers

  • No EC2 instances to manage or patch
  • Pay per task CPU/memory per second
  • Tasks run in isolated microVMs (better security)
  • Best for: most Spring Boot workloads, APIs, microservices
  • Cold start: ~30–60 seconds to provision a new task

EC2 Launch Type

  • You manage a fleet of EC2 instances in the cluster
  • Can be cheaper at sustained high scale
  • Supports GPU instances, custom AMIs
  • Best for: very high density, GPU workloads, special hardware
  • More operational overhead (patching, capacity planning)

3 — ECR — Elastic Container Registry

ECR is AWS's private Docker registry. ECS pulls images from ECR using IAM — no credentials needed if the task execution role has ECR pull permissions:

# CI/CD pipeline — build and push to ECR # Authenticate Docker to ECR aws ecr get-login-password --region us-east-1 \ | docker login --username AWS --password-stdin \ 123456789.dkr.ecr.us-east-1.amazonaws.com # Build the Spring Boot image docker build -t myapp:1.2.0 . # Tag for ECR docker tag myapp:1.2.0 \ 123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:1.2.0 # Push to ECR docker push 123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:1.2.0 # Deploy: update ECS service to use new image aws ecs update-service \ --cluster prod-cluster \ --service spring-boot-api \ --force-new-deployment

ECR lifecycle policies automatically delete old images (e.g., keep only the 10 most recent tagged images). Without this, your registry will fill up with stale images and incur storage costs.

4 — Key ECS Concepts

ConceptDescription
Task RoleIAM role assumed by your running container. Gives your Spring Boot app AWS permissions (S3, Secrets Manager, etc.) without hard-coded credentials.
Execution RoleIAM role used by ECS itself to pull the container image from ECR and fetch secrets from Secrets Manager before starting the container.
awsvpc Network ModeEach Fargate task gets its own ENI (Elastic Network Interface) and private IP. Required for Fargate. Security Groups apply at the task level.
Service DiscoveryRegister services in AWS Cloud Map for service-to-service DNS (e.g., api.local → Spring Boot task IP). Alternative to ALB for internal traffic.
Scheduled TasksRun ECS tasks on a cron schedule (via EventBridge). Use for batch jobs, report generation, nightly cleanup — without a standalone Lambda.
ECS ExecLike "docker exec" into a running Fargate task for debugging — via AWS CLI or console. Replaces SSH. Requires SSM agent in container and IAM permissions.
Deployment Circuit BreakerAutomatically rolls back a deployment if new tasks fail health checks. Prevents bad releases from taking down a service.
Capacity ProviderLinks ECS to Fargate or an EC2 Auto Scaling Group. Controls how capacity is provisioned when tasks need to run.
