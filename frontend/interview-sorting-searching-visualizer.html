Sorting & Searching — Interview Patterns

Master every sort algorithm, binary search variant, and the classic interview problems that test them.

What are sorting and searching algorithms — and why does knowing the right algorithm for the right situation make the difference between passing and failing a coding interview?

Sorting and searching appear in virtually every technical interview because they test your understanding of time complexity, space complexity, and algorithm design trade-offs. There is no single "best" sort — each algorithm has a situation where it wins. Comparison sorts — algorithms that work by comparing elements — have an information-theoretic lower bound of O(n log n) (you must examine each element at least once, and log n comparisons are needed to determine the correct position). Bubble Sort: O(n²) time, O(1) space. Repeatedly swaps adjacent elements if out of order. Stable (equal elements maintain relative order). Useful only for educational purposes or nearly-sorted data (where it approaches O(n) with early exit). Selection Sort: O(n²) time, O(1) space. Finds the minimum element in the unsorted portion and places it at the current position. Not stable. Minimal writes (good for flash memory). Insertion Sort: O(n²) worst, O(n) best (nearly sorted), O(1) space. Stable. Very fast for small arrays and nearly-sorted data — Java's Arrays.sort uses insertion sort for arrays ≤ 47 elements. Merge Sort: O(n log n) guaranteed, O(n) space. Divide and conquer: split in half, recursively sort each half, merge. Stable. The algorithm of choice when stability matters or data doesn't fit in memory (external merge sort). Java's Arrays.sort for objects uses TimSort (merge sort hybrid). Quick Sort: O(n log n) average, O(n²) worst case (poor pivot), O(log n) space (call stack). In-place. Not stable. Typically the fastest in practice due to cache efficiency. Java's Arrays.sort for primitives uses Dual-Pivot QuickSort. Heap Sort: O(n log n) guaranteed, O(1) space. In-place. Not stable. Consistent performance regardless of input, but slower in practice than QuickSort due to cache behavior. Counting/Radix Sort: O(n+k) — better than O(n log n) by exploiting the structure of the data (integers in a known range). Used when element values are bounded.

Merge Sort

// Merge Sort: O(n log n) guaranteed, stable, O(n) space // Divide: split array in half (left, right) // Conquer: recursively sort each half // Combine: merge two sorted halves into one sorted array void mergeSort(int[] arr, int lo, int hi) { if (lo >= hi) return; // base: single element int mid = lo + (hi - lo) / 2; mergeSort(arr, lo, mid); // sort left half mergeSort(arr, mid+1, hi); // sort right half merge(arr, lo, mid, hi); // merge both halves } void merge(int[] arr, int lo, int mid, int hi) { int[] left = Arrays.copyOfRange(arr, lo, mid+1); int[] right = Arrays.copyOfRange(arr, mid+1, hi+1); int i=0, j=0, k=lo; while (i<left.length && j<right.length) { if (left[i] <= right[j]) arr[k++]=left[i++]; // stable: ≤ not < else arr[k++]=right[j++]; } while (i<left.length) arr[k++]=left[i++]; while (j<right.length) arr[k++]=right[j++]; }

Quick Sort

// Quick Sort: O(n log n) avg, O(n²) worst, in-place // Pick a pivot, partition: left=smaller, right=larger // Recursively sort each partition void quickSort(int[] arr, int lo, int hi) { if (lo >= hi) return; int pivotIdx = partition(arr, lo, hi); quickSort(arr, lo, pivotIdx - 1); quickSort(arr, pivotIdx + 1, hi); } int partition(int[] arr, int lo, int hi) { int pivot = arr[hi]; // use last element as pivot int i = lo - 1; // i = last position of smaller element for (int j = lo; j < hi; j++) { if (arr[j] < pivot) { // found element smaller than pivot i++; // expand smaller-than section int tmp=arr[i]; arr[i]=arr[j]; arr[j]=tmp; // swap } } // place pivot in its final sorted position int tmp=arr[i+1]; arr[i+1]=arr[hi]; arr[hi]=tmp; return i+1; // pivot's final index }

Sort algorithm decision table

// Which sort algorithm to use when: // Stability required (equal elements keep order)? // → Merge Sort (guaranteed stable) // → Insertion Sort (stable, fast for small/nearly-sorted) // In-place required (O(1) space)? // → Quick Sort (best average performance, in-place) // → Heap Sort (in-place, guaranteed O(n log n)) // Data nearly sorted? // → Insertion Sort (degrades to O(n) for nearly-sorted!) // General-purpose (Java Arrays.sort behavior): // Primitives: Dual-Pivot QuickSort (fast, in-place, not stable) // Objects: TimSort (Merge+Insertion hybrid, stable) // Can't fit in memory (external sort)? // → External Merge Sort (merge sorted runs from disk) // Integer keys in bounded range [0, k)? // → Counting Sort: O(n+k) — better than O(n log n)! // Multiple-digit integer keys? // → Radix Sort: O(d*(n+k)) where d=digits // Rule of thumb: interviews expect Merge or Quick by default

Interview / Context: Sorting is rarely implemented from scratch in production (Java's Arrays.sort is exceptionally well-tuned), but interviewers use sorting problems to probe your understanding of complexity analysis and algorithm design. The most valuable thing to internalize is which algorithm Java actually uses internally — Arrays.sort for primitives uses Dual-Pivot QuickSort (not stable, excellent cache performance); for objects it uses TimSort (stable, merge-based). This matters when you choose how to sort user data in a Spring Boot service: sorting User objects requires TimSort's stability guarantee (equal users maintain their relative order from the database).

Java Sort API

Bubble Sort O(n²)

How it works

Repeatedly walk the array, swapping adjacent elements when out of order. After pass k, the k largest elements are "bubbled" to the end. Best case O(n) with early-exit flag when no swaps occur.

public void bubbleSort(int[] a) { int n = a.length; for (int i = 0; i < n - 1; i++) { boolean swapped = false; for (int j = 0; j < n - i - 1; j++) { if (a[j] > a[j + 1]) { int tmp = a[j]; a[j] = a[j+1]; a[j+1] = tmp; swapped = true; } } if (!swapped) break; // already sorted! } }

Selection Sort O(n²)

How it works

On each pass, find the minimum element in the unsorted portion and swap it to the front. Always performs exactly n(n-1)/2 comparisons — no early exit. Good when writes are expensive (fewer swaps than bubble sort).

public void selectionSort(int[] a) { int n = a.length; for (int i = 0; i < n - 1; i++) { int minIdx = i; for (int j = i + 1; j < n; j++) { if (a[j] < a[minIdx]) minIdx = j; } int tmp = a[minIdx]; a[minIdx] = a[i]; a[i] = tmp; } } // Always O(n²) — no early exit // Performs at most n-1 swaps (useful when writes cost)

Insertion Sort O(n²) worst, O(n) best

How it works

Build a sorted portion on the left. For each new element, "insert" it into its correct position by shifting larger elements right. Best sort for nearly-sorted data (O(n) best). Java uses Insertion Sort for small arrays (<47 elements) inside TimSort.

public void insertionSort(int[] a) { for (int i = 1; i < a.length; i++) { int key = a[i]; int j = i - 1; // shift right until insertion point found while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; } a[j + 1] = key; // insert } } // Stable sort — preserves equal element order // Online algorithm — works on streaming data

Merge Sort O(n log n) — Stable

Divide & Conquer

Split array in half recursively until single elements, then merge back in sorted order. Always O(n log n) — no worst case. Requires O(n) auxiliary space.

public void mergeSort(int[] a, int l, int r) { if (l >= r) return; int mid = l + (r - l) / 2; // avoids overflow mergeSort(a, l, mid); mergeSort(a, mid + 1, r); merge(a, l, mid, r); } private void merge(int[] a, int l, int mid, int r) { int[] tmp = Arrays.copyOfRange(a, l, r + 1); int i = 0, j = mid - l + 1, k = l; while (i <= mid - l && j <= r - l) { if (tmp[i] <= tmp[j]) a[k++] = tmp[i++]; else a[k++] = tmp[j++]; } while (i <= mid - l) a[k++] = tmp[i++]; while (j <= r - l) a[k++] = tmp[j++]; }

Quick Sort O(n log n) avg, O(n²) worst

Partition & Recurse

Choose a pivot, partition into elements less than/greater than pivot, recurse on each side. In-place O(log n) stack space. Worst case O(n²) on sorted input with bad pivot choice. Use random pivot or median-of-three to mitigate.

public void quickSort(int[] a, int lo, int hi) { if (lo >= hi) return; int p = partition(a, lo, hi); quickSort(a, lo, p - 1); quickSort(a, p + 1, hi); } private int partition(int[] a, int lo, int hi) { // Lomuto partition scheme int pivot = a[hi], i = lo - 1; for (int j = lo; j < hi; j++) { if (a[j] <= pivot) { i++; int tmp = a[i]; a[i] = a[j]; a[j] = tmp; } } int tmp = a[i+1]; a[i+1] = a[hi]; a[hi] = tmp; return i + 1; // pivot's final position }

Binary Search O(log n)

Classic Template

Works only on sorted arrays. Halve the search space each step. Three variants: find exact, find leftmost, find rightmost.

// Exact match — returns -1 if not found public int binarySearch(int[] a, int target) { int lo = 0, hi = a.length - 1; while (lo <= hi) { int mid = lo + (hi - lo) / 2; // no overflow! if (a[mid] == target) return mid; else if (a[mid] < target) lo = mid + 1; else hi = mid - 1; } return -1; } // Left-most position (lower bound) public int lowerBound(int[] a, int target) { int lo = 0, hi = a.length; while (lo < hi) { int mid = (lo + hi) / 2; if (a[mid] < target) lo = mid + 1; else hi = mid; } return lo; // first index where a[i] >= target } // Right-most position (upper bound) public int upperBound(int[] a, int target) { int lo = 0, hi = a.length; while (lo < hi) { int mid = (lo + hi) / 2; if (a[mid] <= target) lo = mid + 1; else hi = mid; } return lo - 1; // last index where a[i] <= target }

Search in Rotated Sorted Array Classic Interview

// [4,5,6,7,0,1,2], target=0 → index 4 // Key: one half is always sorted! public int searchRotated(int[] a, int t) { int lo = 0, hi = a.length - 1; while (lo <= hi) { int mid = lo + (hi - lo) / 2; if (a[mid] == t) return mid; // left half is sorted if (a[lo] <= a[mid]) { if (t >= a[lo] && t < a[mid]) hi = mid - 1; // target in left else lo = mid + 1; // target in right } else { // right half is sorted if (t > a[mid] && t <= a[hi]) lo = mid + 1; // target in right else hi = mid - 1; // target in left } } return -1; }

Key Insight

Why binary search still works on a rotated array:

When you compute mid, at least one of the two halves must be completely sorted. Check if your target falls in the sorted half — if yes, discard the other half; if no, discard the sorted half.

Edge case with duplicates: if a[lo] == a[mid], you can't determine which side is sorted → just increment lo. This degrades to O(n) worst case.
// Find First and Last Position (LeetCode 34) // nums=[5,7,7,8,8,10], target=8 → [3,4] int[] result = {-1, -1}; result[0] = lowerBound(nums, target); if (result[0] < nums.length && nums[result[0]] == target) { result[1] = upperBound(nums, target); } // Use lowerBound/upperBound templates above!

Binary Search on Answer Space Advanced Pattern

Not just searching arrays — binary search on the answer when you can check "is X feasible?" in O(n). If feasibility is monotonic, binary search the answer space.

// "Minimum Largest Subarray Sum" pattern // Can we split array into k parts each ≤ mid? boolean canSplit(int[] a, int k, int maxSum) { int parts = 1, curr = 0; for (int x : a) { if (curr + x > maxSum) { parts++; curr = 0; } curr += x; } return parts <= k; } int splitArray(int[] a, int k) { int lo = Arrays.stream(a).max().getAsInt(); int hi = Arrays.stream(a).sum(); while (lo < hi) { int mid = lo + (hi - lo) / 2; if (canSplit(a, k, mid)) hi = mid; else lo = mid + 1; } return lo; }

Quick Decision Guide

Use Merge Sort when...

  • Stability is required
  • Sorting linked lists
  • External sort (disk-based)
  • Predictable O(n log n)
  • Counting inversions

Use Quick Sort when...

  • Best cache performance needed
  • In-place sort (O(log n) stack)
  • Average case speed priority
  • Quick Select (kth element)
  • Use random pivot in interviews

Use non-comparison sorts when...

  • Integers in known range (Counting)
  • Strings/large integers (Radix)
  • Want O(n) guaranteed
  • Range k is not too large
  • Sorting by digit (Radix)

Classic Interview Problems

Kth Largest Element (LeetCode 215)

// Quick Select — O(n) average! public int findKthLargest(int[] a, int k) { return quickSelect(a, 0, a.length-1, a.length - k); } private int quickSelect(int[] a, int lo, int hi, int k) { int p = partition(a, lo, hi); if (p == k) return a[p]; if (p < k) return quickSelect(a, p+1, hi, k); return quickSelect(a, lo, p-1, k); } // Alternative: Min-Heap of size k // PriorityQueue<Integer> pq = new PriorityQueue<>(); // for(int n:nums){pq.offer(n); if(pq.size()>k)pq.poll();} // return pq.peek(); — O(n log k), stable
Quick Select vs Min-Heap: Quick Select is O(n) average but O(n²) worst. Min-Heap of size k is always O(n log k) — safer in interviews. For k close to n, prefer Quick Select or sort directly.

Top K Frequent Elements (LeetCode 347)

// Bucket Sort approach — O(n)! public int[] topKFrequent(int[] nums, int k) { Map<Integer,Integer> freq = new HashMap<>(); for (int n : nums) freq.merge(n, 1, Integer::sum); // Bucket: index = frequency List<Integer>[] bucket = new List[nums.length + 1]; freq.forEach((num, cnt) -> { if (bucket[cnt] == null) bucket[cnt] = new ArrayList<>(); bucket[cnt].add(num); }); int[] res = new int[k]; int idx = 0; for (int i = bucket.length - 1; i >= 0 && idx < k; i--) { if (bucket[i] != null) for (int n : bucket[i]) if (idx < k) res[idx++] = n; } return res; }

More Classic Problems

Merge Intervals (LeetCode 56)

// [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]] public int[][] merge(int[][] intervals) { Arrays.sort(intervals, (a, b) -> a[0] - b[0]); // sort by start List<int[]> merged = new ArrayList<>(); for (int[] interval : intervals) { if (merged.isEmpty() || merged.get(merged.size()-1)[1] < interval[0]) { merged.add(interval); // no overlap } else { // extend end of last interval merged.get(merged.size()-1)[1] = Math.max(merged.get(merged.size()-1)[1], interval[1]); } } return merged.toArray(new int[0][]); } // O(n log n) — dominated by sort

Sort Colors / Dutch Flag (LeetCode 75)

// [2,0,2,1,1,0] → [0,0,1,1,2,2] // 3-way partition: lo, mid, hi pointers public void sortColors(int[] nums) { int lo = 0, mid = 0, hi = nums.length - 1; while (mid <= hi) { if (nums[mid] == 0) { swap(nums, lo++, mid++); } else if (nums[mid] == 1) { mid++; } else { // nums[mid] == 2 swap(nums, mid, hi--); // don't increment mid — need to check } } } // O(n) time, O(1) space — single pass! // Dutch National Flag algorithm by Dijkstra
Key insight: invariant — [0,lo) = 0s, [lo,mid) = 1s, [mid,hi] = unknown, (hi,n) = 2s. When we swap with hi we don't advance mid because the swapped value is unknown.

Sorting Interview Q&A

Q: When would you choose Merge Sort over Quick Sort in a Java interview?

A: Merge Sort guarantees O(n log n) worst case and is stable (preserves relative order of equal elements). Choose it when: sorting objects where stability matters, sorting linked lists (no random access), external sorting. Quick Sort is better when average-case speed matters and in-place O(log n) stack space is needed.

Q: What does Java's Arrays.sort() use internally?

A: For primitives: Dual-Pivot Quicksort (Vladimir Yaroslavskiy, 2009) — faster than classic quicksort in practice, O(n log n) average. For objects: TimSort (Python's sort) — stable, O(n) best case, O(n log n) worst. It's a hybrid of merge sort and insertion sort, exploiting natural runs in data.

Q: How do you find the Kth largest element in an unsorted array most efficiently?

A: Three approaches: (1) Sort in O(n log n), index at n-k. (2) Min-heap of size k in O(n log k) — always safe. (3) Quick Select in O(n) average — use this when n is large and k is small. In an interview, start with heap solution, then mention Quick Select as an optimization.

Q: Can you sort faster than O(n log n)?

A: Yes — but only for restricted inputs. Comparison-based sorts have an Omega(n log n) lower bound (proof via decision tree). Non-comparison sorts like Counting Sort O(n+k), Radix Sort O(nk), and Bucket Sort O(n) average bypass this by exploiting properties of keys (integers, bounded range).

Implementing Comparable and Comparator

Comparable (natural order)

// Class defines its own natural ordering public class Student implements Comparable<Student> { private String name; private int gpa; @Override public int compareTo(Student other) { // negative = this comes first // 0 = equal, positive = other comes first int cmp = Double.compare( other.gpa, this.gpa); // highest first if (cmp != 0) return cmp; return this.name.compareTo(other.name); } } // Now Arrays.sort(students) works! // TreeSet<Student> also works!

Common Interview Traps

Integer overflow in comparator! Never use a - b for integer comparison — it overflows. Always use Integer.compare(a, b) or a < b ? -1 : a > b ? 1 : 0.
