⚙️ What is Python's function and parameter system — and what is the mutable-default trap?

Python functions are first-class objects. There are four parameter kinds, and order matters: positional, *args (extra positionals → tuple), keyword-only (after *), and **kwargs (extra keywords → dict). The famous trap: default arguments evaluate once at definition, so def f(items=[]) shares one list across all calls — fix with items=None then build inside. Name lookup follows LEGB (Local → Enclosing → Global → Built-in), and closures let inner functions capture enclosing variables.

  • Four parameter kinds — positional, *args, keyword-only, **kwargs.
  • Mutable defaults are shared — defined once; use a None sentinel + build inside.
  • LEGB resolves names — Local → Enclosing → Global → Built-in.
  • Closures capture enclosing scope — inner functions remember outer variables.

Parameter types

# All four kinds of parameters: def api_call( url, # positional method='GET', # positional with default *args, # extra positionals → tuple timeout=30, # keyword-only (after *args) **kwargs # extra keywords → dict ): pass # / forces positional-only before it: def f(a, b, /, c): # a, b = positional-only pass # c can be positional or keyword # Valid calls: api_call('https://api.example.com') api_call('https://...', 'POST', timeout=10) api_call('https://...', headers={'X': 'Y'}) # headers ends up in **kwargs

Mutable default trap

# ❌ THE FAMOUS BUG: def add_role(user, roles=[]): roles.append(user['role']) return roles # Default [] created ONCE at function definition add_role({'role': 'ADMIN'}) # ['ADMIN'] ← ok add_role({'role': 'READER'}) # ['ADMIN', 'READER'] ← BUG! # Both calls share the SAME list object! # ✓ FIX: use None as sentinel def add_role(user, roles=None): if roles is None: roles = [] # new list each call roles.append(user['role']) return roles # Same trap exists for dicts and other mutables: def f(cache={}): ... # ← shared dict, BUG def f(options=[]): ... # ← shared list, BUG

1. The four kinds of parameters — and the / and * markers

A function signature can mix all of these. The order is fixed: positional-only, then normal, then *args, then keyword-only, then **kwargs.

# pos_only / normal *args kw_only **kwargs
def f(a, b, /, c, d, *args, e, f=0, **kwargs):
    pass

# a, b : positional-ONLY  — must be passed by position (the / enforces it)
# c, d : normal           — by position OR keyword
# *args: extra positionals collected into a tuple
# e    : keyword-ONLY     — after *, must be passed by name
# f    : keyword-only with a default
# **kwargs: extra keywords collected into a dict

Calling it

f(1, 2, 3, 4, 5, 6, e=7, x=8)
# a=1 b=2 c=3 d=4
# args=(5, 6)   ← extra positionals
# e=7  f=0      ← e by keyword, f default
# kwargs={'x': 8} ← extra keyword

Unpacking at the call site

nums = [1, 2, 3]
opts = {'e': 7}
f(*nums, 4, **opts)
# * spreads a list into positionals
# ** spreads a dict into keywords
# the SAME * / ** symbols, mirror image

2. LEGB — how a name is resolved

When you read a variable, Python searches four scopes in order and stops at the first hit.

L
Local
this function's body
E
Enclosing
any outer function
G
Global
the module
B
Built-in
len, print, range…
x = "global"

def outer():
    x = "enclosing"
    def inner():
        # reads x → not Local, found in Enclosing
        print(x)        # "enclosing"
    inner()

# To WRITE an outer name, declare intent:
def counter():
    global x        # rebind the module-level x
def make():
    n = 0
    def step():
        nonlocal n     # rebind the enclosing n (a closure)
        n += 1; return n
    return step
Brain Power. Assignment creates a local name by default. So n += 1 inside a nested function without nonlocal raises UnboundLocalError — Python sees the assignment, marks n local, then you read it before it's set. global/nonlocal are how you say "no, I mean that outer one."

3. Closures — functions that remember

A closure captures variables, not values

def multiplier(factor):
    def mul(x):
        return x * factor   # captures `factor`
    return mul

double = multiplier(2)
triple = multiplier(3)
print(double(10), triple(10))  # 20 30
# each closure keeps its own `factor`

The classic loop-closure surprise

fns = [lambda: i for i in range(3)]
print([f() for f in fns])  # [2, 2, 2] !
# all 3 captured the SAME i (now 2)

# Fix: bind per-iteration via a default arg
fns = [lambda i=i: i for i in range(3)]
print([f() for f in fns])  # [0, 1, 2]

Try both snippets in the Python Playground — the surprise is real, and seeing [2, 2, 2] print is the fastest way to never forget it.

The mutable-default trap (scenario ④): def f(x, acc=[]) creates the list once, when the def runs — not per call. Every call without acc shares that one list, so it "remembers" across calls. The fix is the sentinel pattern: def f(x, acc=None): acc = acc or [].
