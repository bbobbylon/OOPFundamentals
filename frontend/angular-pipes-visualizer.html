Pipes — value in, formatted value out

A pipe takes a value and returns a new one. Use them in templates with the | character (yes, the Unix pipe). Built-ins cover dates, currency, numbers, JSON, and async. Write a custom one in 5 lines.

🧪 What is an Angular pipe? Why use one instead of a method?

A pipe transforms a value for display, right in the template: {{ price | currency }} turns 4999 into "$49.99". You could write a formatPrice() method instead — but Angular would call it on every change-detection cycle, even when nothing changed. A pure pipe only re-runs when its input actually changes, reads cleanly, and chains: date | date:'short' | uppercase.

  • Syntax is value | pipeName:arg1:arg2 — left to right, like a Unix pipe; chain as many stages as you like.
  • Pure (default): recomputes only when the input reference changes — cheap and cached. Impure: recomputes every CD cycle — use sparingly.
  • The async pipe subscribes to an Observable/Promise for you and unsubscribes on destroy — no leaks, no manual subscribe().
  • Pure pipes are ideal for formatting; for filtering/sorting big lists, do it in the component (a pipe there hides real performance cost).
  • Write your own with @Pipe({ name: 'x' }) and a transform(value, …args) method.

Handy built-in pipes

  • date:'short' — format dates
  • currency:'USD' — format money
  • uppercase / lowercase / titlecase
  • async — unwrap an Observable/Promise
  • json — debug-dump any object

Pure vs impure — the key distinction

Pure (default): re-runs only when the input reference changes — fast. Impure: re-runs on every change-detection pass — expensive, use sparingly. The built-in async pipe is impure because it must react to each new emission.

The async pipe in CIAM apps:{{ userService.currentUser$ | async }} subscribes to the user stream automatically and unsubscribes when the component is destroyed — preventing the memory leaks that manual subscribe()/unsubscribe() so often cause.

Chaining pipes — left to right

<!-- read left to right: get value, slice it, then uppercase -->
{{ 'hello world' | slice:0:5 | uppercase }}    // HELLO

<!-- format a number to currency, then take first 4 chars (kinda silly but works) -->
{{ 1234.56 | currency:'USD' | slice:0:5 }}    // $1,23

<!-- date piped to async if the date came from an Observable -->
{{ today$ | async | date:'longDate' }}

Pipes with arguments — the colon syntax

<!-- Pass args after the pipe name with `:` -->

            // €1 234,56  (French locale)

<!-- Args can be expressions or class properties -->
{{ price | currency:userCurrency:'symbol':digits }}

The async pipe — the most important one

Angular's HTTP, router, and forms all expose data as Observables. The async pipe subscribes for you, hands the latest value to the template, and automatically unsubscribes when the component is destroyed. Subscriptions you don't manage are memory leaks. 

// ❌ Manual subscribe — must remember to unsubscribe
export class UserComponent implements OnInit, OnDestroy {
  user: User | null = null;
  private sub?: Subscription;

  ngOnInit() {
    this.sub = this.userService.getCurrent().subscribe(u => this.user = u);
  }
  ngOnDestroy() {
    this.sub?.unsubscribe();   // forget this = memory leak
  }
}
<p>Hi, {{ user?.name }}!</p>

// ✅ Async pipe — Angular handles subscribe/unsubscribe
export class UserComponent {
  user$ = this.userService.getCurrent();
}
<p>Hi, {{ (user$ | async)?.name }}!</p>

Convention: name Observable properties with a $ suffix (users$, currentUser$) so it's obvious at the call site that you need the async pipe.

The "as" trick — don't subscribe twice

<!-- ❌ subscribes TWICE — once for the *ngIf, once for the rendered value -->
<div *ngIf="user$ | async">
  Hi, {{ (user$ | async)?.name }}!
</div>

<!-- ✅ subscribe once, alias as `user` -->
<div *ngIf="user$ | async as user">
  Hi, {{ user.name }}!
</div>

<!-- ✅✅ new control flow makes it even cleaner -->
@if (user$ | async; as user) {
  <p>Hi, {{ user.name }}!</p>
}

Write your own — custom pipe in 5 lines

// truncate.pipe.ts
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'truncate',                       // how you reference it in templates
  standalone: true
})
export class TruncatePipe implements PipeTransform {
  transform(value: string, max = 20, suffix = '…'): string {
    if (!value) return '';
    return value.length > max ? value.slice(0, max) + suffix : value;
  }
}

<!-- usage -->
{{ description | truncate }}                       // default max 20
{{ description | truncate:50 }}                    // custom max
{{ description | truncate:50:' [more]' }}            // custom suffix

That's the whole API: a class with one transform(value, ...args) method. The first argument is what's left of the |, the rest come from :-separated args. Import the pipe in the component's imports: [] (standalone) or declare it in an NgModule.

Pure vs Impure — the performance gotcha

Pipes are pure by default. Angular only re-runs them when the input reference changes — not when an object's internal field changes. This is a feature (fast) and a footgun (you mutate an array, the pipe doesn't update). 

// ❌ Mutating the array — pure pipe doesn't re-run
this.users.push(newUser);              // pipe shows stale list

// ✅ Replace the reference — pure pipe re-runs
this.users = [...this.users, newUser];   // pipe updates

// ⚠️ Impure pipe — runs EVERY change detection cycle
@Pipe({ name: 'myFilter', pure: false })

// Use impure ONLY if you have to. It re-evaluates constantly.
// Common reason: filtering/sorting where you can't easily replace the array.

There's no built-in "filter" or "sort" pipe. Angular intentionally left them out because they encourage impure pipes and bad performance. Do filtering/sorting in your component (or with RxJS), then bind the prepared array.

The keyvalue pipe — iterate objects and Maps

You can't use *ngFor / @for directly on a plain object — only arrays and iterables are supported. The keyvalue pipe converts an object (or Map) into an array of { key, value } pairs that @for can iterate.

Basic object iteration

// component
user = {
  name: 'Alice',
  role: 'admin',
  loginCount: 42,
};

<!-- template -->
@for (entry of user | keyvalue; track entry.key) {
  <tr>
    <td>{{ entry.key }}</td>
    <td>{{ entry.value }}</td>
  </tr>
}
<!-- output: loginCount/42, name/Alice, role/admin
     (sorted alphabetically by key) -->

Custom sort + Map iteration

// preserve insertion order — comparator returns 0
orderByInsert = () => 0;

statusMap = new Map([
  ['pending',   12],
  ['approved',  47],
  ['rejected',   3],
]);

<!-- template -->
@for (e of statusMap
         | keyvalue: orderByInsert; track e.key) {
  <li>{{ e.key }}: {{ e.value }}</li>
}
<!-- pending: 12, approved: 47, rejected: 3 -->

CIAM use case: Displaying a user's custom attributes object (returned by Ping / Entra as arbitrary key/value pairs) without knowing the keys at compile time.

Custom pipes with inject() — DI inside a pipe

Since Angular 14 you can call inject() inside a pipe's constructor-less class body — the same way you would in a component. This unlocks localization pipes that pull the locale from a service, auth pipes that check roles, and any formatting that needs config from a token.

Standalone pipe with inject()

@Pipe({
  name: 'roleLabel',
  standalone: true,
  pure: true,
})
export class RoleLabelPipe implements PipeTransform {
  // inject() works here — no constructor needed
  private i18n = inject(RoleI18nService);

  transform(role: string): string {
    return this.i18n.getLabel(role)
      ?? role; // fallback to raw value
  }
}

Null-safe transform pattern

// Always guard against null/undefined at
// the top of transform() — pipes receive
// the raw binding value, which may be null
// before async data resolves.
transform(value: string | null): string {
  if (value == null) return '—';  // em-dash
  return value.trim().toUpperCase();
}

<!-- usage (standalone — import directly) -->
<td>{{ user.role | roleLabel }}</td>

@Component({
  standalone: true,
  imports: [RoleLabelPipe],  // ← just add it
  template: ...
})

When a pipe beats a method: the same transform used in 5+ different component templates (role labels, masked phone numbers, short-id display) should be a pipe — you import it once per component and chain it like any built-in.

Mental model — when to reach for a pipe

✅ Use a pipe when

Formatting a value for display — currency, date, percent, truncate, uppercase. Anything pure: same input → same output, no side effects.

✅ Use the async pipe always

If something is an Observable in your template, pipe it through async. Don't subscribe manually unless you really need to.

❌ Don't use pipes for

Filtering or sorting big lists (do it in the component). Side effects (HTTP calls, mutations). Anything that depends on state outside its inputs.

🎯 Custom pipe checklist

  • Is it pure?
  • Is the transform fast?
  • Would 3+ components use it?
  • Yes → pipe. No → method on the component.

🌱 New to pipes? They reshape a value for display, right in the template.

A pipe formats a value for the screen using the | symbol — without changing your actual data. You've seen them: {{ price | currency }} → "$9.99", {{ today | date:'short' }}, {{ name | uppercase }}. The bit after a colon is an argument (date:'short'), and you can chain them left-to-right: {{ name | lowercase | titlecase }}. Think of | as "send this value through a little formatter on its way to the screen." That's the whole idea — display formatting, declared inline, with your underlying data untouched.

🧠 Expert corner — pure vs impure, async, and when NOT to use a method

  • Pure is the default — and the reason pipes are fast. A pure pipe's transform() only re-runs when its input reference changes, so the result is effectively memoized across change-detection cycles.
  • Impure pipes run every CD cycle (pure: false) — powerful but costly; reserve them for genuinely live data. The built-in async pipe is impure by necessity.
  • The async pipe is a leak-proof subscription. obs$ | async subscribes for you and unsubscribes when the component is destroyed — no manual ngOnDestroy cleanup. It renders the latest emitted value (and works with Promises too).
  • Prefer a pipe over a method call in templates. {{ format(x) }} re-runs on every CD pass; {{ x | format }} (pure) runs only when x changes. Big perf difference on busy views.
  • Locale-aware built-ins. date/currency/number use the Intl APIs and your registered locale data — register it (registerLocaleData) or non-USD/ISO formats break.
  • Write your own with @Pipe({name:'mask'}) + a transform(value, ...args) method. CIAM tie-in: a | date on token exp, or a custom | mask that shows only the last 4 of an account number.
