Regression & Classification

Linear & logistic regression, decision trees, and random forests — the workhorse supervised-learning algorithms, all sharing the same .fit() / .predict() scikit-learn interface.

📈 What are these algorithms actually doing?

Regression predicts a continuous number (a price, a temperature); classification predicts a category (churn / no-churn, spam / not-spam). Linear regression fits a straight line (or hyperplane) that minimizes squared error. Logistic regression — despite the name — is a classifier: it fits that same kind of linear combination, then squashes it through a sigmoid into a 0–1 probability. Decision trees take a completely different approach: they recursively carve the data into purer and purer buckets by asking yes/no questions about features. Random forests train many trees on randomized slices of the data and average their votes — a single tree overfits easily, but the errors of many independently-randomized trees mostly cancel out. All four expose the identical scikit-learn API: model.fit(X_train, y_train) then model.predict(X_test) — swapping the algorithm is close to a one-line change; what actually differs is the shape of the decision boundary each one can draw.

  • Linear regression — continuous output, minimizes sum of squared residuals (OLS).
  • Logistic regression — classification via sigmoid(linear score) → probability → threshold.
  • Decision trees — recursive splits that maximize Gini impurity reduction; interpretable, prone to overfitting.
  • Random forests — bagging + random feature subsets decorrelate trees; ensemble vote beats any single tree.

Linear vs logistic regression

from sklearn.linear_model import LinearRegression, LogisticRegression # Regression: predicts a number lin = LinearRegression() lin.fit(X_train, y_train) # y = continuous (price) lin.predict([[1800]]) # [231000.0] # Classification: predicts a class log = LogisticRegression() log.fit(X_train, y_train) # y = 0/1 (churn) log.predict([[52000, 29]]) # [1] log.predict_proba([[52000, 29]]) # [[0.267, 0.733]]

Decision tree — the readable if/else

from sklearn.tree import DecisionTreeClassifier, export_text tree = DecisionTreeClassifier(max_depth=3) tree.fit(X_train, y_train) print(export_text(tree)) # |--- feature_1 <= 3.00 # | |--- class: A # |--- feature_1 > 3.00 # | |--- feature_0 <= 5.00 # | | |--- class: B # Unbounded depth → one leaf per training # point → memorizes noise → overfits

Random forest — many weak, decorrelated trees

from sklearn.ensemble import RandomForestClassifier forest = RandomForestClassifier( n_estimators=100, # 100 trees max_features='sqrt' # random feature subset per split ) forest.fit(X_train, y_train) forest.predict([[52000, 29]]) # majority vote of 100 trees # Each tree: different bootstrap sample # + different feature subset per split # → uncorrelated errors → averaging wins

CIAM angle: Risk-based / adaptive authentication engines (see ping-ciam-patterns-deep-visualizer.html) score every login attempt with exactly this kind of model — logistic regression or a gradient-boosted tree ensemble takes features like device fingerprint novelty, IP reputation, time-of-day, and impossible-travel distance, and outputs a fraud probability that decides step-up MFA vs silent allow. The "decision boundary" a login-risk model draws is the same shape as the churn boundary a logistic regression draws here.

1. Linear & Logistic Regression

Both fit a linear combination of features, z = b0 + b1*x1 + ... + bn*xn. Linear regression stops there — z IS the prediction. Logistic regression squashes z through the sigmoid function into a 0–1 probability.

Features
x1, x2, ... xn
Linear combo
z = b0 + b1x1 + ...
Linear reg.
prediction = z (a number)
Logistic reg.
p = sigmoid(z), 0..1
Threshold
p >= 0.5 → class 1
# Ordinary Least Squares (OLS): minimize sum((y_true - y_pred)^2)
price = 15000 + 120 * sqft   # fitted coefficients
predict(1800) # = 15000 + 120*1800 = 231000

# Logistic regression: sigmoid squashes any real number into (0, 1)
z = -2.0 + 0.00003*income + 0.05*age
p = 1 / (1 + exp(-z))  # sigmoid(1.01) ≈ 0.733
predict = 1 if p >= 0.5 else 0
Logistic regression is NOT trained by minimizing squared error — squared error against a probability isn't well-behaved for optimization. It's trained by maximum likelihood (minimizing log-loss / cross-entropy), which correctly penalizes confident-and-wrong predictions much harder than uncertain ones.

2. Decision Trees — Splitting by Gini Impurity

A tree picks, at every node, the feature/threshold split that most reduces Gini impurity — a measure of how mixed the classes are in a bucket. Pure buckets (all one class) have Gini = 0.

Root (10 samples)6 class A, 4 class BGini = 1 − (0.6² + 0.4²) = 0.48
Split A: feature X≤5left 4A/1B, right 2A/3Bweighted Gini = 0.40 (reduction 0.08)
Split B: feature Y≤3left 5A/0B (pure!), right 1A/4Bweighted Gini = 0.16 (reduction 0.32)
WinnerSplit B reduces impurity 4× more than Split Atree picks Split B
from sklearn.tree import DecisionTreeClassifier
tree = DecisionTreeClassifier(criterion='gini', max_depth=3)
tree.fit(X_train, y_train)
# Every node picks argmax(impurity_before - weighted_impurity_after)
# across every candidate feature/threshold split
An unbounded tree can keep splitting until every leaf has exactly one training point — Gini = 0 everywhere, 100% training accuracy, and terrible generalization. max_depth, min_samples_leaf, and pruning exist specifically to stop this.

3. Random Forests — Averaging Away the Overfitting

A forest trains many trees, each on a random bootstrap sample (rows drawn with replacement) AND a random subset of features at each split. Individual trees still overfit their own sample — but their mistakes are largely uncorrelated, so the majority vote cancels most of the noise out.

Tree 1bootstrap sample #1 → predicts A
Tree 2bootstrap sample #2 → predicts B (wrong)
Tree 3bootstrap sample #3 → predicts A
Vote: A2 of 3 trees agree → forest is correct
from sklearn.ensemble import RandomForestClassifier
forest = RandomForestClassifier(n_estimators=100, max_features='sqrt')
forest.fit(X_train, y_train)
# Same .fit()/.predict() API as every model above —
# only the internal algorithm and its bias/variance tradeoff differ
Bagging (bootstrap + aggregating) trades a little bias for a large reduction in variance. Individual deep trees have low bias, high variance (overfit); averaging many decorrelated high-variance trees keeps the low bias while crushing the variance — this is why random forests are a strong, low-effort default before reaching for anything fancier.
