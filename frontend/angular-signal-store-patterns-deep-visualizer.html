NgRx SignalStore — Patterns

SignalStore is NgRx reimagined for the signals era: a state container you compose from functional features instead of reducers and actions. withState, withComputed, withMethods, withHooks — stack them up and you get a fully-typed, signal-based store. Drive a live one below.

1. The whole idea: a store is a pipeline of features

No actions, no reducers, no dispatch. You call signalStore(...) with a list of features; each one adds state, derived signals, or methods, and can see everything the features before it added.

export const CartStore = signalStore(
  { providedIn: 'root' },
  withState({ items: [] as Item[], discount: 0 }),   // ① raw state → signals
  withComputed((store) => ({                            // ② derived signals
    count: computed(() => store.items().length),
    total: computed(() => sum(store.items()) * (1 - store.discount())),
  })),
  withMethods((store) => ({                             // ③ behavior
    add(p: Product) { patchState(store, { items: [...store.items(), toItem(p)] }); },
    clear()        { patchState(store, { items: [] }); },
  })),
  withHooks({ onInit(store) { /* load, log, effects */ } }), // ④ lifecycle
);
①withState — turns a plain object into a set of state signals.
②withComputed — adds memoized derived signals from existing ones.
③withMethods — adds functions that update state via patchState (or run async).
④withHooks — onInit / onDestroy lifecycle for the store.

3. patchState — the only way state changes

Two shapes: partial object or updater fn

// ① merge a partial object:
patchState(store, { discount: 0.1 });

// ② updater function (sees current state):
patchState(store, (s) => ({
  items: [...s.items, newItem],
}));

// ③ compose multiple updaters:
patchState(store, addItem(p), recalcTax());

Always immutable — return new arrays/objects, never mutate s.items.push(...). Signals compare by reference, just like OnPush.

Reads are just signals

// in a component:
readonly store = inject(CartStore);

// template — call them like any signal:
// {{ store.count() }} items, total {{ store.total() }}

// derive further locally:
readonly isEmpty = computed(() => this.store.count() === 0);

State and computed are exposed as read-only signals. The only way to change them is through the store's methods → patchState. Encapsulation for free.

4. Async with rxMethod, collections with withEntities

rxMethod — RxJS-powered methods

withMethods((store, api = inject(Api)) => ({
  load: rxMethod<string>(pipe(
    debounceTime(300),
    switchMap((q) => api.search(q).pipe(
      tapResponse({
        next: (r) => patchState(store, { results: r }),
        error: console.error,
      }))),
  )),
}))
// call it with a value OR a signal/observable:
// store.load(querySignal);  // auto-reacts to changes

Best of both worlds: signals for state, RxJS operators (debounce, switchMap, retry) for the async flow — see Signals ↔ RxJS Interop.

withEntities — normalized collections

withEntities<Todo>(),
withMethods((store) => ({
  addTodo(t: Todo) { patchState(store, addEntity(t)); },
  toggle(id: string) {
    patchState(store, updateEntity({ id, changes: t => ({ done: !t.done }) }));
  },
}))
// free signals: store.entities(), store.entityMap(), store.ids()

Gives you a normalized { ids, entityMap } store plus addEntity/updateEntity/removeEntity updaters — the redux "entity adapter," signal-style.

5. Custom features — package & reuse a pattern

Because features are just functions, you can write your own with signalStoreFeature and drop it into any store — e.g. a reusable loading flag or a logger:

export function withLoading() {
  return signalStoreFeature(
    withState({ loading: false }),
    withMethods((store) => ({
      setLoading(v: boolean) { patchState(store, { loading: v }); },
    })),
  );
}
// reuse everywhere:
const UsersStore = signalStore(withLoading(), withState(...), ...);

This composition is the SignalStore superpower: cross-cutting concerns become small, typed, shareable features instead of copy-pasted boilerplate.

6. When to use which

NeedReach for
A few local signals in one componentplain signal() / computed() — no library
Shared, encapsulated feature state (cart, auth, filters)SignalStore (providedIn:'root' or component-provided)
Per-component instance state with lifecycleSignalStore provided in the component (not root)
Large app, time-travel devtools, strict event logclassic NgRx Store (actions/reducers/effects)

SignalStore is the sweet spot for most feature state — far less ceremony than the Redux-style Store, more structure and encapsulation than scattered signals.

7. One-sentence recap

🧩 A SignalStore is composed from functional features — withState (state signals), withComputed (derived signals), withMethods (behavior via patchState), withHooks (lifecycle) — exposing everything as read-only signals; add rxMethod for async, withEntities for collections, and your own signalStoreFeature for reusable patterns — all fully typed, no actions or reducers.
