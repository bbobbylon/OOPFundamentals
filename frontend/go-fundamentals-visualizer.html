Go Fundamentals

Value types vs reference types, slices (the three-word header), maps, pointers, and the zero value system — Go's core memory model.

What is Go — and how does its memory model differ from Java and Python?

Go (often called Golang) is a compiled, statically typed, garbage-collected language created at Google in 2007. It was designed for systems programming and cloud infrastructure — fast compilation, excellent concurrency support, minimal runtime overhead. Go compiles to a single native binary (no JVM, no interpreter), starts in milliseconds, and has a predictable performance profile. Value vs reference types: in Go, basic types (int, float64, bool, string, structs, arrays) are value types — assigned/passed by copying the entire value. Changing a copy doesn't affect the original. Slices, maps, channels, and pointers are reference types — they contain a pointer to underlying data. Zero values: in Go, every variable has a zero value — 0 for numbers, false for booleans, "" for strings, nil for pointers/slices/maps/channels/interfaces. You never have uninitialized memory. Slice (the three-word header): a slice is a struct with three fields: a pointer to an underlying array, a length (number of elements), and a capacity (total space in the array). When you append beyond capacity, Go allocates a new, larger array and copies — this is why appending to a nil slice works (var s []int; s = append(s, 1)). Pointers: Go has pointers (*T) but no pointer arithmetic. &x gives the address of x; *p dereferences. Go's garbage collector manages memory — no manual malloc/free. Maps: built-in hash map. The zero value of a map is nil — reads return zero values but writes panic. Always initialize: m := make(map[string]int).

Value types vs slices

// Value type: struct copied on assignment type User struct { ID int Name string } a := User{ID: 1, Name: "Bobby"} b := a // b is a COPY b.Name = "Alice" fmt.Println(a.Name) // "Bobby" — a unchanged // Slice: three-word header (ptr, len, cap) s1 := []int{1, 2, 3} // len=3, cap=3 s2 := s1 // shares same array! s2[0] = 99 fmt.Println(s1[0]) // 99 — s1 also changed // Append may allocate new array: s3 := append(s1, 4, 5) // cap exceeded → new array s3[0] = 0 fmt.Println(s1[0]) // 99 — s1 NOT changed (different array)

Zero values + maps

// Zero values — always initialized var n int // 0 var s string // "" var b bool // false var p *User // nil var sl []string // nil (but appendable!) // Comma-ok idiom for map reads: roles := map[string][]string{ "alice@eg.com": {"CIAM_ADMIN"}, } r, ok := roles["bob@eg.com"] // ok = false, r = nil (zero value for []string) // Without ok check: r2 := roles["bob@eg.com"] // nil — safe to range over // Write to nil map = PANIC: var m map[string]int m["key"] = 1 // panic: assignment to nil map // Fix: m := make(map[string]int)

Go vs Java/Spring

Go concept → Java/Spring equivalent. type User struct {} → record User() {} / POJO class. Go has no classes, only structs + methods. Methods are attached outside the struct: func (u User) FullName() string {}. No inheritance — composition via embedding: type Admin struct { User; CanDelete bool }. No exceptions — multiple return values for error: user, err := db.Find(id). No generics until Go 1.18 (Java has had them since 2004). Go builds a single binary — no JVM, no classpath. Deploy to containers: FROM scratch; COPY app /app — 10MB image vs 500MB+ for Spring Boot. Fast startup: <5ms vs Spring Boot's 5-15 seconds. Used heavily in infrastructure tooling: Kubernetes, Docker, Prometheus, Terraform — all written in Go.

Go in CIAM context: Go is the language Kubernetes, Docker, Prometheus, and many cloud-native tools are written in — all critical to CIAM infrastructure. Understanding Go helps you: read Kubernetes operators (custom resources for CIAM namespace management), write CLI tools (Go binaries deploy anywhere, no runtime dependencies), build high-throughput services (Go's goroutines handle 10k concurrent connections with minimal memory — better than Spring Boot's thread-per-request model for pure proxy/gateway scenarios). Your CIAM auth flows that use Spring Boot could use Go for the sidecar/gateway: Envoy proxy plugins, token validation sidecars, OAuth callback handlers. Go's fast binary startup makes it ideal for AWS Lambda — no JVM cold start penalty.

1. Value vs Reference Types

Value types (copied on assignment)Reference types (header copied, data shared)
int, float64, bool, string, array, structslice, map, channel, pointer, function
a := 42; b := a; b = 99 — a is still 42a := []int{1,2}; b := a; b[0] = 99 — a[0] is also 99
Strings are value types but immutable and reference-counted under the hood. Assigning a string copies the string header (pointer + length) — the bytes are not copied. Go's optimizer handles this safely because strings are immutable.

2. The Slice Three-Word Header

// make allocates backing array and slice header
s := make([]int, 3, 5)
// Header: { ptr:0x1000, len:3, cap:5 }
// Backing: [0, 0, 0, _, _] (_ = cap)

s = append(s, 4) // len→4, same backing array
s = append(s, 5) // len→5, same backing array (cap=5)
s = append(s, 6) // len→6, cap exceeded → NEW array!
// new cap ≈ 2× old → { ptr:0x2000, len:6, cap:10 }
// GOTCHA: append does not modify caller's slice
func addItem(s []int, v int) {
  s = append(s, v) // s is a local copy!
} // caller's slice unchanged

// FIX: return the new slice
func addItem(s []int, v int) []int {
  return append(s, v)
}
items = addItem(items, 42) // ✅

3. Zero Values — Go Defaults Everything

var i int // 0
var f float64 // 0.0
var b bool // false
var s string // "" (empty string)
var p *int // nil
var sl []int // nil (len=0, cap=0)
var m map[string]int // nil (READ ok, WRITE panic!)

Go zero-initializes every variable — there is no undefined or garbage memory. This eliminates an entire class of bugs. A nil slice is valid to read (len=0, range over it is fine) but a nil map PANICS on write — always initialize maps with make(map[K]V) before writing.
