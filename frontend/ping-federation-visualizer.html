1 — Federation Core Concepts

Identity Provider (IdP)

The authority on who the user is
The system that authenticates the user and asserts their identity. Your company's PingFederate server is the IdP.

The IdP holds the user directory (or connects to one via LDAP/AD). When authentication succeeds, it issues a token or assertion proving who the user is.

Service Provider (SP)

The application consuming the assertion
The application the user wants to access. The SP trusts the IdP to vouch for users rather than maintaining its own username/password store.

In practice: your Spring Boot API or a SaaS app like Salesforce, ServiceNow, or Workday can all be SPs trusting the same corporate IdP.

SAML 2.0

XML-based enterprise SSO standard
Security Assertion Markup Language. The dominant enterprise SSO protocol for B2B federation. PingFederate excels at SAML.

A SAML assertion is a signed XML document containing: who the user is, when they authenticated, and their attributes (email, roles, department).

Used for: corporate SSO to SaaS apps, inter-company federation ("log in with your company account").

OIDC / OAuth2

Modern web & API auth standard
OpenID Connect (OIDC) sits on top of OAuth2. PingFederate also acts as an OAuth2 Authorization Server / OIDC Provider for modern apps.

Produces JWT tokens instead of XML assertions. Used for: Angular SPAs, mobile apps, API-to-API auth (Client Credentials).

Connection (SP Connection)

PingFederate's trust configuration
In PingFederate admin, an SP Connection defines the trust relationship between PingFederate (as IdP) and a specific Service Provider.

You configure: the SP's entity ID, ACS URL (where assertions are sent), signing certificates, attribute contract (which user attributes to include), and authentication policy.

Attribute Contract

What user data is sent in the assertion
Defines which user attributes PingFederate includes in the SAML assertion or OIDC token sent to the SP.

Common attributes: email, displayName, memberOf (AD groups), employeeId, department.

The SP uses these to set up the user's session and apply authorization rules.
