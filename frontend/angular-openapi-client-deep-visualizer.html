OpenAPI → Typed Angular Client

Hand-writing TypeScript interfaces to match your Spring DTOs is a slow leak: the backend changes a field, the frontend's interface doesn't, and the mismatch surfaces as a runtime undefined in production. Generate the client from the OpenAPI spec the backend already publishes, and the contract has one source of truth — drift turns into a compile error you catch before you commit.

1. The model-drift leak

Two hand-maintained copies of the same shape always drift apart:

Hand-written (drifts)

// Spring renamed name → fullName.
// Nobody told this interface.
interface User { id: number; name: string; }
// user.name → undefined at runtime 💥

Generated (can't drift)

// regenerated from /v3/api-docs
interface User { id: number; fullName: string; }
// old usages now fail to COMPILE ✓

3. The toolchain

StageToolOutput
Backend publishes the specspringdoc-openapi/v3/api-docs (OpenAPI 3 JSON) + Swagger UI
Generate the clientopenapi-generatortypescript-angular models + HttpClient services
…lighter alternativesng-openapi-gen / orvalAngular-flavoured clients; orval can emit TanStack Query hooks
 
// package.json — regenerate from the running backend (or a checked-in spec)
"scripts": {
  "gen:api": "openapi-generator-cli generate -i http://localhost:8081/v3/api-docs -g typescript-angular -o src/app/api"
}

Treat src/app/api as build output: never hand-edit it, and add it to review as "generated". Re-run npm run gen:api whenever the backend contract changes.

4. What you actually import

// generated — a typed service, injectable like any other
export class UsersService {
  getUsers(): Observable<User[]> { … }          // GET /api/users
  createUser(body: NewUser): Observable<User> { … } // POST /api/users
}

// your component — fully typed, no hand-written interfaces
private users = inject(UsersService);
readonly list = toSignal(this.users.getUsers());   // Signal<User[] | undefined>

Method names, path/query params, request bodies, response types and enums all come from the spec. Rename a field on the server, regenerate, and every stale reference lights up red in your editor.

↪ Where the spec comes from: Spring · OpenAPI / Swagger. How the JSON maps to types: Spring · JSON Serialization.

5. Gotchas worth configuring

  • Dates are strings. JSON has no date type — Instant/LocalDate generate as string. Parse at the edge (or configure a date type mapping); don't pretend it's a Date.
  • Required vs nullable. The generator trusts the spec — annotate DTOs (@Schema(requiredMode=...), validation) so optional fields become field?: T and you get honest null-safety.
  • Enums. Keep server enum names stable; they become TS string-literal unions that your code switches on.
  • Regenerate in CI. Run gen:api + tsc --noEmit in the pipeline so a backend contract change fails the build rather than shipping drift.
  • Pin versions. Lock the generator version (and ideally the spec) so client output is reproducible across machines.

6. One-sentence recap

🧬 Let Spring publish its contract via springdoc (/v3/api-docs), generate the Angular client from it with openapi-generator (or ng-openapi-gen/orval) into a never-hand-edited src/app/api, and import the typed services + models — now a backend field rename or type change ripples into a compile error at the call site instead of a production undefined, as long as you regenerate (ideally in CI) and configure dates/nullability/enums honestly.
