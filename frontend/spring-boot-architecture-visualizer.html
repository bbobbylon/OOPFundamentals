Spring Boot Architecture

How Spring Boot starts up, wires your beans, and configures itself from the classpath.

🌱 What is Spring Boot? What does it actually do when you run it?

Spring Boot is a framework for building Java apps — most commonly REST APIs. It wraps the older, more verbose Spring Framework and adds auto-configuration: instead of dozens of XML files or @Bean factory methods, it inspects what's on the classpath (the libraries in your pom.xml) and wires sensible defaults for you. Running the app kicks off a startup sequence — scan packages for @Component/@Service/@Repository/@Controller, apply auto-config, build the ApplicationContext (the bean container), start an embedded Tomcat, and begin serving — all in seconds.

  • Convention over configuration. Classpath presence drives defaults; you override only what you need.
  • Component scanning finds your beans by their stereotype annotations and registers them in the context.
  • The server is embedded. Tomcat (or Netty for reactive) ships inside the jar — java -jar just runs.
  • The ApplicationContext is the runtime — it holds every bean and resolves the dependency graph.

Startup sequence

1. JVM loads your classes. 2. Spring scans for @Component beans. 3. Auto-configuration applies. 4. ApplicationContext (IoC container) is created. 5. Embedded Tomcat starts on port 8080.

What auto-config does

Add spring-security → a security filter chain is set up automatically. Add spring-data-jpa + a driver → a datasource + EntityManager appear. You override these defaults only when you actually need to.

CIAM backend: Your API boots with Tomcat (or Netty), Spring Security auto-configured, a JPA datasource on your database, and your @RestController endpoints registered. The Angular frontend calls them with Bearer tokens that Spring Security validates.

1 — Startup Sequence

Click Start App to watch Spring Boot's startup sequence unfold phase by phase.

1

JVM Launches

The JVM loads OopFundamentalsApplication.class and calls main(). SpringApplication.run() begins the startup process.

2

Application Context Created

Spring creates a AnnotationConfigServletWebServerApplicationContext — the bean container that will hold every object in your app.

3

Component Scan

Spring scans your package for classes annotated with @Component, @Service, @Repository, @Controller, and @Configuration and registers them as beans.

4

Auto-Configuration

Spring Boot scans the classpath. Found spring-web? Configure DispatcherServlet. Found spring-data-jpa? Configure EntityManager. Found H2? Configure an in-memory DataSource. No manual XML required.

5

Beans Wired (Dependency Injection)

Spring injects dependencies into every bean. UserController gets its UserService; UserService gets its UserRepository. All wired automatically.

6

Embedded Server Starts

An embedded Tomcat (or Netty for WebFlux) starts on port 8080. No WAR deployment, no external server needed. Your JAR is fully self-contained.

7

✅ App Ready

Console prints: Started OopFundamentalsApplication in 2.3 seconds. Requests can now be handled.

2 — @SpringBootApplication Breakdown

@SpringBootApplication is a convenience annotation that combines three annotations. Click each to see what it does.

@SpringBootApplication
Shorthand for: @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan.
Put this on your main class — the one with public static void main().
@SpringBootConfiguration
Marks this class as a configuration source (like @Configuration). Spring Boot can use it to define additional @Bean methods. Usually you just inherit this via @SpringBootApplication.
@EnableAutoConfiguration
Tells Spring Boot to automatically configure your app based on what's on the classpath. This is the "magic" — it reads spring.factories / AutoConfiguration.imports files inside every starter JAR and activates relevant configurations conditionally.
@ComponentScan
Scans the package of the annotated class (and all sub-packages) for Spring-managed beans: @Component, @Service, @Repository, @Controller, @RestController, and any custom stereotype annotations. Tip: put your main class at the top-level package so it scans everything.
@SpringBootApplication
public class OopFundamentalsApplication {
  public static void main(String[] args) {
    SpringApplication.run(OopFundamentalsApplication.class, args);
  }
}

🌱 New to Spring Boot? It's "Spring with the wiring already done."

Plain Spring made you configure everything by hand. Spring Boot looks at what libraries are on your classpath and auto-configures sensible defaults — an embedded web server, JSON handling, a database connection — so a running web app is one main() away. The idea you'll meet over and over: you write plain classes and annotate them (@RestController, @Service, @Repository), and Spring creates and connects them for you in a "container." You write the logic; the framework does the plumbing. That's why a tiny Boot app does so much with so little code.

🧠 Expert corner — layers, the container, and the auto-config magic

  • The standard shape is layered: @RestController (HTTP) → @Service (business logic + @Transactional) → @Repository (data). Keep controllers thin and rules in the service.
  • @SpringBootApplication is three annotations — @Configuration + @EnableAutoConfiguration + @ComponentScan. Component-scan finds your beans; auto-config supplies the framework ones.
  • Auto-configuration is conditional. Starters (spring-boot-starter-web, …) put libraries on the classpath; auto-config classes use @ConditionalOnClass/@ConditionalOnMissingBean to wire defaults you can always override. (See Auto-Configuration Magic.)
  • The IoC container owns object creation. Beans are wired by dependency injection — you ask for collaborators in the constructor, Spring provides them.
  • Config is externalized via application.yml + profiles, and ops via Actuator — so the same jar runs in dev and prod.
  • CIAM tie-in. Adding spring-boot-starter-oauth2-resource-server + an issuer-uri auto-configures JWT validation — no manual filter wiring. See Security.
