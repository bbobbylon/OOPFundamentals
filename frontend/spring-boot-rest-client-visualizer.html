REST Client

Your Spring Boot service often needs to call other services or external APIs. Spring provides three clients — choose RestClient (Spring 6.1+) for synchronous calls and WebClient for reactive/non-blocking workloads.

1 — Choosing a Client

RestClient

Fluent synchronous HTTP client — the modern replacement for RestTemplate
Spring 6.1 / Boot 3.2+

WebClient

Reactive, non-blocking HTTP client — part of Spring WebFlux
Spring 5+ / Reactor

RestTemplate

The original synchronous HTTP client — now in maintenance mode
Legacy — prefer RestClient

2 — RestClient — Modern Synchronous HTTP

RestClient has a fluent, readable API. Create it as a singleton @Bean and inject it where needed:

// Configuration — create a configured RestClient @Bean @Configuration public class HttpConfig { @Bean public RestClient productApiClient() { return RestClient.builder() .baseUrl("https://api.example.com") .defaultHeader("Accept", "application/json") .defaultHeader("X-API-Key", apiKey) .requestInterceptor(loggingInterceptor) .build(); } } // Usage — GET with automatic JSON deserialization Product product = restClient .get() .uri("/products/{id}", productId) .retrieve() .body(Product.class); // GET list (use ParameterizedTypeReference for generics) List<Product> products = restClient .get() .uri("/products?category={cat}", "electronics") .retrieve() .body(new ParameterizedTypeReference<List<Product>>() {}); // POST with request body Product created = restClient .post() .uri("/products") .contentType(MediaType.APPLICATION_JSON) .body(newProduct) .retrieve() .body(Product.class); // DELETE (no response body needed) restClient .delete() .uri("/products/{id}", productId) .retrieve() .toBodilessEntity();

3 — Error Handling

By default, RestClient throws HttpClientErrorException (4xx) or HttpServerErrorException (5xx). Handle them centrally:

// Option 1: onStatus — handle specific status codes fluently Product product = restClient .get() .uri("/products/{id}", id) .retrieve() .onStatus(HttpStatusCode::is4xxClientError, (req, res) -> { if (res.getStatusCode() == HttpStatus.NOT_FOUND) { throw new ResourceNotFoundException("Product " + id + " not found"); } throw new BadRequestException("Bad request: " + res.getStatusCode()); }) .onStatus(HttpStatusCode::is5xxServerError, (req, res) -> { throw new ExternalServiceException("Product API unavailable"); }) .body(Product.class); // Option 2: exchange — full access to response (status + body + headers) ResponseEntity<String> raw = restClient .get() .uri("/products/{id}", id) .exchange((req, res) -> { if (res.getStatusCode().is2xxSuccessful()) { return ResponseEntity.ok(res.bodyTo(String.class)); } log.warn("Unexpected status: {}", res.getStatusCode()); return ResponseEntity.status(res.getStatusCode()).build(); });

4 — WebClient — Reactive Non-Blocking HTTP

Use WebClient when your service is reactive (Spring WebFlux) or when you need to fan out many parallel HTTP calls efficiently. Add spring-boot-starter-webflux:

@Bean public WebClient webClient(WebClient.Builder builder) { return builder .baseUrl("https://api.example.com") .defaultHeader("Accept", "application/json") .codecs(c -> c.defaultCodecs().maxInMemorySize(2 * 1024 * 1024)) .build(); } // Reactive GET — returns Mono (0 or 1 result) Mono<Product> product = webClient .get() .uri("/products/{id}", id) .retrieve() .bodyToMono(Product.class); // Fan out 3 calls in parallel — total time = max(t1,t2,t3) Mono<Triple<Product,Stock,Price>> combined = Mono.zip( webClient.get().uri("/products/{id}", id).retrieve().bodyToMono(Product.class), webClient.get().uri("/stock/{id}", id).retrieve().bodyToMono(Stock.class), webClient.get().uri("/pricing/{id}", id).retrieve().bodyToMono(Price.class), (Triple::of) ); // Block to get the result in a non-reactive (MVC) context — use carefully Product p = webClient.get().uri("/products/{id}", id) .retrieve().bodyToMono(Product.class) .block(); // do NOT call .block() inside a reactive pipeline

5 — Timeout & Retry

RestClient — timeout via HttpClient
HttpClient httpClient = HttpClient.create() .responseTimeout(Duration.ofSeconds(5)) .option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 3000); RestClient client = RestClient.builder() .requestFactory(new ReactorClientHttpRequestFactory(httpClient)) .build(); // Or with JDK HttpClient var jdk = HttpClient.newBuilder() .connectTimeout(Duration.ofSeconds(3)) .build(); RestClient client = RestClient.builder() .requestFactory(new JdkClientHttpRequestFactory(jdk)) .build();
WebClient — retry with Reactor
webClient.get() .uri("/products/{id}", id) .retrieve() .bodyToMono(Product.class) .timeout(Duration.ofSeconds(5)) .retryWhen(Retry.backoff(3, Duration.ofMillis(500)) .filter(ex -> ex instanceof WebClientResponseException && ((WebClientResponseException)ex).getStatusCode() .is5xxServerError()) ) .doOnError(ex -> log.error("Failed after retries", ex));
Using Spring Retry with RestClient (@EnableRetry)
@Retryable(retryFor = HttpServerErrorException.class, maxAttempts = 3, backoff = @Backoff(delay = 500, multiplier = 2)) public Product fetchProduct(Long id) { return restClient.get().uri("/products/{id}", id).retrieve().body(Product.class); } @Recover public Product fallback(HttpServerErrorException ex, Long id) { log.error("Product API down after retries — returning cached fallback for {}", id); return cacheService.getCachedProduct(id); }
