What just happened? The three jobs of tsc

A TypeScript "build" is really three separate jobs. This playground does all three and shows you each one in its own tab.

1 · Parse & bind

The compiler reads your text into a syntax tree and figures out what every name refers to. Pure syntax mistakes (a missing )) are caught here.

2 · Type-check

It infers a type for every expression and verifies the rules — this is the Type errors tab. Crucially, type-checking only reports; it never changes the emitted code.

3 · Emit

It erases all the types and downlevels syntax to your target — that's the Emitted JS tab. This is the only part that produces something a browser/Node can run.

Notice you can have type errors and still get output. That's not a bug — tsc emits by default even with errors (the JS is what it would be if the types were right). Tools turn that off with noEmitOnError. It's why a type error is a review tool, not a runtime guarantee — the types are erased and gone before the code ever runs. Flip strict off and watch errors vanish while the JS stays identical.
