🔷 What is this — and what is TypeScript actually doing?

TypeScript adds a type-checking layer on top of JavaScript, then throws the types away before your code ever runs. Nothing here is faked: this page loads the real typescript npm package, runs its actual compiler API against your code (same diagnostics as tsc or VS Code), then strips the types to plain JS and executes that — exactly the two-step pipeline every TS build does.

  • Type-check — the compiler walks your code and flags mismatches (passing a string where a number is expected, calling a method that doesn't exist) before anything runs.
  • Strip types — annotations like : string and interface are compile-time-only; they're erased entirely, leaving plain JavaScript.
  • Run — the resulting JS executes for real, with console.log output captured and shown live.
  • strict mode toggles stricter rules (no implicit any, null-checks enforced) — the same flag that separates a loosely-typed codebase from a rigorously-typed one.

The compile pipeline

  1. Parse your TS source
  2. Type-check against declarations
  3. Erase all type annotations
  4. Emit plain JavaScript
  5. Run the JS, capture output

Why types matter

  • Catches bugs before runtime
  • Self-documenting function signatures
  • Safe refactors (rename, find every use)
  • Zero runtime cost — fully erased
Why it matters for CIAM:an Angular app's typed UserDTO/AuthResponse interfaces are exactly this mechanism — they catch a mismatched field name against your Spring API's JSON shape at compile time instead of as a silent undefined in production.

What just happened? The three jobs of tsc

A TypeScript "build" is really three separate jobs. This playground does all three and shows you each one in its own tab.

1 · Parse & bind

The compiler reads your text into a syntax tree and figures out what every name refers to. Pure syntax mistakes (a missing )) are caught here.

2 · Type-check

It infers a type for every expression and verifies the rules — this is the Type errors tab. Crucially, type-checking only reports; it never changes the emitted code.

3 · Emit

It erases all the types and downlevels syntax to your target — that's the Emitted JS tab. This is the only part that produces something a browser/Node can run.

Notice you can have type errors and still get output. That's not a bug — tsc emits by default even with errors (the JS is what it would be if the types were right). Tools turn that off with noEmitOnError. It's why a type error is a review tool, not a runtime guarantee — the types are erased and gone before the code ever runs. Flip strict off and watch errors vanish while the JS stays identical.
