Conditional Types & infer

Type-level if/else. The mechanism behind ReturnType, Awaited, Exclude — and the thing that lets your types react to other types. Plus infer, which is pattern-matching inside conditionals.

What are conditional types — and how do they power ReturnType, Awaited, and Exclude?

A conditional type is a type expression that branches: T extends U ? X : Y. Read as: "if T is assignable to U, the result is X; otherwise the result is Y." This is type-level if/else. Unlike runtime code, this runs entirely at compile time — the result is a type, not a value. Example: type IsString<T> = T extends string ? 'yes' : 'no'. IsString<'hello'> = 'yes'; IsString<42> = 'no'. This powers every advanced TypeScript utility type. ReturnType<T>: type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never. If T is a function type, extract its return type as R. infer: the pattern-matching keyword — used inside the extends clause to capture part of a type. infer R says "if T matches this pattern, call the matched part R and use it in the result." Distributive conditional types: when T is a union, the conditional distributes across each member: Exclude<'a' | 'b' | 'c', 'a'> = ('a' extends 'a' ? never : 'a') | ('b' extends 'a' ? never : 'b') | ('c' extends 'a' ? never : 'c') = never | 'b' | 'c' = 'b' | 'c'. To stop distribution, wrap in a tuple: [T] extends [U] ? X : Y.

Awaited<U> : T; type A = Awaited<Promise<string>>; // string type B = Awaited<Promise<Promise<number>>>; // number // Extract first element of a tuple type Head<T extends any[]> = T extends [infer H, ...any[]] ? H : never; type H = Head<[string, number, boolean]>; // string // Extract function parameters type Params<T> = T extends (...args: infer P) => any ? P : never;

Distributive behaviour

// Exclude: remove U from T type Exclude<T, U> = T extends U ? never : T; // Exclude<'a'|'b'|'c', 'a'> // = ('a' extends 'a' ? never : 'a') // | ('b' extends 'a' ? never : 'b') // | ('c' extends 'a' ? never : 'c') // = never | 'b' | 'c' = 'b' | 'c' // Extract: keep only U type Extract<T, U> = T extends U ? T : never; // Extract<'a'|'b'|'c', 'a'|'b'> = 'a' | 'b' // Stop distribution with tuple wrap: type NoDistrib<T> = [T] extends [string] ? 'yes' : 'no'; type R = NoDistrib<string | number>; // 'no' // (string | number) as a whole is not extends string

Custom utility types

// Unwrap API response type ApiResponse<T> = { data: T; status: number }; type UnwrapData<T> = T extends ApiResponse<infer D> ? D : never; type Users = UnwrapData<ApiResponse<UserDto[]>>; // UserDto[] // DeepPartial: recursively make all optional type DeepPartial<T> = T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T; // NonNullable: remove null and undefined type NonNullable<T> = T extends null | undefined ? never : T; // NonNullable<string | null | undefined> = string // Check if type is never: type IsNever<T> = [T] extends [never] ? true : false;

In CIAM / Angular + Spring: Extract service return types: type UserServiceReturn<M extends keyof UserService> = ReturnType<UserService[M]> — UserServiceReturn<'getUser'> gives Observable<UserDto> without importing it explicitly. Unwrap Observable: type ObservableValue<T> = T extends Observable<infer V> ? V : never. JWT claim extraction: type ExtractClaim<T extends JwtClaims, K extends keyof T> = NonNullable<T[K]> — ensures you always get the value, not undefined. Exclude disabled roles: type ActiveCiamRole = Exclude<CiamRole, 'CIAM_DISABLED' | 'CIAM_PENDING'>.

1. Syntax — type-level if/else

type If<C, A, B> = C extends true ? A : B;

type X = If<true,  'yes', 'no'>;  // 'yes'
type Y = If<false, 'yes', 'no'>;  // 'no'

The pattern is always the same:

SomeType extends OtherType ? ThenThisType : ElseThisType

Just like a ternary, but operating on types instead of values. The result is a new type, computed at compile time.

2. The extends check is assignability

"A extends B" doesn't mean class inheritance. It means: "a value of type A could be assigned to a variable of type B". Structural — based on shape, not name.

type A = string extends unknown ? 'yes' : 'no';
// 'yes' — every string IS assignable to unknown

type B = unknown extends string ? 'yes' : 'no';
// 'no' — unknown is broader, NOT assignable to string

type C = { a: string; b: number } extends { a: string } ? 'yes' : 'no';
// 'yes' — the bigger shape covers the smaller one
Read direction: A extends B ≈ "A is at least B" or "A fits where B is expected". The left side is the more specific type; the right side is the constraint.

3. Distributive conditional types

The killer feature. When the checked type is a "naked" type parameter (no wrapping) and you pass in a union, the conditional distributes over each member of the union, then unions the results.

type ToArray<T> = T extends any ? T[] : never;

type A = ToArray<string>;
// string[]

type B = ToArray<string | number>;
// string[] | number[]   ← NOT (string | number)[]
// Because TS computes ToArray<string> | ToArray<number> separately and unions them.

This is exactly how Exclude and Extract work — distribution over the input union, with each member either kept or thrown away.

type Exclude<T, U> = T extends U ? never : T;

// Exclude<'a'|'b'|'c', 'a'> expands to:
//   ('a' extends 'a' ? never : 'a') |
//   ('b' extends 'a' ? never : 'b') |
//   ('c' extends 'a' ? never : 'c')
// = never | 'b' | 'c'  =  'b' | 'c'

4. Disabling distribution

Sometimes you want the conditional to operate on the union as a whole, not member-by-member. Wrap both sides in a single-element tuple — this prevents distribution.

// Distributive — treats each member separately
type IsString<T> = T extends string ? true : false;
type A = IsString<string | number>; // boolean (true | false)

// Non-distributive — checks the whole union at once
type IsStringAll<T> = [T] extends [string] ? true : false;
type B = IsStringAll<string | number>; // false
type C = IsStringAll<string>;          // true

Why the difference matters

// Detect a "true never" — distinguish never from a union containing never
type IsNever<T> = [T] extends [never] ? true : false;

type A = IsNever<never>;          // true
type B = IsNever<string>;         // false

// Without the tuple wrap, distribution over never gives never (since the union is empty):
type Broken<T> = T extends never ? true : false;
type Bad = Broken<never>;            // never — not what you wanted

5. infer — match-and-bind

infer X can only appear in the extends clause of a conditional type. It tells TS: "find some type X such that the left side matches this pattern, then make X available in the 'then' branch". Like a capture group in a regex.

type Unbox<T> = T extends { value: infer V } ? V : never;

type A = Unbox<{ value: string }>;     // string
type B = Unbox<{ value: number[] }>;   // number[]
type C = Unbox<{ name: string }>;      // never — no 'value' field to match
Mental picture: T extends { value: infer V } ? V : never reads as "if T has the shape { value: ??? }, then ??? is V — give me V back". The compiler figures out what fills in the blank.

6. Inferring function pieces

This is how the standard ReturnType and Parameters are written:

type MyReturnType<F> = F extends (...args: any) => infer R ? R : never;
type MyParameters<F> = F extends (...args: infer P) => any ? P : never;

function getUser(id: string) { return { id, name: 'Bob' }; }

type R = MyReturnType<typeof getUser>;  // { id: string; name: string }
type P = MyParameters<typeof getUser>;  // [id: string]

You can infer multiple things at once — first arg, return, even this:

type FirstArg<F> =
  F extends (first: infer A, ...rest: any) => any ? A : never;

type FA = FirstArg<(name: string, age: number) => void>; // string

7. Inferring inside arrays & tuples

// Get the element type out of an array
type Elem<T> = T extends (infer U)[] ? U : never;
type E1 = Elem<string[]>;            // string
type E2 = Elem<{ id: number }[]>;    // { id: number }

// First & rest of a tuple
type Head<T extends unknown[]> =
  T extends [infer H, ...any[]] ? H : never;

type Tail<T extends unknown[]> =
  T extends [any, ...infer R] ? R : [];

type H = Head<[string, number, boolean]>; // string
type T = Tail<[string, number, boolean]>; // [number, boolean]

8. Inferring from objects & promises

// Unwrap a Promise (one level)
type Unwrap<T> = T extends Promise<infer U> ? U : T;
type A = Unwrap<Promise<string>>;       // string
type B = Unwrap<number>;                // number — not a promise, returned as-is

// Get the value type of a Record
type ValueOf<T> = T extends Record<any, infer V> ? V : never;
type V = ValueOf<{ a: string; b: string }>; // string

9. infer with template-literal types

The combination that turns TS types into a parsing playground. Match parts of a string-literal type and bind each piece.

// Pull the leading word off a string
type FirstWord<S> = S extends `${infer W} ${string}` ? W : S;
type A = FirstWord<'hello world'>;       // 'hello'
type B = FirstWord<'noSpace'>;            // 'noSpace'

// Parse out route params: '/users/:id/posts/:postId' → 'id' | 'postId'
type RouteParams<S> =
  S extends `${string}:${infer P}/${infer R}`  ? P | RouteParams<`/${R}`> :
  S extends `${string}:${infer P}`                  ? P :
                                                            never;

type P = RouteParams<'/users/:id/posts/:postId'>;
// 'id' | 'postId'

10. Chaining conditionals

Nest conditionals to express multi-branch logic. The pattern reads top-to-bottom like a series of if/else if:

type Describe<T> =
  T extends string   ? 'text' :
  T extends number   ? 'numeric' :
  T extends boolean  ? 'flag' :
  T extends any[]    ? 'list' :
  T extends object   ? 'shape' :
                          'unknown';

type A = Describe<'hi'>;        // 'text'
type B = Describe<[1, 2]>;      // 'list'  (list checked before shape)
type C = Describe<{ x: 1 }>;    // 'shape'

11. Recursive conditional types

Since TS 4.1, conditionals can reference themselves. The compiler has a recursion depth limit, but for most "flatten / unwrap / walk" patterns it works.

// Flatten one level of array nesting
type Flat<T> = T extends (infer U)[] ? U : T;
type A = Flat<string[][]>;   // string[]

// Flatten all the way down
type DeepFlat<T> = T extends (infer U)[] ? DeepFlat<U> : T;
type B = DeepFlat<string[][][][]>; // string

// Recursive Awaited — what TS uses internally
type DeepAwaited<T> = T extends Promise<infer U> ? DeepAwaited<U> : T;

Length of a tuple at the type level

type Length<T extends unknown[]> = T['length'];
type L1 = Length<['a', 'b', 'c']>; // 3

// Reverse a tuple — recursion + spread + infer
type Reverse<T extends unknown[]> =
  T extends [infer H, ...infer R] ? [...Reverse<R>, H] : [];

type R = Reverse<['a', 'b', 'c']>; // ['c', 'b', 'a']

12. Real-world patterns

Strict JSON.parse — the result depends on the literal type passed in

// Real-world: type-safe JSON parser via template literals (simplified)
type ParseJson<S> =
  S extends 'null'             ? null :
  S extends 'true'             ? true :
  S extends 'false'            ? false :
  S extends `"${infer U}"`      ? U :
  S extends `${infer N extends number}` ? N :
                                  unknown;

type A = ParseJson<'"hello"'>; // 'hello'
type B = ParseJson<'42'>;      // 42
type C = ParseJson<'true'>;    // true

Promisify — turn a Node-style callback into an async function type

type Promisify<F> = F extends (
  ...args: [...infer A, (err: unknown, result: infer R) => void]
) => any
  ? (...args: A) => Promise<R>
  : never;

declare function readFile(path: string, cb: (e: unknown, data: Buffer) => void): void;
type ReadFileP = Promisify<typeof readFile>;
// (path: string) => Promise<Buffer>

Result type — derived from a function that may throw

type SafeReturn<F> = F extends (...a: any) => infer R
  ? { ok: true; value: R } | { ok: false; error: Error }
  : never;

The boolean distribution quirk

type IsTrue<T> = T extends true ? 'yes' : 'no';

type A = IsTrue<true>;     // 'yes'
type B = IsTrue<false>;    // 'no'
type C = IsTrue<boolean>;  // 'yes' | 'no' — distributed over true|false

When to reach for conditional types: when you want a type to react to its input. If you find yourself writing the same type with three variants depending on what was passed in, that's a conditional. If you want to extract something that's inside another type, that's infer.
