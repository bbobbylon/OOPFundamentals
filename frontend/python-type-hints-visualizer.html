1. Type Hints Are Not Runtime Enforcement

Python type hints are annotations — they live in __annotations__ and are ignored at runtime. mypy or pyright read them statically.

def greet(name: str) -> str:
    return f"Hello, {name}"

# This STILL RUNS (annotations are ignored at runtime):
greet(42)  # → "Hello, 42" — Python does NOT check

# mypy catches it at check time:
# error: Argument 1 to "greet" has incompatible type "int"; expected "str"

# Check annotations at runtime only if you opt in:
from typing import get_type_hints
get_type_hints(greet)  # {'name': str, 'return': str}

3. TypeVar & Generics

from typing import TypeVar
T = TypeVar("T")

def first(lst: list[T]) -> T:
    return lst[0]

# mypy infers T = int here:
n: int = first([1, 2, 3])
# T = str here:
s: str = first(["a", "b"])
# Bounded TypeVar
from typing import TypeVar
Num = TypeVar("Num", int, float)

def double(x: Num) -> Num:
    return x * 2

# Generic class (Python 3.12+ syntax):
class Stack[T]:
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...

4. Protocol — Structural Typing (Duck Typing + Types)

A Protocol defines an interface structurally — any class with the required methods satisfies it, without explicitly inheriting. This is Python's answer to Go interfaces.

from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...

class Circle:
    def draw(self) -> None:
        print("○")
# No "class Circle(Drawable)" needed!

def render(shape: Drawable) -> None:
    shape.draw()

render(Circle())  # mypy: ✓ Circle satisfies Drawable

# Even external types work (no touching the library):
import io
render(io.StringIO())  # io.StringIO has .write(), not .draw() → type error
