Python Type Hints & Protocols

Static typing with mypy, TypeVar generics, Protocol structural typing, dataclasses, and Union/Optional narrowing. Types as documentation that tools can check.

🔖 What are Python type hints — and how do they make Python more like TypeScript?

Python is dynamically typed, but 3.5+ added type hints — optional annotations that do nothing at runtime and only matter to static checkers like mypy/pyright, exactly like TypeScript (types erased, zero runtime cost). They buy three things: checkers catch type errors before you run, IDEs get autocomplete + inline errors, and the signatures are living documentation. dataclass auto-generates __init__/__repr__/__eq__ from fields; Protocol gives structural (duck) typing; TypeVar gives generics. Pydantic goes further and uses hints at runtime for validation.

  • Hints are static-only — erased at runtime; checked by mypy/pyright (like TypeScript).
  • Three wins: early error detection, IDE autocomplete, living documentation.
  • X | None needs narrowing — the checker forces a None check before use.
  • Protocol = structural typing; TypeVar = generics — Pydantic adds runtime validation.

Type hints + dataclass

Union, Optional, narrowing

# Python 3.10+ union syntax: def find_user(email: str) -> UserDto | None: return db.find_by_email(email) user = find_user('bob@example.com') user.id # ← mypy error: user could be None # Narrowing: if user is None: raise ValueError('User not found') user.id # ← ok: mypy knows user is UserDto # Discriminated union: IdpEvent = PingEvent | EntraEvent | KeycloakEvent def handle(event: IdpEvent) -> None: if isinstance(event, PingEvent): process_ping(event) # narrows to PingEvent elif isinstance(event, EntraEvent): process_entra(event) # narrows to EntraEvent else: never: assert_never(event) # exhaustiveness

Protocol (structural typing)

from typing import Protocol class IdpClient(Protocol): def create_user(self, req: CreateUserReq) -> UserDto: ... def delete_user(self, user_id: str) -> None: ... def assign_role(self, uid: str, role: str) -> None: ... # PingClient satisfies WITHOUT inheriting: class PingClient: # no (IdpClient) needed! def create_user(self, req: CreateUserReq) -> UserDto: return self._ping_api.create(req) def delete_user(self, user_id: str) -> None: ... def assign_role(self, uid: str, role: str) -> None: ... # Function accepts any IdpClient: def provision(client: IdpClient, req: CreateUserReq): return client.create_user(req) provision(PingClient(), req) # mypy ok provision(EntraClient(), req) # mypy ok # TypeScript structural typing = same concept!

1. Type Hints Are Not Runtime Enforcement

Python type hints are annotations — they live in __annotations__ and are ignored at runtime. mypy or pyright read them statically.

def greet(name: str) -> str:
    return f"Hello, {name}"

# This STILL RUNS (annotations are ignored at runtime):
greet(42)  # → "Hello, 42" — Python does NOT check

# mypy catches it at check time:
# error: Argument 1 to "greet" has incompatible type "int"; expected "str"

# Check annotations at runtime only if you opt in:
from typing import get_type_hints
get_type_hints(greet)  # {'name': str, 'return': str}

3. TypeVar & Generics

from typing import TypeVar
T = TypeVar("T")

def first(lst: list[T]) -> T:
    return lst[0]

# mypy infers T = int here:
n: int = first([1, 2, 3])
# T = str here:
s: str = first(["a", "b"])
# Bounded TypeVar
from typing import TypeVar
Num = TypeVar("Num", int, float)

def double(x: Num) -> Num:
    return x * 2

# Generic class (Python 3.12+ syntax):
class Stack[T]:
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...

4. Protocol — Structural Typing (Duck Typing + Types)

A Protocol defines an interface structurally — any class with the required methods satisfies it, without explicitly inheriting. This is Python's answer to Go interfaces.

from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...

class Circle:
    def draw(self) -> None:
        print("○")
# No "class Circle(Drawable)" needed!

def render(shape: Drawable) -> None:
    shape.draw()

render(Circle())  # mypy: ✓ Circle satisfies Drawable

# Even external types work (no touching the library):
import io
render(io.StringIO())  # io.StringIO has .write(), not .draw() → type error
