Validation & Exception Handling

Reject bad input before it reaches your service layer, and return consistent, meaningful error responses when things go wrong. These patterns appear in every production Spring Boot codebase.

1 — Bean Validation Constraints

Add the spring-boot-starter-validation dependency. Annotate your DTO fields. Spring Boot validates automatically when you add @Valid to the controller parameter. Click any annotation to see usage details:

@NotNull

Field must be present and not null
Fails on null. Does NOT reject empty string "" — use @NotBlank for that.

Example: @NotNull(message="Name is required")

@NotBlank

Non-null, non-empty, not just whitespace
String only. Trims whitespace before checking. More useful than @NotEmpty for username/email fields.

Example: @NotBlank(message="Username cannot be blank")

@NotEmpty

Non-null, non-empty string/collection
Works on Strings, Collections, Maps, arrays. Rejects "" and empty list. Does NOT reject whitespace-only strings.

Example: @NotEmpty List<String> roles

@Size

Length/size must be in range
Works on String, Collection, Map, array. Params: min, max.

Example: @Size(min=2, max=50, message="Name must be 2–50 chars")

@Min / @Max

Numeric value in range
Works on int, long, BigDecimal etc. Use @DecimalMin/@DecimalMax for string-formatted numbers.

Example: @Min(0) @Max(120) Integer age

@Email

Must be a valid email format
Checks for basic email format. Does not verify the email exists. Null values pass — combine with @NotBlank if required.

Example: @Email @NotBlank String email

@Pattern

Must match regex
Validates against a regular expression. Null values pass by default.

Example: @Pattern(regexp="^[A-Z]{2}\\d{6}$", message="Invalid passport format")

@Past / @Future

Date must be past or future
Works with LocalDate, LocalDateTime, Date. Use @PastOrPresent for birthdates.

Example: @Past LocalDate birthDate

@Valid

Cascade validation to nested object
Needed on nested objects/collections inside your DTO — otherwise nested constraints are ignored.

Example: @Valid @NotNull AddressDto address

@Positive / @PositiveOrZero

Number must be positive (or ≥ 0)
Cleaner than @Min(1) or @Min(0). Works on numeric types.

Example: @Positive BigDecimal price

3 — How @Valid Works Under the Hood

1
HTTP request arrives at DispatcherServlet JSON body: { "username": "", "email": "bad", "age": 200 }
2
HttpMessageConverter deserializes JSON → CreateUserRequest object Jackson reads the fields and populates the DTO POJO
3
MethodValidationInterceptor runs Bean Validation (Hibernate Validator) Triggered because controller method has @Valid on the parameter — all constraint annotations are checked
4a
Constraint violation → throws MethodArgumentNotValidException Contains a BindingResult with all field errors. Spring automatically returns 400 — but without @ControllerAdvice the error format is ugly.
4b
No violations → method handler executes normally The validated object is passed to your controller method. Service layer runs.

4 — @ControllerAdvice — Global Exception Handler

@RestControllerAdvice // = @ControllerAdvice + @ResponseBody public class GlobalExceptionHandler { // Catch @Valid failures — return structured error body @ExceptionHandler(MethodArgumentNotValidException.class) @ResponseStatus(HttpStatus.BAD_REQUEST) public ProblemDetail handleValidationErrors(MethodArgumentNotValidException ex) { ProblemDetail pd = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST); pd.setTitle("Validation Failed"); Map<String, String> errors = new LinkedHashMap<>(); ex.getBindingResult().getFieldErrors() .forEach(fe -> errors.put(fe.getField(), fe.getDefaultMessage())); pd.setProperty("errors", errors); return pd; } // Catch custom domain exceptions @ExceptionHandler(ResourceNotFoundException.class) @ResponseStatus(HttpStatus.NOT_FOUND) public ProblemDetail handleNotFound(ResourceNotFoundException ex) { ProblemDetail pd = ProblemDetail.forStatus(HttpStatus.NOT_FOUND); pd.setTitle("Resource Not Found"); pd.setDetail(ex.getMessage()); return pd; } // Catch everything else — don't leak stack traces @ExceptionHandler(Exception.class) @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR) public ProblemDetail handleGeneric(Exception ex) { ProblemDetail pd = ProblemDetail.forStatus(500); pd.setTitle("Internal Server Error"); pd.setDetail("An unexpected error occurred. Please contact support."); return pd; // never expose ex.getMessage() in production! } }

5 — ProblemDetail (RFC 7807) — Spring 6+

ProblemDetail is Spring Framework 6's built-in implementation of RFC 7807 — the standard error response format. Use it instead of custom error POJOs:

400 — Validation Error Response
{ "type": "about:blank", "title": "Validation Failed", "status": 400, "instance": "/api/users", "errors": { "username": "must not be blank", "email": "must be a valid email", "age": "must be less than 120" } }
404 — Not Found Response
{ "type": "about:blank", "title": "Resource Not Found", "status": 404, "detail": "User with id 99 not found", "instance": "/api/users/99" }

Enable ProblemDetail by default: add spring.mvc.problemdetails.enabled=true in application.yml — Spring Boot 3 will then return ProblemDetail for all built-in Spring exceptions (MethodArgumentNotValidException, HttpMessageNotReadableException, etc.) automatically.

6 — Full Request DTO + Controller

// CreateUserRequest.java — DTO with validation annotations public record CreateUserRequest( @NotBlank(message = "Username is required") @Size(min = 3, max = 30, message = "Username must be 3–30 characters") String username, @NotBlank(message = "Email is required") @Email(message = "Must be a valid email address") String email, @NotNull(message = "Age is required") @Min(value = 0, message = "Age cannot be negative") @Max(value = 120, message = "Age must be realistic") Integer age, @NotBlank(message = "Password is required") @Size(min = 8, message = "Password must be at least 8 characters") String password ) {} // UserController.java @RestController @RequestMapping("/api/users") public class UserController { @PostMapping @ResponseStatus(HttpStatus.CREATED) public UserDto createUser(@Valid @RequestBody CreateUserRequest req) { // @Valid triggers Bean Validation BEFORE entering this method body // If any constraint fails → MethodArgumentNotValidException // → GlobalExceptionHandler.handleValidationErrors → 400 response return userService.createUser(req); } @GetMapping("/{id}") public UserDto getUser(@PathVariable Long id) { return userService.findById(id) .orElseThrow(() -> new ResourceNotFoundException("User with id " + id + " not found")); // → GlobalExceptionHandler.handleNotFound → 404 response } }

7 — Custom Validation Constraint

// Step 1: Create the annotation @Documented @Constraint(validatedBy = UniqueUsernameValidator.class) @Target(ElementType.FIELD) @Retention(RetentionPolicy.RUNTIME) public @interface UniqueUsername { String message() default "Username is already taken"; Class<?>[] groups() default {}; Class<? extends Payload>[] payload() default {}; } // Step 2: Implement the validator (Spring-managed → can inject repos) @Component public class UniqueUsernameValidator implements ConstraintValidator<UniqueUsername, String> { @Autowired private UserRepository userRepo; @Override public boolean isValid(String username, ConstraintValidatorContext ctx) { if (username == null) return true; // let @NotBlank handle null return !userRepo.existsByUsername(username); } } // Step 3: Use it @NotBlank @UniqueUsername String username;
