The Generics page uses keyof T and T[K] in passing. They deserve their own page: keyof turns a type's keys into a union, indexed access looks a value type up by key, and together they're the engine behind mapped and conditional types.

🔑 What are keyof and indexed access types — and how do they make property access type-safe?

keyof T produces a union of T's key names — for UserDto that's 'id' | 'name' | 'email' | 'roles' (a type, not a runtime value). Indexed access T[K] looks up a property's type — UserDto['name'] is string, and UserDto[keyof UserDto] is the union of all value types. Together they enable a fully type-safe getter get<T, K extends keyof T>(obj, key): T[K] with no casts. Array and tuple indexing work the same — typeof ROLES[number] derives a union straight from a const array.

  • keyof T = union of key names. Purely a type, computed at compile time.
  • T[K] looks up a property's type — T[keyof T] is the union of all value types.
  • Together they make property access type-safe — a typo'd key is a compile error.
  • typeof arr[number] derives a union from a const array — one source of truth.

1. keyof T — the keys as a union

Keys become string-literal types

type Person = { id: number; name: string };
type K = keyof Person;
// K = "id" | "name"

type AnyKey = keyof any;
// string | number | symbol

Index signatures change the answer

If the type has a string index signature, its keyof is string | number (number because JS coerces numeric keys to strings) — not the keys you wrote.

type Dict = { [k: string]: number };
type K = keyof Dict;
// K = string | number  (not a specific key!)

2. Indexed access T[K] — look up a value type

Index a type by a key (or a union of keys) to get the value type(s). Indexing by keyof T gives the union of all value types.

type Person = { id: number; name: string; active: boolean };

type A = Person["name"];            // string
type B = Person["id" | "name"];     // number | string
type C = Person[keyof Person];     // number | string | boolean

// arrays & tuples index by number:
type Nums = number[];
type El = Nums[number];            // number (element type)
type Tup = [string, boolean];
type First = Tup[0];               // string

It's a type-level lookup — there's no runtime cost, and T["name"] uses the type "name", not a value.

4. The combo that powers a type-safe get

The canonical use: a getter whose return type is exactly the property you asked for. K extends keyof T constrains the key to a real one, and T[K] returns its value type.

function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const p = { id: 1, name: "Ada", active: true };
const n = get(p, "name");   // n: string ✅
const a = get(p, "active"); // a: boolean ✅
get(p, "email");            // ❌ "email" is not assignable to "id" | "name" | "active"

Drop the K extends keyof T constraint and obj[key] errors — TS can't prove key is a valid index, and you'd lose the precise return type.

5. typeof arr[number] — a union from a runtime array

Combine as const, typeof, and a [number] indexed access to derive a string-literal union from a real array — one source of truth for both runtime iteration and the type.

const ROLES = ["admin", "editor", "viewer"] as const;
// typeof ROLES = readonly ["admin", "editor", "viewer"]

type Role = typeof ROLES[number];
// Role = "admin" | "editor" | "viewer"

function setRole(r: Role) { /* … */ }
ROLES.forEach(setRole);  // ✅ runtime list and the type can't drift apart

Add a role to the array and the Role union updates automatically — no duplicated enum to maintain.

6. Why this is the foundation of the advanced toolkit

Mapped types iterate keyof T and re-index with T[K]; that's all Partial, Readonly, Pick etc. really are.

// the identity mapped type — clone every key & its value type
type Clone<T> = { [K in keyof T]: T[K] };

// Pick = iterate a SUBSET of keys, re-index for the value type
type Pick<T, K extends keyof T> = { [P in K]: T[P] };

// Partial = same keys, value type unchanged, modifier added
type Partial<T> = { [K in keyof T]?: T[K] };

Continue to the Mapped Types and Utility Types pages — every one of them is keyof + indexed access with a twist.

7. Pitfalls

  • keyof on an index-signature type returns string | number, not your literal keys — you can't get specific keys back out of an open dictionary.
  • keyof on a union type yields only the common keys: keyof (A | B) = keyof A & keyof B. Keys unique to one member are excluded.
  • Optional keys still appear in keyof, and T[K] for an optional prop includes undefined (under strict).
  • T[K] needs K extends keyof T in generic code — without the constraint, TS rejects the index and you lose the precise value type.
  • Number vs string keys: keyof a numeric-keyed type gives number, but object property names are strings at runtime — mostly matters for arrays/tuples and Record<number, V>.

8. One-sentence recap

keyof T collapses a type's keys into a union of literal types and T[K] is an indexed access that looks the value type up by key (with T[keyof T] giving every value type and T[number] the element of an array/tuple); constrain a generic key with K extends keyof T for a type-safe get, derive unions from runtime data with typeof arr[number], and recognize that every mapped and utility type is just these two operators with a modifier or key-remap layered on.
