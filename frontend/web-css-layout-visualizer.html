CSS Layout — Flexbox, Grid & Responsive Design

Two layout engines cover almost everything you'll ever build: Flexbox for one-dimensional rows/columns, and Grid for two-dimensional page layouts. Add a mobile-first breakpoint strategy and you can build any responsive page without a single float or table hack.

📐 What problem does CSS layout actually solve?

Every HTML element is a box. By default, block-level boxes (like <div>) stack top-to-bottom and inline boxes (like <span>) flow left-to-right — that's "normal flow," and it's not enough to build a real page: you need a nav bar with items in a row, a page with a sidebar and a main area side by side, a card grid that reflows on mobile. Before 2013 or so, developers hacked this together with float and invisible <table> layouts — both were designed for something else (wrapping text around images, tabular data) and bent painfully into service as layout tools. Flexbox (2013+) and CSS Grid (2017+) are layout systems built for the actual job. Flexbox arranges children along one axis — a row or a column — and is perfect for anything that reads like a line: a nav bar, a button group, a card's internal content. Grid arranges children along two axes at once — rows AND columns together — and is perfect for whole-page structure: header, sidebar, main content, footer, all declared in one place. You will use both, often nested inside each other, on almost every real page you build.

  • Flexbox = 1D — one axis (row or column) at a time; great for nav bars, toolbars, button rows.
  • Grid = 2D — rows and columns simultaneously; great for whole-page layout (header/sidebar/main/footer).
  • Mobile-first — write base styles for small screens, then use min-width media queries to progressively enhance for larger ones.
  • Relative units (rem, %, vw/vh, clamp()) scale with context and respect user accessibility settings — px doesn't.

Flexbox quick reference

display: flex;
flex-direction: row;
justify-content: space-between;
align-items: center;
gap: 12px;

Grid quick reference

display: grid;
grid-template-columns: 200px 1fr;
grid-template-rows: auto 1fr auto;
gap: 16px;

Angular/React comparison

Nothing here is framework-specific — Angular templates, React JSX, and plain HTML all render to the same DOM boxes, and the same flex/grid rules apply. Angular Material's mat-grid-list and CSS Grid solve overlapping but not identical problems — Grid is the lower-level, framework-agnostic tool you should reach for first.

Where this shows up in real apps: a CIAM login page's centered card (display:flex; justify-content:center; align-items:center; min-height:100vh), an admin dashboard's sidebar+content shell (display:grid; grid-template-columns:240px 1fr), and a responsive nav that collapses to a hamburger below 768px are three layout patterns you'll rebuild in nearly every project — get comfortable with them here before hitting Angular's component styles.

1. Flexbox — one axis, distributed

logonavnavbutton
.navbar {
  display: flex;
  flex-direction: row;  /* the main axis */
  justify-content: space-between;  /* spread along main axis */
  align-items: center;  /* center along cross axis */
  gap: 16px;
}
flex-direction picks the main axis, and everything else is relative to it. justify-content always distributes along the main axis; align-items always positions along the cross axis (perpendicular). Flip flex-direction from row to column and the two properties swap which physical direction they control — this is the single most common source of "why isn't my centering working" confusion.

2. CSS Grid — two axes, declared together

.page {
  display: grid;
  grid-template-columns: 200px 1fr;  /* sidebar, main */
  grid-template-rows: auto 1fr auto;  /* header, body, footer */
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  gap: 16px;
}
.header { grid-area: header; }
Grid is the one-declaration replacement for a pile of nested flex divs. A header/sidebar/main/footer shell built with flexbox alone needs at least 2-3 nested flex containers (an outer column flex, an inner row flex for sidebar+main) plus manual width math. The same layout is one grid-template-columns + one grid-template-rows declaration, because Grid controls both axes at once. Use fr units (fractional remaining space) instead of percentages — 1fr 2fr means "give the second column exactly twice the first," recalculated automatically as the container resizes.

3. Responsive design — mobile-first breakpoints

/* BASE styles = mobile, no media query needed */
.cards { display: grid; grid-template-columns: 1fr; gap: 12px; }

/* progressively enhance for larger viewports */
@media (min-width: 768px) {
  .cards { grid-template-columns: 1fr 1fr; }
}
@media (min-width: 1200px) {
  .cards { grid-template-columns: 1fr 1fr 1fr; }
}

/* required in <head> or mobile browsers fake a 980px viewport */
<meta name="viewport" content="width=device-width, initial-scale=1">
Mobile-first means min-width, not max-width. Write the simplest, single-column layout as your unconditional base styles — this is what phones get, with zero media-query overhead. Each min-width query then adds complexity as screen space becomes available. The alternative ("desktop-first" with max-width queries stripping features away) tends to ship more CSS to the devices that can least afford it, and fights the cascade instead of working with it. Prefer rem for font sizes (respects the user's browser zoom/accessibility settings — px does not) and clamp(1rem, 2vw + 0.5rem, 1.5rem) for fluid type that scales smoothly between a min and max without extra breakpoints.
