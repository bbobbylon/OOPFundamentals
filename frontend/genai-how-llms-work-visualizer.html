How LLMs Work — Tokenization, Next-Token Prediction & Sampling

A large language model doesn't "understand" your prompt the way a person does. It converts text to subword tokens, runs one forward pass through a giant matrix of learned weights, produces a probability distribution over its entire vocabulary for the *next* token, samples one, appends it, and repeats — one token at a time, with no built-in fact-checker.

🧠 What is an LLM actually doing when it "answers" you?

A Large Language Model is a next-token predictor. Your prompt is split into subword tokens (not words, not characters — chunks like "token" + "ization"), each token is mapped to a vector, and a Transformer processes the whole sequence at once to output a probability score for every token in its vocabulary — "what comes next?" A sampling strategy (greedy, temperature, top-k, top-p) picks one of those tokens, it gets appended to the context, and the entire sequence is fed back in to predict the token after that. This repeats until a stop condition. There is a hard context window limit on how many tokens fit in one pass, and — critically — there is no internal "is this true?" check. The model produces the statistically most plausible continuation of the text, which is usually correct because true statements dominate its training data, but when it isn't, the result is a fluent, confident, wrong answer: a hallucination. Understanding this pipeline — tokenize → predict → sample → append → repeat — demystifies both what LLMs are remarkably good at (fluent, context-aware text) and where they structurally fail (verifiable facts, arithmetic, "I don't know").

  • Tokenization first — subword units, not words; ~4 characters or ~0.75 words per token.
  • Autoregressive generation — one token predicted per forward pass, fed back into the context.
  • Context window is a hard limit — tokens beyond it are invisible to the model, not "forgotten."
  • Sampling introduces randomness — temperature/top-k/top-p decide how "safe" vs "creative" the pick is.
  • No truth signal — hallucination is plausible-sounding text, not a malfunction; it's the same mechanism that makes correct answers work.

Where this shows up in CIAM work: every LLM-assisted tool you use day to day — Copilot, Claude Code, an internal chatbot answering "how do I configure a Ping policy?" — runs exactly this loop. The context window is why a huge codebase can't all be "in view" at once (hence retrieval — see the RAG page). Non-determinism from sampling is why the same prompt against an LLM API can return slightly different code two runs in a row — pin temperature: 0 in automation scripts that call an LLM API for reproducibility. And hallucination is why an LLM confidently inventing a Ping Identity API endpoint that doesn't exist is a *feature of how the model works*, not a rare bug — always verify generated code/config against real docs before shipping it.

1. Tokenization — Text Becomes Subword Units

An LLM never sees raw characters or whole words. A tokenizer (usually a Byte-Pair Encoding / BPE variant) splits text into a fixed vocabulary of subword chunks learned from training data — common words become one token, rare or made-up words get split into pieces.

# This is why LLM APIs bill per TOKEN, not per word or character
The tokenizer's vocabulary is fixed at training time — a brand-new word (a typo, a made-up product name, a rare technical term) gets broken into smaller, less meaningful pieces. This is also why LLMs are famously bad at character-level tasks like "count the letters in this word": the model only ever sees token IDs, not individual characters.

2. Autoregressive Generation & the Context Window

Generation is autoregressive: one forward pass predicts exactly one next token. That token is appended to the sequence, and the entire sequence — original prompt plus everything generated so far — is fed back through the model to predict the token after that.

def generate(prompt, max_new_tokens=50):
    tokens = tokenize(prompt)
    for _ in range(max_new_tokens):
        # ONE forward pass over the WHOLE sequence so far
        logits = model(tokens)
        next_id = sample(logits[-1])   # distribution for next token
        if next_id == STOP_TOKEN:
            break
        tokens.append(next_id)     # grows every iteration
    return detokenize(tokens)
The context window (e.g. 128k tokens) is a hard architectural limit, not a soft "memory." Content pushed beyond it is not summarized or forgotten gracefully — it's simply not part of the input to the next forward pass. This is exactly why Retrieval-Augmented Generation (RAG) exists: instead of stuffing an entire knowledge base into the prompt, relevant chunks are retrieved and injected just-in-time.

3. Sampling Strategies & Why Hallucination Isn't a Bug

The forward pass doesn't output one token — it outputs a probability (via softmax) over the entire vocabulary. A sampling strategy decides which token to actually pick.

# temperature scales the logits before softmax
def sample(logits, temperature=0.7, top_k=40):
    logits = logits / temperature       # temp<1 sharpens, temp>1 flattens
    top_logits, top_ids = topk(logits, top_k)  # restrict candidate pool
    probs = softmax(top_logits)
    return random_choice(top_ids, weights=probs)  # weighted random pick

# temperature=0  → always argmax → deterministic, "greedy"
# temperature=1  → sample exactly per model's raw distribution
# temperature=1.5→ flatter distribution → more variety, more risk
Because generation is just "pick the statistically most plausible next token," there is no internal true/false check anywhere in this pipeline. When the model has seen the answer many times in training (e.g. "the capital of France is Paris"), the correct token dominates the distribution and the output is reliably right. When it hasn't — an obscure API method, a citation, a fact past its training cutoff — the model still produces the most plausible-sounding continuation, fluently and confidently. That's a hallucination: not a malfunction, but the exact same mechanism that produces every correct answer, applied to a case where "plausible" and "true" have come apart. The fix isn't "ask it to be more careful" — it's grounding the model in retrieved, verifiable facts (RAG) or having it call a real tool instead of guessing.
