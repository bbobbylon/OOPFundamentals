Python: Pydantic v2

Runtime validation + parsing from type hints: BaseModel, coercion, custom @field_validator/@model_validator, serialization, and BaseSettings — the trust boundary for untrusted data.

📋 Where dataclasses trust, Pydantic verifies — at runtime

Pydantic turns type hints into runtime validation. Declare a BaseModel with annotated fields (and Field(...) constraints), and constructing it from external data validates every field and raises a structured ValidationError pinpointing each failure. Unlike a dataclass (which trusts its annotations), Pydantic is built for the moment data crosses a trust boundary — a request body, token payload, config file. It also coerces compatible types (with a strict mode), supports custom @field_validator/@model_validator, serializes via model_dump(), and (as BaseSettings) validates env config. v2's Rust core makes it fast — it's the backbone of FastAPI.

  • Type hints → runtime validation — structured ValidationError with locations.
  • For the trust boundary — request bodies, token payloads, config; dataclass trusts, Pydantic verifies.
  • Coerces + validates + serializes — custom validators, model_dump(), strict mode.
  • Backs FastAPI — automatic 422s + OpenAPI schema; BaseSettings validates env.

Model + constraints

from pydantic import BaseModel, Field, EmailStr class Register(BaseModel): username: str = Field(min_length=3, max_length=50) email: EmailStr password: str = Field(min_length=8) age: int = Field(gt=0, default=0) Register(username="bob", email="b@e.com", password="hunter2!") # validated

Structured errors

try: Register(username="x", email="nope", password="1") except ValidationError as e: e.errors() # [{loc:('username',), msg:'too short'}, # {loc:('email',), msg:'invalid email'}, # {loc:('password',), msg:'too short'}] # FastAPI turns this into a 422

vs dataclass / Java Bean Validation

dataclass: structure only, no runtime checks. Pydantic: validates + coerces + serializes at runtime — for untrusted input. Java: it's @Valid + Bean Validation (@NotNull, @Size) on a DTO, plus Jackson for (de)serialization — Pydantic rolls validation + parsing + schema into one.

CIAM context: Every untrusted input gets a model — RegisterRequest/LoginRequest bodies (bad input → automatic 422, never a deep crash) and the decoded token payload validated into a Claims model. @model_validator enforces password == confirm, EmailStr validates emails, and model_dump(exclude={'password_hash'}) keeps secrets in. BaseSettings loads and validates JWT_SECRET/DATABASE_URL from env, failing fast on a missing secret.

1. BaseModel — Declarative, Validated Fields

from pydantic import BaseModel, Field, EmailStr

class User(BaseModel):
  id: int
  email: EmailStr
  name: str = Field(min_length=1, max_length=100)
  roles: list[str] = [] # default (safe — copied per instance)
  is_active: bool = True

Fields are type-annotated; Field(...) adds constraints (min_length, max_length, gt/ge/lt, pattern) and metadata (description, alias, examples). Special types (EmailStr, HttpUrl, UUID, SecretStr) validate format. Unlike a dataclass, a mutable default like [] is fine — Pydantic deep-copies it per instance. Models nest: a field typed as another BaseModel is validated recursively.

The field annotations are the schema. One model definition gives you validation, (de)serialization, and a JSON Schema (User.model_json_schema()) — which is how FastAPI auto-generates OpenAPI docs. Define the shape once, get the contract everywhere.

2. Validation & Coercion

# construct from untrusted data → validated & coerced
User(id="42", email="b@e.com", name="Bo")
# id coerced "42" → 42 (lax mode)

User.model_validate(json_dict) # from a dict
User.model_validate_json(raw_bytes) # from JSON bytes

# strict: reject coercion
class Strict(BaseModel):
  model_config = {"strict": True}

Constructing (or model_validate/model_validate_json) runs validation. In default lax mode Pydantic coerces compatible types ("42"→int, "2020-01-01"→date), which is ideal for JSON/forms; strict mode (per-model or per-field) refuses. On failure it raises one ValidationError aggregating all problems, each with a loc (field path) and msg — so the caller sees every issue at once, not just the first.

This is the trust boundary in action. A bad request can't sneak a malformed value deep into your code to crash later — it fails immediately at the edge with a precise, structured error. FastAPI converts that ValidationError into an HTTP 422 with the field-by-field details, for free.

3. Custom Validators

from pydantic import field_validator, model_validator

class SignUp(BaseModel):
  password: str
  confirm: str
  @field_validator("password")
  @classmethod
  def strong(cls, v):
    if v.isalnum(): raise ValueError("need a symbol")
    return v
  @model_validator(mode="after")
  def match(self):
    if self.password != self.confirm: raise ValueError("mismatch")
    return self

@field_validator("x") runs a check/transform on one field (raise ValueError to reject — Pydantic wraps it into the ValidationError). @model_validator(mode="after") runs once all fields are set, for cross-field rules (password == confirm, start < end). mode="before" sees the raw input pre-coercion. @computed_field exposes a derived, serialized property. Keep validators pure — they shouldn't do I/O.

Raise ValueError (or AssertionError), not a custom HTTP error, inside validators. Pydantic catches it and folds it into the structured ValidationError with the right field location — so your validation logic stays framework-agnostic and the web layer (FastAPI) decides the HTTP response.

4. Serialization & Settings

# model → dict / JSON, with control
user.model_dump() # dict
user.model_dump_json() # JSON str
user.model_dump(exclude={"password"}) # hide secrets
user.model_dump(by_alias=True) # camelCase out

# config from env / .env, validated
from pydantic_settings import BaseSettings
class Settings(BaseSettings):
  jwt_secret: str # required → missing env = startup error
  database_url: str

model_dump()/model_dump_json() serialize out, with include/exclude (drop the password hash), by_alias (snake↔camel for an API), and exclude_none. BaseSettings (from pydantic-settings) reads fields from environment variables / a .env file and validates them — a required field with no env value fails at startup, exactly the fail-fast posture the backend uses for JWT_SECRET. Use SecretStr so secrets don't leak into logs/repr.

One model, three jobs. A Pydantic model validates input, serializes output, and emits a JSON Schema — which is why FastAPI uses it end to end (request body → validated model → handler → response model → OpenAPI). Pair it with dataclasses (internal value objects) and you have a clean split: Pydantic at the edges, dataclasses in the core.
