Type-Level Programming Lab

TypeScript's type system is a real (Turing-complete) functional language that runs at compile time. Here you'll build the standard utility types from scratch — Partial, Pick, ReturnType, DeepReadonly — and watch conditional, infer, and mapped types resolve step by step.

🧪 What is type-level programming — and how is TypeScript's type system Turing-complete?

TypeScript's type system isn't just annotations — it's a Turing-complete language that runs at compile time with zero runtime output. Types are its values, generic types its functions, conditional types its if/else, and recursive types its loops. The whole standard library (Partial, Pick, ReturnType, Awaited…) is written in this language using mapped types, conditional types, and infer — so learning to build them lets you derive bespoke domain types that stay in sync with your runtime code forever.

  • Types are a programming language — values=types, functions=generics, if=conditional, loop=recursion.
  • The std-lib utilities are just generic types you can read and rebuild.
  • Recursion enables deep transforms — DeepReadonly, Flatten, DeepAwaited.
  • Derive domain types instead of writing them — they never drift from runtime code.

1. The mental shift: types ARE a programming language

Once you stop seeing types as annotations and start seeing them as values in a pure functional language, everything clicks. Here's the Rosetta Stone:

In normal code……the type-level equivalent
a value: const x = 5a type: type X = 5 (literal types are values)
a function: f = (a) => ...a generic: type F<A> = ...
if (cond) a else bconditional: T extends U ? A : B
destructuring / extract a partinfer inside a conditional
for / map over keysmapped type: { [K in keyof T]: ... }
recursiona type that references itself

There are no side effects, no loops (only recursion), and everything is evaluated lazily by the compiler. That's the entire language.

2. Conditional types & the distribution surprise

extends ? : is type-level if/else

type IsString<T> = T extends string ? true : false;

type A = IsString<"hi">;   // true
type B = IsString<42>;     // false

extends here means "is assignable to / is a subtype of," not class inheritance. Read it as "if T fits in string."

Distribution is how Exclude works

      
type MyExclude<T, U> = T extends U ? never : T;
// MyExclude<"a" | "b" | "c", "b">
//   → ("a" extends "b"? never:"a") | ("b" extends "b"? never:"b") | ("c"...)
//   → "a" | never | "c"   →   "a" | "c"      (never drops out of unions)

      
Each member is tested independently; the ones matching U collapse to never, which vanishes from the union. That's the whole trick behind Exclude, Extract, and NonNullable.

5. Recursion — types that call themselves

    

      

        
DeepReadonly walks nested objects

        
type DeepReadonly<T> = {
  readonly [K in keyof T]:
    T[K] extends object
      ? DeepReadonly<T[K]>   // ↻ recurse
      : T[K];               // base case
};

        
The mapped type maps each key; if the value is itself an object, it recurses; otherwise it stops. Same shape as a recursive function with a base case.

      

      

        
Recursion over tuples (a real loop)

        
// reverse a tuple by peeling one element at a time
type Reverse<T> =
  T extends [infer Head, ...infer Rest]
    ? [...Reverse<Rest>, Head]
    : [];

type R = Reverse<[1, 2, 3]>; // [3, 2, 1]

        
Variadic tuple types + infer rest elements give you head/tail recursion — the type-level version of processing a list one item at a time.

8. One-sentence recap

    

      
🧩 TypeScript's types are a pure functional language: generics are functions, conditional types (extends ? :) are if/else that distribute over unions, infer pattern-matches and captures a piece, mapped types loop over keys (optionally remapping with as), and self-reference gives recursion — combine those four and you've rebuilt the entire utility-type standard library.
