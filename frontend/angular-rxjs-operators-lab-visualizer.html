🔮 Why operators are the hardest part of RxJS — and how marbles help

RxJS has 70+ operators; you need maybe a dozen, but those work in subtle ways docs alone can't convey — because operators handle timing. "Projects each source value to an Observable and cancels the previous one" means nothing about switchMap until you watch it cancel an in-flight HTTP request when a new keystroke arrives. Marble diagrams are the cure: time flows left→right, each circle is an emitted value, a vertical bar is completion. This lab makes them interactive — emit values and watch them transform.

  • Master 5 first — map, filter, switchMap, catchError, tap — they cover ~90% of real code.
  • The confusing ones are about time: debounceTime, distinctUntilChanged, throttleTime, delay.
  • Combination operators merge streams: combineLatest, forkJoin, merge, concat — each with a different "wait" rule.
  • Read marbles, not prose: a circle is a value, a bar is complete, an × is an error.
  • The canonical typeahead — debounceTime → distinctUntilChanged → switchMap → catchError — composes several of these.

The 5 you'll use 90% of the time

map (transform), filter (gate), switchMap (map to a new Observable, cancel the old — search/route params), catchError (recover), tap (side-effect/log). Learn these deeply first.

The timing operators that confuse

debounceTime(300) (emit after a pause), distinctUntilChanged() (skip repeats), throttleTime(1000) (at most once/sec — scroll/resize), delay(500). Together: debounceTime(300), distinctUntilChanged(), switchMap(search).

Combination operators

combineLatest([a$, b$]) (emit on either, latest of both), forkJoin([a$, b$]) (wait for both to complete — parallel APIs), merge (pass both through), concat (b$ only after a$ completes).

In CIAM:user search — searchCtrl.valueChanges.pipe(debounceTime(300), distinctUntilChanged(), switchMap(q => userApi.search(q).pipe(catchError(() => of([]))))); load page + roles in parallel — forkJoin({ user: userApi.getUser(id), roles: roleApi.getAll() }). Both are patterns you'll write daily.

Time-based filter

debounceTime — only emit after a pause (the search-box hero)

Click fast and only the last click survives once you stop. Click slowly (wait >1s) and each one passes. This is why search boxes debounce keystrokes.

The four "flattening" operators flatten

When each source value triggers its own inner stream (e.g. an HTTP call)

This is the #1 RxJS decision point. Each outer value (📲) starts an inner async task that takes time to finish (✓). How overlapping tasks are handled is the whole difference:

OperatorStrategyUse it for
switchMapCancel the previous inner stream when a new value arrivesSearch/autocomplete, latest-wins, route params
mergeMapRun all inner streams concurrently (no order guarantee)Independent parallel writes (e.g. bulk save)
concatMapQueue — wait for each to finish before the nextOrder matters (sequential saves)
exhaustMapIgnore new values while one is in flightPrevent double-submit (login button spam)

Combination combine

combineLatest — newest from each

Emits whenever either source emits, pairing the latest value from both. Great for "filter + page" or "form A + form B".

  map(([a, b]) => a + b)
