CMD & Batch Files

The classic Windows Command Prompt (cmd.exe) and its scripting form, batch files (.bat / .cmd). It's older and quirkier than PowerShell, but it's everywhere — CI steps, installers, double-clickable helpers, and legacy automation. Knowing enough to read and fix a batch file is a real-world skill. (For new scripts on Windows, prefer PowerShell.)

⌨️ What is CMD and batch scripting — and what are the quirks (%%variable%%, SETLOCAL, ERRORLEVEL) you need to know to read and fix legacy automation?

CMD (cmd.exe) is the original Windows command interpreter, descended from MS-DOS. It's been in Windows since the beginning and runs on every Windows machine ever made — no installation required. That ubiquity is why it still appears everywhere: CI/CD installers, setup scripts, double-clickable .bat files, and legacy automation. Batch files (.bat or .cmd) are text files of CMD commands. They run when you double-click them or invoke them from the command line. New scripts on Windows should use PowerShell (more powerful, object-pipeline, modern syntax) — but you will encounter CMD batch files that you need to read, understand, and occasionally fix. The CMD quirks that bite everyone: (1) Variable expansion: %VAR% expands at parse time, not execution time. Inside a code block (inside if/for), use !VAR! with SETLOCAL EnableDelayedExpansion to get runtime expansion. (2) Spaces in SET: SET name=value — no spaces around =. SET name = value sets a variable named "name " (with trailing space) to " value" (with leading space). (3) %% in loops: inside a batch file, loop variables need %% (double percent). On the command line, use single %i. (4) ERRORLEVEL: exit code detection uses IF ERRORLEVEL 1 (not IF %ERRORLEVEL% == 1 — that won't work when ERRORLEVEL > 1). (5) ECHO OFF: scripts typically start with @ECHO OFF to suppress command echo. The @ suppresses the echo of the ECHO OFF command itself. (6) CALL vs direct: to invoke another batch file from within a batch file, use CALL other.bat not just other.bat. Without CALL, control never returns to the caller. When to use CMD vs PowerShell: CMD for simple command-line operations, calling executables, and reading legacy scripts; PowerShell for everything involving logic, API calls, file parsing, object manipulation, or complex conditionals.

Batch file skeleton

@ECHO OFF :: @ suppresses echo of this line; ECHO OFF disables all echoing SETLOCAL :: isolate environment changes (best practice) :: This is a comment (use REM or ::) REM This is also a comment :: Variables: SET name=Alice SET "greeting=Hello %name%" :: quotes avoid trailing space issues ECHO %greeting% :: prints: Hello Alice :: Arguments passed to the batch file: :: %0 = script name, %1 = first arg, %2 = second, etc. IF "%~1"=="" ( ECHO Usage: deploy.bat ^<env^> EXIT /B 1 ) SET ENV=%~1 :: %~1 removes surrounding quotes from the argument :: Conditionals: IF "%ENV%"=="prod" ( ECHO Production deployment ) ELSE IF "%ENV%"=="dev" ( ECHO Dev deployment ) ELSE ( ECHO Unknown environment: %ENV% EXIT /B 2 ) ENDLOCAL

ERRORLEVEL + loops

:: ERRORLEVEL: check if a command succeeded mvn clean package IF ERRORLEVEL 1 ( ECHO Maven build FAILED EXIT /B 1 ) ECHO Maven build succeeded :: OR: check exact exit code IF %ERRORLEVEL% NEQ 0 ECHO Command failed :: FOR loops: :: In batch file: use %%i (double percent) :: On command line: use %i (single percent) FOR %%i IN (a.log b.log c.log) DO ( ECHO Processing %%i TYPE "%%i" ) :: FOR /F: parse file contents line by line FOR /F "tokens=*" %%L IN (config.txt) DO ( ECHO %%L ) :: Delayed expansion (needed inside blocks): SETLOCAL EnableDelayedExpansion SET count=0 FOR %%i IN (a b c) DO ( SET /A count+=1 ECHO !count! :: Use !count! not %count% inside the block )

Common commands reference

:: Navigation: CD %USERPROFILE% :: go to home directory CD /D D:\projects :: /D switches drive too DIR /B *.txt :: list .txt files, bare names only :: File operations: MKDIR mydir :: create directory RMDIR /S /Q mydir :: remove directory and contents (/S=recursive, /Q=quiet) DEL /F /Q file.txt :: delete file (/F=force, /Q=quiet) COPY src.txt dest.txt :: copy file XCOPY src\ dest\ /E /I :: copy directory tree MOVE old.txt new.txt :: move/rename :: View files: TYPE file.txt :: = cat MORE file.txt :: = less (paginated) FIND "ERROR" app.log :: grep equivalent (basic) FINDSTR /N /I "jwt" *.log :: = grep -in (regex, line numbers) :: Environment variables: SET :: print all env vars ECHO %PATH% :: print specific var SETX MY_VAR "value" :: set permanently (survives restart) :: Process management: TASKLIST | FINDSTR java :: = ps | grep java TASKKILL /F /IM java.exe :: kill by image name

In CIAM / Your Job: You'll encounter CMD batch files in legacy CI/CD setups, vendor-provided installation scripts, and old ADO pipelines. The most critical skill: reading a batch file and understanding why it fails. Common causes: missing CALL before invoking another .bat (execution doesn't return), variable expansion in for loops (need EnableDelayedExpansion), and ERRORLEVEL checks that use the wrong syntax. For new automation in your CIAM project, always use PowerShell — it's more readable, debuggable, and handles errors more predictably. When you must maintain a CMD batch file: add @ECHO OFF and SETLOCAL at the top, use IF ERRORLEVEL 1 after each important command, and test by running it manually before putting it in a pipeline.

1. A real batch file, annotated

@echo off                       REM @ hides this line; echo off stops echoing commands
setlocal enabledelayedexpansion   REM scope vars + enable !VAR! (see scenario 4)

set "NAME=%~1"                  REM %1 = first arg; %~1 strips surrounding quotes
if "%NAME%"=="" set "NAME=world"  REM default if no arg

echo Hello, %NAME%!

if exist config.ini (
  echo found config
) else (
  echo no config>&2            REM >&2 = write to stderr
  exit /b 1                   REM /b = exit the script, not the whole shell
)
Read it top-down. @echo off is on the first line of nearly every batch file — it stops the prompt from printing each command before running it. REM is a comment (so is ::). exit /b N sets the errorlevel and leaves the script; plain exit would close the whole window.

2. Variables — set, %VAR%, and arguments

Defining & reading

set "NAME=Ada"        REM quotes avoid trailing-space bugs
echo %NAME%           REM Ada

set /a SUM=2+3        REM /a = arithmetic
set /p CITY=Enter city:  REM /p = prompt for input

REM set NAME = Ada  ← WRONG: variable is "NAME " with a space

Arguments & environment

%0   REM the script name
%1 %2 ...  REM positional args
%~1  REM arg 1 without quotes
%*   REM all args
%CD% %USERPROFILE% %PATH%  REM env vars
%ERRORLEVEL%  REM exit code of last command

Expansion uses percent signs: %NAME%. Environment variables use the same syntax (%PATH%). In a for loop, the loop variable doubles its percent in a file: %%i (but just %i when typed at the prompt) — a classic source of confusion.

3. Reference: control flow & common commands

Control flow

if "%x%"=="yes" echo OK
if exist file.txt echo present
if %N% gtr 10 echo big      REM gtr lss equ neq geq leq

for %%f in (*.txt) do echo %%f
for /l %%i in (1,1,5) do echo %%i

:loop                          REM a label
goto :loop                     REM jump to it

Everyday commands

dir            REM list
cd /d D:\proj  REM /d switches drive too
type f.txt     REM print a file
copy / move / del / md / rd
findstr ERROR log.txt   REM grep-like
tasklist / taskkill
where python   REM which executable
The delayed-expansion trap (scenario ④): inside a block (a loop or parenthesized if), %VAR% is replaced once, when the block is parsed — so a variable you change inside the loop looks frozen. Enable setlocal enabledelayedexpansion and use !VAR! to read the live value. This single gotcha accounts for most "my batch loop variable won't update" questions.
