Type: HTML Form · Data Store: Active Directory LDAP · Selector: First adapter in chain

Type: Duo Security MFA · Triggered: after first factor succeeds

Type: X.509 Client Certificate · For: machine-to-machine authentication

Adapters are chained into an Authentication Policy. The policy determines which adapters run in what order based on the SP or OAuth client requesting authentication.

Token Policies — Lifetimes and signing

Default Token Policy
Access Token: 3600s (1h) · Refresh Token: 28800s (8h) · Signing Algorithm: RS256 · Signing Key: pfKey-2024

Token Policies control lifetimes per OAuth client or globally. The signing key referenced here is the private key PingFederate uses to sign JWTs. The corresponding public key appears in the JWKS endpoint — which is what Spring Boot fetches to verify tokens.

Resource Servers — API protection

spring-api-resource
Scopes: api:read, api:write · Attribute mapping: email, groups → JWT claims

A Resource Server definition maps to a protected API. It defines what scopes are valid for that API and which user attributes from the data store are mapped into JWT claims.

2 — Authentication Policy (AuthN Policy)

PingFederate's Authentication Policy is a flow engine that decides HOW to authenticate a user. Different paths can be taken based on the requesting SP or risk signals:

Policy Tree

Visual flow designer in Admin UI
A tree of decision nodes and adapter nodes. PingFederate evaluates the tree for each authentication request and follows the branch that matches conditions (e.g., user agent, SP entity ID, risk score).

Result of each leaf: which IdP adapter to invoke.

Selector

Routing decision node
A Selector evaluates conditions to decide which branch to follow:

• IP Range Selector: corporate network → no MFA, external → MFA required
• Request Context Selector: which SP is requesting → different auth levels
• HTTP Request Selector: mobile user agent → cert auth flow

Step-up Authentication

Trigger MFA for sensitive resources
Configure certain SPs to require step-up auth (e.g., require MFA). If the user has a low-assurance session, PingFederate challenges them again for that SP only — without logging them out of other apps.

Used for: admin portals, financial transactions, sensitive data access.

Session

PingFederate SSO session
After successful authentication, PingFederate creates an SSO session cookie (default 8 hours). Subsequent SP logins reuse this session — no re-authentication needed.

Session timeout and max lifetime are configurable per authentication policy or globally.

3 — PingFederate Admin API

PingFederate exposes a REST Admin API (port 9999) for automation — used in CI/CD pipelines and IaC (Terraform):

# List OAuth clients curl -u admin:Admin1234 \ https://pingfederate:9999/pf-admin-api/v1/oauth/clients # Create an OAuth client (used in CI/CD) curl -X POST -u admin:Admin1234 \ -H "Content-Type: application/json" \ -d '{ "clientId": "new-service", "name": "New Microservice", "grantTypes": ["CLIENT_CREDENTIALS"], "clientAuth": { "type": "SECRET", "secret": "s3cr3t!" }, "restrictedScopes": ["api:read"] }' \ https://pingfederate:9999/pf-admin-api/v1/oauth/clients # Revoke a token (operational use) curl -X POST https://pingfederate:9031/as/revoke_token.oauth2 \ -d "token=eyJhbG...&client_id=angular-spa"
