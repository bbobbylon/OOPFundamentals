PingFederate Admin & Operations

The PingFederate admin UI runs on port 9999. Learn the key configuration areas and operational tasks you'll encounter as a developer or admin.

🛠️ What is the PingFederate admin console — and which config areas map to which runtime behaviors?

PingFederate is an OAuth2/OIDC Authorization Server and SAML hub; its admin console (port 9999) is where every runtime auth decision is configured — so almost every 401 traces back here. OAuth Client Management registers each app: client_id, PKCE/secret, grant types, exact redirect URIs, allowed scopes, token TTLs. Token Policies shape the JWT — format, signing key, claims (sub/iss/exp + custom groups/roles/tenant_id), and the aud your Spring API expects. Authentication Policies map clients to AM journeys/adapters. Signing certificates live in the keystore and are published at /pf/JWKS for Spring to verify signatures — when a cert expires every JWT fails, so monitor expiry. And SP/IdP Connections hold the SAML federation config.

  • Admin console (9999) = source of truth for every runtime auth flow.
  • OAuth clients — id, PKCE/secret, grant types, exact redirect URIs, scopes, TTLs.
  • Token policies shape JWT claims + the aud Spring expects.
  • Signing certs at /pf/JWKS — expiry breaks all JWTs; SP/IdP connections = SAML.

Token policy + JWT claims

// PingFederate token policy controls what's in the JWT // (Security → OAuth Settings → Token Policy) // Standard JWT claims (auto-included): { "iss": "https://ping.example.com", // issuer — MUST match Spring Boot's expected iss "sub": "user-uuid-123", // subject (user or client) "aud": ["spring-orders-service"], // audience — MUST match Spring Boot's aud "exp": 1704153600, // expiry (Unix timestamp) "iat": 1704150000, // issued at "jti": "unique-token-id" // JWT ID (for revocation tracking) } // Custom claims (added via attribute mapping / scripted plugin): { "email": "bobby@example.com", "groups": ["CIAM_ADMIN","READ_ONLY"], "tenant_id": "acme-corp", // custom claim for multi-tenant apps "scp": "read:users openid profile" // granted scopes } // Spring Boot: spring.security.oauth2.resourceserver.jwt.issuer-uri= https://ping.example.com // This fetches /.well-known/openid-configuration // and validates iss + aud automatically

Key admin URLs + cert expiry

// PingFederate admin: https://ping.example.com:9999/pingfederate // Runtime endpoints (port 9031 or 443): // OIDC Discovery (all runtime URLs in one place): GET /.well-known/openid-configuration // Returns: authorization_endpoint, token_endpoint, // jwks_uri, userinfo_endpoint, issuer // JWKS (Spring Boot validates JWT signatures here): GET /pf/JWKS // Returns: { "keys": [{ "kty":"RSA","kid":"key-id","n":"...","e":"..." }] } // Spring Boot caches this, rotates when kid changes // Token introspection (for opaque tokens): POST /as/introspect.oauth2 Authorization: Basic base64(clientId:secret) Body: token=<opaque-token> // Returns: { "active": true, "sub": "user", "exp": 123, "scope": "..." } // CERTIFICATE EXPIRY WARNING: // When signing cert expires → all JWT signatures fail // Monitor: admin → Security → Certificate Management // Spring Boot JWKS cache may hold old cert → force refresh: // restart app OR reduce spring.cache.cache-names=jwkSet TTL

In CIAM / Your Job: Every "why is my token rejected?" session starts in this console. Common issues: iss mismatch (Spring's issuer ≠ Ping's actual issuer — check /.well-known/openid-configuration), aud mismatch (token's aud is the client_id, not your API's resource-server id — check the Access Token Manager), scope not in token (client isn't allowed the scope), and redirect_uri_mismatch (case- and trailing-slash-sensitive). Always decode the actual JWT at jwt.io before debugging config.

Token Policies control lifetimes per OAuth client or globally. The signing key referenced here is the private key PingFederate uses to sign JWTs. The corresponding public key appears in the JWKS endpoint — which is what Spring Boot fetches to verify tokens.

A Resource Server definition maps to a protected API. It defines what scopes are valid for that API and which user attributes from the data store are mapped into JWT claims.

2 — Authentication Policy (AuthN Policy)

PingFederate's Authentication Policy is a flow engine that decides HOW to authenticate a user. Different paths can be taken based on the requesting SP or risk signals:

Policy Tree

Visual flow designer in Admin UI
A tree of decision nodes and adapter nodes. PingFederate evaluates the tree for each authentication request and follows the branch that matches conditions (e.g., user agent, SP entity ID, risk score).

Result of each leaf: which IdP adapter to invoke.

Selector

Routing decision node
A Selector evaluates conditions to decide which branch to follow:

• IP Range Selector: corporate network → no MFA, external → MFA required
• Request Context Selector: which SP is requesting → different auth levels
• HTTP Request Selector: mobile user agent → cert auth flow

Step-up Authentication

Trigger MFA for sensitive resources
Configure certain SPs to require step-up auth (e.g., require MFA). If the user has a low-assurance session, PingFederate challenges them again for that SP only — without logging them out of other apps.

Used for: admin portals, financial transactions, sensitive data access.

Session

PingFederate SSO session
After successful authentication, PingFederate creates an SSO session cookie (default 8 hours). Subsequent SP logins reuse this session — no re-authentication needed.

Session timeout and max lifetime are configurable per authentication policy or globally.

3 — PingFederate Admin API

PingFederate exposes a REST Admin API (port 9999) for automation — used in CI/CD pipelines and IaC (Terraform):

# List OAuth clients curl -u admin:Admin1234 \ https://pingfederate:9999/pf-admin-api/v1/oauth/clients # Create an OAuth client (used in CI/CD) curl -X POST -u admin:Admin1234 \ -H "Content-Type: application/json" \ -d '{ "clientId": "new-service", "name": "New Microservice", "grantTypes": ["CLIENT_CREDENTIALS"], "clientAuth": { "type": "SECRET", "secret": "s3cr3t!" }, "restrictedScopes": ["api:read"] }' \ https://pingfederate:9999/pf-admin-api/v1/oauth/clients # Revoke a token (operational use) curl -X POST https://pingfederate:9031/as/revoke_token.oauth2 \ -d "token=eyJhbG...&client_id=angular-spa"
