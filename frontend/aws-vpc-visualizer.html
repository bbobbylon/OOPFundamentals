VPC & Networking

A VPC is your private, isolated section of the AWS cloud. Every resource (EC2, RDS, ECS) lives inside a VPC. Understanding VPC architecture is essential for secure production deployments.

What is a VPC — and how do subnets, security groups, and NAT gateways create a layered defense for your CIAM backend?

VPC (Virtual Private Cloud) is your private, isolated network segment in AWS. Every EC2 instance, RDS database, ECS task, and Lambda function (when VPC-enabled) lives inside a VPC. Without a properly configured VPC your resources are exposed — VPC is the foundation of AWS network security. A VPC has a CIDR block (a private IP address range — e.g., 10.0.0.0/16 = 65,536 IP addresses from 10.0.0.1 to 10.0.255.254). You divide the VPC CIDR into subnets. Public subnets are connected to an Internet Gateway — resources deployed here can receive traffic from the internet. Application Load Balancers and Bastion hosts live in public subnets. Private subnets have no direct internet connection — EC2 instances, ECS Fargate tasks, and RDS databases go here. Private resources can initiate outbound connections to the internet (to call Ping OAuth endpoints, download updates) through a NAT Gateway deployed in a public subnet. NAT = outbound only; inbound connections from the internet are not possible. Security Groups: stateful virtual firewalls attached to individual resources (not subnets). Stateful = if you allow inbound TCP on port 8080, return traffic is automatically allowed — you only define inbound (and optionally outbound) rules. Security group rules reference other SGs, not raw IPs: "allow inbound 8080 from ALB security group" — any resource in the ALB SG can reach this resource on 8080. Route Tables: each subnet has a route table. Public subnets: route 0.0.0.0/0 → Internet Gateway. Private subnets: route 0.0.0.0/0 → NAT Gateway. VPC Endpoints: connect to AWS services (S3, Secrets Manager, ECR, CloudWatch) through the AWS private backbone instead of going through the NAT Gateway. Saves NAT Gateway costs, keeps traffic off the internet, faster. Gateway endpoints (S3, DynamoDB) are free; Interface endpoints (most others) cost ~$7/month/AZ.

In CIAM / Context: The CIAM production VPC has 3 tiers: public (ALB, NAT Gateway), private-app (ECS Fargate tasks), private-db (RDS). Security groups enforce that RDS is only reachable from ECS tasks. ECS tasks are only reachable from the ALB. Secrets Manager and ECR use VPC Interface Endpoints so no AWS API calls traverse the internet. Ping and Entra OAuth calls are the only internet traffic from the ECS private subnet, routed through NAT Gateway.

Rule: Spring Boot and databases live in private subnets (no direct internet access). The ALB lives in public subnets and forwards traffic inward. NAT Gateway allows private-subnet resources to make outbound internet calls (Maven downloads, Entra ID token validation) without being reachable inbound.

2 — Security Groups — Stateful Firewalls

Security Groups control inbound and outbound traffic for your resources. They're stateful — if traffic is allowed inbound, the response is automatically allowed outbound.

Best practice: Reference security groups by ID (not CIDR) when restricting traffic between resources in the same VPC. More secure and doesn't break when IPs change.

3 — VPC Components Quick Reference

ComponentPurpose
Internet Gateway (IGW)Allows VPC resources to reach the internet (required for public subnets)
NAT GatewayAllows private subnet resources to initiate outbound internet connections. Not reachable inbound. $0.045/hour + data charges.
Route TableDefines where network traffic goes. Public subnet: 0.0.0.0/0 → IGW. Private subnet: 0.0.0.0/0 → NAT Gateway.
SubnetA range of IP addresses in a specific AZ. Public: has route to IGW. Private: no direct internet route.
Security GroupStateful, instance-level firewall. Default: deny all inbound, allow all outbound.
NACLStateless, subnet-level firewall. Rules evaluated in order. Less commonly configured — Security Groups are usually sufficient.
VPC PeeringPrivate connectivity between two VPCs (same or different accounts/regions). No internet traffic.
VPC EndpointsPrivate connection to AWS services (S3, DynamoDB) without going through the internet. Saves cost and improves security.
Elastic IP (EIP)Static public IPv4 address you can assign to EC2 or NAT Gateway. Survives instance restarts.
