VPC & Networking

A VPC is your private, isolated section of the AWS cloud. Every resource (EC2, RDS, ECS) lives inside a VPC. Understanding VPC architecture is essential for secure production deployments.

Rule: Spring Boot and databases live in private subnets (no direct internet access). The ALB lives in public subnets and forwards traffic inward. NAT Gateway allows private-subnet resources to make outbound internet calls (Maven downloads, Entra ID token validation) without being reachable inbound.

2 — Security Groups — Stateful Firewalls

Security Groups control inbound and outbound traffic for your resources. They're stateful — if traffic is allowed inbound, the response is automatically allowed outbound.

Best practice: Reference security groups by ID (not CIDR) when restricting traffic between resources in the same VPC. More secure and doesn't break when IPs change.

3 — VPC Components Quick Reference

ComponentPurpose
Internet Gateway (IGW)Allows VPC resources to reach the internet (required for public subnets)
NAT GatewayAllows private subnet resources to initiate outbound internet connections. Not reachable inbound. $0.045/hour + data charges.
Route TableDefines where network traffic goes. Public subnet: 0.0.0.0/0 → IGW. Private subnet: 0.0.0.0/0 → NAT Gateway.
SubnetA range of IP addresses in a specific AZ. Public: has route to IGW. Private: no direct internet route.
Security GroupStateful, instance-level firewall. Default: deny all inbound, allow all outbound.
NACLStateless, subnet-level firewall. Rules evaluated in order. Less commonly configured — Security Groups are usually sufficient.
VPC PeeringPrivate connectivity between two VPCs (same or different accounts/regions). No internet traffic.
VPC EndpointsPrivate connection to AWS services (S3, DynamoDB) without going through the internet. Saves cost and improves security.
Elastic IP (EIP)Static public IPv4 address you can assign to EC2 or NAT Gateway. Survives instance restarts.
