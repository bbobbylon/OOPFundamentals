Testing in Spring Boot

Unit tests, slice tests, and integration tests with JUnit 5, Mockito, and Spring's test slices.

1 — The Testing Pyramid

Click each layer to understand what it tests and which Spring annotations drive it:

E2E / Integration Tests
Few — slow — high confidence
@SpringBootTest — boots the full application context. Closest to production. Slow (seconds).

@SpringBootTest(webEnvironment = RANDOM_PORT) + TestRestTemplate or WebTestClient

Use for: happy-path API flows, database round-trips, security filter chains end-to-end. Write a handful — not hundreds.
Slice Tests
Some — medium speed — targeted
@WebMvcTest — only web layer (controllers, filters, serialization). No database.
@DataJpaTest — only JPA layer (repositories, entities). Uses H2 in-memory by default.
@JsonTest — only Jackson serialization/deserialization.

These start fast because they load a partial application context — only the beans relevant to that slice.

Use for: controller input validation, JSON shaping, custom query methods, repository behavior.
Unit Tests
Many — milliseconds — isolated
Plain JUnit 5 + Mockito — no Spring context at all. Instantiate the class under test directly.

@ExtendWith(MockitoExtension.class) enables @Mock / @InjectMocks.

Use for: service logic, validation methods, pure business rules — anything that doesn't need the framework to run. These should be the majority of your tests (cheap to write, milliseconds to run).

2 — Key Test Annotations

@SpringBootTest

Full context integration test
Loads the entire ApplicationContext — every bean, every configuration.

webEnvironment options:
• MOCK (default) — MockMvc-based, no real port
• RANDOM_PORT — real embedded Tomcat, random port
• DEFINED_PORT — real Tomcat on configured port

Slowest of all test types. Use sparingly for end-to-end flows.

@WebMvcTest

Controller slice — no DB
Only loads web layer beans: @Controller, @RestController, @ControllerAdvice, filters, Jackson converters.

Service and repository beans are NOT loaded — you must mock them:
@MockBean UserService userService;

Inject MockMvc to send fake HTTP requests and assert responses.

@DataJpaTest

Repository slice — H2 in-memory
Only loads JPA-related beans: @Repository, EntityManager, DataSource (H2), Flyway/Liquibase (if present).

Each test runs in a transaction that rolls back automatically — so tests don't pollute each other.

Injects TestEntityManager to set up test data without calling your repository.

@MockBean

Spring-managed mock
Adds a Mockito mock into the Spring ApplicationContext. Any bean that depends on it gets the mock injected.

Used in slice tests to replace beans that aren't loaded by the slice.

Different from @Mock — that's a plain Mockito mock used in pure unit tests with no Spring context.

@ExtendWith(Mockito)

Pure unit test with mocks
@ExtendWith(MockitoExtension.class) — activates Mockito annotations without Spring.

@Mock — creates a mock of the type.
@InjectMocks — creates the class under test and injects mocks into it.

Fastest possible tests. No application context startup overhead at all.

@TestConfiguration

Override beans for tests
Defines test-only Spring beans that override production beans in the test context.

Use when you want a real (but lighter-weight) implementation instead of a Mockito mock — e.g., an in-memory implementation of a port/interface.

Annotate a static inner class or a separate class and import it with @Import.

@ExtendWith(MockitoExtension.class) class UserServiceTest { @Mock private UserRepository userRepository; // Mockito mock — no Spring context @InjectMocks private UserService userService; // class under test — mocks injected @Test void getUserById_returnsUser_whenFound() { // ARRANGE User user = new User(1L, "Alice"); when(userRepository.findById(1L)).thenReturn(Optional.of(user)); // ACT User result = userService.getUserById(1L); // ASSERT assertThat(result.getName()).isEqualTo("Alice"); verify(userRepository).findById(1L); // verify interaction } @Test void getUserById_throwsException_whenNotFound() { when(userRepository.findById(99L)).thenReturn(Optional.empty()); assertThatThrownBy(() -> userService.getUserById(99L)) .isInstanceOf(UserNotFoundException.class); } }
@WebMvcTest(UserController.class) class UserControllerTest { @Autowired private MockMvc mockMvc; // fake HTTP engine — no real server @MockBean private UserService userService; // replaces real bean in Spring context @Test void getUser_returns200WithJson() throws Exception { given(userService.getUserById(1L)) .willReturn(new User(1L, "Alice")); mockMvc.perform(get("/api/users/1") .contentType(MediaType.APPLICATION_JSON)) .andExpect(status().isOk()) .andExpect(jsonPath("$.name").value("Alice")) .andExpect(jsonPath("$.id").value(1)); } @Test void createUser_returns400_whenNameBlank() throws Exception { String body = """ {"name": ""} """; mockMvc.perform(post("/api/users") .contentType(MediaType.APPLICATION_JSON) .content(body)) .andExpect(status().isBadRequest()); } }
@DataJpaTest class UserRepositoryTest { @Autowired private TestEntityManager em; // for setting up test data @Autowired private UserRepository userRepository; @Test void findByEmail_returnsUser_whenExists() { // persist directly via EntityManager — bypasses repository em.persistAndFlush(new User("Alice", "alice@example.com")); Optional<User> result = userRepository.findByEmail("alice@example.com"); assertThat(result).isPresent(); assertThat(result.get().getName()).isEqualTo("Alice"); } // Each @Test auto-rolls back its transaction → no test pollution }
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT) class UserApiIntegrationTest { @Autowired private TestRestTemplate restTemplate; // real HTTP client against real server @Autowired private UserRepository userRepository; @BeforeEach void setUp() { userRepository.save(new User("Alice", "alice@example.com")); } @Test void getUser_returnsUser_endToEnd() { ResponseEntity<User> response = restTemplate.getForEntity("/api/users/1", User.class); assertThat(response.getStatusCode()).isEqualTo(HttpStatus.OK); assertThat(response.getBody().getName()).isEqualTo("Alice"); } }

4 — Mockito in Practice

The three-step Mockito pattern — used in every unit test:

1. Stub
when(...).thenReturn(...)
→
2. Act
call method under test
→
3. Verify
assertThat / verify(...)
Mockito methodPurposeExample
when().thenReturn()Stub a return valuewhen(repo.findById(1L)).thenReturn(Optional.of(u))
when().thenThrow()Stub an exceptionwhen(repo.save(any())).thenThrow(new RuntimeException())
verify()Assert a method was calledverify(repo, times(1)).save(user)
verify(never())Assert a method was NOT calledverify(emailSvc, never()).send(any())
ArgumentCaptorCapture what was passed incaptor.getValue() → inspect the saved entity
any() / anyLong()Argument matcherswhen(repo.findById(anyLong())).thenReturn(...)
doNothing().when()Stub void methodsdoNothing().when(emailSvc).send(any())
