Suspense & Error Boundaries

Async UI has two failure modes: still loading, and broke. Suspense declares the loading fallback; an Error Boundary declares the error fallback. Together they replace per-component isLoading/isError branching.

What are Suspense and Error Boundaries — and how do they declaratively handle loading and failure?

Without Suspense and Error Boundaries, every component that fetches data needs to manage its own loading and error state: if (isLoading) return <Spinner />; if (error) return <ErrorMessage />; return <Data />. This is imperative and scattered across hundreds of components. Suspense moves loading UI declaration UP to a parent: <Suspense fallback={<Spinner />}><UserList /></Suspense>. When any child inside the Suspense boundary is "suspended" (waiting for data or code), React renders the fallback instead. The child components don't need to handle loading state themselves — they just use the data as if it's always ready. This works with: React.lazy (code splitting), React Server Components data fetching, and TanStack Query's suspense: true option. Error Boundary: a class component (or react-error-boundary library) that catches JavaScript errors thrown during rendering in its subtree — similar to a try/catch but for React's render phase. When an error is thrown, the nearest Error Boundary renders its fallback UI instead of crashing the whole app. A well-structured app has multiple Error Boundaries at different levels: one at the app root (last resort), one per route, one per major feature panel. TanStack Query integration: with throwOnError: true, failed queries throw to the nearest Error Boundary — you get automatic error handling without checking isError in every component.

Suspense + lazy

// Code split: import lazily const UserListPage = React.lazy(() => import('./UserListPage')); const AuditLogPage = React.lazy(() => import('./AuditLogPage')); // Suspense boundary: show spinner during load function App() { return ( <ErrorBoundary fallback={<p>Something went wrong.</p>}> <Suspense fallback={<PageSpinner />}> <Routes> <Route path="/users" element={<UserListPage />} /> <Route path="/audit" element={<AuditLogPage />} /> </Routes> </Suspense> </ErrorBoundary> ); } // Nested Suspense: route-level vs page-level <Suspense fallback={<RouteSpinner />}> <UserListPage> <Suspense fallback={<TableSkeleton />}> <UserTable /> </Suspense> </UserListPage> </Suspense>

Error Boundary (react-error-boundary)

// react-error-boundary library (preferred over class) import { ErrorBoundary } from 'react-error-boundary'; function UserPageError({ error, resetErrorBoundary }: FallbackProps) { return ( <div role="alert"> <h2>Failed to load users</h2> <pre>{error.message}</pre> <button onClick={resetErrorBoundary}>Try again</button> </div> ); } // Usage: <ErrorBoundary FallbackComponent={UserPageError} onError={(error) => logError(error)} onReset={() => queryClient.invalidateQueries(['users'])} > <UserList /> </ErrorBoundary> // TanStack Query throws to Error Boundary: useQuery({ queryKey: ['users'], queryFn, throwOnError: true }) // ← no need to check isError; Error Boundary catches it

Angular comparison

React Suspense → Angular @defer block (Angular 17+): @defer (on viewport) { <app-user-table /> } @loading { <app-spinner /> } @error { <p>Failed</p> } — declarative loading and error fallbacks. React Error Boundary → Angular's ErrorHandler: @Injectable() class GlobalErrorHandler implements ErrorHandler { handleError(error: any) { logError(error); } }. Angular's ErrorHandler is global only (no subtree scoping like React Error Boundaries). Angular's async pipe with *ngIf="users$ | async as users; else loading" is the classic pattern for loading state in Angular templates. Angular 17's @if + @defer blocks modernize this. Error Boundary's "reset" button → Angular: calling the service method again to re-trigger the observable.

In a CIAM React app: App structure: one root ErrorBoundary (catches unexpected crashes), one Suspense (shows page-level spinner during route transitions), then per-feature ErrorBoundaries (user list failure doesn't crash the audit log panel). Specific error handling: 401 Unauthorized → redirect to login in the mutation's onError, not in an Error Boundary. 403 Forbidden → show "access denied" panel. 404 Not Found → show "user not found" inline. 500 Server Error → let the Error Boundary catch it with a "Try again" button. Network error → TanStack Query retries 3 times with exponential backoff automatically, then throws to the Error Boundary. The Error Boundary's onReset invalidates the failed query so "Try again" actually re-fetches rather than re-throwing the cached error.

1. Error Boundaries: what they do and don't catch

An Error Boundary is a class component implementing getDerivedStateFromError (render the fallback) and/or componentDidCatch (log the error). It catches errors thrown during rendering in its child tree — and presents a fallback instead of a white screen.

Caught ✅NOT caught ❌
Render-phase errors in childrenEvent handlers (use try/catch there)
Lifecycle method errorsAsync code (setTimeout, promises, fetch .then)
Constructor errors of childrenErrors thrown in the boundary itself
Server-side rendering errors (handle separately)
There is no hook for this yet. Error boundaries remain class-only, so most teams use the react-error-boundary package — it gives a <ErrorBoundary FallbackComponent onReset> plus a useErrorBoundary() hook to manually trigger the boundary from event handlers and async code (the cases the boundary can't catch on its own).

2. How Suspense works

When a descendant "suspends" (conceptually, it throws a promise instead of a value), React walks up to the nearest <Suspense> and shows its fallback. When the promise resolves, React retries rendering the real content.

<Suspense fallback={<Skeleton />}>
  <Profile /> // if Profile suspends, <Skeleton/> shows
</Suspense>
You don't throw promises by hand. The suspend mechanism is used for you by React.lazy (code splitting), by framework data loaders (Next.js, Remix), by useSuspenseQuery (TanStack Query), and by the use() hook (React 19). You just wrap the area in <Suspense> and declare the fallback.
