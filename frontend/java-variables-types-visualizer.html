Local variable error:
int x;
System.out.println(x); // COMPILE ERROR

"variable x might not have been initialized" — the compiler proves every path must assign before use.
Why different? Fields are initialized when the object is created. Locals only exist on the call stack and the compiler cannot safely give them a default.

Reference Types — the variable holds an address, not the object

// Creating objects on the heap String name = "Alice"; int[] scores = new int[5]; List<String> list = new ArrayList<>(); // Assigning refs copies the ADDRESS String a = "hello"; String b = a; // same object, not a copy Person p1 = new Person("Bob"); Person p2 = p1; p2.name = "Charlie"; // p1.name is now "Charlie" too!

Reference type categories

◆ Classes — String, Integer, List, your own classes
◆ Interfaces — Runnable, Comparable, Iterable
◆ Arrays — int[], String[], Object[]
◆ Enums — enum values are objects
◆ Records — Java 16+ immutable value objects

== vs .equals() — the most common Java gotcha

String a = new String("hello"); String b = new String("hello"); a == b // false — different heap addresses a.equals(b) // true — same characters // String Pool — literals are interned String c = "hello"; String d = "hello"; c == d // true — same pool object // Golden rule: ALWAYS use .equals() for Strings // Null-safe: Objects.equals(a, b)
// Same issue with Integer cache! Integer x = 127; Integer y = 127; x == y // true — cached range [-128, 127] Integer p = 128; Integer q = 128; p == q // false — outside cache, new objects // Always use: x.equals(y) // true Objects.equals(x, y) // null-safe Integer.compare(x, y) // for ordering

Pass-by-value of the reference — Java is NOT pass-by-reference

void tryChange(Person p, String s) { p.name = "New Name"; // mutates the heap object — caller SEES this p = new Person(); // reassigns LOCAL variable — caller does NOT see this s = "changed"; // reassigns LOCAL — String is also immutable anyway } Person alice = new Person("Alice"); String text = "original"; tryChange(alice, text); // alice.name == "New Name" (mutation visible) // text == "original" (reassignment not visible)

Every variable has a home — stack or heap

class Example { int fieldX = 10; // field → on the heap (part of the object) void run() { int localY = 20; // local → on the stack frame for run() Person p = new Person(); // p (ref) on stack; Person object on heap helper(localY); // new stack frame pushed } // localY, p go out of scope → popped void helper(int n) { int result = n * 2; // stack frame for helper() } // popped when helper() returns }
Stack (LIFO, per-thread)
helper() framen=20, result=40
run() framelocalY=20, p→@0x8a4
main() frameargs, ex→@0x2c1
Fast — just move a stack pointer.
Limited — StackOverflowError if too deep (infinite recursion).
Auto-freed when method returns.
Heap (GC-managed, shared)
Example@0x2c1fieldX=10
Person@0x8a4name=null, age=0
String@0x5f0"Alice"
Large — holds all objects, arrays, class metadata.
GC-managed — cleaned up when no references remain.
Shared across all threads (concurrency care needed).

Autoboxing & Unboxing — automatic conversion between primitives and wrappers

Wrapper Classes

int ↔ Integer
long ↔ Long
double ↔ Double
boolean ↔ Boolean
char ↔ Character
byte ↔ Byte
// Autoboxing: primitive → wrapper (automatic) Integer x = 42; // Integer.valueOf(42) List<Integer> nums = new ArrayList<>(); nums.add(5); // autoboxed to Integer // Unboxing: wrapper → primitive (automatic) int sum = x + 10; // x.intValue() + 10 int y = nums.get(0); // unboxed from Integer // Danger: NullPointerException! Integer n = null; int val = n; // NPE — n.intValue() on null!

Performance Pitfall: unnecessary autoboxing in loops

// SLOW: autoboxes every iteration Long sum = 0L; for (long i = 0; i < 1_000_000; i++) { sum += i; // unbox sum, add, rebox } // Creates ~1M Long objects!
// FAST: stay primitive long sum = 0L; for (long i = 0; i < 1_000_000; i++) { sum += i; // pure primitive math } // No boxing, no GC pressure
Useful wrapper methods: Integer.parseInt("42"), Integer.toBinaryString(n), Integer.MAX_VALUE, Double.isNaN(d), Character.isDigit(c)

var — Local Variable Type Inference (Java 10+)

// var tells the compiler: "figure out the type from the right side" var name = "Alice"; // String var count = 42; // int var scores = new int[5]; // int[] var map = new HashMap<String, Integer>(); // HashMap<String,Integer> // var is NOT dynamic — it's still statically typed! var x = 5; x = "hello"; // COMPILE ERROR — x is int // Great for long generic types var entries = new ArrayList<Map.Entry<String, List<Integer>>>(); // vs: ArrayList<Map.Entry<String,List<Integer>>> entries = ... // Use in enhanced for loops for (var entry : map.entrySet()) { System.out.println(entry.getKey() + " = " + entry.getValue()); }

When to use var — and when NOT to

✓ Good uses

// Type obvious from right side var list = new ArrayList<String>(); var user = userService.findById(id); // Long generic type names var result = new HashMap<String, List<Map.Entry<Integer,Double>>>(); // try-with-resources try (var conn = db.getConnection()) { // ... }

✗ Avoid when unclear

// Type not obvious from right side var x = getResult(); // what type? var y = process(map); // reader must look it up // Cannot use with null var z = null; // COMPILE ERROR — no type to infer // Cannot use in method signatures var field = 5; // ERROR — only local vars // Cannot use for lambda params (use explicit type) var fn = (x, y) -> x + y; // ERROR

Variable Shadowing — inner variable hides outer

class Shadow { int x = 10; // instance field void method() { int x = 20; // local SHADOWS field System.out.println(x); // 20 System.out.println(this.x); // 10 (field) } void noShadow() { System.out.println(x); // 10 (field) } }
// Final variables — can't be reassigned final int MAX = 100; MAX = 200; // COMPILE ERROR // final reference — ref can't change // but object itself can still mutate final List<String> list = new ArrayList<>(); list.add("ok"); // fine list = new ArrayList<>(); // COMPILE ERROR // Effectively final (Java 8+) int count = 5; // never reassigned Runnable r = () -> System.out.println(count); // ok

Constants — static final

class Config { // Convention: UPPER_SNAKE_CASE for constants public static final int MAX_RETRIES = 3; public static final double TAX_RATE = 0.08; public static final String APP_NAME = "MyApp"; // Compile-time constants (primitives + String) // can be inlined by the compiler }
