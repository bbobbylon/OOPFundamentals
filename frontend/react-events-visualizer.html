1. There is no listener on your element

When you write <button onClick={fn}>, React does not call button.addEventListener('click', fn). It records fn against the button's fiber and attaches a single click listener at the React root container. Every click in the app bubbles up to that one listener, where React figures out which fibers should receive a synthetic event.

React versionWhere the delegated listeners live
≤ 16document (one set of listeners for the whole page)
17+the root DOM container you passed to createRoot — so multiple React versions and portals can coexist cleanly
Why delegate? One listener per event type instead of thousands. A 10,000-row table with an onClick on every row costs React zero extra native listeners — it is still just the one at the root. It also means dynamically added elements work instantly with no listener wiring.

2. Capture and bubble, simulated on the fiber tree

React reconstructs the W3C event flow on its own tree. For onClickCapture it walks root → target; for onClick it walks target → root. e.stopPropagation() halts the React traversal.

<div onClickCapture={a} onClick={d}> // a (capture, 1st) … d (bubble, 4th)
  <button onClickCapture={b} onClick={c}> // b (capture, 2nd) … c (bubble, 3rd)
    Click
  </button>
</div>
// order: a → b → c → d (capture down, then bubble up)

3. SyntheticEvent fields

MemberWhat it gives you
e.targetthe DOM element the event originated on
e.currentTargetthe element whose handler is running (changes as it propagates)
e.preventDefault()cancel the default action (form submit, link navigation)
e.stopPropagation()stop the synthetic event from reaching parent handlers
e.nativeEventthe underlying real browser event, if you need it
Event pooling is gone (React 17+). React 16 reused one SyntheticEvent object and nulled its fields after the handler returned, so reading e.target in an async callback required e.persist(). React 17 removed pooling — you can safely keep and read the event asynchronously now. If you see e.persist() in a tutorial, it is legacy.

4. The traps

TrapReality & fix
e.preventDefault() in onWheel/onTouchMove does nothingReact attaches these as passive listeners at the root. To block scroll, attach a native listener via a ref with {passive:false}
Mixing native addEventListener + React handlersThey run in different systems; a native stopPropagation can starve React's root listener. Prefer one or the other
onScroll does not bubble (17+)Put onScroll directly on the scrolling element, not an ancestor
onFocus/onBlur do bubble in ReactReact implements them on focusin/focusout, unlike raw DOM focus/blur
