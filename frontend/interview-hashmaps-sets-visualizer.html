Hash Maps & Sets — Frequency, Lookup & Grouping Patterns

Master the 5 core HashMap/HashSet patterns that appear in ~40% of all coding interview problems.

🧩 What are the HashMap and HashSet interview patterns — and why does recognizing which pattern applies let you solve 40% of all coding problems in under 10 minutes?

HashMap and HashSet are the most versatile data structures in a coding interview toolkit. Problems that seem to require O(n²) brute force almost always have an O(n) HashMap solution — the HashMap lets you "remember" things you've seen in a single pass, transforming "search the array for X" from O(n) to O(1). There are five fundamental patterns. 1. Frequency Counter: count occurrences of each element. Map<T, Integer> where key=element, value=count. Use getOrDefault(key, 0) + 1 to increment. Solves: anagram detection, most frequent element, character count problems. 2. Two Sum Pattern (complement lookup): for each element x, check if target-x already exists in the map. If yes, found the pair. If no, add x to the map and continue. O(n) instead of O(n²) for two-pointer. Works for any "find two elements that sum to target" problem. 3. Grouping / Bucketing: group elements by a computed key (their sorted form, their hash, some property). Map<Key, List<T>>. Solves: group anagrams (key = sorted word), group by property. Use computeIfAbsent(key, k -> new ArrayList<>()). 4. Sliding Window with HashMap: track character/element frequencies within a window using a HashMap. Expand/shrink the window based on whether the HashMap constraint is satisfied. Solves: longest substring without repeating characters, minimum window substring. 5. Prefix Sum with HashMap: for subarray sum problems, store cumulative sums in a HashMap. prefixSum → count of times this sum was seen. For subarray sum = target: check if currentSum - target is already in the map. O(n) solution for O(n²) problem. HashSet for O(1) existence checks: when you need "have I seen this?" without storing values, use HashSet. Converts O(n) array contains-check to O(1). Used in: duplicate detection, visited nodes in BFS, cycle detection in linked lists (store addresses).

Two Sum + Frequency Counter

// Pattern 1: Frequency Counter // "Are two strings anagrams?" → count char frequencies boolean isAnagram(String s, String t) { Map<Character,Integer> freq = new HashMap<>(); for (char c : s.toCharArray()) freq.merge(c, 1, Integer::sum); // increment count for (char c : t.toCharArray()) { if (!freq.containsKey(c)) return false; freq.merge(c, -1, Integer::sum); // decrement if (freq.get(c) == 0) freq.remove(c); } return freq.isEmpty(); // all counts back to 0? } // O(n) vs O(n log n) sort approach // Pattern 2: Two Sum complement lookup // "Find two numbers that sum to target" int[] twoSum(int[] nums, int target) { Map<Integer,Integer> seen = new HashMap<>(); // value → index for (int i=0; i<nums.length; i++) { int complement = target - nums[i]; if (seen.containsKey(complement)) return new int[]{seen.get(complement), i}; // FOUND seen.put(nums[i], i); } return new int[]{}; // never reached (problem guarantees solution) } // O(n) ← the classic interview one-liner

Grouping + Sliding Window

// Pattern 3: Grouping by computed key // "Group anagrams" List<List<String>> groupAnagrams(String[] words) { Map<String,List<String>> groups = new HashMap<>(); for (String word : words) { char[] chars = word.toCharArray(); Arrays.sort(chars); String key = new String(chars); // "eat","tea","ate" → "aet" groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word); } return new ArrayList<>(groups.values()); } // O(n * m log m) where m = max word length // Pattern 4: Sliding Window with HashMap // "Longest substring without repeating characters" int lengthOfLongestSubstring(String s) { Map<Character,Integer> lastSeen = new HashMap<>(); int max = 0, lo = 0; // sliding window [lo, hi] for (int hi = 0; hi < s.length(); hi++) { char c = s.charAt(hi); if (lastSeen.containsKey(c)) // duplicate: shrink window lo = Math.max(lo, lastSeen.get(c) + 1); // move past duplicate lastSeen.put(c, hi); // update most recent position max = Math.max(max, hi - lo + 1); } return max; // O(n) }

Prefix Sum HashMap

// Pattern 5: Prefix Sum + HashMap // "Count subarrays with sum = k" // Key insight: subarray sum = prefixSum[j] - prefixSum[i-1] = k // → prefixSum[i-1] = prefixSum[j] - k // So: for each position j, check if (currentSum - k) was seen before int subarraySum(int[] nums, int k) { Map<Integer,Integer> prefixCount = new HashMap<>(); prefixCount.put(0, 1); // empty prefix has sum 0 (count it once) int count = 0, sum = 0; for (int num : nums) { sum += num; // running prefix sum // How many previous prefixes had sum (current - k)? // Those form valid subarrays ending here with sum = k count += prefixCount.getOrDefault(sum - k, 0); prefixCount.merge(sum, 1, Integer::sum); // record this prefix } return count; // O(n) — without HashMap: O(n²) }

Collision handling: Multiple keys that hash to the same bucket form a LinkedList. Java 8+: when a bucket exceeds 8 entries it converts to a TreeNode (red-black tree) → O(log n) vs O(n) worst case.

Key Rules

// Default initial capacity: 16 // Default load factor: 0.75 // Resize trigger: size > capacity * 0.75 // After resize: capacity doubles HashMap<String, Integer> map = new HashMap<>(); // Hash function (simplified): // index = key.hashCode() & (capacity - 1) // capacity is always power of 2 → & is fast // CRITICAL CONTRACT: // If a.equals(b) then // a.hashCode() == b.hashCode() MUST hold // Override BOTH equals() AND hashCode()!
Common mistake: Overriding equals() without overriding hashCode(). The object gets placed in bucket X based on old hashCode, but equals() now finds it "equal" to something in bucket Y. The map can never find it again.

When to Prefer Set vs Map

Use HashSet when: you only need presence/absence (visited nodes in BFS, seen elements in duplicate check, deduplicate a list).
Use HashMap when: you need to associate a value with each key (frequency counts, index storage for Two Sum, grouping, memoization).
Key interview patterns that use Set: Contains Duplicate, Longest Consecutive Sequence, Two Sum (membership check version).
Key patterns that use Map: Two Sum (index needed), Frequency Count, Anagram grouping, Prefix Sum.

Pattern 1 — Frequency Map Very Common

Template

// Universal frequency counter Map<T, Integer> freq = new HashMap<>(); for (T x : arr) { freq.merge(x, 1, Integer::sum); // equivalent: freq.put(x, freq.getOrDefault(x,0)+1) } // Find most frequent element T maxKey = Collections.max(freq.entrySet(), Map.Entry.comparingByValue()).getKey(); // Top K: use PriorityQueue (min-heap of size k) PriorityQueue<Map.Entry<T,Integer>> pq = new PriorityQueue<>(Map.Entry.comparingByValue()); for (var e : freq.entrySet()) { pq.offer(e); if (pq.size() > k) pq.poll(); // evict smallest }

Classic Problems

Top K Frequent Elements — freq map + min-heap of size k. O(n log k)
Valid Anagram — freq map of s, decrement for t, check all zeros
Ransom Note — same idea: magazine builds freq, ransom consumes
First Unique Character — freq pass, then scan for count==1
Sort Characters by Freq — freq map + sort entries by value desc
merge() vs getOrDefault(): merge(key, 1, Integer::sum) is the most concise. Under the hood: if key absent → put(key, 1), else apply the BiFunction. Same performance.

Valid Anagram — Walkthrough

// s = "anagram", t = "nagaram" → true public boolean isAnagram(String s, String t) { if (s.length() != t.length()) return false; int[] freq = new int[26]; // only lowercase letters for (int i = 0; i < s.length(); i++) { freq[s.charAt(i) - 'a']++; // count up for s freq[t.charAt(i) - 'a']--; // count down for t } for (int c : freq) if (c != 0) return false; return true; // O(n) time, O(1) space (fixed 26-element array) // For Unicode: use HashMap instead of int[26] }

Pattern 2 — Two Sum (HashMap O(1) Lookup) Must Know

Core Template

// nums=[2,7,11,15], target=9 → [0,1] public int[] twoSum(int[] nums, int target) { Map<Integer,Integer> seen = new HashMap<>(); for (int i = 0; i < nums.length; i++) { int complement = target - nums[i]; if (seen.containsKey(complement)) { return new int[]{seen.get(complement), i}; } // Store current value and its index seen.put(nums[i], i); } return new int[]{-1, -1}; // no solution } // O(n) time, O(n) space — single pass! // vs O(n²) brute force (nested loops)

Why this works

When we reach nums[i], we check if the value we NEED (target - nums[i]) was seen earlier. If so, we found our pair. Otherwise we record this value for future lookups.

One-pass insight: We don't need to populate the whole map first. The check and insert can happen together because if a[j] + a[i] = target, we find it when processing i (a[j] was already inserted).

Variants

Two Sum II (sorted array) — Two pointers, O(1) space
Three Sum — Sort, then fix one element + two-pointer inner loop. O(n²)
Four Sum — Two nested loops + two-pointer. O(n³)
Two Sum - Less Than Target — Count pairs, sort + two pointers

Three Sum — Sort + Two Pointers

// No duplicates in result public List<List<Integer>> threeSum(int[] nums) { Arrays.sort(nums); // sort first! List<List<Integer>> res = new ArrayList<>(); for (int i = 0; i < nums.length - 2; i++) { if (i > 0 && nums[i] == nums[i-1]) continue; // skip dup int l = i + 1, r = nums.length - 1; while (l < r) { int sum = nums[i] + nums[l] + nums[r]; if (sum == 0) { res.add(Arrays.asList(nums[i], nums[l], nums[r])); while (l < r && nums[l] == nums[l+1]) l++; // skip dups while (l < r && nums[r] == nums[r-1]) r--; // skip dups l++; r--; } else if (sum < 0) l++; else r--; } } return res; // O(n²) time — unavoidable for 3-sum }

Pattern 3 — Grouping / Anagram Pattern Common

Template

// Group elements by canonical key public List<List<String>> groupAnagrams( String[] strs) { Map<String, List<String>> groups = new HashMap<>(); for (String word : strs) { // Canonical key: sorted characters char[] ch = word.toCharArray(); Arrays.sort(ch); String key = new String(ch); // computeIfAbsent: create list if key missing groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word); } return new ArrayList<>(groups.values()); // O(n * m*log(m)) — n words, m avg length }

Canonical Key Strategies

The power of grouping: define a canonical form that all equivalent items share.

Sorted string: "eat" → "aet", "tea" → "aet", "tan" → "ant" ...
Frequency string: "aab" → "a2b1" (handles Unicode, avoids sort overhead for long strings)
Prime product: assign each letter a prime, multiply — equal products = anagrams (clever but overflow risk)
computeIfAbsent is cleaner than: if (!map.containsKey(k)) map.put(k, new ArrayList<>()); map.get(k).add(val);

Pattern 4 — Sliding Window + HashMap Medium–Hard

Minimum Window Substring

// s="ADOBECODEBANC" t="ABC" → "BANC" public String minWindow(String s, String t) { Map<Character,Integer> need = new HashMap<>(); for (char c : t.toCharArray()) need.merge(c, 1, Integer::sum); int have = 0, total = need.size(); // distinct chars Map<Character,Integer> window = new HashMap<>(); int[] best = {0, Integer.MAX_VALUE}; // [l, r] int l = 0; for (int r = 0; r < s.length(); r++) { char c = s.charAt(r); window.merge(c, 1, Integer::sum); if (need.containsKey(c) && window.get(c).equals(need.get(c))) have++; while (have == total) { // valid window → shrink if (r - l < best[1] - best[0]) best = new int[]{l,r}; char lc = s.charAt(l++); window.merge(lc, -1, Integer::sum); if (need.containsKey(lc) && window.get(lc) < need.get(lc)) have--; } } return best[1] == Integer.MAX_VALUE ? "" : s.substring(best[0], best[1]+1); }

Permutation in String (Fixed Window)

// s1="ab" s2="eidbaooo" → true (s2 has "ba") public boolean checkInclusion(String s1, String s2) { if (s1.length() > s2.length()) return false; int[] freq = new int[26]; for (char c : s1.toCharArray()) freq[c - 'a']++; int[] win = new int[26]; int k = s1.length(); for (int i = 0; i < s2.length(); i++) { win[s2.charAt(i) - 'a']++; if (i >= k) win[s2.charAt(i - k) - 'a']--; if (Arrays.equals(freq, win)) return true; } return false; // O(n) — compare 26-element arrays each step }
Key insight: Fixed-size window of k characters. Slide right: add right char, remove leftmost char. When the two frequency arrays match, we found a permutation.

Pattern 5 — Prefix Sum + HashMap Tricky but Common

Subarray Sum Equals K

// Count subarrays with sum == k // nums=[1,1,1], k=2 → 2 public int subarraySum(int[] nums, int k) { Map<Integer,Integer> prefixCount = new HashMap<>(); prefixCount.put(0, 1); // empty prefix has sum 0 int count = 0, sum = 0; for (int num : nums) { sum += num; // If (sum - k) was seen as a prefix sum, // the subarray between has sum k count += prefixCount.getOrDefault(sum - k, 0); prefixCount.merge(sum, 1, Integer::sum); } return count; // O(n) time, O(n) space }

Why it works

Key insight: prefixSum[j] - prefixSum[i] = sum of elements from i+1 to j.

So if sum - k was previously seen at some index i, then the subarray from i+1 to current index j has sum exactly k.

Starting with prefixCount.put(0, 1) handles the case where the subarray starts at index 0.
Common mistake: Forgetting to initialize prefixCount.put(0, 1). Without it, subarrays starting at index 0 are missed.

Prefix Sum Variants

Continuous Subarray Sum

// Sum is multiple of k // Key: store prefix % k // If same remainder seen, // subarray between = multiple of k Map<Integer,Integer> seen = new HashMap<>(); seen.put(0, -1); // remainder→first index int sum = 0; for (int i = 0; i < n; i++) { sum = (sum + nums[i]) % k; if (seen.containsKey(sum)) { if (i - seen.get(sum) >= 2) return true; } else seen.put(sum, i); }

Count Subarrays with Odd Sum

// Track parity of prefix sum // odd + odd = even (prefix sums) // Key insight: parity only matters int[] parityCount = {1, 0}; // [even,odd] // parityCount[0] = 1 = empty prefix int sum = 0, count = 0; for (int num : nums) { sum += num; // current parity int p = sum % 2; // need prefix with opposite parity count += parityCount[1 - p]; parityCount[p]++; }

Longest Subarray with Equal 0s and 1s

// Convert 0→-1, find longest // subarray with sum = 0 // Map: prefix sum → first index Map<Integer,Integer> firstSeen = new HashMap<>(); firstSeen.put(0, -1); int sum = 0, best = 0; for (int i = 0; i < n; i++) { sum += nums[i] == 0 ? -1 : 1; if (firstSeen.containsKey(sum)) best = Math.max(best, i - firstSeen.get(sum)); else firstSeen.put(sum, i); }
