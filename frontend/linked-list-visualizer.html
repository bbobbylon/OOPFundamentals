The decisive race — addFirst() on each

Both structures store the same numbers. Click addFirst(0) to insert at index 0 on both. Watch what happens. The linked list rewires one pointer. The ArrayList shifts every existing element one slot to the right.

LinkedList — O(1) at head

operations: 0

ArrayList — O(n) shifting

operations: 0

At n = 1,000,000, the LinkedList still does ~1 operation. The ArrayList does ~1,000,000 shifts. That's the difference between <1µs and ~10ms.

The flip side — get(index) is where ArrayList wins

ArrayList stores everything in a contiguous block of memory. list.get(500_000) is just memory[base + 500_000 * sizeof(ref)] — one calculation, one fetch. LinkedList has to walk 500,000 next pointers from the head. Worse, the nodes are scattered across the heap, so each step is a cache miss. This is why LinkedList is rarely the right answer in modern Java — even when the algorithm "should" favor it, ArrayList's cache friendliness usually wins.

Where you actually use a linked list

📝 LRU caches (with HashMap)

A doubly linked list + HashMap is the textbook LRU cache. The list gives you O(1) reorder-to-front-on-access; the map gives you O(1) lookup. Java's LinkedHashMap is this exact data structure.

🎵 Music / video playlists

"Next track" and "previous track" are pointer hops on a doubly linked list. Inserting a song mid-queue is O(1) once you have the surrounding nodes — no shifting.

↩️ Undo / redo stacks

Each operation links to the previous and next state. Going back is one hop. Editors, photoshop, IDEs all use linked structures for undo history.

🧵 Process schedulers

OS run queues are often linked lists. Moving a process between queues is just pointer surgery — no copying, no shifting. Speed matters in kernel code.

🧠 Adjacency lists for graphs

Each vertex stores a linked list of edges. Easy to add/remove edges, easy to iterate neighbors. (We use this in the graph visualizer.)

🔗 Hash collision chains

HashMap buckets are linked lists (then trees once they get long). That's how chaining works under the hood. You don't see them, but you use them constantly.

The Java code

// A textbook singly linked list node.
class Node<T> {
    T value;
    Node<T> next;

    Node(T value) { this.value = value; }
}

public class MyLinkedList<T> {
    private Node<T> head;
    private int size = 0;

    // O(1) — just rewire the head pointer
    public void addFirst(T value) {
        Node<T> node = new Node<>(value);
        node.next = head;
        head = node;
        size++;
    }

    // O(n) — must walk to the tail to find where to attach
    public void add(T value) {
        Node<T> node = new Node<>(value);
        if (head == null) { head = node; size++; return; }
        Node<T> cur = head;
        while (cur.next != null) cur = cur.next;
        cur.next = node;
        size++;
    }

    // O(n) — index lookups are slow on linked lists
    public T get(int i) {
        Node<T> cur = head;
        for (int k = 0; k < i; k++) cur = cur.next;
        return cur.value;
    }
}
