DI & the Injector Tree

When you write inject(TokenService), Angular doesn't search "the app" — it walks a precise tree of injectors, from the component asking for the dependency, up through its ancestors, into the environment injectors, and finally to the NullInjector. Understanding that walk explains singletons, the "two instances" bug, and what @Self/@SkipSelf/@Host/@Optional actually do.

Why does Angular have a hierarchy of injectors — not just one global one?

A single global injector would mean every service is a singleton shared across the whole app — useful most of the time, but sometimes you want a service scoped to a specific route (reset when navigating away) or a different instance per component. Angular solves this with a tree of injectors that mirrors the component tree. When you call inject(X), Angular starts at the requesting component's injector and walks UP — parent component → grandparent → route injector → environment injector → root injector → NullInjector (throws). The first injector in the chain that has a provider for X wins. Every component can have its own providers that override parent ones.

The "two instances" bug

If UserService appears in providers of both the root AND a lazy-loaded module, there are two separate instances. Component A (root) gets instance #1; Component B (lazy module) gets instance #2. They don't share state — the auth token stored in one is invisible to the other. Fix: providedIn: 'root' on all services that should be singletons.

@Self / @SkipSelf / @Optional

@Self — only look in this component's injector (don't walk up). @SkipSelf — skip my injector, start from my parent. @Optional — return null if not found (don't throw). @Host — stop the walk at the host component's injector (used in directives). Combine: @Optional() @SkipSelf() for optional parent services.

Route-scoped providers

Provide a service in a route's providers: [WizardStateService] array. Angular creates a new injector for that route's subtree. The service is a singleton within the route, shared by all its child components, but destroyed when navigating away. Perfect for multi-step wizards where state should reset between visits.

In CIAM: AuthStore is root-scoped (one singleton). The /admin/create-user route provides CreateUserWizardService in its providers — it tracks multi-step form state and resets when the user navigates away. A FormValidatorDirective uses @Optional() @Host() inject(FormGroupDirective) to find the nearest form — works with or without a parent form group, stopping the walk at the host boundary.

1. Two injector hierarchies, searched in order

    

      

        
ElementInjectors — the component tree

        
Every component & directive instance gets its own ElementInjector, populated by its providers: [...]. They're arranged exactly like your template: a child's injector has the parent's as its parent. A dependency request starts here and walks up the DOM/component tree.

      

      

        
EnvironmentInjectors — root / platform

        
Above the whole component tree sit environment injectors: the root one (from bootstrapApplication + providedIn:'root'), optional route/lazy injectors, then the platform injector. If the element tree didn't have the provider, the search continues here — and only here does providedIn:'root' live.

      

    

    

      
The resolution order is always: requesting ElementInjector → its ancestor ElementInjectors (up to the root component) → EnvironmentInjector (root) → platform → NullInjector. The first injector that has the token wins. Reach NullInjector without a hit and you get the famous NullInjectorError: No provider for X!

    

  


  
  

    
2. providedIn:'root' vs a component's providers:[]

    

      

        
providedIn:'root' → one shared singleton

        
@Injectable({ providedIn: 'root' })
export class CartService { … }

        
Registered once in the root EnvironmentInjector. Every component resolves to the same instance — an app-wide singleton. It's also tree-shakable: if nothing injects it, it's dropped from the bundle. This is the default you want ~90% of the time.

      

      

        
component providers:[] → a new instance per subtree

        
@Component({
  selector: 'parent',
  providers: [CartService],   // new instance HERE
})
export class Parent { … }

        
Creates a fresh instance in this component's ElementInjector, shared only by this component and its descendants. Great for deliberately-scoped state (a wizard, a per-row editor). A sibling outside the subtree gets a different instance.

4. The four resolution modifiers

    

      

        
ModifierWhat it changes about the walkTypical use

        
          
@Self()Look only in the requester's own ElementInjector. Don't walk up at all.Require a directive's own host provider; fail fast if absent

          
@SkipSelf()Skip the requester's own injector; start the search one level up.A component that wants its parent's instance, not its own

          
@Host()Walk up element injectors but stop at the host component — never reach the EnvironmentInjector (so providedIn:'root' is invisible).Bound a directive's search to its host component

          
@Optional()Doesn't change the search — changes the failure: inject null instead of throwing NullInjectorError.Optional collaborators / feature flags

        
      

      
Modern syntax passes these as options: inject(TOKEN, { self: true, optional: true }). The classic decorator form (@Self() @Optional()) does the same thing in a constructor.

    

  


  
  

    
5. InjectionToken + inject() for non-class dependencies

    

      

        
You can't inject an interface or a string

        
// interfaces vanish at runtime — no DI key.
// Make a typed token instead:
export const API_BASE =
  new InjectionToken<string>('API_BASE');

// provide a value for it
bootstrapApplication(App, {
  providers: [{ provide: API_BASE,
               useValue: 'https://api.dev' }]
});

      

      

        
inject() — the function form

        
export class DataService {
  // field initializer, not the constructor
  private base = inject(API_BASE);
  private http = inject(HttpClient);
}

        
inject() runs the same tree walk as constructor injection, but works in field initializers, functional guards/interceptors, and useFactory. It must run in an injection context (construction time, or inside runInInjectionContext).

      

    

  


  
  

    
6. The classic "two instances of my service" bug

    

      
A service is providedIn:'root' (one singleton). Someone then also adds it to a component's providers:[] — often by reflex, or copied from a snippet. Now that component's subtree resolves to a second, separate instance, because the walk finds the component-level provider first, before ever reaching root.

      

        

          
The bug

          
@Injectable({ providedIn: 'root' })
class CartService {}

@Component({
  providers: [CartService],  // ⛔ stray
})
class CartPage {}      // gets its OWN cart

          
Header badge shows 0 items, the cart page shows 3 — two instances, state never syncs.

        

        

          
The fix

          
@Injectable({ providedIn: 'root' })
class CartService {}

@Component({
  // no providers entry —
  // just inject the singleton
})
class CartPage {
  cart = inject(CartService);
}

          
Only provide at a component level when you intend a scoped instance. Otherwise let providedIn:'root' be the single source of truth.

        

      

      
Reproduce it in the walker above: provide at <Leaf> providers — the walk stops at Leaf and never reaches root, so Leaf gets its own instance even though root also has one.

    

  


  
  

    
7. One-sentence recap

    

      
🌳 inject(TOKEN) walks up the injector tree — from the requesting component's ElementInjector, through its ancestors, into the EnvironmentInjector (root), to the NullInjector — and the first provider wins: so providedIn:'root' is one app-wide singleton, a component's providers:[] makes a new instance per subtree (the source of the "two instances" bug), and @Self/@SkipSelf/@Host/@Optional reshape where the walk starts, stops, and what happens when it finds nothing.
