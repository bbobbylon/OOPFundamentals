Java Annotations — Zero to Hero

Metadata attached to code, not logic — from @Override to custom runtime annotations and how Spring reads them.

📌 What is a Java annotation — and how does Spring read them to wire your application?

An annotation is metadata attached to a class, method, field, or parameter — it doesn't change behavior by itself, it's a marker tools and frameworks read. @Override asks the compiler to verify an override; @Deprecated warns callers. At the framework level Spring reads annotations at runtime via reflection: it scans for @Component/@Service to register beans, finds @Autowired to inject, and wraps @Transactional methods in a proxy. Custom annotations plus AOP let you build the same declarative behavior.

  • Annotations are passive metadata — something else (compiler, framework) acts on them.
  • Retention decides visibility — SOURCE, CLASS, or RUNTIME (reflection needs RUNTIME).
  • Spring reads them via reflection + BeanPostProcessors to wire beans and add proxies.
  • Meta-annotations compose — @Service is just @Component; build your own @AdminOperation.

Defining a custom annotation

@Retention(RetentionPolicy.RUNTIME) // keep at runtime for reflection @Target(ElementType.METHOD) // only on methods @Documented public @interface AuditLog { String action(); // required element boolean sensitive() default false; // optional with default }. Usage: @AuditLog(action="CREATE_USER", sensitive=true) void createUser(). At runtime: method.getAnnotation(AuditLog.class).action(). RetentionPolicy: SOURCE (removed by compiler — @Override), CLASS (in bytecode, not at runtime — @Deprecated), RUNTIME (available via reflection — everything Spring uses).

How Spring reads annotations

Spring uses a BeanPostProcessor to inspect beans after construction. For @Transactional: Spring's InfrastructureAdvisorAutoProxyCreator finds beans with transactional methods → wraps them in a CGLIB proxy. For @Cacheable: similar proxy. For @Scheduled: ScheduledAnnotationBeanPostProcessor registers methods as scheduled tasks. For @Async: AsyncAnnotationBeanPostProcessor replaces the method call with an executor submission. Custom annotations: write an AOP @Around advice that looks for your annotation: if (method.isAnnotationPresent(AuditLog.class)) { ... }.

Meta-annotations (composed)

Spring's @Service is just @Component with a more descriptive name: @Target(TYPE) @Retention(RUNTIME) @Component public @interface Service {}. @RestController = @Controller + @ResponseBody. You can compose your own: @Target(METHOD) @Retention(RUNTIME) @PreAuthorize("hasRole('CIAM_ADMIN')") @AuditLog(action="ADMIN_OP") @interface AdminOperation {}. One annotation applies both security and audit. Reduces repetition and ensures all admin operations are consistently secured and logged. Spring's AnnotationUtils handles meta-annotation resolution.

CIAM / Spring Boot: A custom @AuditLog(action="ASSIGN_ROLE", sensitive=true) + an AOP aspect writes an audit entry (action, caller, timestamp, sensitivity) for every annotated method. @ValidRoleId is a Bean Validation annotation checking the role exists in the DB. @AdminOperation composes @PreAuthorize("hasRole('CIAM_ADMIN')") + @AuditLog, applying two cross-cutting concerns with one annotation.

What is an annotation?

An annotation is a special form of syntactic metadata you attach to declarations: classes, methods, fields, parameters, local variables, type uses, and even other annotations. Critically, annotations carry no logic of their own. They are inert labels. The magic happens when something reads the annotation — the compiler, a bytecode tool, or your own code at runtime via reflection.

// An annotation on a class @Deprecated public class OldService { ... } // An annotation on a method @Override public String toString() { ... } // An annotation with a value (element) @SuppressWarnings("unchecked") List rawList = new ArrayList(); // Multiple annotations on one declaration @NotNull @Size(min=1, max=255) private String username;
Key insight: Annotations are a form of declarative programming. Instead of writing imperative code that says "check this is not null", you declare @NotNull and let a framework enforce it. This separates the what from the how.

Three ways annotations are processed

1. Compiler (SOURCE / CLASS)
The Java compiler reads annotations during compilation. @Override causes an error if the method doesn't actually override anything. @SuppressWarnings silences specific warnings. Annotation Processors (APT) can generate new source files at compile time (Lombok, Dagger).
2. Bytecode Tools
Some frameworks transform bytecode post-compilation. The annotation guides the transformation — e.g. AspectJ weaving or JPA bytecode enhancement can add lazy-loading code to fields marked @ManyToOne.
3. Runtime Reflection (RUNTIME)
Your code (or a framework) calls getAnnotation() at runtime and acts on what it finds. Spring, JUnit, Jakarta EE all use this model heavily. Requires @Retention(RetentionPolicy.RUNTIME).
Comparison to XML config
Spring originally used XML files to describe bean wiring. Annotations co-locate the metadata with the code, making it far easier to understand what a class does at a glance. (See the Spring Plumbing tab for the full before/after comparison.)

@Override — enforce intent at compile time

// Without @Override — silent bug class MyList extends ArrayList<String> { public boolean Remove(Object o) { // Typo: capital R // This is a NEW method, not an override // Compiler is silent. Bug lurks. return super.remove(o); } }
// With @Override — caught immediately class MyList extends ArrayList<String> { @Override public boolean Remove(Object o) { // COMPILE ERROR: // method does not override or implement // a method from a supertype } }
Always annotate methods you intend to override with @Override. It is a zero-cost safety net — the annotation itself costs nothing at runtime.

All standard Java annotations

@Deprecated
java.lang — Retention: RUNTIME
Marks an API element as obsolete. The compiler emits a warning whenever deprecated code is used. Use the @deprecated Javadoc tag alongside it to explain why and what to use instead. Java 9+ added forRemoval=true and since="9.0" parameters.
@SuppressWarnings
java.lang — Retention: SOURCE (discarded after compilation)
Tells the compiler to suppress a named category of warnings for the annotated element. Common values: "unchecked", "deprecation", "rawtypes", "serial", "unused". Use sparingly — it hides real issues. Prefer fixing the root cause over silencing the warning.
@FunctionalInterface
java.lang — Retention: RUNTIME
Documents that an interface is a functional interface (exactly one abstract method). Causes a compile error if the interface has zero or more than one abstract method. Without this annotation the interface can still be used as a functional interface — this annotation just adds the compile-time guard and documents intent.
@SafeVarargs
java.lang — Retention: RUNTIME
Suppresses "heap pollution" warnings when a method takes a generic varargs parameter. Only valid on methods/constructors that are final, static, or constructors. You are asserting: "I know this is safe — I don't do anything dangerous with the array."
@Override
java.lang — Retention: SOURCE
See above. Discarded after compilation — purely a compile-time check.
@Repeatable (meta-annotation)
java.lang.annotation — Retention: RUNTIME
Allows an annotation type to be applied more than once to the same declaration. Requires a "container" annotation type that holds an array. See the Meta-annotations tab for full detail.

Meta-annotations — annotations that annotate annotations

Meta-annotations live in java.lang.annotation and control how your custom annotation behaves: where it can be placed, how long it survives, and whether it shows up in Javadoc or gets inherited by subclasses.

@Target(ElementType...)
Restricts which program elements the annotation can be placed on. Without @Target, it can appear anywhere. Values: TYPE (class/interface/enum), METHOD, FIELD, PARAMETER, CONSTRUCTOR, LOCAL_VARIABLE, ANNOTATION_TYPE, PACKAGE, TYPE_PARAMETER (generic param), TYPE_USE (any type position — Java 8+), MODULE (Java 9+), RECORD_COMPONENT (Java 16+).
@Documented
Marks that the annotation should appear in the generated Javadoc of annotated elements. Without this, Javadoc omits it. Use for annotations that are part of your public API contract.
@Inherited
If a class is annotated with a @Inherited annotation, its subclasses automatically inherit that annotation. Only works for class-level annotations — not methods, fields, interfaces, or interfaces implemented by the class.
@Repeatable(ContainerType.class)
Allows the annotation to be applied multiple times on the same element. You must also define a "container" annotation whose single element is an array of the repeatable annotation.

@Retention — when does the annotation survive?

This is the most important meta-annotation. Choosing the wrong retention policy is the #1 annotation mistake.

SOURCE
Discarded by the compiler. Never in .class files. Used for IDE hints and APT code generation. Example: @Override, @SuppressWarnings.
CLASS (default)
Written into .class files but NOT loaded by the JVM. Invisible at runtime. Used by bytecode tools like ASM. This is the default if you omit @Retention — a common surprise.
RUNTIME
Written into .class files AND available via reflection at runtime. Required for Spring, JUnit, Jakarta EE. Use this when your framework needs to read the annotation after deployment.
@Retention(RetentionPolicy.SOURCE) // disappears after javac @Retention(RetentionPolicy.CLASS) // in .class, not in JVM — DEFAULT @Retention(RetentionPolicy.RUNTIME) // visible via getAnnotation()
Most common pitfall: You create a custom annotation and try to read it with reflection, but getAnnotation() returns null. The fix: add @Retention(RetentionPolicy.RUNTIME). Without it, the default is CLASS — the annotation exists in bytecode but the JVM strips it on class loading.

@Repeatable — multiple instances on one element

// Step 1: define the repeatable annotation @Repeatable(Schedules.class) // points to container @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface Schedule { String cron(); String zone() default "UTC"; } // Step 2: define the container annotation @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface Schedules { Schedule[] value(); // must be named "value" } // Step 3: use it multiple times @Schedule(cron = "0 0 * * MON-FRI") @Schedule(cron = "0 12 * * SAT", zone = "America/New_York") public void runReport() { ... } // Reading them at runtime Schedule[] schedules = method.getAnnotationsByType(Schedule.class);

Creating a custom annotation with @interface

The @interface keyword declares an annotation type. It looks like an interface but each "method" is actually an element (a property you can set when using the annotation). Elements can have default values. The element named value has special status: if it's the only element being set, you can omit the name — @MyAnn("x") instead of @MyAnn(value="x").

Marker annotation (no elements)

@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.TYPE) public @interface ThreadSafe { // No elements — just a flag } // Usage @ThreadSafe public class ConcurrentCache { ... }

Single-value annotation

@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface RateLimit { int value(); // calls per second } // Usage — can omit name when only "value" @RateLimit(100) public Response searchProducts() { ... }
// Multi-value annotation — full featured @Documented @Retention(RetentionPolicy.RUNTIME) @Target({ElementType.METHOD, ElementType.TYPE}) public @interface Audit { // Allowed element types: primitives, String, Class, Enum, annotation, arrays of above String action() default ""; String actor() default "system"; boolean includeParams() default false; String[] tags() default {}; } // Usage @Audit(action = "DELETE_USER", includeParams = true, tags = {"security", "gdpr"}) public void deleteUser(long userId) { ... }

Reading annotations at runtime via reflection

Any annotation with @Retention(RetentionPolicy.RUNTIME) can be read from Class, Method, Field, Constructor, or Parameter objects at runtime. This is the mechanism that powers dependency injection, validation frameworks, test runners, and serialization libraries.

// The annotation we want to read @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface Audit { String action(); boolean includeParams() default false; } // A class using the annotation public class UserService { @Audit(action = "CREATE_USER", includeParams = true) public void createUser(String name, String email) { ... } } // Reading the annotation at runtime Method m = UserService.class.getMethod("createUser", String.class, String.class); // Check presence boolean hasIt = m.isAnnotationPresent(Audit.class); // true // Read the annotation and its elements Audit audit = m.getAnnotation(Audit.class); audit.action(); // "CREATE_USER" audit.includeParams(); // true // Scan all methods for annotated ones for (Method method : UserService.class.getDeclaredMethods()) { if (method.isAnnotationPresent(Audit.class)) { Audit a = method.getAnnotation(Audit.class); auditLog.register(method, a.action(), a.includeParams()); } }

Annotation on fields — validation example

@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.FIELD) public @interface NotBlank { String message() default "must not be blank"; } public class RegistrationForm { @NotBlank(message = "Username is required") private String username; @NotBlank private String email; } // A tiny validation engine void validate(Object obj) throws ValidationException { for (Field f : obj.getClass().getDeclaredFields()) { if (f.isAnnotationPresent(NotBlank.class)) { f.setAccessible(true); Object val = f.get(obj); if (val == null || val.toString().isBlank()) { String msg = f.getAnnotation(NotBlank.class).message(); throw new ValidationException(f.getName() + ": " + msg); } } } }

Step-through: how Spring processes @Autowired

Click Next Step to walk through what happens inside Spring's IoC container at startup.

Step 1 — Classpath Scan
Spring scans every class in the configured base packages. For each class it calls Class.isAnnotationPresent(Component.class) (and its stereotypes: @Service, @Repository, @Controller all carry @Component as a meta-annotation). Every matching class is registered as a bean definition.
Step 2 — Bean Definition Registry
Spring stores a BeanDefinition record for each discovered class: its scope (singleton/prototype), lazy-init flag, and the class itself. No instances are created yet — only metadata.
Step 3 — Instantiation
Spring calls the constructor (using reflection: constructor.newInstance()) to create each singleton bean. Spring Boot does this eagerly at startup unless @Lazy is present.
Step 4 — Dependency Injection (@Autowired)
For each bean, Spring scans its declared fields with getDeclaredFields(). Fields annotated with @Autowired are injected: Spring finds the matching bean by type (or by name if ambiguous), then calls field.setAccessible(true) and field.set(beanInstance, dependency).
Step 5 — Post-Construction
After injection, Spring calls any @PostConstruct-annotated methods (again found via reflection). The bean is now fully initialized and placed in the application context, ready to serve requests.

@RequestMapping — how Spring MVC routes HTTP requests

@RestController // = @Controller + @ResponseBody @RequestMapping("/api/users") // base path for all methods public class UserController { @GetMapping("/{id}") // GET /api/users/{id} public User getUser(@PathVariable long id) { return userService.findById(id); } @PostMapping // POST /api/users @ResponseStatus(HttpStatus.CREATED) public User createUser(@RequestBody @Valid UserDto dto) { return userService.create(dto); } } // At startup, Spring scans @RequestMapping on each @Controller. // It builds a routing table: (HTTP method, path) → handler method. // At request time: dispatcher looks up the table and invokes via reflection.
