Reactive Forms — Comprehensive Reference

Reactive forms model the form in the component class — typed, testable, observable, and predictable. This page is the full reference: every control type, every validator pattern, every state, and the custom-control pattern most devs never learn.

Rule of thumb: if your form has more than one field, more than one validator, or any conditional logic — use Reactive. It pays off immediately.

FormControl — the atom

Every input you bind to a form is backed by one FormControl. The control holds the value AND the metadata (valid, dirty, touched, errors).

import { FormControl, Validators } from '@angular/forms';

const email = new FormControl('', [Validators.required, Validators.email]);

// READ
email.value;          // current value
email.valid;          // boolean
email.invalid;        // boolean — convenience inverse
email.errors;         // { required: true } | { email: true } | null
email.touched;        // user has blurred it at least once
email.dirty;          // user has modified the value
email.pristine;       // !dirty
email.pending;        // async validator running
email.status;         // 'VALID' | 'INVALID' | 'PENDING' | 'DISABLED'

// WRITE
email.setValue('a@b.com');
email.patchValue('a@b.com');
email.markAsTouched();
email.markAsDirty();
email.reset();             // back to initial: value=null, untouched, pristine
email.disable(); email.enable();

// SUBSCRIBE
email.valueChanges.subscribe(v => console.log('now:', v));
email.statusChanges.subscribe(s => console.log('status:', s));

FormGroup — composing controls

A FormGroup bundles named controls into one object. Its value is the object of child values; its validity is the AND of children.

import { inject } from '@angular/core';
import { FormBuilder, Validators } from '@angular/forms';

export class SignupComponent {
  private fb = inject(FormBuilder);

  form = this.fb.group({
    email:    ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8)]],
    age:      [null, [Validators.required, Validators.min(13)]],
  });

  onSubmit() {
    if (this.form.invalid) {
      this.form.markAllAsTouched();   // show errors that weren't blurred
      return;
    }
    this.api.signup(this.form.getRawValue());  // includes disabled fields
  }
}

The template side

<form [formGroup]="form" (ngSubmit)="onSubmit()">
  <input formControlName="email" placeholder="email">
  @if (form.controls.email.touched && form.controls.email.invalid) {
    <small>Please enter a valid email</small>
  }
  <button [disabled]="form.invalid">Sign up</button>
</form>

Accessing children

form.controls.email           // the FormControl instance (typed!)
form.get('email')              // same, by path string
form.get('address.zip')        // dot notation for nested groups
form.value                    // { email, password, age }
form.getRawValue()             // INCLUDES disabled fields (form.value skips them)

FormArray — dynamic forms

When the number of fields is dynamic (a list of phone numbers, line items, tags), use FormArray. You add/remove controls at runtime.

import { FormArray, FormControl, FormGroup } from '@angular/forms';

phones = new FormArray([
  new FormControl('', Validators.pattern(/^\d{10}$/)),
]);

addPhone() {
  this.phones.push(new FormControl('', Validators.pattern(/^\d{10}$/)));
}
removePhone(i: number) {
  this.phones.removeAt(i);
}
clearPhones() {
  this.phones.clear();
}

Template — formArrayName + index binding

<div formArrayName="phones">
  @for (phone of phones.controls; track $index) {
    <input [formControlName]="$index" placeholder="10 digits">
    <button type="button" (click)="removePhone($index)">×</button>
  }
</div>
<button type="button" (click)="addPhone()">Add phone</button>

FormArray of FormGroups — line items, addresses, etc.

items = this.fb.array([
  this.fb.group({ name: [''], qty: [1], price: [0] }),
]);

addItem() {
  this.items.push(this.fb.group({
    name:  ['', Validators.required],
    qty:   [1,  [Validators.required, Validators.min(1)]],
    price: [0,  [Validators.required, Validators.min(0)]],
  }));
}
Gotcha: Don't replace the entire array reference (this.form.setControl('items', newArray)). Use push / removeAt / clear so subscribers don't lose their references.

Typed forms (Angular 14+)

Pre-v14 forms were typed as any — a usability disaster. Now every control infers its type from the initial value or from an explicit generic.

const form = new FormGroup({
  email:    new FormControl('', { nonNullable: true }),
  age:      new FormControl<number | null>(null),
});

form.value;                  // { email?: string, age?: number | null }
form.getRawValue();          // { email: string, age: number | null }
form.controls.email.value;   // string (because nonNullable)
form.controls.age.value;     // number | null

The shortcut: NonNullableFormBuilder

private fb = inject(NonNullableFormBuilder);
// All controls created via this fb are { nonNullable: true } by default.

form = this.fb.group({
  email:    ['', Validators.required],   // type: FormControl<string>
  password: ['', Validators.required],
});

type Signup = typeof this.form.value;
// → { email: string, password: string } — perfect, no null pollution
Use NonNullableFormBuilder as your default. The only time you want a nullable control is when "no value yet" is genuinely distinct from "" — like an optional age field.

FormBuilder shorthand

FormBuilder is just sugar over new FormControl/FormGroup/FormArray — same result, less typing.

Without FormBuilder

form = new FormGroup({
  email: new FormControl('',
    [Validators.required, Validators.email]),
  password: new FormControl('',
    [Validators.required, Validators.minLength(8)]),
});

With FormBuilder

form = this.fb.group({
  email:    ['', [Validators.required, Validators.email]],
  password: ['', [Validators.required, Validators.minLength(8)]],
});

The array form is [initialValue, syncValidators, asyncValidators].

type ValidatorFn = (control: AbstractControl) => ValidationErrors | null;

Custom synchronous validators

A validator is a function: takes the control, returns null (valid) or an error object (invalid).

// 1. Simple: no parameters
export const noSpaces: ValidatorFn = (ctrl) => {
  return /\s/.test(ctrl.value) ? { noSpaces: true } : null;
};

// 2. Parameterized: outer function returns the validator
export function forbiddenName(forbidden: RegExp): ValidatorFn {
  return (ctrl) => {
    return forbidden.test(ctrl.value)
      ? { forbiddenName: { value: ctrl.value } }
      : null;
  };
}

// 3. Wire it up
username = this.fb.control('', [
  Validators.required,
  noSpaces,
  forbiddenName(/^(admin|root)$/),
]);

// 4. Display
// @if (username.errors?.forbiddenName) {
//   "{{ username.errors.forbiddenName.value }} is reserved" }
The convention: return { errorName: extraInfo }. The key becomes how you look it up (control.errors?.errorName); the value can carry context for the message.

Async validators

For checks that need the network — username availability, address verification — use AsyncValidatorFn. The control's status goes to PENDING until the validator emits/resolves.

type AsyncValidatorFn = (ctrl: AbstractControl) =>
  Promise<ValidationErrors | null> | Observable<ValidationErrors | null>;

export function usernameAvailable(api: UserApi): AsyncValidatorFn {
  return (ctrl) => api.isAvailable(ctrl.value).pipe(
    debounceTime(300),                                // don't hammer the API
    distinctUntilChanged(),
    switchMap(ok => of(ok ? null : { taken: true })),
    first()                                          // IMPORTANT — must complete
  );
}

// Wire it up — async validators go in the THIRD slot
username: ['', [Validators.required], [usernameAvailable(this.userApi)]]

Display the pending state

@if (form.controls.username.pending) {
  <small>Checking availability…</small>
} @else if (form.controls.username.errors?.taken) {
  <small>That username is taken</small>
}
Two non-obvious rules:
1. Async validators only run AFTER all sync validators pass. So if required fails, no network call. (Saves you.)
2. The async validator MUST complete (emit then end). Use first() or take(1) — without them the control stays PENDING forever.

Cross-field validators (group-level)

When a rule depends on more than one field — "password matches confirmation", "end date is after start date" — attach the validator to the FormGroup, not a single control.

export function passwordMatch(group: AbstractControl): ValidationErrors | null {
  const pw  = group.get('password')?.value;
  const cpw = group.get('confirm')?.value;
  return pw === cpw ? null : { mismatch: true };
}

form = this.fb.group({
  password: ['', [Validators.required, Validators.minLength(8)]],
  confirm:  ['', Validators.required],
}, { validators: [passwordMatch] });   // group-level option

Display the error in the template

@if (form.errors?.mismatch && form.controls.confirm.touched) {
  <small>Passwords don't match</small>
}

Group-level errors live on the group: form.errors, not control.errors. The form itself becomes invalid until they're cleared.

Conditional validation

Add or remove validators based on another control's value. Always call updateValueAndValidity() after changing validators — otherwise the new rules don't run until the next change.

// "If user picks 'Other', the explanation field is required"
this.form.controls.reason.valueChanges.pipe(
  takeUntilDestroyed()
).subscribe(reason => {
  const explanation = this.form.controls.explanation;
  if (reason === 'other') {
    explanation.setValidators([Validators.required, Validators.minLength(10)]);
  } else {
    explanation.clearValidators();
  }
  explanation.updateValueAndValidity();   // MUST be called
});

// Add a single validator without replacing the existing ones
ctrl.addValidators([Validators.required]);
ctrl.removeValidators([Validators.required]);
ctrl.hasValidator(Validators.required);   // check

Error display strategies — when to show errors

"Show every error from the moment the form renders" is hostile. There are four common strategies — pick one and apply it consistently.

touched && invalid
Show after the user has blurred the field at least once. The most common choice.
dirty && invalid
Show as soon as the user has typed something. Better for hot validation like password strength.
submitted && invalid
Hold all errors until the form is submitted. Common in long-form questionnaires.
(touched || submitted) && invalid
Hybrid: per-field on blur, but everything lights up on submit. The friendliest default.

Track submitted via the directive

// Component
@ViewChild(FormGroupDirective) formDir!: FormGroupDirective;
shouldShow(name: string) {
  const c = this.form.get(name);
  return c?.invalid && (c.touched || this.formDir?.submitted);
}

valueChanges & statusChanges — forms as Observables

Every AbstractControl exposes two streams:

  • valueChanges — emits the new value on every change
  • statusChanges — emits 'VALID' / 'INVALID' / 'PENDING' / 'DISABLED'
// Auto-save when the form is valid and changes settle
this.form.valueChanges.pipe(
  debounceTime(500),
  distinctUntilChanged((a, b) => JSON.stringify(a) === JSON.stringify(b)),
  filter(() => this.form.valid),
  switchMap(value => this.api.save(value)),
  takeUntilDestroyed()
).subscribe();
Gotcha: valueChanges emits on every set, including patchValue calls. To skip emission, pass { emitEvent: false }:
ctrl.patchValue(val, { emitEvent: false }) — useful when you're syncing the form from external state and don't want to ping-pong.

Disabled controls — the trap

// ❌ The classic warning everyone has hit
// Template:
<input formControlName="x" [disabled]="!canEdit">
// Console:
// "It looks like you're using the disabled attribute with a reactive form directive..."

// ✅ Disable in the TypeScript, not the template
if (!this.canEdit) {
  this.form.controls.x.disable();
} else {
  this.form.controls.x.enable();
}

A disabled control is excluded from form.value, form.valid, and validators. Use form.getRawValue() if you need its value anyway.

patchValue vs setValue vs reset

MethodBehaviorUse when
setValue(value)Requires EVERY field in the shape. Throws if you miss one.You're 100% sure of the shape — strict updates from a known source
patchValue(partial)Updates only the fields you provide. Silent on missing/extra keys.API responses, partial edits — the 90% case
reset(value?)Resets to value (or initial), clears touched/dirty, clears errors"Cancel" buttons, post-submit cleanup
reset()Above with default — back to initial valuesRestart a wizard
 
form.setValue({ email: 'a@b.com', password: 'x', age: 30 });  // strict
form.patchValue({ email: 'a@b.com' });                              // lenient
form.reset({ email: '', password: '', age: null });               // clear all metadata

updateOn: 'change' / 'blur' / 'submit'

By default, Angular runs validators and emits valueChanges on every keystroke. For expensive validators or large forms, defer to blur or submit.

// Per-control
email = new FormControl('', { updateOn: 'blur' });

// Per-group — applies to all children unless they opt out
form = this.fb.group({ ... }, { updateOn: 'submit' });
ModeValidators run on…
change (default)Every keystroke
blurWhen the user tabs/clicks away
submitOnly on form submit

ControlValueAccessor — building custom form controls

Want to use your own <app-rating-stars> or <app-date-picker> with formControlName? Implement ControlValueAccessor. Four methods, that's the whole contract.

import {
  ControlValueAccessor, NG_VALUE_ACCESSOR
} from '@angular/forms';

@Component({
  selector: 'app-stars',
  standalone: true,
  providers: [{
    provide:     NG_VALUE_ACCESSOR,
    useExisting: forwardRef(() => StarsComponent),
    multi:       true
  }],
  template: `
    @for (i of [1,2,3,4,5]; track i) {
      <span (click)="select(i)" [class.on]="i <= value">★</span>
    }
  `
})
export class StarsComponent implements ControlValueAccessor {
  value = 0;
  disabled = false;

  private onChange = (_: number) => {};
  private onTouched = () => {};

  // 1. Forms → component
  writeValue(value: number): void { this.value = value ?? 0; }

  // 2. Component → forms (call when user changes value)
  registerOnChange(fn: (v: number) => void): void { this.onChange = fn; }

  // 3. Component → forms (call to mark as touched, usually on blur)
  registerOnTouched(fn: () => void): void { this.onTouched = fn; }

  // 4. Forms → component (toggle interactivity)
  setDisabledState(isDisabled: boolean): void { this.disabled = isDisabled; }

  select(n: number) {
    if (this.disabled) return;
    this.value = n;
    this.onChange(n);     // notify the form!
    this.onTouched();
  }
}

// Now it works with Reactive Forms transparently:
// <app-stars formControlName="rating" />
Why CVA matters: any component that implements it becomes a first-class form control. You can use formControlName on it. Validators, valueChanges, all of it just works. This is how Material/PrimeNG/etc. build their input components.

Custom controls with custom validators

// Also implement Validator if you want the control to expose validation errors
providers: [
  { provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(...), multi: true },
  { provide: NG_VALIDATORS,     useExisting: forwardRef(...), multi: true },
]

validate(ctrl: AbstractControl): ValidationErrors | null {
  return this.value > 0 ? null : { noRating: true };
}

Sometimes a sub-section of a form is logically grouped (an address, a billing block). Nest a FormGroup inside the parent.

form = this.fb.group({

// Template — formGroupName on the wrapper

Reactive Forms + Signals

Forms predate signals, but the two compose beautifully via toSignal.

import { toSignal } from '@angular/core/rxjs-interop';

formValue = toSignal(this.form.valueChanges, {
  initialValue: this.form.value
});

isValid = toSignal(this.form.statusChanges.pipe(
  map(s => s === 'VALID')
), { initialValue: this.form.valid });

// Computed derived state — fully reactive
canSubmit = computed(() => this.isValid() && !this.submitting());

// Template:
// <button [disabled]="!canSubmit()">Save</button>

A new generation of "Signal Forms" is being designed for Angular — keep an eye on the RFC. Until it lands, Reactive Forms + toSignal is the right pattern.

Testing forms — the killer feature

Because the form lives in the component class, you can test it without rendering anything.

describe('SignupForm validation', () => {
  let form: FormGroup;

  beforeEach(() => {
    const fb = new FormBuilder();
    form = fb.group({
      email:    ['', [Validators.required, Validators.email]],
      password: ['', [Validators.required, Validators.minLength(8)]],
    });
  });

  it('rejects bad email', () => {
    form.controls.email.setValue('nope');
    expect(form.controls.email.errors).toEqual({ email: true });
  });

  it('is invalid until both fields are valid', () => {
    form.patchValue({ email: 'a@b.com', password: 'short' });
    expect(form.invalid).toBeTrue();
    form.patchValue({ password: 'longenough' });
    expect(form.valid).toBeTrue();
  });
});

No TestBed, no fixtures, no DOM. Pure logic tests for validation rules.

Errors don't show up Forgot the touched/dirty guard, or never imported ReactiveFormsModule Display condition; add ReactiveFormsModule to imports
Validators don't re-run after I changed them Forgot updateValueAndValidity() Call it after setValidators / clearValidators
Form stays PENDING forever Async validator never completes Add first() or take(1) to the stream
valueChanges fires infinitely You're calling setValue/patchValue in the subscription Pass { emitEvent: false } to the set
form.value is missing a field That control is disabled Use form.getRawValue()
setValue throws "must supply a value for form control..." Some keys missing from the object Provide every key, or switch to patchValue
Cross-field error doesn't clear after fixing Group-level validator only runs on group changes; rare edge case Add the validator at the group level, not on a single control

"Cannot find control with name" Template binding name doesn't match a key in the group Match exactly. Mind nested groups need formGroupName

Mental model — final word

The form is data, not DOM

The FormGroup lives in your class. The template just renders + binds to it. You can build, validate, test, save — all without ever rendering.

Validators are pure functions

(ctrl) => error | null. That's the whole contract. No magic, no framework hooks. Easy to write, easy to test, easy to compose.

Errors are objects, not strings

An error object's KEY is the lookup; the VALUE carries context for the message. { required: true }, { minLength: { requiredLength: 8, actualLength: 4 } }.

State has many dimensions

valid/invalid · pristine/dirty · touched/untouched · pending · disabled. They're independent — touched ≠ dirty ≠ invalid. Display rules combine them.

valueChanges is a stream

Compose it with RxJS — debounce, distinctUntilChanged, switchMap. This is where Reactive Forms shines vs template-driven.

Custom controls = CVA

Anything you build that implements ControlValueAccessor becomes first-class. Star ratings, date pickers, color pickers — all standard formControlName targets.
