Reactive Forms — forms as TypeScript objects

Reactive forms model the form in the component class (not the template). You get type safety, easy testing, sync access to the value, and forms-as-Observables for free.

Template-driven vs Reactive — pick one

Template-driven (FormsModule)Reactive (ReactiveFormsModule)
Source of truthThe template — [(ngModel)] on each inputThe component class — a FormGroup tree
ValidationHTML attributes (required, minlength)TS validator functions, composable
Type safetyLoose — strings everywhereStrict, with typed FormGroups (v14+)
TestingNeeds DOM mountingTest the form object directly
Best forTiny forms (login, search)Anything dynamic, validated, or non-trivial

Default to reactive. Template-driven looks simpler until you need cross-field validation, dynamic add/remove of inputs, or to test a complex form. Then you wish you'd started reactive.

The code behind the demo

import { Component, inject } from '@angular/core';
import { FormBuilder, Validators, ReactiveFormsModule, AbstractControl, ValidationErrors } from '@angular/forms';

@Component({
  selector: 'app-signup',
  standalone: true,
  imports: [ReactiveFormsModule],                  // REQUIRED for reactive forms
  templateUrl: './signup.component.html'
})
export class SignupComponent {
  private fb = inject(FormBuilder);

  form = this.fb.group({
    email:    ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8)]],
    confirm:  ['', Validators.required],
    age:      [null, [Validators.min(18), Validators.max(120)]],
  }, { validators: passwordsMatch });            // cross-field validator on the group

  onSubmit() {
    if (this.form.invalid) return;
    console.log(this.form.value);              // { email, password, confirm, age }
  }
}

// Cross-field validator — receives the whole group
function passwordsMatch(ctrl: AbstractControl): ValidationErrors | null {
  const p = ctrl.get('password')?.value;
  const c = ctrl.get('confirm')?.value;
  return p && c && p !== c ? { passwordMismatch: true } : null;
}
<!-- signup.component.html -->
<form [formGroup]="form" (ngSubmit)="onSubmit()">

  <input formControlName="email" placeholder="email" />
  <div *ngIf="form.get('email')?.touched && form.get('email')?.invalid">
    <small *ngIf="form.get('email')?.errors?.['required']">required</small>
    <small *ngIf="form.get('email')?.errors?.['email']">invalid email</small>
  </div>

  <button [disabled]="form.invalid">Submit</button>
</form>

The three building blocks

ClassWhat it modelsExample
FormControlA single field (one input).email field
FormGroupA fixed set of controls keyed by name.the whole signup form, or an "address" sub-group
FormArrayA dynamic ordered list of controls / groups.list of phone numbers, line items in an invoice
 
// Composable — they nest freely
form = this.fb.group({
  email:    ['', Validators.required],
  address:  this.fb.group({                    // nested FormGroup
    street: [''],
    city:   ['']
  }),
  phones:   this.fb.array([                    // FormArray — variable length
    this.fb.control('')
  ])
});

// Access it the same way you'd read the value
form.value;                       // { email, address: {street, city}, phones: [...] }
form.get('address.street')?.value;
form.get('phones') as FormArray;

FormBuilder — the shorthand you'll actually use

❌ Without FormBuilder — verbose

form = new FormGroup({
  email: new FormControl('', [Validators.required]),
  password: new FormControl('', [
    Validators.required, Validators.minLength(8)
  ])
});

✅ With FormBuilder — tidy

form = this.fb.group({
  email: ['', Validators.required],
  password: ['', [Validators.required, Validators.minLength(8)]]
});

Same thing. [value, validators] tuples instead of new FormControl(...) calls.

Custom validators — sync & async

// Sync — returns null (valid) or an errors object (invalid)
export function noWhitespace(ctrl: AbstractControl): ValidationErrors | null {
  return ctrl.value?.includes(' ') ? { whitespace: true } : null;
}

// Factory — for parameterized validators
export function forbiddenName(name: string): ValidatorFn {
  return (ctrl) => ctrl.value === name ? { forbidden: { value: name } } : null;
}

// Async — returns Observable<ValidationErrors | null>
@Injectable({ providedIn: 'root' })
export class UsernameAvailableValidator {
  private api = inject(UserService);

  validate = (ctrl: AbstractControl): Observable<ValidationErrors | null> =>
    this.api.checkUsername(ctrl.value).pipe(
      map(taken => taken ? { usernameTaken: true } : null),
      catchError(() => of(null))   // network error = let user submit
    );
}

// Wire it up — async validators go in the 3rd position
username: ['', [Validators.required], [this.usernameValidator.validate]]
//             ↑ sync validators            ↑ async validators

Control state — what every property means

PairMeaningTriggers
valid / invalidPasses all validators?Updates as user types
pristine / dirtyHas the user changed the value at all?Becomes dirty on first programmatic OR user change
untouched / touchedHas the field lost focus at least once?Becomes touched on blur
pendingAsync validator is runningUseful for showing a spinner
disabled / enabledWhether the user can interact / validators runSet via .disable() / .enable()

UX rule: only show errors after touched (user has blurred the field) — otherwise every field flashes red the moment the form loads.

valueChanges & statusChanges — forms as streams

Every control and form group exposes valueChanges (Observable of values) and statusChanges (Observable of validity status). Combine with RxJS for live previews, auto-save, etc. 

// Auto-save 500ms after the user stops typing
ngOnInit() {
  this.form.valueChanges.pipe(
    debounceTime(500),
    filter(() => this.form.valid),
    switchMap(value => this.api.saveDraft(value)),
    takeUntilDestroyed(this.destroyRef)
  ).subscribe();
}

// React to one field changing — disable city if country isn't selected
this.form.get('country')!.valueChanges.subscribe(country => {
  const city = this.form.get('city')!;
  country ? city.enable() : city.disable();
});

FormArray — dynamic add/remove of fields

form = this.fb.group({
  name: [''],
  phones: this.fb.array([ this.fb.control('') ])
});

get phones() { return this.form.get('phones') as FormArray; }

addPhone()    { this.phones.push(this.fb.control('', Validators.required)); }
removePhone(i: number) { this.phones.removeAt(i); }

<!-- template -->
<div formArrayName="phones">
  <div *ngFor="let p of phones.controls; let i = index">
    <input [formControlName]="i" />
    <button (click)="removePhone(i)">×</button>
  </div>
  <button (click)="addPhone()">+ add phone</button>
</div>

Patching values — patchValue vs setValue

// setValue — must provide EVERY field. Errors if a key is missing.
this.form.setValue({
  email: 'bob@x.com',
  password: '12345678',
  confirm: '12345678',
  age: 30
});

// patchValue — partial update. Missing fields stay as-is.
this.form.patchValue({ email: 'new@x.com' });   // just updates email

// Reset to initial — clears values, marks pristine/untouched
this.form.reset();
this.form.reset({ email: 'preset@x.com' });   // with new initial values

Use patchValue 99% of the time. setValue's strictness is occasionally useful but mostly just trips you up.

Common patterns

Show error only when touched

<small *ngIf="
  form.get('email')?.touched &&
  form.get('email')?.errors?.['required']">
  Email is required.
</small>

Disable submit unless valid

<button
  [disabled]="form.invalid || form.pending">
  Submit
</button>

Mark-all-touched on submit attempt

onSubmit() {
  if (this.form.invalid) {
    this.form.markAllAsTouched();  // reveal every error
    return;
  }
  ...
}

Mental model

1. Form lives in TS

The FormGroup in your class IS the form. The template just binds inputs to it. The form has a life independent of the DOM.

2. Validators are pure functions

Take a control, return null (valid) or an errors object. Composable, testable, no decorators needed.

3. Forms are streams

valueChanges and statusChanges let you compose form state with RxJS — auto-save, live preview, conditional enable/disable.

4. Only show errors on touched

UX rule that makes the difference between "obnoxious form" and "calm form". Pair with markAllAsTouched() on submit.
