2 — Goals vs Phases

Phase

A named point in the build lifecycle. Running mvn package runs ALL phases from validate up to and including package. You never skip a phase in between.

Goal

A specific task performed by a plugin. Written as plugin:goal — e.g., compiler:compile. Goals are bound to phases. You can also invoke goals directly: mvn spring-boot:run.

# Running a phase runs everything up to and including that phase:
mvn test
→ validate → compile → test

mvn package
→ validate → compile → test → package

# Running a plugin goal directly (doesn't run lifecycle phases):
mvn spring-boot:run
mvn dependency:tree

3 — Commands You'll Use Daily

mvn cleanDeletes the target/ directory. Always run before a full rebuild.
mvn compileCompiles src/main/java to target/classes/.
mvn testCompiles + runs all JUnit tests in src/test/java.
mvn packageCompiles + tests + creates the JAR in target/.
mvn installPackage + copies the JAR to your local ~/.m2/repository so other local projects can use it.
mvn clean packageThe most common combo — clean slate then full build. Runs clean lifecycle then default lifecycle.
mvn package -DskipTestsBuild the JAR but skip running tests. Faster, but don't do this in CI/CD.
mvn dependency:treePrint the full dependency tree. Use to debug version conflicts and transitive dependencies.
mvn spring-boot:runCompile and run a Spring Boot app without packaging it first. Great for local development.

4 — The Clean Lifecycle

Maven has three separate lifecycles. The clean lifecycle deletes build output. The default lifecycle builds. The site lifecycle generates documentation.

Clean Lifecycle

pre-clean → clean → post-clean

mvn clean runs the clean lifecycle and deletes target/. mvn clean package runs clean first, then the default lifecycle.

Why clean matters

Without clean, old compiled classes stay in target/. If you rename a class, the old .class file lingers and can cause subtle "it worked yesterday!" bugs. Always mvn clean when troubleshooting mystery build failures.
