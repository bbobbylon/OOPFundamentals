Maven Build Lifecycle

What happens when you type mvn package — phase by phase.

🏗️ What is the Maven build lifecycle — and what happens between mvn validate and mvn deploy?

Maven's build lifecycle is a fixed sequence of phases; mvn package runs every phase from validate through package, and plugin goals bind to phases. There are three lifecycles: default (compile→test→package→install→deploy), clean, and site. Key default phases in order: validate, compile (src→target/classes), test (Surefire), package (the fat JAR), verify (Failsafe integration tests), install (to ~/.m2), deploy (to Nexus/Artifactory). Annotation processors (Lombok/MapStruct) run at generate-sources. Skip flags differ: -DskipTests skips running tests but still compiles them; -Dmaven.test.skip=true skips both.

  • Phases run in sequence — mvn package runs validate→package.
  • Three lifecycles — default, clean, site; goals bind to phases.
  • compile→test→package→verify→install→deploy — local ~/.m2 then remote.
  • -DskipTests skips running; -Dmaven.test.skip skips compile + run.

Key lifecycle commands

# Runs: validate → compile → test → package mvn package # Skip tests (but still compile them): mvn package -DskipTests # Skip test compile AND run: mvn package -Dmaven.test.skip=true # Run up to compile only: mvn compile # Install to local ~/.m2 repo: mvn install # Now other local projects can depend on this # Clean first (remove target/ dir): mvn clean package # Always clean before final builds to avoid # stale compiled classes causing subtle bugs # Run from module root in multi-module: mvn install -pl ciam-auth -am # -pl = projects (module name) # -am = also make (build deps first)

Plugin goal binding

# Plugins bind their goals to lifecycle phases: # compile phase → maven-compiler-plugin:compile # test phase → maven-surefire-plugin:test # package phase → spring-boot-maven-plugin:repackage # + maven-jar-plugin:jar # Run a plugin goal directly (any phase): mvn dependency:tree # show dep tree mvn dependency:resolve # download all deps mvn flyway:migrate # run DB migrations mvn spring-boot:run # run app (dev mode) mvn checkstyle:check # code style check mvn versions:display-updates # show available updates # Run with verbose output: mvn package -X # debug logging # Offline mode (no internet): mvn package -o # use local cache only # Profile activation: mvn package -Pprod # activate prod profile

2 — Goals vs Phases

Phase

A named point in the build lifecycle. Running mvn package runs ALL phases from validate up to and including package. You never skip a phase in between.

Goal

A specific task performed by a plugin. Written as plugin:goal — e.g., compiler:compile. Goals are bound to phases. You can also invoke goals directly: mvn spring-boot:run.

# Running a phase runs everything up to and including that phase:
mvn test
→ validate → compile → test

mvn package
→ validate → compile → test → package

# Running a plugin goal directly (doesn't run lifecycle phases):
mvn spring-boot:run
mvn dependency:tree

3 — Commands You'll Use Daily

mvn cleanDeletes the target/ directory. Always run before a full rebuild.
mvn compileCompiles src/main/java to target/classes/.
mvn testCompiles + runs all JUnit tests in src/test/java.
mvn packageCompiles + tests + creates the JAR in target/.
mvn installPackage + copies the JAR to your local ~/.m2/repository so other local projects can use it.
mvn clean packageThe most common combo — clean slate then full build. Runs clean lifecycle then default lifecycle.
mvn package -DskipTestsBuild the JAR but skip running tests. Faster, but don't do this in CI/CD.
mvn dependency:treePrint the full dependency tree. Use to debug version conflicts and transitive dependencies.
mvn spring-boot:runCompile and run a Spring Boot app without packaging it first. Great for local development.

4 — The Clean Lifecycle

Maven has three separate lifecycles. The clean lifecycle deletes build output. The default lifecycle builds. The site lifecycle generates documentation.

Clean Lifecycle

pre-clean → clean → post-clean

mvn clean runs the clean lifecycle and deletes target/. mvn clean package runs clean first, then the default lifecycle.

Why clean matters

Without clean, old compiled classes stay in target/. If you rename a class, the old .class file lingers and can cause subtle "it worked yesterday!" bugs. Always mvn clean when troubleshooting mystery build failures.
