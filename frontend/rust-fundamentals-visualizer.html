Rust Fundamentals — Ownership, Borrowing & the Borrow Checker

Rust gives you C-level performance and memory safety without a garbage collector. The trick is ownership: a compile-time discipline — enforced by the borrow checker — that guarantees no dangling pointers, no double-frees, and no data races, all before your program ever runs.

🦀 What is Rust — and how does it get safety without a GC?

Rust is a systems language that achieves memory safety at compile time instead of with a garbage collector or manual malloc/free. The core idea is ownership: every value has exactly one owner (a variable), and when the owner goes out of scope the value is automatically dropped (freed) — deterministically, no GC pause. Assigning or passing a non-Copy value moves ownership, and the old binding becomes invalid, so two variables can never both free the same memory. To use a value without taking ownership you borrow it with a reference: you may have either any number of shared &T references or exactly one mutable &mut T reference — never both at once. That single rule (aliasing xor mutation) is what makes data races impossible. The borrow checker enforces all of this statically, rejecting use-after-move, dangling references, and unsynchronized shared mutation as compile errors. On top sit traits (Rust's interfaces, the basis of generics), and two enums that replace null and exceptions: Option<T> (a value or None — there is no null) and Result<T, E> (success or a typed error — errors are values you handle with match or ?). The payoff is C/C++ speed with the safety of a managed language; the cost is a steeper learning curve as you internalize the borrow checker.

  • Ownership — one owner per value; dropped automatically at end of scope (no GC).
  • Move — assigning/passing a value transfers ownership; the old binding is invalid.
  • Borrowing — many &T OR one &mut T, never both: aliasing xor mutation.
  • No null, no exceptions — Option<T> replaces null; Result<T,E> makes errors values.

Ownership & move

let s1 = String::from("hi"); let s2 = s1; // ownership MOVES to s2 // println!("{s1}"); // ❌ compile error: s1 moved fn takes(s: String) { } takes(s2); // s2 moved into the fn // s2 is now invalid too let n = 5; let m = n; // i32 is Copy → both valid

Borrowing & Result/Option

fn len(s: &String) -> usize { s.len() } // borrow let s = String::from("hi"); let n = len(&s); // lend it; s still owns it fn find(id: u32) -> Option<User> { … } match find(7) { Some(u) => println!("{u.name}"), None => println!("not found"), }

Java / Spring comparison

No GC: memory is freed deterministically when the owner drops (RAII), unlike Java's tracing collector. Move semantics have no Java analog — Java copies references and the GC sorts out lifetimes. Traits ≈ interfaces (with default methods) and power generics like Java's. Option<T> ≈ Optional<T> but enforced — there is no null. Result<T,E> ≈ checked exceptions, but errors are ordinary values you must handle. The borrow checker catches at compile time what would be a NullPointerException / ConcurrentModificationException at runtime in Java.

Rust in a CIAM world: Rust shows up where identity infrastructure needs to be fast and bulletproof — token-introspection services, high-throughput JWT verification gateways, crypto-heavy auth proxies. Option/Result force you to handle "claim missing" and "signature invalid" explicitly: a forgotten case is a compile error, not a production 500. The borrow checker rules out the data races that plague concurrent session stores. And because there is no GC, latency is predictable — valuable for an auth service on the hot path of every request. 1. Move semantics: one owner at a time

let s1 = String::from("hi"); // s1 owns the heap buffer
let s2 = s1; // ownership MOVES s1 → s2
// println!("{s1}"); // ❌ error[E0382]: borrow of moved value: s1
println!("{s2}"); // ✅ s2 is the sole owner
Move, not shallow-copy. Assigning a String (which owns a heap buffer) transfers ownership rather than aliasing it. The compiler invalidates s1 so the buffer has exactly one owner — guaranteeing it is freed exactly once. Simple Copy types (i32, bool, char) are bit-copied instead, so both bindings stay valid.

2. Borrowing: aliasing XOR mutation

let mut v = vec![1, 2, 3];
let a = &v; // shared borrow
let b = &v; // ✅ many shared borrows are fine (read-only)
// let c = &mut v; // ❌ cannot borrow `v` as mutable while shared refs live
println!("{a:?} {b:?}");
let c = &mut v; // ✅ now allowed — a and b are no longer used
c.push(4);

At any point you may have either any number of shared &T references or exactly one mutable &mut T — never both. This single rule eliminates data races and iterator-invalidation bugs at compile time. (Non-lexical lifetimes let c borrow once a/b are last used.)

3. No null, no exceptions — Option & Result

fn find_user(id: u32) -> Option<User> { /* Some(u) or None */ }
fn parse(s: &str) -> Result<u32, ParseIntError> { s.parse() }

match find_user(7) {
  Some(u) => println!("{}", u.name),
  None => println!("no such user"),
}
let n = parse("42")?; // ? unwraps Ok, or returns the Err early
Errors are values, absence is a type. Rust has no null — a maybe-missing value is Option<T>, and the compiler forces you to handle None. Fallible operations return Result<T, E>; the ? operator propagates errors up concisely (like rethrowing a checked exception, but explicit). A forgotten case won't compile — the class of NullPointerException simply doesn't exist.
