Classes Deep — #private vs private, Param Props & this Types

The Classes page shows the surface syntax. This companion goes to the runtime: what TypeScript erases, what actually enforces privacy, how parameter properties desugar, and how a class can stay type-safe across subclasses with this types.

1. The big one: private is a compile-time lie; #private is real

TS private — erased

private/protected/public are TypeScript-only. They're checked by the compiler and then completely erased — at runtime the field is an ordinary, fully-readable property.

class Session {
  private token = "s3cr3t";
}
const s = new Session();
s.token;            // ❌ compile error
(s as any).token;   // ✅ "s3cr3t" at runtime 😱
JSON.stringify(s); // {"token":"s3cr3t"} — it leaks

JS #private — enforced

#name is a real JavaScript private field. It's invisible outside the class at runtime too — not enumerable, not in JSON.stringify, and accessing it from outside is a hard SyntaxError.

class Session {
  #token = "s3cr3t";
}
const s = new Session();
s.#token;           // ❌ SyntaxError (even in plain JS)
(s as any).#token; // can't — # isn't dynamic
JSON.stringify(s); // {} — truly hidden ✅

3. Both keywords also make the class nominal

TypeScript is normally structural — same shape ⇒ interchangeable. But a class with a private or # member becomes effectively nominal: only instances of that exact declaration are assignable, because the private member is unique to it.

class Apple { private seeds = 5; }
class Pear  { private seeds = 5; }   // identical shape

let a: Apple = new Pear();    // ❌ private 'seeds' come from different declarations

// #private brands even harder — the brand check is a runtime operator:
class Box {
  #brand!: void;
  static is(x: unknown): x is Box { return #brand in (x as any); }
}

This is the cleanest way to get Java-style "must be exactly this type" identity out of a structural system — see also branded primitives on the Structural-typing page.

4. Parameter properties — the constructor shorthand

What you write

Put an access modifier (or readonly) on a constructor parameter and TS declares the field and assigns it for you. This is everywhere in Angular services (injected deps).

class UserService {
  constructor(
    private http: HttpClient,
    readonly base: string,
  ) {}
  load() { return this.http.get(this.base); }
}

What it desugars to

class UserService {
  private http: HttpClient;
  readonly base: string;
  constructor(http: HttpClient, base: string) {
    this.http = http;   // generated
    this.base = base;   // generated
  }
}

A parameter with no modifier stays an ordinary local param — no field is created. The modifier is the trigger.

5. abstract classes & implements vs extends

abstract — a base you can't new

abstract class Shape {
  abstract area(): number;   // no body — subclass must supply
  describe() { return `area=${this.area()}`; } // can have real methods + state
}
new Shape();              // ❌ cannot instantiate an abstract class
class Circle extends Shape { area() { return 3.14; } }

Unlike an interface (pure shape, erased), an abstract class can carry implementation and state — pick it when subclasses share code, not just a contract.

implements is a check, not a link

implements only verifies the class structurally matches an interface — it copies nothing and adds no runtime relationship. extends actually inherits members.

interface Logger { log(m: string): void; }

class Console2 implements Logger {
  log(m: string) { console.log(m); }   // must provide it yourself
}
// 'implements' gives you NO inherited code — only a compile-time conformance check.

6. this types — surviving subclassing

Polymorphic this return

Returning this (not the class name) keeps fluent chains typed as the actual subclass, so subclass methods stay reachable mid-chain.

class Builder {
  set(k: string): this { return this; }
}
class FormBuilder extends Builder {
  validate(): this { return this; }
}
new FormBuilder().set("a").validate();
// ✅ set() returns FormBuilder, not Builder → .validate() exists

this is T guards

A method can narrow this to a subtype, so a check unlocks the richer API on the same object.

class Node2 {
  isLeaf(): this is Leaf { return "value" in this; }
}
class Leaf extends Node2 { value = 1; }

if (n.isLeaf()) n.value;  // ✅ n narrowed to Leaf

7. Pitfalls

  • 🔐 Never put secrets in a private field. Tokens, keys, PII in a private property are fully readable at runtime and land in JSON.stringify, logs, and devtools. Use #private (or just don't keep them on the object) — directly relevant to CIAM token handling.
  • Lost this in callbacks. onClick={this.handle} or setTimeout(this.tick) drops the binding. Fix with an arrow class field (handle = () => {…}) which captures this at construction.
  • Field init order with useDefineForClassFields. Modern targets define fields with [[Define]] semantics; a field initializer can't see a value a subclass constructor sets later, and class fields run after super(). Watch initialization that depends on a base-class side effect.
  • #private can't be accessed dynamically. No obj[#x], no reflection — that's the point, but it means you can't enumerate or proxy them.
  • implements ≠ inheritance. It won't give you the interface's (nonexistent) implementation — you must write every member. For shared code, extends a base class.

8. One-sentence recap

private is a compile-time-only modifier that's erased (so secrets in it leak at runtime — use #private, a genuinely hidden JS field), both make a class effectively nominal; parameter properties declare-and-assign a field from a constructor arg; abstract classes carry code+state you can't new while implements is a pure structural check with no inheritance; and this return types + this is T guards keep classes type-safe across subclassing.
