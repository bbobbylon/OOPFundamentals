Angular Lazy Loading, Preloading & @defer

Cut initial bundle size with route-level lazy loading, intelligent preloading strategies, and the @defer block for template-level deferral.

Lazy routes ship as separate JS chunks. On first navigation the router fetches the chunk, evaluates it, creates the component, and renders it. Preloading strategies can fetch chunks in the background after initial load. @defer blocks do the same at the template level. 1. Why Lazy Loading Matters

Every byte of JavaScript the browser downloads must be parsed and compiled before your app is interactive. Lazy loading splits your app into chunks — the browser only downloads what the current page actually needs.

Eager (no lazy)

All code in one main.js. User visiting the login page downloads admin panel, user dashboard, analytics, and settings code they'll never see.

1.4 MB
initial bundle (gzipped)

Route Lazy Loading

Each route is a separate chunk. Login page only downloads main.js + login chunk. Admin downloads lazily when the user navigates there.

280 KB
initial bundle (gzipped)

Lazy + @defer

Routes lazy load AND heavy widgets within pages defer until needed. Chart library only loads when the charts section enters the viewport.

190 KB
initial bundle (gzipped)

2. Route-Level Lazy Loading

loadChildren() — Feature Routes File

// app.routes.ts
export const routes: Routes = [
  { path: '', component: HomeComponent },

  // Lazy feature — downloads admin.chunk.js
  // only when user navigates to /admin
  {
    path: 'admin',
    loadChildren: () =>
      import('./admin/admin.routes')
        .then(r => r.ADMIN_ROUTES)
  },

  // With route-level providers
  {
    path: 'store',
    loadChildren: () =>
      import('./store/store.routes')
        .then(r => r.STORE_ROUTES),
    providers: [CartService]  // scoped to store
  }
];

loadComponent() — Single Component

// For standalone components — no routes file needed
const routes: Routes = [
  {
    path: 'profile',
    loadComponent: () =>
      import('./profile/profile.component')
        .then(c => c.ProfileComponent)
  },
  {
    path: 'settings',
    loadComponent: () =>
      import('./settings/settings.component')
        .then(c => c.SettingsComponent)
  }
];

// Even shorter — if default export:
{
  path: 'about',
  loadComponent: () => import('./about.component')
}

3. Preloading Strategies

Preloading downloads lazy chunks in the background after the initial page is interactive. The user already has the chunk cached when they navigate — feels instant.

StrategyBehaviorBest For
NoPreloadingNever preload — chunks download on demandData-saver users, low-bandwidth sites
PreloadAllModulesEagerly preload every lazy chunk after bootstrapSmall apps where all routes likely to be visited
Custom strategyPreload only routes with data.preload: trueLarge apps — preload critical paths only
QuicklinkStrategyPreload routes whose links are visible on screenApps with heavy navigation menus

Built-in: PreloadAllModules

import { PreloadAllModules } from '@angular/router';

provideRouter(routes,
  withPreloading(PreloadAllModules)
)

Custom Preloading Strategy

@Injectable({ providedIn: 'root' })
export class SelectivePreloadStrategy
  implements PreloadingStrategy {

  preload(route: Route,
          load: () => Observable<any>
  ): Observable<any> {
    return route.data?.['preload']
      ? load()
      : EMPTY;
  }
}

// Mark critical routes:
{ path: 'dashboard', data: { preload: true },
  loadChildren: ... }

4. @defer Block — Template-Level Deferral

@defer is a template syntax for lazy loading a chunk of UI. It uses IntersectionObserver, IdleCallback, and other browser APIs natively — no manual setup needed.

Anatomy of a @defer Block

@defer (on viewport) {
  <!-- Heavy chart component — only downloaded when scrolled into view -->
  <app-analytics-chart [data]="chartData" />
}
@placeholder {
  <!-- Shown immediately, before the deferred content loads -->
  <div class="chart-skeleton"></div>
}
@loading (minimum 300ms; after 100ms) {
  <!-- Shown while the JS chunk is downloading -->
  <!-- minimum: show for at least 300ms (prevents flash) -->
  <!-- after: only show if loading takes longer than 100ms -->
  <app-spinner />
}
@error {
  <!-- Shown if the chunk fails to download -->
  <p>Failed to load chart.</p>
}

All Trigger Types

on idle

Load when browser has no pending work. Uses requestIdleCallback.

on viewport

Load when element enters the visible viewport. Uses IntersectionObserver.

on interaction

Load on first click or focus event on the placeholder.

on hover

Load when the user hovers over the placeholder element.

on timer(2000)

Load after a fixed delay (ms). Simple time-based approach.

when condition

Load when an expression/signal becomes truthy. Most flexible.

Select a trigger above to see how @defer responds to it.

Prefetch vs Defer

// @defer with prefetch — downloads the JS early, renders later
@defer (on viewport; prefetch on idle) {
  <app-heavy-widget />
}
// prefetch on idle: JS chunk downloads when browser is idle
// on viewport: component is RENDERED only when scrolled into view
// The chunk is already in cache, so render is instantaneous

@defer vs Route Lazy Loading — When to Use Each

Route Lazy Loading@defer Block
GranularityWhole page/feature at route levelIndividual component within a page
TriggerNavigation eventviewport, idle, hover, interaction, timer, signal
PlaceholderRoute loading indicator@placeholder, @loading, @error blocks
Use forAdmin panels, feature areas, separate pagesHeavy widgets, below-fold content, rare features
