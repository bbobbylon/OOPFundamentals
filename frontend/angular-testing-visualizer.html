Testing

TestBed, ComponentFixture, spies, fakeAsync, marble tests, and how to know what kind of test to write. The Angular testing playbook. For the modern runner specifically — .spec.ts, vi mocks, watch mode, coverage — see Vitest & .spec.ts. For the top tier of the pyramid — a real browser, a real flow — see E2E Testing (Playwright & Cypress).

🧪 What do you test in Angular — and what can you skip?

Angular testing has three tiers. Unit tests (fastest) check services, guards, resolvers, validators, and pipes in isolation — no DOM, no module, just new MyService() or inject(). Component tests (medium) use TestBed.createComponent() to render into a real DOM fragment and verify bindings + output, mocking HTTP. Integration/E2E (slowest) drive full flows in a real browser (Playwright/Cypress). The golden rule: test behaviour, not implementation — assert the page shows the data, not that ngOnInit called a service.

  • Push logic into pure, injectable pieces (services, guards, validators) so most of it unit-tests with no Angular at all.
  • TestBed builds a mini Angular module; ComponentFixture renders the component and detectChanges() runs change detection.
  • Control async with fakeAsync + tick() (advance the fake clock) — far cleaner than done() callbacks.
  • Mock collaborators with spies (spyOn(...).and.returnValue(of(...))); mock HTTP with HttpTestingController.
  • Spend most effort on the cheap tiers; reserve a few E2E tests for the critical happy paths (login, create user).

TestBed + ComponentFixture

TestBed.configureTestingModule({ imports: [MyComponent], providers: [{ provide: AuthStore, useClass: MockAuthStore }] }); fixture = TestBed.createComponent(MyComponent); fixture.detectChanges(); then query fixture.nativeElement.querySelector(...) and assert.

fakeAsync + tick

Wrap with fakeAsync(() => { … }) to control time. tick(1000) fires any setTimeout/timer synchronously; flushMicrotasks() resolves Promises; flush() drains all pending timers. Great for debounce.

Spies + HTTP testing

spyOn(service, 'getUsers').and.returnValue(of([{ id: '1' }])). For HTTP, provide provideHttpClientTesting(), inject HttpTestingController, then httpMock.expectOne('/api/users').flush(mockUsers) — total control over the "server."

In CIAM:unit-test authGuard by calling it with a mocked AuthStore and asserting it returns a UrlTree to /login; component-test the user list by mocking UserApi.getUsers → of([mockUser]) and asserting one table row; E2E-test logging in as admin and seeing the delete button at /admin/users.

1. Unit test — a pure service (no DOM, no HTTP)

The simplest test: instantiate the service, call methods, assert results.

// counter.service.ts
@Injectable({ providedIn: 'root' })
export class CounterService {
  private count = 0;
  get()       { return this.count; }
  increment() { this.count++; }
  reset()     { this.count = 0; }
}

// counter.service.spec.ts
import { TestBed } from '@angular/core/testing';
import { CounterService } from './counter.service';

describe('CounterService', () => {
  let service: CounterService;

  beforeEach(() => {
    TestBed.configureTestingModule({});            // fresh DI tree per test
    service = TestBed.inject(CounterService);
  });

  it('starts at zero', () => {
    expect(service.get()).toBe(0);
  });

  it('increments by one', () => {
    service.increment();
    service.increment();
    expect(service.get()).toBe(2);
  });

  it('resets to zero', () => {
    service.increment();
    service.reset();
    expect(service.get()).toBe(0);
  });
});
The 3 A's of every test: Arrange (set up state), Act (do the thing), Assert (check the result). One concept per test. If your test has 5 expects, it's probably testing 5 things — split it.

2. Component test — TestBed + ComponentFixture

For components, you need a fixture — it instantiates the component, hands you the host element, and lets you trigger change detection.

// greet.component.ts
@Component({
  selector: 'app-greet',
  standalone: true,
  template: `<h1>Hello, {{ name }}!</h1><button (click)="shout()">!</button>`
})
export class GreetComponent {
  @Input() name = 'World';
  shout() { this.name = this.name.toUpperCase(); }
}

// greet.component.spec.ts
import { ComponentFixture, TestBed } from '@angular/core/testing';
import { By } from '@angular/platform-browser';
import { GreetComponent } from './greet.component';

describe('GreetComponent', () => {
  let fixture: ComponentFixture<GreetComponent>;
  let component: GreetComponent;

  beforeEach(async () => {
    await TestBed.configureTestingModule({
      imports: [GreetComponent]                       // standalone → import it
    }).compileComponents();

    fixture = TestBed.createComponent(GreetComponent);
    component = fixture.componentInstance;
  });

  it('renders default name', () => {
    fixture.detectChanges();                          // trigger change detection
    const h1 = fixture.nativeElement.querySelector('h1');
    expect(h1.textContent).toBe('Hello, World!');
  });

  it('renders the input name', () => {
    component.name = 'Bobby';
    fixture.detectChanges();
    expect(fixture.nativeElement.textContent).toContain('Hello, Bobby!');
  });

  it('shouts when button clicked', () => {
    component.name = 'bobby';
    fixture.detectChanges();
    const btn = fixture.debugElement.query(By.css('button'));
    btn.triggerEventHandler('click', null);
    fixture.detectChanges();
    expect(component.name).toBe('BOBBY');
  });
});
The #1 gotcha: forgetting fixture.detectChanges(). Without it, no template updates happen and your assertions check stale DOM. Always call it after Arrange and after Act.

Two ways to find DOM elements

ApproachBest for
fixture.nativeElement.querySelector('h1')Raw HTMLElement assertions (.textContent, .className)
fixture.debugElement.query(By.css('h1'))Need to dispatch events or read Angular-specific data (component instance, directive)

3. Mocking a dependency with a spy

When your component uses a service, replace the real one with a fake — keeps tests fast and deterministic.

// user-list.component.ts
export class UserListComponent {
  private users = inject(UserService);
  list = this.users.getAll();
}

// user-list.component.spec.ts
describe('UserListComponent', () => {
  let fixture: ComponentFixture<UserListComponent>;
  let userServiceSpy: jasmine.SpyObj<UserService>;

  beforeEach(async () => {
    // Create a fake with the same shape
    userServiceSpy = jasmine.createSpyObj('UserService', ['getAll', 'create']);
    userServiceSpy.getAll.and.returnValue(of([{ id: 1, name: 'Ada' }]));

    await TestBed.configureTestingModule({
      imports: [UserListComponent],
      providers: [
        { provide: UserService, useValue: userServiceSpy }   // swap real for fake
      ]
    }).compileComponents();

    fixture = TestBed.createComponent(UserListComponent);
  });

  it('calls getAll on init', () => {
    fixture.detectChanges();
    expect(userServiceSpy.getAll).toHaveBeenCalledTimes(1);
  });

  it('renders one row per user', () => {
    fixture.detectChanges();
    const rows = fixture.nativeElement.querySelectorAll('.user-row');
    expect(rows.length).toBe(1);
  });
});

Three ways to provide a fake

PatternWhen
useValue: spyObjDefault. Most common. Lets you assert calls.
useClass: MockUserServiceYou want a fully-coded fake (e.g. an in-memory store).
useFactory: () => createMock()Need parameterized fakes per test.

4. Testing HTTP — HttpTestingController

Never let tests hit real HTTP. provideHttpClientTesting() intercepts every call and lets you assert what was sent and reply with whatever you want.

import { provideHttpClient } from '@angular/common/http';
import { HttpTestingController, provideHttpClientTesting }
  from '@angular/common/http/testing';

describe('UserService', () => {
  let service: UserService;
  let httpMock: HttpTestingController;

  beforeEach(() => {
    TestBed.configureTestingModule({
      providers: [
        provideHttpClient(),
        provideHttpClientTesting()                  // intercepts ALL requests
      ]
    });
    service = TestBed.inject(UserService);
    httpMock = TestBed.inject(HttpTestingController);
  });

  afterEach(() => httpMock.verify());          // fails if any request was unmatched

  it('GETs /api/users', () => {
    const fake = [{ id: 1, name: 'Ada' }];
    let result: User[] = [];

    service.getAll().subscribe(users => result = users);

    const req = httpMock.expectOne('/api/users');
    expect(req.request.method).toBe('GET');
    req.flush(fake);                                  // reply with fake data

    expect(result).toEqual(fake);
  });

  it('handles 500 errors', () => {
    let caught: any = null;
    service.getAll().subscribe({ error: e => caught = e });
    httpMock.expectOne('/api/users').flush(
      'Boom', { status: 500, statusText: 'Server Error' }
    );
    expect(caught.status).toBe(500);
  });
});

5. Async tests — fakeAsync & tick

Real setTimeouts slow tests down. fakeAsync swaps in a virtual clock — you control time with tick().

import { fakeAsync, tick, flush, discardPeriodicTasks } from '@angular/core/testing';

it('debounces search input', fakeAsync(() => {
  component.search$ = new Subject<string>();
  let emitted: string[] = [];
  component.search$.pipe(debounceTime(300)).subscribe(v => emitted.push(v));

  component.search$.next('a');
  component.search$.next('ab');
  component.search$.next('abc');

  tick(100);
  expect(emitted.length).toBe(0);              // not yet — still debouncing

  tick(300);
  expect(emitted).toEqual(['abc']);              // only the last one fired
}));
ToolUse
tick(ms)Advance the virtual clock by N ms
flush()Run ALL pending macrotasks (drains setTimeouts)
flushMicrotasks()Drain only Promise .then queue
discardPeriodicTasks()Cancel setIntervals before test ends (else fakeAsync errors)

Or use async + await fixture.whenStable()

it('updates after promise resolves', async () => {
  component.save();
  await fixture.whenStable();         // wait for pending promises
  fixture.detectChanges();
  expect(component.saved).toBe(true);
});

6. Marble tests — RxJS streams over time

For testing complex stream logic, marble syntax expresses time visually. - = 10ms, letters = emissions, | = complete, # = error.

import { TestScheduler } from 'rxjs/testing';
import { map, debounceTime } from 'rxjs';

it('doubles emitted values', () => {
  const scheduler = new TestScheduler((actual, expected) => {
    expect(actual).toEqual(expected);
  });

  scheduler.run(({ cold, expectObservable }) => {
    const source = cold('-a-b-c|', { a: 1, b: 2, c: 3 });
    const result = source.pipe(map(x => x * 2));

    expectObservable(result).toBe('-x-y-z|', { x: 2, y: 4, z: 6 });
  });
});

// Inside scheduler.run, time is FRAME-BASED — each char = 1 frame
// debounceTime(30) needs 3 dashes ('---') between emissions

Marble syntax cheatsheet

CharacterMeaning
-One frame of time (1 virtual ms inside scheduler.run)
a b cEmit a value (looked up in the values map)
|Complete
#Error

^Subscription point (in hot observables)

8. Testing signals (v16+)

import { signal, computed } from '@angular/core';

it('computed re-reads signal', () => {
  const count = signal(2);
  const doubled = computed(() => count() * 2);

  expect(doubled()).toBe(4);
  count.set(5);
  expect(doubled()).toBe(10);
});

// Effects are async — use TestBed + flushEffects or use fakeAsync
import { TestBed } from '@angular/core/testing';
it('effect runs when signal changes', () => {
  TestBed.runInInjectionContext(() => {
    const count = signal(0);
    const spy = jasmine.createSpy();
    effect(() => spy(count()));
    TestBed.flushEffects();
    count.set(1);
    TestBed.flushEffects();
    expect(spy).toHaveBeenCalledTimes(2);
  });
});

9. E2E with Playwright (the modern choice)

E2E drives a real browser. Reserve for critical paths (login → checkout, signup → confirmation). They're slow and flaky — don't write 200 of them.

// e2e/login.spec.ts
import { test, expect } from '@playwright/test';

test('user can log in', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('ada@example.com');
  await page.getByLabel('Password').fill('secret123');
  await page.getByRole('button', { name: 'Sign in' }).click();

  await expect(page).toHaveURL('/dashboard');
  await expect(page.getByText('Welcome, Ada')).toBeVisible();
});
Selector strategy: prefer getByRole / getByLabel / getByText over CSS selectors. They mirror how a screen reader sees the page, double as accessibility audits, and don't break when classnames change.

10. What to test — and what not to

✅ Worth testing

Business logic in services, complex reducers, validators, custom pipes, signal computations, component behavior on user interaction, HTTP error paths.

❌ Not worth testing

Trivial getters, template syntax, Angular itself (don't test that *ngFor works), third-party libraries.

⚠️ Snapshot tests

Use sparingly. They catch unintended visual changes but rot fast — devs end up rubber-stamping them. Prefer behavior assertions.

🎯 Coverage isn't the goal

80% on lies = 0% confidence. Aim for high coverage on critical paths, low coverage on trivial getters. Quality > quantity.

Common bugs & fixes

SymptomCauseFix
"NG0303: Can't bind to 'name' since it isn't a known property"Forgot to import a child component in TestBedAdd it to imports: [...] in the testing module

The mental model: Unit tests for logic. Component tests for behavior. E2E for critical paths. Use TestBed to build a mini Angular module per test, swap real services for spies, control time with fakeAsync, intercept HTTP with HttpTestingController. Don't chase coverage — chase confidence.
