Debugging ExpressionChangedAfterItHasBeenChecked

This dev-only error sounds cryptic but says something precise: a bound value changed after Angular had already checked it in this same tick. In dev, Angular runs a second "verify" pass right after change detection; if a value differs between the two passes, it throws — because in production (no verify pass) that difference would silently render stale or inconsistent UI. The error is a gift: it's catching a real data-flow bug.

What causes ExpressionChangedAfterItHasBeenChecked — and how do you fix it?

In development mode, Angular runs change detection twice per tick — the real check, then an immediate "verify" check. If a bound value is different in the second check than it was in the first, Angular throws ExpressionChangedAfterItHasBeenCheckedError. This means something modified the bound value as a side effect of change detection itself: a lifecycle hook mutated a signal, a getter computed a new object every call, or a parent read a child's value that changed during the parent's own check. The error never appears in production (no second pass), so apps can silently show stale data without it. Fix the root cause — don't silence it with detectChanges().

Root cause #1: getter creates new objects

get users() { return this.rawUsers.map(u => ({...u, display: u.name.toUpperCase()})) } — every call creates a new array reference. Angular checks the template binding in pass 1 (array ref = X), runs CD, then checks again in pass 2 (array ref = Y — new array from second getter call). Fix: use a computed() signal or memoize the getter.

Root cause #2: lifecycle hook mutation

ngAfterViewInit() { this.title = 'Ready' } — ngAfterViewInit fires during the CD pass after the view check. Setting a bound property here triggers the error. Fix: wrap in Promise.resolve().then(() => this.title='Ready') (defers to next tick) or use afterNextRender() / move the logic to ngOnInit.

Root cause #3: parent reads child state

A parent template reads {{child.someValue}} after the child's own ngOnInit set it. During pass 1, parent reads the value. During the child's CD, the child sets it. Pass 2: parent reads it again — different. Fix: the child should emit an @Output event instead; parent stores it in its own field. Data flows down, events flow up.

Quick debug: The error message includes the expression that changed and the component it came from. Look at what that expression returns — if it's a function call or getter that returns a new object/array, that's your culprit. Wrap in computed() for signals, or cache the result in ngOnInit for plain properties. Never wrap in ChangeDetectorRef.detectChanges() as a shortcut — it hides the bug without fixing it.

1. What the error actually means

One change-detection tick, two passes (dev only):

CD pass 1  → read title = ''      → render
verify pass → read title = 'loaded'  → changed! throw

Translation: something mutated state that the view already read, during the same tick. Angular won't re-render within one tick, so prod would show '' while your data says 'loaded'. Fix the timing, don't silence the check.

2. Interactive: which pattern triggered it?

Each runs the two passes and shows the value mismatch Angular detected — plus the fix that removes the mid-tick change.

3. The fixes (by cause)

CauseFix
Mutating in a late hook (ngAfterViewInit)move it to ngOnInit, or defer one tick: Promise.resolve().then(...) / queueMicrotask
Getter returns a new reference each callcompute once (a field, a computed() signal, or memoize) so the reference is stable
Child mutates parent synchronously during CDemit asynchronously, or update through a signal/store the parent reads
Binding to a value that changes every readsnapshot it once into a field; don't bind Math.random()/Date.now()

Signals largely make this disappear: a signal/computed has a stable value within a tick and schedules updates properly, so you stop fighting the verify pass. The nuclear option cdr.detectChanges() inside the hook usually hides the bug rather than fixing it.

4. Adjacent CD bugs worth knowing

  • OnPush component won't update. You mutated an object (user.name = …) instead of replacing the reference. OnPush compares references — assign a new object/array, or use signals.
  • Nothing updates after an async callback (outside Angular's zone, or zoneless). Use signals, async pipe, or cdr.markForCheck().
  • "Why did this re-render?" Use the Angular DevTools profiler to see which component checked and why.

5. One-sentence recap

🔁 ExpressionChangedAfterItHasBeenChecked is a dev-only verify pass catching a value that changed after Angular checked it in the same tick (which prod would render stale) — so find the mid-tick mutation: a write in a late lifecycle hook, a getter returning a new reference each call, a child mutating the parent synchronously, or binding a value that changes every read — and fix the timing (move to ngOnInit, defer a tick, or use signals) rather than silencing it with detectChanges().
