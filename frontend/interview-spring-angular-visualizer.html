Spring Boot, Angular & Java — Interview Cheatsheets

Quick-reference cards, animated walkthroughs, and structured Q&A for Spring Boot, Angular, core Java features, and behavioral interviews.

What does a Spring Boot + Angular interview test — and what are the 10 questions you absolutely must be able to answer cold?

Spring Boot and Angular interviews for full-stack roles combine framework knowledge, architectural understanding, and the ability to reason about integration. Interviewers are checking whether you understand WHY the framework is designed the way it is, not just whether you can copy code. Spring Boot must-know topics: Auto-configuration (how does @SpringBootApplication scan and configure beans?), Dependency Injection (constructor vs setter vs field — always prefer constructor injection; it enables testing without a Spring context and makes required dependencies explicit). Spring Security filter chain (how does a request flow through UsernamePasswordAuthenticationFilter, JwtAuthenticationFilter, etc.). Transaction management (@Transactional — what does it actually do? It wraps the method in an AOP proxy that begins a transaction before the method and commits/rolls back after. PROPAGATION_REQUIRED = join existing or create new. PROPAGATION_REQUIRES_NEW = always new. ISOLATION level controls what concurrent transactions can see). Spring Data JPA (JpaRepository auto-generates queries from method names: findByEmailAndActive(String email, boolean active) becomes SELECT * FROM users WHERE email=? AND active=?). Angular must-know topics: Component lifecycle hooks (@Input change detection, ngOnInit for API calls, ngOnDestroy for cleanup and unsubscribing Observables to prevent memory leaks). Angular Change Detection (Default vs OnPush — OnPush only re-renders when @Input references change or an Observable emits via AsyncPipe; Default re-renders on any event). RxJS Observables (the difference between map, switchMap, mergeMap, concatMap — switchMap cancels the inner Observable when a new outer value arrives, ideal for HTTP search autocomplete). HTTP Interceptors (how to add Auth headers to every request and handle 401 refreshes). Lazy loading (RouterModule.forChild() — load a feature module only when its route is activated, reducing initial bundle size). Integration topics: CORS (why it's needed, how Spring Boot configures it, why the Angular OPTIONS preflight happens). JWT in the Authorization header (Angular interceptor puts it there; Spring Boot's SecurityFilter extracts it). OAuth2 refresh flow (when does the refresh happen? Who triggers it? What happens if the refresh token is also expired?). Behavioral preparation: STAR format (Situation, Task, Action, Result). Questions like "Tell me about a time you debugged a production issue" or "Describe a system you designed that scaled." Prepare 3-4 specific stories from your CIAM work — debugging an OAuth flow failure, designing the provisioning pipeline, optimizing a slow API endpoint.

Spring Boot — Core Concepts

IoC and Dependency Injection

// IoC: Spring manages object lifecycle, not you // DI: Dependencies are injected, not created inside // Three ways to inject: @Service public class OrderService { // 1. Constructor injection (PREFERRED) private final OrderRepository repo; public OrderService(OrderRepository repo) { this.repo = repo; // immutable, testable } // 2. Field injection (@Autowired) — not recommended @Autowired PaymentService paymentService; // 3. Setter injection — for optional deps @Autowired(required = false) public void setEmailService(EmailService e) { this.emailService = e; } }
Best practice: Constructor injection is preferred. Makes dependencies explicit, class easily unit-testable (just pass mocks), and fields can be final (immutable).

@Transactional — Deep Dive

@Service public class TransferService { @Transactional public void transfer(long from, long to, double amount) { accountRepo.debit(from, amount); accountRepo.credit(to, amount); // If ANY exception: both ops rolled back // Spring wraps the method in a proxy! } // Propagation examples: @Transactional(propagation = Propagation.REQUIRES_NEW) public void auditLog(String msg) { // Always in its own transaction // Survives outer rollback } @Transactional(readOnly = true) public Order findById(long id) { // Hint to DB: no writes, optimize reads // JPA: disables dirty checking (faster) } }

Propagation Levels

PropagationBehavior
REQUIRED (default)Join existing tx, or create new if none
REQUIRES_NEWAlways create new tx, suspend outer
SUPPORTSJoin if exists, proceed without if none
NOT_SUPPORTEDSuspend tx if exists, run without
MANDATORYMust have existing tx, else exception
NEVERMust NOT be in tx, else exception
NESTEDNested tx with savepoint inside outer
Self-invocation problem: Calling a @Transactional method from within the same class bypasses the Spring proxy — @Transactional has NO effect on self-calls. The proxy is only invoked from external callers.

JPA vs Hibernate & Auto-Configuration

JPA vs Hibernate

JPA (Java Persistence API) is a specification — defines the standard interfaces (@Entity, @OneToMany, EntityManager, JPQL). It's an API, not an implementation.

Hibernate is the most popular implementation of JPA. Spring Boot uses Hibernate by default when you include spring-boot-starter-data-jpa.

You code against JPA interfaces. Hibernate provides the SQL translation, caching, connection pooling.
@Entity @Table(name = "orders") public class Order { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, fetch = FetchType.LAZY) private List<OrderItem> items; }

Spring Boot Auto-Configuration

@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan. Spring Boot reads META-INF/spring/auto-configuration files, applies each @ConditionalOn... condition.

// Auto-config applies IF conditions met: @ConditionalOnClass(DataSource.class) // only if DataSource is on classpath @ConditionalOnMissingBean(DataSource.class) // only if user hasn't defined their own @ConditionalOnProperty( name = "spring.datasource.url") // only if property is set // See what got applied: // --debug flag prints auto-config report // Actuator: GET /actuator/conditions
Security Filter Chain: Spring Security intercepts requests via a chain of filters (SecurityFilterChain). Key filters: UsernamePasswordAuthenticationFilter, JwtAuthenticationFilter (custom), ExceptionTranslationFilter, FilterSecurityInterceptor (authorization). Order matters — configure with HttpSecurity.

Angular — Core Concepts

Change Detection

Angular detects UI changes by checking if component data has changed. Default: check entire component tree. OnPush: check only when inputs change or an Observable emits.

// Default: CD runs on every event @Component({ selector: 'app-user', template: `{{user.name}}` }) export class UserComponent {} // OnPush: only when @Input changes or async pipe emits @Component({ selector: 'app-user', template: `{{user.name}}`, changeDetection: ChangeDetectionStrategy.OnPush }) export class UserComponent { @Input() user!: User; // CD runs only when 'user' reference changes // Mutating user.name = 'x' won't trigger CD! } // Force CD manually if needed: constructor(private cdr: ChangeDetectorRef) {} ngOnInit() { this.cdr.detectChanges(); } markForCheck() { this.cdr.markForCheck(); }

NgZone and Signals

// NgZone patches async APIs (setTimeout, fetch, etc.) // to trigger change detection automatically // Run outside zone (no CD trigger): performance constructor(private ngZone: NgZone) {} ngOnInit() { this.ngZone.runOutsideAngular(() => { // high-frequency updates (websocket, mouse) window.addEventListener('mousemove', e => { // won't trigger CD on every move if (needsUpdate) { this.ngZone.run(() => { // back inside zone: triggers CD }); } }); }); } // Angular 17+ Signals: fine-grained reactivity count = signal(0); doubled = computed(() => this.count() * 2); // count() reads, count.set(n) writes // Only components reading signal are re-rendered

AOT vs JIT & ViewEncapsulation

JIT (Just-In-Time): Compiles templates in the browser at runtime. Development mode default. Larger bundle (compiler included), slower startup.

AOT (Ahead-Of-Time): Compiles templates at build time. Production default (ng build). Smaller bundle, faster startup, template errors caught at build, no runtime compiler needed.
// ViewEncapsulation options: @Component({ encapsulation: ViewEncapsulation.Emulated // DEFAULT: adds unique attr selector to styles // Component styles don't leak to children }) @Component({ encapsulation: ViewEncapsulation.None // No encapsulation — styles are global // Useful for theming/global overrides }) @Component({ encapsulation: ViewEncapsulation.ShadowDom // Uses native browser Shadow DOM // True style isolation })

Lambda & Functional Interfaces

// Built-in functional interfaces (java.util.function) Function<String, Integer> len = s -> s.length(); Consumer<String> print = s -> System.out.println(s); Supplier<String> greet = () -> "Hello"; Predicate<Integer> isEven = n -> n % 2 == 0; // BiFunction: two inputs BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b; // Compose functions Function<Integer, Integer> times2 = x -> x * 2; Function<Integer, Integer> plus3 = x -> x + 3; Function<Integer, Integer> times2ThenPlus3 = times2.andThen(plus3); // 5→13 // Method references Function<String, Integer> parse = Integer::parseInt; // static method ref Consumer<String> out = System.out::println; // instance method ref

Stream API

List<Integer> nums = List.of(1,2,3,4,5,6); // filter → map → collect List<String> result = nums.stream() .filter(n -> n % 2 == 0) // 2,4,6 .map(n -> "num:" + n) // map to String .collect(Collectors.toList()); // Terminal operations int sum = nums.stream().reduce(0, Integer::sum); long count = nums.stream().filter(n->n>3).count(); Optional<Integer> max = nums.stream().max(Integer::compare); // Collectors Map<Boolean,List<Integer>> partitioned = nums.stream().collect(Collectors.partitioningBy( n -> n % 2 == 0)); Map<Integer,Long> freq = nums.stream() .collect(Collectors.groupingBy( n -> n % 3, Collectors.counting())); // FlatMap: flatten nested collections List<String> words = sentences.stream() .flatMap(s -> Arrays.stream(s.split(" "))) .collect(Collectors.toList());

Optional & Generics

Optional — Avoiding NullPointerException

// Create Optional<String> opt = Optional.of("hello"); // throws if null Optional<String> nullable = Optional.ofNullable(maybeNull); // safe Optional<String> empty = Optional.empty(); // Use opt.isPresent(); // true opt.isEmpty(); // Java 11+ opt.get(); // throws if empty! opt.orElse("default"); // value or default opt.orElseGet(() -> compute()); // lazy supplier opt.orElseThrow( NoSuchElementException::new); // Chain — like Stream but for one value Optional<Integer> len = opt .filter(s -> s.length() > 3) .map(String::length); // DON'T: use Optional as method parameter or field // DO: use as return type for potentially absent values

Generics

// Generic method public <T> T firstOrDefault( List<T> list, T def) { return list.isEmpty() ? def : list.get(0); } // Bounded wildcards // <? extends T> — producer (read only) public double sum(List<? extends Number> list) { return list.stream() .mapToDouble(Number::doubleValue).sum(); } // <? super T> — consumer (write) public void addNumbers(List<? super Integer> list) { list.add(1); list.add(2); } // PECS: Producer Extends, Consumer Super // Type erasure: generics are compile-time only // At runtime, List<String> = List<Object> // Cannot do: new T[], instanceof T

Exceptions — Checked vs Unchecked

// Hierarchy: // Throwable // Error (OutOfMemoryError, StackOverflowError) // Exception // RuntimeException (unchecked) // NullPointerException // IllegalArgumentException // ArrayIndexOutOfBoundsException // IOException (checked) // SQLException (checked) // Custom exceptions public class OrderNotFoundException extends RuntimeException { private final long orderId; public OrderNotFoundException(long orderId) { super("Order not found: " + orderId); this.orderId = orderId; } }

try-with-resources (Java 7+)

// Automatically closes AutoCloseable resources try (InputStream is = new FileInputStream("file.txt"); BufferedReader br = new BufferedReader( new InputStreamReader(is))) { String line; while ((line = br.readLine()) != null) { process(line); } } catch (IOException e) { log.error("Failed to read file", e); } // Both br and is closed automatically // even if exception is thrown // Closes in reverse order of declaration // Multi-catch (Java 7+) try { riskyOp(); } catch (IOException | SQLException e) { handleBoth(e); }

Stream Collectors & Advanced Patterns

// toMap — build a Map from a stream Map<Long, User> userById = users.stream() .collect(Collectors.toMap( User::getId, // key u -> u, // value (u1, u2) -> u1 // merge (duplicates) )); // joining — concatenate strings String csv = names.stream() .collect(Collectors.joining(", ", "[", "]")); // "[a, b, c]" // groupingBy with downstream collector Map<Department, Double> avgSalaryByDept = employees.stream() .collect(Collectors.groupingBy( Employee::getDepartment, Collectors.averagingDouble( Employee::getSalary))); // Custom collector Collector<Integer,?,Integer> sumCollector = Collector.of( () -> new int[1], (acc, n) -> acc[0] += n, (a, b) -> { a[0] += b[0]; return a; }, acc -> acc[0] );

Parallel Streams

// parallelStream() uses ForkJoinPool long count = hugeList.parallelStream() .filter(x -> x % 2 == 0) .count(); // When to use parallel streams: // - Large data sets (100K+ elements) // - CPU-bound operations // - Stateless, side-effect-free pipelines // When NOT to: // - I/O-bound operations // - Small data sets (overhead exceeds benefit) // - Stateful/ordered operations // - Synchronized data structures // Watch out: collectors must be thread-safe // ConcurrentHashMap if accumulating in parallel Map<Integer,Long> freqParallel = nums.parallelStream() .collect(Collectors.groupingBy( n -> n, Collectors.counting())); // groupingBy is not concurrent by default — // use Collectors.toConcurrentMap for true parallel

Behavioral Interview — STAR Framework

S — Situation

Set the context. What was the project, team size, timeline? Be specific but concise. Interviewers want to understand the stakes.

Example: "I was the tech lead on a 4-person team building a payment processing microservice with a 6-week deadline before a major product launch."

T — Task

What was your specific responsibility? What problem needed to be solved? Why was it challenging?

Example: "I was responsible for designing the API contract and ensuring PCI compliance. The challenge was the existing codebase had no tests and was tightly coupled."

A — Action

What did YOU do? Use "I" not "we." Describe your thought process, specific technical decisions, and why you chose them over alternatives.

Example: "I introduced the Strangler Fig pattern — wrapping the legacy system with a new service layer. I wrote integration tests first to establish a safety net, then refactored incrementally."

R — Result

What was the measurable outcome? Quantify where possible. What did you learn? What would you do differently?

Example: "Launched on time. Test coverage went from 0% to 78%. Payment processing latency dropped 40%. Team can now ship features 3x faster with confidence."
