Java Reflection & Introspection

Zero to Hero: inspect and modify classes, methods, and fields at runtime — plus how Spring and Jackson use it under the hood.

🪞 What is reflection — and why do Spring and Jackson need it to work?

Reflection lets a program inspect and modify its own structure at runtime — call a method named by a string (User.class.getMethod("getName").invoke(user)), read fields, types, and annotations without knowing the class at compile time. It's the engine of Spring (scan for @Component, inject @Autowired, wrap @Transactional in a proxy) and Jackson (read fields + @JsonProperty to map JSON). It's powerful but slower than direct calls and bypasses access modifiers — which is why Spring's AOT/native images replace it with generated code.

  • Inspect & invoke at runtime — by name, without compile-time knowledge of the class.
  • Spring & Jackson run on it — component scan, DI, proxies, JSON mapping.
  • It costs speed & safety — slower than direct calls; can read private via setAccessible.
  • AOT replaces it — native images generate code instead of reflecting.

Basic reflection API

Class<?> clazz = User.class or Class.forName("com.example.User"). Fields: clazz.getDeclaredFields() (all, incl. private). field.setAccessible(true) to read/write private. Methods: clazz.getDeclaredMethods(). Invoke: method.invoke(instance, arg1, arg2). Constructors: clazz.getDeclaredConstructor(String.class).newInstance("value"). Annotations: field.getAnnotation(JsonProperty.class). Parameter names: method.getParameters()[0].getName() (requires -parameters compiler flag). Generic types: ((ParameterizedType)field.getGenericType()).getActualTypeArguments()[0] — gets the T in List<T>.

How Spring uses reflection

Component scan: classpath scanning finds classes annotated @Component/@Service/etc. Dependency injection: for @Autowired UserRepository repo, Spring finds the field via reflection, makes it accessible, and sets it. Annotation processing: @PreAuthorize("hasRole('ADMIN')") — Spring reads this annotation value at runtime and applies AOP advice. Proxy creation: CGLIB creates a subclass at runtime, overriding methods to add transaction/cache/security behaviour. AOT native (Spring Boot 3 with GraalVM): generates code at build time to replace runtime reflection, producing faster startup and lower memory native images.

Custom annotation processor

// AOP aspect that reads @AuditLog via reflection @Around("@annotation(com.ciam.AuditLog)") Object audit(ProceedingJoinPoint pjp) throws Throwable { Method m = ((MethodSignature)pjp.getSignature()).getMethod(); AuditLog al = m.getAnnotation(AuditLog.class); String action = al.action(); // read annotation value auditService.log(action, SecurityContextHolder.getContext()); return pjp.proceed(); }. The AOP framework (also uses reflection internally) calls this around advice for any method annotated @AuditLog.

CIAM / Spring Boot: You rarely write reflection yourself, but it explains the gotchas: @Transactional can't wrap a private method (the CGLIB proxy can't override it), Jackson needs -parameters to read record field names, native images need a reflect-config.json, and @Autowired works on a private field because Spring calls setAccessible(true). MapStruct generates mapping code instead — which is why it beats Jackson for DTO conversion.

What is Reflection?

Reflection is Java's ability to examine and manipulate its own structure at runtime. Normally, the compiler enforces every type relationship and method call. With reflection you can bypass the compiler entirely: discover what methods a class has, call a private method, read or write a private field, or instantiate a class whose name you only know as a String. The API lives in java.lang.reflect.

// Without reflection — compiler knows everything at compile time User u = new User("Alice"); u.getName(); // compiler checks this exists // With reflection — everything happens at runtime Class<?> clazz = Class.forName("com.example.User"); Constructor<?> ctor = clazz.getDeclaredConstructor(String.class); Object u = ctor.newInstance("Alice"); Method m = clazz.getDeclaredMethod("getName"); Object name = m.invoke(u); // "Alice" — no compile-time check
When is this useful? Reflection powers every major Java framework: Spring (dependency injection), Hibernate (ORM), Jackson (JSON), JUnit (test discovery), and countless others. You rarely write reflection code yourself, but understanding it explains why frameworks can do seemingly magical things.
Trade-offs: Reflection bypasses compile-time safety, is significantly slower than direct calls (method dispatch can be 20-50x slower without caching), and breaks encapsulation. Use it only when there is no cleaner alternative, and always cache the reflected objects.

Three ways to get a Class<?> object

Every loaded class in the JVM has exactly one Class<T> instance. It is the entry-point for all reflection. You can obtain it three ways, each suited to different situations.

1. Class literal — compile-time, no exception, preferred when class is known
Class<String> c = String.class; Class<int[]> arr = int[].class; Class<Void> v = Void.class; // Works on primitives too Class<Integer> boxed = int.class; // NOT Integer.class — different!
2. getClass() — at runtime, on an existing object
Object obj = "hello"; Class<?> c = obj.getClass(); // java.lang.String // Useful when you receive an Object and need its actual type void inspect(Object o) { Class<?> c = o.getClass(); // actual runtime type, not declared type System.out.println(c.getName()); }
3. Class.forName() — at runtime, by fully-qualified name string; throws ClassNotFoundException
// Used when the class name comes from config/database/user input try { Class<?> c = Class.forName("com.example.plugins.PayPalProcessor"); PaymentProcessor p = (PaymentProcessor) c.getDeclaredConstructor().newInstance(); } catch (ClassNotFoundException e) { // class not on classpath }
Class<T> vs Class<?>: Use Class<T> when you know the exact type (e.g. Class<String>). Use Class<?> when the type is unknown at compile time — this is the common case in framework code.

What Class<?> can tell you without even inspecting members

Class<?> c = ArrayList.class; c.getName() // "java.util.ArrayList" c.getSimpleName() // "ArrayList" c.getPackageName() // "java.util" (Java 9+) c.getSuperclass() // class java.util.AbstractList c.getInterfaces() // [List, RandomAccess, Cloneable, Serializable] c.getModifiers() // int bitmask — use Modifier.isPublic(mods) etc. c.isInterface() // false c.isAnnotation() // false c.isEnum() // false c.isRecord() // false (Java 16+) c.isSealed() // false (Java 17+) c.isArray() // false c.isPrimitive() // false c.getAnnotations() // all present annotations c.getClassLoader() // which ClassLoader loaded it

getDeclared*() vs get*() — a critical distinction

This is the most commonly confused part of the reflection API. There are two families of methods and they behave very differently.

getDeclared*() family
// Returns ALL visibility levels // public, protected, package, private // BUT only members declared in THIS class // Does NOT include inherited members c.getDeclaredFields() // all fields (incl. private) c.getDeclaredMethods() // all methods (incl. private) c.getDeclaredConstructors() // all constructors c.getDeclaredAnnotations() // annotations on this class // To access private: need setAccessible(true)
get*() family
// Returns PUBLIC members ONLY // BUT includes inherited public members // (from superclasses and interfaces) c.getFields() // public fields incl. inherited c.getMethods() // public methods incl. inherited c.getConstructors() // public constructors only // getMethod() can traverse superclasses: c.getMethod("equals", Object.class) // finds Object.equals c.getMethod("hashCode") // finds Object.hashCode
Rule of thumb: Framework code almost always uses getDeclaredFields() + setAccessible(true) to reach private state. If you are walking the class hierarchy (e.g., to find all annotated fields including inherited ones), you must loop via getSuperclass() until you hit Object.

Inspecting fields, methods, and constructors in detail

// --- Fields --- Field[] fields = clazz.getDeclaredFields(); for (Field f : fields) { f.getName() // "name", "age", etc. f.getType() // Class<?> for the field type f.getGenericType() // preserves List<String> generic info Modifier.isPrivate(f.getModifiers()) // true/false f.getAnnotations() // e.g. @Column, @NotNull f.isAnnotationPresent(NotNull.class) // boolean check } // --- Methods --- Method[] methods = clazz.getDeclaredMethods(); for (Method m : methods) { m.getName() // "getName", "setAge", etc. m.getReturnType() // return type Class<?> m.getParameterTypes() // Class<?>[] of param types m.getParameterCount() // int — Java 8+ m.getGenericReturnType() // preserves generics m.getExceptionTypes() // declared checked exceptions Modifier.isStatic(m.getModifiers()) // is it static? m.getAnnotation(Transactional.class) // get specific annotation } // --- Finding a specific method/field by name --- Method m = clazz.getDeclaredMethod("setName", String.class); // NoSuchMethodException Field f = clazz.getDeclaredField("name"); // NoSuchFieldException

Walking the inheritance hierarchy — the right way

// To find ALL fields including those from superclasses: static List<Field> getAllFields(Class<?> clazz) { List<Field> fields = new ArrayList<>(); Class<?> current = clazz; while (current != null && current != Object.class) { fields.addAll(Arrays.asList(current.getDeclaredFields())); current = current.getSuperclass(); // walk up } return fields; } // Example: Employee extends Person — gets both classes' fields List<Field> allFields = getAllFields(Employee.class);

Method.invoke() — calling methods at runtime

Class<?> clazz = User.class; User instance = new User("Alice", 30); // --- Call an instance method --- Method getName = clazz.getDeclaredMethod("getName"); String name = (String) getName.invoke(instance); // "Alice" // --- Call with arguments --- Method setAge = clazz.getDeclaredMethod("setAge", int.class); setAge.invoke(instance, 31); // sets age to 31 // --- Call a static method --- Method parse = Integer.class.getMethod("parseInt", String.class); int n = (Integer) parse.invoke(null, "42"); // null = no instance for static // --- Handle exceptions --- // invoke() wraps any exception thrown by the method in InvocationTargetException try { method.invoke(obj, args); } catch (InvocationTargetException e) { Throwable cause = e.getCause(); // the actual exception }

Field.get() / Field.set() — reading and writing fields

User user = new User("Bob", 25); Field nameField = User.class.getDeclaredField("name"); nameField.setAccessible(true); // required for private fields // Read the field String name = (String) nameField.get(user); // "Bob" // Write the field nameField.set(user, "Robert"); // user.name = "Robert" // Primitive fields — use typed variants Field ageField = User.class.getDeclaredField("age"); ageField.setAccessible(true); int age = ageField.getInt(user); // avoid boxing ageField.setInt(user, 26); // Static fields — pass null as the instance Field counterField = User.class.getDeclaredField("instanceCount"); counterField.setAccessible(true); int count = counterField.getInt(null);

Constructor.newInstance() — creating objects dynamically

// No-arg constructor Class<?> clazz = Class.forName("com.example.User"); Object obj = clazz.getDeclaredConstructor().newInstance(); // Constructor with arguments Constructor<?> ctor = clazz.getDeclaredConstructor(String.class, int.class); Object obj2 = ctor.newInstance("Alice", 30); // Private constructor (Singleton, factory pattern) Constructor<?> privateCtor = clazz.getDeclaredConstructor(); privateCtor.setAccessible(true); // must set accessible first Object singleton = privateCtor.newInstance();
Java 9+ shortcut: clazz.getDeclaredConstructor().newInstance() replaces the deprecated clazz.newInstance(), which could not handle private constructors and swallowed exceptions.

setAccessible(true) — the power and the danger

Calling setAccessible(true) on a Field, Method, or Constructor disables Java's normal access checks. After this call, code that would normally be rejected with IllegalAccessException — because the member is private — will succeed.

// Without setAccessible(true): Field f = User.class.getDeclaredField("password"); f.get(user); // throws IllegalAccessException — field is private // With setAccessible(true): Field f = User.class.getDeclaredField("password"); f.setAccessible(true); // disable access checks String pwd = (String) f.get(user); // works — encapsulation bypassed
Why setAccessible is dangerous:
1. Security: It bypasses the encapsulation that class designers relied on. Private state may be an implementation detail that can change. Code reading it will silently break.
2. Performance: The JVM's JIT compiler can inline and optimize regular method calls. Reflective calls skip these optimizations. Without caching, a reflective loop over 1M objects can be 20-100x slower.
3. Module system (Java 9+): Modules can explicitly forbid deep reflection. Code that worked on Java 8 may now throw InaccessibleObjectException.
Best practice — cache the reflected objects: Do NOT call getDeclaredField() inside a loop. Call it once, store the Field object, call setAccessible(true) once, then reuse it. This is what Jackson and Spring do.

Performance cost — why caching matters

// BAD — getDeclaredField() is called on every loop iteration for (User user : users) { Field f = User.class.getDeclaredField("name"); // expensive lookup each time! f.setAccessible(true); process(f.get(user)); } // GOOD — reflect once, reuse many times private static final Field NAME_FIELD; static { try { NAME_FIELD = User.class.getDeclaredField("name"); NAME_FIELD.setAccessible(true); // done once } catch (NoSuchFieldException e) { throw new ExceptionInInitializerError(e); } } for (User user : users) { process(NAME_FIELD.get(user)); // fast — no lookup, no access check }

How Spring uses reflection — @Autowired field injection

Spring's IoC container uses reflection at startup to wire your application together. Understanding this makes @Autowired feel less magical.

// Your code — Spring sees this annotation @Service public class OrderService { @Autowired private PaymentGateway gateway; // private field! @Value("${payment.timeout}") private int timeout; } // What Spring does internally (simplified): Class<?> clazz = OrderService.class; Object instance = clazz.getDeclaredConstructor().newInstance(); // 1. instantiate for (Field f : clazz.getDeclaredFields()) { if (f.isAnnotationPresent(Autowired.class)) { // 2. find @Autowired Object dep = beanFactory.getBean(f.getType()); // 3. look up dependency f.setAccessible(true); // 4. bypass private f.set(instance, dep); // 5. inject it } if (f.isAnnotationPresent(Value.class)) { String key = f.getAnnotation(Value.class).value(); Object val = environment.resolvePlaceholder(key); f.setAccessible(true); f.set(instance, val); } }

How Jackson uses reflection — JSON serialization/deserialization

// Your POJO public class User { private String name; private int age; // no annotations needed — Jackson discovers via reflection } // Jackson serialization — simplified Class<?> clazz = obj.getClass(); Field[] fields = clazz.getDeclaredFields(); StringBuilder json = new StringBuilder("{"); for (Field f : fields) { f.setAccessible(true); String key = f.getName(); // or @JsonProperty value Object value = f.get(obj); // read the field json.append("\"").append(key).append("\":").append(toJson(value)); } // Jackson deserialization — simplified Object obj = clazz.getDeclaredConstructor().newInstance(); // no-arg ctor for (Map.Entry<String,Object> entry : parsedJson.entrySet()) { Field f = clazz.getDeclaredField(entry.getKey()); f.setAccessible(true); f.set(obj, convertType(entry.getValue(), f.getType())); // write the field }
Why Jackson requires a no-arg constructor (by default): Jackson's deserialization uses getDeclaredConstructor().newInstance() to create the object, then sets each field individually. Without a no-arg constructor, it cannot create the object. The @JsonCreator annotation allows you to designate a different constructor.

VarHandles (Java 9+) — the modern, safer alternative

VarHandle (in java.lang.invoke) is the modern replacement for reflective field access. It provides the same ability to read/write arbitrary fields but with better performance (JIT-friendly), type safety, and atomic operations.

import java.lang.invoke.*; // Create a VarHandle for a specific field — do this once, statically private static final VarHandle NAME_HANDLE; static { try { MethodHandles.Lookup lookup = MethodHandles.privateLookupIn( User.class, MethodHandles.lookup()); NAME_HANDLE = lookup.findVarHandle(User.class, "name", String.class); } catch (Exception e) { throw new ExceptionInInitializerError(e); } } // Usage — strongly typed, no cast needed User user = new User("Alice"); String name = (String) NAME_HANDLE.get(user); // read NAME_HANDLE.set(user, "Bob"); // write // Atomic operations (unlike Field) NAME_HANDLE.compareAndSet(user, "Alice", "Bob"); // CAS NAME_HANDLE.getAndSet(user, "Charlie"); // atomic swap

Java 9 Module System — how it restricts reflection

// Pre-Java 9: any code could reflect into any class // Java 9+: modules must explicitly allow deep reflection // module-info.java for a library that needs reflection into it: module com.example.myapp { opens com.example.model; // allows deep reflection (all modules) opens com.example.model to jackson.databind; // opens to specific module only exports com.example.api; // exports (compile-time + public reflection) } // Without 'opens', this throws at runtime: // java.lang.reflect.InaccessibleObjectException: // Unable to make field private ... accessible: module X does not 'opens' Y to Z // Workaround for classpath/legacy mode (command line): // java --add-opens java.base/java.lang=ALL-UNNAMED ...
Migration pain: A lot of code that worked on Java 8 throws InaccessibleObjectException on Java 17+ when running in named modules. The fix is either to add opens declarations, use --add-opens on the command line, or migrate to VarHandles/MethodHandles.

Reflection vs. Interface — when to use which

Reflection (avoid when possible)
// You need to call "process" but // only know the class as a String Method m = clazz.getMethod("process"); m.invoke(instance); // No compile-time check. Breaks if // method is renamed. Slower.
Interface (prefer this)
// Define a contract interface Processor { void process(); } // Use the interface Processor p = getProcessor(); p.process(); // Compile-time checked. Fast. // Refactor-safe.
Golden rule: Use reflection when you cannot know the type at compile time (plugin system, framework, serialization). If you control both sides of the code, use interfaces.
