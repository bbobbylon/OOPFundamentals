GitHub Copilot — Autocomplete to Agent

Copilot is really four different tools wearing one name — ghost-text completion, chat, an autonomous agent that edits multiple files, and a custom-instructions layer that steers all of the above toward your repo's conventions.

🐙 What is GitHub Copilot, and how far does it go?

GitHub Copilot started as a single feature — inline suggestions, the grayed "ghost text" that appears as you type — but the product has grown into a spectrum of assistance with very different levels of autonomy. At the low end, inline completion reads the current file plus nearby open tabs and repo context, and proposes the next few lines; you accept with Tab or keep typing to ignore it, and nothing is ever written unless you accept. One step up, Copilot Chat is a sidebar conversation: you ask a question or request a snippet, the model answers using the files you have open (or explicitly reference) as context, and you decide whether to paste the result in — still fundamentally reactive, one exchange at a time. Further up the spectrum, Edits / Agent mode takes a single higher-level instruction — "add pagination to this endpoint" — and plans and applies changes autonomously across multiple files, running commands and iterating on its own, before presenting a diff for you to review and accept or reject. Cutting across all three levels is a fourth mechanism that is not autonomy at all but steering: a .github/copilot-instructions.md file at the repo root that VS Code auto-detects and silently prepends to every chat and agent request in that workspace, so the same prompt produces different, more on-convention output once the repo defines its own house rules. Understanding Copilot means knowing which of these four modes you are in, because each carries a different blast radius — ghost text touches nothing, chat touches nothing until you paste, agent mode touches files directly, and instructions quietly reshape all of them.

  • Inline (ghost text) — completions as you type, informed by the open file and nearby context; Tab to accept, otherwise nothing changes.
  • Chat — a sidebar Q&A over your code; still conversational, you paste in what you want.
  • Agent mode — a single instruction becomes a multi-file plan the agent applies on its own, then you review the diff.
  • Custom instructions — .github/copilot-instructions.md is read on every request and steers style, conventions, and tooling choices.

Blast radius by mode

Inline suggestions and chat responses are inert until you act on them — nothing is written to disk. Agent mode is the first mode that writes files on its own initiative, which is exactly why it always stops at a reviewable diff rather than committing directly.

Instructions are silent

Custom instructions don't appear in the chat transcript as a visible message — they're prepended behind the scenes. Two developers typing the identical prompt in the same repo get identical steering; the same prompt in a repo without the file gets generic output.

Not just VS Code

Copilot ships across VS Code, JetBrains IDEs, Vim/Neovim, and Xcode. The instructions-file convention is spreading beyond Copilot too, via the emerging cross-tool AGENTS.md standard several agentic CLIs now recognize.

Copilot in a CIAM world: a copilot-instructions.md that says "controllers return ResponseEntity<HttpResponse>, use constructor injection, never hand-roll JWT parsing" is exactly the kind of house rule this codebase's Spring Boot backend recipe encodes — it turns Copilot's suggestions (inline, chat, or agent-mode multi-file edits) toward the same `CustomAuthFilter` / permission-string / `NamedParameterJdbcTemplate` patterns used across this machine's projects, instead of generic JPA-and-`@PreAuthorize` boilerplate that would fight the existing security filter chain.

The instructions file that steers every request

See the Code Walkthrough below for a full line-by-line read of a realistic .github/copilot-instructions.md. The short version: VS Code finds this file automatically and quietly prepends it to chat, inline, and agent requests alike — you never "invoke" it, it's just always in effect once it exists.

A few things worth knowing

  • Workspace auto-detection — VS Code looks for .github/copilot-instructions.md at the workspace root and applies it to every chat request in that workspace, with no configuration step required beyond creating the file. There's also a scoped variant, .github/instructions/**.instructions.md, for rules that should only apply to certain paths.
  • A cross-tool standard is emerging — AGENTS.md is a newer, tool-agnostic convention that Copilot and several other CLI-based coding agents now recognize, aimed at letting one instructions file steer more than one vendor's assistant.
  • Agent mode is fast, not always careful — Copilot's Agent mode plans and applies multi-file changes in one pass, but on complex, high-stakes refactors it tends to move faster and check its own work less methodically than more deliberate agentic coding tools, so a careful diff review before accepting still matters.
