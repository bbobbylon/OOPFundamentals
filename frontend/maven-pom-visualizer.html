POM Anatomy

Every element in a real Spring Boot pom.xml explained. Click each section to expand details.

🧾 What is a POM file — and what does every element actually do?

POM (Project Object Model, pom.xml) defines everything Maven needs: what the project is, its dependencies, how to build, and which plugins to run — one per project root. Every artifact has three coordinates: groupId, artifactId, version. Spring Boot projects inherit spring-boot-starter-parent, which manages versions for hundreds of libraries — so you declare a spring-boot-starter-web dependency with no <version>. dependencies pull JARs (and transitives) from Maven Central with a scope; build/plugins configures plugins (the spring-boot-maven-plugin makes the fat JAR on mvn package); properties set things like java.version; and dependencyManagement pins versions for sub-modules without adding them to the classpath.

  • One pom.xml defines identity, deps, build, plugins.
  • Coordinates = groupId : artifactId : version.
  • Parent manages versions — declare starters without a <version>.
  • spring-boot-maven-plugin builds the fat JAR; dependencyManagement pins versions.

Spring Boot pom.xml

<?xml version="1.0"?> <project> <!-- Coordinates: uniquely identify this artifact --> <groupId>com.company.ciam</groupId> <artifactId>ciam-auth</artifactId> <version>1.2.3-SNAPSHOT</version> <packaging>jar</packaging> <!-- Inherit Spring Boot defaults + managed versions --> <parent> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-parent</artifactId> <version>3.3.0</version> </parent> <properties> <java.version>21</java.version> <!-- Override managed dep version: --> <jackson.version>2.17.0</jackson.version> </properties>

Dependencies + scopes

<dependencies> <!-- Spring starters (no version = parent manages it): --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> <!-- Spring MVC + Tomcat + Jackson --> </dependency> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-data-jpa</artifactId> </dependency> <dependency> <groupId>org.postgresql</groupId> <artifactId>postgresql</artifactId> <!-- Runtime scope: not needed to compile --> <scope>runtime</scope> </dependency> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-test</artifactId> <scope>test</scope> </dependency> </dependencies>

Build + plugins

<build> <plugins> <!-- Spring Boot Maven Plugin --> <plugin> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-maven-plugin</artifactId> <configuration> <excludes> <exclude> <!-- Don't include in fat JAR: --> <groupId>org.projectlombok</groupId> <artifactId>lombok</artifactId> </exclude> </excludes> <layers> <enabled>true</enabled> <!-- Split JAR into layers for Docker caching --> </layers> </configuration> </plugin> <!-- Flyway for DB migrations: --> <plugin> <groupId>org.flywaydb</groupId> <artifactId>flyway-maven-plugin</artifactId> </plugin> </plugins> </build>

CIAM pom.xml starters: A CIAM auth service pulls spring-boot-starter-web, -data-jpa, -security, -oauth2-resource-server (JWT validation of Ping/Entra tokens), -actuator (K8s probes), -validation, postgresql (runtime), flyway-core, and -cache + -data-redis (session cache). Add Lombok (provided scope) and spring-cloud-starter-openfeign for declarative Ping/Entra clients. Use mvn dependency:tree to see the transitive graph and spot conflicts.

1 — Annotated pom.xml — Click Any Section

<?xml version="1.0" encoding="UTF-8"?> <project> <modelVersion>4.0.0</modelVersion> <parent> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-parent</artifactId> <version>3.3.0</version> </parent>
Parent POM — inherits configuration from spring-boot-starter-parent, which itself inherits from spring-boot-dependencies.

What you get for free: default plugin configurations (compiler, surefire, jar), encoding settings, resource filtering, and the entire BOM (Bill of Materials) — hundreds of pre-tested dependency versions.

That's why you can write <artifactId>spring-boot-starter-web</artifactId> without a version tag — the parent's BOM provides it.
<groupId>com.example</groupId> <artifactId>my-spring-app</artifactId> <version>1.0.0-SNAPSHOT</version> <packaging>jar</packaging>
Maven Coordinates — the globally unique address for this artifact in the Maven ecosystem.

groupId: your organization's reverse-domain name (like a Java package for your company).
artifactId: the project/module name (lowercase, hyphens).
version: -SNAPSHOT means "in development / not released". Remove SNAPSHOT for a release version.
packaging: jar (default), war (web archive), or pom (parent POM only — no code).
<properties> <java.version>21</java.version> <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding> </properties>
Properties — key-value pairs used throughout the POM as ${java.version} placeholders.

java.version: picked up by the parent's compiler plugin configuration — sets source and target version.
project.build.sourceEncoding: ensures all source files are read as UTF-8 (avoids "special character" compile bugs).

You can define custom properties here and reference them anywhere in the POM: ${my.custom.version}.
<dependencies> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> <!-- no version: inherited from parent BOM --> </dependency> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-test</artifactId> <scope>test</scope> </dependency> </dependencies>
Dependencies — libraries your project uses. Maven downloads them from Maven Central (or a configured private registry).

No version: Spring Boot dependencies managed by the parent BOM — Spring guarantees these versions work together.
scope: test means this dependency is only on the test classpath, not compiled into the final JAR.

Maven checks ~/.m2/repository first (local cache) before downloading from the network.
<build> <plugins> <plugin> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-maven-plugin</artifactId> </plugin> </plugins> </build>
Build / Plugins — adds or configures Maven plugins.

spring-boot-maven-plugin: the most important Spring Boot plugin. It:
• Repackages the JAR into an executable fat JAR (includes all dependencies)
• Enables mvn spring-boot:run to run the app directly
• Enables mvn spring-boot:build-image to create a Docker image

Without this plugin, java -jar target/app.jar would fail — it wouldn't be an executable JAR.

2 — Maven Coordinates

The three coordinates uniquely identify every artifact in the Maven ecosystem — like a GPS coordinate for a library:

groupId

Your organization's namespace. Convention: reverse domain name.

com.example · org.springframework · io.micrometer

Corresponds roughly to a top-level Java package.

artifactId

The specific project or module name. Lowercase with hyphens.

spring-boot-starter-web · jackson-databind · my-api-service

Becomes the filename of the built JAR: my-api-service-1.0.jar

version

The release version. SNAPSHOT = in development.

3.3.0 (release) · 3.3.1-SNAPSHOT (in dev) · 1.0.0-RC1 (release candidate)

Maven caches releases. SNAPSHOT versions always re-check the remote.

3 — Parent & BOM Inheritance

Spring Boot uses a 3-level inheritance chain. Your pom inherits from the top:

your pom.xml

Your app. Declares dependencies, plugins, properties.

↑ inherits from

spring-boot-starter-parent

Default plugin config (compiler: Java 21, surefire, jar, resource filtering). Sets encoding. Inherits from spring-boot-dependencies.

↑ inherits from

spring-boot-dependencies (the BOM)

Defines versions for 500+ libraries. The reason you don't need to specify versions for spring-*, jackson-*, junit-*, hibernate-*, etc. Spring tests these combinations together.

ℹ️ To override a version managed by the BOM, add a <properties> entry like:
<jackson.version>2.17.0</jackson.version>
The BOM uses properties internally, so your override wins. Only do this when you have a specific reason (vulnerability fix, new feature needed).
