CSS Fundamentals — Box Model, Selectors & Specificity

or, why your rule lost to one you wrote three files ago

Every element on a page is a rectangular box, every visual rule reaching that box came from a cascade of competing selectors, and the browser resolves conflicts with one deterministic algorithm: specificity. Learn these three ideas and the rest of CSS is just vocabulary.

The problem

"It's not applying" is almost never a typo.

The escalation everyone has done

The rule doesn't apply, so you make the selector longer. Then longer. Then you reach for the nuclear option.

.btn { color: red } .card .btn { … } #page .card .btn { … } !important ⚠

Each step wins today and makes tomorrow harder — because the next person has to out-specify you.

Know who wins, and why
inline style — 1,0,0,0 ↓ beats #id — 0,1,0,0 ↓ beats .class · [attr] · :hover — 0,0,1,0 ↓ beats element · ::before — 0,0,0,1
Specificity is compared left to right, and it does not carry. A single #id beats any number of classes — a thousand classes never add up to one id. Source order only decides ties.

Questions from the back row

Is !important ever acceptable?

Rarely and deliberately: overriding a third-party stylesheet you cannot edit, or a utility that must always win, like a .hidden. What makes it bad is using it to win an argument with your own CSS — the fix there is a lower-specificity structure, not a bigger hammer.

Why did my two margins become one?

Vertical margins collapse: adjacent top and bottom margins merge into the larger, rather than adding. It surprises everyone once. Padding never collapses, and neither do margins inside a flex or grid container.

🎨 What is CSS, and why does the same element sometimes ignore your rule?

HTML describes what is on the page — a paragraph, a button, an image. CSS (Cascading Style Sheets) describes how it looks — color, spacing, layout, position. You attach CSS to HTML three ways: a <link rel="stylesheet"> to an external .css file (the normal, cacheable, reusable way), a <style> block inside the page, or an inline style="…" attribute on one element. The tricky part beginners hit almost immediately: what happens when two rules target the same element and disagree? The browser doesn't guess — it runs a precise, mechanical algorithm called specificity that scores every selector and lets the highest score win, with source order as the tiebreaker and !important as a deliberate escape hatch above everything else. Underneath every element sits the box model: content, then padding, then a border, then a margin, nested like Russian dolls — and whether a declared width includes that padding/border or not is controlled by a single property, box-sizing, that nearly every real stylesheet overrides from its confusing default. Master the cascade, the box model, and positioning contexts, and CSS stops feeling like guesswork.

  • Three ways to attach CSS — external stylesheet, <style> block, inline style="" — inline wins the cascade by default.
  • Specificity is a score, not a vibe — id beats any number of classes; a class beats any number of elements; !important beats all of it.
  • The box model — content → padding → border → margin; box-sizing: border-box makes width include padding+border (what you actually want almost always).
  • Positioning contexts — absolute anchors to the nearest position: relative ancestor, not the page; fixed anchors to the viewport and ignores scroll.
  • CSS variables (--accent) — declare once on :root, reuse everywhere via var(--accent); change the one declaration and every consumer updates.

The problem it solves

"Why isn't my CSS applying?" is almost always a specificity fight you're losing, or a box-model width surprise (padding pushed your box wider than you declared). Learning to read a rule's specificity score and the box model's four layers turns "CSS is random" into "CSS is deterministic, I just haven't traced it yet."

Core concepts here

The cascade (which stylesheet/rule applies), specificity (id > class > element, scored numerically), the box model (content/padding/border/margin), and positioning contexts (what absolute/fixed/relative actually anchor to).

Where this shows up next

Every framework you'll learn — Angular's component styles, React's CSS-in-JS, Tailwind's utility classes — still resolves through this exact same cascade and box model. This DevHub's own devhub.css themes every track with the --accent/--accent2 custom-property pattern taught in scenario 4 below.

Where this bites in real apps: a login form's error-state red text not showing up is almost always a specificity loss — a more specific selector elsewhere (often a third-party UI library's own CSS) is quietly winning. Learning to read specificity scores, rather than reaching for !important as a first move, is what separates "I fought the CSS for an hour" from a 10-second fix.

1. The cascade & specificity: how the browser picks a winner

/* three rules, one paragraph — who wins? */
p { color: blue; } /* element selector: specificity 0-0-1 */
.card p { color: green; } /* class + element: specificity 0-1-1 */
#hero p { color: purple !important; } /* id + element, !important: wins outright */

<p style="color: orange">text</p> /* inline: specificity 1-0-0 — beats classes/elements, loses to !important */
Specificity is a 4-part score, read left to right: inline, id, class/attribute/pseudo-class, element. A single id (0-1-0-0 territory) beats any number of classes; a single class beats any number of element selectors. Ties break by source order — whichever matching rule was declared last in the stylesheet wins. !important is not part of the specificity score at all — it's a separate, higher-priority layer that overrides everything except another !important (where specificity then decides between the two). Overusing !important is a classic beginner trap: it wins the current fight but makes every future override need its own !important, escalating forever.

2. The box model: content, padding, border, margin

/* the default: content-box */
.card {
  width: 200px;
  padding: 20px;
  border: 5px solid;
  /* rendered width = 200 + 20+20 + 5+5 = 250px — surprise! */
}

/* what almost every real stylesheet does instead */
* { box-sizing: border-box; }
.card {
  width: 200px;
  padding: 20px;
  border: 5px solid;
  /* rendered width = exactly 200px — padding/border eat into it */
}
Every element is content wrapped by padding, wrapped by a border, wrapped by margin — margin is the odd one out: it's transparent space outside the border that pushes neighboring elements away, and is never part of an element's own rendered size. Under the browser's default box-sizing: content-box, width sets only the content box, so padding and border add on top of your declared width. box-sizing: border-box redefines width to mean "the whole visible box, padding and border included" — which matches how most people intuitively expect sizing to work, which is why a universal * { box-sizing: border-box; } is one of the first lines in nearly every production stylesheet.

3. Positioning contexts: what "absolute" is actually relative to

/* absolute anchors to the NEAREST positioned ancestor */
.modal-wrapper { position: relative; } /* establishes the context */
.modal-close-btn {
  position: absolute;
  top: 8px; right: 8px; /* relative to .modal-wrapper, not the page */
}

/* fixed anchors to the VIEWPORT — ignores scroll entirely */
.cookie-banner {
  position: fixed;
  bottom: 0; left: 0; right: 0; /* stays pinned no matter how far you scroll */
}
static is the default (normal document flow, top/left/right/bottom do nothing); relative shifts an element from where it would normally sit and — this is the important side effect — establishes a positioning context for any absolute descendant. An absolute element ignores normal flow entirely and anchors to the nearest ancestor with a non-static position — if none exists, it falls all the way back to the page itself, which is the classic "why is my tooltip in the corner of the whole page" bug. fixed anchors to the viewport and never moves on scroll (banners, sticky headers); sticky is a hybrid — normal flow until a scroll threshold, then it behaves like fixed within its container.
