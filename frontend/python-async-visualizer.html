Python Async / Await & asyncio

Coroutines, the event loop, asyncio.gather(), task cancellation, and the #1 gotcha: blocking the event loop with synchronous calls.

⚡ What is Python async/await — and how does it differ from Java threads or Angular Observables?

Python's async/await is cooperative concurrency — many I/O-bound operations on a single thread, no OS-thread overhead. An async def coroutine doesn't run when called; you await it, which suspends it and hands control to the event loop to run other coroutines until the I/O completes (the same model as JavaScript's loop). asyncio.gather() runs coroutines concurrently — three sequential 300ms calls become ~300ms. The fatal trap: a blocking call (time.sleep, requests.get) freezes the whole loop — use asyncio.sleep/httpx instead.

  • Cooperative, single-threaded concurrency — great for I/O, not CPU.
  • await suspends to the event loop — other coroutines run during the wait.
  • gather() overlaps awaits — N sequential calls collapse to ~the slowest.
  • Never block the loop — await asyncio.sleep/httpx, never time.sleep/requests.

Coroutine + await

import asyncio, httpx async def fetch_user(client: httpx.AsyncClient, uid: int): # await: suspend here until response arrives # event loop runs other coroutines during wait r = await client.get( f'/api/users/{uid}', headers={'Authorization': f'Bearer {token}'} ) r.raise_for_status() return r.json() async def main(): async with httpx.AsyncClient(base_url='https://eg.com') as c: user = await fetch_user(c, 42) print(user) asyncio.run(main()) # ❌ DON'T: blocks entire event loop async def bad_handler(): import requests r = requests.get('/api/users') # BLOCKING! # 0 other coroutines run during this request

asyncio.gather() concurrency

async def export_all_users(): async with httpx.AsyncClient() as c: # Sequential: 300ms × 3 = 900ms u1 = await fetch_user(c, 1) u2 = await fetch_user(c, 2) u3 = await fetch_user(c, 3) # Concurrent: max(300ms, ...) ≈ 300ms u1, u2, u3 = await asyncio.gather( fetch_user(c, 1), fetch_user(c, 2), fetch_user(c, 3) ) # With error handling: results = await asyncio.gather( fetch_user(c, 1), fetch_user(c, 2), return_exceptions=True # don't cancel others on first failure ) return [u for u in results if not isinstance(u, Exception)]

Java/Angular comparison

Python async → Java: async def coroutine ≈ CompletableFuture<T>. await coro ≈ .get() (but non-blocking). asyncio.gather() ≈ CompletableFuture.allOf(f1, f2) or RxJava Observable.zip(). Python async → Angular/RxJS: await ≈ subscribing to an Observable that emits one value. asyncio.gather() ≈ RxJS forkJoin([obs1, obs2]). Task cancellation: task.cancel() raises CancelledError at the next await ≈ Angular's takeUntil(destroy$). FastAPI route: @app.get('/users') async def list_users(): users = await db.fetch_users(); return users — handles hundreds of concurrent requests without threads. Spring Boot alternative: reactive Spring WebFlux with Reactor — same non-blocking I/O model but in Java.

CIAM Python script: Export from Ping and Entra concurrently — ping_users, entra_users = await asyncio.gather(ping_client.list_all(), entra_client.list_all()) turns 4s sequential into ~2s. Fan out 100 paginated pages with await asyncio.gather(*tasks) for a 100× speedup. A FastAPI async def list_users(...) with an async DB query serves hundreds of admin-UI requests on one thread, unlike sync Flask's thread-per-request.

1. The Event Loop Mental Model

Single thread, multiple coroutines

One thread runs the event loop. Coroutines voluntarily yield at await points, letting others run. No true parallelism — but I/O-bound tasks overlap perfectly because they spend most of their time waiting, not computing.

import asyncio

async def fetch(url):
    await asyncio.sleep(1)  # yields control
    return f"data from {url}"

async def main():
    # Both run "concurrently" — total ~1s
    a, b = await asyncio.gather(
        fetch("api-1"),
        fetch("api-2")
    )

asyncio.run(main())

Concurrency vs Parallelism

asyncio: 1 thread, concurrent I/O (network, disk). Best for I/O-bound tasks.

threading: multiple threads, the GIL limits true CPU parallelism. OK for I/O-bound.

multiprocessing: multiple processes, true parallelism, bypasses GIL. Best for CPU-bound.

asyncio.to_thread(): run sync blocking code in a thread pool without blocking the event loop.

2. async / await Rules

You can only await awaitables

async def good():
    # ✓ await a coroutine
    result = await fetch_data()
    # ✓ await asyncio primitives
    await asyncio.sleep(0)  # yield once
    # ✓ await asyncio.Task / Future
    task = asyncio.create_task(work())
    await task

The blocking trap

⚠️ NEVER do this in async code:
time.sleep(5) — blocks the ENTIRE thread
requests.get(url) — synchronous HTTP
open(file).read() — synchronous file I/O

Use instead:
await asyncio.sleep(5)
await httpx.get(url) or aiohttp
await asyncio.to_thread(open(f).read)

3. Task Patterns

import asyncio

# gather: run all, wait for all, return list of results
results = await asyncio.gather(task1(), task2(), task3())

# create_task: fire and not necessarily wait (runs in background)
task = asyncio.create_task(background_sync())
await other_work()
await task  # collect result later

# TaskGroup (Python 3.11+): structured concurrency
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(fetch("api-1"))
    t2 = tg.create_task(fetch("api-2"))
# both tasks done here — any exception cancels the group

# Timeout (Python 3.11+)
async with asyncio.timeout(5.0):
    result = await slow_fetch()  # TimeoutError if > 5s
