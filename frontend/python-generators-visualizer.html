Python Generators & Iterators

A generator is a function that can pause itself. Each yield hands a value back to the caller and freezes the function — local variables, instruction pointer, everything — until you ask for the next value. That's how Python streams a billion items through a few bytes of memory. Press ▶ and watch a generator pause and resume.

Calling a generator function doesn't run it — it returns a paused generator object. Each next() runs to the next yield, returns that value, and freezes again. Pick a scenario and press ▶.

1. Generator function vs generator expression

Function — use yield

def countdown(n):
    while n > 0:
        yield n        # pause, hand back n
        n -= 1         # resumes HERE next time

g = countdown(3)   # nothing runs yet!
next(g)  # 3
next(g)  # 2  (resumed after the yield)

Expression — like a comprehension with ()

# list comp builds the whole list NOW
squares = [x*x for x in range(10)]

# gen expr is lazy — () not []
squares = (x*x for x in range(10))
sum(x*x for x in range(10))  # no extra ()
# computes one value at a time
Brain Power. Why does countdown(3) print nothing? Because the body of a generator function does not run when you call it. You get a generator object, frozen at the top. The first next() runs until the first yield. This laziness is the entire point.

2. The iterator protocol — what for really does

for x in thing:
    use(x)

# is exactly:
it = iter(thing)          # thing.__iter__()
while True:
    try:
        x = next(it)       # it.__next__()
    except StopIteration:  # the loop's exit signal
        break
    use(x)

Generators implement __iter__ and __next__ for you, and raise StopIteration automatically when the function returns. That's why every generator works in a for loop, in list(), in sum(), in *unpacking — anywhere an iterable is accepted.

3. Why it matters — memory

list: [x*x for x in range(10_000_000)]
~400 MB — every value materialized at once.
generator: (x*x for x in range(10_000_000))
~200 bytes — one value at a time, on demand.

Same result if you only iterate once. The generator never holds more than the current value, so it scales to data that wouldn't fit in RAM — log files, query cursors, infinite sequences.

Generators are single-use: once exhausted, a generator is done — iterate it again and you get nothing. If you need the data twice, either rebuild the generator or materialize it with list(). And an infinite generator (itertools.count()) must be bounded with islice/break or it never stops.
