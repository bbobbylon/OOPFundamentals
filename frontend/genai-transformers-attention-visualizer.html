Transformers & Attention

The architecture behind every modern LLM (GPT, Claude, Gemini, Llama): self-attention, Query/Key/Value, multi-head attention, positional encoding, and causal masking.

🧠 What is a Transformer — and why did it replace RNNs?

Before 2017, sequence models (RNNs, LSTMs) processed text one token at a time, carrying a hidden state forward — slow to train and bad at remembering things said far earlier. The Transformer (Vaswani et al., "Attention Is All You Need") replaced recurrence with self-attention: every token looks directly at every other token in a single parallel step, and learns how much to weigh each one. That's the whole trick, repeated and stacked: turn "which words matter to this word?" into a matrix multiplication a GPU can run for the entire sequence at once. Every LLM you've used — GPT, Claude, Gemini, Llama — is a stack of these attention blocks.

  • Self-attention — each token computes a Query, compares it against every token's Key, and blends their Values by relevance.
  • Fully parallel — no token-by-token loop like an RNN; the whole sequence is one matrix multiply (this is why LLMs can be trained on GPUs at massive scale).
  • Multi-head — attention runs several times in parallel with different learned projections, so different heads specialize in different relationships (syntax, coreference, etc).
  • Positional encoding + causal masking — attention alone has no sense of word order or "the future"; both are added back explicitly.

The problem

You just built a heatmap that makes it look like the model is "paying attention to" the meaningful word — and for a lot of tokens, it's lying to you.

Token 0 grabs 38% of the attention weight for a query it has nothing to do with

Run the scenario above on a long sentence and pick a query token buried in the middle — say, the word "report" in "...the quarterly report was late." You'd expect the biggest slice of its attention weight to land on "quarterly," the one word it actually needs. Instead a huge chunk lands on the very first token in the sequence: a BOS marker, or whatever word happened to start the input — a token with no semantic connection to "report" at all.

Here's why: every row of an attention matrix has to sum to exactly 1.0 — that's what softmax guarantees. When a query token doesn't have a strongly relevant match anywhere else (which is most tokens, most of the time), the leftover probability mass still has to land somewhere. Researchers studying long-context and streaming LLMs found it reliably dumps onto the first few tokens of the sequence, regardless of what those tokens say — a learned "no-op" address, not a vote for relevance.

high weight on the closest real match ✓ low weight on unrelated filler words ✓ 38% weight parked on a BOS tag ⚠

Read that 38% at face value and you'd swear the model thinks the BOS token is what matters here. It doesn't. It's a drain, not a decision.

Read attention weight as plumbing, not as an explanation
Expect a sink at the start of the sequence ↓ almost every trained decoder does this — treat a spike on position 0-2 as a pressure-release valve, not a signal Look at the RELATIVE weight among the non-sink tokens ↓ once you discount the sink, the remaining spread across real content words is where the actual "what mattered" signal lives Never ship "attention weight = explanation" to a stakeholder ↓ if you're building an audit trail for why a model flagged something, attention weight is not a citation — it wasn't validated for that job
The one-sentence rule. Softmax normalizes, it doesn't judge — a row of attention weights always sums to 1 whether or not anything in the sequence is truly relevant to the query, so a large number is proof that the row was normalized, not proof that the model found something meaningful.
Attention sinks aren't a curiosity — they're load-bearing. Long-context and streaming-inference systems keep the first few tokens pinned in the KV cache even after evicting everything else to save memory, because evicting the sink collapses output quality, even though those tokens "don't say anything."

1. Self-Attention: Query, Key, Value

Every token produces three vectors from the same embedding, via three separate learned weight matrices: a Query ("what am I looking for?"), a Key ("what do I offer?"), and a Value ("what do I actually contribute if picked?"). A token's new representation is a weighted blend of every token's Value, where the weights come from comparing its Query against every Key.

Query (Q)
X · W_q — "what I'm looking for"
Key (K)
X · W_k — "what I offer"
Value (V)
X · W_v — "what I contribute"
# scaled dot-product attention
def attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / sqrt(d_k)
    weights = softmax(scores, dim=-1)
    return weights @ V
# weights[i][j] = how much token i attends to token j
Why divide by √d_k? Dot products grow large as dimensionality increases, which pushes softmax into regions with tiny gradients. Scaling keeps the scores in a stable range so training doesn't stall.

2. Multi-Head Attention

Instead of one big attention computation, the model splits its embedding dimension into several smaller "heads" that each learn their own Q/K/V projections and run attention independently and in parallel. Each head is free to specialize — one might track adjacent-word syntax, another long-range coreference. The heads' outputs are concatenated and passed through one more learned projection.

def multi_head_attention(x, num_heads=8):
    heads = split_into_heads(x, num_heads)  # d_model=512 → 8 heads of 64
    outputs = [attention(Q_h, K_h, V_h) for h in heads]
    concat = concatenate(outputs, dim=-1)   # back to 512
    return concat @ W_o                    # final learned mix
Nothing tells a head what to specialize in — it emerges purely from gradient descent on the training objective (next-token prediction). Interpretability research has found heads that reliably do things like "attend to the previous token" or "attend to the subject of the current clause."

3. Positional Encoding

Attention itself is permutation-invariant — if you shuffled a sentence's tokens, the weighted-sum math wouldn't know the difference. So before the first attention layer, a positional encoding vector is added to each token embedding, injecting "I am at position 7" directly into the representation.

# original Transformer: fixed sinusoidal encoding
def positional_encoding(pos, i, d_model):
    angle = pos / (10000 ** (2*i / d_model))
    return sin(angle) if i % 2 == 0 else cos(angle)

x_with_position = token_embedding(x) + positional_encoding(pos, :, d_model)
# modern LLMs (GPT/Llama) often use RoPE (rotary) instead — same problem, different fix
Skip this step and a Transformer literally cannot tell "the dog bit the man" from "the man bit the dog" — attention would produce the identical set of weights either way, since it only sees a bag of Query/Key/Value vectors, not their order.

4. Encoder vs Decoder: Causal Masking

An encoder block (BERT-style) lets every token attend to every other token — full bidirectional context, since the whole input is available up front. A decoder block (GPT-style) generates text one token at a time, so during training it must be prevented from "cheating" by attending to tokens that come after the one it's predicting. The fix: add -∞ to the scores for any future position before softmax, so their weight collapses to exactly 0.

This one mask is the entire difference between BERT (encoder-only, great at understanding) and GPT (decoder-only, great at generating) — same attention math, different mask. It's also exactly what makes autoregressive generation work: at inference the model only ever needs tokens it has already produced.
