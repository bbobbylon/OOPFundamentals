Advanced Git Tools

Power tools for debugging, history manipulation, and productivity: git bisect, blame, stash, worktrees, hooks, and aliases.

What are advanced Git tools — and how do they solve problems regular Git can't?

Beyond the daily commands (add/commit/push/pull/merge), Git has powerful tools for specific problems: debugging "which commit broke this?", understanding "why was this line written this way?", and working on multiple things simultaneously without stash gymnastics. git bisect: binary search through commit history to find which commit introduced a bug. You mark a known-good commit and a known-bad commit — Git checks out the midpoint commit. You test: if bad, bisect good half is eliminated; if good, bisect bad half eliminated. Repeats until the guilty commit is found. With git bisect run mvn test, Git does this automatically — finds the regression commit in O(log n) tests instead of reading every diff. For a 300-commit range: ~8 tests to find the bug. git blame: shows which commit last modified each line of a file, who made the change, and when. Not for blaming — for understanding context: why was this written this way? What was the PR? Use IntelliJ's "Annotate" view for a better UI. Key: git blame -L 42,55 AuthService.java shows only lines 42-55. git worktree: check out multiple branches simultaneously in different directories without stashing. git worktree add ../ciam-hotfix hotfix/session-bug — creates a new directory with the hotfix branch checked out while your main directory stays on your feature branch. Two branches, two directories, one repository. Great for: reviewing a colleague's PR while you're mid-feature, or working on a hotfix without interrupting a long compile. git hooks: scripts that run automatically at specific Git events. .git/hooks/pre-commit: runs before every commit — great for linting, formatting, running fast tests. pre-push: runs before pushing — run full test suite. commit-msg: validate commit message format (Conventional Commits). Use Husky (Node.js) or pre-commit (Python) framework to manage hooks in source control.

git bisect

# Ping session bug appeared in last 300 commits # Find the guilty commit: git bisect start git bisect bad # current HEAD is broken git bisect good v1.2.0 # this tag was fine # Git checks out midpoint commit... # Test: does the bug exist? # YES: git bisect bad # NO: git bisect good # Repeat 8 times → Git finds the exact commit: # a72dd56 is the first bad commit # Automated (requires a test that exits 1 = bad, 0 = good): git bisect start git bisect bad HEAD git bisect good v1.2.0 git bisect run mvn test -pl auth-service -Dtest=PingSessionTest # Git binary searches automatically! # Finds regression commit in ~8 tests # End bisect: git bisect reset # return to original HEAD

git blame + worktree

# git blame: who wrote this and why? git blame AuthService.java # a72dd56 (Bobby 2025-11-15 14:32) 42: ... # Blame specific lines: git blame -L 42,55 src/AuthService.java # Follow renames/refactors: git blame -C -C AuthService.java # See the full commit for a line: git show a72dd56 # git worktree: multiple branches, one repo git worktree add ../ciam-hotfix hotfix/session-bug # Now: # /projects/ciam-auth/ ← main feature branch # /projects/ciam-hotfix/ ← hotfix branch # Same repo, different checkouts # List worktrees: git worktree list # Remove when done: git worktree remove ../ciam-hotfix

Hooks + aliases

# pre-commit hook (.git/hooks/pre-commit): #!/bin/sh # Run checkstyle before commit: mvn checkstyle:check -q || { echo "Checkstyle failed! Fix before commit." exit 1 } # commit-msg hook (enforce Conventional Commits): #!/bin/sh MSG=$(cat "$1") if ! echo "$MSG" | grep -qE "^(feat|fix|chore|docs|test|refactor|style|ci)\(.+\): .{10,}"; then echo "Commit message must match: type(scope): description" exit 1 fi # Useful aliases (add to ~/.gitconfig): [alias] lg = log --oneline --graph --decorate --all st = status -s undo = reset HEAD~1 --mixed # undo last commit, keep changes aliases = config --get-regexp alias

Advanced Git in CIAM work: Real scenario: "Ping sessions stopped working last Wednesday — what broke it?" git bisect start; git bisect bad HEAD; git bisect good wednesday-morning-tag; git bisect run ./test-ping-session.sh — 8 automated test runs find the exact commit (maybe the Spring Boot 3.3 upgrade changed how the Ping OAuth token response is deserialized). git blame on the session validation code — shows that a particular null-check was removed in commit b8c4d12 — git show b8c4d12 shows the full PR context and message: "removed defensive null check per PR review feedback." Now you know why and who reviewed it. Worktrees: reviewing a colleague's PR while working on your own feature — git worktree add ../pr-review PR-245. Pre-commit hook enforcing no TODO comments with a hardcoded IP or bearer token before committing — catches security issues before they hit the repo.

1 — Power Tools — Click Each to Expand

git bisect
Binary search to find the commit that introduced a bug
Binary search — tell Git which commit is "good" and which is "bad". Git checks out the midpoint, you test, then mark good or bad. Repeats until the first bad commit is found.

git bisect start
git bisect bad HEAD — current commit is broken
git bisect good v1.0.0 — this tag was fine
git bisect good/bad — after testing each candidate
git bisect reset — return to HEAD

For 1000 commits, bisect finds the culprit in ≤ 10 steps (log₂ 1000 ≈ 10). git bisect run mvn test can automate it entirely.
git blame
Who wrote which line, and when
git blame UserService.java — annotates every line with commit SHA, author, and date.

git blame -L 50,80 File.java — only lines 50–80
git blame -w — ignore whitespace changes
git blame -C — detect lines moved from another file

In IDEs: IntelliJ and VS Code have inline blame — right-click a line → "Git Blame" or "Annotate with Git Blame" to see who wrote it and the commit message without leaving the editor.
git stash
Shelve uncommitted work temporarily
git stash — shelve current changes, restore clean working tree
git stash push -m "WIP: login form" — named stash
git stash list — see all stashes
git stash pop — apply + remove latest stash
git stash apply stash@{2} — apply specific stash (keep it in list)
git stash branch feature/login — create a branch from the stash
git stash drop stash@{0} — delete a stash

Common scenario: mid-feature, urgent hotfix needed → stash → fix + push → pop → resume.
git worktree
Multiple branches checked out simultaneously
Check out a branch in a separate directory while keeping your current work intact — without stashing or switching branches.

git worktree add ../hotfix hotfix/v1.2 — new dir for hotfix branch
git worktree list — see all checked-out worktrees
git worktree remove ../hotfix — clean up

Use case: you're in the middle of a big refactor and need to review and run a hotfix. Worktree lets you open the hotfix in another terminal tab or IDE window without disturbing your main workspace.
git hooks
Run scripts on Git events
Scripts in .git/hooks/ that run on Git events. Share them via a scripts/hooks/ directory and symlink or use a tool like Husky (Node.js).

pre-commit: run linter, formatter, tests before commit
commit-msg: enforce commit message format (e.g., Jira ticket required)
pre-push: run full test suite before push
post-merge: npm install if package.json changed

chmod +x .git/hooks/pre-commit — make the hook executable.
git log —advanced
Powerful history searching and formatting
git log --oneline --graph --all — ASCII branch graph
git log --author="Alice" — filter by author
git log --since="2 weeks ago" — date filter
git log --grep="JIRA-123" — search commit messages
git log -S "functionName" — find commits that added/removed a string (pickaxe)
git log -p -- path/to/file — show diffs for a specific file's history
git log main..feature — commits in feature not in main

Alias tip: git config --global alias.lg "log --oneline --graph --all"

3 — Useful Git Aliases

# ~/.gitconfig — add to [alias] section [alias] lg = log --oneline --graph --all --decorate st = status -sb # short status with branch co = checkout br = branch -vv # branches with upstream info undo = reset HEAD~1 --mixed # undo last commit, keep changes wip = commit -am "WIP" # quick save whoami = !git config user.name && git config user.email aliases = config --get-regexp alias # Show what changed in the last N commits lastN = "!f() { git log --oneline HEAD~$1..HEAD; }; f" # Find the commit that added a string find = "!f() { git log -S \"$1\" --oneline; }; f"
