app.config.ts — All Providers Decoded

What is app.config.ts?

In Angular 14+, the standalone component API replaced AppModule as the default way to bootstrap an Angular application. Instead of decorating a class with @NgModule, you export a plain ApplicationConfig object and pass it to bootstrapApplication().

// src/app/app.config.ts
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { provideHttpClient, withFetch, withInterceptors } from '@angular/common/http';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes, withComponentInputBinding()),
    provideHttpClient(withFetch(), withInterceptors([authInterceptor])),
    provideAnimationsAsync()
  ]
};
// src/main.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch(err => console.error(err));

ApplicationConfig Interface

// Angular source — the interface is extremely simple
interface ApplicationConfig {
  providers: Array<Provider | EnvironmentProviders>;
}

EnvironmentProviders is an opaque type returned by provideRouter(), provideHttpClient() etc. It can only be used at the environment/application level — not in a component's providers array. This is a safety mechanism that prevents you from providing router configuration at the component level by mistake.

Migration from AppModule

OLD — NgModule style
@NgModule({
  declarations: [AppComponent],
  imports: [
    BrowserModule,
    RouterModule.forRoot(routes),
    HttpClientModule,
    BrowserAnimationsModule
  ],
  bootstrap: [AppComponent]
})
export class AppModule {}
NEW — Standalone style
export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),
    provideAnimations()
  ]
};

For NgModule-based third-party libraries that haven't migrated yet, use importProvidersFrom() as a bridge:

import { importProvidersFrom } from '@angular/core';

providers: [
  importProvidersFrom(SomeOldNgModule),           // bridges NgModule providers
  importProvidersFrom(MatDialogModule, MatSnackBarModule)  // multiple modules
]

provideRouter() — Router Features

provideRouter replaces RouterModule.forRoot(). Its optional feature functions (passed as extra arguments) are tree-shakeable — features you don't use are excluded from the bundle.

import {
  provideRouter, withComponentInputBinding, withViewTransitions,
  withHashLocation, withInMemoryScrolling, withPreloading,
  PreloadAllModules, withRouterConfig, withDebugTracing,
  withEnabledBlockingInitialNavigation
} from '@angular/router';

provideRouter(
  routes,
  withComponentInputBinding(),
  withViewTransitions({ skipInitialTransition: true }),
  withInMemoryScrolling({ scrollPositionRestoration: 'enabled' }),
  withPreloading(PreloadAllModules)
)
withComponentInputBinding()
Bind route params, query params, and data directly to component @Input() properties. No more ActivatedRoute injection for simple cases.
// Route definition
{ path: 'users/:id', component: UserDetailComponent }

// Component — no ActivatedRoute needed
@Input() id!: string;          // from :id route param
@Input() page!: string;        // from ?page= query param
@Input() title!: string;       // from route data: { title: 'Users' }

// Angular 17+ with signals:
id = input<string>();
withViewTransitions({ skipInitialTransition: true })
Enables CSS View Transitions API for page navigation. Cross-fade or slide animations between routes with zero JS animation code.
// app.config.ts
provideRouter(routes, withViewTransitions({ skipInitialTransition: true }))

// styles.scss — the browser handles the animation
::view-transition-old(root) {
  animation: 100ms ease-out fade-out;
}
::view-transition-new(root) {
  animation: 200ms ease-in fade-in;
}
// Works with Chrome 111+. Falls back gracefully in other browsers.
withHashLocation()
Use hash-based URLs (#/path) instead of HTML5 history API. Required when you cannot configure the web server for SPA fallback routing.
// Without: http://myapp.com/dashboard (requires server config)
// With:    http://myapp.com/#/dashboard (server only serves index.html)

// Useful for: GitHub Pages, static hosting, embedded apps
// Downside: # in URL, no real "path" for SEO
withInMemoryScrolling({ scrollPositionRestoration: 'enabled' })
Restores scroll position when navigating back in browser history. Without this, Angular SPA navigation always scrolls to top.
withInMemoryScrolling({
  scrollPositionRestoration: 'enabled', // restore on back, scroll top on forward
  anchorScrolling: 'enabled'           // fragment links (#section) work
})
withPreloading(PreloadAllModules)
Preload all lazy-loaded route modules in the background after the initial page loads. Faster subsequent navigation.
// PreloadAllModules: preload everything (simple, aggressive)
withPreloading(PreloadAllModules)

// Custom preloading strategy — only preload routes with preload:true
class SelectivePreloadStrategy implements PreloadingStrategy {
  preload(route: Route, load: () => Observable<any>) {
    return route.data?.preload ? load() : of(null);
  }
}
withPreloading(SelectivePreloadStrategy)
withEnabledBlockingInitialNavigation()
Block the browser render until the first navigation completes. Required for SSR to avoid flash of unstyled content.
// Without: Angular renders AppComponent before route resolves → blank flash
// With: Angular waits for initial route guard/resolver before rendering

// Required when using:
// - provideClientHydration() for SSR
// - Route resolvers that fetch data before component renders
withDebugTracing()
Log every router event to the console. Invaluable for debugging navigation guards and resolver order.
// Development only! Remove from production build
import { isDevMode } from '@angular/core';

provideRouter(routes, ...(isDevMode() ? [withDebugTracing()] : []))

provideHttpClient() — HTTP Features

provideHttpClient replaces HttpClientModule. Functional interceptors (plain functions) are now the recommended approach over class-based interceptors.

import {
  provideHttpClient, withInterceptors, withInterceptorsFromDi,
  withFetch, withXsrfConfiguration, withNoXsrfProtection, withJsonpSupport
} from '@angular/common/http';

provideHttpClient(
  withFetch(),                          // use Fetch API instead of XHR
  withInterceptors([authInterceptor, loggingInterceptor]),
  withXsrfConfiguration({
    cookieName: 'MY-XSRF-TOKEN',
    headerName: 'X-MY-XSRF-TOKEN'
  })
)

Functional Interceptors

Functional interceptors are plain functions — no class, no @Injectable, no DI needed. They're simpler and tree-shakeable. Use inject() inside them if you need services.

// auth.interceptor.ts — functional interceptor
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const authService = inject(AuthService);
  const token = authService.getToken();
  if (token) {
    req = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
  }
  return next(req);
};

// logging.interceptor.ts — log request timing
export const loggingInterceptor: HttpInterceptorFn = (req, next) => {
  const start = Date.now();
  return next(req).pipe(
    tap({
      finalize: () => console.log(`${req.url} — ${Date.now() - start}ms`)
    })
  );
};
// Order matters: interceptors run in declaration order for request,
// and reverse order for response (like Express middleware)
withInterceptors([authInterceptor, loggingInterceptor])
// Request:  authInterceptor → loggingInterceptor → HTTP
// Response: HTTP → loggingInterceptor → authInterceptor

Animation Providers

Angular's animation system is modular — you only pay for it if you use it. The three providers give you different trade-offs between bundle size, startup time, and animation support.

provideAnimations() standard

Loads @angular/animations synchronously at startup. Use when animations are core to your UI and needed immediately on first load.

import { provideAnimations } from '@angular/platform-browser/animations';

providers: [
  provideAnimations()   // loads BrowserAnimationsModule providers
]

provideAnimationsAsync() Angular 17+

Lazy-loads the animations library only when first needed. Reduces initial bundle size by ~60KB. The library is loaded via dynamic import when the first animation is triggered.

import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';

providers: [
  provideAnimationsAsync()  // animations loaded on-demand
]

provideNoopAnimations() — The Testing / Accessibility Choice

Provides a stub animation module where all animations complete instantly (0ms duration). Two use cases:

  • Unit tests: TestBed.configureTestingModule with provideNoopAnimations() eliminates animation timing from tests
  • Reduced motion: Check window.matchMedia('(prefers-reduced-motion: reduce)') and conditionally use this provider
import { provideNoopAnimations } from '@angular/platform-browser/animations';

// In tests:
TestBed.configureTestingModule({
  providers: [provideNoopAnimations()]
});

// Conditional based on user preference:
const prefersReduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
providers: [
  prefersReduced ? provideNoopAnimations() : provideAnimationsAsync()
]

Other Built-in Providers

provideZoneChangeDetection({ eventCoalescing: true })
Configure Zone.js change detection. eventCoalescing groups multiple browser events into a single CD cycle — reduces unnecessary checks.
// Without eventCoalescing: each event → one CD cycle
// click fires → CD runs. focusin fires → CD runs. (2 cycles)

// With eventCoalescing: batched events → one CD cycle
// click + focusin → merged → CD runs once

provideZoneChangeDetection({
  eventCoalescing: true,    // default in Angular 18+
  runCoalescing: true        // also coalesce setTimeout/Promise.then
})
provideExperimentalZonelessChangeDetection()
Remove Zone.js entirely. Change detection is triggered manually by signal changes. Angular 18+ experimental, Angular 19 stable.
// No polyfills needed for zone.js
// package.json polyfills: [] (remove zone.js)
// angular.json polyfills: [] (remove zone.js)

// Components must use signals or markForCheck():
readonly count = signal(0);
increment() { this.count.update(n => n + 1); } // triggers CD automatically
provideClientHydration(withEventReplay())
SSR hydration: Angular attaches the server-rendered HTML without re-rendering. withEventReplay() captures user interactions before hydration completes and replays them after.
import { provideClientHydration, withEventReplay } from '@angular/platform-browser';

// Only in app.config.ts (browser), not app.config.server.ts
provideClientHydration(withEventReplay())

// withEventReplay: if user clicks a button before hydration completes,
// the click event is replayed after Angular takes over. No lost interactions.
provideServiceWorker('ngsw-worker.js', { enabled: !isDevMode() })
Register the Angular Service Worker for PWA capabilities: offline caching, push notifications, background sync.
import { provideServiceWorker } from '@angular/service-worker';
import { isDevMode } from '@angular/core';

provideServiceWorker('ngsw-worker.js', {
  enabled: !isDevMode(),           // disable in dev (SW causes caching confusion)
  registrationStrategy: 'registerWhenStable:30000'  // wait 30s for app to be idle
})

// Also needs ngsw-config.json at project root:
// defines what to cache (assets, API responses), caching strategies, etc.
provideNgRxStore(reducers) + provideEffects(effects)
NgRx state management — the standalone way to register the global store and effects without StoreModule.forRoot().
import { provideStore, provideState } from '@ngrx/store';
import { provideEffects } from '@ngrx/effects';

providers: [
  provideStore({ auth: authReducer }),  // global/root store
  provideEffects(AppEffects),
  // Lazy feature states registered in the route:
  // { path: 'products', ... providers: [provideState({ products: productReducer })] }
]

Custom Providers

InjectionToken — Typed DI Tokens

Inject primitive values, config objects, or functions with full type safety using InjectionToken.

// tokens.ts — define the token
import { InjectionToken } from '@angular/core';

export const API_URL = new InjectionToken<string>('apiUrl');
export const APP_CONFIG = new InjectionToken<AppConfig>('appConfig');

// app.config.ts — provide the value
providers: [
  { provide: API_URL,    useValue: 'https://api.myapp.com' },
  { provide: APP_CONFIG, useValue: { theme: 'dark', pageSize: 20 } }
]

// component.ts — inject it
readonly apiUrl = inject(API_URL);   // string — fully typed

APP_INITIALIZER — Run Code Before Bootstrap

APP_INITIALIZER is Angular's hook to run async work before the app finishes bootstrapping. Angular waits for all initializers to complete. Use to load config, check auth state, or populate caches.

// config.service.ts
@Injectable({ providedIn: 'root' })
export class ConfigService {
  private config: AppConfig | null = null;

  load(): Promise<void> {
    return fetch('/assets/config.json')
      .then(r => r.json())
      .then(cfg => { this.config = cfg; });
  }

  get<T>(key: keyof AppConfig): T { return this.config![key] as T; }
}

// app.config.ts — APP_INITIALIZER
{
  provide: APP_INITIALIZER,
  useFactory: (cs: ConfigService) => () => cs.load(),  // factory returns a function
  deps: [ConfigService],                               // DI for the factory
  multi: true                                          // must be true
}

ENVIRONMENT_INITIALIZER

Like APP_INITIALIZER but for synchronous environment-level setup. Useful for logging, analytics, or side-effect-based initialization that doesn't need to be async.

import { ENVIRONMENT_INITIALIZER, inject } from '@angular/core';

{
  provide: ENVIRONMENT_INITIALIZER,
  useValue: () => {
    inject(LogService).init();       // inject() works here
    inject(AnalyticsService).track('app_start');
  },
  multi: true
}

Factory Providers

// Provide a value computed at runtime using other injected services
{
  provide: THEME_CONFIG,
  useFactory: (userPrefs: UserPreferencesService, platform: Platform) => {
    return platform.isMobile ? userPrefs.getMobileTheme() : userPrefs.getDesktopTheme();
  },
  deps: [UserPreferencesService, Platform]
}

// Provide based on global window object (runtime config pattern)
{
  provide: APP_CONFIG,
  useFactory: () => (window as any).APP_CONFIG || DEFAULT_CONFIG,
  deps: []
}

Multi-providers

Setting multi: true tells Angular to collect all registered values for a token into an array. When you inject the token, you get T[] not T. This is the pattern used by Angular's own extensible APIs.

// Defining a custom multi-token
const VALIDATORS = new InjectionToken<Validator[]>('validators');

// Multiple providers for the same token
providers: [
  { provide: VALIDATORS, useClass: RequiredValidator, multi: true },
  { provide: VALIDATORS, useClass: EmailValidator,    multi: true },
  { provide: VALIDATORS, useClass: MinLengthValidator, multi: true },
]

// Consuming component — gets all three
readonly validators = inject(VALIDATORS); // Validator[] (array of 3)

EnvironmentProviders vs Provider

Angular 15+ distinguishes between two provider types as a safety mechanism:

EnvironmentProviders

Returned by provideRouter(), provideHttpClient(), provideAnimations(). Can only go in: bootstrapApplication(), ApplicationConfig.providers, or route-level providers. Cannot go in a component's providers array.

Provider (plain)

Plain object providers: {provide: X, useValue: Y}, or MyService. Can go anywhere — application providers, component providers, or @Injectable({providedIn:'root'}).

// TypeScript will catch this mistake at compile time:
@Component({
  providers: [
    provideRouter(routes)   // Error: Type 'EnvironmentProviders' is not assignable to 'Provider'
  ]
})
