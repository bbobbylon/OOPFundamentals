Components & Templates

Angular apps are trees of components. A component is just a TypeScript class with a decorator that says "here's my HTML and my CSS." That's literally it.

Live demo — a real component in action

In Angular, this entire box below is one component called <app-counter>. Click the buttons — the click handler is wired through Angular's event binding (next visualizer).

<app-counter>

My first Angular component

0
</app-counter>

The four pieces of every component

// counter.component.ts
import { Component } from '@angular/core';

@Component({                                  // 1️⃣ DECORATOR — metadata
  selector: 'app-counter',                   //    the HTML tag to use this with
  standalone: true,                          //    modern Angular: no NgModule needed
  templateUrl: './counter.component.html',    // 2️⃣ TEMPLATE — what you see (HTML)
  styleUrl: './counter.component.css'         // 3️⃣ STYLES — how it looks (CSS)
})
export class CounterComponent {              // 4️⃣ CLASS — state & behavior (TS)
  title = 'My first Angular component';
  count = 0;

  increment() { this.count++; }
  decrement() { this.count--; }
  reset()     { this.count = 0; }
}

2️⃣ Template — counter.component.html

<h3>{{ title }}</h3>
<div class="count">{{ count }}</div>
<button (click)="decrement()">−</button>
<button (click)="reset()">reset</button>
<button (click)="increment()">+</button>

3️⃣ Styles — counter.component.css

/* SCOPED — only affect this component */
:host {
  display: block;
  text-align: center;
}
.count {
  font-size: 48px;
  color: #4ade80;
}

Connecting them — selector + parent template

The selector: 'app-counter' line tells Angular: "wherever you see <app-counter></app-counter> in HTML, instantiate this component there." A parent component uses it by importing it (standalone) and referencing the tag. 

// app.component.ts — the root component
import { Component } from '@angular/core';
import { CounterComponent } from './counter.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [CounterComponent],                  // must import to use the tag
  template: `
    <h1>My App</h1>
    <app-counter />                              // ← use it here!
    <app-counter />                              // ← use it as many times as you want
  `
})
export class AppComponent {}

Each tag is a fresh instance with its own count. Two counters on the page = two completely independent instances, just like new CounterComponent() twice.

Inline vs external — pick your style

External files (good for big components)

@Component({
  selector: 'app-counter',
  templateUrl: './counter.component.html',
  styleUrl:    './counter.component.css'
})

Separate files. Best when HTML > 20 lines or CSS is non-trivial. Editor gets full syntax highlighting per file.

Inline (good for tiny components)

@Component({
  selector: 'app-badge',
  template: `<span class="badge">{{ text }}</span>`,
  styles: `.badge { padding: 4px 8px; }`
})

All-in-one. Best for trivial components — badges, icons, dumb display components. Easier to read at a glance.

Standalone components — the modern way (Angular 14+, default since 17)

For years, every component had to be declared in an NgModule. As of Angular 17, standalone: true is the default — components import what they need directly, no boilerplate module file required.

❌ Old way — NgModule (still works, but verbose)

@NgModule({
  declarations: [CounterComponent],
  imports: [CommonModule, FormsModule],
  exports: [CounterComponent]
})
export class CounterModule {}

✅ New way — standalone

@Component({
  selector: 'app-counter',
  standalone: true,
  imports: [CommonModule, FormsModule],
  template: `...`
})
export class CounterComponent {}

New apps (ng new my-app) generate standalone by default. Use them. The NgModule world isn't going away — old codebases still have it everywhere — but you don't need to learn it to start building today.

Bootstrapping — how the app actually starts

// main.ts — the entry point
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent)
  .catch(err => console.error(err));
<!-- index.html — the only hand-written HTML -->
<html>
  <body>
    <app-root></app-root>                  <!-- ← Angular replaces this with the rendered AppComponent -->
  </body>
</html>

Angular finds <app-root> in the DOM, mounts AppComponent there, and from that point on the entire UI is rendered by Angular's component tree.

The file convention you'll see everywhere

Run ng generate component counter (shorthand: ng g c counter) and Angular CLI creates this:

📁 counter/
  ├── counter.component.ts← the class + @Component decorator
  ├── counter.component.html← the template
  ├── counter.component.css← scoped styles
  └── counter.component.spec.ts← unit tests (auto-generated)

Every component lives in its own folder with these (up to) 4 files. The CLI also wires it into the nearest module/imports for you. Don't fight the convention — every Angular codebase looks the same, which is a feature, not a bug.

Component-tree mental model

         <app-root>                       // root component (mounted in index.html)
       /     |     \
 <app-header> <app-sidebar> <app-main>     // three children
                          /        \
                <app-product-list>  <app-cart>
                       |
              <app-product-card> × N        // looped with *ngFor / @for

Your whole app is a tree of components. Data flows down via @Input(), events bubble up via @Output(). (We'll see exactly how in the Component Communication visualizer.)

View encapsulation — why your CSS doesn't leak

Define .title { color: red; } in counter.component.css and it ONLY affects .title elements inside <app-counter> — not any other .title on the page. Angular does this by attaching a unique attribute to your elements and rewriting your CSS. 

<!-- What you write -->
<h3 class="title">Hi</h3>

<!-- What Angular renders -->
<h3 class="title" _ngcontent-abc-1>Hi</h3>

/* What you wrote */
.title { color: red; }

/* What Angular generates */
.title[_ngcontent-abc-1] { color: red; }

Three modes: Emulated (default — the attribute trick above), ShadowDom (real browser Shadow DOM), None (global — escape hatch).

Mental model — the 4 things that make a component

1. A class

Plain TypeScript. Holds state (properties) and behavior (methods). Nothing Angular-specific about the class itself.

2. A decorator

@Component({...}) attached above the class. Tells Angular "this is a component" and provides the metadata: selector, template, styles.

3. A template

HTML, possibly with Angular's binding syntax ({{ }}, [prop], (event)). Angular compiles it into rendering instructions.

4. Styles (optional)

Scoped CSS — only affects this component's DOM. Add as many .css files as you want via styleUrls: [...].
