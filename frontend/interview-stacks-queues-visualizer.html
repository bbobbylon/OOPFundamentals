Stacks & Queues — Monotonic Stack, BFS & Deque

The patterns that unlock Next Greater Element, Sliding Window Max, Trapping Rain Water, and BFS shortest paths.

🧩 What are monotonic stacks and deques — and how do they transform O(n²) brute force into O(n) for range-comparison problems?

Beyond basic LIFO/FIFO, stacks and queues unlock powerful patterns that solve range-comparison problems in O(n) — problems where brute force requires O(n²) nested loops. Monotonic Stack: a stack that maintains a monotonically increasing or decreasing sequence of elements. When a new element violates the monotonic property, pop elements from the stack until the property is restored. Each element is pushed and popped at most once → O(n) total. Next Greater Element: classic monotonic stack application. Maintain a stack of elements whose "next greater element" hasn't been found yet. For each new element: while the stack is not empty AND the top of stack is smaller than the current element → the current element IS the next greater element for the top. Pop and record. Push current. Trapping Rain Water: for each position, water trapped = min(max-height-left, max-height-right) - height[i]. Brute force is O(n²). Monotonic stack approach: maintain a stack of bar indices. When a taller bar is found, calculate how much water fills the valley between the current bar and the one before the popped bar. O(n). Sliding Window Maximum (Deque): find the maximum element in each window of size k as the window slides. Brute force: O(n×k). Deque approach: maintain a deque of indices in decreasing order of their values. When the window slides, remove indices that fell out of the window from the front (deque.pollFirst()). Before adding a new index, remove indices from the back whose values are smaller (they can never be the maximum while the new element exists). Front of deque is always the current window's maximum. O(n). BFS with Queue: for shortest path in unweighted graphs and trees. Level-order traversal: process all nodes at distance 1 before any at distance 2. Each node's distance is determined by when it's added to the queue — guaranteed shortest path because FIFO ordering. When to reach for monotonic stack: any problem about "the next greater/smaller element," "the largest rectangle in histogram," "spans and intervals" usually has a monotonic stack solution. Think: "if I push elements and pop when I find something that breaks my monotonic invariant, what information do I gain?"

Monotonic Stack — Next Greater

// Next Greater Element: for each element, find the // first element to its RIGHT that is greater // [2,1,5,3,4] → [5,5,-1,4,-1] int[] nextGreater(int[] nums) { int n = nums.length; int[] res = new int[n]; Arrays.fill(res, -1); // default: no greater element found Deque<Integer> stack = new ArrayDeque<>(); // stores INDICES for (int i = 0; i < n; i++) { // Pop all elements smaller than current // Current element IS their next greater element while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) { int idx = stack.pop(); // this index's next greater = nums[i] res[idx] = nums[i]; } stack.push(i); // push current index } // anything remaining in stack has no greater element → stays -1 return res; // O(n) — each element pushed/popped exactly once }

Sliding Window Max (Deque)

// Sliding Window Maximum: max of each window of size k // [1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7] int[] maxSlidingWindow(int[] nums, int k) { int n = nums.length; int[] result = new int[n - k + 1]; Deque<Integer> deque = new ArrayDeque<>(); // stores INDICES // Invariant: deque is in DECREASING order of nums[i] for (int i = 0; i < n; i++) { // 1. Remove indices OUTSIDE the current window while (!deque.isEmpty() && deque.peekFirst() < i - k + 1) deque.pollFirst(); // 2. Remove indices smaller than current (they can't be max) while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) deque.pollLast(); deque.offerLast(i); // add current index // 3. Front is always the current window's maximum if (i >= k - 1) result[i - k + 1] = nums[deque.peekFirst()]; } return result; // O(n) — each element added/removed from deque once }

BFS for shortest path

// BFS: find shortest path (fewest edges) in unweighted graph // Classic: word ladder — minimum transformations from "hit" to "cog" // (change one letter at a time, each intermediate word must be valid) int ladderLength(String begin, String end, Set<String> words) { if (!words.contains(end)) return 0; Queue<String> q = new LinkedList<>(); q.offer(begin); words.remove(begin); // visited int steps = 1; while (!q.isEmpty()) { int size = q.size(); // nodes at current distance for (int i=0; i<size; i++) { String curr = q.poll(); if (curr.equals(end)) return steps; // Try changing each character to a-z char[] chars = curr.toCharArray(); for (int j=0; j<chars.length; j++) { char orig = chars[j]; for (char c='a'; c<='z'; c++) { chars[j] = c; String next = new String(chars); if (words.remove(next)) q.offer(next); // unvisited neighbor } chars[j] = orig; // restore } } steps++; // finished this BFS level → increment distance } return 0; // not reachable }

Interview / Context: Monotonic stack problems are medium-to-hard interview questions that test advanced pattern recognition. The key insight — which takes practice to internalize — is that the "pop when violated" operation is doing useful work: it's discovering relationships between elements (next greater, previous smaller) lazily, exactly when they become relevant. For BFS: in interviews, BFS is the go-to algorithm whenever the problem involves finding the minimum number of steps/moves/transformations to reach a goal — word ladder, 0/1 matrix distances, minimum knight moves. Any time you see "minimum steps" in an unweighted graph → BFS. In your Spring Boot work, BFS reasoning applies to minimum-hop delegation chain discovery in role hierarchies.

Stack — LIFO Use ArrayDeque

// CORRECT: Use Deque as a stack (not java.util.Stack!) Deque<Integer> stack = new ArrayDeque<>(); stack.push(1); // addFirst — O(1) stack.push(2); // top → [2, 1] stack.push(3); // top → [3, 2, 1] int top = stack.peek(); // 3 — no removal int val = stack.pop(); // 3 — removeFirst stack.isEmpty(); // false stack.size(); // 2 // WHY NOT java.util.Stack? // - Extends Vector → synchronized (slow) // - Has indexed access methods (not stack-like) // - Legacy class, deprecated in spirit // ArrayDeque is 2-10x faster in practice

Queue — FIFO

// Queue interface — LinkedList or ArrayDeque Queue<Integer> q = new LinkedList<>(); // Or (faster for most cases): Queue<Integer> q = new ArrayDeque<>(); q.offer(1); // add to back — O(1) q.offer(2); q.offer(3); q.peek(); // 1 — front, no removal q.poll(); // 1 — removes front q.isEmpty(); // false, q = [2, 3] // offer vs add: offer returns false on full // poll vs remove: poll returns null on empty // peek vs element: peek returns null on empty // Always prefer the "null-returning" versions
Interview tip: The interviewer may ask "why not Stack?" Answer: ArrayDeque is not synchronized, has no unnecessary methods, and is faster. It's the official recommendation in the Javadoc.

Deque — Double-Ended Queue

// Deque can act as both stack AND queue Deque<Integer> deque = new ArrayDeque<>(); // Front operations (stack-like) deque.addFirst(1); // push to front deque.removeFirst(); // pop from front (= peekFirst + remove) deque.peekFirst(); // see front without removing // Back operations (queue-like) deque.addLast(2); // enqueue to back deque.removeLast(); // remove from back deque.peekLast(); // see back without removing // Aliases: push = addFirst, pop = removeFirst, offer = addLast, poll = removeFirst // Used for: sliding window max (Pattern 4), palindrome check, monotonic deque

Pattern 1 — Monotonic Stack Must Know

Template — Next Greater Element

// O(n) — each element pushed/popped once public int[] nextGreaterElement(int[] arr) { int n = arr.length; int[] result = new int[n]; Arrays.fill(result, -1); // default: no greater Deque<Integer> stack = new ArrayDeque<>(); // Stack stores INDICES (not values!) for (int i = 0; i < n; i++) { // While top of stack has no greater yet // and current element IS greater than it while (!stack.isEmpty() && arr[stack.peek()] < arr[i]) { result[stack.pop()] = arr[i]; // found NGE! } stack.push(i); // push current index } return result; // Remaining stack: no NGE (already -1) }

Daily Temperatures — LeetCode 739

// temps=[73,74,75,71,69,72,76,73] // result=[1,1,4,2,1,1,0,0] public int[] dailyTemperatures(int[] temps) { int[] res = new int[temps.length]; Deque<Integer> stack = new ArrayDeque<>(); for (int i = 0; i < temps.length; i++) { while (!stack.isEmpty() && temps[stack.peek()] < temps[i]) { int j = stack.pop(); res[j] = i - j; // days to wait } stack.push(i); } return res; }
Why store indices not values? We need to know how far away (in days) the warmer day is: res[j] = i - j requires both positions. Always store indices in a monotonic stack unless you only need values.

Largest Rectangle in Histogram Hard

// heights=[2,1,5,6,2,3] → 10 public int largestRectangleArea(int[] heights) { Deque<Integer> stack = new ArrayDeque<>(); int maxArea = 0; int[] h = Arrays.copyOf(heights, heights.length + 1); // Append 0 to flush remaining stack at end for (int i = 0; i <= heights.length; i++) { while (!stack.isEmpty() && h[stack.peek()] > h[i]) { int height = h[stack.pop()]; int width = stack.isEmpty() ? i : i - stack.peek() - 1; maxArea = Math.max(maxArea, height * width); } stack.push(i); } return maxArea; // Key insight: for each bar, find the // leftmost and rightmost extent at that height }

Pattern 2 — Trapping Rain Water Classic Hard

Two Pointers (Optimal — O(n) time, O(1) space)

// height=[0,1,0,2,1,0,1,3,2,1,2,1] → 6 public int trap(int[] height) { int l = 0, r = height.length - 1; int leftMax = 0, rightMax = 0, water = 0; while (l < r) { if (height[l] < height[r]) { if (height[l] >= leftMax) leftMax = height[l]; else water += leftMax - height[l]; l++; } else { if (height[r] >= rightMax) rightMax = height[r]; else water += rightMax - height[r]; r--; } } return water; }

Stack Approach (intuitive)

public int trapStack(int[] height) { Deque<Integer> stack = new ArrayDeque<>(); int water = 0; for (int r = 0; r < height.length; r++) { while (!stack.isEmpty() && height[stack.peek()] < height[r]) { int mid = stack.pop(); if (stack.isEmpty()) break; int l = stack.peek(); int h = Math.min(height[l], height[r]) - height[mid]; int w = r - l - 1; water += h * w; } stack.push(r); } return water; // Stack: water fills like a bathtub // between left wall and current right wall }
Key insight (two pointers): Water at position i = min(maxLeft, maxRight) - height[i]. The smaller side determines water level. When left < right, we know maxRight >= right pointer's height which is > left pointer, so leftMax is the binding constraint.

Pattern 3 — Parentheses Matching Easy-Medium

Valid Parentheses

// s = "()[]{}" → true // s = "([)]" → false public boolean isValid(String s) { Deque<Character> stack = new ArrayDeque<>(); for (char c : s.toCharArray()) { if (c == '(' || c == '[' || c == '{') { stack.push(c); } else { if (stack.isEmpty()) return false; char top = stack.pop(); if (c == ')' && top != '(') return false; if (c == ']' && top != '[') return false; if (c == '}' && top != '{') return false; } } return stack.isEmpty(); // all matched }

Generate Parentheses (Backtracking)

// n=3 → ["((()))","(()())","(())()","()(())","()()()"] public List<String> generateParenthesis(int n) { List<String> res = new ArrayList<>(); backtrack(res, new StringBuilder(), 0, 0, n); return res; } void backtrack(List<String> res, StringBuilder cur, int open, int close, int n) { if (cur.length() == n * 2) { res.add(cur.toString()); return; } if (open < n) { // can add '(' cur.append('('); backtrack(res, cur, open + 1, close, n); cur.deleteCharAt(cur.length() - 1); } if (close < open) { // can add ')' if it closes something cur.append(')'); backtrack(res, cur, open, close + 1, n); cur.deleteCharAt(cur.length() - 1); } }

Minimum Remove to Make Valid Parentheses

// s = "lee(t(c)o)de)" → "lee(t(c)o)de" public String minRemoveToMakeValid(String s) { Set<Integer> toRemove = new HashSet<>(); Deque<Integer> stack = new ArrayDeque<>(); for (int i = 0; i < s.length(); i++) { char c = s.charAt(i); if (c == '(') { stack.push(i); // push index of unmatched '(' } else if (c == ')') { if (stack.isEmpty()) toRemove.add(i); // no matching '(' → remove else stack.pop(); // matched! pop the '(' } } // Remaining stack = unmatched '(' indices toRemove.addAll(stack); StringBuilder sb = new StringBuilder(); for (int i = 0; i < s.length(); i++) if (!toRemove.contains(i)) sb.append(s.charAt(i)); return sb.toString(); }

Pattern 4 — Sliding Window Max (Monotonic Deque) Hard / Very Common

Template

// nums=[1,3,-1,-3,5,3,6,7], k=3 // result=[3,3,5,5,6,7] public int[] maxSlidingWindow(int[] nums, int k) { int n = nums.length; int[] res = new int[n - k + 1]; Deque<Integer> dq = new ArrayDeque<>(); // deque stores INDICES, values are decreasing for (int i = 0; i < n; i++) { // Remove indices outside window while (!dq.isEmpty() && dq.peekFirst() < i - k + 1) dq.pollFirst(); // Remove smaller elements from back // (they can never be max while nums[i] exists) while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i]) dq.pollLast(); dq.offerLast(i); if (i >= k - 1) res[i - k + 1] = nums[dq.peekFirst()]; } return res; // O(n) — each element added/removed once }

Why the Deque is Monotonically Decreasing

We maintain a decreasing deque of indices.

When a new element is larger than the back of the deque, those smaller elements are useless — they can never be the max while the larger element is in the window. So we remove them.

The front of the deque is always the index of the maximum for the current window.
Time complexity: O(n) — each index is added at most once and removed at most once. Despite the nested while loops, total operations across all iterations = 2n.

Pattern 5 — BFS with Queue Very Common

Level-Order BFS Template

// Binary Tree Level Order Traversal public List<List<Integer>> levelOrder(TreeNode root) { List<List<Integer>> res = new ArrayList<>(); if (root == null) return res; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); while (!q.isEmpty()) { int levelSize = q.size(); // snapshot level size List<Integer> level = new ArrayList<>(); for (int i = 0; i < levelSize; i++) { TreeNode node = q.poll(); level.add(node.val); if (node.left != null) q.offer(node.left); if (node.right != null) q.offer(node.right); } res.add(level); } return res; // Key: snapshot levelSize BEFORE processing level }

Multi-Source BFS Template

// Rotting Oranges: all rotten oranges spread simultaneously // Add ALL sources to queue before starting BFS! Queue<int[]> q = new LinkedList<>(); // Phase 1: add all starting sources for (int i = 0; i < rows; i++) for (int j = 0; j < cols; j++) if (grid[i][j] == 2) q.offer(new int[]{i, j}); // all rotten initially // Phase 2: BFS spread int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}}; int minutes = 0; while (!q.isEmpty()) { minutes++; int size = q.size(); for (int i = 0; i < size; i++) { int[] cell = q.poll(); for (int[] d : dirs) { int r = cell[0]+d[0], c = cell[1]+d[1]; if (r>=0 && r<rows && c>=0 && c<cols && grid[r][c] == 1) { grid[r][c] = 2; q.offer(new int[]{r, c}); } } } }
Multi-source BFS: all sources are equidistant (distance 0) from each other, so by adding all of them to the queue first, BFS naturally spreads in parallel from all of them.

Classic BFS Problems

Word Ladder

Each BFS level = one transformation. Add all valid one-letter-change neighbors. Use HashSet for wordList for O(1) lookup. Remove words as visited to avoid cycles.
O(M² × N)

01 Matrix

Multi-source BFS: start from all 0-cells. BFS distance from the nearest 0 for each 1-cell. dist[r][c] = dist of its BFS-level parent + 1.
O(rows × cols)

Shortest Path in Binary Grid

Standard BFS on grid. State = (row, col). Avoid revisiting: mark cell as visited. 8-directional movement.
O(N²)
