Data Binding — the 4 flavors

Binding is how the component class and the template stay in sync. Four syntaxes, three directions of data flow. Memorize the punctuation and you've got 90% of Angular templates figured out.

Direction of data flow — the mental model

Component class ────{{ value }}───→ Template  # 1. Interpolation (one-way)
Component class ──[prop]="value"──→ Template / DOM  # 2. Property binding (one-way)
Component class ←(event)="handler()"── Template / DOM  # 3. Event binding (one-way up)
Component class ←[(ngModel)]="value"→ Template / DOM  # 4. Two-way binding

Mnemonic: the punctuation tells the direction. [] = data IN to the DOM. () = events OUT of the DOM. [()] = both, the "banana in a box". Interpolation {{ }} is just shorthand for property binding to textContent.

Try all four — click around

1. Interpolation

{{ expression }}

Insert a class property's value into the rendered HTML as text.

Hello, Bobby!
2 + 2 = 4 (yes, expressions work)
// .ts
name = 'Bobby';

<!-- .html -->
Hello, {{ name }}!
2 + 2 = {{ 2 + 2 }}

2. Property binding

[domProperty]="expression"

Bind a class value to a DOM property (not attribute). Direction: TS → DOM.

disabled: false
// .ts
logoUrl = '/assets/logo.png';
isDisabled = false;

<!-- .html -->
<img [src]="logoUrl">
<button [disabled]="isDisabled">...</button>

3. Event binding

(domEvent)="handler($event)"

Run a class method when the DOM fires an event. Direction: DOM → TS.

clicks: 0
last key: —
// .ts
clicks = 0;
onClick() { this.clicks++; }
onKey(e: KeyboardEvent) { console.log(e.key); }

<!-- .html -->
<button (click)="onClick()">...</button>
<input (keyup)="onKey($event)">

4. Two-way binding

[(ngModel)]="property"

Both at once: TS → DOM and DOM → TS. The "banana in a box".

value: ''
// .ts
text = '';

<!-- .html -->
<input [(ngModel)]="text">
<!-- expands to: -->
<input [ngModel]="text" (ngModelChange)="text = $event">

The most common gotchas

⚠️ Attribute vs property

HTML attributes initialize the DOM property. Once rendered, attribute and property can drift. [src] binds the PROPERTY (what the browser actually uses); writing src="{{url}}" binds the attribute. Always prefer [] for dynamic values.

⚠️ ngModel needs FormsModule

If [(ngModel)]="text" doesn't compile, you forgot to import FormsModule in your component's imports: []. Reactive forms use a different module entirely.

⚠️ Don't put logic in templates

Templates re-evaluate on every change-detection cycle. {{ heavyCompute() }} runs constantly. Compute in ngOnInit or use a computed() signal / memoized getter.

⚠️ The $event variable

Inside an event binding, $event is the DOM event (or the emitted value if it's a custom component event). Pass it: (click)="handle($event)". Without it, methods receive undefined.

Bonus: key modifiers — common shortcut

<!-- Run save() only when Enter is pressed -->
<input (keyup.enter)="save()">

<!-- Ctrl+S, Escape, etc -->
<textarea (keyup.control.s)="save()"></textarea>
<div (keydown.escape)="close()">...</div>

Beats reading $event.key === 'Enter' every time. Modifiers: .shift, .control, .alt, .meta (cmd/win key), .enter, .escape, .tab, .space.

Template reference variables — grab the DOM directly

<!-- #nameBox creates a reference to this input -->
<input #nameBox placeholder="your name">
<button (click)="greet(nameBox.value)">say hi</button>
<p>Length: {{ nameBox.value.length }}</p>

Useful for one-off "I just need this input's value when the user clicks save" — saves you wiring up [(ngModel)] and a class property. Reference variables can also point at a directive instance: #form="ngForm".

Mental model — when to reach for which

Display a value

Use {{ }} for text content. Use [prop] for anything else (src, href, disabled, value, etc).

React to user input

Use (event). Add $event if you need the event object.

Form input that the class also writes to

Use [(ngModel)] for template-driven simplicity, or pair [value]+(input) manually for full control.

One-off DOM access

Use #ref template variable. No class property needed.
