Go Interfaces & Embedding

Implicit interface satisfaction (duck typing), the interface value (type + data), struct embedding for composition, and the io.Reader / io.Writer design pattern.

🦆 What are Go interfaces — and why is implicit satisfaction so different from Java?

Go interfaces are satisfied implicitly — a type implements one just by having the methods, no implements keyword. This structural/duck typing means you define the interface in the consumer package with only the methods it needs, decoupling it from the provider. An interface value is a (type, data) pair, which causes the classic gotcha: an interface holding a nil pointer is not a nil interface (the type is set). Go has no inheritance — you embed structs (type Admin struct { User; ... } promotes User's methods) and compose interfaces by embedding (io.ReadWriter). The one-method io.Reader/io.Writer are so simple they're universally composable — files, HTTP bodies, gzip, JSON encoders all implement them.

  • Implicit satisfaction — have the methods, you implement it; no implements.
  • Define interfaces in the consumer — only the methods it needs; decoupled.
  • Interface value = (type, data) — a nil pointer inside is NOT a nil interface.
  • Embed, don't inherit — promoted methods; io.Reader/Writer compose everywhere.

Implicit satisfaction

// Interface defined by the CONSUMER type IdpClient interface { CreateUser(ctx context.Context, req CreateUserReq) (*User, error) DeleteUser(ctx context.Context, userID string) error AssignRole(ctx context.Context, userID, role string) error } // PingClient satisfies WITHOUT "implements": type PingClient struct { BaseURL string; Token string } func (c *PingClient) CreateUser(...) (*User, error) { // ... call Ping API } func (c *PingClient) DeleteUser(...) error { ... } func (c *PingClient) AssignRole(...) error { ... } // Compile-time check (common pattern): var _ IdpClient = (*PingClient)(nil) // If PingClient doesn't fully implement IdpClient, // this line causes a compile error

Interface value + nil gotcha

// Interface value = (type, data) pair var client IdpClient = &PingClient{...} // interface value: (type=*PingClient, data=ptr) // THE GOTCHA: var p *PingClient = nil // nil pointer var c IdpClient = p // NOT a nil interface! // interface value: (type=*PingClient, data=nil) if c == nil { // FALSE! fmt.Println("nil") // this never runs } // c is non-nil (type is set) but calling methods // on c will call *PingClient methods on nil receiver // Safe nil check: if c == nil { ... } // only true if BOTH nil // Type assertion to check concrete type: if pc, ok := c.(*PingClient); ok && pc == nil { ... }

Embedding + io.Reader pattern

// Struct embedding (composition, not inheritance): type User struct { ID int; Name string; Email string } type Admin struct { User // embedded — promotes all methods/fields CanDelete bool } admin := Admin{User: User{1,"Bob","b@eg.com"}, CanDelete: true} admin.Name // "Bob" — promoted from User // io.Reader: read from anything // type Reader interface { Read(p []byte) (n int, err error) } // Works with: // os.File, http.Response.Body, strings.NewReader(""), // gzip.Reader, csv.Reader, json.Decoder // Decode JSON from HTTP response (both io.Reader): resp, _ := http.Get(url) defer resp.Body.Close() // io.ReadCloser (embeds Reader) json.NewDecoder(resp.Body).Decode(&result)

Go interfaces vs Java/Spring: Java needs class PingClient implements IdpClient; Go needs nothing — having the right methods is enough, so you can wrap a third-party type in your own interface without touching its source (in Spring you'd need an adapter or subclass). TypeScript's structural typing works the same way. And mocking is trivial: define a test interface with just the method you need and implement it inline — type mockIdp struct{}; func (m *mockIdp) CreateUser(...) (*User, error) { return &User{}, nil }.

1. Interfaces are Implicit

In Go, a type implements an interface by implementing all its methods — no implements keyword, no declaration. If the method set matches, the interface is satisfied. This is structural typing ("duck typing").

// Interface defined in the consumer package
type Stringer interface {
  String() string
}

// User defined independently — no "implements Stringer"
type User struct { Name, Email string }
func (u User) String() string {
  return u.Name + " <" + u.Email + ">"
}

// User satisfies Stringer — no changes needed to User
var s Stringer = User{Name: "Alice", Email: "a@b.com"}
// Interface defined by consumer, not producer
// This is the key Go principle: define small interfaces
// at the POINT OF USE, not alongside the concrete type

type Repository interface {
  FindByID(id int) (*User, error)
  Save(u *User) error
}

// PostgresRepo satisfies Repository automatically
// MockRepo satisfies it too — perfect for testing
// No coupling between producer and consumer packages

Define interfaces where they are USED, not where the concrete type lives. This lets you introduce an interface for testing without changing the original package.

2. The Interface Value (Two-Word Header)

An interface variable holds two words: a type pointer (which concrete type implements this interface) and a data pointer (the value). A nil interface has both as nil. A non-nil interface wrapping a nil pointer is NOT nil — a famous Go gotcha.

The nil interface gotcha: var p *PostgresRepo = nil; var r Repository = p — here r != nil even though p is nil, because r holds (type=*PostgresRepo, data=nil). Checking r != nil passes. Calling a method on r may panic. Always return typed nil (return nil, err) instead of assigning a nil pointer to an interface.

3. Embedding vs Inheritance

// Embedding promotes methods to the outer type
type Base struct { ID int; CreatedAt time.Time }
func (b Base) Age() time.Duration {
  return time.Since(b.CreatedAt)
}

type User struct {
  Base // embedded — no field name
  Name, Email string
}

u := User{Base: Base{ID: 1, CreatedAt: time.Now()}}
u.Age() // promoted from Base — no delegation needed
u.ID // also promoted
// Embedding satisfies interfaces too
type Logger interface { Log(msg string) }

type ConsoleLogger struct{}
func (l ConsoleLogger) Log(msg string) { fmt.Println(msg) }

type Service struct {
  ConsoleLogger // Service now satisfies Logger!
  DB *sql.DB
}

// var l Logger = Service{...} ← valid

Embedding promotes all methods and fields. The outer type automatically satisfies any interfaces satisfied by the embedded type. This is Go's composition-based alternative to inheritance.
