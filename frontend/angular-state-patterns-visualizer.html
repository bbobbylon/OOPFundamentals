Angular State Management — Patterns & Comparison

Five patterns from a simple BehaviorSubject to NgRx SignalStore — with the same todo app implemented in all five.

1. Why State Management?

Sharing Data

Components need the same data. Without a shared state layer you either pass data down through many layers (prop drilling) or duplicate API calls.

Derived State

The total cart price is derived from cart items. The unread count is derived from messages. State management tools make derivation automatic and consistent.

Predictability

With mutable service fields anything can change state at any time. A state store enforces clear update paths — easier to debug, test, and reason about.

2. The Five Patterns — Side by Side

Beginner RxJS Best for small-medium apps. Easy to start, hard to scale. 
import { Injectable, signal } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

interface TodoState {
  items: Todo[];
  filter: 'all' | 'active' | 'done';
}

@Injectable({ providedIn: 'root' })
export class TodoService {
  private readonly _state = new BehaviorSubject<TodoState>({
    items: [],
    filter: 'all'
  });

  // Public read-only observable
  readonly state$ = this._state.asObservable();

  // Derived observables using map
  readonly items$ = this.state$.pipe(map(s => s.items));
  readonly count$ = this.items$.pipe(map(i => i.length));
  readonly doneCount$ = this.items$.pipe(map(i => i.filter(x => x.done).length));

  addTodo(text: string) {
    const current = this._state.value;
    this._state.next({
      ...current,
      items: [...current.items, { id: Date.now(), text, done: false }]
    });
  }

  toggle(id: number) {
    const s = this._state.value;
    this._state.next({
      ...s,
      items: s.items.map(t => t.id === id ? {...t, done: !t.done} : t)
    });
  }
}

// Component usage:
// items$ | async in template, or toSignal(service.items$)
Medium Signals Zero RxJS required. Works great with zoneless Angular. 
@Injectable({ providedIn: 'root' })
export class TodoStore {
  // Private writable signals
  private readonly _items = signal<Todo[]>([]);
  private readonly _filter = signal<'all'|'active'|'done'>('all');

  // Public read-only signals
  readonly items = this._items.asReadonly();
  readonly filter = this._filter.asReadonly();

  // Computed (auto-derived, memoized)
  readonly count = computed(() => this._items().length);
  readonly doneCount = computed(() =>
    this._items().filter(t => t.done).length
  );
  readonly visibleItems = computed(() => {
    const f = this._filter();
    return f === 'all' ? this._items()
      : this._items().filter(t => f === 'done' ? t.done : !t.done);
  });

  // Methods that mutate state
  addTodo(text: string) {
    this._items.update(items => [
      ...items, { id: Date.now(), text, done: false }
    ]);
  }

  toggle(id: number) {
    this._items.update(items =>
      items.map(t => t.id === id ? {...t, done: !t.done} : t)
    );
  }

  setFilter(f: 'all'|'active'|'done') {
    this._filter.set(f);
  }
}

Advanced ComponentStore Component-scoped NgRx-style state. Lifecycle tied to component. 
interface TodoState { items: Todo[]; filter: string; }

@Injectable()
export class TodoComponentStore
  extends ComponentStore<TodoState> {

  constructor() {
    super({ items: [], filter: 'all' });
  }

  // Selectors
  readonly items$ = this.select(s => s.items);
  readonly count$ = this.select(this.items$, i => i.length);

  // Updaters (synchronous state changes)
  readonly addTodo = this.updater((state, text: string) => ({
    ...state,
    items: [...state.items, { id: Date.now(), text, done: false }]
  }));

  readonly toggle = this.updater((state, id: number) => ({
    ...state,
    items: state.items.map(t =>
      t.id === id ? {...t, done: !t.done} : t)
  }));

  // Effects (async operations)
  readonly loadFromApi = this.effect((trigger$: Observable<void>) =>
    trigger$.pipe(
      switchMap(() =>
        inject(TodoHttpService).getAll().pipe(
          tapResponse(
            todos => this.patchState({ items: todos }),
            err => console.error(err)
          )
        )
      )
    )
  );
}

Newest @ngrx/signals Angular 17+. Signals all the way down. No RxJS required. 
import { signalStore, withState, withComputed,
         withMethods, withHooks } from '@ngrx/signals';

export const TodoStore = signalStore(
  { providedIn: 'root' },

  // Initial state — all keys become signals automatically
  withState({
    items: [] as Todo[],
    filter: 'all' as Filter,
    loading: false
  }),

  // Computed signals (derived, memoized)
  withComputed(({ items, filter }) => ({
    count: computed(() => items().length),
    doneCount: computed(() =>
      items().filter(t => t.done).length),
    visibleItems: computed(() => {
      const f = filter();
      return f === 'all' ? items()
        : items().filter(t =>
          f === 'done' ? t.done : !t.done);
    })
  })),

  // Methods that mutate state via patchState
  withMethods((store, http = inject(TodoHttpService)) => ({
    addTodo(text: string) {
      patchState(store, { items: [
        ...store.items(),
        { id: Date.now(), text, done: false }
      ]});
    },
    toggle(id: number) {
      patchState(store, { items:
        store.items().map(t =>
          t.id === id ? {...t, done: !t.done} : t)
      });
    },
    async loadAll() {
      patchState(store, { loading: true });
      const todos = await firstValueFrom(http.getAll());
      patchState(store, { items: todos, loading: false });
    }
  })),

  withHooks({
    onInit: (store) => store.loadAll()
  })
);

4. Decision Matrix — Which Pattern to Use?

Pattern App Size RxJS Required DevTools Boilerplate Best For
BehaviorSubject Service Small Yes No Low Prototypes, simple shared data
Signals Store Small–Med No Limited Low Modern apps, zoneless, simple state
NgRx Store Large Yes Full Redux DevTools High Enterprise, teams, time-travel debug
ComponentStore Component Yes Limited Medium Complex components with rich local state
SignalStore (@ngrx/signals) Med–Large Optional NgRx DevTools Medium New Angular 17+ projects wanting NgRx+signals

5. State Management Anti-Patterns

Mutable Service State

// Don't do this:
class UserService {
  users: User[] = []; // mutable!
  add(u: User) {
    this.users.push(u); // mutation!
  }
}

Components hold references to the array — changes don't trigger change detection in OnPush components.

God Service

// Don't do this:
class AppStateService {
  user: User;
  cart: CartItem[];
  notifications: Notification[];
  settings: Settings;
  // 200 methods...
}

One service with everything creates tight coupling, makes testing impossible, and no clear boundaries.

Prop Drilling

// Don't do this:
<app-page [user]="user">
  <app-header [user]="user">
    <app-avatar [user]="user">
    </app-avatar>
  </app-header>
</app-page>

Passing data through intermediate components that don't need it. Lift state to a shared service instead.
