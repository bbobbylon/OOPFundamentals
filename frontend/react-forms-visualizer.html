React Forms & Validation

Controlled inputs, React Hook Form (RHF) for performance, Zod schema validation, and form submission with error handling.

📝 What are controlled vs uncontrolled forms — and why does React Hook Form perform better?

Controlled: React owns the value — every keystroke runs onChange→setState→re-render, enabling instant validation but re-rendering the whole form constantly. Uncontrolled: the DOM owns the value, React reads it via a ref on submit — no re-renders while typing, much faster. React Hook Form takes the uncontrolled path (inputs registered with refs), only re-rendering when error state changes: a 20-field form that costs ~2000 re-renders controlled costs ~20 with RHF. It pairs with Zod — one schema both validates data and infers the TypeScript type (z.infer<typeof schema>), no separate interface. Angular's Reactive Forms (FormGroup/FormControl) are the closest equivalent.

  • Controlled = React owns value — validates live, re-renders every keystroke.
  • Uncontrolled = DOM owns value — ref-read on submit, no typing re-renders.
  • RHF uses refs — ~20 re-renders vs ~2000; only re-renders on error changes.
  • Zod = one schema validates AND infers the type; ≈ Angular Validators + typed FormGroup.

Controlled form

// Controlled: React drives value via state function LoginForm() { const [email, setEmail] = useState(''); const [password, setPassword] = useState(''); const [error, setError] = useState(''); const handleSubmit = async (e: FormEvent) => { e.preventDefault(); try { await login(email, password); } catch (err) { setError('Invalid credentials'); } }; return ( <form onSubmit={handleSubmit}> <input value={email} onChange={e => setEmail(e.target.value)} /> <input type="password" value={password} onChange={e => setPassword(e.target.value)} /> {error && <p>{error}</p>} <button type="submit">Login</button> </form> ); }

RHF + Zod

// Schema + type from one definition const schema = z.object({ email: z.string().email('Invalid email'), password: z.string().min(8, 'Min 8 characters'), }); type LoginData = z.infer<typeof schema>; function LoginForm() { const { register, handleSubmit, formState: { errors } } = useForm<LoginData>({ resolver: zodResolver(schema) }); const onSubmit = (data: LoginData) => login(data.email, data.password); return ( <form onSubmit={handleSubmit(onSubmit)}> <input {...register('email')} /> {errors.email && <p>{errors.email.message}</p>} <input type="password" {...register('password')} /> <button type="submit">Login</button> </form> ); }

Angular Forms comparison

React RHF concept → Angular equivalent. useForm() → new FormGroup({...}). register('email') → formControlName="email" in template. formState.errors → form.get('email')?.errors. zodResolver(schema) → Angular Validators (Validators.email, Validators.minLength(8)). handleSubmit(onSubmit) → (ngSubmit)="onSubmit()". Zod's type inference → Angular's form group is typed with strict typing in Angular 14+: FormGroup<{email: FormControl<string>}>. Both approaches support validation on submit only or on touch or on every keystroke (updateOn: 'change' | 'blur' | 'submit' in Angular; mode: 'onSubmit' | 'onBlur' | 'onChange' in RHF).

CIAM React app: A create-user form's Zod schema (email: z.string().email(), role: z.enum(['CIAM_ADMIN','CIAM_READER','CIAM_AUDITOR']), idpType: z.enum(['PING','ENTRA'])) yields a CreateUserDto via z.infer — the same shape as the Spring Boot CreateUserRequest record. On submit, POST to /api/users and map a 409 Conflict to setError('email', { message: 'Email already exists' }). The schema is the single source of truth for rules and types — the front-end mirror of @NotBlank @Email Bean Validation.

1. Controlled vs Uncontrolled

Controlled — React owns the value

const [email, setEmail] = useState("");
<input
  value={email}
  onChange={e => setEmail(e.target.value)}
/>
// Every keystroke → setState → re-render
// Input ALWAYS shows state value

Pros: instant validation, conditional logic, derive other state. Cons: re-render on every keystroke — can be slow for large forms.

Uncontrolled — DOM owns the value

const emailRef = useRef();
<input ref={emailRef} defaultValue="" />
// Read value only when needed:
const value = emailRef.current.value;
// No re-renders on keystroke

Pros: no keystroke re-renders. Cons: harder to validate live, can get out of sync. React Hook Form is the best of both — refs under the hood, controlled API on top.

2. React Hook Form — The Right Way

const {
  register, handleSubmit,
  formState: { errors, isSubmitting }
} = useForm({ resolver: zodResolver(schema) });

// register() returns { ref, onChange, onBlur, name }
<input {...register("email", { required: true })} />
{errors.email && <span>{errors.email.message}</span>}
// handleSubmit validates then calls your fn
const onSubmit = async (data) => {
  // data is fully typed, validated
  await createUser(data);
};
<form onSubmit={handleSubmit(onSubmit)}>
  ...
  <button disabled={isSubmitting}>Save</button>
</form>

RHF uses uncontrolled refs internally — no re-render on keystroke. Only re-renders on submit or on validation changes. Orders of magnitude faster for large forms.

3. Zod Schema

const schema = z.object({
  email: z.string().email("Invalid email format"),
  password: z.string().min(8, "Min 8 characters").regex(/[A-Z]/, "Need uppercase"),
  confirmPassword: z.string(),
  age: z.number().min(18, "Must be 18+").max(120),
}).refine(data => data.password === data.confirmPassword, {
  message: "Passwords do not match",
  path: ["confirmPassword"], // attach error to this field
});

// TypeScript type is automatically inferred:
type UserForm = z.infer<typeof schema>;
// { email: string; password: string; confirmPassword: string; age: number }
Zod + React Hook Form = end-to-end type safety. The same schema can validate on the frontend and backend. z.infer<typeof schema> gives you a TypeScript type for free — no separate interface needed. Cross-field validation (password match) uses .refine().
