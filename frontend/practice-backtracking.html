Backtracking — Coding Practice

Six classic "try it, undo it, try the next thing" problems — the hardest pattern to reason about until you've written a few. Real code, real hidden tests.

Backtracking is DFS with an undo step: pick a choice, recurse deeper as if it were permanent, and when that path is exhausted, undo the choice and try the next one. Every exercise here follows that shape. One grading note that matters for three of them: Subsets and Combinations expect the elements WITHIN each result to stay in their original input order (e.g. [1, 3] is graded as correct, [3, 1] is not, even though both are "the same subset") — this page's outer LISTING order is still flexible (any order of results is accepted), but a fixed inner-ordering rule is what lets an automated grader check a backtracking answer at all. Permutations and Letter Combinations need no such rule — every valid output is already a uniquely fixed sequence, so any listing order works. N-Queens asks for a COUNT only (not the actual boards) to sidestep the same "which layout is canonical" question entirely. Pick a language tab, write the function, press Run Tests. Stuck?
