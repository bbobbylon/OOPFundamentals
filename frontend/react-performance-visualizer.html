React Performance & Rendering

React.memo, useMemo, useCallback, Suspense for code splitting, and startTransition for keeping the UI responsive — measurable wins, not premature optimization.

⏱️ What are React performance tools — and when do you actually need them?

By default a state/props change re-renders a component and all its children — fast enough for most apps, but large lists and heavy trees need the toolkit. React.memo skips a child whose props are shallow-equal. useMemo caches a computed value between renders (sort only when users changes); useCallback caches a function reference so memoized children don't see a "new" function each render. Suspense + React.lazy code-splits a component into its own bundle, downloaded on demand. startTransition marks an update non-urgent so typing/clicking stay responsive. The rule: profile first (DevTools Profiler), optimize second — useMemo/useCallback aren't free.

  • React.memo skips a child when props are shallow-equal.
  • useMemo/useCallback cache a value / function ref across renders.
  • Suspense + lazy code-split bundles, loaded on demand.
  • startTransition defers heavy updates; profile before optimizing.

React.memo

// UserRow only re-renders if user or onEdit prop changes const UserRow = React.memo(function UserRow({ user, onEdit }: { user: UserDto; onEdit: (id: number) => void }) { console.log('UserRow render:', user.id); return ( <tr> <td>{user.name}</td> <button onClick={() => onEdit(user.id)}>Edit</button> </tr> ); }); // In parent: must useCallback for onEdit // otherwise new function ref every render // = memo check always fails const handleEdit = useCallback((id: number) => { navigate(\`/users/${id}/edit\`); }, [navigate]); // Now UserRow memo works correctly

Suspense + lazy loading

// Code split: each page = separate JS bundle const UserListPage = React.lazy(() => import('./pages/UserListPage')); const UserDetailPage = React.lazy(() => import('./pages/UserDetailPage')); // Wrap with Suspense in router function App() { return ( <Suspense fallback={<div>Loading...</div>}> <Routes> <Route path="/users" element={<UserListPage />} /> <Route path="/users/:id" element={<UserDetailPage />} /> </Routes> </Suspense> ); } // Browser only downloads UserDetailPage.js // when user navigates to /users/:id // First visit: fetch + parse. Subsequent: cached.

startTransition

// Search box: typing should feel instant // Filtering 10k users can lag function UserSearch() { const [inputValue, setInputValue] = useState(''); const [searchQuery, setSearchQuery] = useState(''); const [isPending, startTransition] = useTransition(); const handleChange = (e: ChangeEvent<HTMLInputElement>) => { setInputValue(e.target.value); // urgent: instant startTransition(() => { setSearchQuery(e.target.value); // non-urgent: deferred }); }; return ( <> <input value={inputValue} onChange={handleChange} /> {isPending && <Spinner />} <UserList query={searchQuery} /> </> ); }

CIAM React app: On a 10k-user table: React.memo(UserRow) so only changed rows re-render on sort/filter, useMemo on the sorted array so it doesn't re-sort every keystroke, React.lazy for the rarely-visited audit-log page, and startTransition to keep the search input instant while the filter is deferred. Angular maps these to OnPush (≈ React.memo), trackBy (≈ keys), @defer (≈ lazy + Suspense), and Signals (≈ useMemo). Both stacks: profile first, don't optimize prematurely.

1. When React Re-renders

React re-renders a component when: (1) its state changes via setState/dispatch, (2) its parent re-renders and passes new props, (3) a Context it consumes changes value. By default, every child re-renders when the parent re-renders, even if the child's props have not changed.

React.memo wraps a component and does a shallow prop comparison before re-rendering. If all props are equal (Object.is), React SKIPS the re-render entirely. The caveat: if any prop is a new function or object reference on each parent render, memo is useless — stabilize those with useCallback/useMemo.

❌ Unstable callback breaks memo

// Parent re-renders → new fn reference every time
function Parent() {
  // NEW function on every Parent render:
  const handleClick = () => dispatch({type:"INC"});
  return <MemoChild onClick={handleClick} />;
}
// React.memo(MemoChild) → ALWAYS re-renders
// because handleClick !== handleClick (new ref)

✅ useCallback stabilizes

// dispatch is stable (from useReducer)
function Parent() {
  // SAME function reference while dispatch stable:
  const handleClick = useCallback(
    () => dispatch({type:"INC"}), [dispatch]);
  return <MemoChild onClick={handleClick} />;
}
// React.memo(MemoChild) → SKIPS re-render ✅

2. Suspense + React.lazy (Code Splitting)

// Lazily load heavy components
const Dashboard = React.lazy(
  () => import("./Dashboard")
);

// Wrap with Suspense
<Suspense fallback={<Spinner />}>
  <Dashboard />
</Suspense>

Webpack / Vite splits Dashboard into a separate JS chunk. The chunk is only downloaded when Dashboard first renders — not in the initial bundle.

// Route-based code splitting (most common)
const router = createBrowserRouter([
  { path: "/", element: <Home /> },
  { path: "/dashboard", element:
    <Suspense fallback={<PageSpinner />}>
      <Dashboard />
    </Suspense>
  },
]);
// Initial bundle is small; dashboard JS downloads on demand

Route-level splitting is the highest ROI — each route becomes a separate chunk, downloaded only when the user navigates there.

3. useTransition — Keep Input Responsive

const [isPending, startTransition] = useTransition();

function handleInput(e) {
  // URGENT: update the input immediately
  setQuery(e.target.value);

  // NON-URGENT: defer the expensive list filter
  startTransition(() => {
    setFilteredItems(filterItems(items, e.target.value));
  });
}

// During the transition: input stays responsive
// isPending = true → show loading indicator on list
{isPending && <ListSpinner />}
startTransition marks work as non-urgent. React may pause and resume this work if a higher-priority update comes in (like another keystroke). Without startTransition, filtering 50,000 items blocks the browser from updating the input, making it feel laggy. With it: input updates instantly, list updates when the browser has time.
