index.html

⚙️ What is index.html in an Angular app — and how does the CLI transform it during every build?

index.html is the HTML shell file that bootstraps your Angular application. It's a static file that Angular doesn't render into at request time — it's transformed by the CLI at build time. The source src/index.html you author is intentionally minimal: a <!doctype html>, a <html> tag, some meta tags, a <title>, and the root component selector (<app-root>). You do NOT include <script> or <link> tags for your app's JS and CSS — the Angular CLI injects those automatically at build time. The CLI adds: hashed script tags (<script src="main.a1b2c3d4.js" type="module">), hashed CSS link tags (<link rel="stylesheet" href="styles.a1b2c3d4.css">), and optionally inline critical CSS and font preload hints. base href: the <base href="/"> tag is critical for Angular Router. It tells the browser what the "base" of all relative URLs is. Without it, Angular Router's pushState navigation breaks on deep links (navigating to /users/123 and refreshing sends the browser to the wrong relative base). If your app is served from a subdirectory (/my-app/), set <base href="/my-app/"> and configure it in ng build --base-href /my-app/. CSP (Content Security Policy): the <meta http-equiv="Content-Security-Policy"> tag restricts what resources the browser loads. For CIAM apps: script-src 'self' prevents injected scripts, connect-src 'self' https://api.myco.com https://ping.myco.com whitelists only your API and Ping OAuth endpoints. CSP is a critical security layer — XSS attacks that can't load scripts or send data anywhere are neutralized. Performance hints: <link rel="preload"> for critical resources, <link rel="preconnect"> to pre-establish connections to API domains.

index.html anatomy

<!doctype html> <html lang="en"> <head> <meta charset="utf-8"> <title>CIAM Portal</title> <base href="/"> <!-- base href is CRITICAL for Angular Router --> <meta name="viewport" content="width=device-width, initial-scale=1"> <link rel="icon" type="image/x-icon" href="favicon.ico"> <!-- Preconnect to your API domain (DNS resolved early) --> <link rel="preconnect" href="https://api.myco.com"> <link rel="preconnect" href="https://ping.myco.com"> <!-- CLI injects at build time (NOT in source): --> <!-- <link rel="stylesheet" href="styles.a1b2c3d4.css"> --> </head> <body> <app-root></app-root> <!-- CLI injects: --> <!-- <script src="main.a1b2c3d4.js" type="module"></script> --> </body></html>

base href explained

<!-- Without base href="/" : --> <!-- User navigates to: https://app.co/users/123 --> <!-- Browser refreshes the page --> <!-- Browser looks for: --> <!-- main.js at /users/123/main.js ← WRONG! --> <!-- With base href="/" : --> <base href="/"> <!-- Browser always resolves relative URLs from / --> <!-- main.js → /main.js ← CORRECT --> <!-- Subdirectory deployment: --> <base href="/ciam-portal/"> <!-- Or at build time: --> <!-- ng build --base-href /ciam-portal/ --> <!-- Server must rewrite ALL paths to index.html: --> <!-- nginx: try_files $uri $uri/ /index.html; --> <!-- Without this: refreshing /users/123 → 404 --> <!-- (server doesn't know /users/123 route -- Angular Router handles it client-side) -->

CSP for CIAM (security)

<!-- Content Security Policy for CIAM Angular app --> <meta http-equiv="Content-Security-Policy" content=" default-src 'self'; script-src 'self'; <!-- NO unsafe-inline, NO unsafe-eval --> <!-- Prevents injected <script> from running --> style-src 'self' 'unsafe-inline'; <!-- unsafe-inline needed for Angular Material + --> <!-- dynamically generated styles --> connect-src 'self' https://api.myco.com https://ping.myco.com https://login.microsoftonline.com; <!-- Only these hosts for XHR/fetch/WebSocket --> <!-- XSS that steals token has nowhere to send it --> frame-src https://ping.myco.com; <!-- Ping silent refresh iframe allowed --> img-src 'self' data: https://ciam-uploads.s3.amazonaws.com; ">

In CIAM / Context: The CIAM app's index.html includes: preconnect to the Spring Boot API and Ping OAuth server (DNS resolved before first API call), a strict CSP that only allows XHR to api.myco.com and ping.myco.com (neutralizes XSS token theft), and a base href of "/". The nginx config serving the Angular SPA includes try_files to route all paths to index.html — essential for Angular Router's pushState to work on page refresh.

index.html Anatomy

The HTML shell that Angular serves. It's a static file — Angular doesn't render anything into it at request time. The CLI rewrites it at build time to inject script and style tags.

<!-- src/index.html — the Angular app shell -->
<!doctype html>
<html lang="en">
<head>

  <!-- ── Character encoding: must be first ──────────────────── -->
  <meta charset="utf-8"/>

  <!-- ── Page title (shown in browser tab) ─────────────────── -->
  <title>MyApp</title>

  <!-- ── Responsive viewport: required for mobile ──────────── -->
  <meta name="viewport" content="width=device-width, initial-scale=1"/>

  <!-- ── Angular router: base path for all URLs ────────────── -->
  <base href="/"/>

  <!-- ── Favicon ───────────────────────────────────────────── -->
  <link rel="icon" type="image/x-icon" href="favicon.ico"/>

  <!-- ── SEO / social meta tags ────────────────────────────── -->
  <meta name="description" content="My Angular application"/>
  <meta property="og:title" content="MyApp"/>
  <meta property="og:description" content="My Angular application"/>
  <meta property="og:image" content="https://myapp.com/og-image.png"/>

  <!-- ── PWA: Android / iOS icons ──────────────────────────── -->
  <link rel="manifest" href="manifest.webmanifest"/>
  <meta name="theme-color" content="#1976d2"/>

  <!-- ── Performance: preconnect to external origins ────────── -->
  <link rel="preconnect" href="https://fonts.googleapis.com"/>
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin/>

  <!-- ── Fonts ──────────────────────────────────────────────── -->
  <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&display=swap"
        rel="stylesheet"/>

  <!-- ▼▼▼ Angular CLI injects <link rel="stylesheet"> tags here at build time ▼▼▼ -->

</head>
<body>

  <!-- ── Angular mount point ───────────────────────────────── -->
  <app-root></app-root>
  <!-- Angular replaces this with AppComponent's rendered template.
       The selector must match @Component({ selector: 'app-root' }). -->

  <!-- ── Noscript fallback ─────────────────────────────────── -->
  <noscript>Please enable JavaScript to run this app.</noscript>

  <!-- ▼▼▼ Angular CLI injects <script> tags here at build time ▼▼▼ -->

</body>
</html>

base href — the Angular Router's anchor

The <base href> tag tells the browser (and Angular's router) what the root URL of your app is. Get it wrong and routing silently breaks.

What it does

<base href="/"/>
<!-- App is served from root: https://myapp.com/ -->
<!-- /home → https://myapp.com/home        ✓ -->
<!-- assets/logo.png → /assets/logo.png    ✓ -->

<base href="/my-app/"/>
<!-- App is deployed to a sub-path: https://myapp.com/my-app/ -->
<!-- /home → https://myapp.com/my-app/home -->
<!-- assets/logo.png → /my-app/assets/logo.png -->

Setting base href at build time

# Override base href when building for a sub-path deployment:
ng build --base-href /my-app/
ng build --base-href https://cdn.myapp.com/

# The CLI rewrites <base href="/"> in the output index.html

APP_BASE_HREF provider (alternative)

// In app.config.ts — useful if you can't modify index.html:
import { APP_BASE_HREF } from '@angular/common';

export const appConfig = {
  providers: [
    { provide: APP_BASE_HREF, useValue: '/' }
  ]
};

Hash location strategy (no server config needed)

// For static hosting (GitHub Pages, S3) without server-side rewrites:
// URLs look like: https://myapp.com/#/home

provideRouter(routes, withHashLocation())

// base href is still needed, but routing uses # so the server
// always serves the same index.html regardless of the hash fragment

Server-side 404 → index.html rewrites

# For HTML5 pushState routing (no hash), the server must rewrite
# all 404s to index.html so Angular can handle the route.

# Nginx config:
location / {
  try_files $uri $uri/ /index.html;
}

# Apache .htaccess:
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.html [L]

# Express (Node):
app.get('*', (req, res) => res.sendFile(path.join(__dirname, 'dist/my-app/browser/index.html')));

Performance Hints

HTML resource hints tell the browser to start loading resources before they're needed. They can dramatically reduce time-to-interactive for fonts, APIs, and CDN assets.

The four resource hints

HintDoesUse for
preconnectOpens TCP+TLS connection early — no downloadFonts, analytics, APIs you'll definitely hit
dns-prefetchResolves DNS only — lighter than preconnectDomains you might hit (3rd party)
preloadDownloads the resource now at high priorityHero images, critical fonts, above-fold CSS
prefetchDownloads at low priority for future navigationNext-page resources, lazy routes

preconnect — critical external origins

<!-- Google Fonts: two connections needed -->
<link rel="preconnect" href="https://fonts.googleapis.com"/>
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin/>
<!-- crossorigin needed when the fetch is cross-origin (fonts, API) -->

<!-- Your API server -->
<link rel="preconnect" href="https://api.myapp.com" crossorigin/>

<!-- CDN for static assets -->
<link rel="preconnect" href="https://cdn.myapp.com"/>

preload — high-priority early loads

<!-- Hero image — fetch at highest priority, before CSS processes it -->
<link rel="preload" as="image" href="assets/hero.avif"
      type="image/avif"/>

<!-- Critical font subset -->
<link rel="preload" as="font" type="font/woff2"
      href="fonts/inter-v13-latin-regular.woff2" crossorigin/>

<!-- JavaScript module (rare — Angular CLI handles scripts) -->
<link rel="preload" as="script" href="main.js"/>

<!-- as= values: image | font | script | style | fetch | audio | video -->

Font loading best practice

<!-- ✓ Self-hosted fonts with preload (fastest) -->
<link rel="preload" as="font" type="font/woff2"
      href="fonts/inter.woff2" crossorigin/>
<style>
  @font-face {
    font-family: 'Inter';
    src: url('fonts/inter.woff2') format('woff2');
    font-display: swap; /* show fallback font, swap when Inter loads */
  }
</style>

<!-- ✓ Google Fonts with display=swap (avoids FOIT) -->
<link href="https://fonts.googleapis.com/css2?family=Inter&display=swap"
      rel="stylesheet"/>

<!-- ✗ Avoid -->
<link href="https://fonts.googleapis.com/css2?family=Inter"
      rel="stylesheet"/> <!-- no display=swap → blocks render while font loads -->

NgOptimizedImage (Angular v14+)

// Better than manual preload — Angular generates the preload automatically
// In component template:
<img ngSrc="hero.avif" width="1200" height="600" priority/>

// priority attribute → automatically adds <link rel="preload"> in <head>
// Also: lazy loads non-priority images, enforces width/height for CLS

Content Security Policy (CSP)

CSP is an HTTP response header (or meta tag) that tells browsers which resources are allowed to load. It's the most powerful XSS mitigation available.

Setting CSP via meta tag (fallback)

<!-- Works but has limitations: no report-uri, some directives ignored -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self'"/>

<!-- Preferred: set via HTTP response header (Nginx, Apache, Node) -->
// Nginx:
add_header Content-Security-Policy "default-src 'self';";

CSP directives explained

default-srcFallback for all resource types not explicitly listed. Use 'self' as a safe baseline.
script-srcControls JavaScript sources. Angular's inline styles require 'unsafe-inline' unless you use nonces or hashes.
style-srcControls CSS. Angular Material's inline styles require 'unsafe-inline' (or migrate to CSP nonces with v15+).
img-srcImage sources. Add data: if you inline base64 images. Add CDN domains.
font-srcFont sources. Add https://fonts.gstatic.com for Google Fonts.
connect-srcAjax / fetch / WebSocket targets. Add your API domain and any analytics endpoints.
frame-srciframe sources. Use 'none' if you don't embed external content.
report-uriURL to receive violation reports. Use report-to (newer) for modern browsers.

Angular-compatible strict CSP

# Angular v15+ supports CSP nonces (replaces unsafe-inline for styles)
# Configure in angular.json:
"security": {
  "autoCsp": true   // experimental: auto-generate nonces
}

# Practical production CSP for an Angular SPA:
Content-Security-Policy:
  default-src 'self';
  script-src  'self';
  style-src   'self' 'unsafe-inline';  # Angular needs this for component styles
  font-src    'self' https://fonts.gstatic.com;
  img-src     'self' data: https://cdn.myapp.com;
  connect-src 'self' https://api.myapp.com;
  frame-src   'none';
  report-uri  https://myapp.com/csp-reports;

Other security headers

# Add these in your web server config (not index.html):
X-Content-Type-Options: nosniff           # prevent MIME-type sniffing
X-Frame-Options: DENY                    # prevent clickjacking
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

What the Angular CLI Rewrites

The index.html you write is a template. The CLI transforms it at build time — adding hashed script tags, injecting styles, and setting up SSR hydration markers.

Development build transform

src/index.html → dist/my-app/browser/index.html (development)
<head>
<meta charset="utf-8"/>
<title>MyApp</title>
<base href="/"/>
+ <link rel="stylesheet" href="styles.css">
</head>
<body>
<app-root></app-root>
+ <script src="polyfills.js" type="module"></script>
+ <script src="main.js" type="module"></script>
</body>

Production build transform

src/index.html → dist/my-app/browser/index.html (production)
<head>
<meta charset="utf-8"/>
<title>MyApp</title>
<base href="/"/>
+ <link rel="stylesheet" href="styles.a3b7c9d2.css"> <!-- content hash! -->
</head>
<body>
<app-root></app-root>
+ <script src="polyfills.f1e2d3c4.js" type="module"></script>
+ <script src="main.8a9b0c1d.js" type="module"></script>
+ <!-- 3rd-party licenses extracted to 3rdpartylicenses.txt -->
</body>

SSR transform (Angular Universal / @angular/ssr)

Server renders AppComponent into <app-root> — then client hydrates
<body>
- <app-root></app-root> <!-- empty placeholder -->
+ <app-root ng-version="17.3.0" _nghost-ng-c12345="">
+ <!-- Server-rendered HTML here -->
+ <h1 _ngcontent-ng-c12345="">Hello World</h1>
+ </app-root>
+ <script id="ng-state" type="application/json">{"transfers":{}}</script>
<script src="main.js" type="module"></script>
</body>

index.html injection order rules

  • Styles — injected at the end of <head>
  • Scripts — injected at the end of <body> with type="module"
  • Content hash — appended to filenames in production (outputHashing: "all")
  • Deferred scripts — lazy-loaded chunks are not in index.html; Angular's router requests them on navigation
  • Scripts marked inject: false in angular.json are built but not auto-added to index.html — you reference them manually

Customizing the index.html transform

// Custom IndexHtmlTransform (Angular 14+) — run arbitrary transformations:
import { IndexHtmlTransform } from '@angular-devkit/build-angular';

export function myTransform(content: string): string {
  return content.replace(
    '</head>',
    '<script>window.__BUILD_DATE__="' + new Date().toISOString() + '"</script></head>'
  );
}
