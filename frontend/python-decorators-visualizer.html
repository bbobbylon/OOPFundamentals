Python Decorators

A decorator is just a function that takes a function and returns a (usually wrapped) function. The @ syntax is pure sugar. Once you see that @deco above def f means f = deco(f), every decorator — timing, caching, auth checks, retries, Flask routes — stops being magic. Press ▶ and watch the rewrap happen.

1. The anatomy — three nested layers

import functools, time

def timed(func):                 # ① takes the original function
    @functools.wraps(func)      # ③ copy __name__, __doc__, signature
    def wrapper(*args, **kwargs):  # ② accepts ANY call
        start = time.perf_counter()
        result = func(*args, **kwargs)   # call the real one
        dur = time.perf_counter() - start
        print(f"{func.__name__} took {dur*1000:.2f}ms")
        return result
    return wrapper                  # hand back the replacement

@timed
def work(n):
    return sum(range(n))
Brain Power. Why does wrapper take *args, **kwargs instead of the same parameters as work? Because a good decorator is generic — it should wrap any function regardless of its signature. Capturing with *args, **kwargs and re-spreading them forwards the call transparently.

2. @functools.wraps — keep the identity

Without @wraps — identity lost

work.__name__   # 'wrapper' 😦
work.__doc__    # None
# help(), tracebacks, and debuggers
# now all say "wrapper"

With @wraps — identity preserved

work.__name__   # 'work' ✓
work.__doc__    # the real docstring
work.__wrapped__ # the original fn
# @wraps copies the metadata over

Always use @functools.wraps(func) on your wrapper. It's one line and it stops your decorator from making every function look like wrapper in stack traces.

3. Decorators that take arguments — one more layer

def retry(times):              # ① the FACTORY — takes the arg
    def decorator(func):        # ② the real decorator
        @functools.wraps(func)
        def wrapper(*a, **k):    # ③ the wrapper
            for i in range(times):
                try: return func(*a, **k)
                except Exception:
                    if i == times - 1: raise
        return wrapper
    return decorator

@retry(3)                     # retry(3) RETURNS a decorator, then it's applied
def flaky(): ...

@retry(3) means: call retry(3) first (it returns decorator), then apply that to flaky. That's why an argument-taking decorator needs three nested functions instead of two.

Stacking (scenario ④): decorators apply bottom-up but execute top-down. @a over @b over def f builds a(b(f)) — so b wraps f first, then a wraps that. At call time you enter a's wrapper first. Order matters: @app.route over @login_required is not the same as the reverse.
