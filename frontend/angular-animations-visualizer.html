Animations

The @angular/animations package — triggers, states, transitions, keyframes, and enter/leave. Plus when to just use CSS instead.

The mental model

An Angular animation has three pieces:

  1. Trigger — a named animation attached to an element: [@fadeIn]
  2. States — labels for "what does the element look like now": 'visible', 'hidden'
  3. Transitions — what happens when going state-to-state: 'hidden => visible', duration, easing

Plus the special states :enter (element being added) and :leave (element being removed).

// app.config.ts — opt in (animations don't ship by default)
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';

provideAnimationsAsync()                       // recommended — code-split, lazy loaded
// or provideAnimations() for eager loading

Demo 1: simple fade in/out

Hello!
// fade.component.ts
import { trigger, state, style, transition, animate } from '@angular/animations';

@Component({
  selector: 'app-fade',
  template: `
    <button (click)="visible = !visible">Toggle</button>
    <div [@fade]="visible ? 'visible' : 'hidden'">Hello!</div>
  `,
  animations: [
    trigger('fade', [
      state('visible', style({ opacity: 1 })),
      state('hidden',  style({ opacity: 0 })),
      transition('hidden => visible', animate('500ms ease-in')),
      transition('visible => hidden', animate('300ms ease-out'))
    ])
  ]
})
export class FadeComponent {
  visible = true;
}

Shortcut: 'hidden <=> visible' defines both directions at once.

Demo 2: slide in / slide out

→ I'm sliding from the left
trigger('slide', [
  transition(':enter', [                            // element added to DOM
    style({ transform: 'translateX(-100%)', opacity: 0 }),
    animate('400ms cubic-bezier(0.4, 0, 0.2, 1)',
            style({ transform: 'translateX(0)', opacity: 1 }))
  ]),
  transition(':leave', [                            // element removed from DOM
    animate('300ms ease-out',
            style({ transform: 'translateX(100%)', opacity: 0 }))
  ])
])

Demo 3: enter/leave on a list

The classic — animate items added to or removed from a list. Each item gets its own enter/leave transition.

    @Component({
  template: `
    <ul>
      @for (item of items; track item.id) {
        <li [@itemAnim]>
          {{ item.text }}
          <button (click)="remove(item.id)">✕</button>
        </li>
      }
    </ul>
  `,
  animations: [
    trigger('itemAnim', [
      transition(':enter', [
        style({ opacity: 0, transform: 'translateY(-12px)' }),
        animate('300ms ease-out',
                style({ opacity: 1, transform: 'translateY(0)' }))
      ]),
      transition(':leave', [
        animate('300ms ease-in',
                style({ opacity: 0, transform: 'translateX(60px)' }))
      ])
    ])
  ]
})

    Demo 4: state machine (multiple states)

    States aren't limited to two. Click through small → medium → large to see the box transition between three named styles.

    Medium
    trigger('sizeChange', [
  state('small',  style({ transform: 'scale(0.6)', background: '#6366f1' })),
  state('medium', style({ transform: 'scale(1)',   background: '#dd0031' })),
  state('large',  style({ transform: 'scale(1.4) rotate(15deg)', background: '#f59e0b' })),

  // '*' = "any state" — one transition rule covers them all
  transition('* => *', animate('500ms cubic-bezier(0.4, 0, 0.2, 1)'))
])

// In template:
<div [@sizeChange]="currentSize"></div>

    Demo 5: stagger — animate children one after another

    Don't animate a list all at once. Stagger them by 50–100ms each — way more polished.

    import { trigger, transition, query, stagger, style, animate } from '@angular/animations';

trigger('listStagger', [
  transition('* => *', [
    query(':enter', [                                // query into the children
      style({ opacity: 0, transform: 'translateY(20px)' }),
      stagger(80, [                                  // 80ms delay between each
        animate('300ms ease-out',
                style({ opacity: 1, transform: 'translateY(0)' }))
      ])
    ], { optional: true })
  ])
])

    Demo 6: keyframes (multi-step animations)

    When ease isn't enough — e.g. a wiggle that goes left, right, left, right.

    Hi!
    import { keyframes } from '@angular/animations';

trigger('wiggle', [
  transition('* => wiggling', [
    animate('600ms ease-in-out', keyframes([
      style({ transform: 'rotate(0)',     offset: 0    }),
      style({ transform: 'rotate(-10deg)', offset: 0.25 }),
      style({ transform: 'rotate(8deg)',   offset: 0.5  }),
      style({ transform: 'rotate(-5deg)',  offset: 0.75 }),
      style({ transform: 'rotate(0)',     offset: 1    })
    ]))
  ])
])

    Demo 7: route transitions

    Animate between router views — the leaving page slides out while the entering page slides in.

    🏠 Home

    Welcome to the homepage.

    ℹ️ About

    A small company doing big things.

    📨 Contact

    hello@example.com

    // In your AppComponent, wrap the <router-outlet>
@Component({
  template: `
    <div [@routeAnim]="getRouteAnimationData(outlet)">
      <router-outlet #outlet="outlet"></router-outlet>
    </div>
  `,
  animations: [
    trigger('routeAnim', [
      transition('* <=> *', [
        query(':enter, :leave', style({ position: 'absolute', width: '100%' }), { optional: true }),
        query(':enter', [
          style({ opacity: 0, transform: 'translateX(40px)' }),
          animate('350ms ease-out',
                  style({ opacity: 1, transform: 'translateX(0)' }))
        ], { optional: true })
      ])
    ])
  ]
})
export class AppComponent {
  getRouteAnimationData(outlet: RouterOutlet) {
    return outlet?.activatedRouteData?.['animation'];
  }
}

// In routes.ts, label each route:
{ path: 'home',    component: HomeComponent,    data: { animation: 'Home' } },
{ path: 'about',   component: AboutComponent,   data: { animation: 'About' } }

    The core API in one table

    FunctionWhat it does
    trigger(name, [...])Defines a named animation — bind it as [@name]
    state(name, style({...}))Names a "resting" style
    transition(rule, [...])What runs when transitioning between states
    style({ ... })Sets CSS properties (camelCase: backgroundColor)
    animate('500ms ease-in')Tween over a duration with timing function
    keyframes([style(...), ...])Multi-step animation with offset: 0…1
    query(':enter', [...])Select child elements inside the trigger element
    stagger(80, [...])Delay each matched child by N ms
    group([...])Run animations in parallel
    sequence([...])Run animations one after another
    animateChild()Trigger an inner element's own animation from the parent

    Transition rules

    PatternMeaning
    'hidden => visible'Going FROM hidden TO visible only
    'visible => hidden'The other direction only
    'hidden <=> visible'Both directions
    ':enter' / ':leave'Element being added/removed from DOM
    '* => *'Any state to any other state
    'void => *'Same as :enter
    '* => void'Same as :leave

    Reading animation events

    Each trigger emits (@trigger.start) and (@trigger.done) events. Useful for chaining or cleanup.

    <div [@fade]="state"
     (@fade.start)="onStart($event)"
     (@fade.done)="onDone($event)"></div>

onDone(e: AnimationEvent) {
  console.log(e.fromState, '→', e.toState, 'in', e.totalTime, 'ms');
}

    When NOT to use @angular/animations

    Bundle cost reality check: the animations package adds ~50KB to your bundle. For simple hover/fade/focus effects, plain CSS is smaller, faster (GPU-accelerated transitions are essentially free), and works without Angular at all.

    Use CSS when

    Simple hover, focus, or class-toggle transitions. transition: all 0.2s covers 80% of UI.

    Use @angular/animations when

    You need :enter / :leave hooks (CSS can't see DOM removal), staggered lists, route transitions, or coordinated multi-element animations.

    Use the Web Animations API when

    You need imperative control — physics, interactive drag, complex programmatic timing. Skip both abstractions.

    Use a library when

    GSAP, Motion One, Framer Motion for Web — heavy-duty motion design. They beat both CSS and @angular/animations for complex storytelling.

    Performance gotchas

    PropertyCheap?Why
    transform (translate, scale, rotate)✅ GPUCompositor-only, no layout or paint
    opacity✅ GPUCompositor-only
    filter (blur, brightness)⚠️ mediumGPU but still expensive
    width, height, top, left❌ expensiveTriggers layout reflow on every frame
    background-color⚠️ mediumCauses repaint but no layout
    box-shadow animations❌ expensiveRepainted every frame
    The rule: animate transform and opacity only. To "grow" an element, use transform: scale() instead of changing width/height. To move, use transform: translate() instead of top/left.

    Accessibility — respect prefers-reduced-motion

    @HostListener()
ngOnInit() {
  const reduced = matchMedia('(prefers-reduced-motion: reduce)').matches;
  this.animationDuration = reduced ? 0 : 300;
}

// Or in CSS:
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
    Takeaway: Angular animations = trigger + state + transition. Use them for enter/leave, stagger, and route transitions. Use plain CSS for hover/focus. Always animate transform/opacity — never width/height. Respect prefers-reduced-motion.
