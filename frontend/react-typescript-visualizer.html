TypeScript with React

Typing the React surface: props (incl. children and extending native elements), hooks (useState/useRef/useReducer/context), event handlers, and generic components — plus the inference that lets you write fewer annotations than you'd think.

🔷 What does TypeScript add to React — and where does it actually catch bugs?

Without types, React props are plain objects — wrong or missing props surface at runtime; with TypeScript the compiler catches them at write time. The React typing surface: props interfaces (missing/wrong/extra props flagged), children as React.ReactNode, event handlers typed to the element (ChangeEvent<HTMLInputElement> so e.target.value is string), hooks (useState<UserDto | null> constrains the setter; useReducer + discriminated-union actions force an exhaustive switch), Context (createContext<T | null> forces a null-check), and generic components (a Select<T> that flows T through). Same discipline as Spring Boot DTO generics, one layer up.

  • Typed props — missing/wrong/extra props caught at write time, not in prod.
  • Typed events — element-specific, so e.target.value is always string.
  • Typed hooks — useState<T> constrains the setter; reducers stay exhaustive.
  • Generic components + typed Context — flow T through; force the null-check.

// useState with type argument const [user, setUser] = useState<UserDto | null>(null); // TypeScript infers: setUser: (value: UserDto | null) => void // setUser(42) ← compile error // setUser(null) ← ok // useRef with DOM element type const inputRef = useRef<HTMLInputElement>(null); inputRef.current?.focus(); // optional chain: current can be null // Event handlers — type the event AND element const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => { setQuery(e.target.value); // e.target.value: string ✓ }; const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => { e.preventDefault(); submitForm(); }; const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => { e.currentTarget.disabled = true; };

3. The React.FC debate

Prefer a plain function with a typed props parameter over React.FC. React.FC historically forced an implicit children prop (even for components that take none), complicates generics, and adds little. The community-recommended style is function Comp(props: Props) {} or const Comp = (props: Props) => {} and declare children explicitly when you want it.
