Data Visualization — Matplotlib, Seaborn & Choosing the Right Chart

The Figure/Axes object model, Seaborn's DataFrame-aware statistical layer on top of it, how to pick the right chart for the question you're actually asking, and the deceptive-chart tricks to never (accidentally) use yourself.

📊 A chart is an argument — the wrong chart type actively misleads

A chart isn't decoration — it's a claim about the data, made visually. Pick the wrong shape for the question you're asking (a pie chart for 12 near-equal categories, a bar chart with a truncated y-axis) and you haven't just made an ugly chart, you've made an inaccurate one, because human eyes are bad at comparing angles and areas but very good at comparing bar heights and line slopes — which is exactly why bad actors (and, more often, just careless analysts) reach for the wrong chart type to make a small difference look big. Matplotlib is the low-level engine every Python plotting library sits on: a Figure (the whole canvas) contains one or more Axes (an individual plot). Seaborn sits on top of Matplotlib as a statistical layer that understands pandas DataFrames directly, with sane defaults for color and confidence intervals. This page is about the object model underneath both, and about training your eye to catch a misleading chart — including ones you almost built yourself.

  • Figure contains Axes — fig, ax = plt.subplots() is the object-oriented API, preferred over bare plt.plot() once you have more than one panel.
  • Seaborn reads column names — sns.barplot(data=df, x=..., y=..., hue=...), no manual array extraction.
  • Chart type is an answer to a question — categories→bar, trend→line, relationship→scatter, distribution→histogram/box.
  • Pie charts are usually the wrong call — eyes compare angles/areas poorly; a bar chart almost always communicates the same data more honestly.
  • A truncated y-axis and a bin-width choice both change the story — same data, different (mis)leading conclusion.

Figure vs Axes (object-oriented API)

import matplotlib.pyplot as plt # One Figure, one Axes fig, ax = plt.subplots() ax.plot(months, revenue) ax.set_title('Revenue') # One Figure, TWO Axes (side by side) fig, (ax1, ax2) = plt.subplots(1, 2) ax1.plot(months, revenue) ax2.bar(regions, headcount) # vs the pyplot state-machine style # (fine for one quick plot, ambiguous beyond that): plt.plot(months, revenue) # implicit "current axes" plt.title('Revenue')

Seaborn: statistical layer on pandas

import seaborn as sns # Reads column NAMES, not raw arrays sns.barplot(data=df, x='region', y='revenue', hue='quarter') # Confidence-interval shading is automatic sns.lineplot(data=df, x='day', y='signups') # Distribution in one call sns.histplot(data=df, x='latency_ms', bins=30) sns.boxplot(data=df, x='region', y='latency_ms')

Job relevance: Every observability dashboard you'll ever look at (Grafana panels on request latency, error-rate-by-tenant charts) is making the exact same chart-type decisions this page teaches — a truncated y-axis on an incident graph can make a 2% error-rate blip look like a full outage. The habit of asking "does this axis start at zero, and does the chart type match the question?" transfers directly to reading (and building) production dashboards, not just Jupyter notebooks.

1. The Figure/Axes Object Model

Every Matplotlib plot is a Figure (the canvas) holding one or more Axes (an individual plot with its own x/y scales). The object-oriented API — fig, ax = plt.subplots() — is explicit about which panel you're drawing on; the older pyplot state-machine style (plt.plot(...)) implicitly targets "whatever Axes was drawn last," which gets ambiguous fast once you have more than one panel.

Figure
the whole canvas/window
Axes
one plot: x/y scales, ticks
Artists
lines, bars, text on an Axes
ax.plot()
draws onto ONE specific Axes
fig.savefig()
renders the whole Figure to file
# Two panels, side by side — each Axes is addressed explicitly
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10,4))
ax1.plot(months, revenue)
ax1.set_title('Revenue by Month')
ax2.bar(regions, headcount)
ax2.set_title('Headcount by Region')
fig.savefig('report.png', dpi=150)
Once a script builds more than one panel, always use fig, ax = plt.subplots(). The pyplot state-machine style (plt.plot(), plt.title()) works for a single quick plot but silently targets "the current Axes" — a real source of "why did my title show up on the wrong subplot" bugs.

2. Choosing the Right Chart

The chart type should be dictated by the question, not by habit. Seaborn's DataFrame-aware API makes trying several fast: sns.barplot, sns.lineplot, sns.scatterplot, sns.histplot/sns.boxplot all take the same data=df, x=..., y=... shape.

Trend over time → line

# A pie chart for 12 near-equal categories: readers can't rank slices by eye
# A sorted horizontal bar chart shows the SAME data more accurately:
sns.barplot(data=df.sort_values('share'), y='category', x='share', orient='h')
Pie charts are rarely the right call. Human perception is good at comparing bar lengths and line slopes, but poor at comparing wedge angles or areas — beyond 3-4 slices, a sorted bar chart communicates the same part-to-whole data more accurately.

3. Distribution Charts: Histograms & Box Plots

A histogram's bin width is itself an analytical choice — too few bins hides real structure (like a bimodal distribution), too many bins shows sampling noise as if it were signal. A box plot summarizes a distribution's quartiles, median, and outliers in one compact shape, which is why it's the go-to for comparing distributions across categories side by side.

Too few bins (hides structure)

bins=2 — looks like one blob

Well-chosen bins (reveals bimodal)

bins=8 — two real peaks visible

Too many bins (all noise)

bins=40 — spiky, no clear story
# Compare a numeric distribution ACROSS categories in one call
sns.boxplot(data=df, x='region', y='latency_ms')
# quartiles + median + whiskers + outlier points, per region, side by side
sns.histplot(data=df, x='latency_ms', bins=30)  # try a few bin counts before trusting the shape
There's no universally "correct" bin count — Sturges'/Freedman-Diaconis rules give a reasonable starting point (Seaborn's default), but always sanity-check by trying 2-3 different bin counts. If the story changes wildly with bin count, the sample size is probably too small to trust the shape yet.
