Linked Lists — Deep Dive

Singly, doubly, circular. Pointer manipulation, interview patterns, and Floyd's cycle detection.

What is a linked list — and when does it actually beat an array despite slower random access?

A linked list is a sequence of nodes where each node contains a value AND a pointer (reference) to the next node. Unlike an array (contiguous memory block), linked list nodes can live anywhere in memory — connected only by their pointers. The last node points to null. Singly linked list: each node has one pointer (next). Traversal is forward-only. Insert/delete at the head is O(1) — just update the head pointer. Insert/delete at the tail requires traversal: O(n). Doubly linked list: each node has two pointers (next and prev). Enables O(1) insert/delete at BOTH head and tail (the tail pointer directly accesses the last node, and prev lets you delete without traversing). Java's LinkedList is a doubly linked list. The big trade-off: arrays give O(1) random access but O(n) insert/delete in the middle. Linked lists give O(1) insert/delete at known positions but O(n) traversal to FIND a position. The critical nuance: LinkedList.get(n) in Java is O(n) — it must traverse from head. This makes it disastrous for index-based access. But LinkedList.addFirst() and LinkedList.removeFirst() are O(1) — it's a great stack/deque implementation. Interview patterns: linked list problems appear in 30% of coding interviews. Master: (1) Fast/slow pointer (Floyd's cycle detection) — fast moves 2 steps, slow 1 step; if cycle exists, they meet. (2) Reversal in-place — traverse with prev/curr/next pointers, redirect pointers. (3) Merge two sorted lists — compare heads, advance smaller. (4) Find middle — fast/slow pointer: when fast reaches end, slow is at middle. (5) Detect nth from end — advance one pointer by n, then advance both until first reaches end. Circular linked list: last node points back to head instead of null. Used for round-robin scheduling, circular buffers, and undo history that wraps around.

Reverse a linked list

// Reverse singly linked list in O(n) time, O(1) space: // Input: 1 → 2 → 3 → 4 → null // Output: 4 → 3 → 2 → 1 → null Node reverse(Node head) { Node prev = null; Node curr = head; while (curr != null) { Node next = curr.next; // save next curr.next = prev; // redirect pointer BACK prev = curr; // advance prev curr = next; // advance curr } return prev; // new head (was old tail) } // Step-by-step trace: // Start: prev=null curr=1 next=2 // Step1: prev=1 curr=2 (1→null) // Step2: prev=2 curr=3 (2→1) // Step3: prev=3 curr=4 (3→2) // Step4: prev=4 curr=null (4→3) // End: return 4 (new head)

Floyd's cycle detection

// Floyd's algorithm: detect cycle in O(n) time, O(1) space // (no visited set — doesn't grow with input size) boolean hasCycle(Node head) { Node slow = head; Node fast = head; while (fast != null && fast.next != null) { slow = slow.next; // 1 step fast = fast.next.next; // 2 steps } // Why they meet if cycle exists: // Fast enters cycle first, laps slow // Relative speed = 1 step/iteration // They MUST meet within (cycle length) iterations return slow == fast; } // Find cycle START (follow-up): Node cycleStart(Node head) { // ... find meeting point (as above) ... // Reset slow to head, keep fast at meeting point // Advance BOTH one step at a time // Where they meet = cycle start // Mathematical proof: distances from head and // meeting point to cycle start are equal return meetingPoint; }

When to use LinkedList vs ArrayList

// USE ArrayList when: // ✓ Random access by index (get(i)) is needed // ✓ Iterating the whole list // ✓ Most operations are read (not insert/delete) // ✓ Cache performance matters // ✓ Memory matters (no pointer overhead) // USE LinkedList when: // ✓ Frequent insert/delete at BOTH ends (O(1)) // ✓ Implementing Stack or Queue // ✓ You hold an iterator and insert at iterator // ✓ Frequent insertions in the middle via iterator // Java: LinkedList implements both Deque and List Deque<Task> queue = new LinkedList<>(); queue.addFirst(task); // O(1) prepend queue.pollLast(); // O(1) remove last // In practice: // 90% of the time: ArrayList wins // LinkedList wins: O(1) front ops, deque semantics // NEVER use for: // list.get(500_000) // O(n) = traverses 500K nodes // Any index-based access = ArrayList wins

In CIAM / Context: Spring Security's filter chain is conceptually a linked list — each filter calls the next via FilterChain.doFilter(). The order matters (authentication before authorization). Java's LinkedList is used inside Spring's event dispatching system where listeners are frequently added/removed at the front. Understanding linked lists explains why Spring's WebMvcConfigurer interceptor order matters and how HandlerInterceptorAdapter chains work under the hood.

Circular Linked List — tail.next points back to head

// Use case: round-robin scheduling, circular buffers class CircularList<T> { Node<T> tail; // keep tail, not head void add(T data) { Node<T> n = new Node<>(data); if (tail == null) { n.next = n; // points to itself } else { n.next = tail.next; // new → head tail.next = n; // old tail → new } tail = n; } // Traversal — stop when back at start void print() { if (tail == null) return; Node<T> cur = tail.next; // head do { System.out.print(cur.data + " "); cur = cur.next; } while (cur != tail.next); } }

Core Operations — with pointer walkthroughs

// Reverse a singly linked list — O(n) O(1) space Node<T> reverse(Node<T> head) { Node<T> prev = null; Node<T> curr = head; while (curr != null) { Node<T> next = curr.next; // save curr.next = prev; // reverse prev = curr; // advance prev curr = next; // advance curr } return prev; // new head }
// Find middle node — fast/slow pointers Node<T> findMiddle(Node<T> head) { Node<T> slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; // 1 step fast = fast.next.next; // 2 steps } return slow; // slow is at middle }

Floyd's Cycle Detection Algorithm

// Detect if a cycle exists — O(n) O(1) boolean hasCycle(Node<T> head) { Node<T> slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; if (slow == fast) return true; // met! } return false; // fast reached null → no cycle } // Find cycle start node Node<T> cycleStart(Node<T> head) { Node<T> slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; if (slow == fast) { slow = head; // reset slow to head while (slow != fast) { slow = slow.next; fast = fast.next; } return slow; // cycle start } } return null; }

More Interview Patterns

// Merge two sorted lists Node merge(Node a, Node b) { Node dummy = new Node(0); Node cur = dummy; while (a != null && b != null) { if (a.data <= b.data) { cur.next = a; a = a.next; } else { cur.next = b; b = b.next; } cur = cur.next; } cur.next = (a != null) ? a : b; return dummy.next; }
// Remove Nth from end — one pass! Node removeNthFromEnd(Node head, int n) { Node dummy = new Node(0); dummy.next = head; Node fast = dummy, slow = dummy; for (int i = 0; i <= n; i++) fast = fast.next; while (fast != null) { fast = fast.next; slow = slow.next; } slow.next = slow.next.next; // skip return dummy.next; }
