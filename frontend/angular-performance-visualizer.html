2. Lazy loading routes — split the bundle

The biggest single win. Every route lazy-loaded = a separate chunk only downloaded when needed.

Eager (everything in initial bundle)

AppComponent [in main.js — 1.2MB]
├── HomeComponent
├── DashboardComponent (used by 5% of users)
├── AdminPanel (used by 0.1% of users)
└── ReportsModule (includes chart.js, 240kb)

Lazy (each route = separate chunk)

AppComponent [main.js — 220kb]
├── HomeComponent (eager — landing page)
├── dashboard.chunk.js [80kb — only loaded on /dashboard]
├── admin.chunk.js [120kb — only for admins]
└── reports.chunk.js [280kb — chart.js stays here] 
// routes.ts — modern standalone lazy loading
export const routes: Routes = [
  { path: '', component: HomeComponent },                  // eager

  // Lazy COMPONENT (v14.1+)
  {
    path: 'dashboard',
    loadComponent: () => import('./dashboard.component')
      .then(m => m.DashboardComponent)
  },

  // Lazy ROUTE FILE (for a feature with sub-routes)
  {
    path: 'admin',
    loadChildren: () => import('./admin/admin.routes')
      .then(m => m.ADMIN_ROUTES)
  }
];

Preloading strategies — load lazy chunks in the background

import { PreloadAllModules, withPreloading } from '@angular/router';

provideRouter(
  routes,
  withPreloading(PreloadAllModules)         // load everything after app idle
)
StrategyWhen to use
NoPreloading (default)Smallest initial bundle. Slight delay on first navigation to a lazy route.
PreloadAllModulesApp-sized you can preload everything in seconds. Most common choice.
Custom strategyPreload routes the user is LIKELY to visit (e.g. based on role, hover, link visibility)

3. @defer — lazy load PARTS of a page (v17+)

Lazy loading isn't just for routes. @defer blocks let you postpone loading anything — heavy charts, modals, comments — until they're actually needed.

Click the buttons to simulate different defer triggers:

@placeholder — lightweight stub (0 kB chart code)
// In a template — no module imports, no manual splitting needed
@defer (on viewport) {                // when this region scrolls into view
  <heavy-chart [data]="data"/>
} @placeholder {
  <div class="stub">Chart will load when scrolled into view</div>
} @loading (minimum 500ms) {
  <spinner/>                       // shown while chunk downloads
} @error {
  <div>Failed to load chart.</div>
}

All trigger types

TriggerFires whenUse for
on idle (default)Browser becomes idle (requestIdleCallback)Below-the-fold widgets
on viewportElement scrolls into view (IntersectionObserver)Comments, recommendations, footer content
on interactionUser clicks/keyboards the placeholderModals, dialogs, expandable panels
on hoverMouse enters the placeholderTooltips, dropdowns
on timer(2s)After N msDelayed splash animations
on immediateASAP after renderAlways-load-soon stuff
when conditionWhen expression is truePermission-gated content

Prefetch (download eagerly, render lazily)

@defer (on interaction; prefetch on hover) {
  <comment-section/>
}
// User hovers → download starts. User clicks → render instantly. Best UX.

4. NgOptimizedImage — drop-in image win

Images are usually the biggest LCP element. NgOptimizedImage gives you lazy-loading, responsive srcsets, priority hints, and lint-time warnings — for free.

import { NgOptimizedImage } from '@angular/common';

@Component({
  imports: [NgOptimizedImage],
  template: `
    <!-- Before: lazy by default; below the fold -->
    <img ngSrc="/photo.jpg" width="600" height="400" alt="..." />

    <!-- Hero / above the fold — opt into priority + preload -->
    <img ngSrc="/hero.jpg" width="1200" height="600" priority alt="..." />

    <!-- Responsive — auto-generates srcset -->
    <img ngSrc="/cover.jpg" fill sizes="(min-width: 768px) 50vw, 100vw" alt="..." />
  `
})

5. trackBy in @for — stop nuking the DOM

Without a track key, Angular re-creates every DOM node when the array reference changes. With one, it keeps existing nodes and only updates what moved.

No trackBy

    Every row pulses pink — entire DOM rebuilt

    With trackBy

      Rows pulse green — same nodes, just reordered

      // ❌ No track — Angular falls back to identity (object reference)
@for (user of users; track $index) { <user-row [user]="user"/> }
// $index is OK only for static lists — terrible for reorder/insert

// ✅ Track by stable id — Angular keeps DOM nodes, only moves them
@for (user of users; track user.id) { <user-row [user]="user"/> }

// Old syntax (still works) — *ngFor with trackBy
<div *ngFor="let u of users; trackBy: trackById">...</div>
trackById(_: number, u: User) { return u.id; }
      Real impact: on a 1,000-row table where the user sorts a column, no-trackBy reuses 0 DOM nodes (1,000 destroys + 1,000 creates). With track user.id, 0 destroys + 0 creates — just reordering. The difference is usually 100x faster.

      6. OnPush change detection

      Default CD checks every component on every event. OnPush only checks when (a) input reference changes, (b) an event fires inside it, (c) a signal it reads changes, (d) an async pipe emits.

      @Component({
  selector: 'app-user-card',
  changeDetection: ChangeDetectionStrategy.OnPush,    // add this
  /* ... */
})
export class UserCard {
  @Input() user!: User;
}
      Rule of thumb: default ALL leaf/presentational components to OnPush. The hit comes when you mutate input objects (user.name = 'X') — Angular doesn't notice because the reference is the same. Fix: always create new objects, or use signals.

      7. Pure pipes vs methods in template

      // ❌ Method call in template — runs on EVERY change detection cycle
<div>{{ expensiveFormat(user) }}</div>
expensiveFormat(u: User) {
  console.log('called');   // you'll see this 100x per second
  return u.name.toUpperCase() + ' ' + u.email;
}

// ✅ Pure pipe — memoized, only re-runs if input reference changes
@Pipe({ name: 'userLabel', pure: true })
export class UserLabelPipe implements PipeTransform {
  transform(u: User) {
    return u.name.toUpperCase() + ' ' + u.email;
  }
}
<div>{{ user | userLabel }}</div>

// ✅ Or: derive once in a computed signal
label = computed(() => this.user().name.toUpperCase() + ' ' + this.user().email);
<div>{{ label() }}</div>

      8. Web Workers — for genuinely heavy computation

      If you're doing image processing, big sorts, parsing megabytes of CSV — move it off the main thread.

      ng generate web-worker app                  # scaffolds + wires up
      // app.worker.ts
<reference lib="webworker" />
addEventListener('message', ({ data }) => {
  const result = heavyComputation(data);
  postMessage(result);
});

// component
const worker = new Worker(new URL('./app.worker', import.meta.url));
worker.postMessage(bigData);
worker.onmessage = ({ data }) => this.result = data;

      9. The full optimization checklist

      📦 Build

      Production mode (ng build defaults to it). Brotli/gzip at the server. ESBuild via application builder. Source maps for analysis.

      🌳 Tree-shake

      Always import from sub-paths (lodash-es/isEqual, not lodash). Use standalone components — easier dead-code elimination than NgModules.

      🪓 Drop heavy libs

      moment → date-fns / Intl. lodash → native. jQuery → DOM APIs. Big component libs → handpick.

      ✂️ Code split

      loadComponent for routes. @defer for parts. Preload eagerly after idle.

      🎯 OnPush + signals

      Default to OnPush. Replace Observable | async with toSignal. Or go zoneless entirely.

      🖼️ Images

      NgOptimizedImage always. priority on the hero image. Set width/height to prevent CLS.

      📋 Lists

      track on every @for. Virtual scroll (@angular/cdk/scrolling) for >100 rows.

      🧠 Memoize

      Pure pipes > method calls in templates. computed() for derived values. Memoize expensive selectors.

      🔌 Defer 3rd-party

      Analytics, chat widgets, ads — load after main app, never block initial render.

      ⚡ SSR + hydration

      For content sites: ship HTML on first load, hydrate after. Massive LCP/FCP win. (See the SSR visualizer.)

      📡 Service Worker

      ng add @angular/pwa — caches assets, instant repeat loads, offline support.

      📊 Measure

      Lighthouse in DevTools. WebPageTest for real-world. Chrome Performance tab for runtime jank.
