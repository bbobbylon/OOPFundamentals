Declarative HTTP Clients — @HttpExchange

Your CIAM backend is also an HTTP client: it calls the IDM's admin/Graph API, a userinfo endpoint, partner services. Modern Spring (6.1+) lets you declare those calls as a Java interface — annotate the methods, and Spring generates the client. No RestTemplate boilerplate, no Feign dependency. The interesting part for identity: how the outgoing request gets a token.

📡 What is @HttpExchange — and why is it better than RestTemplate for calling external APIs?

Your CIAM backend is also an HTTP client — it calls the Ping/Entra admin API, Microsoft Graph, the OIDC userinfo endpoint, partner APIs. The old way (RestTemplate) means building an HttpEntity, a UriComponentsBuilder, calling exchange(), casting, and handling errors — boilerplate on every call. Spring 6.1+'s @HttpExchange lets you declare the API as a Java interface and annotate each method; Spring generates the implementation, backed by RestClient or WebClient so you inherit their error handling, retry, and logging.

  • Declarative client. One interface replaces pages of imperative call code.
  • Backed by RestClient/WebClient — same timeouts, interceptors, and error handling.
  • Auth via a default header or interceptor — fetch and refresh the machine token automatically.
  • Pick the backend: RestClient (sync, default), WebClient (reactive), never new RestTemplate.

Declaring a client

@HttpExchange(url="…/v1.0") interface MsGraphClient { @GetExchange("/users/{id}") GraphUser getUser(@PathVariable String id); @PostExchange("/users") GraphUser createUser(@RequestBody …); }. Build with HttpServiceProxyFactory.builderFor(RestClientAdapter.create(restClient))…createClient(MsGraphClient.class).

Adding the auth token

For machine-to-machine (Client Credentials), get a token from the IdP and set a default header — restClient.mutate().defaultHeader("Authorization", "Bearer " + tokenManager.getToken()) — or use an interceptor that fetches/refreshes before each call.

RestClient vs WebClient vs RestTemplate

RestClient (6.1+, fluent, sync) is the default. WebClient for non-blocking/reactive pipelines (Mono/Flux). RestTemplate is legacy — migrate off it. For occasional CIAM admin calls, RestClient + @HttpExchange is the sweet spot.

CIAM: Three @HttpExchange interfaces — PingAdminClient (CRUD users in Ping Directory), EntraGraphClient (Azure AD groups via Graph), UserInfoClient (OIDC userinfo). Each RestClient has a token interceptor that pulls a Client-Credentials token from its IdP, cached and refreshed 60s before expiry. Zero boilerplate — just interfaces and return types.

1. From imperative plumbing to a declared interface

Before — RestTemplate / RestClient by hand

User u = restClient.get()
   .uri("/users/{id}", id)
   .header("Authorization", "Bearer " + token)
   .retrieve()
   .body(User.class);
// repeat for every endpoint…

After — a declarative client

@HttpExchange("/users")
public interface IdmAdminApi {

  @GetExchange("/{id}")
  User getUser(@PathVariable String id);

  @PostExchange
  User createUser(@RequestBody NewUser dto);
}

You write the interface; Spring writes the implementation. Methods map to requests via @GetExchange/@PostExchange/… with @PathVariable, @RequestBody, @RequestParam, @RequestHeader binding the parts.

3. Wiring the proxy (it's just a bean)

@Bean
IdmAdminApi idmAdminApi(RestClient.Builder builder) {
  RestClient client = builder
      .baseUrl("https://graph.example-idm.com/v1")
      .requestInterceptor(new BearerTokenInterceptor())   // ← attaches identity
      .build();
  var factory = HttpServiceProxyFactory
      .builderFor(RestClientAdapter.create(client))
      .build();
  return factory.createClient(IdmAdminApi.class);
}

Spring Boot can also auto-register interfaces for you (@ImportHttpServices / group config) so you skip the factory boilerplate — but the shape is the same: an adapter over RestClient (blocking) or WebClient (reactive), wrapped by an HttpServiceProxyFactory.

4. The identity question: whose token goes out?

On-behalf-of (relay the user)

// grab the incoming token from the security context
var jwt = ((JwtAuthenticationToken) SecurityContextHolder
    .getContext().getAuthentication()).getToken();
request.getHeaders().setBearerAuth(jwt.getTokenValue());

The downstream sees the end user. Simplest relay; for cross-audience calls use a proper OAuth2 token-exchange instead of forwarding verbatim.

Client-credentials (act as the app)

var authorized = authorizedClientManager.authorize(
    OAuth2AuthorizeRequest
      .withClientRegistrationId("idm-graph")
      .principal("system").build());
request.getHeaders().setBearerAuth(
    authorized.getAccessToken().getTokenValue());

A service identity — no user. Spring fetches & caches the app token via the client_credentials grant and refreshes it automatically.

↪ Relaying the user's token end-to-end is the heart of the BFF / Token Relay pattern (next). Where that token came from: Angular · Access Tokens & Silent Refresh.

5. Don't forget timeouts, errors, and tests

  • Timeouts — set connect/read timeouts on the underlying ClientHttpRequestFactory; a hung IDM call shouldn't hang your request thread.
  • Error decoding — a 4xx/5xx from the downstream throws; translate it (onStatus / an exchange-error handler) into a meaningful failure, not a raw 500.
  • Resilience — wrap calls with timeouts/retries/circuit-breakers (Resilience4j) so a flaky IDM degrades gracefully.
  • Return shape — methods can return the body, ResponseEntity<T> (for status/headers), or reactive Mono/Flux with a WebClient adapter.
  • Testing — point the client at a MockWebServer / RestClient test setup and assert the request it builds — exactly what the simulator above shows.

6. One-sentence recap

📡 Declare a downstream call as a Java interface annotated with @HttpExchange/@GetExchange/@PostExchange, back it with a RestClient (or WebClient) through an HttpServiceProxyFactory, and register the generated proxy as a bean — then a request interceptor decides whose token goes out: on-behalf-of (relay the user's JWT from the SecurityContext) or client-credentials (the app's own token from OAuth2AuthorizedClientManager) — all with timeouts, error decoding, and resilience around it.
