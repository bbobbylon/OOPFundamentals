Debugging with Actuator & Logs

Before you attach a debugger, ask the running app. Spring Boot Actuator is a built-in diagnostic console: it'll tell you what's down, the effective value of any property, why a bean did or didn't load, what URL mappings exist, and it'll let you flip a log level to DEBUG without a redeploy. Most "works on my machine" mysteries are one endpoint away.

1. Actuator is your in-app diagnostics

Each endpoint answers a specific debugging question against the live application — its real, fully-resolved state, not what you think the config says. (This app exposes only health,info by default; in dev you widen the allow-list to expose the rest.)

# application-dev.yml — expose the diagnostic endpoints in DEV only
management.endpoints.web.exposure.include: health,info,env,beans,conditions,mappings,loggers,httpexchanges

2. Interactive: which endpoint answers my question?

Each answer shows the endpoint → what you'd see → what it rules out. The Network/CLI view is the same JSON you'd curl.

3. Flip a log level live

# see the current level
curl http://localhost:8081/actuator/loggers/com.bob.devhub

# crank it to DEBUG on the running app — no restart
curl -X POST http://localhost:8081/actuator/loggers/com.bob.devhub \
  -H "Content-Type: application/json" -d '{"configuredLevel":"DEBUG"}'

# ...reproduce the bug, read the logs, then reset
curl -X POST http://localhost:8081/actuator/loggers/com.bob.devhub \
  -H "Content-Type: application/json" -d '{"configuredLevel":null}'

Gold for production debugging: capture DEBUG from a real request, then turn it back off — without a deploy or restart. Target a narrow package (org.springframework.transaction, org.hibernate.SQL) to avoid log floods.

4. Log smarter, not louder

  • Levels are a filter, not decoration. ERROR = needs attention, WARN = suspicious, INFO = lifecycle, DEBUG = flow, TRACE = firehose. Log at the right one so prod can stay at INFO.
  • Targeted DEBUG packages reveal a lot: org.springframework.transaction (tx boundaries), org.hibernate.SQL + ...type.descriptor.sql=TRACE (queries + bound params), org.springframework.web (request mapping), org.springframework.security (the filter-chain decision).
  • Correlate requests with a trace/correlation id (MDC) so one request's lines are greppable across threads.
  • Don't log secrets — tokens, passwords, PII. A DEBUG that dumps a JWT is a leak.

5. One-sentence recap

🔭 Interrogate the running app with Actuator before reaching for a debugger: /health (what's down) · /env (the effective property + which source won) · /conditions (why a bean did/didn't load) · /mappings (is the endpoint registered) · /beans (is it a proxy) · and POST /loggers/{pkg} to flip a targeted package to DEBUG live — expose these endpoints in dev only, keep prod at INFO, and never log secrets.
