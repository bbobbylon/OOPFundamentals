Angular DI Advanced — InjectionToken, Hierarchical Injectors & Providers

The complete dependency injection system: typed tokens, provider recipes, injector hierarchy, and modern inject().

What is Angular DI — and why can't you just use new MyService()?

If every component called new UserService(new HttpClient(...)), you'd have: a different UserService instance per component (no shared cache, no shared auth state), components tightly coupled to specific classes (can't swap a mock in tests), and no control over lifetime. Dependency Injection inverts this: you declare what you need (inject(UserService)) and Angular's injector decides how to provide it — one shared singleton, a scoped instance, or a mock in tests. The component never knows or cares which implementation it gets.

inject() — modern field injection

Old: constructor(private svc: UserService) {}. Modern (Angular 14+): private svc = inject(UserService) in the class field. Both produce the same singleton result. inject() also works inside factory functions, interceptors, and guards — anywhere in the injection context, not just constructors. No emitDecoratorMetadata needed.

InjectionToken — for non-class values

const API_URL = new InjectionToken<string>('API_URL'). Provide in app.config.ts: {provide: API_URL, useValue: environment.apiUrl}. Inject anywhere: private url = inject(API_URL). Use for config values, feature flags, environment settings — anything that's not a class instance. Different environments can provide different values with no code change.

Provider recipes

useClass: provide a different class (swap RealService for MockService in tests). useValue: provide a static value or object. useFactory: call a function to create the instance (can inject its own deps via deps:[]). useExisting: alias one token to an already-provided instance. Combine to build flexible service configuration.

In CIAM: AuthStore is providedIn: 'root' — one singleton across the app. const PING_URL = new InjectionToken('PING_URL') provided in app.config.ts from environment.pingBaseUrl. In tests: TestBed.configureTestingModule({ providers: [{provide: AuthStore, useClass: MockAuthStore}] }) — every component that injects AuthStore gets the mock automatically, with no test-specific code in the component itself.

1. DI System Recap: Tokens, Providers, Injectors

Token

The key used to look up a dependency. Can be a class (most common), an InjectionToken, or a string (avoid strings — use tokens).

Provider

The recipe that tells the injector how to create the value. Types: useValue, useClass, useExisting, useFactory.

Injector

The container that holds token→value mappings. Multiple injectors form a tree. Resolution walks up the tree until found.

// The DI lookup process in pseudo-code:
function inject(Token) {
  let injector = getCurrentElementInjector();
  while (injector !== null) {
    if (injector.has(Token)) return injector.get(Token);
    injector = injector.parent; // walk up
  }
  throw new NullInjectorError(`No provider for ${Token}`);
}

2. InjectionToken<T> — Typed Tokens for Non-Class Values

Use InjectionToken when you need to inject a primitive value, configuration object, or function — anything that isn't a class.

import { InjectionToken } from '@angular/core';

// Basic string token
export const API_URL = new InjectionToken<string>('apiUrl');

// With inline factory + providedIn — no need to add to providers array
export const BASE_URL = new InjectionToken<string>('baseUrl', {
  providedIn: 'root',
  factory: () => 'https://api.example.com'
});

// Complex type token
interface AppConfig {
  apiUrl: string;
  maxRetries: number;
  debugMode: boolean;
}
export const APP_CONFIG = new InjectionToken<AppConfig>('appConfig');

// Register in providers (bootstrapApplication or component)
providers: [
  { provide: API_URL, useValue: 'https://prod.api.example.com' },
  {
    provide: APP_CONFIG,
    useFactory: () => ({
      apiUrl: environment.apiUrl,
      maxRetries: 3,
      debugMode: !environment.production
    })
  }
]

// Inject using inject() function (recommended, modern)
@Injectable({ providedIn: 'root' })
export class ApiService {
  private readonly apiUrl = inject(API_URL);
  private readonly config = inject(APP_CONFIG);
}

3. All Four Provider Types

useValue — Constant

{ provide: API_URL,
  useValue: 'https://api.example.com' }

{ provide: ENVIRONMENT,
  useValue: { production: false } }

Provides a static, already-constructed value. The value is never instantiated — it's given as-is. Good for config, flags, constants.

useClass — New Instance

{ provide: UserService,
  useClass: MockUserService }

// Provide a different impl in tests
// or for feature flags

Angular creates a new instance of the given class when the token is first requested. Useful for swapping implementations (e.g., mock in tests).

useExisting — Alias

{ provide: AbstractLogger,
  useExisting: ConsoleLogger }

// Both tokens resolve to the SAME
// ConsoleLogger instance — no duplication

Maps one token to an already-registered token. Unlike useClass, it reuses the existing singleton — no second instance created.

useFactory — Computed

{ provide: DbConnection,
  useFactory: (config: AppConfig,
               http: HttpClient) => {
    return new DbConnection(config.dbUrl, http);
  },
  deps: [APP_CONFIG, HttpClient]
}

Runs a function to produce the value. Deps array lists what the factory needs — Angular injects them and passes as args.

Multi-Providers — Collecting Multiple Values

// Register multiple interceptors — all use the SAME token, multi:true
{ provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }
{ provide: HTTP_INTERCEPTORS, useClass: LoggingInterceptor, multi: true }
{ provide: HTTP_INTERCEPTORS, useClass: RetryInterceptor, multi: true }

// inject(HTTP_INTERCEPTORS) returns [AuthInterceptor, LoggingInterceptor, RetryInterceptor]

// Custom multi-provider token
export const APP_INITIALIZER_TOKEN = new InjectionToken<AppInitFn[]>('appInit');
{ provide: APP_INITIALIZER_TOKEN, useValue: loadUserFn, multi: true }
{ provide: APP_INITIALIZER_TOKEN, useValue: loadConfigFn, multi: true }

4. DI Decorators: @Optional, @Self, @SkipSelf, @Host

DecoratorBehaviorUse Case
@Optional() Returns null instead of throwing if token not found Optional feature modules, plugins, optional configuration
@Self() Only looks in the current element injector — does not walk up the tree Ensure a dep is provided locally, fail if not
@SkipSelf() Skips the current injector — starts search at the parent Module forChild pattern, avoid circular self-reference
@Host() Stops search at the host component (won't go past view boundary) Directive accesses a service from its host component only 
// @Optional — won't throw
readonly logger = inject(LogService, {
  optional: true  // inject() syntax
});

// Or decorator syntax
constructor(
  @Optional() private logger: LogService
) {}
// @Self — component-local only
constructor(
  @Self() private ctrl: NgControl
) {}

// @SkipSelf — parent's injector
constructor(
  @SkipSelf() private parentSvc: SomeService
) {}

// @Host — stops at host boundary
constructor(
  @Host() @Optional() private form: FormGroupDirective
) {}

import { inject, PLATFORM_ID, DOCUMENT } from '@angular/core';
import { isPlatformBrowser } from '@angular/common';

export class ThemeService {
  private readonly platformId = inject(PLATFORM_ID);
  private readonly document = inject(DOCUMENT);

  setTheme(theme: string) {
    if (isPlatformBrowser(this.platformId)) {
      this.document.documentElement.setAttribute('data-theme', theme);
    }
  }
}

6. The inject() Function — Modern DI

The inject() function is the modern way to resolve dependencies in Angular. It can be called in class fields, constructors, and factory functions — anywhere Angular's injection context is active.

Old: constructor injection

@Component({...})
export class UserComponent {
  private readonly userService: UserService;
  private readonly router: Router;
  private readonly http: HttpClient;

  constructor(
    userService: UserService,
    router: Router,
    http: HttpClient
  ) {
    this.userService = userService;
    this.router = router;
    this.http = http;
  }
}

New: inject() as class fields

@Component({...})
export class UserComponent {
  private readonly userService = inject(UserService);
  private readonly router = inject(Router);
  private readonly http = inject(HttpClient);

  // No constructor needed!
  // TypeScript infers the types automatically.
  // Works in directives, services, pipes too.
}

inject() in Functions (injection context required)

// Guards — standalone functional style (Angular 15+)
export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);      // inject() inside guard function
  const router = inject(Router);
  return auth.isLoggedIn() || router.navigate(['/login']);
};

// Resolvers
export const userResolver: ResolveFn<User> = (route) => {
  return inject(UserService).getUser(route.params['id']);
};

// Class field with computed token
readonly config = inject(APP_CONFIG, { optional: true }) ?? defaultConfig;

8. forwardRef — Resolving Circular References

When you need forwardRef: TypeScript evaluates class definitions in order. If class A references class B that's defined after A (circular or forward reference), the value is undefined at definition time. forwardRef wraps it in a function that's resolved lazily. 
import { forwardRef } from '@angular/core';
import { NG_VALUE_ACCESSOR } from '@angular/forms';

// Custom form control — classic forwardRef use case
@Component({
  selector: 'app-custom-input',
  standalone: true,
  providers: [{
    provide: NG_VALUE_ACCESSOR,
    useExisting: forwardRef(() => CustomInputComponent),
    multi: true
  }]
})
export class CustomInputComponent implements ControlValueAccessor {
  // ... the class body
}
// forwardRef needed because CustomInputComponent is used in its OWN decorator,
// before the class definition is complete.
