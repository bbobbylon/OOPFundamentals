TypeScript Classes — The Full Picture

TypeScript's class system builds on JavaScript's ES2015+ class syntax and adds access modifiers, parameter properties, abstract classes, generics, mixins, and a dual type/value nature that is unique to TypeScript's design.

1. Class basics: TypeScript vs JavaScript

TypeScript classes look very similar to ES2015+ JavaScript classes, but with one critical addition: you must declare properties at the top of the class body before using them. JavaScript silently creates properties in the constructor; TypeScript requires upfront declaration so it can type-check every access.

JavaScript class

class Animal {
  // No property declarations needed
  constructor(name, sound) {
    this.name = name;   // implicit string
    this.sound = sound; // implicit string
  }
  speak() {
    return `${this.name} says ${this.sound}`;
  }
}

TypeScript class

class Animal {
  // Properties declared with types
  name: string;
  sound: string;

  constructor(name: string, sound: string) {
    this.name = name;
    this.sound = sound;
  }
  speak(): string {
    return `${this.name} says ${this.sound}`;
  }
}

TypeScript also infers property types from constructor assignments when strict is off, but with strictPropertyInitialization on (part of strict: true), you must declare and initialize every property — which surfaces bugs where a property is declared but never set.

2. Access modifiers — public, private, protected, readonly

TypeScript adds four access modifiers to class members. These are compile-time enforcements — the compiler rejects code that violates them. Click any member in the diagram below to see the access rules.

Click a member above to see its access rules.
ModifierSymbolAccessible fromNotes
public+Anywhere: the class itself, subclasses, and external codeDefault — you never need to write it explicitly
protected#The class itself and any subclassExternal code (outside the class hierarchy) cannot access it
private-Only the class where it is declaredNot accessible in subclasses. Soft-private — erased at runtime.
readonlyRAnywhere a public property is accessibleCan be set in constructor only; subsequent assignments are errors
class BankAccount {
  public    owner:    string;    // accessible everywhere
  protected balance:  number;    // accessible in this class + subclasses
  private   pin:      number;    // only this class
  readonly  id:       string;    // set in constructor, immutable after

  constructor(owner: string, pin: number) {
    this.owner   = owner;
    this.balance = 0;
    this.pin     = pin;
    this.id      = crypto.randomUUID();
  }
  deposit(amount: number): void {
    this.balance += amount; // ✅ same class
  }
  checkPin(attempt: number): boolean {
    return this.pin === attempt; // ✅ same class
  }
}

class SavingsAccount extends BankAccount {
  addInterest(): void {
    this.balance *= 1.02; // ✅ protected — subclass OK
    // this.pin;  ❌ private — subclass cannot access
  }
}

const acct = new BankAccount("Alice", 1234);
acct.owner;        // ✅ public
// acct.balance;  ❌ protected
// acct.pin;      ❌ private
// acct.id = "x"; ❌ readonly

3. Parameter properties shorthand

Writing private name: string; then this.name = name; in the constructor is repetitive boilerplate. TypeScript's parameter properties shorthand combines property declaration, visibility modifier, and constructor assignment into a single token in the constructor signature.

Before — verbose (4 extra lines per property)

After — parameter properties shorthand

When to use parameter properties: they are ideal for simple value-object classes where the constructor just stores its arguments. Avoid them when the constructor needs to transform or validate the input, as the transformation can't happen inline in the parameter list — use explicit properties in that case.

4. TypeScript private vs # hard-private fields

TypeScript has two ways to make a field private, and they work very differently:

Featureprivate keyword# field (hard private)
EnforcementCompile time only. The field is public at runtime.Runtime enforced. The JS engine truly hides it.
Visibility via consoleVisible in browser devtools, accessible via (obj as any).fieldCompletely invisible outside the class
Subclass access❌ Cannot access parent's private❌ Cannot access parent's #field
Typeof checkNot possible'#field' in obj works as a type guard
PerformanceNo overheadTiny overhead (WeakMap or engine-native)
Use inMost TS code. Old frameworks.When true runtime privacy matters (security-sensitive fields)
class TsPrivate {
  private secret: string = "hidden";
  getSecret() { return this.secret; }
}

const a = new TsPrivate();
// a.secret;          ❌ compile-time error
// (a as any).secret  ✅ works at runtime! TS-private is soft.

class HardPrivate {
  #secret: string = "hidden";
  getSecret() { return this.#secret; }
}

const b = new HardPrivate();
// b.#secret;          ❌ compile-time error
// (b as any).#secret  ❌ runtime SyntaxError
// Object.keys(b)      → [] (field not enumerable)

5. Abstract classes — partial templates

An abstract class is a class that cannot be instantiated directly. It exists to be extended. It may contain a mix of fully-implemented methods (concrete) and abstract method declarations (signatures with no body that subclasses must implement).

Abstract class: Shape

abstract class Shape {
  // Concrete — provided, subclasses inherit it
  describe(): string {
    return `A shape with area ${this.area().toFixed(2)}`;
  }

  // Abstract — must be implemented by subclasses
  abstract area(): number;
  abstract perimeter(): number;
}

// new Shape();  ❌ Cannot create an instance of abstract class

class Circle extends Shape {
  constructor(private radius: number) { super(); }
  area():      number { return Math.PI * this.radius ** 2; }
  perimeter(): number { return 2 * Math.PI * this.radius; }
}

class Square extends Shape {
  constructor(private side: number) { super(); }
  area():      number { return this.side ** 2; }
  perimeter(): number { return 4 * this.side; }
}

const c = new Circle(5);
c.describe(); // "A shape with area 78.54"
// describe() is inherited; area() is Circle's own impl

6. implements vs extends

A class can extend one parent class (inheriting implementation) and implement any number of interfaces (agreeing to satisfy a shape contract). These serve different purposes:

extendsimplements
LimitOne class onlyUnlimited interfaces
Inherits code?Yes — methods and propertiesNo — just the contract; you write the code
Inherits type?YesYes — the class becomes assignable to the interface type
PurposeReuse and specialize behaviorCommit to a public API contract
interface Serializable {
  serialize(): string;
}
interface Cloneable<T> {
  clone(): T;
}

abstract class Entity {
  abstract id: string;
  createdAt: Date = new Date();
}

// Extends one class, implements two interfaces
class User
  extends    Entity
  implements Serializable, Cloneable<User>
{
  id = crypto.randomUUID();
  constructor(public name: string) { super(); }

  // Must implement both interface methods:
  serialize(): string { return JSON.stringify({ id: this.id, name: this.name }); }
  clone(): User        { return new User(this.name); }
}

const u: Serializable = new User("Alice"); // ✅ User satisfies Serializable

7. Class types: typeof MyClass vs InstanceType<typeof MyClass>

A class declaration creates two things: a type (for instances) and a value (the constructor function). TypeScript has utility types to refer to each one explicitly.

class Dog {
  constructor(public name: string) {}
  bark() { return "Woof!"; }
}

// The instance type — what "new Dog('Rex')" produces
type DogInstance = Dog;                         // same as just: Dog
type DogInstance2 = InstanceType<typeof Dog>; // explicit form

// The constructor type — the class itself
type DogClass = typeof Dog;
// DogClass is: { new(name: string): Dog; prototype: Dog; ... }

// Useful for factory functions
function create<T>(Ctor: new(...args: any[]) => T, ...args: any[]): T {
  return new Ctor(...args);
}
const dog = create(Dog, "Rex"); // T = Dog

8. Static members — fields, methods, and blocks

Static members belong to the class constructor, not to instances. TypeScript fully types static members and also supports static initialization blocks (ES2022), which run once when the class is first evaluated — useful for complex static setup.

class Counter {
  // Static field — one copy per class, not per instance
  static count: number = 0;

  // Static method
  static reset(): void { Counter.count = 0; }

  // Static block (ES2022 / TS 4.4+)
  static {
    // complex initialization, runs once on class load
    Counter.count = parseInt(localStorage.getItem('count') ?? '0');
  }

  constructor() {
    Counter.count++;
  }
}

new Counter(); Counter.count; // 1
new Counter(); Counter.count; // 2
Counter.reset(); Counter.count; // 0
Static members cannot use the class's type parameter. If your class is Box<T>, a static method on it cannot reference T — there is no "T" for a class-level concept, only for instances. Declare a separate type parameter on the static method if needed.

9. Generic classes

Classes can declare type parameters just like functions. Every instance is bound to a specific type for its lifetime — you choose it at construction time.

class Repository<T extends { id: string }> {
  private store = new Map<string, T>();

  save(item: T): T {
    this.store.set(item.id, item);
    return item;
  }
  findById(id: string): T | undefined {
    return this.store.get(id);
  }
  list(): T[] {
    return [...this.store.values()];
  }
}

interface User { id: string; name: string; }

const userRepo = new Repository<User>();
userRepo.save({ id: "u1", name: "Alice" }); // T = User
userRepo.save({ id: 123, name: "Bob" });    // ❌ id must be string
userRepo.findById("u1");                    // User | undefined

10. The dual nature of a class in TypeScript

In TypeScript, a class declaration simultaneously creates two things:

  • A type — the shape of an instance of the class, used in type positions (let x: MyClass)
  • A value — the constructor function itself, usable as a runtime object (typeof MyClass)
class Point {
  constructor(public x: number, public y: number) {}
}

// Using Point as a TYPE (erased at runtime):
let p: Point;                     // p is an instance of Point
function distance(a: Point, b: Point): number { /* ... */ }

// Using Point as a VALUE (remains at runtime):
const PointClass = Point;         // reference to the constructor
const q = new PointClass(3, 4);  // creates Point instance
console.log(typeof Point);       // "function" (at runtime)
console.log(q instanceof Point); // true
This is why you can use a class as both a type annotation and pass it as an argument to a factory function. The type aspect is erased; the value (constructor) remains. interfaces, by contrast, are type-only — they produce no runtime value at all.

11. Mixins — composing classes from multiple behaviors

TypeScript does not support multiple inheritance, but the mixin pattern achieves similar composition by building a chain of base classes at call time. A mixin is a function that takes a base class and returns an extended version of it.

// The mixin type: a constructor function
type Constructor<T = {}> = new (...args: any[]) => T;

// Mixin 1: adds timestamp behavior
function Timestamped<B extends Constructor>(Base: B) {
  return class extends Base {
    createdAt = new Date();
  };
}

// Mixin 2: adds activation behavior
function Activatable<B extends Constructor>(Base: B) {
  return class extends Base {
    isActive = false;
    activate()   { this.isActive = true; }
    deactivate() { this.isActive = false; }
  };
}

// Base class
class User {
  constructor(public name: string) {}
}

// Compose: User + Timestamped + Activatable
const TimestampedUser = Timestamped(User);
const FullUser = Activatable(TimestampedUser);

const u = new FullUser("Alice");
u.name;       // string — from User
u.createdAt;  // Date — from Timestamped
u.isActive;   // boolean — from Activatable
u.activate(); // method from Activatable

12. The override keyword (TypeScript 4.3+)

Before TypeScript 4.3, overriding a parent method by re-declaring it was implicit and error-prone. If the parent renamed or removed a method, the subclass silently "added" a new unrelated method instead of overriding. The override keyword makes overrides explicit and generates an error if the parent doesn't have a matching method.

Without override — silent bug

class Animal {
  // Parent renames method from
  // speak() to makeSound()
  makeSound(): string { return "..."; }
}

class Dog extends Animal {
  // Still says speak() — no error!
  // This is now a NEW method, not override.
  speak(): string { return "Woof"; }
  // Animal.makeSound() calls base impl
  // Dog.speak() is unreachable polymorphically
}

With override — caught immediately

class Animal {
  makeSound(): string { return "..."; }
}

class Dog extends Animal {
  // TS4113: This member cannot have an
  // 'override' modifier because it is not
  // declared in the base class 'Animal'.
  override speak(): string { return "Woof"; }

  // Correct:
  override makeSound(): string { return "Woof"; }
}

Enable "noImplicitOverride": true in tsconfig to require the override keyword on all overrides — the compiler will then refuse any method re-declaration that doesn't use the keyword.

13. Class vs interface — when to use which

ConsiderationUse a classUse an interface
Runtime presenceNeed a constructor, instanceof, or static membersType-only — erased at compile time
ImplementationWant to ship method implementationsPurely defining the shape/contract
Multiple inheritanceCan only extend one classCan extend/merge unlimited interfaces
Declaration mergingNot possibleInterfaces can be re-opened and merged
Framework DIUsually required (Angular, NestJS inject class tokens)Cannot be injected (no runtime token)
Object shapes / DTOsOverkill if no behavior neededIdeal — just the shape, no baggage
Rule of thumb: if the construct only describes what something looks like and never needs to be instantiated or passed as a value, use an interface. If you need a constructor, runtime behavior, or static members — use a class.
