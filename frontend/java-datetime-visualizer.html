Java Date/Time API

java.time (Java 8+): immutable, thread-safe date/time handling. Replaces the broken Date and Calendar classes.

📅 Why was java.util.Date broken — and how does java.time fix it?

java.util.Date (1995) is broken three ways: it's mutable (a shared Date is a race condition), month is 0-indexed (endless off-by-one bugs), and it has no timezone (just epoch millis). java.time (Java 8) fixes all of it with immutable types: LocalDate/LocalTime/LocalDateTime (no zone), ZonedDateTime (with zone), Instant (a UTC point — the machine-to-machine format), plus Duration and Period for amounts of time.

  • java.time is immutable — methods return new objects; safe to share across threads.
  • Pick the right type — LocalDateTime (no zone) vs ZonedDateTime (zoned) vs Instant (UTC).
  • Store UTC, display local — Instant in the DB, convert only for the user.
  • Configure Jackson — write-dates-as-timestamps=false for ISO-8601 strings Angular can parse.

Key types at a glance

LocalDate.now() → 2024-01-15. LocalDate.of(2024, 1, 15). LocalDateTime.now() → 2024-01-15T14:30:00. Instant.now() → UTC epoch-based. ZonedDateTime.now(ZoneId.of("America/New_York")). Arithmetic: date.plusDays(7), date.minusMonths(1), dateTime.withHour(9). Comparison: date.isBefore(other), date.isAfter(other), date.isEqual(other). Between: ChronoUnit.DAYS.between(start, end). Parse: LocalDate.parse("2024-01-15"). Format: date.format(DateTimeFormatter.ofPattern("dd/MM/yyyy")).

Timezone handling

LocalDateTime has no timezone — "2024-01-15T14:00" could be any timezone. If you store this in a DB and a user in London and a user in New York both read it, they see the same string but may interpret it differently. ZonedDateTime is unambiguous: ZonedDateTime.of(localDt, ZoneId.of("UTC")). Convert: localDt.atZone(ZoneId.systemDefault()).toInstant(). For APIs: always use UTC internally, convert to user's timezone only for display. Instant for DB storage (most precise, always UTC). ZoneId.getAvailableZoneIds(): all supported TZs.

Jackson serialization of java.time

By default, Jackson serialises LocalDateTime as an array: [2024,1,15,14,30,0] — not useful for Angular. Add jackson-datatype-jsr310 and configure: spring.jackson.serialization.write-dates-as-timestamps=false. Now LocalDateTime → "2024-01-15T14:30:00" (ISO-8601 string). ZonedDateTime → "2024-01-15T14:30:00+05:00". Instant → "2024-01-15T14:30:00.000Z". Angular: createdAt: string in the interface (parse to Date with new Date(user.createdAt) or Angular's DatePipe).

CIAM / Spring Boot: Entities use @CreatedDate Instant createdAt (UTC in the DB); token expiry is Instant.now().plus(15, ChronoUnit.MINUTES), checked with isBefore(Instant.now()). Audit timestamps are ISO-8601 so Angular's DatePipe renders the user's local zone, and a @Scheduled(cron="0 0 2 * * *") cleanup deletes tokens where expiresAt < Instant.now().

Why java.time? — What was wrong with the old API

java.util.Date (the old way)

// Mutable — leads to bugs in multi-threaded code Date d = new Date(); d.setTime(0); // can be changed! // Confusing: month is 0-indexed! new Date(2024-1900, 0, 15); // Jan 15 2024 // year = year-1900, month 0=January! // Not thread-safe: SimpleDateFormat // Date has no timezone — always UTC // No concept of "just a date" or "just a time"

java.time (Java 8+)

// Immutable — thread-safe by design LocalDate d = LocalDate.now(); LocalDate d2 = d.plusDays(5); // new object // Clear, human-readable API LocalDate.of(2024, Month.JANUARY, 15); // Thread-safe formatting with DateTimeFormatter // Separate classes for date, time, datetime, timezone // ISO 8601 by default // Inspired by Joda-Time (now in JDK)

The java.time Class Hierarchy — pick the right one

LocalDate
Date only, no time, no timezone
Birthday, invoice date, holiday. No time-of-day.
LocalDate.of(2024, 3, 15)
LocalDate.now()
LocalTime
Time only, no date, no timezone
Business hours, alarm time, recurring time.
LocalTime.of(9, 30)
LocalTime.now()
LocalDateTime
Date + time, no timezone
Meeting datetime without timezone context.
LocalDateTime.of(2024,3,15, 9,30)
LocalDateTime.now()
ZonedDateTime
Date + time + timezone
Store timestamps in user's timezone. For scheduling across timezones.
ZonedDateTime.now(ZoneId.of("US/Eastern"))
Instant
UTC nanosecond timestamp
Machine-time: logs, audits, database timestamps. Always UTC.
Instant.now()
Instant.ofEpochSecond(0)
OffsetDateTime
Date + time + UTC offset
When you need timezone offset but not full zone rules. Good for DB storage.
OffsetDateTime.now(ZoneOffset.ofHours(-5))
Duration
Amount of time in seconds/nanos
Time-based: "2 hours 30 minutes". Between two Instants/times.
Duration.ofHours(2).plusMinutes(30)
Period
Amount of time in years/months/days
Date-based: "3 months and 5 days". Between two LocalDates.
Period.ofMonths(3).plusDays(5)
Year / YearMonth / MonthDay
Partial date representations
Credit card expiry (YearMonth), birthday (MonthDay), fiscal year (Year).
YearMonth.of(2024, 12)
MonthDay.of(3, 15)

Arithmetic — plus, minus, with, until (all return new objects)

LocalDate today = LocalDate.now(); // Adding today.plusDays(7) today.plusWeeks(2) today.plusMonths(3) today.plusYears(1) // Subtracting today.minusDays(30) today.minusMonths(6) // Specific field override today.withDayOfMonth(1) // first of month today.withMonth(1) // January // TemporalAdjusters — calendar math today.with(TemporalAdjusters.nextOrSame(DayOfWeek.MONDAY)) today.with(TemporalAdjusters.lastDayOfMonth()) today.with(TemporalAdjusters.firstDayOfNextYear())
// Difference between dates LocalDate start = LocalDate.of(2024,1,1); LocalDate end = LocalDate.of(2024,6,15); Period p = Period.between(start, end); p.getMonths() // 5 p.getDays() // 14 long days = ChronoUnit.DAYS.between(start, end); // 166 long weeks = ChronoUnit.WEEKS.between(start, end); // 23 // Duration — for time-based Instant s = Instant.now(); doWork(); Duration elapsed = Duration.between(s, Instant.now()); elapsed.toMillis() // elapsed milliseconds elapsed.toMinutes() // elapsed minutes

Comparison & Querying

LocalDate d1 = LocalDate.of(2024,1,1); LocalDate d2 = LocalDate.of(2024,6,1); d1.isBefore(d2) // true d1.isAfter(d2) // false d1.isEqual(d2) // false d1.compareTo(d2) // negative (d1 < d2) // Field accessors d1.getYear() // 2024 d1.getMonth() // JANUARY (enum) d1.getMonthValue() // 1 (int) d1.getDayOfMonth() // 1 d1.getDayOfWeek() // MONDAY (enum) d1.getDayOfYear() // 1 d1.isLeapYear() // true (2024 is leap) d1.lengthOfMonth() // 31 d1.lengthOfYear() // 366

DateTimeFormatter — parse and format

// Pre-defined formatters (ISO 8601) DateTimeFormatter.ISO_LOCAL_DATE // "2024-03-15" DateTimeFormatter.ISO_LOCAL_TIME // "09:30:45" DateTimeFormatter.ISO_LOCAL_DATE_TIME // "2024-03-15T09:30:45" DateTimeFormatter.ISO_INSTANT // "2024-03-15T09:30:45Z" // Custom pattern DateTimeFormatter fmt = DateTimeFormatter .ofPattern("dd/MM/yyyy HH:mm"); String str = LocalDateTime.now().format(fmt); // "15/03/2024 09:30" // Locale-aware formatting DateTimeFormatter locFmt = DateTimeFormatter .ofLocalizedDate(FormatStyle.LONG) .withLocale(Locale.UK); // "15 March 2024"
// Parsing strings to date/time LocalDate d = LocalDate.parse("2024-03-15"); // ISO format — no formatter needed LocalDateTime dt = LocalDateTime.parse( "15/03/2024 09:30", DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm") ); // Safe parsing with try/catch try { LocalDate d = LocalDate.parse(input, fmt); } catch (DateTimeParseException e) { // invalid format } // Pattern tokens: // yyyy — 4-digit year y — year // MM — month (01-12) M — month (1-12) // dd — day (01-31) d — day (1-31) // HH — hour 24h hh — hour 12h // mm — minute ss — second // a — AM/PM z — timezone name

Time Zones — the hard part of datetime

// ZoneId — named timezone ZoneId utc = ZoneId.of("UTC"); ZoneId eastern = ZoneId.of("America/New_York"); ZoneId london = ZoneId.of("Europe/London"); ZoneId tokyo = ZoneId.of("Asia/Tokyo"); ZoneId local = ZoneId.systemDefault(); // All available zone IDs ZoneId.getAvailableZoneIds().stream() .sorted() .forEach(System.out::println);
// Converting between timezones ZonedDateTime nyTime = ZonedDateTime.now(eastern); ZonedDateTime tokyoTime = nyTime.withZoneSameInstant(tokyo); // LocalDateTime → ZonedDateTime LocalDateTime local = LocalDateTime.of(2024,3,10,2,30); ZonedDateTime zoned = local.atZone(eastern); // Note: 2:30 AM on Mar 10 2024 in Eastern doesn't exist! // DST gap — ZonedDateTime handles this // Instant is always UTC Instant now = Instant.now(); ZonedDateTime inNY = now.atZone(eastern);
Always store timestamps as Instant or UTC OffsetDateTime in databases. Convert to local timezone only for display. DST transitions, political timezone changes, and offset rules change — Instant is immune to all of this.

Interoperating with Legacy java.util.Date / Calendar

// java.util.Date → Instant Date legacyDate = new Date(); Instant instant = legacyDate.toInstant(); // Instant → java.util.Date Date back = Date.from(Instant.now()); // Calendar → Instant Calendar cal = Calendar.getInstance(); Instant i = cal.toInstant(); // LocalDate → Date (via ZonedDateTime) LocalDate ld = LocalDate.of(2024,3,15); Date d = Date.from(ld.atStartOfDay(ZoneId.systemDefault()).toInstant()); // sql.Date → LocalDate java.sql.Date sqlDate = java.sql.Date.valueOf(LocalDate.now()); LocalDate localDate = sqlDate.toLocalDate(); // JPA / Hibernate: map Instant to TIMESTAMP @Column private Instant createdAt; // auto-mapped to TIMESTAMP
