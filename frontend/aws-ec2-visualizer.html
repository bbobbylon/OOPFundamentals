EC2 — Elastic Compute Cloud

EC2 gives you virtual machines (instances) in AWS. For Spring Boot, EC2 is the traditional deployment target — full control over the OS and runtime environment.

1 — Instance Type Families

Instance type format: family.size — e.g., t3.medium. Choose based on your workload:

t3 / t4g
Burstable General Purpose
t3.micro, t3.medium
CPU credits — low baseline, burst when needed. Best for dev/test Spring Boot apps with uneven load. t3.micro = free tier.
m6i / m7g
General Purpose
m6i.large, m6i.xlarge
Balanced CPU/memory. The production default for Spring Boot APIs. m6i.large = 2 vCPU, 8 GB RAM.
c6i / c7g
Compute Optimized
c6i.large
High CPU, less RAM. Use for CPU-intensive workloads: batch processing, high-throughput REST APIs under heavy mathematical load.
r6i / r7g
Memory Optimized
r6i.large
High RAM, moderate CPU. Use for large JVM heap requirements, in-memory caching, or apps with big data sets.

ARM vs x86: g suffix (e.g., t4g, m7g) = AWS Graviton (ARM). Up to 40% better price/performance for Java workloads. Spring Boot runs natively on Graviton.

Running: billed per second. Stop: instance stops, EBS volume persists and is billed. Terminate: instance and EBS deleted permanently — irreversible.

3 — User Data Scripts — Bootstrap on Launch

User Data is a shell script that runs once when an instance first launches. Used to install software, configure the OS, and start your application:

#!/bin/bash # User data script — runs as root on first boot # Update packages yum update -y # Install Java 21 (Amazon Linux 2023) yum install -y java-21-amazon-corretto # Download your Spring Boot JAR from S3 aws s3 cp s3://my-company-artifacts/myapp-1.0.jar /opt/myapp/app.jar # Create a systemd service cat > /etc/systemd/system/myapp.service <<EOF [Unit] Description=Spring Boot Application After=network.target [Service] ExecStart=/usr/bin/java -jar /opt/myapp/app.jar Restart=always Environment=SPRING_PROFILES_ACTIVE=prod User=ec2-user [Install] WantedBy=multi-user.target EOF systemctl enable myapp systemctl start myapp

4 — Key EC2 Concepts

ConceptDescription
AMIAmazon Machine Image — the OS snapshot used to launch an instance. AWS provides Amazon Linux, Ubuntu, Windows AMIs. You can create custom AMIs with your software pre-installed.
Key PairSSH key pair for Linux instances. Download the .pem file at creation — AWS only stores the public key. Use for SSH access to instances.
EBS VolumeElastic Block Store — persistent disk attached to the instance. Like a hard drive. Root volume (OS) billed even when stopped. Can take snapshots.
Elastic IPStatic public IP address. Assigned to instances. Doesn't change on restart. Free while attached to a running instance; charged when not attached.
Instance ProfileIAM Role attached to an EC2 instance. Grants the instance (and your app running on it) AWS permissions without hard-coded credentials.
Auto Scaling GroupAutomatically adds/removes instances based on load. Define: min, max, desired capacity + scaling policies (CPU > 70% → add instance).
Launch TemplateSaved configuration for launching instances (instance type, AMI, security group, user data). Used by Auto Scaling Groups.
Placement GroupControls physical placement of instances for low latency (cluster) or fault isolation (spread).
