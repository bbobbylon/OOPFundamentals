EC2 — Elastic Compute Cloud

EC2 gives you virtual machines (instances) in AWS. For Spring Boot, EC2 is the traditional deployment target — full control over the OS and runtime environment.

💻 What is EC2 — and how does it compare to running Spring Boot on a server or a container service?

EC2 gives you virtual machines (instances) — still the compute layer under ECS, EKS and RDS. You pick an AMI (OS image) and an instance type (m5.large = family m, gen 5, size large): families are t (burstable), m (balanced), c (compute), r (memory, good for big JVM heaps), g (GPU). Pricing: On-Demand (flexible), Reserved (1-3yr, up to 72% off baseline), Spot (up to 90% off but interruptible — batch only). Security Groups are stateful firewalls — allow 8080 from the ALB SG, never 0.0.0.0/0, and return traffic is automatic. User Data scripts run on first boot. For new projects, prefer ECS Fargate over bare EC2.

  • EC2 = VMs — the layer under ECS/EKS/RDS.
  • AMI + instance type — t/m/c/r/g families; r for big JVM heaps.
  • On-Demand / Reserved / Spot — flexible / cheap baseline / interruptible batch.
  • Security Groups = stateful firewalls — allow ALB SG, never 0.0.0.0/0; prefer Fargate.

Instance types for Spring Boot

# Choosing instance type for Spring Boot: # Dev / CI runners: t3.micro (2 vCPU, 1GB) — free tier t3.small (2 vCPU, 2GB) — light services # Production CIAM service: m5.large (2 vCPU, 8GB) — most services m5.xlarge (4 vCPU, 16GB) — high-traffic # Memory-intensive (large JVM heap): r5.large (2 vCPU, 16GB) r5.xlarge (4 vCPU, 32GB) # JVM tip: allocate 60% of RAM to heap # m5.large (8GB): set -Xmx5g # Leave rest for OS + JVM overhead # Check your Spring Boot app's actual usage: # CloudWatch: MemoryUtilization metric # IntelliJ Profiler or jcmd locally # Right-size in prod — don't over-provision

Security Groups (firewall)

# Security Group for Spring Boot EC2 instance: # Inbound rules (what can REACH this instance): Type Source Purpose TCP 8080 sg-alb-prod (ALB SG) receive traffic TCP 22 sg-bastion (Bastion SG) SSH for debug # NO 0.0.0.0/0 — never open to internet! # ALB Security Group (public-facing): Type Source Purpose TCP 443 0.0.0.0/0 HTTPS from internet TCP 80 0.0.0.0/0 HTTP (redirect to 443) # Outbound rules (what this instance can call): # EC2 SG outbound (usually): TCP 5432 RDS SG connect to PostgreSQL TCP 443 0.0.0.0/0 call Ping/Entra OAuth TCP 443 S3 VPC endpoint upload to S3 # Security groups are STATEFUL: # allow inbound TCP 8080 → return traffic # is automatically allowed (no outbound rule needed)

Pricing: On-Demand vs Reserved vs Spot

# m5.large pricing in us-east-1 (approx): On-Demand: $0.096/hr (~$70/mo) # Use for: dev, variable load, new projects # No commitment — spin up and down anytime Reserved (1yr, no upfront): $0.055/hr (~$40/mo) # Use for: steady production baseline # 43% cheaper — commit to 1 year usage Reserved (3yr, all upfront): ~$30/mo # Use for: stable, long-term workloads # 72% cheaper vs On-Demand Spot: $0.01-0.03/hr (varies) # Use for: batch jobs, data processing # Up to 90% cheaper BUT: # - 2 min warning before termination # - NOT for: Spring Boot APIs, RDS, ECS prod # Strategy for CIAM production: # Reserved: baseline capacity (2 instances) # On-Demand: burst capacity (auto-scale adds)

In CIAM / Context: EC2 is usually the host under ECS/EKS rather than running Spring Boot directly; for new projects ECS Fargate removes EC2 management entirely (you define CPU/memory per task). EC2 knowledge still matters for debugging — SSH into a bastion, inspect container instances, or run tooling that doesn't fit a container.

1 — Instance Type Families

Instance type format: family.size — e.g., t3.medium. Choose based on your workload:

t3 / t4g
Burstable General Purpose
t3.micro, t3.medium
CPU credits — low baseline, burst when needed. Best for dev/test Spring Boot apps with uneven load. t3.micro = free tier.
m6i / m7g
General Purpose
m6i.large, m6i.xlarge
Balanced CPU/memory. The production default for Spring Boot APIs. m6i.large = 2 vCPU, 8 GB RAM.
c6i / c7g
Compute Optimized
c6i.large
High CPU, less RAM. Use for CPU-intensive workloads: batch processing, high-throughput REST APIs under heavy mathematical load.
r6i / r7g
Memory Optimized
r6i.large
High RAM, moderate CPU. Use for large JVM heap requirements, in-memory caching, or apps with big data sets.

ARM vs x86: g suffix (e.g., t4g, m7g) = AWS Graviton (ARM). Up to 40% better price/performance for Java workloads. Spring Boot runs natively on Graviton.

Running: billed per second. Stop: instance stops, EBS volume persists and is billed. Terminate: instance and EBS deleted permanently — irreversible.

3 — User Data Scripts — Bootstrap on Launch

User Data is a shell script that runs once when an instance first launches. Used to install software, configure the OS, and start your application:

#!/bin/bash # User data script — runs as root on first boot # Update packages yum update -y # Install Java 21 (Amazon Linux 2023) yum install -y java-21-amazon-corretto # Download your Spring Boot JAR from S3 aws s3 cp s3://my-company-artifacts/myapp-1.0.jar /opt/myapp/app.jar # Create a systemd service cat > /etc/systemd/system/myapp.service <<EOF [Unit] Description=Spring Boot Application After=network.target [Service] ExecStart=/usr/bin/java -jar /opt/myapp/app.jar Restart=always Environment=SPRING_PROFILES_ACTIVE=prod User=ec2-user [Install] WantedBy=multi-user.target EOF systemctl enable myapp systemctl start myapp

4 — Key EC2 Concepts

ConceptDescription
AMIAmazon Machine Image — the OS snapshot used to launch an instance. AWS provides Amazon Linux, Ubuntu, Windows AMIs. You can create custom AMIs with your software pre-installed.
Key PairSSH key pair for Linux instances. Download the .pem file at creation — AWS only stores the public key. Use for SSH access to instances.
EBS VolumeElastic Block Store — persistent disk attached to the instance. Like a hard drive. Root volume (OS) billed even when stopped. Can take snapshots.
Elastic IPStatic public IP address. Assigned to instances. Doesn't change on restart. Free while attached to a running instance; charged when not attached.
Instance ProfileIAM Role attached to an EC2 instance. Grants the instance (and your app running on it) AWS permissions without hard-coded credentials.
Auto Scaling GroupAutomatically adds/removes instances based on load. Define: min, max, desired capacity + scaling policies (CPU > 70% → add instance).
Launch TemplateSaved configuration for launching instances (instance type, AMI, security group, user data). Used by Auto Scaling Groups.
Placement GroupControls physical placement of instances for low latency (cluster) or fault isolation (spread).
