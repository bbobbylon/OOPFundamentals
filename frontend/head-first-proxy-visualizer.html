The Proxy Pattern — a stand-in that controls access

Chapter 11. The CEO wants to monitor every gumball machine in the country from her desk — but they're on machines all over. A Proxy is a stand-in object that implements the same interface as the real thing, so the client can't tell the difference — while the proxy quietly controls access: across a network (remote), defers expensive creation (virtual), checks permissions (protection), or caches results.

The shape — the proxy wears the subject's interface

Client, Proxy, and RealSubject all implement one Subject interface. The client holds a Subject — it never knows it's talking to a proxy.

interface GumballMachineRemote {     // the Subject
  int getCount();
  State getState();
}
class GumballMachine      implements GumballMachineRemote { ... }  // RealSubject
class GumballMachineProxy implements GumballMachineRemote { // Proxy — controls access
  GumballMachineRemote real;          // holds/finds the real one
}
Brain Power. Decorator also wraps an object behind the same interface — so how is Proxy different? Intent. A Decorator's job is to add behavior; a Proxy's job is to control access (where the object lives, when it's created, whether you're allowed, whether the answer is cached). Same diagram, different reason — exactly like State vs Strategy.

Remote proxy — the machine is on another JVM

The CEO's monitor holds a local stub. Calling getCount() on it marshals the call across the network (Java RMI) to the real machine, which runs the method and ships the result back. The monitor code looks like a plain local call.

GumballMachineRemote machine =
    (GumballMachineRemote) Naming.lookup("rmi://denver/gumball");
machine.getCount();   // looks local — actually runs in Denver

Q: So a remote proxy is just networking?

A: It's networking hidden behind the subject's interface. The value is that the client is decoupled from "where" — swap the proxy for a local object and the client code is identical. That location-transparency is the pattern.

Virtual proxy — don't pay until you have to

An ImageProxy stands in for an album cover that's slow to fetch. It paints "Loading…" immediately, downloads the real ImageIcon on a background thread, and swaps it in when ready — so the UI never freezes.

public void paintIcon(...) {
  if (realIcon != null) realIcon.paintIcon(...);
  else {
    g.drawString("Loading album cover…", x, y);   // placeholder
    loadInBackground();                          // create the real one lazily
  }
}

Lazy initialization, on-demand. Hibernate uses exactly this for lazy-loaded entity associations — the proxy is a placeholder until you touch it, then it hits the DB.

Protection proxy — Java's dynamic proxy

A dating service lets people set ratings — but you shouldn't rate yourself. A protection proxy built with java.lang.reflect.Proxy intercepts every call in an InvocationHandler and decides whether to forward it.

class OwnerHandler implements InvocationHandler {
  public Object invoke(Object proxy, Method m, Object[] args) {
    if (m.getName().equals("setGeekRating"))
      throw new IllegalAccessException();   // owners can't rate themselves
    return m.invoke(real, args);            // otherwise delegate
  }
}
The dynamic-proxy "aha". The proxy class doesn't exist in your source — Proxy.newProxyInstance(...) generates it at runtime to implement the interfaces you name, routing every method into your invoke(). This is the same machinery Spring uses for @Transactional and @PreAuthorize — a proxy wraps your bean and runs the cross-cutting check before delegating. (See the Spring "Debugging Proxies" page for when that silently doesn't fire.)

The Proxy Pattern, defined

The Proxy Pattern provides a surrogate or placeholder for another object to control access to it.
It's a familyremote · virtual · protection · caching · firewall · smart-reference
All the same structure — only the kind of access control differs.

Proxy vs Decorator vs Adapter — same wrapper, different intent

Proxy

Same interface. Controls access — location, lifecycle, permission, caching. The client shouldn't notice it's there.

Decorator

Same interface. Adds behavior/responsibility by stacking wrappers. Meant to extend, not gate.

Adapter

Changes the interface so two incompatible types can work together. Proxy/Decorator keep the interface; Adapter converts it.
