early SecurityContextPersistenceFilter
Loads the SecurityContext from the session (for stateful apps) or creates a new empty one for each request (for stateless APIs). Saves it back after the request.
auth BearerTokenAuthenticationFilter
Extracts the Bearer token from the Authorization header. Validates the JWT signature + expiry + issuer + audience. On success, populates the SecurityContext with an Authentication object containing the user's claims and granted authorities.
auth UsernamePasswordAuthenticationFilter
Only active for form-login. Intercepts POST /login, extracts username + password, authenticates against UserDetailsService. Not used when your API uses JWT Bearer tokens.
error ExceptionTranslationFilter
Catches security exceptions: AuthenticationException → 401 response. AccessDeniedException → 403 response. Translates Spring Security exceptions into proper HTTP responses.
authz FilterSecurityInterceptor / AuthorizationFilter
Authorization check — the last gate. Compares the authenticated user's granted authorities against the access rules defined in your SecurityFilterChain (e.g., .requestMatchers("/admin/**").hasRole("ADMIN")). Throws AccessDeniedException if insufficient.

2 — Authentication vs Authorization

Authentication — "Who are you?"

Verifying identity. Checking credentials: username+password, JWT signature, OAuth2 token.

Result: a Authentication object in SecurityContextHolder containing the principal (who they are) and their authorities (what they can do).

Failure → 401 Unauthorized

Authorization — "What can you do?"

Checking if an authenticated principal has permission to perform an action on a resource.

Roles (ROLE_ADMIN, ROLE_USER) or scopes (SCOPE_api.read) are granted authorities checked against your access rules.

Failure → 403 Forbidden

3 — JWT Bearer Token Flow

Click Next Step to walk through the stateless JWT authentication flow:

1

User Logs In

Client POSTs to /auth/login (your auth server or Entra ID) with credentials. Spring Security authenticates them.

2

Server Issues JWT

Server creates a JWT: header.payload.signature. Signs it with a private key. Payload contains: user ID, roles/scopes, exp (expiry), iss (issuer). Returns it to the client.

3

Client Stores JWT

Angular stores the token in memory (safest) or sessionStorage. Never store JWTs in localStorage — vulnerable to XSS attacks that can steal tokens.

4

Client Sends JWT in Every Request

Every API call includes: Authorization: Bearer eyJhbGciOiJSUzI1NiJ9.eyJ1c2VyIjoiYm9i.... An Angular HTTP interceptor (or MSAL interceptor) does this automatically.

5

Server Validates JWT Locally

Spring Security's BearerTokenAuthenticationFilter extracts the token. Validates signature using the public key (from JWKS endpoint — cached). Checks exp not past, iss matches config. No database call. No network call.

6

Access Granted

Security context populated with user's identity and roles/scopes. Request proceeds to the controller. Controller can access: @AuthenticationPrincipal Jwt jwt to read claims.

4 — Securing Endpoints

@Configuration @EnableMethodSecurity // enables @PreAuthorize on methods public class SecurityConfig { @Bean SecurityFilterChain api(HttpSecurity http) throws Exception { return http .sessionManagement(s -> s.sessionCreationPolicy(STATELESS)) // no session .csrf(csrf -> csrf.disable()) // safe for stateless APIs .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults())) // validate JWTs .authorizeHttpRequests(a -> a .requestMatchers("/api/public/**").permitAll() // no auth needed .requestMatchers("/api/admin/**").hasRole("ADMIN") // ROLE_ADMIN required .requestMatchers("/api/reports/**").hasAuthority("SCOPE_reports.read") .anyRequest().authenticated() // all else: logged in ) .build(); } } // application.yml — point Spring to Entra ID (or any OIDC provider): // spring.security.oauth2.resourceserver.jwt.issuer-uri= // https://login.microsoftonline.com/{tenantId}/v2.0
@PreAuthorize on individual controller methods (requires @EnableMethodSecurity):
@PreAuthorize("hasRole('ADMIN') or hasAuthority('SCOPE_write')")
Fine-grained, self-documenting, works alongside class-level requestMatchers rules.
