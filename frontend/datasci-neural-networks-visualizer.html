Neural Networks Fundamentals

Perceptrons, activation functions, forward passes, loss, gradient descent, and backpropagation — the mental model every deep learning system (including every LLM) is built on.

🧠 What is a neural network, really?

A neural network is just repeated applications of one simple operation: take some numbers in, multiply each by a weight, add them up plus a bias, then squash the result through a non-linear activation function. Stack that operation in layers — an input layer, one or more hidden layers, an output layer — and you have a network that can approximate remarkably complex functions. Training is the process of automatically finding good weight values: run a forward pass to get a prediction, measure how wrong it was with a loss function, then use backpropagation (the chain rule, applied backward through every layer) to compute exactly how much each individual weight contributed to that error, and nudge every weight a little in the direction that reduces it — gradient descent. Repeat millions of times and the network "learns." This exact architecture — weighted sums, non-linearities, backprop, gradient descent — is the foundation every deep learning model sits on, including the transformer architecture behind every modern LLM (Claude, GPT, and friends), which is really just a very large, very specifically-shaped stack of these same operations.

  • Weighted sum + non-linear activation is the entire computation of one neuron.
  • Non-linearity is mandatory — stacked linear layers collapse into one linear layer.
  • Backprop computes every weight's gradient efficiently by reusing the chain rule backward, layer by layer.
  • Gradient descent repeatedly steps every weight opposite its gradient, scaled by a learning rate.

One neuron, in full

# z = weighted sum + bias z = w1*x1 + w2*x2 + b # a = non-linear activation a = relu(z) # max(0, z) # Without activation, N stacked # linear layers = ONE linear layer: # y = W2(W1 x) = (W2 W1) x # — depth adds nothing without # a non-linearity between layers

# Binary classification output: z2 = a1 @ W2 + b2 y_hat = sigmoid(z2) # squashes to (0,1) # Multi-class output (softmax): # scores -> probabilities that # sum to 1 across all classes # Loss (binary cross-entropy): loss = -(y*log(y_hat) + (1-y)*log(1-y_hat))

# gradient points toward MORE loss grad = dL_dw # step OPPOSITE the gradient w = w - learning_rate * grad # lr too high -> overshoots # lr too low -> painfully slow # repeated over many mini-batches # = one epoch per full dataset pass

The problem

You did everything the tutorials warn you to do, and the network still won't learn a single thing.

Ten layers deep, and every activation is 0.0000000003

You take the two-layer net from this page's own code — W1 = np.random.randn(2, 3) * 0.1 — and stack it ten layers deep, because your real dataset needs more capacity than a toy 2-input net. You keep the exact same * 0.1 scale on every layer, because it's what worked before.

Layer 1's activations look fine. By layer 5 they're barely a whisper. By layer 10, every activation has rounded down to something indistinguishable from zero — and so has every gradient trying to flow back through them. loss.backward() runs. No exception. No NaN. The loss number simply refuses to move, epoch after epoch.

random init, not zero ✓ ReLU in every hidden layer ✓ the *scale* of that randomness was never adjusted for how many layers it has to survive ⚠

Randomizing your weights only solves the symmetry problem. It says nothing about whether the signal survives the trip through ten layers.

Scale the initial variance to the layer's fan-in
Compute each layer's fan-in — the number of inputs it receives ↓ that's how many terms get summed into each neuron's weighted sum, and more terms means more variance unless you correct for it Draw initial weights from a distribution scaled by 1/fan_in (Xavier/Glorot) or 2/fan_in (He, for ReLU layers) ↓ this keeps activation variance roughly constant from the first layer to the last, instead of compounding smaller (or larger) at every layer Let a framework default do it instead of a single hand-picked constant
The one-sentence rule. A network's activations have to stay in a usable range from the first layer to the last, and that range depends on both the weights' scale AND how many of them get summed per neuron — a constant like * 0.1 that's perfectly safe for a 2-input toy net can silently strangle a 10-layer real one.
If training loss is completely flat — not slow, flat — go check whether activations even reach the output layer with a non-zero magnitude before you blame the learning rate, the architecture, or the data.

The mechanism

This isn't a bug in any one layer — it's a compounding effect across all of them.

  1. Layer 1 receives raw inputs and multiplies them by weights drawn from N(0, 0.1²)L1
  2. Layer 2 receives layer 1's already-shrunk output and applies the same 0.1-scale weights againL2
  3. Each layer's output variance is roughly (previous variance) × fan_in × weight variance — with the weight variance fixed too small, that ratio lands below 1 at every single layerTHE RATIO
  4. A ratio under 1, multiplied by itself ten times, doesn't shrink gently — it collapses exponentiallyCOMPOUNDING
  5. By layer 8-10, activations are computationally indistinguishable from 0.0 — ReLU's derivative there is 0, so backprop's gradient is 0 tooSIGNAL GONE
  6. loss.backward() still computes real numbers the whole way — they're just all ~0. Nothing throws, nothing warns, training just silently does nothingSILENT FAILURE

Steps 3 and 4 are the ones to sit with: a 5% shortfall per layer sounds harmless, but 0.95 raised to the tenth power is 0.60, and 0.7 raised to the tenth power is only 0.03. Small per-layer ratios compound into near-total signal loss within the number of layers most real networks actually have.

Nothing about this diagram involves a mistake in any single layer's code — x @ W1 + b1 is exactly as correct at layer 10 as it was at layer 1. The failure is a property of the WHOLE STACK, which is exactly why it stays invisible if you only ever print or debug one layer at a time.

A too-low learning rate would still show SOME gradual movement over 200 epochs, just slowly. A loss that is completely flat — not just slow — points to a gradient that's actually near-zero, not merely a small step size. Check the activations themselves before blaming the learning rate.

Right. Each layer's output variance depends on both the weight variance and how many inputs it sums (fan-in); leaving the scale factor fixed while stacking more layers compounds a small per-layer shrinkage into a near-total collapse by layer 10, silently — no exception fires because every operation still produces valid, just tiny, numbers.

Depth itself isn't the limit — production networks routinely run far deeper than 10 layers in any framework, NumPy included. What breaks a naive deep network is exactly this kind of initialization mismatch, which is also why frameworks ship a sensible default (Kaiming/He, Xavier) instead of leaving the scale to one hand-picked constant.

1. The Neuron and Why Non-Linearity Is Mandatory

Every neuron computes a weighted sum of its inputs plus a bias, then passes that through a non-linear activation function. Skip the non-linearity and depth buys you nothing.

Input
one node per feature
Weighted Sum
z = Σ(w·x) + b
Activation
ReLU, sigmoid, softmax
Hidden Layer(s)
fully-connected, repeats
Output
shape depends on the task
# Two linear layers with NO activation between them...
y = W2 @ (W1 @ x)
# ...always collapses to ONE linear layer:
y = (W2 @ W1) @ x   # same result, one matrix
# Depth without non-linearity is mathematically pointless.
This is the single most important fact in this page: a network with no activation functions, no matter how many layers you stack, can only ever represent what a single linear layer already represents. The activation function is where the actual "learning power" comes from.
SigmoidSquashes to (0,1). Historically common, but vanishing gradients in deep nets.1 / (1 + e^-z)
ReLUmax(0, z). The modern default for hidden layers — cheap, avoids vanishing gradients for z>0.max(0, z)
SoftmaxConverts a score vector into a probability distribution that sums to 1. Used at the OUTPUT for multi-class classification.e^zi / Σe^zj

2. Forward Pass, Loss, and Network Architecture

Inputs flow layer by layer — weighted sum, then activation, feeding the next layer — until the output layer produces a prediction. The loss function then measures exactly how wrong that prediction was.

Architecture shape depends on the task

# Input layer: no computation,
# one node per feature

# Hidden layer(s): fully connected —
# every neuron sees every input
hidden = relu(x @ W1 + b1)

# Output layer shape by task:
#  regression        -> 1 node, no activation
#  binary classify    -> 1 node, sigmoid
#  N-class classify   -> N nodes, softmax

Loss quantifies "how wrong"

# Regression: Mean Squared Error
mse = mean((y_hat - y_true) ** 2)

# Classification: Cross-Entropy
bce = -(y*log(y_hat) + (1-y)*log(1-y_hat))

# Training's entire goal:
# minimize this one number
The output layer's shape is not a style choice — it's dictated by the task. Get this wrong (e.g. softmax on a regression problem) and the network literally cannot represent the answer you want.

3. Gradient Descent and Backpropagation

Backpropagation efficiently computes the loss's gradient with respect to every weight, by applying the chain rule backward from the output layer and reusing each layer's computation for the next. Gradient descent then uses those gradients to update the weights.

↑gradient points toward MORE loss
↓step OPPOSITE the gradient
× lrstep size scaled by learning rate
lr too highovershoots, diverges
lr too lowconverges painfully slowly
for epoch in range(num_epochs):
    for batch in mini_batches(data):
        y_hat = forward(batch.x)
        L = loss(y_hat, batch.y)
        grads = backprop(L)          # chain rule, output -> input
        for w, g in zip(weights, grads):
            w -= learning_rate * g   # gradient descent step
One epoch = one full pass through the training set. In practice weights update after each mini-batch, not the whole dataset at once — a compromise between noisy-but-fast (batch size 1) and stable-but-slow (full-batch) gradient descent.
