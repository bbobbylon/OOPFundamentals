useReducer & useContext

useReducer centralizes state transitions in a pure function; useContext beams a value down the tree without prop drilling. Together they are React's built-in, dependency-free state manager.

1. useReducer vs useState

Reach for useStateReach for useReducer
One or two independent valuesSeveral values that change together
Simple set/replace updatesMany actions / complex transition logic
Logic lives in the componentLogic worth extracting + unit-testing (it is a plain function)
Next state rarely depends on prevNext state derived from prev + an action
const [state, dispatch] = useReducer(reducer, { count: 0 });
// dispatch is a STABLE reference — safe to omit from deps & pass down
dispatch({ type: 'increment', by: 5 });
dispatch never changes identity. Like setState, React guarantees a stable dispatch across renders. You can pass it through context or to memoized children without it triggering re-renders, and you can safely leave it out of effect dependency arrays.

2. A reducer is a pure function

function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + action.by };
    case 'reset': return { count: 0 };
    default: throw new Error('unknown action ' + action.type);
  }
}
Rules: Always return a new object (never mutate state) so React's Object.is check detects the change. No side effects, no async, no fetching — a reducer takes (state, action) and returns the next state, deterministically. That purity is exactly what makes it trivially unit-testable and replayable.

3. The context re-render gotcha

Every component that calls useContext(X) re-renders whenever X's Provider value changes by Object.is — even React.memo cannot stop it. Passing a fresh object value={{ state, dispatch }} every render re-renders all consumers.

ProblemFix
New value object each renderuseMemo(() => ({ state, dispatch }), [state])
Dispatch-only components re-render on state changeSplit into a state context and a dispatch context
One huge context for everythingMultiple focused contexts so changes are scoped
