1. The Hooks Linked List

React stores hook state in a linked list on the fiber node. Each call to a hook (useState, useEffect, useRef…) reads the NEXT slot in that list. This is why the Rules of Hooks exist: call order must be the same every render so React reads the right slot.

Rule: Never call hooks inside conditionals, loops, or nested functions. If hook call 1 is skipped on render 2, every subsequent hook reads the wrong slot — React cannot detect this at runtime until the values are observably wrong.

2. useEffect Dependency Array

No deps array

useEffect(() => {
  fetchData(); // runs after EVERY render
});

Runs after every commit. Rarely what you want — usually causes infinite loops if fetchData sets state.

Empty deps array []

useEffect(() => {
  const sub = ws.subscribe();
  return () => sub.unsubscribe();
}, []);
// mount only, cleanup on unmount

Runs once after mount. Cleanup runs on unmount. Correct for one-time subscriptions.

Specific deps

useEffect(() => {
  document.title = `User: ${userId}`;
}, [userId]);
// runs when userId changes

Runs when any dep changes (Object.is comparison). The linter rule exhaustive-deps helps you list everything.

⚠️ Stale closure trap

useEffect(() => {
  // count here is ALWAYS 0
  setInterval(() => console.log(count), 1000);
}, []); // count not in deps

The closure captures count=0. Adding count to deps fixes the value but restarts the interval every render. Use useRef to hold the latest value without re-running the effect.

3. useMemo vs useCallback

useMemo — cache a VALUE

const filtered = useMemo(
  () => items.filter(x => x.active),
  [items]
);
// filtered only recomputed when items changes

Use when the computation is genuinely expensive (large sort, heavy parse). useMemo is a hint, not a guarantee — React may evict cached values.

useCallback — cache a FUNCTION

const handleClick = useCallback(
  () => dispatch({ type: 'INC' }),
  [dispatch]
);
// same fn reference while dispatch is stable

useCallback(fn, deps) ≡ useMemo(() => fn, deps). Use when passing a callback to a memoized child component (React.memo) so it does not re-render on every parent render.

When NOT to memoize: Premature memoization adds overhead (dep comparison) without benefit. Profile first. Most components render fast enough that memoization makes no measurable difference. Only reach for useMemo/useCallback when you can demonstrate a render perf problem, or when a child is wrapped in React.memo.
