💻 What is this — and why do three shells even exist?

A shell is just a program that reads text you type, figures out what command you mean, runs it against the filesystem, and prints the result. Bash (Linux/macOS), PowerShell (Windows-native, object-based), and CMD (legacy Windows) all do this same job with different syntax — and switching between them is one of the most common friction points when moving between a dev laptop and a Linux server/container.

  • Navigation — cd, ls/dir/Get-ChildItem — same idea, different command name per shell.
  • Variables — Bash uses $VAR, PowerShell uses $env:VAR, CMD uses %VAR% — a common source of copy-paste script failures across platforms.
  • Pipes & redirection (|, >) — chain one command's output into the next, or into a file — the core Unix philosophy, present (with quirks) in all three.
  • Flip the mode switch to feel these differences side by side on the exact same underlying filesystem.

Same job, different name

The deep difference isn't the names — it's that Bash pipes text between commands, while PowerShell pipes objects. ls | ... in Bash passes lines of text; in PowerShell it passes FileInfo objects with real properties. See the PowerShell page for why that changes everything.
