Angular Built-in Control Flow

@if, @for, @switch, @let, and @defer — Angular 17+'s template syntax that replaces structural directives, compiled away for zero runtime overhead.

🔀 What is Angular's built-in control flow? How is it different from *ngIf / *ngFor?

Before Angular 17, conditional rendering meant the *ngIf structural directive (a CommonModule import) and *ngFor for lists. Angular 17 replaced them with native template syntax — @if, @for, @switch, @let — built into the compiler. No imports, cleaner @else/@empty blocks, better type-narrowing inside @if, a mandatory track on @for, and more efficient compiled output. All new code should use it.

  • @if / @else if / @else — and inside an @if (user()) block, TypeScript narrows user() to non-null automatically.
  • @for (x of xs(); track x.id) — track is required; it tells Angular how to reuse DOM rows instead of rebuilding them.
  • @empty { … } renders when a loop's collection is empty — no more *ngIf="items.length" wrapper.
  • Loop locals are built in: $index, $first, $last, $even, $odd.
  • @let name = … declares a read-only, block-scoped template variable so you compute a value once and reuse it.

@if / @else if / @else

@if (isAuth()) { <app-dashboard/> } @else if (loading()) { <spinner/> } @else { <app-login/> }. Inside the block the condition is type-narrowed — @if (user()) { {{ user()!.name }} } needs no as alias.

@for (track required)

@for (u of users(); track u.id) { <app-row [user]="u"/> } @empty { <p>No users</p> }. track drives DOM reuse; $index/$first/$last/$even/$odd are available; @empty covers the empty case.

@let — template variables

@let displayName = user()?.profile?.name ?? 'Anonymous' — a read-only, block-scoped local that avoids repeating long expressions across the template.

In CIAM:a user list is @for (u of users(); track u.id) { … } @empty { … }; an admin-only button is @if (hasRole('ADMIN')) { <button>Delete</button> }; a clean three-state load is @if (loading()) { <spinner/> } @else if (error()) { <error-banner/> } @else { <user-table/> } — no nested *ngIfs.

1. Why Angular 17 Replaced Structural Directives

Structural Directives (Old)

  • Imported from CommonModule or NgIf, NgFor standalone
  • Runtime directive overhead on each change detection cycle
  • ng-template else blocks are awkward
  • trackBy requires a class method — can't use inline
  • Tree-shaking across different directive imports

Built-in Control Flow (New)

  • Part of the template compiler — no imports needed
  • Compiled away — zero runtime directive cost
  • @else if and @else blocks are first-class syntax
  • track is a required expression — inline lambdas work
  • Smaller bundles — no directive code in output JS

Performance Win

The Angular team reports 30–90% faster @for rendering vs *ngFor in benchmarks, because the compiler emits optimal low-level DOM operations instead of going through the directive abstraction layer.

2. @if / @else if / @else

Replaces *ngIf and the old ng-template #elseBlock pattern. The new syntax reads like real programming language control flow.

OLD — *ngIf with ng-template
<!-- Must import NgIf or CommonModule -->
<div *ngIf="isLoggedIn; else notLoggedIn">
  Welcome, {{ user.name }}!
</div>

<ng-template #notLoggedIn>
  <p>Please sign in.</p>
</ng-template>

<!-- No native else-if — must nest ngIf or use switch -->
<div *ngIf="role === 'admin'">Admin view</div>
<div *ngIf="role === 'mod'">Mod view</div>
<div *ngIf="role !== 'admin' && role !== 'mod'">
  User view
</div>
NEW — @if / @else if / @else
<!-- No imports — built into the compiler -->
@if (isLoggedIn) {
  <div>Welcome, {{ user.name }}!</div>
} @else {
  <p>Please sign in.</p>
}

<!-- Native else-if chain — clean and readable -->
@if (role === 'admin') {
  <div>Admin view</div>
} @else if (role === 'mod') {
  <div>Mod view</div>
} @else {
  <div>User view</div>
}

@if with variable alias

<!-- Store the truthy result in a local variable — no more async | as user -->
@if (user$ | async; as user) {
  <h2>{{ user.name }}</h2>
  <p>{{ user.email }}</p>
}
The as alias inside @if works just like the old *ngIf="obs$ | async as value" pattern — the resolved value is typed and available inside the block.

3. @for — Lists, track, and Context Variables

@for replaces *ngFor and makes track required — no more forgetting trackBy and getting full list re-renders.

OLD — *ngFor
<!-- trackBy is OPTIONAL — easy to forget -->
<ul>
  <li *ngFor="let item of items;
          trackBy: trackByFn;
          let i=index;
          let first=first;
          let last=last">
    {{ i }}: {{ item.name }}
  </li>
</ul>

// In the component class — boilerplate!
trackByFn(index: number, item: Item) {
  return item.id;
}
NEW — @for with track
<!-- track is REQUIRED — compiler error if missing -->
<ul>
  @for (item of items; track item.id) {
    <li>
      {{ $index }}: {{ item.name }}
      <!-- $first, $last, $even, $odd, $count -->
      @if ($first) { <span>NEW</span> }
    </li>
  }
</ul>

<!-- No trackBy method in class needed -->
<!-- Inline expression, identity fn: track $index -->

All $context Variables

VariableTypeDescription

$firstbooleanTrue when this is the first item

$evenbooleanTrue when $index is even

@empty Block — Handle Empty Lists

@for (item of items; track item.id) {
  <li>{{ item.name }}</li>
} @empty {
  <!-- Rendered when items is empty or null -->
  <p>No items found. <a href="#">Add one</a>.</p>
}

4. @switch / @case / @default

Replaces [ngSwitch]/*ngSwitchCase/*ngSwitchDefault. The new syntax is dramatically cleaner — the switch expression is checked once per cycle instead of re-evaluating per case.

OLD — [ngSwitch]
<!-- ngSwitch lives on a wrapper element -->
<div [ngSwitch]="status">
  <p *ngSwitchCase="'loading'">
    Loading...
  </p>
  <p *ngSwitchCase="'error'">
    Error!
  </p>
  <p *ngSwitchDefault>
    {{ data }}
  </p>
</div>
NEW — @switch
<!-- No wrapper element needed -->
@switch (status) {
  @case ('loading') {
    <p>Loading...</p>
  }
  @case ('error') {
    <p>Error!</p>
  }
  @default {
    <p>{{ data }}</p>
  }
}

5. @let — Template-Local Variables (Angular 18+)

@let declares a read-only variable scoped to the current template block. It is re-evaluated every change detection cycle — like a computed but inline in the template.

Basic @let usage

<!-- Compute once, use multiple times -->
@let fullName = firstName + ' ' + lastName;
@let isAdmin = user?.role === 'admin';

<h2>{{ fullName }}</h2>
@if (isAdmin) {
  <app-admin-panel [user]="user" />
}

@let with async pipe

<!-- Replace the awkward *ngIf="obs$ | async as val" -->
@let user = user$ | async;
@let config = config$ | async;

@if (user) {
  <app-profile
    [name]="user.name"
    [theme]="config?.theme" />
}

<!-- user and config are typed — no ! needed -->
@let is read-only. You cannot do @let count = count + 1 to mutate — it is a template alias, not a mutable variable. Use component signals or properties for mutation.
Scope rules: A @let is only visible from its declaration point downward within the same block. It does not escape to parent templates or sibling blocks.

6. @defer Alongside @if and @for

@defer is a sibling of @if and @for in the control flow family — it controls when a block's JS chunk is downloaded, rather than whether the block renders.

<!-- @defer wraps heavy components to delay their download -->
@for (post of posts; track post.id) {
  <article>
    <h3>{{ post.title }}</h3>

    <!-- Comment section: only load JS when user scrolls to it -->
    @defer (on viewport) {
      <app-comments [postId]="post.id" />
    }
    @placeholder {
      <div class="comment-skeleton"></div>
    }
    @loading (minimum 300ms) {
      <app-spinner />
    }
    @error {
      <p>Comments unavailable.</p>
    }
  </article>
}
BlockWhen shownNotes
@deferAfter trigger fires and chunk loads successfullyThis is the main content
@placeholderBefore the trigger fires (initial state)Should be lightweight — loaded eagerly
@loadingWhile the JS chunk is downloadingSupports minimum and after time params
@errorIf the chunk fetch failsNetwork error, 404, etc.

8. Performance: Compiled Away vs Runtime Directives

Angular's new Ivy compiler converts @if/@for/@switch into direct DOM instructions. There is no directive class to instantiate, no input binding cycle, no change detector to attach.

Old: *ngFor compiled output (simplified)

// Creates a NgForOf directive instance
// Attaches its own change detector
// Binds ngForOf input on every CD cycle
// Calls trackBy function through indirection
i0.ɵɵdirectiveCreate(0,
  NgForOf, // <-- directive class alloced
  [IterableDiffers, ...]);
i0.ɵɵproperty('ngForOf', items);   // input
i0.ɵɵproperty('ngForTrackBy', fn); // input

New: @for compiled output (simplified)

// Direct loop — no directive object created
// No input binding overhead
// Compiler inlines the track expression
i0.ɵɵrepeater(
  ctx.items,
  template,     // <-- just a function
  item => item.id // track inline
);
// ~30-90% faster for long lists (Angular benchmarks)
Bundle size: After migrating, remove CommonModule or individual directive imports. Each removed import saves ~1-3KB gzipped. A fully migrated app with 20+ components can save 20-60KB.

9. Common Gotcha: track Must Be Unique

Duplicate track values cause incorrect DOM recycling

If two items share the same track value, Angular cannot distinguish them. It will recycle the wrong DOM node, causing visual glitches, form state corruption, or animation bugs.

Bad — duplicate track values

// Items with same 'category' as track key:
items = [
  { category: 'A', name: 'Apple' },
  { category: 'A', name: 'Avocado' }, // dup!
  { category: 'B', name: 'Banana' },
];

<!-- track category — not unique, Angular warns -->
@for (item of items;
       track item.category) {
  <li>{{ item.name }}</li>
}

Good — unique track values

// Use a guaranteed-unique id field
items = [
  { id: 1, name: 'Apple' },
  { id: 2, name: 'Avocado' },
  { id: 3, name: 'Banana' },
];

<!-- track id — always unique -->
@for (item of items; track item.id) {
  <li>{{ item.name }}</li>
}

<!-- Fallback: track $index (safe but slower) -->
@for (item of items; track $index) { ... }
Use track $index only as a last resort — it disables DOM recycling and forces full re-render on list reorder. Always prefer tracking a stable unique identifier from your data.

9b. @for @empty — the no-items branch

@for can have an @empty fallback block — shown when the iterable is empty. No wrapper @if needed, no loading-state gymnastics for the common "nothing here yet" case.

Before: two separate blocks

<!-- *ngIf to check if empty, then *ngFor -->
*ngIf="users.length > 0; else empty"

<ng-template #empty>
  <p>No users yet.</p>
</ng-template>

<li *ngFor="let u of users">{{ u.name }}</li>

After: @for @empty together

@for (u of users; track u.id) {
  <li>{{ u.name }}</li>
} @empty {
  <li>No users yet. <a href="/invite">Invite one.</a></li>
}

// users = [] → shows @empty block
// users = [{id:1,...}] → shows the li
Angular always shows @empty when the iterable has zero items — including when the array is null or undefined (Angular coerces those to empty). You do not need a separate null check.

9c. All @defer trigger types

The trigger tells Angular when to start downloading the lazy chunk. Multiple triggers can be combined with a semicolon. The prefetch keyword fetches the JS chunk earlier than the trigger fires, so it's already cached when the user needs it.

TriggerFires when…Typical use
on idleBrowser is idle (no queued tasks)Low-priority widgets, analytics, chat
on viewportElement enters the viewport (IntersectionObserver)Images, comment sections, below-the-fold features
on interactionFirst click or tap on the placeholderTooltips, popovers, rich text editors
on hoverMouse enters the placeholderDropdown menus, preview cards
on timer(ms)After a fixed delaySoft prompts, cookie banners
on immediateImmediately (non-blocking)Split JS init from render — avoids layout shifts
when conditionSignal/expression becomes truthyLoad after auth check, feature-flag gate

Combined trigger + prefetch example

<!-- Load on hover; prefetch during idle so it's instant -->
@defer (on hover; prefetch on idle) {
  <app-rich-preview [data]="item" />
}
@placeholder { <span class="preview-thumb">hover to preview</span> }

<!-- Condition-based: load chart library after auth resolves -->
@defer (when user() !== null; prefetch on idle) {
  <app-analytics-chart />
}
@placeholder { <div class="chart-skeleton"></div> }
@loading (minimum 200ms) { <app-spinner /> }
@error { <p>Chart unavailable.</p> }
Combine on viewport with prefetch on idle for the best experience: the browser silently caches the chunk during idle time, so when the user scrolls down the component loads instantly with no spinner.
