NgRx & State Management

The Redux pattern in Angular — Actions, Reducers, Store, Selectors, and Effects. One direction. No surprises. (And yes, when you don't need it.)

The big picture: unidirectional data flow

Every state change goes through the same five stops. No component reaches into another component's state. No service mutates shared objects from twelve places. One direction.

Action — "something happened" Reducer — "given old state + action, return new state" Store — the single source of truth Selector — "give me a slice" View — what the user sees

    The five pieces, in code

    1 Actions — "what happened"

    Plain objects with a string type and an optional payload. They describe events, not commands. Past tense: Todo Added, not Add Todo.

    // todo.actions.ts
import { createAction, props } from '@ngrx/store';

export const addTodo = createAction(
  '[Todo Page] Add Todo',                 // '[Source] Event' — convention
  props<{ text: string }>()              // the payload shape
);

export const toggleTodo = createAction(
  '[Todo Page] Toggle Todo',
  props<{ id: number }>()
);

export const removeTodo = createAction(
  '[Todo Page] Remove Todo',
  props<{ id: number }>()
);

// Effects fire these on API responses
export const loadTodos = createAction('[Todo Page] Load Todos');
export const loadTodosSuccess = createAction(
  '[Todo API] Load Success',
  props<{ todos: Todo[] }>()
);
export const loadTodosFailure = createAction(
  '[Todo API] Load Failure',
  props<{ error: string }>()
);
    Naming convention: [Source] Event. Source = which UI page or API caused it. Event = what happened in past tense. This makes the Redux DevTools timeline readable.

    2 Reducer — "old state + action → new state"

    A pure function. Takes current state and an action, returns the new state. Never mutates. No HTTP calls, no Date.now(), no random — same inputs always give same output.

    // todo.reducer.ts
import { createReducer, on } from '@ngrx/store';
import * as TodoActions from './todo.actions';

export interface TodoState {
  todos: Todo[];
  filter: 'all' | 'active' | 'done';
  loading: boolean;
  error: string | null;
}

export const initialState: TodoState = {
  todos: [],
  filter: 'all',
  loading: false,
  error: null
};

export const todoReducer = createReducer(
  initialState,

  on(TodoActions.addTodo, (state, { text }) => ({
    ...state,                                       // spread = immutable
    todos: [...state.todos, { id: Date.now(), text, done: false }]
  })),

  on(TodoActions.toggleTodo, (state, { id }) => ({
    ...state,
    todos: state.todos.map(t =>
      t.id === id ? { ...t, done: !t.done } : t   // new object, not mutation
    )
  })),

  on(TodoActions.removeTodo, (state, { id }) => ({
    ...state,
    todos: state.todos.filter(t => t.id !== id)
  })),

  on(TodoActions.loadTodos, state => ({ ...state, loading: true })),
  on(TodoActions.loadTodosSuccess, (state, { todos }) => ({
    ...state, loading: false, todos, error: null
  })),
  on(TodoActions.loadTodosFailure, (state, { error }) => ({
    ...state, loading: false, error
  }))
);
    The #1 NgRx bug: mutating state. state.todos.push(t) ❌ — the reference doesn't change, OnPush components don't re-render, and you've broken time-travel debugging. Always spread or use libraries like immer via @ngrx/store's createReducer.

    3 Store — the single source of truth

    A central object holding all feature state. You register reducers at app bootstrap, then inject Store anywhere you need to dispatch or query.

    // app.config.ts (modern standalone)
import { provideStore } from '@ngrx/store';
import { provideStoreDevtools } from '@ngrx/store-devtools';

export const appConfig: ApplicationConfig = {
  providers: [
    provideStore({ todos: todoReducer }),       // register feature slice
    provideStoreDevtools({ maxAge: 25 })       // Redux DevTools in the browser
  ]
};
    // todo.component.ts
import { Store } from '@ngrx/store';

export class TodoComponent {
  private store = inject(Store);

  add(text: string) {
    this.store.dispatch(TodoActions.addTodo({ text }));
  }
}
    Install the Redux DevTools browser extension. With provideStoreDevtools wired in, you get a time-travel timeline of every action — pause, scrub backward, replay. This single feature pays for the boilerplate.

    4 Selectors — "give me a slice"

    Pure functions that derive data from state. Memoized — if inputs don't change, the result is returned from cache. This is what makes NgRx fast.

    // todo.selectors.ts
import { createFeatureSelector, createSelector } from '@ngrx/store';

export const selectTodoState = createFeatureSelector<TodoState>('todos');

export const selectAllTodos = createSelector(
  selectTodoState,
  state => state.todos
);

export const selectFilter = createSelector(
  selectTodoState,
  state => state.filter
);

// Composed: depends on TWO selectors, recomputed only when EITHER changes
export const selectVisibleTodos = createSelector(
  selectAllTodos,
  selectFilter,
  (todos, filter) => {
    switch (filter) {
      case 'active': return todos.filter(t => !t.done);
      case 'done':   return todos.filter(t =>  t.done);
      default:        return todos;
    }
  }
);

export const selectActiveCount = createSelector(
  selectAllTodos,
  todos => todos.filter(t => !t.done).length
);
    // In the component — subscribe with async pipe (Observable) or use signals
visibleTodos$ = this.store.select(selectVisibleTodos);
activeCount   = this.store.selectSignal(selectActiveCount);  // v16+
    Memoization in plain English: selectActiveCount only recomputes when selectAllTodos returns a different reference. Toggle the filter? The todos array reference didn't change → the count is returned instantly from cache.

    5 Effects — "actions in, actions out"

    Reducers are pure — they can't fetch from APIs, write to localStorage, or log to analytics. Effects handle the messy outside world. They listen for one action and dispatch another.

    // todo.effects.ts
import { Injectable, inject } from '@angular/core';
import { Actions, createEffect, ofType } from '@ngrx/effects';
import { switchMap, map, catchError } from 'rxjs';

@Injectable()
export class TodoEffects {
  private actions$ = inject(Actions);
  private api      = inject(TodoApi);

  loadTodos$ = createEffect(() =>
    this.actions$.pipe(
      ofType(TodoActions.loadTodos),                // listen for THIS action
      switchMap(() =>
        this.api.getAll().pipe(
          map(todos => TodoActions.loadTodosSuccess({ todos })),
          catchError(err =>
            of(TodoActions.loadTodosFailure({ error: err.message }))
          )
        )
      )
    )
  );
}

// Register in app.config.ts:
provideEffects([TodoEffects]);
    The pattern: Component dispatches loadTodos → Reducer flips loading: true → Effect hears the same action, calls API, dispatches loadTodosSuccess → Reducer stores results & flips loading: false. Three actions, one round trip. Click "Load from API" above and watch it happen in the log.

    switchMap, mergeMap, concatMap, exhaustMap — pick one

    Effects almost always use one of these four RxJS operators. Choosing wrong = race conditions.

    OperatorWhat it does on new actionUse it for
    switchMapCancels in-flight, starts newSearch-as-you-type, "load latest"
    mergeMapRuns both in parallelIndependent fire-and-forget (analytics)
    concatMapQueues, runs in orderSaves that must not reorder (POST queue)
    exhaustMapIgnores new until current finishesLogin button — don't double-submit

    The full directory layout

    src/app/store/todos/
├── todo.actions.ts      // the verbs (addTodo, removeTodo, loadTodosSuccess, ...)
├── todo.reducer.ts      // pure (state, action) → state, holds initial state
├── todo.selectors.ts    // memoized read-side queries
├── todo.effects.ts      // side-effect handlers (HTTP, localStorage, router)
├── todo.model.ts        // interface Todo { id, text, done }
└── index.ts             // barrel re-export

    Some teams add todo.facade.ts — a single service that wraps store.dispatch and store.select so components never see @ngrx/store directly. Opinion-based; not required.

    The NgRx family (what's in the box)

    @ngrx/store

    The core — Actions, Reducers, Store, Selectors. This is what 90% of "NgRx" refers to.

    @ngrx/effects

    Side-effects layer. Listens for actions, performs I/O, dispatches result actions.

    @ngrx/store-devtools

    Hooks up Redux DevTools for time-travel debugging. Install always.

    @ngrx/entity

    Normalized collections (Dictionary<Id, Entity>). Auto-generates CRUD reducer logic for lists.

    @ngrx/router-store

    Mirrors router state into the store. Selectors can read the URL.

    @ngrx/component-store

    Local, lightweight per-component store. No actions/reducers. The "starter" version.

    @ngrx/signals (v17+)

    The new hotness — SignalStore. Signals-first, way less boilerplate. Look here first if starting today.

    @ngrx/operators

    Helper RxJS operators tailored for effects (concatLatestFrom, etc.).

    NgRx vs SignalStore vs a plain service

    The honest comparison. NgRx isn't always the answer — and in 2026, often isn't.

    ApproachBoilerplateDevToolsUse when
    Plain service + signal() Almost none No time-travel Small/medium apps. Auth state. User prefs. Anything one feature owns.
    @ngrx/signals (SignalStore) Light — declarative Coming / partial You want NgRx's structure with signals, not RxJS. Default choice for new apps.
    @ngrx/component-store Medium No time-travel Complex local state for one component (modal wizard, data table).
    @ngrx/store + effects (classic) Heavy Full time-travel Large app, many features, multiple teams. You need an audit log of every state change. 
    // @ngrx/signals — the same todo logic, fraction of the code
import { signalStore, withState, withMethods, patchState } from '@ngrx/signals';

export const TodoStore = signalStore(
  { providedIn: 'root' },
  withState({ todos: [] as Todo[], filter: 'all' as Filter }),
  withMethods((store) => ({
    add(text: string) {
      patchState(store, s => ({
        todos: [...s.todos, { id: Date.now(), text, done: false }]
      }));
    },
    toggle(id: number) {
      patchState(store, s => ({
        todos: s.todos.map(t => t.id === id ? { ...t, done: !t.done } : t)
      }));
    }
  }))
);

// In the component:
store = inject(TodoStore);
// template: @for (t of store.todos(); track t.id) { ... }
    If you're starting a new Angular app today (2026): use @ngrx/signals SignalStore unless you have a hard requirement for action-replay time-travel. It's 1/3 the code and signals-native.

    When NgRx is overkill (most of the time)

    Small CRUD apps

    One service holding a signal() beats Actions + Reducers + Selectors for any <10-screen app. Don't pay the boilerplate tax.

    Form state

    Use Reactive Forms (FormGroup). Don't dispatch FieldChanged on every keystroke.

    UI-only state

    Modal open/closed, accordion expanded — keep it local to the component. Lifting to a global store is a code smell.

    Server data alone

    If your "state" is just an HTTP cache, look at @tanstack/angular-query or HTTP interceptor caching first.

    Signs you actually need NgRx (classic): 50+ components, multiple teams touching the same state, complex undo/redo, an audit-log requirement, or you genuinely want to time-travel-debug user reports.

    Anti-patterns & common bugs

    BugWhy it breaksFix
    Mutating state in reducerReference equality fails, OnPush won't update, DevTools liesAlways spread/map/filter to make new objects
    HTTP call inside a reducerReducer must be pure & syncMove it to an Effect
    Selectors that aren't memoizedRecomputes on every tick → perf cliffUse createSelector, not raw map on the store
    Sharing actions across features"God actions" become impossible to refactorOne action per source. Add a separate [Other Feature] Foo if needed.
    Forgetting ofType in effectsEffect fires on every action everAlways start effects with ofType(specificAction)
    Subscribing to store.select(...) without async pipeMemory leakUse | async in template, or selectSignal, or takeUntilDestroyed

    The takeaway

    NgRx in one breath: components dispatch actions describing what happened, pure reducers return new state, the store holds it, selectors read slices (memoized), and effects handle the async/side-effecty stuff by listening for actions and dispatching new ones.

    One direction. Pure functions. Immutable updates. That's the whole pattern — everything else is library API.
