Services & Networking

Services give pods a stable DNS name and load-balance traffic. Ingress routes HTTP from outside the cluster.

What are Kubernetes Services — and how does traffic actually reach your pods?

Pods are ephemeral — they start and stop, get new IP addresses every time. You can't hardcode a pod's IP in another service's config. Services solve this: a Service gives a stable virtual IP (ClusterIP) and DNS name to a set of pods, selected by label. Traffic sent to the Service IP is load-balanced across all healthy matching pods. kube-proxy on each node maintains iptables/ipvs rules to route Service IPs to pod IPs. Service types: ClusterIP (default) — only reachable INSIDE the cluster. Other pods call http://ciam-auth-service:8080 — DNS resolves to the ClusterIP. NodePort — also exposes the service on a static port (30000-32767) on EVERY node's IP. Reachable from outside, but clunky (node IP + port). LoadBalancer — provisions a cloud load balancer (AWS NLB, Azure Load Balancer, GCP LB). Gets a public IP. One service = one load balancer = expensive for many services. ExternalName — maps a Service to an external DNS name. Ingress: a smarter HTTP router in front of multiple Services. One Ingress controller (nginx, Traefik, AWS ALB controller) handles TLS termination, path-based routing (/api → backend service, /auth → CIAM service), host-based routing (api.example.com vs auth.example.com), and rate limiting. One Ingress can front many services — much cheaper than one LoadBalancer per service. DNS: CoreDNS runs in-cluster. Every Service gets a DNS entry: <service-name>.<namespace>.svc.cluster.local. Within the same namespace: http://ciam-auth works. Cross-namespace: http://ciam-auth.ciam-prod.

Service manifest

apiVersion: v1 kind: Service metadata: name: ciam-auth # DNS name namespace: ciam-prod spec: type: ClusterIP # default selector: app: ciam-auth # matches pod labels ports: - port: 8080 # service port targetPort: 8080 # pod port protocol: TCP --- # Another service calls it: # http://ciam-auth:8080/api/users # http://ciam-auth.ciam-prod:8080/api/users (cross-ns) # http://ciam-auth.ciam-prod.svc.cluster.local:8080 # LoadBalancer for external access: spec: type: LoadBalancer # provisions AWS ALB selector: app: ciam-auth ports: - port: 443 targetPort: 8080

NetworkPolicy security

By default, all pods in a cluster can talk to all other pods — no network isolation. NetworkPolicy adds firewall rules at the pod level. Deny all traffic first, then allow only what's needed: apiVersion: networking.k8s.io/v1; kind: NetworkPolicy; spec: { podSelector: { matchLabels: { app: ciam-auth }}; policyTypes: [Ingress, Egress]; ingress: [{ from: [{ podSelector: { matchLabels: { app: api-gateway }}}], ports: [{ port: 8080 }] }]; egress: [{ to: [{ podSelector: { matchLabels: { app: postgres }}}], ports: [{ port: 5432 }] }] }. This says: ciam-auth pods can ONLY receive traffic from api-gateway pods on port 8080, and can ONLY send traffic to postgres pods on port 5432. Everything else blocked. Essential for CIAM: prevents compromised services from communicating laterally to identity stores.

CIAM networking topology: External traffic: Internet → AWS ALB (or Azure Application Gateway) → Ingress Controller pod → routes by host/path → ClusterIP Services → pods. Ping Identity server: ClusterIP service named ping-gateway, DNS ping-gateway.ciam-prod:9031 — other services reach it via that stable name. CIAM auth Spring Boot: ClusterIP ciam-auth:8080. Angular frontend served by nginx pods: ClusterIP ciam-frontend:80. TLS terminates at the Ingress (one cert for all services). NetworkPolicy: ciam-auth pods only accept from the Ingress controller pod (label app: nginx-ingress) — direct pod-to-pod calls from untrusted pods are blocked. This is critical for a CIAM service — you don't want a compromised microservice to directly call your user management endpoints.

2 — ClusterIP Service Manifest




apiVersion: v1
kind: Service
metadata:
  name: api-server-svc
  namespace: default
spec:
  selector:
    app: api-server    # matches Deployment pod labels
  ports:
  - port: 80           # service port (what callers use)
    targetPort: 8080   # pod port (what Spring Boot listens on)
  type: ClusterIP      # default — internal only
---
# Other pods call it by DNS:
# http://api-server-svc              (same namespace)
# http://api-server-svc.default.svc.cluster.local (FQDN)









3 — Ingress




An Ingress is an L7 HTTP router. It requires an Ingress Controller (nginx, Traefik, AWS ALB…) to be installed. Multiple services share one cloud load balancer.


apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  tls:
  - hosts: [api.myapp.com]
    secretName: tls-cert
  rules:
  - host: api.myapp.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-server-svc
            port: { number: 80 }









4 — Network Policies




By default, all pods can talk to all pods. NetworkPolicies restrict ingress/egress at the pod level (requires a CNI that enforces them, e.g. Calico or Cilium).


# Allow only the frontend to call the api-server
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-only
spec:
  podSelector:
    matchLabels: { app: api-server }
  ingress:
  - from:
    - podSelector:
        matchLabels: { app: frontend }
    ports:
    - { port: 8080 }
