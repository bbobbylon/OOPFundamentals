Routing — turning URLs into components

Angular Router maps a URL path to a component. Click a link → the URL changes → a different component renders in the <router-outlet>. No page reload, no server roundtrip. Add guards, lazy loading, and route data on top.

Defining routes

// app.routes.ts — central place where every route lives
import { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '',         redirectTo: '/home', pathMatch: 'full' },
  { path: 'home',     component: HomeComponent },
  { path: 'users',    component: UserListComponent },
  { path: 'users/:id', component: UserDetailComponent },  // :id = param
  { path: 'admin',    component: AdminComponent,
    canActivate: [authGuard] },                              // gate
  { path: '**',       component: NotFoundComponent }      // catch-all 404
];

// main.ts — register the router
bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes)
  ]
});

<!-- app.component.html — where the routed component renders -->
<app-header />
<router-outlet/>           <!-- this is where Angular puts the matched component -->
<app-footer />

RouterLink — navigation in templates

<!-- Don't use plain <a href="/users"> — that triggers a full page reload! -->

<!-- Use routerLink — Angular intercepts and does in-app navigation -->
<a routerLink="/home">Home</a>
<a [routerLink]="['/users', user.id]">{{ user.name }}</a>
<!--                ↑ array form — segments joined with /, params interpolated -->

<!-- routerLinkActive adds a class when the link's route is active -->
<a routerLink="/users"
   routerLinkActive="active"
   [routerLinkActiveOptions]="{exact: true}">
  Users
</a>
<!-- {exact: true} → only active if URL matches EXACTLY (not for prefix matches) -->

Programmatic navigation — Router.navigate()

export class LoginComponent {
  private router = inject(Router);

  async onLogin() {
    await this.authService.login();
    this.router.navigate(['/dashboard']);          // absolute
  }

  openUser(id: string) {
    this.router.navigate(['/users', id]);
  }

  goWithQueryParams() {
    this.router.navigate(['/search'], {
      queryParams: { q: 'angular', page: 2 }
    });   // → /search?q=angular&page=2
  }

  goBack() {
    this.router.navigate(['..']);   // relative — go up one segment
  }
}

Route params & query params — reading the URL

When the user is on /users/42?tab=settings, the :id param is 42 and the query param tab is settings. Read them via ActivatedRoute. 

export class UserDetailComponent {
  private route = inject(ActivatedRoute);

  // Snapshot — value at time of route activation. Good if it never changes.
  id = this.route.snapshot.paramMap.get('id');                // '42'
  tab = this.route.snapshot.queryParamMap.get('tab');          // 'settings'

  // Observable — fires every time the param changes WITHOUT recreating the component
  id$ = this.route.paramMap.pipe(map(p => p.get('id')));
}

The gotcha: navigating from /users/1 to /users/2 does NOT recreate UserDetailComponent — Angular reuses it for performance. snapshot would still show 1. Use paramMap observable when params can change without leaving the route.

Route guards — gate access to a route

Guards are functions Angular runs before navigating. Return true → allow. Return false or a UrlTree → block / redirect. (Class-based CanActivate still works but functional is the modern way.) 

// auth.guard.ts — functional guard (Angular 14.2+)
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';

export const authGuard: CanActivateFn = () => {
  const auth   = inject(AuthService);
  const router = inject(Router);

  if (auth.isLoggedIn()) return true;

  // Block AND redirect — return a UrlTree
  return router.createUrlTree(['/login']);
};

// Wire it up in routes
{ path: 'admin', component: AdminComponent, canActivate: [authGuard] }

Guard types — when each fires

GuardFires whenUse case
canActivateBefore activating a routeAuth checks, feature flags.
canActivateChildBefore activating any child routeSection-wide auth (e.g. all /admin/*).
canDeactivateBefore leaving a route"You have unsaved changes" confirm dialog.
canMatchBefore route is even matchedA/B test routes, role-based redirects.
resolvePre-fetch data before activatingBlock route until critical data is loaded.

Nested routes (child routes) + multiple outlets

export const routes: Routes = [
  {
    path: 'users',
    component: UserLayoutComponent,                // has its own <router-outlet>
    children: [
      { path: '',        component: UserListComponent },
      { path: ':id',     component: UserDetailComponent,
        children: [
          { path: 'posts',   component: UserPostsComponent },
          { path: 'settings', component: UserSettingsComponent }
        ]
      }
    ]
  }
];

// URL → routed components:
// /users               → UserLayoutComponent + UserListComponent
// /users/42            → UserLayoutComponent + UserDetailComponent
// /users/42/posts      → UserLayoutComponent + UserDetailComponent + UserPostsComponent

Lazy loading — load code only when needed

The biggest perf lever in Angular. Without lazy loading, every component, service, and library across your whole app ships in one JS bundle on first load. With it, route-specific code downloads only when the user actually navigates there. 

// ❌ Eager — admin code is in the main bundle even if user never goes to /admin
{ path: 'admin', component: AdminComponent }

// ✅ Lazy — admin code is a separate chunk, downloaded on demand
{
  path: 'admin',
  loadComponent: () => import('./admin/admin.component').then(m => m.AdminComponent)
}

// ✅ Lazy whole feature with its own sub-routes
{
  path: 'admin',
  loadChildren: () => import('./admin/admin.routes').then(m => m.adminRoutes)
}

Route data & resolvers

// Static route data — for things like page titles, roles, breadcrumbs
{
  path: 'admin',
  component: AdminComponent,
  data: { title: 'Admin', role: 'admin', breadcrumb: 'Admin' }
}

// Read it in the component
private route = inject(ActivatedRoute);
title = this.route.snapshot.data['title'];

// Resolver — fetch data BEFORE the route activates
export const userResolver: ResolveFn<User> = (route) => {
  const id = route.paramMap.get('id')!;
  return inject(UserService).getById(id);
};

{ path: 'users/:id', component: UserDetailComponent,
  resolve: { user: userResolver } }

// Read it in the component
user = this.route.snapshot.data['user'];   // already loaded — no loading spinner needed

Resolvers block navigation until data is ready. Convenient, but for slow APIs they make the UI feel unresponsive. Often better to navigate immediately and show a loading skeleton inside the component.

Router events — react to navigation

export class AppComponent {
  private router = inject(Router);

  constructor() {
    this.router.events.pipe(
      filter(e => e instanceof NavigationEnd)
    ).subscribe((e: NavigationEnd) => {
      console.log('navigated to', e.url);
      analytics.track('page_view', { url: e.url });
    });
  }
}

// All event types: NavigationStart, RoutesRecognized, GuardsCheckStart,
// ResolveStart, ActivationStart, NavigationEnd, NavigationCancel,
// NavigationError, Scroll. NavigationEnd is the one you'll use 99% of the time.

The 5 mistakes to avoid

❌ Using <a href="/foo">

Plain anchors trigger a full page reload — your app reinitializes from scratch. Use routerLink for all in-app links.

❌ Forgetting {exact: true}

routerLinkActive matches by prefix. /users would stay "active" on /users/42. Add [routerLinkActiveOptions]="{exact: true}" for nav items that should only highlight on an exact match.

❌ Reading params from snapshot when they can change

If users can navigate between /users/1 and /users/2 while staying in the same component, use paramMap observable, not snapshot.

❌ Putting auth state in the URL

Don't write /dashboard?auth_token=.... Tokens belong in headers / cookies / storage, never in URLs (they leak to logs, history, referer headers).

❌ Loading everything eagerly

A 5MB initial bundle = a 4-second first paint on a 3G phone. Lazy-load every feature route unless it's the homepage.

❌ Heavy work in guards

Guards run on every navigation. A slow guard = a slow app. Cache results, return Observables, and never make N synchronous network calls.

Mental model

URL = state

The URL is the source of truth for "what page are we on." Bookmark it, share it, refresh → same view. Router-state must be reflected in the URL.

One outlet per layout level

The root <router-outlet> shows the top-level routed component. Each nested layout has its own <router-outlet> for its children.

Guards = the bouncer

Stand at the door, check ID, let you in or send you to /login. They run BEFORE the component is even constructed.

Lazy load by feature

Each top-level feature (admin, settings, reports) is its own lazy chunk. Initial bundle stays small, page-load stays fast.
