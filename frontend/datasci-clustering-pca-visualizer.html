Clustering & Dimensionality Reduction — K-Means & PCA

Unsupervised learning's two core moves: grouping similar points together (clustering) and simplifying high-dimensional data down to its most informative axes (dimensionality reduction) — with no labels required.

🧭 What are clustering and PCA, and why do they need each other?

Clustering and dimensionality reduction are the two pillars of unsupervised learning — there's no y label to predict, only structure to discover in the raw feature vectors. K-means groups points into k clusters by repeatedly assigning each point to its nearest centroid and then recomputing centroids as the mean of their assigned points, until assignments stop changing. It's fast and intuitive, but it requires you to pick k up front (the elbow method is the standard heuristic), assumes roughly spherical clusters, and is extremely sensitive to feature scale since it's built entirely on Euclidean distance. PCA solves a different but related problem: when you have too many correlated features to visualize or train on efficiently, it finds new axes — principal components — ordered by how much variance each one captures, so keeping just the top few compresses your data while losing as little information as possible. Both techniques show up constantly as a preprocessing or exploratory step before a supervised model ever sees the data.

  • K-means iterates — assign to nearest centroid, recompute centroid, repeat until stable.
  • Choosing k is a heuristic — the elbow method plots inertia vs. k and looks for the bend.
  • Scale your features first — unscaled ranges silently dominate the distance calculation.
  • PCA compresses, it doesn't select — components are combinations of ALL features, so they trade interpretability for compression.

K-means in scikit-learn

from sklearn.cluster import KMeans km = KMeans( n_clusters=3, init='k-means++', # smarter init n_init=10, # 10 random restarts random_state=42 ) labels = km.fit_predict(X_scaled) km.inertia_ # within-cluster sum of squares km.cluster_centers_ # the 3 centroid vectors

PCA in scikit-learn

from sklearn.decomposition import PCA pca = PCA(n_components=2) X_reduced = pca.fit_transform(X_scaled) pca.explained_variance_ratio_ # array([0.72, 0.23]) # → top 2 components keep 95% of # the original variance

Always scale before either one

from sklearn.preprocessing import StandardScaler X_scaled = StandardScaler().fit_transform(X) # mean 0, std 1 per feature # Without this, a feature ranging # 20,000–200,000 (income) swamps # a feature ranging 18–70 (age) # in every distance calculation.

Why this matters beyond a notebook: clustering shows up in production identity/security work too — grouping login events by behavioral features (time of day, device fingerprint, geo-velocity) to flag anomalous sessions is k-means (or a density-based cousin) applied to auth logs. PCA is the same trick used to compress high-dimensional embeddings before feeding them into a faster downstream classifier — the exact tradeoff (compression vs. interpretability) you'll hit again on the AI/LLM Engineering track's embeddings page.

1. K-Means — Iterate Until the Centroids Stop Moving

K-means is a loop, not a formula: place k centroids, assign every point to its nearest one, recompute each centroid as the mean of its assigned points, and repeat until no point changes its assignment.

1. Init
place k centroids (k-means++ picks smarter starting points than pure random)
2. Assign
each point joins its nearest centroid by Euclidean distance
3. Update
recompute each centroid as the mean of its current members
4. Repeat
stop when assignments no longer change (converged)
from sklearn.cluster import KMeans
km = KMeans(n_clusters=3, init='k-means++', n_init=10, random_state=42)
labels = km.fit_predict(X_scaled)
km.inertia_  # within-cluster sum of squared distances — lower is tighter
K-means is not guaranteed to find the global best split — a bad random initial placement can converge to a poor local optimum. That's exactly why init='k-means++' (smarter initial spread) and n_init=10 (run it 10 times, keep the best inertia) are the scikit-learn defaults, not extras.

Choosing k: the elbow method

Inertia always drops as k grows — more clusters always fit tighter. The elbow method looks for where that drop stops being worth it.

The steep drop from k=1 to k=3, followed by a much flatter line from k=3 onward, is the "elbow" — the point past which adding clusters buys little. It's a visual heuristic, not an exact answer; domain knowledge should still have a vote.

2. Why Feature Scaling Matters for Distance-Based Clustering

K-means (and k-NN, and anything else built on Euclidean distance) treats every feature's raw numeric range as equally meaningful — which is almost never true.

Unscaled — income dominates

20,000–200,000income range
18–70age range
# distance is ~entirely driven by income
dist = sqrt((income1-income2)**2 + (age1-age2)**2)
# age's contribution rounds to noise

Scaled — both features count

from sklearn.preprocessing import StandardScaler
X_scaled = StandardScaler().fit_transform(X)
# every feature: mean 0, std 1
# now income and age contribute fairly
This is the single most common reason a beginner's first k-means result looks nonsensical: one large-range feature silently decides every cluster assignment by itself. Always StandardScaler (or MinMaxScaler) before clustering.

3. PCA — Compress Dimensions, Keep the Variance

PCA finds new axes (principal components) as linear combinations of your original features, ordered by how much variance each one explains. Keep the top few, drop the rest.

from sklearn.decomposition import PCA
pca = PCA(n_components=2)
X_reduced = pca.fit_transform(X_scaled)   # 3 features → 2 components
pca.explained_variance_ratio_             # [0.72, 0.23] → 95% of variance kept
The curse of dimensionality is the real motivation: as feature count grows, points spread out and become roughly equidistant from each other, which quietly breaks distance-based methods like k-means and k-NN. PCA fights this by compressing correlated features into fewer, information-dense axes.
The catch: principal component 1 isn't "mostly height" — it's a weighted blend of every original feature. You gain compression and noise reduction, but you lose the ability to point at a component and say what it directly means. That tradeoff is the whole reason PCA is a preprocessing step, not a replacement for understanding your raw features.
