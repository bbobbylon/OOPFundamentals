Observable Fundamentals

An Observable is a lazy push stream — it produces values over time and pushes them to subscribers. Unlike a Promise (eager, one value), an Observable is lazy (nothing happens until subscribed) and can emit multiple values.

import { Observable, of, from, interval, timer } from 'rxjs'; // Create observables const sync$ = of(1, 2, 3); // emits 1, 2, 3 synchronously const arr$ = from([10, 20, 30]); // from array/promise/iterable const tick$ = interval(1000); // 0,1,2,3... every second const once$ = timer(2000); // emits 0 after 2s, completes // Custom observable const custom$ = new Observable<number>(subscriber => { subscriber.next(1); // push a value subscriber.next(2); subscriber.complete(); // signal done // subscriber.error(err) // signal error return () => { /* teardown: cleanup on unsubscribe */ }; }); // Subscribe const sub = custom$.subscribe({ next: v => console.log('value:', v), error: err => console.error('error:', err), complete: () => console.log('done') }); sub.unsubscribe(); // clean up!

Observable Contract

Sequences of notifications:
• next(value) — zero or more times
• then error(err) OR complete() — at most once
• After error/complete: no more next() calls

Filtering Operators

filter / take / takeUntil / skip

// filter — only pass values that match predicate events$.pipe(filter(e => e.type === 'click')) // take — only first N values, then complete infinite$.pipe(take(5)) // first 5 then complete // takeWhile — emit while condition true count$.pipe(takeWhile(n => n < 10)) // takeUntil — emit until notifier emits // KEY pattern: unsubscribe on component destroy data$.pipe( takeUntil(this.destroy$) // or takeUntilDestroyed() ) // skip / skipWhile — ignore first N values$.pipe(skip(1)) // skip first emission values$.pipe(skipWhile(x => x < 5))

distinct / distinctUntilChanged

// distinctUntilChanged — skip identical CONSECUTIVE values // Essential for search to avoid duplicate requests searchTerm$.pipe( distinctUntilChanged(), // skip if same as previous switchMap(term => search(term)) ) // distinctUntilChanged with custom comparator: users$.pipe( distinctUntilChanged((prev, curr) => prev.id === curr.id) ) // distinct — skip ALL values seen before // (keeps full history — use with care on infinite streams) ids$.pipe(distinct()) // no duplicate IDs ever // first / last — take exactly one events$.pipe(first()) // first + complete events$.pipe(first(e => e.ok)) // first matching events$.pipe(last()) // wait for complete, then last

Error Handling

An unhandled Observable error kills the stream! After an error, the Observable completes and no more values will be emitted. Always handle errors inside the pipe using catchError or retry — not in the subscriber.

catchError — Recover From Error

// catchError receives err, must return an Observable http.get('/api/data').pipe( catchError(err => { // Option 1: return fallback value return of([]); // Option 2: re-throw (let caller handle) throw err; // Option 3: return EMPTY (complete silently) return EMPTY; }) ) // catchError per request (not whole stream): requests$.pipe( mergeMap(req => http.get(req.url).pipe( catchError(() => of({ error: true, url: req.url })) // per-request ) ) )

retry / retryWhen

// retry — simple immediate retry http.get('/api').pipe(retry(3)) // try up to 4 times // retry with exponential backoff (RxJS 7+) http.get('/api').pipe( retry({ count: 3, delay: (err, retryCount) => timer(retryCount * 1000) // 1s, 2s, 3s between retries }) ) // Manual exponential backoff: http.get('/api').pipe( retryWhen(errors$ => errors$.pipe( mergeMap((err, i) => { if (i >= 3) throw err; // give up after 3 return timer(2 ** i * 1000); // 1s, 2s, 4s }) ) ) )

Subjects — Observables You Can Push To

A Subject is both an Observable (you can subscribe) and an Observer (you can call next/error/complete). Used for multicasting and bridging imperative to reactive code.

Subject — Hot, No Replay

// Subject: like an EventEmitter const subject = new Subject<string>(); subject.subscribe(v => console.log('A:', v)); // subscriber A subject.next('hello'); // A sees 'hello' subject.subscribe(v => console.log('B:', v)); // subscriber B joined late subject.next('world'); // BOTH see 'world' // B missed 'hello' — no replay // In Angular service — shared event bus: @Injectable({ providedIn: 'root' }) class EventBus { private refresh$ = new Subject<void>(); onRefresh$ = this.refresh$.asObservable(); // expose read-only triggerRefresh() { this.refresh$.next(); } }

BehaviorSubject — Always Has Current Value

// BehaviorSubject: replays last value to new subscribers // MUST provide initial value const user$ = new BehaviorSubject<User | null>(null); user$.subscribe(u => renderHeader(u)); // gets null immediately user$.next({ name: 'Alice' }); // renders 'Alice' // New subscriber immediately gets current value: user$.subscribe(u => setupSidebar(u)); // gets {name:'Alice'} right away // Read current value without subscribing: const currentUser = user$.value; // synchronous! // Most common use: Auth state in Angular @Injectable({ providedIn: 'root' }) class AuthService { private user = new BehaviorSubject<User|null>(null); user$ = this.user.asObservable(); isLoggedIn$ = this.user$.pipe(map(u => !!u)); login(u: User) { this.user.next(u); } logout() { this.user.next(null); } }

ReplaySubject — Buffers N Values

// ReplaySubject(N) — replay last N to new subscriber const chat$ = new ReplaySubject<Message>(50); // last 50 messages // Any new subscriber sees last 50 messages immediately // With time window: const events$ = new ReplaySubject<Event>(100, 60000); // Replay up to 100 events from last 60 seconds

AsyncSubject — Last Value on Complete

// AsyncSubject: only emits LAST value when complete() // Like a Promise — useful for caching one-time requests const config$ = new AsyncSubject<Config>(); fetch('/config.json').then(r => r.json()).then(c => { config$.next(c); config$.complete(); // triggers emission }); // shareReplay — multicast and replay without Subject boilerplate const cachedUser$ = http.get('/user/me').pipe( shareReplay(1) // one HTTP call, shared among all subscribers );

Essential Angular + RxJS Patterns

Search with Debounce & Cancel

@Component({ template: ` <input [formControl]="search"/> <div *ngFor="let r of results$ | async">{{ r }}</div> ` }) export class SearchComponent { search = new FormControl(''); results$ = this.search.valueChanges.pipe( debounceTime(300), // wait for pause distinctUntilChanged(), // skip duplicates filter(term => term.length > 2), // min 3 chars switchMap(term => // cancel previous this.http.get<string[]>(`/search?q=${term}`).pipe( catchError(() => of([])) // empty on error ) ) ); }

Polling with Auto-Stop

@Component({...}) export class StatusComponent { private http = inject(HttpClient); private destroyRef = inject(DestroyRef); status$ = timer(0, 30000).pipe( // immediate, repeat every 30s switchMap(() => this.http.get<Status>('/status')), retry({ count: 3, delay: 2000 }), takeUntilDestroyed(this.destroyRef) // auto-stop on destroy ); } // Template: <status [data]="status$ | async"/>

Chained Dependent Requests

// Get user, then fetch their orders using userId this.http.get<User>('/user/me').pipe( switchMap(user => this.http.get<Order[]>(`/orders/${user.id}`).pipe( map(orders => ({ user, orders })) // combine ) ) )

Loading / Error State

interface State<T> { data?: T; loading: boolean; error?: string } const state$: Observable<State<User>> = this.http.get<User>('/user').pipe( map(data => ({ data, loading: false })), startWith({ loading: true }), catchError(err => of({ loading: false, error: err.message })) );

The async Pipe — No Manual unsubscribe

// async pipe: subscribes + auto-unsubscribes on destroy // Also triggers change detection when OnPush @Component({ template: ` @if (users$ | async; as users) { <ul> @for (u of users; track u.id) { <li>{{ u.name }}</li> } </ul> } `, changeDetection: ChangeDetectionStrategy.OnPush }) export class UserListComponent { users$ = this.userSvc.getAll(); // NO subscribe, NO unsubscribe }
async pipe best practices:
• Use as alias: *ngIf="obs$ | async as data"
• OnPush + async pipe = optimal change detection
• Share one subscription with share() or shareReplay(1) if multiple | async in template
• In v17+: prefer signals + resource() over async pipe for new code
Don't subscribe inside components manually unless you need side effects. Each manual subscribe = a memory leak risk if not properly unsubscribed.
