Adapter & Facade — two ways to wrap

Chapter 7. Two patterns that both put a new front on existing code, for opposite reasons. Adapter changes an interface so a class fits where it otherwise couldn't (make a Turkey look like a Duck). Facade simplifies a messy subsystem behind one friendly call (one watchMovie() instead of twelve). Same shape, different intent.

🎯 What are Adapter and Facade — and what is the crucial difference between them?

Both patterns wrap existing code — but their intents differ completely. Adapter: converts the interface of a class into another interface the client expects. You have a Duck interface with quack() and fly(). You have a Turkey with gobble() and fly(short distance). You create a TurkeyAdapter implements Duck that wraps the turkey: quack() calls turkey.gobble(); fly() calls turkey.fly() five times to cover the same distance. Now anywhere code expects a Duck, you can pass a TurkeyAdapter — the client never knows. Facade: doesn't convert — it simplifies. A home-theatre has Amplifier, DVDPlayer, Projector, Screen, PopcornMaker — each with their own API. A HomeTheatreFacade provides watchMovie(movie) which calls all twelve setup calls in the right order. The subsystem classes still exist and can be used directly — the facade is just a simpler entry point. The key principle: Facade introduces the "Principle of Least Knowledge" (Law of Demeter) — only talk to your immediate friends, not to strangers through other objects: order.getCustomer().getAddress().getZip() is bad; ask only what you directly need.

Object vs Class Adapter

Object Adapter (composition): class TurkeyAdapter implements Duck { Turkey turkey; TurkeyAdapter(Turkey t) { this.turkey=t; } void quack() { turkey.gobble(); } }. Preferred — adapts any subclass of Turkey, not just one. Class Adapter (multiple inheritance): extends both Turkey and implements Duck — impossible in Java (only one superclass). Java uses Object Adapter exclusively. The Head First book uses the Turkey/Duck story to illustrate: any Turkey can be adapted; any new Turkey subclass (WildTurkey, ThaiTurkey) works through the same adapter without changes.

Adapter in Java stdlib

Arrays.asList(array): adapts an array to the List interface. Collections.list(enumeration): adapts old Enumeration to ArrayList. InputStreamReader(InputStream): adapts a byte stream to a character stream — converts the byte-oriented InputStream interface to the character-oriented Reader interface. ExecutorCompletionService: adapts Future results to a completion-order queue. Spring's HandlerAdapter: adapts different controller types (annotated, functional) to the DispatcherServlet's uniform handler interface. Adapters are everywhere in Java.

Facade in Spring Boot

JdbcTemplate is a Facade over raw JDBC: instead of Connection conn = ds.getConnection(); PreparedStatement ps = conn.prepareStatement(sql); ResultSet rs = ps.executeQuery(); while(rs.next()) { ... } rs.close(); ps.close(); conn.close() (7 steps, 3 try-catch-finally blocks), you write: jdbcTemplate.query(sql, rowMapper) — one call. The Facade handles connection acquisition, statement preparation, result mapping, and closing — all in one method. RestTemplate/RestClient: facade over HttpClient + request/response handling. @Service classes are often Facades over repositories and external services.

In CIAM / Spring Boot: Adapter: Ping returns user as PingUserResponse; Entra returns EntraUserResponse — both have different field names and structures. PingUserAdapter implements UserProvider maps PingUserResponse → UserDto. EntraUserAdapter implements UserProvider maps EntraUserResponse → UserDto. The rest of the app works with UserDto — it never sees Ping or Entra types. Adding Keycloak: write KeycloakUserAdapter. Nothing else changes. Facade: IdmFacade.provisionUser(CreateUserRequest) calls pingClient.createUser(), auditService.log(), notificationService.sendWelcome(), groupService.assignDefaultGroups() — one method hides 4 subsystem calls. Angular calls this one endpoint; it doesn't orchestrate subsystems directly.

The interface mismatch

Your code is written against Duck (quack(), fly()). You're handed a Turkey (gobble(), fly() — but only short hops). You can't change either class. The shapes don't line up.

interface Duck   { void quack(); void fly(); }
interface Turkey { void gobble(); void fly(); }  // short hops
duckGame.play(turkey);  // ✗ won't compile — a Turkey is not a Duck

The Turkey adapter

A TurkeyAdapter implements Duck (so it fits) and wraps a Turkey (so it can do the work), translating each Duck call into Turkey calls.

class TurkeyAdapter implements Duck {
  private Turkey turkey;                       // the adaptee
  TurkeyAdapter(Turkey t) { turkey = t; }
  public void quack() { turkey.gobble(); }       // translate
  public void fly() {
    for (int i=0; i<5; i++) turkey.fly();   // 5 hops ≈ 1 duck flight
  }
}
duckGame.play(new TurkeyAdapter(turkey));  // ✓ the client never knows

Q: Is this the same as Decorator? Both wrap an object.

A: Same structure, different intent. Decorator keeps the interface and adds behavior. Adapter changes the interface to a different one. The wrapping looks alike; what they're for is the opposite.

The Adapter Pattern, defined

The Adapter Pattern converts the interface of a class into another interface the client expects. Adapter lets classes work together that couldn't otherwise because of incompatible interfaces.

You've used it: Arrays.asList() adapts an array to a List; an Angular @Pipe adapts a model value to a display string; an InputStreamReader adapts a byte stream to a char stream.

Facade — the home theater

"Watch a movie" really means: dim the lights, drop the screen, turn on the projector in widescreen, power the amp, set it to surround, start the DVD. Six objects, a dozen calls. A Facade wraps the subsystem and offers one method.

class HomeTheaterFacade {
  void watchMovie(String movie) {
    lights.dim(10);  screen.down();
    projector.on();  projector.wideScreenMode();
    amp.on();  amp.setSurroundSound();  amp.setVolume(5);
    dvd.on();  dvd.play(movie);
  }
}
// the client:
homeTheater.watchMovie("Inception");  // one call, not twelve
Brain Power. A facade doesn't hide the subsystem — you can still reach the projector directly for advanced use. It just provides a simple default path for the common case. Adapter wraps one class to change its interface; Facade wraps many classes to simplify them.

The principle this chapter hands you

Design Principle — Least Knowledge (Law of Demeter)Talk only to your immediate friends.

A facade means the client talks to one object instead of reaching through six. Fewer objects you depend on = fewer things that can break you when they change. "Don't call methods on objects returned by other methods" (a.getB().getC().doThing()) — that train-wreck couples you to the whole chain.

The Facade Pattern, defined

The Facade Pattern provides a unified interface to a set of interfaces in a subsystem. Facade defines a higher-level interface that makes the subsystem easier to use.
The trio, side by side: Decorator = same interface, adds behavior. Adapter = converts one interface to another. Facade = one simple interface over many. All wrap — intent is everything. Next in the track: Template Method.

Adapter in the wild — Java & the framework layer

You've been using Adapter for years without naming it:

Java standard library

// Arrays.asList adapts T[] → List<T>
List<String> list = Arrays.asList("a", "b");
// InputStreamReader adapts byte stream → char stream
BufferedReader br = new BufferedReader(
  new InputStreamReader(socket.getInputStream()));
// Collections.enumeration adapts Iterator → Enumeration

Angular — @Pipe as Adapter

@Pipe({ name: 'currency' })
export class CurrencyPipe implements PipeTransform {
  transform(value: number): string {
    return '$' + value.toFixed(2);  // adapt number → display
  }
}
Object adapter vs class adapter. Head First uses an object adapter (HAS-A Turkey, wrapped via composition). A class adapter would extend both Duck and Turkey — fine in C++, but Java doesn't allow extending two classes. In Java, always object adapter. In TypeScript you can implement multiple interfaces, but convention is still composition.

Facade in Spring MVC — @Service as a Facade

A Spring @Service often plays the Facade role: the controller calls one method, which coordinates repositories, event publishing, and downstream APIs — exactly what watchMovie() does for the home theater subsystems.

@Service
public class UserOnboardingService {   // the Facade
  public void register(UserDto dto) {
    User user = userRepo.save(new User(dto));    // subsystem 1
    emailService.sendWelcome(user);               // subsystem 2
    auditLog.record("REGISTERED", user.getId());  // subsystem 3
    eventBus.publish(new UserRegisteredEvent(user)); // subsystem 4
  }
}
// Controller calls ONE method — not four subsystems

The controller depends on one class instead of four. When the onboarding process changes (add a welcome SMS, update the audit format), only the service method changes — the controller and the subsystems don't.
