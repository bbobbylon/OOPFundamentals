The interceptor pipeline

Every request from HttpClient goes through a chain of interceptors before hitting the network, and every response comes back through the chain in reverse. Interceptors are how you add auth tokens, log requests, cache responses, and handle errors globally — without touching the call site.

1. The basics — HttpClient

Inject HttpClient, call get / post / put / delete — you get back an Observable. Always subscribe (or use the async pipe).

// app.config.ts — register HttpClient at the app root
import { provideHttpClient } from '@angular/common/http';

export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient()                          // modern standalone API (v15+)
  ]
};
// user.service.ts
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

interface User { id: number; name: string; email: string; }

@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);
  private base = '/api/users';

  // Type the response — HttpClient is generic
  getAll(): Observable<User[]> {
    return this.http.get<User[]>(this.base);
  }

  getOne(id: number): Observable<User> {
    return this.http.get<User>(`${this.base}/${id}`);
  }

  create(user: Partial<User>): Observable<User> {
    return this.http.post<User>(this.base, user);   // 2nd arg = body, auto-JSON
  }

  update(id: number, user: Partial<User>): Observable<User> {
    return this.http.put<User>(`${this.base}/${id}`, user);
  }

  remove(id: number): Observable<void> {
    return this.http.delete<void>(`${this.base}/${id}`);
  }
}
// Calling from a component — three ways

// 1) Subscribe manually (verbose, must unsubscribe)
this.userService.getAll().subscribe(users => this.users = users);

// 2) async pipe in template (recommended — auto-unsubscribes)
users$ = this.userService.getAll();
// template: @for (u of users$ | async; track u.id) { ... }

// 3) Signals (v16+) — convert Observable to signal
import { toSignal } from '@angular/core/rxjs-interop';
users = toSignal(this.userService.getAll(), { initialValue: [] });
// template: @for (u of users(); track u.id) { ... }

2. Query params & custom headers

import { HttpParams, HttpHeaders } from '@angular/common/http';

search(q: string, page: number) {
  // HttpParams is IMMUTABLE — each .set() returns a new instance
  const params = new HttpParams()
    .set('q', q)
    .set('page', page);
  // → ?q=foo&page=2 (auto-URL-encoded)

  const headers = new HttpHeaders({
    'X-Trace-Id': crypto.randomUUID(),
    'Accept-Language': 'en-US'
  });

  return this.http.get<SearchResult>('/api/search', { params, headers });
}

// Shortcut: pass params/headers as plain objects (v15+)
this.http.get('/api/search', { params: { q, page } });

3. Interceptors — functional (v15+, modern)

Interceptors are functions (req, next) => next(req). They can:

  • Modify the request before it leaves (add headers, change URL)
  • Short-circuit it (return a cached response without hitting the network)
  • Tap the response (logging, analytics)
  • Handle errors (retry, redirect to login, show a toast)
// auth.interceptor.ts
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth = inject(AuthService);
  const token = auth.getToken();

  // Skip for login endpoint, or for public routes
  if (!token || req.url.includes('/auth/login')) {
    return next(req);
  }

  // Clone the request — requests are immutable
  const authReq = req.clone({
    setHeaders: { Authorization: `Bearer ${token}` }
  });
  return next(authReq);
};
// logging.interceptor.ts — tap on response, time the request
import { tap, finalize } from 'rxjs';

export const loggingInterceptor: HttpInterceptorFn = (req, next) => {
  const start = performance.now();
  console.log(`→ ${req.method} ${req.url}`);

  return next(req).pipe(
    finalize(() => {
      const ms = (performance.now() - start).toFixed(0);
      console.log(`← ${req.method} ${req.url} (${ms}ms)`);
    })
  );
};
// cache.interceptor.ts — return cached response for GETs
import { HttpResponse } from '@angular/common/http';
import { of, tap } from 'rxjs';

const cache = new Map<string, HttpResponse<any>>();

export const cacheInterceptor: HttpInterceptorFn = (req, next) => {
  if (req.method !== 'GET') return next(req);   // only cache GETs

  const cached = cache.get(req.urlWithParams);
  if (cached) return of(cached.clone());        // short-circuit!

  return next(req).pipe(
    tap(event => {
      if (event instanceof HttpResponse) {
        cache.set(req.urlWithParams, event.clone());
      }
    })
  );
};
// error.interceptor.ts — retry on 5xx, redirect to login on 401
import { catchError, retry, throwError, timer } from 'rxjs';
import { HttpErrorResponse } from '@angular/common/http';

export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const router = inject(Router);
  const toast  = inject(ToastService);

  return next(req).pipe(
    retry({
      count: 3,
      delay: (err, retryCount) => {
        // Only retry network/5xx, exponential backoff
        if (err.status >= 500 || err.status === 0) {
          return timer(Math.pow(2, retryCount) * 300);
        }
        return throwError(() => err);
      }
    }),
    catchError((err: HttpErrorResponse) => {
      if (err.status === 401) router.navigate(['/login']);
      else if (err.status === 403) toast.error('Forbidden');
      else toast.error(`Error ${err.status}: ${err.message}`);
      return throwError(() => err);                // re-throw so component can react
    })
  );
};
// Register them — ORDER MATTERS. Outer interceptors wrap inner ones.
// Request flows top → bottom. Response flows bottom → top.
import { provideHttpClient, withInterceptors } from '@angular/common/http';

provideHttpClient(
  withInterceptors([
    authInterceptor,      // 1st: add token
    loggingInterceptor,   // 2nd: log timing (sees the auth'd request)
    cacheInterceptor,     // 3rd: check cache
    errorInterceptor      // last: retry / catch (closest to network)
  ])
)
Order tip: put auth early (so all subsequent interceptors see the token) and error/retry last (so retries get a fresh token each attempt). Cache should usually sit between auth and error.

4. Class-based interceptors (legacy, pre-v15)

You'll still see these in older codebases. Same logic, more boilerplate.

@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  intercept(req: HttpRequest<any>, next: HttpHandler) {
    // same as functional, but `this` is a class instance
    return next.handle(req.clone({ /* ... */ }));
  }
}

// register via DI multi-provider:
{ provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }

For new code, use functional. For old code, leave it alone — both work side-by-side via withInterceptorsFromDi().

5. Common patterns

Loading spinner

An interceptor increments a counter on request start, decrements on end. A signal exposes isLoading; a global spinner reads it.

Request deduplication

If three components ask for the same URL in the same tick, share one HTTP call. Use shareReplay(1) in your service.

Stale-while-revalidate

Return cached value immediately, then fetch fresh in the background and update. Pair with a BehaviorSubject.

Cancellation

Use switchMap on user input — when a new value arrives, the in-flight request is auto-cancelled.

Optimistic updates

Update local state immediately, fire the request, roll back on error. Pairs nicely with NgRx + Effects.

File uploads

Use FormData as the body; subscribe with reportProgress: true + observe: 'events' for upload progress.

7. HttpContext — talk to interceptors per-request

Sometimes one request needs different interceptor behavior (skip auth, skip cache, etc.). Use HttpContextToken.

// tokens.ts
export const SKIP_AUTH = new HttpContextToken<boolean>(() => false);
export const CACHE_TTL_MS = new HttpContextToken<number>(() => 60000);

// auth.interceptor.ts
if (req.context.get(SKIP_AUTH)) return next(req);

// caller — opt out of auth for this one call
this.http.get('/api/public', {
  context: new HttpContext().set(SKIP_AUTH, true)
});

Anti-patterns

❌ Don't✅ Do
Mutate req directlyreq.clone({ ... }) — requests are immutable
Forget to subscribeObservables are cold — nothing fires until subscribed (or piped through | async)
Subscribe in template + serviceOne source of truth — users$ in service, | async in template
Catch errors only at call siteUse an error interceptor for global handling (toasts, redirects); catch locally only for component-specific recovery
Put business logic in interceptorsInterceptors are cross-cutting (auth, log, cache). Business logic belongs in services.
Forget to unsubscribeUse | async, toSignal, or takeUntilDestroyed() (v16+)
The mental model: HttpClient is just an Observable factory. Interceptors are a pipeline of (req, next) => Observable<event> functions wrapped around it. Auth, logging, cache, retry, error mapping — all live in interceptors so your services stay clean.

8. Error handling — retry, global interceptor, typed errors

Retry with exponential backoff

import { retry, timer } from 'rxjs';

// Retry up to 3 times, delay 1s/2s/4s
this.http.get<User[]>('/api/users').pipe(
  retry({
    count: 3,
    delay: (err, attempt) =>
      timer(Math.pow(2, attempt) * 1000)
  })
).subscribe(...);

// In an interceptor: retry transient errors only
return next(req).pipe(
  retry({
    count: 2,
    delay: (err) => {
      if (err instanceof HttpErrorResponse
          && err.status >= 500) {
        return timer(1000); // retry server errors
      }
      throw err; // don't retry 4xx
    }
  })
);

Global error interceptor — toasts + 401 redirect

export const errorInterceptor: HttpInterceptorFn =
  (req, next) =>
    next(req).pipe(
      catchError((err: HttpErrorResponse) => {
        const toast = inject(ToastService);
        const router = inject(Router);

        switch (err.status) {
          case 0:
            toast.error('Network error'); break;
          case 401:
            // token expired — silent refresh handles it
            // or redirect if refresh also fails
            router.navigate(['/login']); break;
          case 403:
            toast.error('Permission denied'); break;
          case 503:
            toast.error('Service unavailable'); break;
          default:
            toast.error(err.message);
        }
        return throwError(() => err);
      })
    );
Rule: Handle component-specific recovery (show an empty state, hide a spinner) at the call site with catchError. Handle cross-cutting responses (toast, redirect, logging) in the error interceptor. Don't duplicate both.

9. CIAM bearer token interceptor — full implementation

In a CIAM app (Ping / Entra) the one job of an HTTP interceptor is to attach the access token as a Bearer header to every protected API call, skip it for public routes, and kick off silent refresh when the token is expired. The functional interceptor pattern makes this clean:

// auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth   = inject(AuthService);
  const skipAuth = req.context.get(SKIP_AUTH); // public endpoints opt out

  if (skipAuth || !req.url.startsWith('/api')) {
    return next(req);         // public route — no token
  }

  const token = auth.getAccessToken(); // reads from memory/cookie

  if (auth.isTokenExpired(token)) {
    // token expired — refresh first, then retry with new token
    return auth.refreshTokens().pipe(
      switchMap(newToken => next(addBearer(req, newToken))),
      catchError(() => {
        auth.logout();                  // refresh failed → force login
        return throwError(() => new Error('Session expired'));
      })
    );
  }

  return next(addBearer(req, token));
};

// helper — clone request with Authorization header (requests are immutable)
function addBearer(req: HttpRequest<unknown>, token: string) {
  return req.clone({
    setHeaders: { Authorization: `Bearer ${token}` }
  });
}

// register it (app.config.ts)
provideHttpClient(withInterceptors([authInterceptor, errorInterceptor]))
Security note: The interceptor attaches the token to /api/* calls. Verify the path prefix matches your API base URL — never send the Bearer header to third-party URLs or CDN calls (the token would leak). Use HttpContextToken for precise opt-in/opt-out on individual requests.

10. httpResource() — Angular 19 signal-based HTTP

httpResource() is Angular 19's signal-native HTTP primitive. It wraps an HTTP GET into a Resource — a signal that carries value(), isLoading(), error(), and status() — no subscribe(), no async pipe needed.

Basic usage

import { httpResource } from '@angular/core';

export class UserListComponent {
  // GET /api/users — auto-fetches on init
  users = httpResource<User[]>(
    '/api/users'
  );
}

<!-- template -->
@if (users.isLoading()) { <app-spinner/> }
@if (users.error()) { <p>Error loading</p> }
@for (u of users.value() ?? []; track u.id) {
  <li>{{ u.name }}</li>
}

Reactive URL — refetches when signal changes

export class UserDetailComponent {
  // route param as signal (withComponentInputBinding)
  id = input.required<string>();

  // re-fetches whenever id() changes
  user = httpResource<User>(() =>
    `/api/users/${this.id()}`
  );

  // derived signal from the resource
  displayName = computed(() =>
    this.user.value()?.name ?? 'Loading…'
  );
}

// Status values: 'idle'|'loading'|
//               'refreshing'|'resolved'|'error'
if (user.status() === 'resolved') { ... }
When to use httpResource() vs HttpClient directly: Use httpResource() for "load data, display it, re-load when params change" — the 80% case. Use HttpClient directly when you need POST/PUT/DELETE, cancellation with switchMap, retry logic, or file upload progress.

🌱 New to this? Talking to a server in three lines.

To get data from a backend, you inject(HttpClient) and call http.get('/api/users'). The catch for newcomers: it doesn't return the data directly — it returns an Observable, because the response arrives later, over the network. You subscribe to receive it (or, in a template, use the async pipe and Angular subscribes for you). The HTTP verbs map straight across: get reads, post creates, put/patch update, delete removes. So the whole basics: pick the verb, call it, and handle the result when it arrives.

🧠 Expert corner — cold requests, interceptors, and typed responses

  • HttpClient Observables are cold. Nothing happens until you subscribe — and subscribing twice fires the request twice. The async pipe subscribes once; shareReplay caches a shared result.
  • Interceptors are the cross-cutting layer. Register functional interceptors with withInterceptors([...]) to attach the auth header, retry, log, or transform errors for every request in one place. This is where the bearer token gets added — not in each call.
  • Type your responses. http.get<User[]>('/api/users') flows the type through; pair it with an OpenAPI-generated client so the contract can't drift.
  • HttpParams/HttpHeaders are immutable — .set() returns a new instance; assign it back.
  • Errors arrive as HttpErrorResponse on the error channel — handle with catchError; switchMap gives you free cancellation of stale requests (type-ahead). For load-and-display, httpResource() (v19+) wraps it declaratively as a signal.
  • CIAM tie-in. An auth interceptor adds Authorization: Bearer … and, on a 401, kicks off a silent refresh and retries the request. See HTTP Interceptors, Error Handling, and Tokens & Refresh.
