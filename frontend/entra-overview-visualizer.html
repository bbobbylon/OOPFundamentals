Microsoft Entra ID Overview

The identity platform behind Microsoft 365, Azure, and thousands of enterprise apps — formerly known as Azure Active Directory (Azure AD).

1 — Core Concepts

Click each concept to expand the full explanation:

Tenant

One organization's isolated directory
A tenant is a dedicated, isolated instance of Entra ID for one organization. Your company "Acme Corp" has exactly one tenant. Each tenant has a globally unique Tenant ID (a GUID like a1b2c3d4-...). Even if two companies use Entra ID, they are completely isolated from each other.

Directory

Container of identities and registrations
The directory inside your tenant holds all your users, groups, app registrations, and service principals. Think of it as a database of everything identity-related in your organization. One tenant = one directory.

User

A person's identity in the directory
A user object has: userPrincipalName (like an email: bob@company.com), objectId (unique GUID), display name, group memberships, MFA methods, and account status. Users can be Members (your employees) or Guests (from another tenant — B2B collaboration).

Group

Collection of users for permission assignment
Groups let you assign permissions to many users at once. Two types: Security groups (control access to resources), Microsoft 365 groups (collaboration: shared mailbox, Teams, SharePoint). Add a user to a group → they inherit all its permissions.

Service Principal

An application's identity in the directory
When an application (not a human) needs to authenticate to Entra ID or access resources, it needs a service principal — the app's identity object in the directory. Created automatically when you register an app or when an Enterprise App is added.

Managed Identity

Auto-managed credentials for Azure resources
Azure resources (VMs, App Services, Functions) can have a System-Assigned Managed Identity. Azure manages the credential automatically — no secrets to store, rotate, or leak. The resource authenticates to Entra ID using its managed identity. Always prefer this over client secrets for Azure-hosted apps.

2 — Entra ID vs Traditional Active Directory

Many companies run BOTH — using Azure AD Connect (now Entra Connect) to sync on-prem users to the cloud:

ℹ️ Hybrid Identity: Most enterprises sync AD → Entra ID using Entra Connect Sync. Employees log in to Windows with their AD credentials, and those same credentials work for Microsoft 365 and your web apps via Entra ID.

3 — Key Services Within Entra

Entra ID (core)

User/group directory, app registrations, single sign-on for SaaS apps, B2B guest access.

formerly Azure AD

Conditional Access

If user is on an unmanaged device AND accessing sensitive data → require MFA. Policy-based access control on every sign-in.

Zero Trust gateway

Entra ID Protection

AI-powered risk signals. Detects leaked credentials, impossible travel, atypical sign-in locations. Can auto-block risky sign-ins.

risk-based auth

External ID

Customer identity (B2C): let users sign in with Google, Facebook, or local accounts. Also B2B for partner access.

formerly Azure AD B2C

Privileged Identity Management

Time-limited admin role activation. "I need Global Admin for 2 hours." Requires justification + approval. Full audit trail.

PIM · just-in-time

Microsoft Graph

REST API to read/write directory data: users, groups, calendar, mail, Teams. One API to rule them all.

graph.microsoft.com

Key insight: Entra ID never touches your database or your API directly. It issues JWT tokens. Your Angular app passes the token to your Spring Boot API. Spring Boot validates the token's signature using Entra ID's public keys (JWKS endpoint) — no network call to Entra required at request time.
