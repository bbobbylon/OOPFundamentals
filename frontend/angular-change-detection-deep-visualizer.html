Angular Change Detection — Internals

What actually happens when "something changes": Zone.js, the component tree, OnPush pruning, and how signals make it surgical. Flip strategies and fire triggers to watch the dirty-checking walk the tree.

🔄 Deep dive: what triggers a change-detection cycle — and what happens during one?

A "change-detection cycle" is Angular's pass through the component tree, comparing each bound value to its previous value and patching the DOM where they differ. Two questions define it: what triggers the cycle, and which components are visited? Zone.js is the trigger — it intercepts async operations and notifies Angular after each. The top-down, depth-first tree walk is the mechanism — every component, unless pruned. OnPush pruning and signals are the two escape hatches that cut the work per cycle.

  • Trigger: Zone.js patches async APIs and calls ApplicationRef.tick() when one completes — one event = one tree walk.
  • Mechanism: a top-down, depth-first walk checking each component's bindings against their previous values.
  • OnPush prunes: a clean OnPush component (and its subtree) is skipped unless an input ref changed, an event fired, an async pipe emitted, or markForCheck() ran.
  • Signals skip the walk entirely — a set() marks only the components that read that signal dirty.
  • OnPush's dirty check is reference equality, so you must replace objects/arrays, not mutate them.

How Zone.js triggers CD

Zone.js wraps setTimeout, addEventListener, fetch, Promise.then, XHR. When one completes it calls ApplicationRef.tick() → a top-down tree walk. 10 responses/second = 10 walks/second.

OnPush pruning explained

During the walk Angular checks if each component is "dirty." An OnPush component starts clean and is skipped (with its subtree) unless an input reference changed, an event fired inside it, an async pipe emitted, or markForCheck() was called. A 500-component tree might check only ~15.

Signal-based reactivity

Signals bypass the walk: the compiler tracks which template reads which signal, so user.set(v) marks only those components dirty and schedules a targeted update — no Zone.js, no tree walk. The architecture of Angular's future.

Key gotcha — mutation vs replacement:this.users.push(newUser) with OnPush does not trigger CD — the array reference is unchanged (OnPush checks newRef !== oldRef). You must replace: this.users = [...this.users, newUser], or with signals this.users.update(arr => [...arr, newUser]) which notifies automatically.

1. The 30-second mental model

Angular doesn't have magic data-watchers. It does dirty checking: periodically it walks the component tree top-down and, for each component, re-evaluates the template expressions and compares each to its previous value. If a bound value changed, it updates that piece of the DOM. The only real questions are when does this walk run, and which components does it bother to check.

When? → Zone.js notices async events (clicks, timers, XHR) and triggers a check Which? → strategy (Default vs OnPush vs signals) decides which subtrees to skip

2. Step 1 — "When": Zone.js is the alarm bell

Zone.js monkey-patches async APIs

At startup Angular (with zone.js) replaces the browser's async functions with wrapped versions. When any of them fires, Zone tells Angular "an async task finished — you should probably check for changes."

// conceptually, zone.js does this to ~40 APIs:
const realSetTimeout = window.setTimeout;
window.setTimeout = (cb, ms) => {
  return realSetTimeout(() => {
    cb();              // your callback runs…
    ngZone.onMicrotaskEmpty();  // …then Angular checks
  }, ms);
};

Patched: addEventListener, setTimeout/Interval, Promise, fetch/XHR, requestAnimationFrame, and more. That's why you almost never call change detection yourself.

One "tick" = one full top-down pass

When the zone goes stable (all microtasks drained), Angular runs ApplicationRef.tick() — it starts at the root component and walks down, checking each component once.

tick() {
  for (const root of this.rootViews)
    detectChanges(root); // walks the whole tree
}

The cost: with the Default strategy, every component is checked on every tick — even a click in one corner re-checks the whole app. Usually fine; sometimes a perf problem. That's the problem OnPush and signals solve.

Zoneless (v18+): you can drop zone.js entirely and let signals schedule ticks instead. Same tree walk, different alarm bell.

4. The four things that mark an OnPush component dirty

An OnPush component is skipped on a tick unless one of these happened since the last check. Memorize this list — it's the whole game (and the #1 Angular interview question):

#TriggerWhy it works
1An @Input() reference changedAngular compares inputs by ===. A new object/array reference marks the child dirty. Mutating the same reference does not.
2A DOM event fired in the component (or a child)The event handler ran "inside" it, so Angular marks it + the path to root dirty.
3cdr.markForCheck() was calledManually marks this view + ancestors dirty. The async pipe calls this for you on every emission.
4A signal() read in its template changedv17+. The component subscribes to exactly the signals it reads; a change marks just those consumers dirty — no input plumbing needed.

Notice what's missing: a plain property reassignment (this.count++) from a callback Zone doesn't track, or an in-place mutation, will not refresh an OnPush view. That's the trade-off you accept for the speed.

5. markForCheck() vs detectChanges() — don't confuse them

markForCheck() — "check me next tick"

Does not run change detection now. It just flips dirty flags on this view and every ancestor up to the root, so that the next scheduled tick won't prune this branch. Cheap, safe, the common one.

constructor(private cdr: ChangeDetectorRef) {}

ngOnInit() {
  this.feed.onMessage(m => {
    this.messages.push(m);
    this.cdr.markForCheck(); // refresh on next tick
  });
}

detectChanges() — "check me & my children NOW"

Synchronously runs CD on this view and its subtree, right now. Heavier, and easy to misuse (can throw ExpressionChangedAfterItHasBeenChecked in dev). Reach for it only for detached views or imperative redraws.

// detach from the tree, drive CD by hand
this.cdr.detach();
setInterval(() => {
  this.updateChart();
  this.cdr.detectChanges(); // only this subtree
}, 16);

Use detach() + detectChanges() for high-frequency widgets (charts, tickers) so the rest of the app isn't checked 60×/sec.

8. One-sentence recap

⏰ Zone.js notices async work and fires a tick; the tick walks the component tree from the root and dirty-checks each component's template bindings — Default checks everything, OnPush prunes any subtree that wasn't marked dirty (new input ref / inner event / markForCheck / changed signal), and signals let Angular mark only the exact components that read the changed value — which is what makes zoneless possible.
