SQL Fundamentals

SELECT, WHERE, JOIN, GROUP BY — the building blocks of every database query.

What is SQL — and why does every backend developer need to master it?

SQL (Structured Query Language) is the language used to communicate with relational databases. Every web application — from your CIAM auth service to the world's largest financial systems — stores its persistent data in tables and retrieves it with SQL. SQL has been standardized since 1986 and runs on PostgreSQL, MySQL, Oracle, SQL Server, SQLite, and dozens more. The basics are transferable across all of them. Relational model: data is organized into tables (named collections of rows and columns). Tables relate to each other through foreign keys — a users table has a primary key id; an orders table has a user_id foreign key pointing back to users.id. SELECT: the most-used statement. Choose which columns to return, from which table, with which filters. SELECT email, created_at FROM users WHERE active = true AND created_at > '2024-01-01'. WHERE: filters rows. AND, OR, NOT, IN, LIKE, BETWEEN, IS NULL, IS NOT NULL. JOIN: combines rows from two or more tables. INNER JOIN = only rows matching in BOTH tables. LEFT JOIN = all rows from left table, NULLs where right table has no match. RIGHT JOIN = opposite. FULL OUTER JOIN = all rows from both. GROUP BY: collapses multiple rows into one summary row per group. Always paired with aggregate functions: COUNT(), SUM(), AVG(), MAX(), MIN(). HAVING: filters AFTER grouping (WHERE filters before grouping). ORDER BY: sorts results. ORDER BY created_at DESC LIMIT 20. DML vs DDL: DML (Data Manipulation: SELECT/INSERT/UPDATE/DELETE), DDL (Data Definition: CREATE TABLE/ALTER TABLE/DROP TABLE).

SELECT + WHERE + JOIN

-- Users with their roles (INNER JOIN): SELECT u.id, u.email, r.role_name FROM users u INNER JOIN user_roles ur ON u.id = ur.user_id INNER JOIN roles r ON ur.role_id = r.id WHERE u.active = true AND r.role_name LIKE 'CIAM_%' ORDER BY u.created_at DESC LIMIT 50; -- All users + their last login (LEFT JOIN): SELECT u.email, MAX(s.created_at) AS last_login FROM users u LEFT JOIN sessions s ON u.id = s.user_id GROUP BY u.id, u.email HAVING MAX(s.created_at) < NOW() - INTERVAL '90 days' OR MAX(s.created_at) IS NULL -- never logged in ORDER BY last_login NULLS LAST;

GROUP BY + aggregates

-- Login attempts per user per day: SELECT user_id, DATE(created_at) AS login_date, COUNT(*) AS attempts, COUNT(*) FILTER (WHERE success = false) AS failures FROM login_events WHERE created_at > NOW() - INTERVAL '7 days' GROUP BY user_id, DATE(created_at) HAVING COUNT(*) FILTER (WHERE success = false) > 5 ORDER BY failures DESC; -- INSERT / UPDATE / DELETE: INSERT INTO users (email, idp_type, created_at) VALUES ('bob@eg.com', 'PING', NOW()); UPDATE users SET active = false WHERE last_login < NOW() - INTERVAL '180 days'; DELETE FROM sessions WHERE expires_at < NOW() RETURNING id;

Spring Boot + JPA mapping

SQL concept → Spring/JPA equivalent. SELECT * FROM users WHERE id = ? → userRepository.findById(id) (JPA generates the SQL). JOIN user_roles ON users.id = user_roles.user_id → @ManyToMany relationship in entity: @ManyToMany(fetch = LAZY) @JoinTable(name = "user_roles", joinColumns = @JoinColumn(name = "user_id"), inverseJoinColumns = @JoinColumn(name = "role_id")) List<Role> roles;. GROUP BY + COUNT() → @Query("SELECT u.idpType, COUNT(u) FROM User u GROUP BY u.idpType") List<Object[]> countByIdpType();. WHERE active = true AND last_login > ? → Spring Data JPA derived query: findByActiveTrueAndLastLoginAfter(LocalDateTime date). SQL is what JPA generates — understanding SQL is essential for debugging N+1 queries, performance tuning, and writing custom @Query JPQL or native SQL when JPA auto-generation isn't efficient enough.

In your CIAM database: Core CIAM tables: users (id, email, idp_type, external_id, active, created_at, last_login), roles (id, role_name, description), user_roles (user_id, role_id, assigned_at, assigned_by), sessions (id, user_id, token_hash, expires_at, created_at), audit_events (id, user_id, event_type, ip_address, created_at, metadata JSONB). Key queries: "which users have CIAM_ADMIN role?" = JOIN users → user_roles → roles with WHERE. "How many users registered per IDP this month?" = GROUP BY idp_type with COUNT(). "Who has sessions expiring in the next hour?" = WHERE expires_at BETWEEN NOW() AND NOW() + INTERVAL '1 hour'. "Inactive users to soft-delete?" = LEFT JOIN sessions and HAVING last session > 180 days ago. Spring's JPA handles CRUD, but you'll write native SQL for reporting and bulk operations.

2 — JOIN Types






JOIN typeReturnsUse case


INNER JOINRows that match in both tablesUsers with at least one order


LEFT JOINAll left rows + matching right (NULLs for no match)Users with or without orders


RIGHT JOINAll right rows + matching left (NULLs for no match)Rarely used — flip to LEFT JOIN instead


FULL OUTER JOINAll rows from both tablesReconciliation — find mismatches


CROSS JOINCartesian product (every row × every row)Generating combinations




SELECT u.email, COUNT(o.id) AS order_count
FROM   users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE  u.active = true
GROUP BY u.id, u.email
ORDER BY order_count DESC;









3 — GROUP BY & Aggregates




SELECT
  DATE_TRUNC('month', created_at) AS month,
  COUNT(*)                         AS total_orders,
  SUM(amount)                      AS revenue,
  AVG(amount)                      AS avg_order
FROM  orders
WHERE status = 'completed'
GROUP BY 1
HAVING COUNT(*) > 100    -- HAVING filters AFTER grouping
ORDER BY month DESC;


WHERE vs HAVING: WHERE filters individual rows BEFORE grouping; HAVING filters groups AFTER aggregation. You can only use aggregate functions (COUNT, SUM, AVG, MAX, MIN) in HAVING, not WHERE.









4 — NULL Handling




NULL means "unknown" — it is NOT zero, empty string, or false. NULL comparisons with = return NULL (unknown), not TRUE or FALSE. Always use IS NULL / IS NOT NULL.


-- These return 0 rows (NULL != 'US' is NULL, not TRUE)
SELECT * FROM users WHERE country != 'US';

-- Include NULLs explicitly:
SELECT * FROM users
WHERE country != 'US' OR country IS NULL;

-- COALESCE: return first non-NULL value
SELECT COALESCE(display_name, email, 'Anonymous') AS name
FROM  users;

-- COUNT(*) counts ALL rows; COUNT(col) skips NULLs
SELECT COUNT(*), COUNT(phone) FROM users;
