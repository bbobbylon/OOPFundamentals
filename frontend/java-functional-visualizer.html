Functional Interfaces & Lambdas

Write concise, expressive code: lambdas, method references, closures, and the standard functional interface toolbox.

What is a lambda — and how is it different from an anonymous class?

Before Java 8, passing behaviour required an anonymous class: button.addListener(new ActionListener() { public void actionPerformed(ActionEvent e) { doSomething(); } }). A lambda is a concise syntax for the same thing: button.addListener(e -> doSomething()). A lambda is an instance of a functional interface — any interface with exactly one abstract method. The compiler infers which method to implement from the target type. Standard functional interfaces in java.util.function: Predicate<T> (T -> boolean), Function<T,R> (T -> R), Consumer<T> (T -> void), Supplier<T> (() -> T), BiFunction<T,U,R> ((T,U) -> R). A method reference is a shorthand for a lambda that just calls a method: User::getName is u -> u.getName(). Closures: lambdas can capture variables from the enclosing scope, but those variables must be effectively final (not reassigned after capture) — this is a thread-safety constraint.

Lambda syntax forms

No params: () -> "hello". One param (no parens needed): x -> x * 2. Multiple params: (a, b) -> a + b. Block body with return: (x, y) -> { int sum = x + y; return sum; }. Method references — 4 forms: System.out::println (instance method of specific object), String::toUpperCase (instance method of arbitrary object), Integer::parseInt (static method), ArrayList::new (constructor). Type inference: List.of("a","b").stream().map(String::toUpperCase) — compiler infers the method reference matches Function<String,String>.

Function composition

Function<T,R> has andThen(Function after) and compose(Function before): Function<String,String> trim = String::trim; Function<String,String> upper = String::toUpperCase; Function<String,String> clean = trim.andThen(upper). Predicate: isActive.and(hasEmail).or(isAdmin).negate(). Consumer: logUser.andThen(saveUser) — both consumers called in sequence. This composability lets you build pipelines from tiny named functions instead of writing everything inline.

Custom @FunctionalInterface

@FunctionalInterface interface ThrowingSupplier<T> { T get() throws Exception; }. The @FunctionalInterface annotation causes a compile error if you accidentally add a second abstract method. Useful when the standard interfaces don't fit (e.g., you need to throw checked exceptions). @FunctionalInterface interface TriFunction<A,B,C,R> { R apply(A a, B b, C c); } for 3-parameter lambdas. Spring's @Lazy and many Spring Boot auto-config features rely on functional-interface callbacks internally.

In CIAM / Spring Boot: Spring Security's lambda DSL: http.authorizeHttpRequests(auth -> auth.requestMatchers("/api/admin/**").hasRole("ADMIN").anyRequest().authenticated()). Comparators for sorting users: users.sort(Comparator.comparing(User::getLastName).thenComparing(User::getFirstName)). Angular's canMatch guard: canMatch: [() -> inject(AuthStore).hasRole('ADMIN')] — in Java, the equivalent Spring Security: http.requestMatchers(req -> req.getHeader("X-Admin-Token") != null). MapStruct custom mappings accept method references: @Mapping(target="name", source="displayName").

What is a Functional Interface?

// A functional interface has exactly ONE abstract method // Can have default/static methods (many, that's fine) // @FunctionalInterface annotation — optional but recommended @FunctionalInterface interface Transformer<T, R> { R transform(T input); // single abstract method default Transformer<T,R> andLog() { ... } // ok — default static Transformer<String,String> identity() { return x -> x; } // ok } // Usage with lambda Transformer<String, Integer> len = s -> s.length(); int result = len.transform("hello"); // 5
Why does this matter? Any place that accepts a functional interface type can receive a lambda or method reference. This is the foundation of the entire Streams API, Collections.sort(), CompletableFuture, and much more.

Lambda Syntax — evolution from anonymous class to arrow

Anonymous Class (pre-Java 8)
Comparator<String> comp = new Comparator<String>() { @Override public int compare(String a, String b) { return a.compareTo(b); } };
Lambda — full form
Comparator<String> comp = (String a, String b) -> { return a.compareTo(b); };
Lambda — types inferred
Comparator<String> comp = (a, b) -> { return a.compareTo(b); };
Lambda — expression body (single expression: no braces or return)
Comparator<String> comp = (a, b) -> a.compareTo(b);
Method reference — cleaner still
Comparator<String> comp = String::compareTo;

Lambda Forms — all the variations

// No parameters Runnable r = () -> System.out.println("hello"); // One parameter (parens optional for single untyped param) Consumer<String> print = s -> System.out.println(s); Consumer<String> print2 = (s) -> System.out.println(s); // same Consumer<String> print3 = (String s) -> System.out.println(s); // explicit type // Multiple parameters BiFunction<Integer,Integer,Integer> add = (a, b) -> a + b; // Multi-statement block body Function<String, String> fmt = s -> { if (s == null) return "null"; String trimmed = s.trim(); return trimmed.toUpperCase(); }; // Returning a lambda from a method Predicate<String> longerThan(int n) { return s -> s.length() > n; // closes over n }

java.util.function — the built-in functional interfaces

Function<T, R>
R apply(T t)
Transform input → output. The most common.
Function<String, Integer> len = String::length; // "hello" → 5
BiFunction<T, U, R>
R apply(T t, U u)
Two inputs → one output.
BiFunction<String, Integer, String> rep = String::repeat;
Predicate<T>
boolean test(T t)
Test input → boolean. Used for filtering.
Predicate<String> isEmpty = String::isEmpty; // "" → true
BiPredicate<T, U>
boolean test(T t, U u)
Two inputs → boolean.
BiPredicate<String, String> contains = String::contains;
Consumer<T>
void accept(T t)
Input → side effect, no return. Used in forEach.
Consumer<String> print = System.out::println;
BiConsumer<T, U>
void accept(T t, U u)
Two inputs → side effect.
BiConsumer<String, Integer> log = (msg, lvl) -> logger.log(lvl, msg);
Supplier<T>
T get()
No input → produces a value. Lazy initialization.
Supplier<List<String>> newList = ArrayList::new;
UnaryOperator<T>
T apply(T t) — extends Function<T,T>
Input and output same type.
UnaryOperator<String> upper = String::toUpperCase;
BinaryOperator<T>
T apply(T t, T u) — extends BiFunction<T,T,T>
Two same-type inputs → same type output. Used in reduce.
BinaryOperator<Integer> sum = Integer::sum;
Runnable
void run()
No input, no output. Thread tasks, scheduled jobs.
Runnable task = () -> processQueue();
Callable<V>
V call() throws Exception
Like Runnable but returns a value and can throw.
Callable<Integer> c = () -> computeAnswer();
Comparator<T>
int compare(T o1, T o2)
Ordering. Rich default methods: reversed(), thenComparing().
Comparator.comparing(User::getName).thenComparing(User::getAge)

Method References — the 4 types

1. Static method reference

// Syntax: ClassName::staticMethod Function<String,Integer> parse = Integer::parseInt; // Same as: s -> Integer.parseInt(s) Predicate<Object> isNull = Objects::isNull;

2. Instance method on a specific object

// Syntax: instance::method String prefix = "Hello"; Predicate<String> starts = prefix::startsWith; // Same as: s -> prefix.startsWith(s) Consumer<String> print = System.out::println;

3. Instance method on an arbitrary instance

// Syntax: ClassName::instanceMethod // First param becomes the receiver Function<String,Integer> len = String::length; // Same as: s -> s.length() Predicate<String> isEmpty = String::isEmpty;

4. Constructor reference

// Syntax: ClassName::new Supplier<ArrayList> newList = ArrayList::new; // Same as: () -> new ArrayList() Function<String,StringBuilder> sb = StringBuilder::new; // Same as: s -> new StringBuilder(s)

Closures — lambdas capture variables from enclosing scope

// Lambdas can capture local variables // BUT only "effectively final" ones int multiplier = 3; // effectively final Function<Integer,Integer> triple = x -> x * multiplier; // captures multiplier triple.apply(5); // 15 // This would fail: int count = 0; Runnable bad = () -> count++; // COMPILE ERROR! // "count" is not effectively final
// Workarounds for mutable captures // Option 1: int[] as a mutable container int[] count = {0}; Runnable r = () -> count[0]++; // Option 2: AtomicInteger AtomicInteger count = new AtomicInteger(); Runnable r = () -> count.incrementAndGet(); // Option 3: collect result via Stream long count = list.stream() .filter(predicate) .count(); // no mutation needed

Instance variable capture — always allowed

class EmailService { private String domain = "company.com"; public List<String> formatEmails(List<String> names) { return names.stream() .map(name -> name + "@" + domain) // captures this.domain .collect(Collectors.toList()); } } // 'domain' is an instance field — lambdas always capture 'this' // so all instance state is accessible

Function Composition — build complex behavior from simple pieces

// Function.compose() — apply g then f Function<Integer,Integer> doubler = x -> x * 2; Function<Integer,Integer> adder = x -> x + 10; // compose: adder THEN doubler Function<Integer,Integer> f1 = doubler.compose(adder); // (x+10)*2 f1.apply(5); // (5+10)*2 = 30 // andThen: doubler THEN adder Function<Integer,Integer> f2 = doubler.andThen(adder); // x*2+10 f2.apply(5); // 5*2+10 = 20
// Predicate composition Predicate<String> notEmpty = s -> !s.isEmpty(); Predicate<String> longEnough = s -> s.length() > 3; Predicate<String> noSpaces = s -> !s.contains(" "); // and, or, negate Predicate<String> valid = notEmpty .and(longEnough) .and(noSpaces); valid.test("hello") // true valid.test("hi") // false — too short valid.test("hello world") // false — has space

Consumer andThen — chaining side effects

Consumer<String> logger = msg -> log.info(msg); Consumer<String> auditor = msg -> audit.record(msg); Consumer<String> printer = System.out::println; Consumer<String> all = logger.andThen(auditor).andThen(printer); all.accept("user.login"); // logs, then audits, then prints // Comparator composition Comparator<Employee> byDept = Comparator.comparing(Employee::getDepartment); Comparator<Employee> bySalary = Comparator.comparingDouble(Employee::getSalary).reversed(); employees.sort(byDept.thenComparing(bySalary));
