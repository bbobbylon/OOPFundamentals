Object Types Deep — Excess Props, Index Signatures & Optionality

The everyday object-shape rules the Fundamentals page only sketches: when excess-property checks actually fire, how index signatures differ from Record, and the real difference between x?: T and x: T | undefined.

1. Excess property checks — the "freshness" rule

Structural typing normally ignores extra properties (a wider object satisfies a narrower type). But that would let typos slip through silently. So TS adds one targeted exception: when you assign or pass a fresh object literal directly, it flags any property the target type doesn't declare. The instant that literal flows through a variable first, it's no longer "fresh" and the check is gone.

type Opts = { width: number; color?: string };

const a: Opts = { width: 5, colour: "red" };
// ❌ 'colour' does not exist in type 'Opts'. Did you mean 'color'?

const raw = { width: 5, colour: "red" };
const b: Opts = raw;   // ✅ not fresh → extra ignored (plain structural)

3. Index signatures — open-ended keys

    

      

        
The dictionary shape

        
An index signature types an object whose keys aren't known ahead of time — a bag of values keyed by string (or number). Every declared property must be compatible with the index signature's value type.

        
interface Scores {
  [player: string]: number;   // any string key → number
  topScore: number;          // ✅ number fits the index
  // name: string;  ❌ string is not assignable to number index
}
const s: Scores = { alice: 10, bob: 7, topScore: 10 };
s.charlie;  // type number — even though we never declared it

        
Reading a key that may not exist still gives number here — turn on noUncheckedIndexedAccess to make it number | undefined and force a check.

      

      

        
Number vs string index

        
JS object keys are always strings at runtime (arrays included). A number index signature must therefore return a subtype of the string index's value, if both exist.

        
interface Mixed {
  [n: number]: Animal;
  [s: string]: Animal | string;  // must be ⊇ number's type
}

        
Reach for index signatures only when keys are truly dynamic. If the key set is known, a Record or explicit props give far better safety.

      

    

  


  
  

    
4. Index signature vs Record vs mapped type

    

      

        
FormKeysUse when

        
          
{ [k: string]: V }Open — any string/number, unknown in advancea genuine dictionary / cache / parsed JSON bag

          
Record<K, V>Finite — exactly the union K (e.g. 'a'|'b')you know every key; want errors for missing/typo'd keys

          
{ [K in keyof T]: … }Derived — the keys of an existing type, transformedbuilding a new type from another (see Mapped Types)

        
      

      
// Record gives a CLOSED key set — missing keys are errors:
type Theme = Record<"bg" | "fg", string>;
const t: Theme = { bg: "#000" };  // ❌ missing 'fg'

// index signature is OPEN — this compiles, missing keys are silently allowed:
type Theme2 = { [k: string]: string };
const t2: Theme2 = { bg: "#000" };  // ✅ (no 'fg' required)

// under the hood, Record IS a mapped type:
type Record<K extends keyof any, V> = { [P in K]: V };

    

  


  
  

    
5. Optional ? vs | undefined

    

      

        
They are not the same

        
x?: T means the key may be absent. x: T | undefined means the key must be present, but its value may be undefined. The first lets you omit the property entirely; the second forces you to write it.

        
type A = { id: number; nick?: string };
type B = { id: number; nick: string | undefined };

const a: A = { id: 1 };               // ✅ nick omitted
const b: B = { id: 1 };               // ❌ 'nick' is required
const b2: B = { id: 1, nick: undefined }; // ✅ present, undefined

      

      

        
exactOptionalPropertyTypes

        
By default, ? quietly adds | undefined to the value too — so you can assign undefined to an optional prop. Turn this strict flag on and ? means "absent or a real T", but not an explicit undefined.

        
// with exactOptionalPropertyTypes: true
type A = { nick?: string };

const ok:  A = {};                  // ✅ absent
const ok2: A = { nick: "x" };       // ✅ real value
const bad: A = { nick: undefined }; // ❌ explicit undefined not allowed

        
It separates "I didn't set it" from "I set it to undefined" — useful for PATCH-style partial updates where the two mean different things.

      

    

  


  
  

    
6. readonly properties

    

      
readonly blocks reassignment through that reference at compile time — it's shallow and erased at runtime (unlike a class #private). It does not deep-freeze, and a value can be aliased through a non-readonly type that can then mutate it.

      
interface Point { readonly x: number; readonly y: number; }
const p: Point = { x: 1, y: 2 };
p.x = 9;   // ❌ Cannot assign to 'x' — it is read-only

// shallow: nested objects are still mutable
interface Box { readonly p: { x: number } }
const bx: Box = { p: { x: 1 } };
bx.p.x = 9;  // ✅ allowed — readonly didn't reach inside

// readonly is structural-only — aliasing escapes it:
const mutable: { x: number } = p;  // ✅ assignable…
mutable.x = 9;                       // …now p.x is 9 too

      
For a deep, recursive version see DeepReadonly in the Mapped Types page. For real runtime immutability you still need Object.freeze.

Beyond objectsobject/function/class shapes only✅ unions, tuples, primitives, conditional/mapped types

Performanceslightly better for large extends chains (cached)complex intersections can be costlier to check

        
      

      
Rule of thumb: use interface for public object/class shapes that might be extended or augmented; use type when you need a union, tuple, or anything computed. Both are structural — neither creates a nominal type.

    

  


  
  

    
8. One-sentence recap

    

      
Object shapes are structural, so extras are normally ignored — except excess-property checks on fresh literals (gone the moment a variable launders it); use an index signature for open-ended keys but a Record (a mapped type underneath) when the key set is finite; remember x?: (key may be absent) differs from x: T | undefined (key required, value may be undefined) — sharpened by exactOptionalPropertyTypes; readonly is shallow and compile-time only; and pick interface for extendable/augmentable shapes, type for anything union/tuple/computed.
