Template Reference Variables, ViewChild & ContentChild

Template reference variables let you name elements in your template so you can pass them to event handlers or read them in your component class. ViewChild and ContentChild are the decorators (and their modern signal equivalents) that make template elements available as TypeScript properties.

🎯 What is ViewChild? When do you reach into the template from the component?

Data binding usually makes direct DOM access unnecessary — set a signal and the template updates. But sometimes you need the actual element or child component instance: to focus an input, call a method on a child, measure an element, or hand a real HTMLElement to a chart library. ViewChild gives you a property Angular populates with that reference. The critical timing rule: the element only exists after ngAfterViewInit — not in the constructor, not in ngOnInit.

  • Query by template-ref name ('searchInput'), a component class, or a directive class.
  • Decorator form @ViewChild(...) resolves after ngAfterViewInit (use { static: true } only for always-present elements).
  • Signal form viewChild(...) (17+) is reactive — undefined until ready, then updates as the element appears/disappears (e.g. inside @if); viewChild.required() asserts presence.
  • @ContentChild / contentChild() query projected content (from the consumer's template) and resolve after ngAfterContentInit.
  • Use it for imperative needs — focus, scroll, measure, integrate a JS lib — not as a substitute for binding.

@ViewChild — query an element

@ViewChild('searchInput') input!: ElementRef + template <input #searchInput>. In ngAfterViewInit: this.input.nativeElement.focus(). The ! is needed because Angular sets it asynchronously.

viewChild() signal (17+)

input = viewChild<ElementRef>('searchInput'). Read it as this.input()?.nativeElement.focus() — no ngAfterViewInit dance; the signal updates when the element appears or is removed.

ContentChild — projected content

@ContentChild queries elements the consumer projected via <ng-content> (not the component's own template). Resolves after ngAfterContentInit. For wrapper components — modal, card, accordion.

In CIAM:after the "Create User" dialog opens, auto-focus email with this.emailInput()?.nativeElement.focus(); call this.userForm()?.resetForm() on the child form after a successful save; pass a <div #chartHost> ref to a Chart.js init in ngAfterViewInit (it needs a real DOM node, not data).

Template reference variables — #myRef

Add a #name attribute to any element in a template to create a reference variable. Its meaning depends on what you put it on:

Element typeWhat #ref refers toExample
Plain HTML element The native HTMLElement (an ElementRef.nativeElement) <input #myInput> → myInput.value
Angular component The component class instance — all its public properties and methods <app-timer #timer> → timer.start()
Directive on element By default: the ElementRef. Export the directive with exportAs and use #ref="directiveName" to get the directive instance instead. <input #f="ngModel" [(ngModel)]="val"> → f.valid
<ng-template> A TemplateRef object you can use to render the template imperatively <ng-template #tpl> 
<!-- 1. Reference a plain input — use in template directly -->
<input #searchInput type="text" placeholder="Search..." />
<button (click)="onSearch(searchInput.value)">Search</button>

<!-- 2. Read a child component's instance  -->
<app-accordion #accordion></app-accordion>
<button (click)="accordion.closeAll()">Collapse All</button>

<!-- 3. Get the ngModel directive instance (not the element) -->
<input #emailField="ngModel" [(ngModel)]="email" name="email" required email />
<p *ngIf="emailField.invalid && emailField.touched">Enter a valid email</p>

<!-- 4. Reference an ng-template for ViewContainerRef usage -->
<ng-template #modalTemplate>
  <app-modal>...</app-modal>
</ng-template>

@ViewChild decorator — all four overloads

@ViewChild queries the component's own template (not projected content). You pass either a string matching a template reference variable name, or the class of the component/directive you want. Angular populates the decorated property after ngAfterViewInit. 

import { ViewChild, ElementRef, AfterViewInit } from '@angular/core';

export class DashboardComponent implements AfterViewInit {

  // 1. By template reference variable name (string)
  @ViewChild('chartCanvas') canvas!: ElementRef<HTMLCanvasElement>;

  // 2. By component class — gets the first instance of that component in the template
  @ViewChild(ChartComponent) chart!: ChartComponent;

  // 3. By directive class — gets the directive applied to any element in the template
  @ViewChild(ResizableDirective) resizable!: ResizableDirective;

  // 4. static: true — populate BEFORE ngOnInit (only for non-conditional elements)
  @ViewChild('header', { static: true }) header!: ElementRef;
  //  ^ This works in ngOnInit. But ONLY if <div #header> is NEVER inside *ngIf/*ngFor

  // Default: static: false — populate after view init, required for conditional elements
  @ViewChild('tooltip', { static: false }) tooltip?: ElementRef;
  //  ^ element might be inside *ngIf, so it's optional (?) and only available in ngAfterViewInit

  // 5. Get the injector's ElementRef — the host element of this component itself
  @ViewChild(ElementRef) hostEl!: ElementRef;

  ngAfterViewInit(): void {
    // All @ViewChild fields (except static:true) are populated HERE
    this.chart.setData([10, 20, 30]);
    this.canvas.nativeElement.getContext('2d');
  }
}

static: true vs static: false — when to use each

The static option controls when the query is resolved. The default (false) is almost always the right choice. Use true only in the narrow case where you need the reference available in ngOnInit and you're certain the element is not conditional.

static: false (default) — correct for most cases

<!-- element inside *ngIf — dynamic -->
<div *ngIf="showPanel">
  <app-panel #panel></app-panel>
</div>

// ✅ static: false → resolved after view init
@ViewChild('panel') panel?: AppPanelComponent;
// panel is undefined if showPanel is false
// panel is populated in ngAfterViewInit when showPanel is true

ngAfterViewInit() {
  if (this.panel) { this.panel.open(); }
}

static: true — only for always-present elements

<!-- element is ALWAYS in the template, no *ngIf -->
<app-navbar #nav></app-navbar>

// ✅ static: true → resolved before ngOnInit
@ViewChild('nav', { static: true }) nav!: NavbarComponent;

ngOnInit() {
  this.nav.setTitle('Dashboard');
  // Works! nav is available here because static: true
}

// ❌ DO NOT use static: true if the element could be inside *ngIf
// The query will silently return undefined and confuse you

@ViewChildren — QueryList of all matches

When you have multiple matching elements — typically created by *ngFor — use @ViewChildren (plural). It returns a QueryList<T>, not a plain array. A QueryList is a special Angular collection that stays live: when items are added or removed from the DOM, the QueryList updates automatically. It also emits on its .changes Observable. 

import { ViewChildren, QueryList } from '@angular/core';

export class AccordionComponent implements AfterViewInit, OnDestroy {
  private destroy$ = new Subject<void>();

  // Gets ALL PanelComponent instances in the template
  @ViewChildren(PanelComponent) panels!: QueryList<PanelComponent>;

  ngAfterViewInit(): void {
    console.log(this.panels.length);         // number of panels
    console.log(this.panels.toArray());      // convert to regular array
    this.panels.first.expand();              // access first item directly
    this.panels.last.collapse();             // access last item directly

    // Subscribe to QueryList changes — fires when *ngFor adds/removes panels
    this.panels.changes
      .pipe(takeUntil(this.destroy$))
      .subscribe((updated: QueryList<PanelComponent>) => {
        console.log('Panels updated — new count:', updated.length);
        updated.forEach(p => p.recalculateSize());
      });
  }

  closeAll(): void {
    // forEach works just like on an array
    this.panels.forEach(p => p.collapse());
  }

  ngOnDestroy(): void { this.destroy$.next(); this.destroy$.complete(); }
}

@ContentChild and @ContentChildren

@ContentChild queries content projected into the component via <ng-content> — not content defined in the component's own template. It works exactly like @ViewChild but targets projected content. Available from ngAfterContentInit onward (earlier than @ViewChild's ngAfterViewInit).

The component template (defines a slot)

<!-- card.component.html — the "host" component -->
<div class="card-wrapper">
  <div class="card-header">
    <!-- any content projected as #header goes here -->
    <ng-content select="[slot=header]"></ng-content>
  </div>
  <div class="card-body">
    <ng-content></ng-content>  <!-- default slot -->
  </div>
</div>

// card.component.ts — query the projected icon button
export class CardComponent implements AfterContentInit {
  @ContentChild(ActionButtonComponent)
  actionBtn!: ActionButtonComponent;

  ngAfterContentInit() {
    // ✅ actionBtn is available HERE (content has been projected)
    this.actionBtn.setVariant('outline');
  }
}

The parent template (projects content in)

<!-- parent.component.html -->
<app-card>

  <!-- This ActionButtonComponent is projected into <app-card> -->
  <!-- @ContentChild in CardComponent will find it -->
  <app-action-button slot="header">
    Edit
  </app-action-button>

  <!-- default slot content -->
  <p>Card body content here.</p>

</app-card>

// @ContentChildren — get ALL projected children of a type:
@ContentChildren(MenuItemComponent)
menuItems!: QueryList<MenuItemComponent>;

Signal-based queries (Angular 17+)

Angular 17 introduced signal versions of all four query APIs. Instead of decorated properties that are populated by lifecycle hooks, they return Signals that automatically update whenever the DOM changes. The big advantage: no lifecycle timing issues — you can safely read the signal anywhere, and it's always current.

Decorator-based (before Angular 17)

import { ViewChild, ViewChildren, QueryList } from '@angular/core';

export class OldSearchBar implements AfterViewInit {
  @ViewChild('input') input!: ElementRef;
  @ViewChildren(OptionComponent) options!: QueryList<OptionComponent>;

  ngAfterViewInit() {
    // Must wait for this hook. If you access input in ngOnInit — undefined.
    this.input.nativeElement.focus();
    this.options.forEach(o => o.recalc());
  }
}

Signal-based (Angular 17+)

import { viewChild, viewChildren } from '@angular/core';

export class NewSearchBar {
  // Signal<ElementRef | undefined> — no lifecycle hook needed
  input = viewChild<ElementRef>('input');
  // Signal<readonly OptionComponent[]>
  options = viewChildren(OptionComponent);

  focusInput() {
    // Read the signal — always current, works from ngOnInit onward
    this.input()?.nativeElement.focus();
  }

  recalcOptions() {
    // viewChildren returns a plain readonly array (not a QueryList)
    this.options().forEach(o => o.recalc());
  }
}
// All four signal query APIs — mirroring the four decorator APIs
import { viewChild, viewChildren, contentChild, contentChildren } from '@angular/core';

export class MyComponent {
  // @ViewChild equivalent — Signal<T | undefined>
  chart = viewChild<ChartComponent>(ChartComponent);
  // required() throws if undefined instead of returning undefined
  header = viewChild.required<ElementRef>('header');

  // @ViewChildren equivalent — Signal<readonly T[]>
  tabs = viewChildren(TabComponent);

  // @ContentChild equivalent
  icon = contentChild(IconComponent);

  // @ContentChildren equivalent
  items = contentChildren(ListItemComponent);

  // Use them as computed values — no lifecycle hook needed
  tabCount = computed(() => this.tabs().length);
}

The signal APIs return plain arrays for viewChildren/contentChildren — not a QueryList. You don't need to subscribe to a .changes observable; the signal reactivity system handles updates automatically. Signal queries are the modern recommendation for new Angular 17+ code.

Common real-world patterns

Focus an input on component open

@Component({
  template: `<input #search type="text" />`
})
export class SearchDialogComponent implements AfterViewInit {
  @ViewChild('search') search!: ElementRef<HTMLInputElement>;

  ngAfterViewInit() {
    // Auto-focus the input when dialog opens
    setTimeout(() => this.search.nativeElement.focus());
    // setTimeout defers past the current CD cycle — avoids ExpressionChangedError
  }
}

Call a method on a child component

@Component({
  template: `<app-video-player #player [src]="url"></app-video-player>
             <button (click)="player.pause()">Pause</button>`
})
export class VideoPageComponent implements AfterViewInit {
  @ViewChild('player') player!: VideoPlayerComponent;
  url = '/video/intro.mp4';

  skipToEnd() {
    // Call methods on the child directly via ViewChild
    this.player.seekTo(this.player.duration);
  }
}

Measure DOM element dimensions

export class ResponsiveChartComponent implements AfterViewInit {
  @ViewChild('container') container!: ElementRef<HTMLDivElement>;
  width = 0;
  height = 0;

  ngAfterViewInit() {
    const rect = this.container.nativeElement.getBoundingClientRect();
    this.width  = rect.width;
    this.height = rect.height;
    this.drawChart(this.width, this.height);

    // Keep re-measuring on resize
    const ro = new ResizeObserver(entries => {
      this.width  = entries[0].contentRect.width;
      this.height = entries[0].contentRect.height;
    });
    ro.observe(this.container.nativeElement);
  }
}

Access FormGroup via ContentChild

// A "card" wrapper that can read any form inside it
export class FormCardComponent implements AfterContentInit {
  @ContentChild(NgForm) form?: NgForm;

  ngAfterContentInit() {
    if (this.form) {
      // Subscribe to the projected form's validity changes
      this.form.statusChanges?.subscribe(status => {
        this.isValid = status === 'VALID';
      });
    }
  }
  isValid = false;
}

All four APIs compared

APIQueriesReturnsAvailable fromModern signal equiv.
@ViewChild First matching element/component/directive in own template Single instance or undefined ngAfterViewInit (or ngOnInit with static:true) viewChild()
@ViewChildren ALL matching elements/components in own template QueryList<T> ngAfterViewInit viewChildren()
@ContentChild First matching element in projected content (<ng-content>) Single instance or undefined ngAfterContentInit contentChild()
@ContentChildren ALL matching elements in projected content QueryList<T> ngAfterContentInit contentChildren()

Common mistakes

Accessing @ViewChild in ngOnInit

Unless static: true, @ViewChild is undefined in ngOnInit. The view hasn't been built yet. Move DOM access to ngAfterViewInit.

Forgetting ? on conditional ViewChild

If the element could be inside *ngIf, declare the property with ? (optional): @ViewChild('x') x?: ElementRef. Otherwise TypeScript will complain and you'll get runtime errors when the condition is false.

Using QueryList as an array

QueryList is not an array — it doesn't have array methods like .map(). Use .toArray() to convert it, or use the signal viewChildren() which returns a real readonly array.

Not subscribing to QueryList.changes

If you do work in ngAfterViewInit based on the initial QueryList but then items get added/removed by *ngFor, your logic doesn't re-run. Subscribe to queryList.changes or switch to signal queries.

Modifying component state in ngAfterViewInit

Setting a component property in ngAfterViewInit that the template binds to causes ExpressionChangedAfterItHasBeenCheckedError. Wrap the change in setTimeout() or call cdr.detectChanges().

Mixing @ContentChild and @ViewChild up

@ViewChild queries the component's own template. @ContentChild queries content projected into it from the outside via <ng-content>. Using the wrong one returns undefined with no error message.
