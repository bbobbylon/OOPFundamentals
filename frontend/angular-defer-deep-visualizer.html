@defer — Lazy-Load Anything, Declaratively

Angular's @defer block code-splits a chunk of your template and its dependencies into a separate bundle that downloads only when a trigger says so — no router, no manual import(). Pick a trigger and watch the placeholder → loading → loaded lifecycle, and the bundle download.

⏳ What is @defer — and how is it different from route-level lazy loading?

Route-level lazy loading splits your app by route — /admin's bundle isn't fetched until you navigate there. But what about a heavy chart, an audit-log table, or a rich editor that's on the current page but below the fold or inside an unopened tab? @defer code-splits at the template level: wrap any component in @defer and Angular puts it in its own chunk that downloads only when a trigger fires — no router change needed.

  • Splits at the template, not the route — perfect for heavy widgets that share a page with light content.
  • A block has four parts: the deferred content, @placeholder (shown first), @loading (during fetch), @error (on failure).
  • Triggers: on viewport, on interaction, on idle, after 200ms, or when condition() — and they can be combined.
  • prefetch is independent of render: download early (prefetch on idle) so the component renders instantly when its real trigger fires.
  • Net effect: a smaller initial bundle + faster first paint, with the heavy code arriving exactly when it's needed.

@defer block structure

@defer (on viewport) { <heavy-chart/> } @placeholder { <div class="skeleton"></div> } @loading { <spinner/> } @error { <p>Failed</p> }. Placeholder shows first; the trigger fetches the chunk, shows loading, then swaps in the component (or @error).

Triggers

on idle (background), on viewport (IntersectionObserver), on interaction (first click/focus/keydown), after 200ms, when showChart() (any signal/boolean). Combine: on viewport; prefetch on idle.

prefetch

@defer (on interaction; prefetch on idle) downloads during idle before the click, so the component renders instantly on click. Render trigger and prefetch trigger are independent — great for predictable interactions.

In CIAM:an admin dashboard's audit-log table (pulls in ag-Grid + date-fns) uses @defer (on viewport; prefetch on idle) — a skeleton until it scrolls in, and the main page loads ~3× faster because ag-Grid isn't in the initial chunk. The activity-chart tab uses @defer (when activeTab() === 'activity') — fetched only on click.

1. The anatomy of a @defer block

    

      
@defer (on viewport) {           // ← trigger: when to load
  <app-comments [postId]="id" />   // this + its imports become a lazy chunk
} @placeholder (minimum 500ms) { // ← shown BEFORE loading starts
  <div class="skeleton">Comments will load here</div>
} @loading (after 100ms; minimum 1s) { // ← shown WHILE the chunk downloads
  <app-spinner />
} @error {                       // ← shown if the import() fails
  <p>Couldn't load comments.</p>
}

      
    
        
  • @defer — the content to lazy-load. Its components/pipes/directives are pulled into a separate JS chunk.
    • 
        
  • @placeholder — lightweight stand-in shown until the trigger fires. minimum avoids a flash.
    • 
        
  • @loading — shown during the download. after = wait this long before showing (skip for fast loads); minimum = show at least this long (avoid flicker).
    • 
        
  • @error — fallback if the network fetch fails.
    •

Combine them: @defer (on viewport; on timer(10s)) loads on whichever happens first. Add prefetch to download early without rendering: @defer (on interaction; prefetch on idle) — the chunk is ready the instant the user clicks.

    

  


  
  

    
4. Rules & gotchas

    

      

        
What can be deferred

        
    
          
  • Dependencies used only inside the @defer block are moved to the lazy chunk. If a component is also used eagerly elsewhere in the template, it can't be split out.
    • 
          
  • Works with standalone components/directives/pipes (the modern default). Anything NgModule-declared and shared eagerly stays in the main bundle.
    • 
          
  • The build does the code-splitting automatically — you never write import().
    • 
        

      

      

        
SSR & correctness

        
    
          
  • With SSR/SSG, @placeholder is what gets server-rendered; the deferred content hydrates/loads on the client per its trigger.
    • 
          
  • Always provide a @placeholder for layout stability (avoid content-shift when it loads).
    • 
          
  • on viewport, interaction, and hover need a placeholder (or an explicit trigger element) — there must be something on screen to observe.
    • 
          
  • Triggers are about loading, not data — fetch data inside the loaded component as usual.
    • 
        

      

    

  


  
  

    
5. One-sentence recap

    

      
⏬ @defer moves a slice of your template (and its standalone deps) into a lazy chunk that downloads only when a trigger fires — idle/viewport/interaction/hover/timer/immediate/when — showing @placeholder until then, @loading during the fetch, and @error if it fails, with optional prefetch to download early; it's router-free code-splitting for any piece of UI.
