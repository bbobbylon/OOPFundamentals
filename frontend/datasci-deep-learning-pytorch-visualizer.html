Deep Learning in Practice — CNNs, RNNs & PyTorch Basics

Different data shapes need different architectures: convolutional networks for images, recurrent networks for sequences — then how PyTorch's autograd and training loop actually turn a loss value into updated weights.

🧠 Why doesn't one neural network shape fit everything?

The plain feedforward network from Neural Networks Fundamentals treats every input feature as independent and unordered — fine for tabular data, terrible for images (where NEARBY pixels are related) and terrible for sequences (where ORDER carries meaning). Convolutional Neural Networks (CNNs) exploit spatial locality with small, shared filters that slide across an image. Recurrent Neural Networks (RNNs) exploit sequence order by carrying a hidden state forward from one step to the next, giving the network a form of memory. Both are still trained by the exact same backpropagation + gradient descent loop you already know — what changes is the architecture's shape, not the training algorithm. PyTorch is the framework most teams actually build these in: it auto-builds the computation graph as your code runs (autograd) and hands you a five-line training loop that works for a CNN, an RNN, or anything else.

  • CNNs — a small filter slides across the image, sharing the same weights everywhere (parameter sharing).
  • Pooling downsamples feature maps, keeping the strongest signal and adding translation tolerance.
  • RNNs carry a hidden state step-to-step — memory of what came before in the sequence.
  • Vanishing gradients make vanilla RNNs forget long-range context — LSTM/GRU gates fix it.
  • PyTorch's loop: forward → loss → backward() → step() → zero_grad(), always in that shape.

A convolution, conceptually

\# a 3x3 filter slides over the image, \# one dot-product per position output[i][j] = sum( filter[a][b] * image[i+a][j+b] for a in range(3) for b in range(3) ) \# the SAME filter[a][b] weights are \# reused at every (i, j) — that's \# parameter sharing

An RNN cell update

\# hidden state carries memory forward h_t = tanh( W_input @ x_t + W_hidden @ h_prev + b ) \# h_t depends on x_t AND h_prev, \# which itself depended on x_(t-1) \# ... memory chains backward

PyTorch autograd in 5 lines

pred = model(x) \# forward loss = criterion(pred, y) \# compute loss loss.backward() \# autograd fills .grad optimizer.step() \# apply update optimizer.zero_grad() \# clear for next time

CIAM angle: Adaptive/risk-based authentication (the kind Ping's CIAM platform does — see CIAM & Adaptive Auth) scores a login attempt using exactly this machinery: a model trained on historical login sequences (device, geo, typing cadence over time — sequence data, RNN-shaped) outputs a fraud/risk score that a policy engine turns into "allow / step-up MFA / deny." The model training loop underneath is the same forward → loss → backward → step cycle covered here.

1. Convolutional Neural Networks — Spatial Feature Extraction

A convolutional layer slides a small learnable filter (e.g. 3×3) across the input, computing one dot product per position to build a feature map. The SAME filter weights are reused at every position — parameter sharing — which is why a CNN needs vastly fewer parameters than a fully-connected layer would to process an image-sized input.

\# a 3x3 filter (kernel) at one position:
region = image[i:i+3, j:j+3]
output[i][j] = (filter * region).sum()   \# one dot product
\# slide by 1 pixel, repeat for every (i, j)
\# → output is a feature map, same filter reused everywhere
Parameter sharing is the whole trick. A fully-connected layer on a 224×224 image needs a weight per pixel per output unit — millions of parameters. A 3×3 conv filter has 9 weights, period, and it's applied at every position. Stacking conv+pool layers builds a feature hierarchy: early layers learn edges and textures, deeper layers combine those into shapes and object parts.

Max pooling then downsamples: for each 2×2 block of the feature map, keep only the strongest (maximum) value. This shrinks the spatial size and gives some tolerance to small shifts in position — an edge detected slightly left or right of where pooling expected it still survives.

2. Recurrent Neural Networks — Memory Across a Sequence

An RNN processes a sequence one element at a time, maintaining a hidden state that carries information from earlier steps forward. Unlike a plain feedforward network (which has no notion of "before" or "after"), an RNN's prediction at step t can depend on everything it has seen since step 1.

The recurrence

h_t = tanh(W_x @ x_t + W_h @ h_prev + b)
\# h_t: new hidden state
\# x_t: current input (e.g. word embedding)
\# h_prev: hidden state from the LAST step
\# same W_x, W_h reused at every time step

The vanishing gradient

\# gradient flowing back through T steps
\# multiplies by ~tanh' derivative each step
grad_at_step_1 ≈ grad_at_T * (0.25)^T
\# for T=10, that's roughly 0.25^10
\# ≈ 0.00000095 — essentially zero
Vanilla RNNs forget. Because the same small derivative multiplies in at every backward step, gradients shrink exponentially over long sequences — early-sequence information stops influencing training at all. LSTMs (Long Short-Term Memory) and GRUs fix this with learned gates that explicitly decide what to keep, forget, or output at each step, giving gradients a more direct path backward. This exact limitation — recurrence forcing information through a narrow, decaying channel — is what later motivated the Transformer architecture (attention instead of recurrence), covered in the AI/LLM Engineering track's Transformers & Attention page.

3. PyTorch in Practice — Tensors, Autograd & the Training Loop

PyTorch's core abstractions: a Tensor (like a NumPy array, but it can live on a GPU and track gradients), autograd (PyTorch builds a computation graph automatically as your tensor operations execute — .backward() walks that graph and fills in every parameter's .grad, so you never hand-derive backpropagation), and nn.Module (the base class where you define layers in __init__ and the forward computation in forward()).

import torch, torch.nn as nn

model = SimpleCNN(num_classes=10)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
criterion = nn.CrossEntropyLoss()

for images, labels in train_loader:
    optimizer.zero_grad()          \# clear old gradients FIRST
    outputs = model(images)        \# forward pass
    loss = criterion(outputs, labels)
    loss.backward()                \# autograd fills .grad on every param
    optimizer.step()               \# apply the gradient-descent update
The bug everyone writes once: PyTorch accumulates gradients into .grad by default — it does not reset them automatically between iterations. Forget optimizer.zero_grad() and every batch's gradient silently adds on top of the last one, corrupting training in a way that doesn't crash, just quietly trains a worse model.

Transfer learning is the practical reality for most real projects: training a large CNN or RNN from scratch needs huge datasets and compute. Instead, start from a model pretrained on a big generic dataset (e.g. ImageNet), freeze its early layers (param.requires_grad = False, so backward() skips updating them), and fine-tune only the final layers on your own smaller dataset — dramatically less data and compute, and the standard approach in industry.
