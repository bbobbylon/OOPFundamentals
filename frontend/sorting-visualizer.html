🧩 What are sorting algorithms — and why do Merge Sort, Quick Sort, and Heap Sort dominate real systems while Bubble Sort only teaches the concept?

Sorting algorithms arrange elements in order (typically ascending or descending). The fundamental trade-offs between sorting algorithms are: time complexity (how long does it take?), space complexity (how much extra memory?), and stability (does it preserve the relative order of equal elements?). Bubble Sort O(n²) — educational only: repeatedly compare adjacent elements and swap if out of order. After each pass, the largest unsorted element "bubbles" to the end. Simple to understand but O(n²) time means it takes 100× longer on 10× more data. Never use in production. Selection Sort O(n²) — slightly better: find the minimum unsorted element, swap it to the front. O(n²) but does fewer swaps than Bubble. Educational. Insertion Sort O(n²) — but good for small n: build sorted array one element at a time by inserting each element into its correct position. O(n²) worst case, but O(n) on nearly-sorted data. Used as a sub-routine by Java's TimSort for small arrays. Merge Sort O(n log n) stable — the reliable choice: divide the array in half recursively until single elements, then merge back in sorted order. Always O(n log n) — no worst case (unlike Quick Sort). Stable (preserves order of equal elements). Downside: O(n) extra space for the merge operation. Java's Arrays.sort() for objects uses a variant of Merge Sort (TimSort). Quick Sort O(n log n) average, O(n²) worst — the fast choice: choose a pivot, partition the array into elements less-than and greater-than the pivot, recursively sort both partitions. O(n log n) average but O(n²) worst case on already-sorted data with a bad pivot choice. In-place (O(log n) stack space). Typically faster than Merge Sort in practice due to cache locality. Java's Arrays.sort() for primitives uses Dual-Pivot Quick Sort. Heap Sort O(n log n) — guaranteed, in-place: build a max-heap, then repeatedly extract the max. Always O(n log n), in-place (O(1) space), but not stable and has poor cache behavior. Used when you need guaranteed O(n log n) without extra space. The decision guide: use TimSort (Java built-in) for objects; use Dual-Pivot QuickSort (Java built-in) for primitives; implement Merge Sort when you need stable sorting with custom comparators; use Heap Sort when memory is tight and you need guaranteed O(n log n).

Merge Sort implementation

// Merge Sort: O(n log n) always, stable, O(n) space // Pattern: divide in half recursively, then merge void mergeSort(int[] arr, int left, int right) { if (left >= right) return; // base case: 1 element int mid = left + (right - left) / 2; // avoid int overflow mergeSort(arr, left, mid); // sort left half mergeSort(arr, mid+1, right); // sort right half merge(arr, left, mid, right); // merge the two sorted halves } void merge(int[] arr, int left, int mid, int right) { int[] temp = new int[right - left + 1]; // O(n) extra space int i=left, j=mid+1, k=0; while (i<=mid && j<=right) { // Stable: take left when equal (preserves original order) if (arr[i] <= arr[j]) temp[k++] = arr[i++]; else temp[k++] = arr[j++]; } while (i<=mid) temp[k++] = arr[i++]; // remaining left while (j<=right) temp[k++] = arr[j++]; // remaining right System.arraycopy(temp, 0, arr, left, temp.length); }

Quick Sort implementation

// Quick Sort: O(n log n) avg, O(n²) worst, in-place // Key: partition around pivot void quickSort(int[] arr, int low, int high) { if (low >= high) return; // base case int pivotIdx = partition(arr, low, high); quickSort(arr, low, pivotIdx - 1); // sort left of pivot quickSort(arr, pivotIdx + 1, high); // sort right of pivot } int partition(int[] arr, int low, int high) { int pivot = arr[high]; // choose last element as pivot int i = low - 1; // pointer for "less than" section for (int j=low; j<high; j++) { if (arr[j] <= pivot) { i++; // expand "less than" section int tmp=arr[i]; arr[i]=arr[j]; arr[j]=tmp; // swap } } int tmp=arr[i+1]; arr[i+1]=arr[high]; arr[high]=tmp; // pivot in place return i+1; // pivot's final index } // O(log n) worst-case pivot workaround: // Randomize pivot: swap arr[random(low,high)] with arr[high] before partitioning

Each algorithm at a glance

Bubble Sort

Best: O(n) · Avg/Worst: O(n²) · Space: O(1) · Stable: yes

Walks the array repeatedly, swapping adjacent out-of-order pairs. The biggest unsorted value "bubbles" to the end each pass. Dead simple to write; awful at scale. Useful for: teaching, tiny arrays.

Selection Sort

Best/Avg/Worst: O(n²) · Space: O(1) · Stable: no

Repeatedly finds the minimum of the unsorted region and swaps it into place. Always O(n²), even on already-sorted input. But it does the fewest swaps of any sort — useful when writes are expensive (e.g., flash memory).

Insertion Sort

Best: O(n) · Avg/Worst: O(n²) · Space: O(1) · Stable: yes

Builds the sorted region one element at a time by sliding each new value into its correct slot. Surprisingly fast on small or nearly-sorted data — that's why Java's Arrays.sort switches to insertion sort for small subarrays inside its Timsort.

Quick Sort

Best/Avg: O(n log n) · Worst: O(n²) · Space: O(log n) · Stable: no

Pick a pivot, partition the array around it, recurse on both halves. Extremely fast in practice. Used in: C's qsort, the JVM's int sort. The worst case (already sorted with naive pivot) is rare with smart pivot picking.

Merge Sort

Best/Avg/Worst: O(n log n) · Space: O(n) · Stable: yes

Splits in half, sorts each half, merges them. Predictable O(n log n) regardless of input. Needs O(n) extra memory for merging. Used in: Java's Arrays.sort for objects, Python's Timsort base. Great when stability matters.

What "stable" means

A property, not a complexity

A sort is stable if equal elements keep their original relative order. Matters when sorting by a key while preserving prior order (e.g., sort emails by date, keeping the alphabetical sort by sender within the same date).

Which one should I use?

  • In real code: just call Arrays.sort() / Collections.sort(). They use sophisticated hybrids (TimSort for objects, dual-pivot quicksort for ints).
  • In interviews: know Quick and Merge cold. Be ready to write Insertion sort if asked.
  • Stability matters? Merge sort, insertion sort, bubble sort. Quick and selection are NOT stable.
  • Memory tight? Quick sort (O(log n) stack) over merge sort (O(n) extra).
  • Tiny data? Insertion sort — it has the smallest constant factor for small n.
