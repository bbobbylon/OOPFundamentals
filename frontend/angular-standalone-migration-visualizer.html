Angular Standalone — Migration from NgModules

How NgModules work, why standalone eliminates them, and a step-by-step migration of a real app.

1. What NgModule Does (and What Standalone Eliminates)

NgModule was Angular's original compilation unit — it grouped components together so the template compiler knew which directives and pipes were in scope. Standalone components make every component its own compilation unit.

NgModule approach
@NgModule({
  declarations: [
    AppComponent,
    UserCardComponent,
    HighlightDirective,
    DateFormatPipe
  ],
  imports: [
    BrowserModule,
    HttpClientModule,
    RouterModule.forRoot(routes)
  ],
  providers: [UserService],
  bootstrap: [AppComponent]
})
export class AppModule {}
Every component, directive, and pipe must be declared in exactly one NgModule. Forgetting a declaration = compiler error. Sharing requires SharedModule imports everywhere.
Standalone approach
@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [
    CommonModule,  // or just NgIf, NgFor
    RouterLink,
    HighlightDirective,
    DateFormatPipe
  ],
  template: `...`
})
export class UserCardComponent {}
Each component declares its own dependencies. No NgModule needed. Import exactly what you use — enables better tree-shaking.
ConcernNgModuleStandalone
Compilation scopeModule-level (all declarations share scope)Component-level (each component manages its own)
Dependency declarationIn NgModule.declarations + shared via importsIn @Component.imports
ProvidersIn NgModule.providers or providedIn:'root'In bootstrapApplication or component-level
Lazy loadingloadChildren: () => import('./mod').then(m => m.Mod)loadChildren: () => import('./routes') or loadComponent()
BoilerplateHigh — always need at least AppModuleLow — zero modules required
Tree-shakingCoarser — whole module includedFine-grained — only imported items

2. bootstrapModule vs bootstrapApplication

main.ts — NgModule bootstrap
import { platformBrowserDynamic } from
  '@angular/platform-browser-dynamic';
import { AppModule } from './app/app.module';

platformBrowserDynamic()
  .bootstrapModule(AppModule)
  .catch(err => console.error(err));
main.ts — Standalone bootstrap
import { bootstrapApplication } from
  '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch(err => console.error(err));

app.config.ts — The new provider home

import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient, withInterceptors } from '@angular/common/http';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';
import { routes } from './app.routes';
import { authInterceptor } from './auth.interceptor';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(withInterceptors([authInterceptor])),
    provideAnimationsAsync(),
    // any other app-wide providers...
  ]
};

Modern Provider Functions vs Old Module Imports

Old (NgModule)New (Standalone)Notes
HttpClientModuleprovideHttpClient()Add withInterceptors([]) for functional interceptors
RouterModule.forRoot(routes)provideRouter(routes)Add withPreloading(), withDebugTracing() etc.
BrowserAnimationsModuleprovideAnimations()Or provideAnimationsAsync() for lazy-loaded animations
NoopAnimationsModuleprovideNoopAnimations()Use in tests
FormsModuleImport directly in componentimports:[FormsModule] in component decorator
ReactiveFormsModuleImport directly in componentimports:[ReactiveFormsModule]
importProvidersFrom(): For old third-party modules that haven't been updated yet, use importProvidersFrom(SomeOldModule) inside the providers array of bootstrapApplication. This extracts the module's providers without needing an NgModule. 
import { importProvidersFrom } from '@angular/core';
import { SomeThirdPartyModule } from 'some-library';

providers: [
  importProvidersFrom(SomeThirdPartyModule.forRoot({ key: 'value' })),
]

3. Lazy Loading — Routes File & loadComponent()

Old: lazy feature module
// app.routes.ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.module')
      .then(m => m.AdminModule)
}

// admin/admin.module.ts
@NgModule({
  declarations: [AdminDashboardComponent],
  imports: [RouterModule.forChild([
    { path: '', component: AdminDashboardComponent }
  ])]
})
export class AdminModule {}
New: lazy route file
// app.routes.ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes')
      .then(r => r.ADMIN_ROUTES)
}

// admin/admin.routes.ts
export const ADMIN_ROUTES: Routes = [
  {
    path: '',
    loadComponent: () =>
      import('./dashboard.component')
        .then(c => c.AdminDashboardComponent)
  }
];

loadComponent() for Single Component Routes

// Lazy-load a single standalone component — no routes file needed
const routes: Routes = [
  {
    path: 'profile',
    loadComponent: () =>
      import('./profile/profile.component')
        .then(c => c.ProfileComponent)
  },
  {
    path: 'settings',
    loadComponent: () =>
      import('./settings/settings.component')
        .then(c => c.SettingsComponent)
  }
];
Each loadComponent() creates a separate JS chunk. The browser downloads it only when the user navigates to that route. No intermediate NgModule required.

4. Shared Functionality Without SharedModule

The SharedModule anti-pattern: In NgModule apps, teams created a giant SharedModule that exported everything — CommonModule, ReactiveFormsModule, every shared component and pipe. Any component that needed anything imported the entire SharedModule.
SharedModule (anti-pattern)
@NgModule({
  declarations: [
    ButtonComponent,
    CardComponent,
    TruncatePipe,
    HighlightDirective
  ],
  imports: [CommonModule, FormsModule],
  exports: [
    CommonModule, FormsModule,
    ButtonComponent, CardComponent,
    TruncatePipe, HighlightDirective
  ]
})
export class SharedModule {}

// Every component module does:
imports: [SharedModule]
// Even if it only needs ButtonComponent
Standalone: explicit direct imports
// Just import what you need, exactly
@Component({
  standalone: true,
  imports: [
    NgIf,           // not all of CommonModule
    ButtonComponent,
    TruncatePipe
    // HighlightDirective NOT imported = not in bundle
  ],
  template: `...`
})
export class ProfileComponent {}

// Optional: barrel file for convenience
// shared/index.ts
export { ButtonComponent } from './button';
export { TruncatePipe } from './truncate.pipe';

5. Generating Standalone with the Angular CLI

Generate standalone component

# Angular 17+ defaults to standalone
ng generate component user-card
# Equivalent explicit flag:
ng g c user-card --standalone

# Angular 14-16 needed the flag:
ng g c user-card --standalone

Generate standalone directive & pipe

# Standalone directive
ng g directive highlight --standalone

# Standalone pipe
ng g pipe truncate --standalone

# Standalone guard
ng g guard auth --functional

Automated Migration Schematic

ng g @angular/core:standalone — runs in 3 passes and converts an existing NgModule app to standalone automatically. Always commit first so you can review the diff.
Pass 1

Convert Components

Adds standalone: true to every component, directive, and pipe. Adds necessary imports arrays. Removes them from NgModule declarations.

Pass 2

Remove Modules

Deletes now-empty NgModule files (where safe). Rewrites bootstrapModule → bootstrapApplication with extracted providers.

Pass 3

Clean Up

Removes unused imports in TypeScript files. Replaces module-based providers with modern provide*() functions where possible.

# Run all 3 passes (recommended)
ng g @angular/core:standalone

# Run a single specific pass
ng g @angular/core:standalone --mode=convert-to-standalone
ng g @angular/core:standalone --mode=prune-ng-modules
ng g @angular/core:standalone --mode=standalone-bootstrap

6. Interactive: Step-by-Step Migration

Walk through migrating a sample Angular app from NgModules to standalone. Click each step to see what changes.

Starting Point — NgModule App

app.module.ts
@NgModule({
  declarations: [
    AppComponent,
    NavComponent,
    HomeComponent,
    UserCardComponent,
  ],
  imports: [
    BrowserModule,
    HttpClientModule,
    RouterModule.forRoot(routes),
    ReactiveFormsModule,
  ],
  providers: [
    UserService,
    { provide: HTTP_INTERCEPTORS,
      useClass: AuthInterceptor,
      multi: true }
  ],
  bootstrap: [AppComponent]
})
export class AppModule {}
app.component.ts
@Component({
  selector: 'app-root',
  // NO standalone flag
  // NO imports array
  template: `
    <app-nav></app-nav>
    <router-outlet></router-outlet>
  `
})
export class AppComponent {
  title = 'my-app';
}
AppComponent depends on AppModule knowing about NavComponent and RouterOutlet. The component itself has no declaration of its deps.

Step 1 — Convert AppComponent to Standalone

Before
@Component({
  selector: 'app-root',
  template: `
    <app-nav></app-nav>
    <router-outlet></router-outlet>
  `
})
export class AppComponent {}
After
@Component({
  selector: 'app-root',
  standalone: true,  // ← ADD
  imports: [        // ← ADD
    NavComponent,   // explicit dep
    RouterOutlet,   // from @angular/router
  ],
  template: `
    <app-nav></app-nav>
    <router-outlet></router-outlet>
  `
})
export class AppComponent {}
AppComponent now self-documents its template dependencies. The compiler no longer needs AppModule to compile this component.

Step 2 — Convert FeatureComponent

user-card.component.ts (before)
@Component({
  selector: 'app-user-card',
  template: `
    <div *ngIf="user">
      <h2>{{ user.name }}</h2>
      <p *ngFor="let r of user.roles">
        {{ r }}
      </p>
    </div>
  `
})
export class UserCardComponent {
  @Input() user: User | null = null;
}
user-card.component.ts (after)
@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [NgIf, NgFor], // or @if/@for
  template: `
    @if (user) {
      <div>
        <h2>{{ user.name }}</h2>
        @for (r of user.roles; track r) {
          <p>{{ r }}</p>
        }
      </div>
    }
  `
})
export class UserCardComponent {
  @Input() user: User | null = null;
}

Step 3 — Update main.ts

main.ts (before)
import { platformBrowserDynamic }
  from '@angular/platform-browser-dynamic';
import { AppModule } from './app/app.module';

platformBrowserDynamic()
  .bootstrapModule(AppModule)
  .catch(err => console.error(err));
main.ts (after)
import { bootstrapApplication }
  from '@angular/platform-browser';
import { AppComponent }
  from './app/app.component';
import { appConfig }
  from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch(err => console.error(err));
app.config.ts (new file)
export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(
      withInterceptors([authInterceptor])
    ),
    provideAnimationsAsync(),
    // UserService with providedIn:'root' needs no entry here
  ]
};

Step 4 — Remove AppModule

Once all components are standalone and main.ts uses bootstrapApplication, the AppModule file can be deleted entirely.
DELETE THESE FILES
✕ app.module.ts
✕ shared.module.ts
✕ admin/admin.module.ts
✕ user/user.module.ts
WHAT TAKES THEIR PLACE
✓ app.config.ts → app-wide providers
✓ admin/admin.routes.ts → route config
✓ user/user.routes.ts → route config
✓ Each component imports its own deps

Step 5 — Lazy Feature Route File

Old lazy module route
// app.routes.ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.module')
      .then(m => m.AdminModule)
}
New lazy routes file
// app.routes.ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes')
      .then(r => r.ADMIN_ROUTES)
}
admin/admin.routes.ts
import { Routes } from '@angular/router';

export const ADMIN_ROUTES: Routes = [
  {
    path: '',
    loadComponent: () =>
      import('./dashboard/admin-dashboard.component')
        .then(c => c.AdminDashboardComponent)
  },
  {
    path: 'users',
    loadComponent: () =>
      import('./users/admin-users.component')
        .then(c => c.AdminUsersComponent)
  }
];
Migration complete. No NgModules remain. Each route is a separate chunk. Components own their dependencies. The app is leaner, easier to understand, and tree-shakes better.
