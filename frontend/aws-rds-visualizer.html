RDS — Relational Database Service

RDS is a managed relational database service. AWS handles provisioning, patching, backups, and failover — you focus on your schema and queries. Supports PostgreSQL, MySQL, MariaDB, Oracle, SQL Server, and Aurora.

What is RDS — and how does AWS managing your database infrastructure free you to focus on schema design and Spring Data JPA?

RDS (Relational Database Service) is AWS's managed relational database offering. Instead of provisioning a server, installing PostgreSQL, configuring replication, setting up backup scripts, and monitoring disk space yourself — AWS handles all of that. You create an RDS instance, get a connection endpoint, and focus on your schema and queries. RDS supports PostgreSQL, MySQL, MariaDB, Oracle, SQL Server, and Aurora (AWS's proprietary MySQL/PostgreSQL-compatible engine). For CIAM/Spring Boot: PostgreSQL is the default choice — best standards compliance, excellent JSONB support (store auth provider metadata as JSON), rich extension ecosystem, citext for case-insensitive email lookups. Multi-AZ deployment: RDS provisions a primary instance in one AZ and a synchronous standby replica in a different AZ. Every write to the primary is committed to the standby before returning success (synchronous). If the primary fails: RDS detects the failure, promotes the standby, updates the DNS endpoint to point to the new primary. Failover typically completes in 60-120 seconds. Your Spring Boot app reconnects automatically (HikariCP connection pool retries). Read Replicas: async replication to one or more read-only copies. Use for read-heavy operations — reporting queries, search, data exports. Important: read replicas can lag behind the primary by milliseconds to seconds. Don't use for reads that need to immediately see a just-written value. RDS Proxy: a connection pooling layer between your app and RDS. Your 10 Spring Boot tasks each open a HikariCP pool of 10 = 100 connections to RDS. RDS Proxy multiplexes those 100 app connections down to 10 actual database connections. Critical for Lambda functions (each cold start opens a new connection, potentially exhausting RDS's connection limit). Secrets Manager integration: RDS can automatically rotate the database master password in Secrets Manager every N days. Spring Boot reads the password from Secrets Manager at startup and on cache miss — no restarts during rotation.

Read Replica — what it IS
  • Scales read throughput horizontally
  • Can be in a different Region (cross-region replica)
  • Can be promoted to standalone DB manually
  • Has its own endpoint URL — you must configure your app to use it for reads
Read Replica — what it IS NOT
  • Not an automatic failover target (that's Multi-AZ standby)
  • Not zero-lag — there's replication lag (seconds to minutes)
  • Not a backup strategy — use automated backups for that

4 — Spring Boot Configuration

# application.yml — RDS PostgreSQL configuration spring: datasource: # RDS endpoint — DNS auto-updates after failover url: jdbc:postgresql://${DB_HOST}:${DB_PORT:5432}/${DB_NAME}?sslmode=require username: ${DB_USERNAME} password: ${DB_PASSWORD} # inject via AWS Secrets Manager driver-class-name: org.postgresql.Driver # HikariCP connection pool (Spring Boot default) hikari: minimum-idle: 5 maximum-pool-size: 20 # match your DB instance max_connections connection-timeout: 30000 # 30s — don't hang forever idle-timeout: 600000 # 10 min idle before closing max-lifetime: 1800000 # 30 min — recycle connections keepalive-time: 30000 # important for RDS — prevents dropped connections jpa: database-platform: org.hibernate.dialect.PostgreSQLDialect hibernate: ddl-auto: validate # never "create-drop" in production! properties: hibernate: jdbc.batch_size: 50 # batch inserts for performance order_inserts: true # Grab credentials from AWS Secrets Manager at startup # (spring-cloud-aws-starter-secrets-manager) spring.config.import: aws-secretsmanager:/prod/myapp/db

Never hardcode credentials. Store the DB password in AWS Secrets Manager. Spring Cloud AWS can inject secrets directly into Spring's Environment at startup — the app reads them as normal ${DB_PASSWORD} properties.

5 — Supported Engines

PostgreSQL
v14, v15, v16
Best choice for Spring Boot + JPA. Full ACID, JSON support (jsonb), excellent Hibernate dialect. Most Java shops use this.
MySQL
v8.0
Legacy or LAMP-stack apps. Spring Boot works fine. InnoDB engine. Consider Aurora MySQL as an upgrade path.
Aurora PostgreSQL
Serverless v2
AWS-native PostgreSQL-compatible. 5× faster than standard RDS PG. Shared storage cluster — replicas share the same volume. Auto-scaling storage.
Aurora MySQL
v3 (MySQL 8.0)
AWS-native MySQL-compatible. Faster, better HA than standard RDS MySQL. Used heavily in AWS-native apps.
MariaDB
v10.11
MySQL fork. Used when migrating from self-hosted MariaDB. Similar Spring Boot config to MySQL.
SQL Server
2019, 2022
For .NET/enterprise shops. RDS handles licensing. Spring Boot works via JDBC. Most expensive option.

6 — Key RDS Features

FeatureHow it works
Automated BackupsDaily snapshots + continuous transaction log backup. Point-in-time recovery to any second within your retention period (1–35 days). Stored in S3.
Manual SnapshotsOn-demand snapshot of the entire DB instance. Retained until you delete them. Use before schema migrations as a safety net.
Multi-AZSynchronous standby in a second AZ. Auto failover in ~60–120s. Your app reconnects via same DNS hostname. +$$ but required for production.
Read ReplicasAsync replicas for read-heavy workloads. Up to 5 replicas per instance. Can be cross-region. Your app needs separate datasource URL for reads.
Parameter GroupsDB engine configuration (max_connections, shared_buffers, work_mem). Apply without instance replacement for most params.
Secrets ManagerRDS can automatically rotate DB passwords in Secrets Manager every N days. Your app reads the secret — no downtime during rotation.
Performance InsightsVisual DB performance dashboard. Shows top SQL by load, wait events, DB connections. Free for 7 days retention.
Enhanced MonitoringOS-level metrics (CPU steal, filesystem) at 1-second granularity. Sends to CloudWatch Logs.
Storage AutoscalingRDS automatically increases storage when you approach capacity. Set a max limit to control costs.
VPC SecurityRDS always runs in your VPC private subnet. Access controlled by Security Groups. Never exposed to the public internet directly.
