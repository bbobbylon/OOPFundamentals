Python: pytest

Plain-assert tests with rich introspection, fixtures as dependency injection, parametrize for table-driven cases, and mocking with monkeypatch — Python's de-facto test framework.

🧫 Why pytest replaced unittest for almost everyone

pytest wins on low ceremony: a test is just a test_* function in a test_*.py file, auto-discovered, asserted with plain assert (rewritten to show actual values on failure). Its headline feature is fixtures — @pytest.fixture functions a test requests by naming them as parameters (DI for setup), which can yield a value and run teardown after, with a configurable scope; shared ones live in conftest.py. @pytest.mark.parametrize turns one test into a table of cases, and monkeypatch/mock handle fakes.

  • Zero ceremony — test_* functions, plain assert with rich failure diffs.
  • Fixtures = DI for setup — request by parameter; yield + teardown; scoped.
  • parametrize = table-driven tests — one test, many reported rows.
  • Mock with monkeypatch/mock — auto-undone patches.

Plain assert + parametrize

import pytest @pytest.mark.parametrize("n, want", [ (3, 3), (-3, 3), (0, 0), ]) def test_abs(n, want): assert my_abs(n) == want # 3 separate test cases, each named # failure prints: assert -3 == 3

Fixture with setup/teardown

@pytest.fixture def db(): conn = connect(":memory:") # setup yield conn # given to test conn.close() # teardown def test_insert(db): # requests the fixture db.execute("INSERT ...") assert db.count() == 1

pytest vs JUnit

JUnit: @Test, assertEquals(a,b), @BeforeEach/@AfterEach, Mockito. pytest: name a function test_*, plain assert (with rich diffs), fixtures-as-parameters instead of lifecycle annotations, and monkeypatch/mock for fakes. Fixtures compose (a fixture can request other fixtures) and pick scope, which is more flexible than per-class setup methods. Same goals, far less boilerplate.

CIAM context: A session-scoped fixture spins up an in-memory test DB or fake IdP and injects it everywhere. parametrize is ideal for a claim→authority mapper — one test, a row per IdM shape (Entra roles, Ping group, Keycloak realm_access.roles). And monkeypatch.setattr(jwks, "fetch", fake) keeps token-validation tests fast and offline — never hitting a real IdP in CI.

1. Discovery & Plain assert

# test_math.py — discovered automatically
def test_add():
  assert add(2, 2) == 4

def test_add_fails():
  assert add(2, 2) == 5
# E assert 4 == 5 ← pytest shows the real values

# run everything: pytest -q

pytest collects files matching test_*.py and functions/methods named test_* — no base class, no registration. You write the bare assert keyword; pytest's assertion rewriting inspects the expression and prints the operands on failure (lists/dicts get a diff). Compare to unittest's self.assertEqual(a, b) — pytest needs none of that vocabulary.

Test expected exceptions with pytest.raises: with pytest.raises(ValueError, match="bad token"): parse(raw). The block passes only if that exception is raised and (optionally) its message matches the regex — the clean way to assert your code rejects bad input.

2. Fixtures = Dependency Injection for Tests

# conftest.py — auto-shared, no import needed
@pytest.fixture(scope="session")
def db():
  conn = connect(":memory:") # setup
  yield conn # hand to tests
  conn.close() # teardown after

def test_user(db): # requests db by name
  db.execute("INSERT ...")

A test names a fixture as a parameter; pytest builds it and injects the result. yield splits setup (before) from teardown (after). Scope controls reuse: function (default, fresh each test), class, module, or session (built once for the whole run — perfect for an expensive DB/IdP). Fixtures can request other fixtures, so they compose into a dependency graph. Put shared ones in conftest.py and every test in that directory tree sees them automatically.

Built-in fixtures you get for free: tmp_path (a unique temp dir), capsys (capture stdout/stderr), monkeypatch (patching, auto-undone), and caplog (assert on log records). Request them by name like any fixture — no setup required.

3. parametrize — Table-Driven Tests

@pytest.mark.parametrize("idm, claims, want", [
  ("entra", {"roles": ["Admin"]}, ["ROLE_ADMIN"]),
  ("keycloak", {"realm_access": {"roles": ["user"]}}, ["ROLE_USER"]),
  ("ping", {"group": "admins"}, ["ROLE_ADMIN"]),
], ids=["entra", "keycloak", "ping"])
def test_map_authorities(idm, claims, want):
  assert map_authorities(idm, claims) == want
Each row is its own reported test (test_map_authorities[entra]), so one failing IdM doesn't hide the others and you can re-run just one with pytest -k entra. Stack two parametrize decorators and pytest runs the cartesian product — handy for matrix testing (every IdM × every role).
