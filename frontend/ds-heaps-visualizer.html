Heaps & Priority Queues

Complete binary tree stored as an array. O(log n) insert/delete, O(1) peek at min/max.

What is a heap — and why does it give O(1) access to the maximum or minimum while keeping insertion at O(log n)?

A heap is a complete binary tree stored as an array that maintains the heap property. In a max-heap: every parent is GREATER THAN OR EQUAL TO its children. This means the maximum value is always at the root — accessible in O(1). In a min-heap: every parent is LESS THAN OR EQUAL TO its children — minimum at the root in O(1). The brilliant trick: storing a binary tree in an array without pointers. For a node at index i: left child is at index 2i + 1, right child at 2i + 2, parent at (i-1) / 2. No null pointers, no Node class — just arithmetic on array indices. Insert (O(log n)): add the new value at the end of the array (end of tree), then "sift up" — swap with parent while the heap property is violated. Worst case: new value bubbles all the way to root = tree height = log n. Extract max/min (O(log n)): remove the root (that's the max/min), replace it with the last element in the array, then "sift down" — swap with the larger/smaller child while heap property is violated. Worst case: element sifts all the way to a leaf = log n swaps. Peek (O(1)): just return the first element of the array — always the max (or min). This is the heap's superpower vs BST: BST takes O(log n) to find the max (traverse all the way right). Heap's max/min is instant. Priority Queue (Java's PriorityQueue): implements a min-heap. poll() always returns the smallest element. Pass a custom Comparator to change to max-heap or to define your own ordering. Heapify: building a heap from n random elements takes O(n) — not O(n log n) as you might expect. The algorithm: start from the last non-leaf and sift down each element. This is used in Heap Sort (O(n log n) guaranteed, O(1) space — in-place).

Java PriorityQueue

// Java PriorityQueue = min-heap by default // poll() always returns smallest element PriorityQueue<Integer> minHeap = new PriorityQueue<>(); minHeap.offer(30); minHeap.offer(10); minHeap.offer(50); minHeap.peek(); // 10 (min) — O(1) minHeap.poll(); // 10 removed — O(log n) // Max-heap: reverse order PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder()); // OR: (a, b) -> b - a // Custom ordering (by login time): PriorityQueue<UserSession> byExpiry = new PriorityQueue<>( Comparator.comparing(UserSession::getExpiresAt) ); // poll() = session expiring soonest // Use case: expire oldest sessions when at capacity // K elements: top K most active users PriorityQueue<User> topK = new PriorityQueue<>(k, (a,b) -> a.loginCount - b.loginCount); // Keep only K elements: if size > K, poll()

Heap vs sorted array vs BST

// Operation | Heap | Sorted Array | BST (balanced) // -----------|----------|--------------|--------------- // Find max | O(1) | O(1) (end) | O(log n) // Find min | O(1) | O(1) (start) | O(log n) // Insert | O(log n) | O(n) (shift) | O(log n) // Delete max | O(log n) | O(1) (end) | O(log n) // Search | O(n) | O(log n) | O(log n) // Sort all | O(n log n)| already sorted| O(n) in-order // When to use each: // Need frequent min/max + insert + delete // → HEAP (PriorityQueue) // Need to find arbitrary values by key // → BST (TreeMap) or HashMap // Need sorted order + search // → Sorted Array + binary search // Classic heap use cases: // 1. Dijkstra's shortest path // 2. Top K elements // 3. Merge K sorted lists // 4. Median maintenance (two heaps: max + min) // 5. Job scheduling by priority // 6. Session expiry management (CIAM)

In CIAM / Context: Heaps appear in CIAM systems when managing session expiry: a min-heap keyed by expiry time gives O(1) access to the session expiring soonest. When the session cleanup job runs, it polls the heap — popping all expired sessions in O(k log n) where k is the number expired. Spring's TaskScheduler uses a priority queue internally to fire scheduled tasks in the right order. Rate limiting (Ping's token endpoint) often uses a min-heap of timestamps for sliding window calculations.

Insert (sift up) & Extract-Min (sift down)

// Insert: add to end, sift UP void insert(int val) { heap.add(val); siftUp(heap.size() - 1); } void siftUp(int i) { while (i > 0) { int parent = (i - 1) / 2; if (heap[i] < heap[parent]) { swap(i, parent); // bubble up i = parent; } else break; // heap property restored } }
// Extract-min: swap root with last, remove, sift DOWN int extractMin() { int min = heap[0]; heap[0] = heap.remove(heap.size() - 1); siftDown(0); return min; } void siftDown(int i) { int n = heap.size(); while (2*i+1 < n) { int j = 2*i+1; // left child if (j+1<n && heap[j+1]<heap[j]) j++; // pick smaller child if (heap[i] <= heap[j]) break; swap(i, j); i = j; } }

Heap Sort — O(n log n) time, O(1) space

// Phase 1: Build max-heap from array — O(n) // Start from last non-leaf and sift down void buildMaxHeap(int[] arr) { for (int i = arr.length/2 - 1; i >= 0; i--) { siftDown(arr, i, arr.length); } } // Phase 2: Extract elements in order — O(n log n) void heapSort(int[] arr) { buildMaxHeap(arr); // max at arr[0] for (int end = arr.length - 1; end > 0; end--) { swap(arr, 0, end); // move max to end siftDown(arr, 0, end); // restore heap on reduced array } // arr is now sorted ascending! } // Why not used in practice? // - Poor cache performance (sifting jumps around memory) // - Not stable // - Quicksort is faster in practice // - Merge sort is stable and nearly as fast // - Java Arrays.sort() uses TimSort (merge + insertion)

Java PriorityQueue — min-heap by default

// Min-heap (natural ordering) PriorityQueue<Integer> minHeap = new PriorityQueue<>(); minHeap.offer(5); // add minHeap.offer(2); minHeap.offer(8); minHeap.peek(); // 2 — view min, no remove minHeap.poll(); // 2 — remove and return min minHeap.size(); // 2 // Max-heap — reverse comparator PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder()); // Or with Comparator.reverseOrder() PriorityQueue<Integer> max2 = new PriorityQueue<>((a, b) -> b - a);
// Custom objects — sort by field PriorityQueue<Task> tasks = new PriorityQueue<>( Comparator.comparingInt(Task::getPriority) ); tasks.offer(new Task("low", 5)); tasks.offer(new Task("urgent", 1)); tasks.offer(new Task("medium", 3)); tasks.poll(); // Task{urgent, priority=1} // Note: iteration order is NOT guaranteed sorted // Only poll() gives sorted order // PQ doesn't allow O(1) search or update-key
