Go Generics (Go 1.18+)

Type parameters, constraints (interfaces as type sets), type inference, generic functions and types, and the golang.org/x/exp/slices and maps packages — Go generics from syntax to practical use.

📦 What are Go generics — and how are they different from Java or TypeScript generics?

Go added generics in 1.18 (2022) — before them, multi-type code used interface{} (no safety) or codegen. Type parameters declare them — func Map[T, U any](s []T, fn func(T) U) []U — and Go usually infers them from arguments. Constraints are interfaces-as-type-sets: type Number interface { ~int | ~float64 } (the ~ means "underlying type"), plus built-ins comparable/any/constraints.Ordered. Whole types can be generic too (type Result[T any] struct { Value T; Err error }), and the slices/maps packages ship generic utilities (slices.SortFunc, maps.Keys). Go generics are simpler than Java's (no wildcards/HKT) and use monomorphization — a copy per type, like C++ templates — not Java's erasure.

  • Type parameters, usually inferred — write Map(users, fn), not the types.
  • Constraints = type sets — ~int | ~float64; comparable/any/Ordered.
  • Generic types too — Result[T], Cache[K comparable, V any].
  • Monomorphized, not erased — a copy per type; no generic methods.

Generic functions

// Generic Map: transform slice func Map[T, U any](s []T, fn func(T) U) []U { result := make([]U, len(s)) for i, v := range s { result[i] = fn(v) } return result } // Generic Filter: func Filter[T any](s []T, pred func(T) bool) []T { var out []T for _, v := range s { if pred(v) { out = append(out, v) } } return out } // Usage (type parameters inferred): emails := Map(users, func(u User) string { return u.Email }) // emails: []string admins := Filter(users, func(u User) bool { return contains(u.Roles, "CIAM_ADMIN") })

Constraints + generic types

// Constraint: only ordered types type Ordered interface { ~int | ~int64 | ~float64 | ~string } func Min[T Ordered](a, b T) T { if a < b { return a } return b } // Generic Result type: type Result[T any] struct { Value T Err error } func OK[T any](v T) Result[T] { return Result[T]{Value: v} } func Fail[T any](e error) Result[T] { return Result[T]{Err: e} } // Use with any type: r := OK(user) // Result[*User] r2 := OK(42) // Result[int] // Generic cache: type Cache[K comparable, V any] struct { mu sync.RWMutex m map[K]V }

Java/TypeScript comparison

Go generics → Java/TypeScript. func Map[T, U any](s []T, fn func(T)U) []U → Java: <T, U> List<U> map(List<T> list, Function<T, U> fn) → TypeScript: function map<T, U>(arr: T[], fn: (x: T) => U): U[]. Constraint [T comparable] → Java: <T extends Comparable<T>> → TypeScript: no direct equivalent (use conditional types). Go's ~int (underlying type) has no Java/TS equivalent. Java generics are erased at runtime (type erasure) — generics only exist in source code. Go generics use monomorphization — a separate function is generated per type substitution (like C++ templates, but at compile time). TypeScript generics are erased at compile time. Key Go limitation: no generic methods (only generic functions and types) — func (c *Cache[K,V]) Get(k K) works, but you can't add a generic type parameter to a method that wasn't on the struct.

CIAM Go service: A generic Cache[K comparable, V any] serves both Cache[string, *rsa.PublicKey] (JWKS keys) and Cache[string, *User] (sessions) from one type; a generic Page[T any] covers Page[User]/Page[AuditEvent]/Page[Session] — before 1.18 you'd write a type for each. The slices package cleans up user management (slices.SortFunc(users, func(a, b User) int { return cmp.Compare(a.Email, b.Email) })) with less reflection than sort.Slice.

1. Before Generics vs After

Before: copy-paste or interface{}

// Need a Map for int slice AND string slice
func MapInts(s []int, f func(int) int) []int {
  result := make([]int, len(s))
  for i, v := range s { result[i] = f(v) }
  return result
}
func MapStrings(s []string, f func(string) string) []string {
  // identical logic...
}

After: one generic Map

// One function, all types
func Map[T, U any](s []T, f func(T) U) []U {
  result := make([]U, len(s))
  for i, v := range s { result[i] = f(v) }
  return result
}

Map([]int{1,2,3}, func(x int) int { return x*2 })
Map([]string{"a","b"}, strings.ToUpper)

2. Constraints as Type Sets

// constraints.Ordered: all comparable + ordered types
type Ordered interface {
  ~int | ~int8 | ~int16 | ~int32 | ~int64 |
  ~float32 | ~float64 | ~string
}

func Min[T Ordered](a, b T) T {
  if a < b { return a }
  return b
}
// ~ means "underlying type"
type Celsius float64
type Fahrenheit float64

// ~float64 includes Celsius AND Fahrenheit
// because their underlying type is float64
Min(Celsius(37.0), Celsius(36.5)) // ✅ works
Min(37.0, Celsius(36.5)) // ✗ mixed types

The ~ prefix means "any type whose underlying type is X." Without ~, only the exact type matches. With ~, named types built on float64 also match.

Constraints are interfaces used as type sets. A constraint can list: allowed types (int | string), method requirements (Stringer), or both. any is interface{} — no constraint. comparable allows == and != (needed for map keys).

3. Generic Types (Data Structures)

// Generic Stack — works with any type
type Stack[T any] struct {
  items []T
}
func (s *Stack[T]) Push(v T) {
  s.items = append(s.items, v)
}
func (s *Stack[T]) Pop() (T, bool) {
  if len(s.items) == 0 {
    var zero T; return zero, false
  }
  n := len(s.items)-1
  v := s.items[n]; s.items = s.items[:n]
  return v, true
}
// Type must be specified for generic types (no inference)
s := &Stack[int]{} // int stack
s.Push(42)
s.Push(99)
v, ok := s.Pop() // v=99, ok=true

bs := &Stack[string]{} // string stack
bs.Push("hello")
// s.Push("hello") — COMPILE ERROR: string ≠ int

Generic types require explicit type argument at instantiation. Methods on generic types use [T] in the receiver: func (s *Stack[T]) Push(v T). The zero value trick (var zero T; return zero) returns the zero value of any type.
