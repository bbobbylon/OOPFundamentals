Configuration & Profiles

application.properties vs .yml, @Value, @ConfigurationProperties, and how profiles target dev/staging/prod environments.

1 — application.properties vs application.yml

Same configuration — two formats. Toggle to compare:

server.port=8080 server.servlet.context-path=/api spring.datasource.url=jdbc:postgresql://localhost:5432/myapp spring.datasource.username=dbuser spring.datasource.password=secret spring.jpa.hibernate.ddl-auto=validate spring.jpa.show-sql=false logging.level.com.example=INFO logging.level.org.springframework.security=WARN management.endpoints.web.exposure.include=health,info,metrics
server: port: 8080 servlet: context-path: /api spring: datasource: url: jdbc:postgresql://localhost:5432/myapp username: dbuser password: secret jpa: hibernate: ddl-auto: validate show-sql: false logging: level: com.example: INFO org.springframework.security: WARN management: endpoints: web: exposure: include: health,info,metrics

Both formats work identically. YAML is more readable for nested config (less repetition of prefixes). Properties is simpler for flat config. Spring Boot supports both — choose one and be consistent.

2 — Spring Profiles

Click a profile to see which properties are active (green) vs overridden (strikethrough):

application.properties (always loaded)

server.port=8080
app.name=MyApp
logging.level.root=INFO
spring.jpa.show-sql=false

application-dev.properties

server.port=9090
spring.datasource.url=jdbc:h2:mem:devdb
spring.jpa.show-sql=true
logging.level.root=DEBUG

application-prod.properties

server.port=8080
spring.datasource.url=${PROD_DB_URL}
spring.jpa.show-sql=false
logging.level.root=WARN

Effective Configuration:

Activate with: -Dspring.profiles.active=prod (JVM arg) or SPRING_PROFILES_ACTIVE=prod (env var).
Profile properties OVERRIDE base properties. Multiple profiles: -Dspring.profiles.active=prod,logging.

3 — @Value vs @ConfigurationProperties

@Value — single values

@Service public class EmailService { @Value("${app.smtp.host}") private String host; @Value("${app.smtp.port:587}") // :587 = default private int port; @Value("${app.smtp.username}") private String username; }

Good for: one or two related values. Downside: scattered, harder to see all config for a feature, no auto-completion in some IDEs.

@ConfigurationProperties — groups

@ConfigurationProperties(prefix = "app.smtp") @Component public class SmtpProperties { private String host; private int port = 587; // default private String username; // getters + setters } // application.yml: // app.smtp.host=smtp.example.com // app.smtp.port=465 // app.smtp.username=noreply@example.com

Good for: groups of related config. Type-safe. IDE auto-completion. Validated with @Validated + JSR-303 annotations.

4 — Common Properties Reference

PropertyWhat it does
server.portHTTP port (default: 8080)
server.servlet.context-pathURL prefix for all endpoints (default: /)
spring.datasource.urlJDBC connection URL
spring.datasource.username/passwordDatabase credentials
spring.jpa.hibernate.ddl-autonone | validate | update | create | create-drop
spring.jpa.show-sqlLog every SQL query to console (true in dev, false in prod)
spring.profiles.activeWhich profile(s) to activate
logging.level.{package}Log level for a package: TRACE DEBUG INFO WARN ERROR
spring.security.oauth2.resourceserver.jwt.issuer-uriJWT issuer URI for token validation (Entra ID, PingFederate)
management.endpoints.web.exposure.includeWhich Actuator endpoints to expose (health,info,metrics,*)
spring.application.nameApp name used in logs, service discovery, and /actuator/info
