Trees — Coding Practice

Six classic binary tree problems — real node traversal, not array shortcuts. Real code, real hidden tests.

Trees are given to you the same way Linked Lists were: a plain array in, a real node structure inside your function. A test like [3, 9, 20, null, null, 15, 7] is LeetCode's standard level-order encoding — read left to right, top row first; a null means "no node here," and (importantly) a null's own children are never listed, since it has none. This page builds a real { val, left, right } node structure from that array before calling your function, and — for the one problem that returns a tree — converts whatever you return back into the same array format automatically.

Need to build a brand-new node? In JavaScript/TypeScript that's a plain object: { val: x, left: null, right: null }. In Python, a TreeNode class is already provided in the starter code. Pick a language tab, write the function, press Run Tests. Stuck? Use a hint, or jump to the Trees visualizer for the underlying technique.
