Map, Set, WeakMap & WeakSet

JavaScript's built-in collection types — when to use them, how they work, and TypeScript typing for all of them

🗂️ What are Map and Set? Why not just use arrays and objects?

JavaScript already has arrays and plain objects, so why Map and Set? Because arrays and objects have real limitations: Array.includes() is O(n), object keys get coerced to strings, plain objects carry inherited keys like toString that can collide with your data, and getting an object's size means Object.keys(obj).length. Map and Set fix all four — O(1) lookups, any key type, a clean key space, and a free .size.

  • Set.has() is O(1) — checking membership in 10,000 IDs is instant, unlike Array.includes().
  • Map keys can be any type — numbers, symbols, even objects (plain objects coerce keys to strings).
  • Maps have no inherited keys — no toString collisions like a plain object.
  • Map.size is O(1) — versus Object.keys(obj).length.

Map — key→value store

A dictionary/hashmap where keys can be any type and insertion order is guaranteed. Use it to look things up by a runtime key (user ID, token, DOM element).

Set — unique values

An array that auto-removes duplicates, with O(1) .has(). Perfect for permission sets, deduplication, and set algebra (union / intersection / difference).

WeakMap / WeakSet — GC-friendly

Like Map/Set but keys are held weakly — the GC can reclaim them once the object has no other references. No leaks for per-request or per-DOM metadata.

CIAM / Spring / Angular: Session caches keyed by token.sub (Map), deduplicating permission lists (Set), per-request auth context in middleware (WeakMap), and tracking processed event IDs to prevent replays (Set).

Map vs Plain Object — Know When to Use Each

FeatureMap<K, V>Plain Object { [key: string]: V }
Key typesAny type — object, function, symbol, numberOnly string or symbol (numbers coerced to string)
Insertion orderAlways preservedPreserved for string keys (spec-defined in modern JS)
Sizemap.size — O(1)Object.keys(obj).length — O(n)
IterationDirectly iterable: for...of, .forEach()Need Object.keys/values/entries()
Prototype pollutionNo built-in keys (clean)Inherits from Object.prototype (toString, hasOwnProperty…)
JSONNot JSON-serializable directlyJSON.stringify works natively
PerformanceFaster for frequent add/deleteBetter for small, static collections

Rule of thumb: Use Map when keys are dynamic, non-string, or when you need size/iteration. Use object for known-shape data (DTOs, config).

Map<K, V> — Complete API

All Map methods

// TypeScript — Map is generic over key AND value
const scores = new Map<string, number>();

// set(key, value) → Map (chainable)
scores.set('Alice', 95);
scores.set('Bob', 87);
scores.set('Alice', 99); // overwrites — keys are unique

// get(key) → V | undefined
scores.get('Alice'); // 99
scores.get('Eve');   // undefined

// has(key) → boolean
scores.has('Bob');  // true

// delete(key) → boolean (true if key existed)
scores.delete('Bob'); // true

// size → number
scores.size; // 1

// clear() → void
scores.clear();

// Initialize from entries
const m = new Map([
  ['a', 1], ['b', 2], ['c', 3]
]);

Iteration — 4 ways

const m = new Map([
  ['x', 10], ['y', 20], ['z', 30]
]);

// 1. for...of entries (most common)
for (const [key, val] of m) {
  console.log(key, val); // 'x' 10, 'y' 20, 'z' 30
}

// 2. .forEach()
m.forEach((val, key) => console.log(key, val));

// 3. keys() / values() / entries() iterators
[...m.keys()];    // ['x', 'y', 'z']
[...m.values()];  // [10, 20, 30]
[...m.entries()]; // [['x',10],['y',20],['z',30]]

// 4. Spread into array of entries
const arr = [...m]; // [['x',10],['y',20],['z',30]]

// Convert Map → Object and back
const obj = Object.fromEntries(m);  // {x:10, y:20, z:30}
const m2  = new Map(Object.entries(obj));

Map as cache / memoization

function memoize<K, V>(
  fn: (key: K) => V
): (key: K) => V {
  const cache = new Map<K, V>();
  return (key) => {
    if (cache.has(key)) return cache.get(key)!;
    const result = fn(key);
    cache.set(key, result);
    return result;
  };
}

const expensiveCalc = memoize((n: number) => {
  console.log('computing...');
  return n * n;
});

expensiveCalc(5); // computing... → 25
expensiveCalc(5); // (cached) → 25

Map as frequency counter

function frequency<T>(arr: T[]): Map<T, number> {
  const freq = new Map<T, number>();
  for (const item of arr) {
    freq.set(item, (freq.get(item) ?? 0) + 1);
  }
  return freq;
}

const votes = ['A','B','A','C','B','A'];
const tally = frequency(votes);
// Map { 'A' → 3, 'B' → 2, 'C' → 1 }

// Find winner
const winner = [...tally.entries()]
  .reduce((a, b) => a[1] > b[1] ? a : b)[0]; // 'A'

WeakMap — Object-keyed, GC-friendly

WeakMap rules & use cases

Keys must be objects (or non-registered symbols). If the key object has no other references, it gets garbage collected — and the WeakMap entry disappears automatically. No memory leak.

const wm = new WeakMap<object, string>();

let user = { id: 1 };
wm.set(user, 'admin');
wm.get(user);   // 'admin'
wm.has(user);   // true
wm.delete(user);

// When the key object goes out of scope:
user = null! // → GC can collect { id: 1 }
// → WeakMap entry also disappears ✓

// ⚠ No .size, no .keys(), not iterable
// (GC timing is non-deterministic — can't enumerate)
✓ Private instance data (classes without private fields)
✓ DOM node → metadata (listener tracking, event data)
✓ Library internals that must not prevent GC
✗ Anything that needs iteration or size

Classic WeakMap pattern: private class data

// Before TypeScript private fields (#)
// WeakMap was THE way to have true privacy

const _balance = new WeakMap<BankAccount, number>();

class BankAccount {
  constructor(initial: number) {
    _balance.set(this, initial);
  }
  deposit(n: number) {
    _balance.set(this, _balance.get(this)! + n);
  }
  getBalance() { return _balance.get(this)!; }
}

const acc = new BankAccount(100);
acc.deposit(50);
acc.getBalance(); // 150
// (acc as any)._balance → undefined — truly private!

// Modern equivalent with native private fields:
class BankAccount2 {
  #balance: number;
  constructor(n: number) { this.#balance = n; }
}

Set<T> — Unique Value Collections

Set API — all methods

const tags = new Set<string>(['js', 'ts', 'rxjs']);

// add(value) → Set (chainable)
tags.add('angular');
tags.add('js'); // duplicate — ignored silently

// has(value) → boolean
tags.has('ts');  // true
tags.has('vue'); // false

// delete(value) → boolean
tags.delete('rxjs'); // true

// size
tags.size; // 3

// iteration (insertion order preserved)
for (const tag of tags) { console.log(tag); }
[...tags]; // ['js', 'ts', 'angular']

// Deduplicate an array — one liner!
const unique = [...new Set([1,2,2,3,3,3])]; // [1,2,3]

Set Algebra — union, intersection, difference

const A = new Set([1,2,3,4]);
const B = new Set([3,4,5,6]);

// Union — everything in A or B
const union = new Set([...A, ...B]);
// {1,2,3,4,5,6}

// Intersection — only in both A and B
const intersection = new Set(
  [...A].filter(x => B.has(x))
);
// {3,4}

// Difference A∖B — in A but not B
const diffAB = new Set(
  [...A].filter(x => !B.has(x))
);
// {1,2}

// Symmetric difference — in one but not both
const symDiff = new Set([
  ...[...A].filter(x => !B.has(x)),
  ...[...B].filter(x => !A.has(x))
]);
// {1,2,5,6}

// Superset / subset checks
const isSubset = (a: Set<any>, b: Set<any>) =>
  [...a].every(x => b.has(x));

WeakSet — Tracking Objects Without Leaking

WeakSet API

const ws = new WeakSet<object>();

const elem = document.getElementById('btn')!;
ws.add(elem);
ws.has(elem);    // true
ws.delete(elem); // true

// ⚠ No .size, no iteration
// Keys must be objects
✓ "Have I processed this object?" checks
✓ Circular reference guards
✓ Visitor pattern — mark visited nodes in graph traversal

Real use case: seen object guard

// Safely serialize circular structures
function safeStringify(obj: unknown): string {
  const seen = new WeakSet();
  return JSON.stringify(obj, (_, value) => {
    if (typeof value === 'object' && value !== null) {
      if (seen.has(value)) return '[Circular]';
      seen.add(value);
    }
    return value;
  });
}

// Graph traversal — never revisit a node
function dfs(node: Node) {
  const visited = new WeakSet<Node>();
  function visit(n: Node) {
    if (visited.has(n)) return;
    visited.add(n);
    // process n...
    n.children.forEach(visit);
  }
  visit(node);
}
