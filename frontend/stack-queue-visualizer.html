Stack & Queue — LIFO vs FIFO

Two ways to manage a sequence of items, plus the real-world systems built on top of them.

🧩 What is a Stack vs Queue — and why does the order items come out completely change what problems each one solves?

Stacks and Queues are both linear data structures that manage sequences of items, but they differ in one critical way: the order in which items are removed. This one difference makes them suited for entirely different problem categories. Stack (LIFO — Last In, First Out): the most recently added item is the first to be removed. Like a stack of plates — you always add and remove from the top. Core operations: push(item) (add to top), pop() (remove from top), peek() (see top without removing). O(1) for all. Analogy: your browser's back button. Every page you visit is pushed onto a history stack. Pressing Back pops the most recent page. Queue (FIFO — First In, First Out): the oldest item is the first to be removed. Like a queue at a coffee shop — first person in line is served first. Core operations: offer(item) / enqueue (add to back), poll() / dequeue (remove from front), peek() (see front without removing). O(1) for all. When each applies: use a Stack when you need to reverse order, track "where you came from" (undo/back), evaluate nested structures (matching brackets, recursive call tracking), or perform DFS. Use a Queue when you need FAIR ordering (process in arrival order), level-by-level processing, BFS, or producer-consumer decoupling. In Java: the Stack class exists but is legacy (synchronized, slow). For a stack, use ArrayDeque as a stack (push/pop/peek). For a queue, use ArrayDeque as a queue (offer/poll/peek) or LinkedList. ArrayDeque is a double-ended queue (Deque) that can act as BOTH a stack and a queue. Priority Queue: a variant of queue where the highest-priority item (not the oldest) is dequeued first. Backed by a heap. O(log n) offer/poll, O(1) peek. Use for Dijkstra's algorithm, task scheduling by priority, finding the k-largest elements.

Stack — matching brackets

// Classic stack problem: valid parentheses // "({[]})" → valid // "([)]" → INVALID // Rule: every open bracket must be closed // by the CORRESPONDING close bracket boolean isValid(String s) { Deque<Character> stack = new ArrayDeque<>(); for (char c : s.toCharArray()) { if (c=='(' || c=='{' || c=='[') { stack.push(c); // push open brackets } else { if (stack.isEmpty()) return false; // nothing to match char top = stack.pop(); if (c==')' && top!='(') return false; // mismatch if (c=='}' && top!='{') return false; if (c==']' && top!='[') return false; } } return stack.isEmpty(); // all opened must be closed } // Why stack? Last opened bracket must be FIRST closed (LIFO)

Queue — BFS level order

// Queue enables BFS level-order tree traversal // Process all nodes at depth 1, then depth 2, then 3... List<List<Integer>> levelOrder(TreeNode root) { List<List<Integer>> result = new ArrayList<>(); if (root == null) return result; Queue<TreeNode> queue = new LinkedList<>(); queue.offer(root); // start with just the root while (!queue.isEmpty()) { int levelSize = queue.size(); // how many nodes at this level List<Integer> level = new ArrayList<>(); for (int i = 0; i < levelSize; i++) { TreeNode node = queue.poll(); // FIFO: process in order level.add(node.val); if (node.left != null) queue.offer(node.left); if (node.right != null) queue.offer(node.right); } result.add(level); } return result; } // Queue ensures left nodes are processed before right nodes

Java Deque + PriorityQueue

// NEVER use Stack class in modern Java (legacy, slow) // Use ArrayDeque for BOTH stack AND queue // AS A STACK (LIFO): Deque<Integer> stack = new ArrayDeque<>(); stack.push(1); stack.push(2); stack.push(3); stack.pop(); // returns 3 (last in, first out) stack.peek(); // returns 2 (doesn't remove) // AS A QUEUE (FIFO): Deque<Integer> queue = new ArrayDeque<>(); queue.offer(1); queue.offer(2); queue.offer(3); queue.poll(); // returns 1 (first in, first out) queue.peek(); // returns 2 // PRIORITY QUEUE: ordered by priority (min-heap by default) PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0]-b[0]); // min by first element pq.offer(new int[]{5, "task5"}); pq.offer(new int[]{1, "urgent"}); pq.offer(new int[]{3, "normal"}); pq.poll(); // returns [1,"urgent"] — HIGHEST PRIORITY first

In CIAM / Context: Stacks and queues are core to Spring Boot and CIAM architecture. Spring's SecurityFilterChain is a queue of filters — each request passes through them in FIFO order (authentication filter → authorization filter → response filter). The Java call stack (actual program call stack) is a hardware stack — understanding LIFO explains why StackOverflowError happens in deep recursion. Kafka and AWS SQS are distributed queues — FIFO ordering ensures OAuth token revocation events are processed in the order they were emitted. Ping AM's authentication journey is a queue of nodes — a subject traverses them in order. PriorityQueue is used in rate-limiter implementations where high-priority requests (admin vs anonymous) jump ahead in the processing queue.

2. Where you actually see these in real software

Stack — the function call stack

Every method call in any program pushes a "stack frame." When the method returns, its frame is popped. That's why infinite recursion gives you StackOverflowError.

Stack — undo / redo (Ctrl+Z)

Every action you take pushes a state onto the undo stack. Hit Ctrl+Z and the most recent action pops off and reverses.

Stack — bracket matching in parsers

Compilers parse ([{}]) using a stack: push each opener, pop on each closer, and check they match. If the stack isn't empty at the end, you've got a syntax error.

if (c == '(') stack.push(c);
else if (c == ')') {
    if (stack.pop() != '(') return false;
}

Stack — DFS (depth-first search)

Either explicit via a Stack data structure, or implicit via the call stack when written recursively. "Go deep before going wide."

Queue — task / message queues

RabbitMQ, Kafka, SQS, JMS — all queue systems. Producer drops a message in; consumer picks it up in order. Decouples slow work from your fast request path.

Queue — print spoolers

Multiple users send print jobs; the printer handles them one at a time, in arrival order. That's literally a FIFO queue.

Queue — BFS (breadth-first search)

Shortest path on an unweighted graph, level-order tree traversal, social network "people 2 hops away" — all queue-based BFS.

Queue — OS scheduler (round-robin)

Threads/processes waiting for CPU time wait in a queue. Each gets a slice in order, then goes back to the end.

3. Real-world demo — browser back/forward (TWO stacks)

Browser history uses two stacks: one for back, one for forward. Navigating to a new URL pushes the current page onto the back stack and clears forward. Clicking Back pops the back stack and pushes onto forward. Try it:

4. Real-world demo — print spooler (FIFO queue)

Jobs arrive at the printer and queue up. Click "Print next" — it pulls from the FRONT of the queue, just like a coffee shop serves the next person in line. Adding to the back is O(1). Removing from the front is O(1).

Big takeaways

  • Stack ops all happen at ONE end (top): push, pop, peek. All O(1).
  • Queue ops happen at BOTH ends: enqueue at back, dequeue from front. Both O(1) with the right structure.
  • In Java: use ArrayDeque for both — it's faster than Stack (legacy, synchronized) and LinkedList (worse cache behavior).
  • PriorityQueue is a special queue where highest-priority comes out first, not FIFO. Backed by a heap, O(log n) per op.
