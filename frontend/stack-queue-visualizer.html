Stack & Queue — LIFO vs FIFO

Two ways to manage a sequence of items, plus the real-world systems built on top of them.

1. The basic operations

Stack — LIFO (Last In, First Out)

A stack of plates. The plate you put on LAST is the one you take off FIRST.

Queue — FIFO (First In, First Out)

2. Where you actually see these in real software

Stack — the function call stack

Every method call in any program pushes a "stack frame." When the method returns, its frame is popped. That's why infinite recursion gives you StackOverflowError.

Stack — undo / redo (Ctrl+Z)

Every action you take pushes a state onto the undo stack. Hit Ctrl+Z and the most recent action pops off and reverses.

Stack — bracket matching in parsers

Compilers parse ([{}]) using a stack: push each opener, pop on each closer, and check they match. If the stack isn't empty at the end, you've got a syntax error.

if (c == '(') stack.push(c);
else if (c == ')') {
    if (stack.pop() != '(') return false;
}

Stack — DFS (depth-first search)

Either explicit via a Stack data structure, or implicit via the call stack when written recursively. "Go deep before going wide."

Queue — task / message queues

RabbitMQ, Kafka, SQS, JMS — all queue systems. Producer drops a message in; consumer picks it up in order. Decouples slow work from your fast request path.

Queue — print spoolers

Multiple users send print jobs; the printer handles them one at a time, in arrival order. That's literally a FIFO queue.

Queue — BFS (breadth-first search)

Shortest path on an unweighted graph, level-order tree traversal, social network "people 2 hops away" — all queue-based BFS.

Queue — OS scheduler (round-robin)

Threads/processes waiting for CPU time wait in a queue. Each gets a slice in order, then goes back to the end.

3. Real-world demo — browser back/forward (TWO stacks)

Browser history uses two stacks: one for back, one for forward. Navigating to a new URL pushes the current page onto the back stack and clears forward. Clicking Back pops the back stack and pushes onto forward. Try it:

4. Real-world demo — print spooler (FIFO queue)

Jobs arrive at the printer and queue up. Click "Print next" — it pulls from the FRONT of the queue, just like a coffee shop serves the next person in line. Adding to the back is O(1). Removing from the front is O(1).

Big takeaways

  • Stack ops all happen at ONE end (top): push, pop, peek. All O(1).
  • Queue ops happen at BOTH ends: enqueue at back, dequeue from front. Both O(1) with the right structure.
  • In Java: use ArrayDeque for both — it's faster than Stack (legacy, synchronized) and LinkedList (worse cache behavior).
  • PriorityQueue is a special queue where highest-priority comes out first, not FIFO. Backed by a heap, O(log n) per op.
