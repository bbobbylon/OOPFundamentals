Binary Tree Terminology

// Node definition class TreeNode<T> { T val; TreeNode<T> left, right; TreeNode(T val) { this.val = val; } } // Tree properties // Root: topmost node (no parent) // Leaf: node with no children // Height: longest path root → leaf // Depth: distance from root to node // Level: depth + 1 // Full binary tree: every node has 0 or 2 children // Complete: all levels full except last (left-filled) // Perfect: all leaves at same level // Balanced: height = O(log n)
Height h → max 2ʰ⁺¹ − 1 nodes
N nodes → min height ⌊log₂ N⌋
N nodes → max height N − 1 (degenerate = list)
Why balance matters
Balanced tree: search O(log n)
Degenerate tree: search O(n)
Inserting sorted data into BST → degenerate!

Binary Search Tree — left < node < right

// BST invariant: for every node n, // ALL nodes in left subtree < n.val // ALL nodes in right subtree > n.val // Search — O(h) where h is height TreeNode search(TreeNode node, int key) { if (node == null || node.val == key) return node; if (key < node.val) return search(node.left, key); else return search(node.right, key); } // Insert — O(h) TreeNode insert(TreeNode node, int key) { if (node == null) return new TreeNode(key); if (key < node.val) node.left = insert(node.left, key); else node.right = insert(node.right, key); return node; }
// Delete — O(h) — 3 cases TreeNode delete(TreeNode node, int key) { if (node == null) return null; if (key < node.val) { node.left = delete(node.left, key); } else if (key > node.val) { node.right = delete(node.right, key); } else { // Case 1: leaf if (node.left == null) return node.right; if (node.right == null) return node.left; // Case 2: two children — replace with inorder successor int succ = minVal(node.right); node.val = succ; node.right = delete(node.right, succ); } return node; } int minVal(TreeNode n) { while (n.left != null) n = n.left; return n.val; }

The Three Depth-First Traversals

// Tree: 4 // / \ // 2 6 // / \ / \ // 1 3 5 7 // Inorder: Left → Root → Right // Result: 1 2 3 4 5 6 7 ← SORTED for BST! void inorder(TreeNode n) { if (n == null) return; inorder(n.left); visit(n); inorder(n.right); } // Preorder: Root → Left → Right // Result: 4 2 1 3 6 5 7 ← copies tree structure void preorder(TreeNode n) { if (n == null) return; visit(n); preorder(n.left); preorder(n.right); } // Postorder: Left → Right → Root // Result: 1 3 2 5 7 6 4 ← deletes safely void postorder(TreeNode n) { if (n == null) return; postorder(n.left); postorder(n.right); visit(n); }
// Level-order (BFS) — using a Queue // Result: 4 2 6 1 3 5 7 void levelOrder(TreeNode root) { if (root == null) return; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); while (!q.isEmpty()) { TreeNode n = q.poll(); visit(n); if (n.left != null) q.offer(n.left); if (n.right != null) q.offer(n.right); } } // When to use which: // Inorder → sorted sequence from BST // Preorder → serialize/copy a tree // Postorder → delete a tree, eval expressions // Level → shortest path, print by level

AVL Trees — self-balancing BST

// Balance factor = height(left) - height(right) // AVL invariant: balance factor ∈ {-1, 0, 1} // When violated, perform rotations: // LEFT ROTATION (right-heavy) // z y // / \ / \ // T1 y → z x // / \ / \ // T2 x T1 T2 TreeNode rotateLeft(TreeNode z) { TreeNode y = z.right; TreeNode T2 = y.left; y.left = z; z.right = T2; updateHeight(z); updateHeight(y); return y; }
// RIGHT ROTATION (left-heavy) // z y // / \ / \ // y T3 → x z // / \ / \ // x T2 T2 T3 TreeNode rotateRight(TreeNode z) { TreeNode y = z.left; TreeNode T2 = y.right; y.right = z; z.left = T2; updateHeight(z); updateHeight(y); return y; } // 4 cases: LL → rotateRight // RR → rotateLeft // LR → rotateLeft(left), then rotateRight // RL → rotateRight(right), then rotateLeft
AVL vs Red-Black Tree: AVL is more strictly balanced → faster lookups but more rotations on insert/delete. Red-Black allows 2× height variation → faster writes, used in Java's TreeMap/TreeSet. Both guarantee O(log n) operations.

B-Trees — how databases store indexes

// B-Tree properties (order m): // - Every node has at most m children // - Every non-root node has at least ⌈m/2⌉ children // - Root has 2 to m children (if not leaf) // - All leaves at the same level (perfectly balanced!) // - A node with k children has k-1 keys // Example B-Tree (order 5): // [20 40] // / | \ // [5 10] [25 30] [50 60 70] // B+ Tree (used in databases): // - All actual data in LEAF nodes // - Internal nodes only have keys (for routing) // - Leaf nodes linked → efficient range scans // - MySQL InnoDB uses B+ Trees for PRIMARY KEY index
Why B-Trees for disk I/O?
Each node can hold hundreds of keys. A B-Tree with order 100 and height 3 can store 100³ = 1M records with only 3 disk reads. BST would need log₂(1M) ≈ 20 reads.
B-Tree in Java
Java's TreeMap/TreeSet use Red-Black trees (in-memory). For on-disk B-Trees, use a database (PostgreSQL, MySQL) or embedded DB (H2, SQLite). RocksDB and LSMT use LSM trees instead.
