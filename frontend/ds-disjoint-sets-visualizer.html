DS Disjoint Sets (Union-Find)

Track connected components · union by rank · path compression · Kruskal's MST

🧩 What is Union-Find — and how does it answer "are these two nodes connected?" in near O(1) time?

The Disjoint Set (Union-Find) data structure efficiently answers one deceptively simple question: are nodes A and B in the same connected component? This is harder than it sounds when you have thousands of nodes being merged together dynamically. A naive approach using DFS or BFS for each query is O(n+e) per query — too slow for real-time use. Union-Find solves this with nearly constant time per operation using two brilliant optimizations. Core idea: each node has a "parent" pointer. Nodes in the same component form a tree pointing upward to a representative root. Two nodes are in the same component iff they have the same root. find(x): traverse parent pointers until reaching the root. Without optimization: O(n) in the worst case (linear chain). Path compression: during find(), make every node point directly to the root. Cost paid once, subsequent finds on the same path are O(1). Formally: find(x) makes all nodes on the path from x to root point directly to root. union(x, y): link two trees by making one root point to the other. Without optimization: always attach one tree under the other, which can create tall trees → O(log n). Union by rank: always attach the smaller-rank tree under the larger-rank tree. Rank is an upper bound on tree height. If both have equal rank, arbitrarily pick one and increment its rank. Together, path compression + union by rank achieves amortized O(α(n)) per operation, where α is the inverse Ackermann function — essentially constant (α(n) < 5 for any practical n). Kruskal's MST algorithm uses Union-Find: sort all edges by weight, then process each edge — if its two endpoints are in different components (union-find check), add the edge to the MST and union the two components. This greedily builds the Minimum Spanning Tree in O(E log E) time. Key applications: detecting cycles in undirected graphs, Kruskal's MST, social network component detection, image segmentation (connected pixels), and network connectivity queries.

Union-Find with optimizations

class UnionFind { int[] parent; // parent[i] = parent of node i int[] rank; // rank[i] = tree height upper bound UnionFind(int n) { parent = new int[n]; rank = new int[n]; for (int i=0; i<n; i++) parent[i] = i; // each node is its own root } // find with PATH COMPRESSION int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); // flatten: point directly to root return parent[x]; } // union by RANK boolean union(int x, int y) { int rx=find(x), ry=find(y); if (rx==ry) return false; // already same component if (rank[rx]<rank[ry]) {int t=rx;rx=ry;ry=t;} // swap: rx=bigger parent[ry]=rx; // attach smaller under bigger if (rank[rx]==rank[ry]) rank[rx]++; // tie → increment rank return true; } } // Amortized O(α(n)) per operation ≈ O(1) in practice

Kruskal's MST

// Minimum Spanning Tree: connect all nodes // with minimum total edge weight, no cycles // Input: n nodes, edges as [weight, u, v] int kruskalMST(int n, int[][] edges) { // Sort edges by weight: greedily pick cheapest first Arrays.sort(edges, (a,b) -> a[0]-b[0]); UnionFind uf = new UnionFind(n); int totalWeight = 0; int edgesAdded = 0; for (int[] e : edges) { int w=e[0], u=e[1], v=e[2]; if (uf.union(u, v)) { // different components? totalWeight += w; // add this edge to MST edgesAdded++; // MST needs exactly n-1 edges if (edgesAdded==n-1) break; // MST complete } // if union returns false: would create a cycle → skip } return totalWeight; // O(E log E) sort dominates }

Cycle detection

// Detect cycle in undirected graph // Using Union-Find: if we try to union two nodes // already in the same component, that edge creates a cycle boolean hasCycle(int n, int[][] edges) { UnionFind uf = new UnionFind(n); for (int[] e : edges) { int u=e[0], v=e[1]; if (!uf.union(u, v)) { // already connected? return true; // adding this edge creates a cycle } } return false; } // Alternative use: number of connected components // = (n - number of successful union() calls) // Each successful union reduces component count by 1 // Start with n components (each node alone) // After all unions: remaining components = n - merges

What Is a Disjoint Set?

A disjoint set (union-find) structure maintains a collection of non-overlapping sets and supports two key operations: union (merge two sets) and find (which set does this element belong to?). The magic: nearly O(1) amortized for both.

The Two Operations

find(x) — Returns the representative (root) of the set containing x. If find(a) == find(b), they're in the same set.
union(a, b) — Merges the set containing a with the set containing b. After this, find(a) == find(b).
connected(a, b) — Just return find(a) == find(b). O(α(n)) ≈ O(1) amortized.

Naive Implementation — Forest of Trees

Represent each set as a tree. Each node stores its parent. The root is its own parent and is the set's representative. Find walks up to the root; union links one root to another.

// Naive union-find (no optimizations) class UnionFind { int[] parent; UnionFind(int n) { parent = new int[n]; for (int i = 0; i < n; i++) parent[i] = i; // each element is its own root } int find(int x) { while (parent[x] != x) x = parent[x]; // walk up return x; } void union(int a, int b) { int rootA = find(a), rootB = find(b); if (rootA != rootB) parent[rootA] = rootB; // attach A's tree under B } boolean connected(int a, int b) { return find(a) == find(b); } }

The Problem: Degenerate Trees

If we always attach the larger tree's root to the smaller, we get a chain:

union(0,1), union(1,2), union(2,3), union(3,4)
parent: [1, 2, 3, 4, 4]
Tree: 0→1→2→3→4 ← chain!
find(0) walks 0→1→2→3→4: O(n) per call
Naive union-find degrades to O(n) per operation in the worst case — no better than a linked list. We need two optimizations.

Optimization 1: Union by Rank

Always attach the shorter tree under the taller tree. This bounds tree height to O(log n). "Rank" is an upper bound on height (it's not the actual height — path compression keeps it valid as an upper bound).

int[] parent, rank; UnionFind(int n) { parent = new int[n]; rank = new int[n]; // initially all 0 for (int i = 0; i < n; i++) parent[i] = i; } void union(int a, int b) { int ra = find(a), rb = find(b); if (ra == rb) return; // already same set // Attach smaller rank under larger rank if (rank[ra] < rank[rb]) parent[ra] = rb; else if (rank[ra] > rank[rb]) parent[rb] = ra; else { parent[rb] = ra; // tie: pick either, increase winner's rank rank[ra]++; } }

Why Rank Bounds Height to O(log n)

// Rank only increases when two equal-rank trees merge
Rank 0: single node (1 element)
Rank 1: two rank-0 trees merge (≥2 elements)
Rank 2: two rank-1 trees merge (≥4 elements)
Rank k: ≥ 2ᵏ elements

Max rank = log₂(n) → height = O(log n) ✓

Optimization 2: Path Compression

After find(x) walks to the root, update all nodes along the path to point directly to the root. Future finds on the same path become O(1). Done automatically during find() — no extra work.

int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); // point directly to root return parent[x]; } // Iterative version (no recursion stack): int find(int x) { int root = x; while (parent[root] != root) root = parent[root]; // find root while (parent[x] != root) { int next = parent[x]; parent[x] = root; // compress path x = next; } return root; }

Before & After Path Compression

Before find(0): chain 0→1→2→3→4(root)
parent: [1, 2, 3, 4, 4]

After find(0): all point to root
parent: [4, 4, 4, 4, 4]

Next find(0): direct lookup: O(1) ✓
Next find(1): direct lookup: O(1) ✓

Combined: Union by Rank + Path Compression

Together they achieve O(α(n)) amortized per operation — α is the inverse Ackermann function, effectively constant for all practical inputs. This is the theoretically optimal amortized complexity for any union-find structure (proved by Tarjan, 1975).
// Complete, production-ready UnionFind with both optimizations: class UnionFind { private int[] parent, rank; private int components; UnionFind(int n) { parent = new int[n]; rank = new int[n]; components = n; for (int i = 0; i < n; i++) parent[i] = i; } public int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); // path compress return parent[x]; } public boolean union(int a, int b) { int ra = find(a), rb = find(b); if (ra == rb) return false; // already same set (cycle!) if (rank[ra] < rank[rb]) parent[ra] = rb; else if (rank[ra] > rank[rb]) parent[rb] = ra; else { parent[rb] = ra; rank[ra]++; } components--; return true; // sets were different, merged successfully } public boolean connected(int a, int b) { return find(a) == find(b); } public int count() { return components; } // number of distinct sets }

Kruskal's MST with Union-Find

Union-Find makes Kruskal's MST algorithm elegant. Sort edges by weight, then add each edge if its endpoints are in different sets. O(E log E + E × α(V)) ≈ O(E log E).

int[] kruskalMST(int n, int[][] edges) { // edges[i] = {weight, u, v} Arrays.sort(edges, (a, b) -> a[0] - b[0]); // sort by weight ascending UnionFind uf = new UnionFind(n); List<int[]> mst = new ArrayList<>(); int totalWeight = 0; for (int[] e : edges) { int w = e[0], u = e[1], v = e[2]; if (uf.union(u, v)) { // false if u,v already connected (cycle) mst.add(e); totalWeight += w; if (mst.size() == n - 1) break; // MST complete } } // If mst.size() < n-1: graph was disconnected (forest, not spanning tree) return new int[]{totalWeight, mst.size()}; } // Why union() returning boolean is crucial: // If union(u,v) returns false → they're ALREADY connected → adding edge creates cycle // Skip it! This is how we guarantee a tree (acyclic) structure.

Real-World Applications

Network Connectivity

Are computers A and B in the same network segment? Union-Find tracks which components are connected as links go up/down. Used in network partition monitoring.

Incremental connectivity: Union-Find excels when connections are only added, never removed. For dynamic removal, need more complex structures (link-cut trees).

Image Segmentation

Merge adjacent pixels with similar color into regions. Start with each pixel as its own set; union neighboring pixels that are "close enough." Result: distinct color regions.

Used in: compression (JPEG regions), object detection, flood fill (paint bucket tool).

Percolation (Physics)

Model whether fluid percolates through a porous material. Open sites = union with neighbors; percolation = top row connects to bottom row. The Sedgewick/Wayne MOOC opens with this problem.

Kruskal's MST

As shown in the Implementation tab: sort edges, greedily add non-cycle-forming edges. Union-Find makes cycle detection O(α(n)) — without it, you'd need DFS per edge: O(V).

2D Grid: Number of Islands (LeetCode 200)

// Classic: count connected land cells ('1') int numIslands(char[][] grid) { int rows = grid.length, cols = grid[0].length; UnionFind uf = new UnionFind(rows * cols); int[] dr = {0, 0, 1, -1}; int[] dc = {1, -1, 0, 0}; int waterCount = 0; for (int r = 0; r < rows; r++) { for (int c = 0; c < cols; c++) { if (grid[r][c] == '0') { waterCount++; continue; } int cell = r * cols + c; // 2D → 1D index for (int d = 0; d < 4; d++) { int nr = r+dr[d], nc = c+dc[d]; if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == '1') uf.union(cell, nr * cols + nc); } } } return uf.count() - waterCount; // subtract water components }
