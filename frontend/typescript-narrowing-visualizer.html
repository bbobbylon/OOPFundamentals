Type Narrowing

How TypeScript's control-flow analysis turns a broad type into a specific one as it reads your code top-to-bottom. The mechanic behind every if, switch, and type guard.

1. What is narrowing?

A variable can start with a broad type like string | number | null. As you write checks against it, TypeScript follows along and narrows the type to whatever's still possible at each line. Inside an if, the type is whatever made the condition true; in the else, it's whatever's left.

function describe(x: string | number | null) {
  // here, x is: string | number | null
  if (x === null) {
    // here, x is: null
    return 'nothing';
  }
  // here, x is: string | number  (null was returned out)
  if (typeof x === 'string') {
    // here, x is: string
    return x.toUpperCase();
  }
  // here, x is: number  (string handled above)
  return x.toFixed(2);
}
Mental model: the compiler simulates running your code, tracking what each variable's type could be at every point. It uses your conditions to subtract impossible cases from the set.

2. typeof guards

The classic. typeof x === '...' narrows to one of these JavaScript primitive strings — TS knows the full set.

The null trap: typeof null === 'object' is one of JavaScript's most famous quirks. If you write if (typeof x === 'object') and x includes null in its type, TS keeps null in the narrowed type. Add && x !== null or check != null first. 
function printLen(x: string | string[] | null) {
  if (typeof x === 'object') {
    // x is: string[] | null  ← null sneaked in!
    if (x !== null) {
      console.log(x.length); // now x is string[]
    }
  }
}

3. Truthiness narrowing

TS knows what JS coerces to false: 0, NaN, "", 0n, null, undefined, and false itself. A plain if (x) narrows away any of those that are in x's type.

function greet(name?: string) {
  // name is: string | undefined
  if (name) {
    // name is: string (and not "")
    console.log(`Hi, ${name}!`);
  }
}
Watch out: if (x) on string | undefined also skips the empty string "". If you care about "defined but empty", check x !== undefined explicitly. 
// Three different narrowings:
function f(s: string | undefined) {
  if (s)              { /* s: string, NOT "" */ }
  if (s !== undefined) { /* s: string, INCLUDES "" */ }
  if (s != null)    { /* loose check: excludes null & undefined */ }
}

4. Equality narrowing

===, !==, ==, != all narrow. With strict equality, the two sides must share a type for the comparison to be possible — TS uses that to refine both sides.

function same(a: string | number, b: string | boolean) {
  if (a === b) {
    // Only string === string is possible here
    // a is: string
    // b is: string
    return a.toUpperCase() + b.toLowerCase();
  }
}

Loose != null is the idiomatic "not null and not undefined" check — it narrows both away in one go.

5. The in operator

'key' in obj narrows a union of object types to those that declare key. Great for shapes that don't share a tag field.

type Fish = { swim: () => void };
type Bird = { fly:  () => void };

function move(animal: Fish | Bird) {
  if ('swim' in animal) {
    animal.swim(); // animal: Fish
  } else {
    animal.fly();  // animal: Bird
  }
}
Optional properties: if a key is optional, both branches of 'key' in obj keep that type — the presence isn't proven, only that the key could be there. TS handles this conservatively.

6. instanceof guards

For classes. x instanceof Foo narrows to Foo (or a subclass).

class ApiError extends Error { status = 500; }

function handle(e: unknown) {
  if (e instanceof ApiError) {
    console.log(e.status);   // e: ApiError
  } else if (e instanceof Error) {
    console.log(e.message);  // e: Error
  } else {
    console.log('unknown'); // e: unknown
  }
}
Cross-realm caveat: instanceof compares prototype chains, so an object from another iframe/worker won't pass even if it's "the same class". For values from outside your realm (or for plain object shapes), prefer the in operator or a user-defined guard.

7. Assignment narrowing

Assigning a value narrows the variable to that value's type from that point forward — even if the declaration was broader. Reassigning broadens again.

let x: string | number = Math.random() > 0.5 ? 'a' : 1;
// x: string | number

x = 10;
// x: number  (narrowed by assignment)

x = 'hi';
// x: string  (re-narrowed)

x.toUpperCase(); // ✅ works — x is currently string

For const, the narrowing is permanent because const can't be reassigned. This is why const x = 'red' infers the literal type 'red' (assuming the contextual type allows it), while let x = 'red' infers string.

8. Discriminated unions

The single most useful TS pattern. Each variant of a union has a shared tag property with a unique literal value. Switching on the tag narrows to the matching variant — and TS knows exactly which fields are available.

type Shape =
  | { kind: 'circle';    radius: number }
  | { kind: 'square';    side:   number }
  | { kind: 'rectangle'; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle':    return Math.PI * s.radius ** 2;
    case 'square':    return s.side * s.side;
    case 'rectangle': return s.w * s.h;
  }
}

Why this beats inheritance: no abstract classes, no virtual dispatch, no instanceof at runtime. The "polymorphism" is just a switch, and TS proves at compile time that you covered every case.

9. User-defined type guards

When a built-in check isn't enough, write a function that returns a type predicate: x is T. TS trusts you — if the function returns true, x is treated as T in the caller.

type User  = { id: string; email: string };
type Guest = { id: string };

function isUser(x: User | Guest): x is User {
  return 'email' in x;
}

function notify(person: User | Guest) {
  if (isUser(person)) {
    send(person.email); // ✅ person: User
  } else {
    prompt('sign up');  // person: Guest
  }
}
You're making a promise: TS doesn't verify the body of a type-guard function. If isUser returns true but the value isn't actually a User, callers will trust you and crash at runtime. Keep guards small and provably correct.

Guards for arrays

// Array.isArray narrows to readonly unknown[] in strict mode.
// For your own typed check on items, write a guard:
function isStringArray(x: unknown): x is string[] {
  return Array.isArray(x) && x.every(item => typeof item === 'string');
}

10. Assertion functions

Same idea as a guard, but instead of returning true/false it throws when the check fails. Signature: asserts x is T. After the call, TS narrows the variable for the rest of the scope.

function assertString(x: unknown): asserts x is string {
  if (typeof x !== 'string') throw new Error('not a string');
}

function use(input: unknown) {
  assertString(input);
  console.log(input.toUpperCase()); // ✅ input: string
}

A plain asserts x (no "is T") asserts truthiness — useful for non-null assertions when you really want to throw rather than return.

function assert(cond: unknown, msg = 'failed'): asserts cond {
  if (!cond) throw new Error(msg);
}

function head<T>(xs: T[]): T {
  assert(xs.length > 0, 'empty');
  return xs[0]; // no "possibly undefined" error
}
Functions with assertion signatures must be declared as function. Arrow functions stored in a variable lose the assertion. const assert = (c: unknown): asserts c => { ... } won't work — TS doesn't propagate the narrowing.

11. Exhaustiveness with never

never is the type that has no values. If you've narrowed every case of a union away, the leftover type is never. Assign the variable to a never parameter at the end of a switch — if you ever add a new case and forget to handle it, the assignment fails to compile.

type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side:   number };

function assertNever(x: never): never {
  throw new Error(`unexpected: ${JSON.stringify(x)}`);
}

function area(s: Shape) {
  switch (s.kind) {
    case 'circle': return Math.PI * s.radius ** 2;
    case 'square': return s.side ** 2;
    default:       return assertNever(s); // 🛡 exhaustive
  }
}

// Later, add a 'triangle' variant to Shape:
//   ❌ Type '{ kind: "triangle"; ... }' is not assignable to type 'never'.

This pattern is the single biggest reason to model state as a discriminated union: the compiler nags you into handling every case.

12. Widening & as const

Narrowing's opposite problem: TS often widens a literal to its general type so the value is more useful. let x = 'red' is string, not 'red'. Two ways to keep the narrow form:

// 1. const + primitive → literal type
const a = 'red';        // a: 'red'
let   b = 'red';        // b: string

// 2. `as const` — freezes the entire literal
const c = { theme: 'dark' } as const;
// c: { readonly theme: 'dark' }

const colors = ['red', 'blue'] as const;
// colors: readonly ['red', 'blue']
type Color = typeof colors[number]; // 'red' | 'blue'

This unlocks the typeof arr[number] trick: derive a string-union type from an actual runtime array.

typeof x === 'object' null stays in the type Add && x !== null or check != null first
typeof x === 'array' That string never exists — arrays are 'object' Array.isArray(x)

Narrowing inside a callback TS loses narrowing across function boundaries — by the time the callback runs, x might be different Copy to a const first: const v = x; if (v) { setTimeout(() => use(v)) }
Property access on a mutable object after a guard If something between the guard and the access could have mutated, TS re-widens the property Copy the property into a const, or use readonly

Re-widening from mutation

let obj: { x: string | null } = { x: 'hi' };
if (obj.x !== null) {
  someAsyncThing();        // could reassign obj.x
  obj.x.toUpperCase();     // ❌ Object is possibly 'null'
}
// Fix: pin it down first
const v = obj.x;
if (v !== null) {
  someAsyncThing();
  v.toUpperCase();         // ✅
}
