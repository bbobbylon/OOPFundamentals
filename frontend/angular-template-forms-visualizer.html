Template-Driven Forms

How Angular's FormsModule turns plain HTML inputs into tracked, validated, stateful form fields — with nothing but directives and two-way binding.

Template-Driven vs Reactive Forms — when to use each

Angular ships two completely different approaches to forms. Pick one per form — you can mix across forms in the same app, but don't mix within a single form.

FactorTemplate-DrivenReactive
Setup complexityLow — just add FormsModuleMedium — must build FormGroup in class
Data flowTwo-way binding [(ngModel)]Explicit via patchValue / valueChanges
Validation logicHTML attributes in templateValidator functions in class
Unit testabilityHard (needs DOM / TestBed)Easy (pure TS, no DOM needed)
Dynamic fieldsVerbose — needs ngModelGroupEasy — FormArray
RxJS integrationManual subscriptionNative — valueChanges is an Observable
Best forSimple login / contact formsComplex, dynamic, or wizard forms
Angular versionAll versions (classic approach)Angular 2+ (preferred modern approach)
Rule of thumb: fewer than 5 fields with no conditional logic? Template-driven is faster. Any dynamic fields, cross-field validation, or unit tests? Go reactive.

Mental model — the core difference

Template-Driven: template is the source of truth

The form model is derived from the DOM. Angular reads your [(ngModel)] directives and builds an internal NgForm / NgModel automatically.

<!-- The template IS the model -->
<input [(ngModel)]="user.name"
       name="name"
       required
       minlength="2">

Reactive: class is the source of truth

The form model is built in the component class. The template binds to it. The model exists before the DOM does.

// The CLASS defines the model
form = new FormGroup({
  name: new FormControl('', [
    Validators.required,
    Validators.minLength(2)
  ])
});

Setup & ngModel two-way binding

1. Import FormsModule

// app.component.ts (standalone)
import { FormsModule } from '@angular/forms';

@Component({
  standalone: true,
  imports: [FormsModule],   // ← must import this
  template: `...`
})
Without FormsModule in imports, Angular ignores ngModel entirely — no error, just silent no-op. Always check imports first when ngModel doesn't work.

2. Two-way binding with [(ngModel)]

<!-- template -->
<input
  [(ngModel)]="username"
  name="username"    <!-- REQUIRED inside <form> -->
  placeholder="Enter username"
>
<p>Hello, {{ username }}!</p>
// component class
export class AppComponent {
  username = '';
  // No other code needed!
  // [(ngModel)] = [ngModel] + (ngModelChange)
  // = property binding + event binding
}

3. ngModel INSIDE a <form> vs standalone

ContextRequires name attr?Registered in NgForm?Can submit with (ngSubmit)?
Inside <form> tagYes — Angular uses name as the control keyYes — NgForm tracks itYes
Outside <form>NoNo — standalone controlN/A — no parent form
Forgetting name="..." inside a <form> with ngModel throws: "If ngModel is used within a form tag, either the name attribute must be set or the form control must be defined as 'standalone' in ngModelOptions."

Form State — CSS classes Angular manages automatically

Every ngModel input and every <form ngForm> element gets a set of CSS classes that reflect its current state. Angular adds and removes these classes automatically — no code needed.

Class pairMeaningInitial state
ng-pristine / ng-dirtyHas the user typed anything yet?ng-pristine
ng-untouched / ng-touchedHas the input lost focus (blur)?ng-untouched
ng-valid / ng-invalidDo all validators pass?Depends on validators
ng-pendingAn async validator is runningNot applied unless async validator present
Show validation errors only when the user has touched the field: email.invalid && email.touched. Never show errors on a fresh/pristine field — it's annoying UX.

Built-in Validators

All built-in validators are HTML attributes. Angular's directives intercept them and wire them into the form model automatically when FormsModule is imported.

AttributeWhat it validatesExample
requiredValue is not empty<input required>
minlength="n"Value has at least n characters<input minlength="3">
maxlength="n"Value has at most n characters<input maxlength="50">
emailValue matches email pattern<input type="email" email>
pattern="regex"Value matches the regex<input pattern="[A-Z]{3}">
min="n"Number ≥ n (type="number")<input type="number" min="0">
max="n"Number ≤ n (type="number")<input type="number" max="100">

Full example — login form with validators

<form #loginForm="ngForm" (ngSubmit)="onSubmit(loginForm)">

  <div class="field">
    <label>Email</label>
    <input
      type="email"
      name="email"
      #email="ngModel"
      [(ngModel)]="formData.email"
      required
      email
    >
    <div *ngIf="email.invalid && email.touched">
      <span *ngIf="email.errors?.['required']">Email is required</span>
      <span *ngIf="email.errors?.['email']">Must be valid email</span>
    </div>
  </div>

  <div class="field">
    <label>Password</label>
    <input
      type="password"
      name="password"
      #pwd="ngModel"
      [(ngModel)]="formData.password"
      required
      minlength="8"
      pattern="(?=.*[0-9]).{8,}"   <!-- must contain digit -->
    >
    <div *ngIf="pwd.invalid && pwd.touched">
      <span *ngIf="pwd.errors?.['minlength']">Min 8 characters</span>
      <span *ngIf="pwd.errors?.['pattern']">Must contain a number</span>
    </div>
  </div>

  <button type="submit" [disabled]="loginForm.invalid">Login</button>

</form>

Template Reference Variables & Submitting

Template reference variables let you access the Angular form/control objects directly inside the template — no class property needed.

#myForm="ngForm"

<form #myForm="ngForm"
      (ngSubmit)="onSubmit(myForm)">
  ...
  <!-- access NgForm instance in template -->
  <p>Valid? {{ myForm.valid }}</p>
  <p>Value: {{ myForm.value | json }}</p>
  <button [disabled]="myForm.invalid">
    Submit
  </button>
</form>

#email="ngModel"

<input
  type="email"
  name="email"
  #email="ngModel"   <!-- ref to NgModel -->
  [(ngModel)]="formData.email"
  required email
>
<!-- use #email below -->
<div *ngIf="email.invalid && email.touched">
  Error: {{ email.errors | json }}
</div>

What you get from these refs

Ref typeClass it accessesUseful properties
#f="ngForm"NgFormf.valid, f.invalid, f.value, f.touched, f.submitted, f.reset()
#c="ngModel"NgModelc.valid, c.invalid, c.dirty, c.touched, c.errors, c.value
#g="ngModelGroup"NgModelGroupSame as NgForm — a sub-group's validity/value as a nested object

Submitting the form & reading its value

// component.ts
export class LoginComponent {
  formData = { email: '', password: '' };

  onSubmit(form: NgForm) {
    if (form.invalid) return;

    console.log('Form value:', form.value);
    // { email: 'user@example.com', password: 'abc12345' }

    console.log('Bound model:', this.formData);
    // Same thing — both are in sync via [(ngModel)]

    form.reset();  // clears values AND resets all state flags to pristine/untouched
  }
}

Advanced Patterns

1. Cross-field validation — custom validator directive

Template-driven forms can't access two fields simultaneously in a single validator. Wrap both fields in an ngModelGroup and apply a custom directive to the group.

// password-match.directive.ts
@Directive({
  selector: '[passwordMatch]',
  providers: [{
    provide: NG_VALIDATORS,
    useExisting: PasswordMatchDirective,
    multi: true
  }]
})
export class PasswordMatchDirective
    implements Validator {
  validate(group: AbstractControl) {
    const pw  = group.get('password');
    const cpw = group.get('confirm');
    return pw?.value !== cpw?.value
      ? { mismatch: true }
      : null;
  }
}
<!-- Template usage -->
<div ngModelGroup="passwords"
     passwordMatch
     #pwGroup="ngModelGroup">

  <input name="password"
         [(ngModel)]="pw"
         required>

  <input name="confirm"
         [(ngModel)]="cpw"
         required>

  <div *ngIf="pwGroup.errors?.['mismatch']">
    Passwords do not match
  </div>
</div>

2. Dynamic forms with *ngFor + ngModelGroup

// component.ts
addresses = [{ street: '', city: '' }];
addAddress() { this.addresses.push({ street: '', city: '' }); }

<!-- template -->
<div *ngFor="let addr of addresses; let i = index"
     ngModelGroup="address-{{ i }}">
  <input name="street" [(ngModel)]="addr.street" required>
  <input name="city"   [(ngModel)]="addr.city"   required>
</div>
<button (click)="addAddress()">+ Add address</button>
Note: dynamic forms get awkward quickly in template-driven mode — each dynamic group needs a unique ngModelGroup name built from index. For anything beyond 2–3 dynamic fields, switch to Reactive Forms with FormArray.

3. Select, checkbox & radio with ngModel

<!-- Select -->
<select name="role" [(ngModel)]="user.role">
  <option value="admin">Admin</option>
  <option value="editor">Editor</option>
</select>

<!-- Checkbox -->
<input type="checkbox" name="agree"
       [(ngModel)]="user.agreed">

<!-- Radio group -->
<input type="radio" name="size"
       value="small" [(ngModel)]="user.size"> Small
<input type="radio" name="size"
       value="large" [(ngModel)]="user.size"> Large

Same form — Template-Driven vs Reactive

A simple login form (email + password, required, email validator, submit) built both ways.

Template-Driven — component class

import { Component } from '@angular/core';
import { FormsModule, NgForm } from '@angular/forms';

@Component({
  standalone: true,
  imports: [FormsModule],
  templateUrl: './login.component.html'
})
export class LoginComponent {
  formData = { email: '', password: '' };

  onSubmit(f: NgForm) {
    if (f.invalid) return;
    console.log(f.value); // { email, password }
    f.reset();
  }
}

Reactive — component class

import { Component } from '@angular/core';
import { ReactiveFormsModule, FormGroup,
         FormControl, Validators } from '@angular/forms';

@Component({
  standalone: true,
  imports: [ReactiveFormsModule],
  templateUrl: './login.component.html'
})
export class LoginComponent {
  form = new FormGroup({
    email: new FormControl('',
      [Validators.required, Validators.email]),
    password: new FormControl('',
      [Validators.required, Validators.minLength(8)])
  });

  onSubmit() {
    if (this.form.invalid) return;
    console.log(this.form.value);
    this.form.reset();
  }
}

Template-Driven — HTML template

<form #f="ngForm"
      (ngSubmit)="onSubmit(f)">

  <input
    type="email" name="email"
    #email="ngModel"
    [(ngModel)]="formData.email"
    required email
  >
  <div *ngIf="email.invalid && email.touched">
    <span *ngIf="email.errors?.['required']">
      Required</span>
    <span *ngIf="email.errors?.['email']">
      Invalid email</span>
  </div>

  <input
    type="password" name="password"
    #pwd="ngModel"
    [(ngModel)]="formData.password"
    required minlength="8"
  >
  <div *ngIf="pwd.invalid && pwd.touched">
    Min 8 characters
  </div>

  <button [disabled]="f.invalid">
    Login
  </button>
</form>

Reactive — HTML template

<form [formGroup]="form"
      (ngSubmit)="onSubmit()">

  <input
    type="email"
    formControlName="email"
  >
  <div *ngIf="form.get('email')?.invalid
           && form.get('email')?.touched">
    <span *ngIf="form.get('email')?.errors?.['required']">
      Required</span>
    <span *ngIf="form.get('email')?.errors?.['email']">
      Invalid email</span>
  </div>

  <input
    type="password"
    formControlName="password"
  >
  <div *ngIf="form.get('password')?.invalid
           && form.get('password')?.touched">
    Min 8 characters
  </div>

  <button [disabled]="form.invalid">
    Login
  </button>
</form>

Verdict

Template-Driven wins for:

  • Quick forms (2–4 fields)
  • Prototyping
  • Developers who think in HTML
  • When you want the HTML to be self-documenting

Reactive wins for:

  • Dynamic field counts
  • Complex validation logic
  • Unit testing validators
  • Streaming valueChanges with RxJS

Both share:

  • Same CSS state classes
  • valid, invalid, errors API
  • reset() method
  • (ngSubmit) event
