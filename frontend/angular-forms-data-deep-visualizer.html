Angular Forms & FormData Handling

From form value to HTTP body — typed reactive forms, reading values, and the native FormData object for multipart file uploads

📤 How does a form value become an HTTP request body?

When a user submits a form, the raw data has to travel to your Spring API — and the body format matters. There are three: JSON (the default, for typed fields), application/x-www-form-urlencoded (legacy key=value), and multipart/form-data (uploading files alongside fields). HttpClient sends JSON automatically when you pass an object; to upload a file you build a native FormData — and you never set Content-Type yourself with FormData (the browser adds it with the boundary).

  • Pass a plain object → Angular serializes JSON and sets Content-Type: application/json; Spring reads @RequestBody.
  • Use form.getRawValue() (not .value) so disabled controls (like id) are included and types stay non-partial.
  • For files, build FormData with append() and pass it directly — let the browser set the multipart boundary.
  • Spring reads multipart via @RequestParam MultipartFile + other @RequestParam fields.
  • Track upload progress with { reportProgress: true, observe: 'events' } and the HttpEventType.UploadProgress events.

JSON body (default)

http.post('/api/users', form.getRawValue()) — Angular serializes to JSON and sets Content-Type: application/json; Spring receives @RequestBody. Use getRawValue() to include disabled controls like id.

FormData for file uploads

const fd = new FormData(); fd.append('avatar', file); fd.append('userId', '123'); then http.post(url, fd) — do not set Content-Type. Spring reads @RequestParam("avatar") MultipartFile.

Typed form values

Since Angular 14, FormControl<string> types control.value. But FormGroup.value is partial (excludes disabled controls) — use getRawValue() for a fully-typed, all-controls snapshot to send.

In CIAM:a profile-update form does form.getRawValue() → JSON to PATCH /api/users/{id}; a profile-photo upload builds FormData from the <input type="file"> + userId, POSTed to /api/users/{id}/avatar where Spring reads @RequestParam MultipartFile avatar.

1. The mental model — a form is a value object

    

      
Strip away the UI and a form is just a typed object you collect, validate, and send. Everything else is plumbing.

      

        User types
        →
        FormGroup tracks value + validity
        →
        form.value (a plain object)
        →
        http.post(url, value)
      

      
This page is about that data flow — capturing the value, typing it, validating it, and shipping it (as JSON or as multipart FormData for files). For the structural side (FormControl/FormGroup/FormArray wiring) see the Reactive Forms and Form Arrays visualizers.

    

  


  
  

    
2. Reading the value — .value, getRawValue(), valueChanges

    

      

        
Three ways to get data out

        
const form = new FormGroup({
  name:  new FormControl('Bobby'),
  email: new FormControl('b@mail.dev'),
  tier:  new FormControl({ value: 'pro', disabled: true }),
});

// 1. snapshot of current value
form.value;
// { name: 'Bobby', email: 'b@mail.dev' }
//   ⚠ disabled 'tier' is OMITTED

// 2. include disabled controls
form.getRawValue();
// { name:'Bobby', email:'b@mail.dev', tier:'pro' }

// 3. react to every change (Observable)
form.valueChanges.subscribe(v => console.log(v));

// …or as a signal (Angular 17+)
const value = toSignal(form.valueChanges);

        
⚠ The form.value / getRawValue() distinction trips up everyone — disabled fields silently vanish from .value. Use getRawValue() when you need them.

3. Typed reactive forms v14+

    

      

        
Strong types flow from form to .value

        
// declare the shape — TS infers .value type
const form = new FormGroup({
  name:  new FormControl('', { nonNullable: true }),
  age:   new FormControl<number>(0, { nonNullable: true }),
  admin: new FormControl(false, { nonNullable: true }),
});

// form.value is fully typed:
// { name: string; age: number; admin: boolean }
const name: string = form.value.name!; // ✓

// the FormBuilder shorthand (cleaner)
private fb = inject(FormBuilder);
form = this.fb.nonNullable.group({
  name: '',
  age: 0,
  admin: false,
});

      

      

        
Why nonNullable?

        
By default a control's value type includes null (because reset() sets it to null). That forces ! or null-checks everywhere.

        
// default — value is string | null 😖
new FormControl('');
// reset() → null

// nonNullable — value is string ✓
new FormControl('', { nonNullable: true });
// reset() → '' (back to the initial value)

4. Validate & submit JSON to Spring

    

      

        
Validation + a clean error helper

        
form = this.fb.nonNullable.group({
  name:  ['', [Validators.required, Validators.minLength(3)]],
  email: ['', [Validators.required, Validators.email]],
});

// show an error only after the user touched the field
showError(ctrl: string, error: string): boolean {
  const c = this.form.get(ctrl);
  return !!c && c.hasError(error) && (c.touched || c.dirty);
}

onSubmit() {
  if (this.form.invalid) {
    this.form.markAllAsTouched(); // reveal errors
    return;
  }
  this.http.post('/api/users', this.form.getRawValue())
    .subscribe(() => this.form.reset());
}

5. The native FormData object — multipart & file uploads

    

      
JSON can't carry binary files. To upload a file (with other fields), you build a native FormData object — the browser encodes it as multipart/form-data.

    

    

      

        
Building & sending FormData

        
// 1. read the file from an <input type="file">
onFileSelected(e: Event) {
  const input = e.target as HTMLInputElement;
  this.file = input.files?.[0] ?? null;
}

// 2. assemble FormData — files + plain fields together
upload() {
  const data = new FormData();
  data.append('avatar', this.file!, this.file!.name);
  data.append('title', this.title);
  data.append('tags', JSON.stringify(['a','b']));

  // 3. POST it — note: NO Content-Type header!
  this.http.post('/api/upload', data)
    .subscribe();
}

        
⚠ Never set Content-Type manually for FormData. The browser must set it — including the unique boundary=…. If you hardcode application/json or even multipart/form-data, the upload breaks.

      

      

        
What goes over the wire

        
FormData becomes a multipart body — each field is a "part" separated by a boundary string:

        
POST /api/upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----Abc123

------Abc123
Content-Disposition: form-data; name="avatar";
  filename="photo.png"
Content-Type: image/png

‹binary image bytes›
------Abc123
Content-Disposition: form-data; name="title"

My holiday photo
------Abc123--

6. Tracking upload progress with HttpClient

    

      

        
Use reportProgress + observe: 'events'

        
import { HttpEventType } from '@angular/common/http';

upload(data: FormData) {
  return this.http.post('/api/upload', data, {
    reportProgress: true,    // emit progress events
    observe: 'events',       // get the full event stream
  }).pipe(
    map(event => {
      switch (event.type) {
        case HttpEventType.UploadProgress:
          return Math.round(
            100 * event.loaded / (event.total ?? 1)
          ); // % complete
        case HttpEventType.Response:
          return 100;
        default:
          return 0;
      }
    })
  );
}

// template: <progress [value]="pct$ | async" max="100">

      

      

        
File input handling & validation

        
onFile(e: Event) {
  const file = (e.target as HTMLInputElement).files?.[0];
  if (!file) return;

  // validate type
  if (!file.type.startsWith('image/')) {
    this.error = 'Images only'; return;
  }
  // validate size (5 MB)
  if (file.size > 5 * 1024 * 1024) {
    this.error = 'Max 5 MB'; return;
  }
  this.file = file;

  // preview an image without uploading
  const reader = new FileReader();
  reader.onload = () => this.preview = reader.result as string;
  reader.readAsDataURL(file);
}
