Reactive forms recap: the control hierarchy

Angular reactive forms are built from three primitives that compose into a tree:

The hierarchy

// FormControl — single value
new FormControl('Alice')

// FormGroup — object of named controls
new FormGroup({
  name:  new FormControl(''),
  email: new FormControl(''),
})

// FormArray — ordered list of controls
new FormArray([
  new FormControl('first item'),
  new FormControl('second item'),
])

FormBuilder shorthand

// Inject FormBuilder — cleaner syntax
constructor(private fb: FormBuilder) {}

form = this.fb.group({
  name:   ['', Validators.required],
  phones: this.fb.array([    // ← FormArray
    this.fb.control(''),
  ]),
});
AbstractControl: FormControl, FormGroup, and FormArray all extend AbstractControl, giving them the same core API: .value, .valid, .errors, .disable(), .valueChanges, etc.

FormArray — what problem it solves

A FormGroup has a fixed, named set of controls. It cannot grow or shrink at runtime. FormArray solves this: it's an ordered, dynamic list of controls. Each item can be a FormControl (a single value), a FormGroup (an object with fields), or even another FormArray (nested arrays).

What FormGroup can't do

// FormGroup: fixed keys, set at build time
form = fb.group({
  phone1: [''],
  phone2: [''],
  // What if the user wants 5 phones?
  // What if they only want 1?
  // Hard-coding is not the answer.
});

What FormArray enables

// FormArray: dynamic list, grows/shrinks
form = fb.group({
  phones: fb.array(['']),  // starts with 1
});

addPhone() {
  this.phones.push(fb.control(''));
}

removePhone(i: number) {
  this.phones.removeAt(i);
}

FormArray API reference

Method / PropertyDescription
.controlsArray of all child AbstractControl instances. Use in templates with *ngFor="let ctrl of myArray.controls".
.lengthNumber of controls in the array.
.at(index)Returns the control at the given index. Useful when you need a typed reference inside code.
.push(control)Appends a new control to the end of the array.
.insert(index, control)Inserts a control at the given index, shifting later controls down.
.removeAt(index)Removes and destroys the control at the given index.
.clear()Removes all controls from the array.
.setControl(index, control)Replaces the control at the given index with a new one (e.g., swap from disabled to enabled).
.valueArray of all control values. Same order as .controls.
.validtrue only if every control in the array is valid (and the array-level validator passes).
.valueChangesObservable that emits a new array value whenever any child control changes.
.getRawValue()Like .value but includes the values of disabled controls (which .value omits).

FormArray in templates

The template wires up to a FormArray using three directives: formArrayName to declare the array, *ngFor to iterate over its controls, and either formGroupName or formControlName per item.

Array of simple controls

<form [formGroup]="form">
  <div formArrayName="phones">
    <div *ngFor="let ctrl of phones.controls; let i = index">
      <input [formControlName]="i" placeholder="Phone" />
      <button (click)="removePhone(i)">Remove</button>
    </div>
  </div>
  <button (click)="addPhone()">Add phone</button>
</form>

Array of FormGroups

<div formArrayName="contacts">
  <div
    *ngFor="let g of contacts.controls; let i = index"
    [formGroupName]="i">
    <input formControlName="name"  />
    <input formControlName="email" />
  </div>
</div>

Note: [formGroupName]="i" uses property binding because i is a number, not a static string.

Add / remove / reorder patterns

export class ContactsFormComponent {
  form = this.fb.group({
    contacts: this.fb.array([this.newContact()]),
  });

  // Getter for type-safe template access
  get contacts() {
    return this.form.get('contacts') as FormArray;
  }

  // Factory method — keeps the group definition in one place
  private newContact() {
    return this.fb.group({
      name:  ['', [Validators.required, Validators.minLength(2)]],
      email: ['', [Validators.required, Validators.email]],
    });
  }

  addContact()              { this.contacts.push(this.newContact()); }
  removeContact(i: number) { this.contacts.removeAt(i); }

  // Reorder: swap item at index i with i-1 (move up)
  moveUp(i: number) {
    if (i === 0) return;
    const ctrl = this.contacts.at(i);
    this.contacts.removeAt(i);
    this.contacts.insert(i - 1, ctrl);
  }
}

Nested FormGroups inside FormArray

Each item in a FormArray can itself be a FormGroup containing multiple controls. This is the standard pattern for repeating structured objects (a list of addresses, line items in an order, team members in a project).

// Nested structure: FormArray<FormGroup<{name, qty, price}>>
lineItems = fb.array([
  fb.group({ product: ['Widget'], qty: [2],  price: [9.99]  }),
  fb.group({ product: ['Gadget'], qty: [1],  price: [24.99] }),
]);

// Template iterates using [formGroupName]="i"
// and accesses nested controls with formControlName
Tip — computed values: Total price per line item is not a form control — it's a derived value. Compute it in the component with item.value.qty * item.value.price, or use a computed() signal if you have signal-based forms. Do not create redundant controls for computed values.

FormArray validators

You can attach validators to the FormArray itself (not just to individual controls). Array-level validators receive the entire FormArray and can check things like minimum count, no duplicates, or at least one item required.

Custom array-level validator

// Validator: at least N items required
function minLengthArray(min: number): ValidatorFn {
  return (ctrl: AbstractControl) => {
    const arr = ctrl as FormArray;
    return arr.length < min
      ? { minLengthArray: { required: min, actual: arr.length } }
      : null;
  };
}

Attaching to FormArray

contacts = fb.array(
  [this.newContact()],
  [minLengthArray(1), maxLengthArray(5)]
);

// Check errors in template:
<span *ngIf="contacts.errors?.['minLengthArray']">
  At least 1 contact required
</span>

No-duplicates validator

function noDuplicateEmails(ctrl: AbstractControl) {
  const arr = (ctrl as FormArray).controls;
  const emails = arr.map(g =>
    (g as FormGroup).get('email')?.value
  );
  const hasDupe = emails.length !== new Set(emails).size;
  return hasDupe ? { duplicateEmail: true } : null;
}

Cross-item validator (async)

// Async validator: check if any email is already registered
const checkEmails: AsyncValidatorFn = (ctrl) => {
  const emails = (ctrl as FormArray).value
    .map((g: any) => g.email);
  return userService.checkEmails(emails).pipe(
    map(taken => taken.length ? { takenEmails: taken } : null)
  );
};

Typed Reactive Forms (Angular 14+)

Angular 14 introduced full TypeScript generics for all form classes. FormArray<FormGroup<{...}>> means .value and .at() return properly typed objects instead of any.

// Fully typed: no 'any' anywhere
type ContactForm = FormGroup<{
  name:  FormControl<string>;
  email: FormControl<string>;
}>;

contacts: FormArray<ContactForm> = new FormArray<ContactForm>([]);

addContact() {
  this.contacts.push(
    new FormGroup({
      name:  new FormControl('', { nonNullable: true, validators: Validators.required }),
      email: new FormControl('', { nonNullable: true, validators: Validators.email   }),
    })
  );
}

// .value is now: Array<{ name: string; email: string }>
const firstEmail: string = this.contacts.at(0).value.email; // fully typed!
nonNullable: true means the control's value type is string instead of string | null. This makes the .value return type cleaner and eliminates many null checks. Always set this for controls that should never be null.

Multi-step wizard forms

A wizard pattern uses a separate FormGroup per step. Each step validates independently. The final step aggregates all step values using FormGroup.getRawValue().

export class OnboardingWizardComponent {
  currentStep = 0;

  step1 = fb.group({
    firstName: ['', Validators.required],
    lastName:  ['', Validators.required],
  });

  step2 = fb.group({
    email:    ['', [Validators.required, Validators.email]],
    phone:    [''],
  });

  step3 = fb.group({
    plan:     ['free', Validators.required],
    agree:    [false, Validators.requiredTrue],
  });

  steps = [this.step1, this.step2, this.step3];

  next() {
    if (this.steps[this.currentStep].invalid) return;
    this.currentStep++;
  }

  submit() {
    const allData = {
      ...this.step1.getRawValue(),
      ...this.step2.getRawValue(),
      ...this.step3.getRawValue(),
    };
    console.log(allData);
  }
}

Performance: large FormArrays & OnPush

The problem

With the default change detection strategy, Angular re-checks every row's template on any change. A FormArray with 500 rows means 500 re-checks per keystroke in any field.

  • Use ChangeDetectionStrategy.OnPush on row components
  • Pass control.value as an @Input — OnPush then only re-renders the specific row that changed
  • Use trackBy in *ngFor to prevent DOM recycling on every array mutation

Solution pattern

// Row component uses OnPush
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class ContactRowComponent {
  @Input() control!: FormGroup;
  @Input() index!: number;
}

// Template uses trackBy on the FormArray
<app-contact-row
  *ngFor="let g of contacts.controls; trackBy: trackByIndex"
  [control]="g"
/>
// trackByIndex(i) { return i; }
