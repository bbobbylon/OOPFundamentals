Mapped Types

Loop over the keys of one type to build another. { [K in keyof T]: ... } is the type-level for loop — and the engine behind Partial, Readonly, Pick, Record and most of TS's other utility types.

1. Syntax — the type-level for loop

type Stringify<T> = {
  [K in keyof T]: string;
};

type User = { id: number; name: string; active: boolean };
type U = Stringify<User>;
// { id: string; name: string; active: string }

Read it as a loop: "for every key K in the keys of T, make a property K whose value is <something>". The something on the right side is free to reference K and T[K] — that's where the work happens.

Three moving parts:
1. The key source — usually keyof T, but can be any union of string | number | symbol.
2. The key name — the loop variable, by convention K.
3. The value type — what each property maps to. Often involves T[K] to "look up the original value type".

2. The keyof + T[K] pair

Mapped types almost never appear without keyof and indexed access. They're the supporting cast.

type Person = { name: string; age: number; admin: boolean };

// keyof gives you the union of keys
type K = keyof Person;       // 'name' | 'age' | 'admin'

// T[K] is indexed access — "the type at key K"
type V = Person[keyof Person]; // string | number | boolean
type N = Person['name'];         // string

Put together: a mapped type that does an identity transformation — every property mapped to itself — and the world's tiniest utility:

type Identity<T> = { [K in keyof T]: T[K] };
type I = Identity<Person>;
// { name: string; age: number; admin: boolean } — same shape, fresh object type

This identity form is sometimes useful on its own: it forces TS to flatten a complex computed type into a plain object literal in tooltips. Often wrapped as Prettify<T>.

type Prettify<T> = { [K in keyof T]: T[K] } & {};
// Hover Prettify<X & Y> in your editor and you see one flat object,
// not "X & Y" — much nicer for debugging types.

3. Modifiers: readonly and ?

You can add property modifiers in front of the value type. These are the engines of Readonly and Partial:

type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

type User = { id: number; name: string };
type R = MyReadonly<User>;
// { readonly id: number; readonly name: string }
type P = MyPartial<User>;
// { id?: number; name?: string }

You can combine them. Order is: readonly [K in keyof T]?: T[K] — modifier on the left, optional ? after the brackets.

4. Stripping modifiers with -

Prefix a modifier with - to remove it. This is how Required works — it removes the optional flag from every property.

type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

type Frozen = { readonly id: number; readonly name?: string };
type M = Mutable<Frozen>;
// { id: number; name?: string }  — readonly stripped
type R = MyRequired<Frozen>;
// { readonly id: number; readonly name: string } — optional stripped

Without a sign, TS uses + by default. You'll occasionally see +readonly written explicitly, but it's redundant.

5. Key remapping with as

TS 4.1 added the as clause to mapped types. It lets you rewrite the key name itself — not just the value. Combined with template-literal types, this is the trick behind typed event-handler maps, getter/setter generators, and prefix/suffix transforms.

// Turn { name; age } into { getName; getAge } — typed
type Getters<T> = {
  [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K];
};

type Person = { name: string; age: number };
type G = Getters<Person>;
// {
//   getName: () => string;
//   getAge:  () => number;
// }

The & string intersection narrows K (which is string | number | symbol in general) down to a string so the template literal can use it.

Naming the original key while remapping is a common ask — you can use a helper:

// Prefix every key with 'on' and capitalize: { click } → { onClick }
type EventHandlers<T> = {
  [K in keyof T as `on${Capitalize<K & string>}`]: (e: T[K]) => void;
};

type Events = { click: MouseEvent; submit: SubmitEvent };
type H = EventHandlers<Events>;
// { onClick: (e: MouseEvent) => void; onSubmit: (e: SubmitEvent) => void }

6. Filtering keys

If the as clause produces never for a particular key, that key gets dropped from the output. This is the trick that turns as into a key-level filter.

// Pick only the string-typed properties of T
type StringKeysOnly<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type User = { id: number; name: string; email: string; active: boolean };
type S = StringKeysOnly<User>;
// { name: string; email: string }

The other classic uses of "remap to never to drop":

// Drop function-valued properties (the inverse of "pick methods")
type NonMethods<T> = {
  [K in keyof T as T[K] extends Function ? never : K]: T[K];
};

// Drop a specific named key (a poor man's Omit)
type Drop<T, N extends PropertyKey> = {
  [K in keyof T as K extends N ? never : K]: T[K];
};

type U = Drop<User, 'id'>;
// { name: string; email: string; active: boolean }
Why "remap to never" drops keys: a property whose key type is never can't exist (there are no values of type never to use as the key). TS recognizes this and removes the property entirely. Same trick used at the value level produces a property whose value is never — which is very different. Make sure you're remapping the key (via as), not the value.

7. Homomorphic mapped types

This word sounds scary; it just means "preserves the shape of the input". A mapped type is homomorphic when it has the form { [K in keyof T]: ... } — iterating directly over keyof T, where T is a generic parameter.

Homomorphic mapped types are special because the compiler preserves modifiers (readonly, ?) and the array-ness of the input automatically.

type Box<T> = { [K in keyof T]: { value: T[K] } };

type A = { readonly id: number; name?: string };
type B = Box<A>;
// {
//   readonly id: { value: number };
//   name?: { value: string | undefined };  ← optionality kept!
// }

// Arrays are also handled — Box<string[]> gives you { value: string }[]
type C = Box<string[]>; // { value: string }[]

Contrast with the non-homomorphic form, where keys are sourced from a union (not keyof T):

type Record<K extends PropertyKey, V> = {
  [P in K]: V;
};
// Record doesn't iterate keyof T — it iterates the K union directly.
// So Record doesn't carry over modifiers (there's no T to take them from).
Rule of thumb: reach for the keyof T form when you're transforming an existing object type. Reach for K in SomeUnion when you're building a fresh shape from scratch (like Record).

8. Build your own utility types

Almost every built-in TS utility is a one-line mapped type. Here are five worth memorizing.

DeepReadonly — recurse into nested objects

type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object
    ? DeepReadonly<T[K]>
    : T[K];
};

type Cfg = { server: { host: string; port: number }; debug: boolean };
type Frozen = DeepReadonly<Cfg>;
// {
//   readonly server: { readonly host: string; readonly port: number };
//   readonly debug: boolean;
// }

NonNullableFields — strip null | undefined from every property

type NonNullableFields<T> = {
  [K in keyof T]: NonNullable<T[K]>;
};

type Form = { name: string | null; age: number | undefined };
type Submitted = NonNullableFields<Form>;
// { name: string; age: number }

Nullable — the opposite (add | null everywhere)

type Nullable<T> = { [K in keyof T]: T[K] | null };

PickByType — keep only properties whose value matches

type PickByType<T, U> = {
  [K in keyof T as T[K] extends U ? K : never]: T[K];
};

type Mixed = { id: number; name: string; ok: boolean; tag: string };
type OnlyStrings = PickByType<Mixed, string>;
// { name: string; tag: string }

Setters — mirror Getters, key remapping in action

type Setters<T> = {
  [K in keyof T as `set${Capitalize<K & string>}`]: (v: T[K]) => void;
};

type P = { name: string; age: number };
type S = Setters<P>;
// { setName: (v: string) => void; setAge: (v: number) => void }

10. Real-world patterns

Form state with parallel error fields

type FormErrors<T> = {
  [K in keyof T as `${K & string}Error`]?: string;
};

type SignupForm = { email: string; password: string };
type Errors = FormErrors<SignupForm>;
// { emailError?: string; passwordError?: string }

// Combine into one form state:
type FormState<T> = T & FormErrors<T>;

RxJS-style observables — every property becomes an Observable

type Observed<T> = {
  [K in keyof T]: Observable<T[K]>;
};
// Used by libraries like Angular's reactive forms / NgRx selectors.

Promisify every method on an object

type Promisified<T> = {
  [K in keyof T]: T[K] extends (...a: infer A) => infer R
    ? (...a: A) => Promise<Awaited<R>>
    : T[K];
};

type SyncFs = {
  readFile: (path: string) => Buffer;
  writeFile: (path: string, data: Buffer) => void;
};
type AsyncFs = Promisified<SyncFs>;
// {
//   readFile:  (path: string) => Promise<Buffer>;
//   writeFile: (path: string, data: Buffer) => Promise<void>;
// }

Typed action map for a reducer / state machine

type ActionMap<M> = {
  [K in keyof M]: { type: K; payload: M[K] };
};

type Payloads = {
  ADD_TODO: { text: string };
  REMOVE_TODO: { id: number };
  TOGGLE_TODO: { id: number };
};

type Actions = ActionMap<Payloads>[keyof Payloads];
// { type: 'ADD_TODO'; payload: { text: string } }
//   | { type: 'REMOVE_TODO'; payload: { id: number } }
//   | { type: 'TOGGLE_TODO'; payload: { id: number } }

That last pattern — mapped type indexed by keyof to flatten a record into a discriminated union — is one of the most useful idioms in the language.

The optional-vs-undefined trap

// Under default settings, these two types are equivalent:
type A = { name?: string };
type B = { name: string | undefined };

// But Required<> only strips the '?' — not the | undefined.
type RA = Required<A>; // { name: string } — '?' removed
type RB = Required<B>; // { name: string | undefined } — no '?' to remove!

// Enable exactOptionalPropertyTypes to keep these distinct in the type system.

When to reach for a mapped type: when you need a new object type whose shape is computed from another object type. If you find yourself writing the same nine field types with one twist — make them optional, wrap in a Promise, prefix with on — that's a mapped type waiting to happen. Combine with as for renaming/filtering, with conditional types for branching on each value, and with template-literal types for string-key transforms.
