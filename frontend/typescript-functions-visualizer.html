🔧 Functions in TypeScript — more than just adding types to parameters

Typing a simple function takes seconds — function greet(name: string): string — but real functions have optional and rest parameters, multiple valid signatures (overloads), and special return types like void, never, or a type predicate. TypeScript's function-type system is also how you describe what a callback looks like, which is essential for higher-order functions, DI tokens, and event handlers.

  • Parameters can be optional, default, or rest — the signature captures arity precisely.
  • Return types carry meaning — void (ignore it), undefined (returns nothing), never (never returns).
  • Overloads describe multiple call shapes — how HttpClient.get() returns different types by options.
  • Function types describe callbacks — the backbone of higher-order functions and DI tokens.

Return-type special cases

void — caller ignores the return value. undefined — explicitly returns nothing. never — the function never returns (always throws or loops).

Overloads: multiple signatures

function format(x: string): string; function format(x: number): string; — Angular's HttpClient uses this so http.get<T>(url) returns Observable<T>.

Angular / Spring: Angular DI tokens use call signatures, RxJS operators are higher-order functions with rich types, and void vs undefined matters in event callbacks like addEventListener. Overloads explain how HttpClient.get() returns either Observable<T> or Observable<HttpEvent<T>> by options.

1. The shape of a function type

A function type in TS is two things together: a parameter list and a return type. Three ways to write it — same meaning:

// (a) function declaration — hoisted, named
function add(a: number, b: number): number { return a + b; }

// (b) function expression — assigned to a variable
const add2: (a: number, b: number) => number =
  function (a, b) { return a + b; };

// (c) arrow function — inherits surrounding `this`
const add3 = (a: number, b: number): number => a + b;

The type of all three is (a: number, b: number) => number. Notice the arrow in a type position uses =>, while an arrow function also uses => — read by context.

2. Parameter types & positions

Parameter names in a function type are documentation — they don't have to match the implementation. Only the position and type matter.

type Greeter = (name: string) => string;

const g: Greeter = (person) => `Hi ${person}`; // ✅ rename allowed
const h: Greeter = () => 'Hi';                 // ✅ fewer params is fine
const i: Greeter = (a, b) => 'x';              // ❌ extra required param
Why fewer parameters is OK: the caller will pass an argument, the implementation just ignores it. This is how arr.forEach(x => ...) works when forEach would have given you (x, index, array).

3. Optional & default parameters

Trailing parameters can be marked optional with ?. Inside the function, their type becomes T | undefined.

function greet(name: string, greeting?: string): string {
  // greeting: string | undefined
  return `${greeting ?? 'Hi'}, ${name}`;
}

greet('Bob');             // "Hi, Bob"
greet('Bob', 'Howdy');    // "Howdy, Bob"
greet('Bob', undefined);  // ✅ same as omitting
greet('Bob', null);       // ❌ null is not undefined

A default value drops the | undefined from the type inside the function — but the call site can still omit it:

function greet2(name: string, greeting: string = 'Hi'): string {
  // greeting: string  (NOT string | undefined)
  return `${greeting}, ${name}`;
}
Optional and required are positional. function f(a?: number, b: string) is a syntax error — once a parameter is optional, every parameter after it must be optional too (or have a default).

4. Rest parameters & spreads

Rest params collect remaining arguments into an array. The annotation goes on the array type.

function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3);              // 6
sum(...[10, 20, 30]);      // 60 — spread into rest

Rest can be a tuple to keep per-position types:

function greet(...args: [name: string, age: number]) {
  return `${args[0]} is ${args[1]}`;
}
greet('Bob', 30);                // ✅
greet('Bob');                    // ❌ Expected 2 arguments

Combined with generics, you can forward arguments perfectly:

function withLog<A extends unknown[], R>(fn: (...args: A) => R) {
  return (...args: A): R => {
    console.log('calling with', args);
    return fn(...args);
  };
}

const loudAdd = withLog((a: number, b: number) => a + b);
loudAdd(2, 3);   // ✅ — preserves the (number, number) => number signature
loudAdd('x');    // ❌

5. Return-type inference & annotation

Omit the return annotation and TS infers it from the body. Almost always fine for private code — but on public APIs, annotate explicitly so adding a new branch doesn't silently change the signature.

// Inferred — convenient, but the return type is whatever the body produces today
function tagged(x: unknown) {
  if (typeof x === 'string') return { kind: 'str', v: x };
  return { kind: 'other', v: x };
}
// return type: { kind: 'str'; v: string } | { kind: 'other'; v: unknown }

// Annotated — adding a new branch that returns a different shape is now an error
type Tagged = { kind: 'str' | 'other'; v: unknown };
function tagged2(x: unknown): Tagged { /* ... */ }

6. void vs undefined vs never

TypeMeansUse for
void"Caller shouldn't use the return value"Event handlers, side-effect-only functions
undefined"This function returns the value undefined"Functions that explicitly produce undefined
never"This function does not return at all"Throws, infinite loops, exit-the-process functions
function sideEffect(): void       { console.log('hi'); }
function nothing():    undefined  { return undefined; }
function die(msg: string): never { throw new Error(msg); }
The void trick: when a callback parameter is typed as returning void, you can still pass a function that returns something — TS just ignores the value. That's why [1,2,3].forEach(n => arr.push(n)) works: push returns a number, but forEach's callback is typed => void, so the number is harmlessly discarded. 
function each(items: number[], cb: (n: number) => void) { items.forEach(cb); }
each([1, 2, 3], n => return n * 2); // ✅ — return value discarded

7. Contextual typing of callbacks

When a function is passed as an argument, TS uses the parameter type from the receiver to infer the callback's parameter types. No annotation needed.

const nums = [1, 2, 3];
nums.map(n => n * 2);
//        ↑ n is typed as number, because map's callback is (n: number, ...) => ...

document.addEventListener('click', e => e.clientX);
//                                  ↑ e is MouseEvent, because of the literal 'click'

document.addEventListener('keydown', e => e.key);
//                                    ↑ e is KeyboardEvent

This is how the DOM library's event-map typing works — the literal event name selects the right callback signature via an overloaded addEventListener.

8. Function overloads

When one function call site needs to accept differently-typed inputs and produce correspondingly-typed outputs — and you can't express it with a union — overload declarations let you list each supported signature, followed by one implementation signature that handles all cases.

// Overload signatures — what callers see
function parse(input: string): string[];
function parse(input: number): number;
function parse(input: boolean): boolean;

// Implementation signature — invisible to callers
function parse(input: string | number | boolean) {
  if (typeof input === 'string')  return input.split(',');
  if (typeof input === 'number')  return input * 2;
  return !input;
}

parse('a,b,c');  // string[]
parse(5);        // number
parse(true);     // boolean
parse(null);     // ❌ no overload matches
The implementation signature is invisible. Even though it accepts string | number | boolean, callers can only use one of the three declared overloads. If you find yourself writing overloads that all return the same union, consider a single signature with a union return — overloads should add precision.

Prefer a single generic over overloads when possible

// Overloaded — verbose
function first(xs: string[]): string;
function first(xs: number[]): number;
function first(xs: unknown[]) { return xs[0]; }

// Generic — one line, covers every type
function first2<T>(xs: T[]): T { return xs[0]; }

9. Call signatures & hybrid types

Sometimes a function value also has properties on it — like jQuery being both a function and an object. Describe it with a "callable" interface or type.

type Counter = {
  (start: number): string;   // call signature
  reset(): void;
  interval: number;
};

function makeCounter(): Counter {
  const c = (start: number) => `starting at ${start}`;
  c.reset = () => { /* ... */ };
  c.interval = 100;
  return c as Counter;
}

const ctr = makeCounter();
ctr(5);          // "starting at 5"
ctr.reset();
ctr.interval;     // 100

Call signature inside an interface

interface Greet {
  (name: string): string;
  defaultName: string;
}

10. Construct signatures

The new in front of the signature says "this value can be called with new". Used by APIs that take a class itself as an argument.

type Ctor<T> = new (...args: any[]) => T;

function create<T>(C: Ctor<T>): T {
  return new C();
}

class Service {}
const s = create(Service); // s: Service

Hybrid: a single type can be both callable and constructible (think Date — Date() as a function returns a string, new Date() returns a Date).

interface DateLike {
  (): string;
  new(): Date;
}

11. Typing this

Arrow functions inherit this from their enclosing scope. Regular functions have their own this bound by how they're called. When TS can't tell what this will be, add a fake first parameter named this — it doesn't show up at runtime.

interface Db { tables: string[]; }

function addTable(this: Db, name: string) {
  this.tables.push(name);
}

const db: Db = { tables: [] };
addTable.call(db, 'users');   // ✅ this is Db
addTable('users');            // ❌ this would be undefined in strict mode

this in classes

class Counter {
  count = 0;

  // Polymorphic this: returns the actual subclass type, not just Counter
  add(n: number): this { this.count += n; return this; }
}

class StepCounter extends Counter { step = 10; }

const sc = new StepCounter().add(5);
// sc: StepCounter — NOT Counter — because of `this` return type

12. Predicate & assertion returns

Two special return-type forms that influence the caller's types. See the Narrowing visualizer for full coverage — the short version:

// Type predicate — informs the caller's narrowing
function isString(x: unknown): x is string {
  return typeof x === 'string';
}

// Assertion function — throws on failure, narrows on success
function assertString(x: unknown): asserts x is string {
  if (typeof x !== 'string') throw new Error();
}
