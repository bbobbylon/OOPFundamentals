Java Control Flow

if/else, switch (old & new), all loop forms, break, continue, labeled statements, and pattern matching.

🔀 What is control flow — and how has switch evolved from a jump table to pattern matching?

Control flow is the order statements run — conditionals (if/else), loops (for/while/do-while), and jumps (break/continue/return). Modern Java upgraded it: the switch expression (Java 14+) uses -> arrows with no fall-through, compiler-checked exhaustiveness, and a returned value, while pattern matching (instanceof 16+, switch 21) tests a type and binds a variable in one step — and with sealed types the compiler verifies you handled every subtype.

  • Three building blocks: conditionals, loops, jumps.
  • Switch expressions kill fall-through — arrows, a returned value, exhaustiveness checked.
  • Pattern matching tests + binds — if (obj instanceof User u), no manual cast.
  • Sealed + switch = exhaustive — a new subtype is a compile error until handled.

Old vs new switch

Old (statement, fall-through): switch (status) { case ACTIVE: doA(); break; case SUSPENDED: doB(); break; default: doC(); }. Forget break → ACTIVE also runs SUSPENDED code. New (expression, no fall-through): String label = switch (status) { case ACTIVE -> "Active"; case SUSPENDED -> "Suspended"; case LOCKED -> "Locked"; }. Compiler ensures all enum cases are covered (no default needed). Can use yield for multi-line blocks: case ACTIVE -> { log("active"); yield "Active"; }.

Loops: for-each vs indexed vs while

For-each: for (User u : users) — cleanest, no index, works on any Iterable. Indexed: for (int i = 0; i < users.size(); i++) — use when you need the index. While: while (hasMore) — for condition-driven loops without known count. Do-while: do { ... } while (retry) — runs at least once. break: exits the innermost loop. continue: skips to next iteration. Labeled break outer: exits a named outer loop (rarely needed — usually a sign to extract a method). break in switch exits the switch. Don't use for(;;) unless you have a break inside — infinite loop.

Pattern matching instanceof (Java 16+)

Old: if (obj instanceof User) { User u = (User) obj; u.getEmail(); } — check then cast, redundant. New: if (obj instanceof User u) { u.getEmail(); } — one step, u in scope. Switch pattern matching (Java 21): switch (shape) { case Circle c -> Math.PI * c.radius() * c.radius(); case Rectangle r -> r.width() * r.height(); }. Guards: case User u when u.isAdmin() -> handleAdmin(u). With sealed classes, compiler verifies all subtypes handled — no default needed.

CIAM / Spring Boot: A switch expression routes by IdP — switch (user.getIdpType()) { case PING -> …; case ENTRA -> …; case KEYCLOAK -> …; } — and adding a new IdP enum value makes it a compile error until the case exists. Pattern matching replaces cast chains for claims: if (claim instanceof ListClaim lc) return lc.values(); else if (claim instanceof StringClaim sc) return List.of(sc.value());.

or, the case your default was never going to catch

The problem

You wrote a default case. Java throws before it ever gets there.

default doesn't mean "everything else" — null skips it entirely

You write a defensive-looking switch on a form field: switch (status) { case "ACTIVE" -> activate(); case "SUSPENDED" -> suspend(); default -> log("unexpected: " + status); }. It has a default, so it looks total — every input, however weird, should land somewhere. It compiles clean, passes review, and passes every test where status is actually set to something.

Nobody wrote the test for the field that's simply missing. status arrives as null — an optional form field, an absent JSON key deserialized as null — and the switch throws NullPointerException at the switch statement itself, before comparing against a single case. default never runs, because Java checks for null before it evaluates any label at all.

every named case ✓ the default branch ✓ the day status is just missing ⚠

default catches every value that reaches case-matching. null never reaches case-matching — it throws first.

Make the missing case an ordinary case
Null-check or normalize before the switch ↓ status = Objects.requireNonNullElse(status, "UNKNOWN"); turns the missing value into an ordinary case, so default really is total again Or add an explicit case null (Java 21+ pattern-matching switch) ↓ case null -> handleMissing(); lets the switch handle the absence on purpose, right next to the cases it's missing among And write the one test that sends null
The one-sentence rule. A classic switch — and a Java 21 pattern-matching switch with no case null — throws NullPointerException the instant the selector is null, before any label, including default, is ever considered; default is total over the non-null cases only.

The mechanism

What the JVM checks before it looks at a single case.

  1. switch (status) begins executingstart
  2. the selector expression status is evaluated to get its valueevaluate
  3. the JVM checks: is that value null?null check
  4. if yes — for a classic switch, or a pattern-matching switch with no case null — a NullPointerException is thrown right herethrow
  5. case labels are compared against the value only if it's non-nullmatch cases
  6. default is chosen only when execution reaches this step and nothing else matched — a step null never reachesdefault

Steps 3 and 4 happen before any code you wrote runs. The null check isn't one of your cases competing for a match — it's a gate in front of all of them, including default.

Every case reacts the same way to null: not at all. The surprising one is default, because it's the branch you specifically wrote to catch "anything else" — and it's exactly as skipped as the rest.

A form handler runs switch (status) { case "ACTIVE" -> activate(); case "SUSPENDED" -> suspend(); default -> log("unexpected: " + status); }. The status field is optional and arrives as null when the client omits it. What happens when that request comes in?

Right — Java checks whether the selector is null before it looks at a single case label, including default. The switch throws immediately; the log line never executes.

That's the natural assumption — default reads as "anything I didn't name" — but null is special-cased to throw before case-matching even starts, so default doesn't get the chance.

Java never silently "falls through" a switch when nothing matches a non-null value, and that isn't what happens here either — the actual outcome is louder: an uncaught exception.

Common Patterns & Pitfalls

// Pattern: early return — avoids deep nesting void process(User user) { if (user == null) return; if (!user.isActive()) return; if (!user.hasPermission()) return; // main logic at low nesting doWork(user); } // vs. "arrow" antipattern: void process(User user) { if (user != null) { if (user.isActive()) { if (user.hasPermission()) { doWork(user); // 3 levels deep! } } } }
// Pitfall: dangling else if (a > 0) if (b > 0) System.out.println("both positive"); else System.out.println("?"); // else belongs to inner if! use braces to be safe // Always use braces — even for one-liners if (cond) doA(); // easy to forget when adding line 2 doB(); // NOT in the if — always runs! // Better: if (cond) { doA(); }

Classic switch Statement (Java 1.0) — fallthrough by default

switch (day) { // int, String, char, enum case "MONDAY": case "TUESDAY": // fallthrough: no break needed System.out.println("Weekday"); break; // MUST break or falls to next case case "SATURDAY": case "SUNDAY": System.out.println("Weekend"); break; default: System.out.println("Other"); }
// Classic switch: what it can switch on // ✓ byte, short, int, char // ✓ Byte, Short, Integer, Character (wrappers) // ✓ String (Java 7+) // ✓ enum values // ✗ long, float, double, boolean, objects // Fallthrough example (intentional) switch (level) { case 3: bonus += 300; // falls through! case 2: bonus += 200; // falls through! case 1: bonus += 100; break; }

Modern switch Expression (Java 14+) — no fallthrough, returns a value

// Switch expression — yields a value, arrow syntax String label = switch (day) { case "MONDAY", "TUESDAY", "WEDNESDAY", "THURSDAY", "FRIDAY" -> "Weekday"; case "SATURDAY", "SUNDAY" -> "Weekend"; default -> "Unknown"; }; // No break needed — arrows don't fall through // Multiple values per case with comma // Compiler checks exhaustiveness for enums
// yield keyword — for multi-statement cases int points = switch (grade) { case "A" -> 4; case "B" -> 3; case "C" -> 2; case "D" -> 1; default -> { log("Invalid grade: " + grade); yield 0; // yield from block } }; // Pattern matching switch (Java 21) switch (obj) { case Integer i -> System.out.println("int: "+i); case String s -> System.out.println("str: "+s); case null -> System.out.println("null"); default -> System.out.println("other"); }

for loop — when you know the count

// Classic for: init; condition; update for (int i = 0; i < 5; i++) { System.out.println(i); // 0 1 2 3 4 } // Count down for (int i = 10; i >= 0; i -= 2) { System.out.print(i + " "); // 10 8 6 4 2 0 } // Multiple init/update for (int i = 0, j = 10; i < j; i++, j--) { System.out.println(i + "," + j); } // Infinite loop with break for (;;) { if (done) break; }
// Enhanced for (for-each) — iterate collections/arrays int[] nums = {1, 2, 3, 4, 5}; for (int n : nums) { System.out.print(n + " "); } List<String> names = List.of("Alice", "Bob"); for (String name : names) { System.out.println(name); } // Pitfall: can't modify index or use index // Use regular for if you need the index for (int i = 0; i < names.size(); i++) { System.out.println(i + ": " + names.get(i)); }

while & do-while — when count is unknown

// while — checks condition BEFORE each iteration int i = 0; while (i < 5) { System.out.println(i); i++; } // If i is already 5: zero iterations // Common: read until sentinel Scanner sc = new Scanner(System.in); String line; while (!(line = sc.nextLine()).isEmpty()) { process(line); }
// do-while — checks condition AFTER each iteration // Guaranteed to run at least once int n; do { n = getInput(); // prompts user until valid input } while (n < 1 || n > 10); // Menu loop example int choice; do { showMenu(); choice = sc.nextInt(); handleChoice(choice); } while (choice != 0); // 0 = exit

Choosing the Right Loop

for
Known iteration count, index needed, or iterating collection. Most common.
while
Condition-based, may run zero times (polling, reading input).
do-while
Must run at least once (menus, validation loops).

break — exit the loop immediately

// break exits the innermost loop for (int i = 0; i < 10; i++) { if (i == 5) break; // stops at 5 System.out.print(i + " "); // 0 1 2 3 4 } // Search pattern — find and stop int target = 42, foundAt = -1; for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { foundAt = i; break; // no need to keep searching } }
// Labeled break — exit outer loop outer: for (int i = 0; i < 5; i++) { for (int j = 0; j < 5; j++) { if (matrix[i][j] == target) { found = true; break outer; // exits BOTH loops } } } // Continues here after break outer // break in switch — exits the switch switch (x) { case 1: doA(); break; // no fallthrough case 2: doB(); break; }

continue — skip current iteration

// continue skips the rest of this iteration for (int i = 0; i < 10; i++) { if (i % 2 == 0) continue; // skip evens System.out.print(i + " "); // 1 3 5 7 9 } // Filter and process pattern for (User user : users) { if (!user.isActive()) continue; if (user.getAge() < 18) continue; sendEmail(user); }
// Labeled continue — skip to next outer iteration outer: for (int i = 0; i < 3; i++) { for (int j = 0; j < 3; j++) { if (j == 1) continue outer; System.out.println(i + "," + j); } } // Prints: 0,0 1,0 2,0 // (j=1 triggers skip of rest of inner loop) // return — exits the entire method for (Order o : orders) { if (o.isFulfilled()) return true; } return false;
