Angular Zoneless Mode (v19+)

What is Angular Zoneless Mode — and why is Zone.js the source of Angular's infamous change-detection overhead?

Traditional Angular uses Zone.js — a library that monkey-patches every asynchronous browser API: setTimeout, setInterval, Promise.then, addEventListener, XMLHttpRequest, fetch. After any of these async operations complete, Zone.js tells Angular "something might have changed — run change detection." Angular then walks the entire component tree, checking every binding. If you have 200 user rows, Angular checks all 200 — even if only one changed. Zoneless mode (Angular 18+ stable, 17 experimental) removes Zone.js entirely. Angular no longer polls the entire tree — components only re-render when you explicitly tell Angular they need to: via Signals (signal(), computed()), or via ChangeDetectorRef.markForCheck(). Signals are the preferred mechanism — when a signal's value changes, Angular precisely knows which templates read that signal and re-renders only those. This is called fine-grained reactivity. Enable: bootstrapApplication(AppComponent, { providers: [provideExperimentalZonelessChangeDetection()] }) (v18+) or provideZonelessChangeDetection() (v19+). Remove zone.js from polyfills in angular.json. Result: smaller bundle, lower CPU overhead, faster initial paint.

Zone.js vs Zoneless

With Zone.js: click a button → Zone.js intercepts the click event handler → after it completes, calls zone.run() → Angular's ApplicationRef.tick() → walks every component tree from root → checks all bindings. 100 components = 100 checks per event. Zoneless: click a button → your handler runs → if you call signal.set(newValue) → Angular schedules a microtask → re-renders only the components that read signal() in their template. 3 components read the signal = 3 checks. The rest: untouched. Also means no Zone.js bundle (~48KB min+gzip) = smaller app.

Signals in Zoneless

@Component({ template: `<p>Users: {{userCount()}}</p>` }) class DashboardComponent { userCount = signal(0); // signal writable adminCount = computed(() => this.users().filter(u => u.isAdmin).length ); // derived, updates when users changes ngOnInit() { this.userService.getUsers().subscribe(users => { this.users.set(users); // set() triggers fine-grained update }); } }. Template reads userCount() (called as a function). When users.set() is called, Angular knows exactly which templates to re-render — only those that read users() or adminCount().

Migration path

You can migrate gradually. Step 1: Add ChangeDetectionStrategy.OnPush to all components — components only check when their @Input()s change or you call markForCheck(). This reduces Zone.js overhead without removing it. Step 2: Replace @Input() with signal inputs (input()), internal state with signal(), derived state with computed(). Step 3: Enable zoneless. Components that still use RxJS: wrap with toSignal(observable$) — converts an Observable to a Signal, works in zoneless mode. Angular material and router are already zoneless-compatible in v18+.

In CIAM / Angular: A CIAM user management table with 500 rows: with Zone.js + Default change detection, every click triggers checks on all 500 UserRowComponents. With Signals + Zoneless: users = signal<UserDto[]>([]) in the service. selectedUserId = signal<number|null>(null). Each UserRowComponent reads isSelected = computed(() => this.selectedId() === this.user().id). Clicking a row calls selectedUserId.set(user.id) — Angular re-renders only the previously selected row (deselect) and the newly selected row (select). 498 rows: untouched, zero change-detection work. JWT refresh indicator: isRefreshing = signal(false) — only the header component that reads this signal re-renders during token refresh. No polling, no Zone.js overhead.

What is Zone.js — and why is it being removed?

  
Zone.js is a library that monkey-patches every async browser API — setTimeout, Promise.then, addEventListener, fetch, and more — to intercept when an async operation completes. Angular uses this as a trigger to run change detection across the entire component tree.


  

    

      
Zone.js patch layer

      
Monkey-patches setTimeout, Promise, fetch, addEventListener. Creates an execution "zone" that fires notifications when tasks enter/exit.

    

    

      
NgZone (Angular)

      
Angular's wrapper around the NgZone. Listens for onMicrotaskEmpty — fires after every microtask queue flush. This is when CD triggers.

    

    

      
Change Detection loop

      
Angular walks the entire component tree top-down, comparing current values to previous snapshot. Renders updated bindings to DOM.

    

    

      
The cost

      
Runs on EVERY async event — a mousemove, a setInterval tick, any Promise. Large trees = expensive checks. Plus ~56KB bundle just for zone.js.

    

  


  
The problem with Zone.js

  

    

      
What Zone.js triggers CD on

      
    
        
  • Every click, keyup, mousemove
    • 
        
  • Every setTimeout / setInterval
    • 
        
  • Every Promise resolution
    • 
        
  • Every HTTP response
    • 
        
  • Every WebSocket message
    • 
        
  • Any third-party library async code
    • 
      

      
Angular literally cannot tell if the event changed anything. It always checks.

    

    

      
What Zoneless triggers CD on

      
    
        
  • Signal writes ONLY
    • 
        
  • Nothing else causes a check
    • 
        
  • Angular knows exactly WHICH signals changed
    • 
        
  • Only components that read those signals re-render
    • 
        
  • No surprise checks from third-party timers
    • 
        
  • Predictable, auditable render graph
    • 
      

    

  


  

    Zone.js bundle cost: zone.js itself is ~56KB (minified+gzipped: ~18KB). More importantly, it parses and patches the entire async API surface at startup — adding latency even on fast devices. Every Angular app has paid this cost since v2. Zoneless eliminates it entirely.

// The old world (zone-based) — triggered on anything async:
setTimeout(() => {
  // Zone.js intercepts this. When it finishes, Angular runs CD.
  // Even if you didn't change any component state. Wasteful.
  console.log('hello');
}, 1000);

// The new world (zoneless) — only signals trigger CD:
setTimeout(() => {
  // Angular does NOT intercept this. No CD runs.
  // If you need state to update, write to a signal:
  this.message.set('updated!');  // THIS triggers CD, only for components reading it
}, 1000);







  
Setting up Zoneless mode

  
Three changes are needed to go fully zoneless in an existing Angular project.


  
Step 1 — Replace the zone provider in app.config.ts

  

    
// app.config.ts — Angular 19+
import { ApplicationConfig, provideZonelessChangeDetection } from '@angular/core';
import { provideRouter } from '@angular/router';

export const appConfig: ApplicationConfig = {
  providers: [
    // ❌ Remove this:
    // provideZoneChangeDetection({ eventCoalescing: true }),

    // ✅ Add this instead:
    provideZonelessChangeDetection(),

    provideRouter(routes),
  ]
};

    

      v18 name: in Angular 18 the function was called provideExperimentalZonelessChangeDetection(). In v19 it was promoted to stable as provideZonelessChangeDetection(). Both exist; use the non-experimental one in new code.

Step 3 — Remove zone.js from package.json (optional but recommended)

    // "zone.js": "^0.15.0",

npm uninstall zone.js

Step 4 — Set ChangeDetectionStrategy.OnPush on every component

  

    
In zoneless mode, OnPush is effectively the default — components only re-check when their signals change. But you should explicitly set it for clarity and for lint rules.

    
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,   // ← required for zoneless
  template: `
    <button (click)="increment()">+</button>
    <span>{{ count() }}</span>
  `
})
export class CounterComponent {
  count = signal(0);
  increment() { this.count.update(n => n + 1); }
}

    

      In Angular 19+, new projects scaffold with OnPush as the default when you choose zoneless. The CLI sets this automatically. For existing projects, use ng update plus the schematics to migrate automatically.
    

  


  
Step 5 — Remove zone.js from main.ts (if referenced directly)

  

    
// main.ts — check for explicit imports

import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig).catch(err => console.error(err));

// Complete zoneless component — signal drives everything
@Component({
  selector: 'app-user-card',
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div class="card">
      <h2>{{ user().name }}</h2>
      <p>Score: {{ formattedScore() }}</p>
      <p [class.active]="isActive()">{{ statusLabel() }}</p>
      <button (click)="addPoint()">+1 Point</button>
    </div>
  `
})
export class UserCardComponent {
  // Signal input (v17+)
  user = input.required<User>();

  // Local writable state
  bonusPoints = signal(0);

  // Derived — recomputes when user() or bonusPoints() changes
  totalScore  = computed(() => this.user().score + this.bonusPoints());
  formattedScore = computed(() => this.totalScore().toLocaleString());
  isActive    = computed(() => this.totalScore() > 1000);
  statusLabel = computed(() => this.isActive() ? 'Active' : 'Inactive');

  addPoint() { this.bonusPoints.update(n => n + 1); }
  // When addPoint() runs: bonusPoints changes → totalScore recomputes → formattedScore
  // recomputes → isActive recomputes → statusLabel recomputes → Angular
  // schedules a re-render ONLY for this component. NavBar? Untouched.
}

BEFORE — Zone-based

      

        // No changeDetection specified (defaults to Default)
        @Component({ selector: 'app-todo', ... })
        export class TodoComponent {
          todos: Todo[] = [];         // plain array
          loading = false;            // plain boolean
          filter = 'all';            // plain string

            this.loading = true;

              this.loading = false;
            });
          }
          get filtered() {
            return this.todos.filter(  // recomputed every CD cycle
              t => this.filter === 'all' || t.done === (this.filter === 'done'));
          }
        }
      

    

    

      
AFTER — Zoneless signals

      

        // OnPush + signals = zoneless
        @Component({ ..., changeDetection: OnPush })
        export class TodoComponent {
          todos   = signal<Todo[]>([]);  // writable signal
          loading = signal(false);
          filter  = signal<'all'|'done'|'pending'>('all');
        
          private svc = inject(TodoService);
        
          constructor() {
            this.loading.set(true);
            toSignal(this.svc.getAll(), { injector: ... });
            // or use resource():
            // todoRes = resource({ loader: () => ... });
          }
          filtered = computed(() =>     // only recomputes when deps change
            this.todos().filter(t =>     // lazy evaluation
              this.filter() === 'all' || t.done === (this.filter() === 'done')));
        }

Third-party library compatibility

  

    The main migration risk. Libraries that use timers, Promises, or callbacks internally to update state may stop working correctly in zoneless mode. Common offenders: drag-drop libraries, rich text editors, chart libraries, date pickers that use native inputs.
  


  
// Pattern for wrapping third-party library callbacks:
import { NgZone, inject } from '@angular/core';

export class ChartComponent {
  private ngZone = inject(NgZone);
  selection = signal<DataPoint | null>(null);

  ngAfterViewInit() {
    // Third-party chart lib uses its own callbacks
    this.chart = new Chart(canvas, {
      onClick: (dataPoint) => {
        // Run inside Angular zone, OR write to signal:
        this.ngZone.run(() => {
          this.selection.set(dataPoint);  // signal write triggers CD
        });
        // OR just write to signal (runs ngZone.run internally in v19+):
        // this.selection.set(dataPoint);
      }
    });
  }
}


  

    Angular 19 improvement: in v19, signal writes automatically schedule a CD check even outside NgZone. So in many cases, you can simply write to a signal in a third-party callback without ngZone.run(). The old wrapper is only needed if the library itself needs to detect that CD has run (rare).
  


  
Testing in zoneless mode

  

    
// TestBed setup for zoneless components
import { TestBed } from '@angular/core/testing';
import { provideZonelessChangeDetection } from '@angular/core';

describe('CounterComponent', () => {
  beforeEach(async () => {
    await TestBed.configureTestingModule({
      imports: [CounterComponent],
      providers: [provideZonelessChangeDetection()],  // ← key
    }).compileComponents();
  });

  it('increments on click', async () => {
    const fixture = TestBed.createComponent(CounterComponent);
    fixture.detectChanges();
    const btn = fixture.nativeElement.querySelector('button');
    btn.click();
    await fixture.whenStable();  // ← waits for CD to settle
    fixture.detectChanges();
    expect(fixture.nativeElement.querySelector('span').textContent).toBe('1');
  });
});
