Spring Boot OAuth2 Resource Server & JWT Security

Secure your REST API with Bearer token authentication. Spring Security validates JWTs automatically — you just configure the JWKS URI and annotate your endpoints.

🔑 What is an OAuth2 Resource Server — and how does it validate JWTs without calling the IdP on every request?

An OAuth2 Resource Server is a Spring Boot API that guards its endpoints by requiring a valid Bearer JWT on every request. Angular obtains the token from the IdP (Ping/Entra) and sends it; Spring Security validates it and grants or denies access. Validation is signature-based: decode the header for the kid + alg, fetch the IdP's JWKS (public RSA keys), verify the signature with the matching key, then check the claims (iss, aud, exp). Configure a jwk-set-uri and oauth2ResourceServer(jwt -> …) does all of it — fetching keys once, caching them, and validating every later request locally with no network hop.

  • Bearer in, decision out. No server-side session — the JWT itself carries identity and scopes.
  • Validation is local & cached. Keys load from jwk-set-uri once; an unknown kid after rotation triggers a refresh — which is why JWT auth scales.
  • Always check iss, aud, and exp — a valid signature alone isn't enough.
  • Claims → authorities. Scopes map to SCOPE_* by default; a custom converter maps a roles claim to ROLE_* for hasRole(...).
  • Read the token with @AuthenticationPrincipal Jwt jwt directly in the controller.

SecurityConfig (resource server)

@Configuration @EnableMethodSecurity // enables @PreAuthorize on methods public class SecurityConfig { @Bean public SecurityFilterChain filterChain(HttpSecurity http) throws Exception { return http .csrf(csrf -> csrf.disable()) // REST APIs use tokens, not CSRF cookies .sessionManagement(sm -> sm.sessionCreationPolicy(STATELESS)) // JWT = no sessions .authorizeHttpRequests(auth -> auth .requestMatchers("/health", "/actuator/info").permitAll() // public endpoints .requestMatchers("/api/admin/**").hasRole("ADMIN") // role-gated .anyRequest().authenticated() // everything else: must have token ) .oauth2ResourceServer(oauth2 -> oauth2 .jwt(jwt -> jwt .jwtAuthenticationConverter(jwtAuthConverter()) // map claims → authorities ) ) .build(); } } // application.yml: // spring.security.oauth2.resourceserver.jwt.jwk-set-uri: https://idp.example.com/jwks

JWT claims in controllers

@RestController @RequestMapping("/api/users") public class UserController { @GetMapping("/me") public UserProfile getProfile( @AuthenticationPrincipal Jwt jwt) { // Spring injects the validated JWT String sub = jwt.getSubject(); // user ID from IdP String email = jwt.getClaimAsString("email"); // custom claim String tenant = jwt.getClaimAsString("tid"); // Entra tenant ID List<String> scopes = jwt.getClaimAsStringList("scp"); // delegated scopes return userService.getProfile(sub, tenant); } @PostMapping("/admin/provision") @PreAuthorize("hasAuthority('SCOPE_users.admin')") // requires scp=users.admin in JWT public void provisionUser(@RequestBody ProvisionRequest req, @AuthenticationPrincipal Jwt jwt) { // Only reaches here if JWT contains scp=users.admin String callerSub = jwt.getSubject(); auditService.log("provision", callerSub, req); userService.provision(req); } }

Custom JWT converter (roles)

// JWT claims map to Spring Security "GrantedAuthority" objects // Default: Spring maps scopes (scp) as "SCOPE_{value}" authorities // Custom: map roles claim as "ROLE_{value}" authorities @Bean JwtAuthenticationConverter jwtAuthConverter() { var converter = new JwtGrantedAuthoritiesConverter(); // If IdP puts roles in a "roles" claim (not "scp"): converter.setAuthoritiesClaimName("roles"); converter.setAuthorityPrefix("ROLE_"); // enables hasRole("ADMIN") var jwtConverter = new JwtAuthenticationConverter(); jwtConverter.setJwtGrantedAuthoritiesConverter(converter); return jwtConverter; } // PING custom: Ping AM puts roles in "groups" or "memberOf" claim // ENTRA custom: Entra puts app roles in "roles" claim (app role assignments) // Custom implementation: @Bean JwtAuthenticationConverter customConverter() { var jwtConverter = new JwtAuthenticationConverter(); jwtConverter.setJwtGrantedAuthoritiesConverter(jwt -> { List<String> scopes = jwt.getClaimAsStringList("scp"); // delegated List<String> roles = jwt.getClaimAsStringList("roles"); // app roles return Stream.concat( (scopes==null?List.<String>of():scopes).stream().map(s -> "SCOPE_"+s), (roles==null?List.<String>of():roles).stream().map(r -> "ROLE_"+r) ).map(SimpleGrantedAuthority::new).collect(toList()); }); return jwtConverter; }

CIAM / your job: This is the core of your day job — APIs that accept JWTs from both Ping AM and Entra ID. Ping uses scp for scopes; Entra uses scp for delegated but roles for app-role assignments. JWKS URIs: Ping https://am.example.com/oauth2/jwks, Entra https://login.microsoftonline.com/{tenantId}/discovery/v2.0/keys. Accepting both (multi-IdP) needs a custom JwtDecoder that tries multiple issuers — see the multi-idm-claims page. Top production failures: aud mismatch (your client ID must be in aud), clock skew (time drift fails exp), and a key-rotation gap (the JWKS cache refreshing too slowly).

1. OAuth2 Roles — Where Does Spring Boot Fit?

Resource Owner
The end user who owns the protected data and grants access to it.
Alice (human user)
Client
The application that wants access. Gets tokens from the auth server to call the API.
React SPA, Mobile App, Another Microservice
Authorization Server
Issues JWT tokens after authenticating users/clients. Manages JWKS public keys.
Keycloak, Auth0, Okta, AWS Cognito, Azure AD
Resource Server ← YOU
Your Spring Boot API. Validates Bearer tokens and serves protected resources.
spring-security-oauth2-resource-server
Your Spring Boot app only plays the Resource Server role. It does NOT issue tokens — that's the Authorization Server's job. You configure the JWKS URI so Spring can verify token signatures.

2. JWT Bearer Token Flow

1
Client authenticates with Authorization Server
Client sends credentials (password, client_credentials, auth_code, etc.) to /oauth/token. Auth server validates and issues a JWT.
2
Client calls your Resource Server with Bearer token
Authorization: Bearer eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJ1c2VyMTIzIi...} — included in every request header.
3
Spring Security's BearerTokenAuthenticationFilter intercepts
Extracts the token from the Authorization header. Delegates to JwtDecoder for validation.
4
JwtDecoder fetches JWKS and validates signature
On first request, downloads public keys from {issuer}/.well-known/jwks.json. Caches them. Verifies RS256/ES256 signature. Checks exp, iss, aud claims.
5
JwtAuthenticationConverter extracts authorities
Converts JWT claims (scopes, roles) to Spring GrantedAuthority objects. Populates SecurityContext.
6
Authorization check — @PreAuthorize or SecurityFilterChain rules
Method security or URL pattern rules verify the principal has required scopes/roles. 403 Forbidden if not.

SecurityFilterChain

@Configuration @EnableMethodSecurity // enables @PreAuthorize public class SecurityConfig { @Bean public SecurityFilterChain filterChain( HttpSecurity http) throws Exception { return http .authorizeHttpRequests(auth -> auth .requestMatchers("/actuator/health").permitAll() .requestMatchers("/api/public/**").permitAll() .anyRequest().authenticated() ) .oauth2ResourceServer(oauth2 -> oauth2 .jwt(Customizer.withDefaults()) // auto-configures JwtDecoder ) .sessionManagement(s -> s .sessionCreationPolicy(SessionCreationPolicy.STATELESS)) .csrf(AbstractHttpConfigurer::disable) .build(); } }

Custom JwtAuthenticationConverter

@Bean public JwtAuthenticationConverter jwtConverter() { var grantedAuthConverter = new JwtGrantedAuthoritiesConverter(); // Default: reads "scope" or "scp" claim → SCOPE_ prefix // Change to read roles from a custom claim: grantedAuthConverter.setAuthoritiesClaimName("roles"); grantedAuthConverter.setAuthorityPrefix("ROLE_"); var converter = new JwtAuthenticationConverter(); converter.setJwtGrantedAuthoritiesConverter( grantedAuthConverter); return converter; } // Or use custom converter for complex multi-claim logic @Bean public JwtAuthenticationConverter customConverter() { var converter = new JwtAuthenticationConverter(); converter.setJwtGrantedAuthoritiesConverter(jwt -> { List<GrantedAuthority> authorities = new ArrayList<>(); // scopes → SCOPE_read, SCOPE_write var scopes = (List<String>) jwt.getClaim("scope"); if(scopes != null) scopes.forEach(s -> authorities.add( new SimpleGrantedAuthority("SCOPE_" + s))); // roles → ROLE_ADMIN, ROLE_USER var roles = (List<String>) jwt.getClaim("roles"); if(roles != null) roles.forEach(r -> authorities.add( new SimpleGrantedAuthority("ROLE_" + r))); return authorities; }); return converter; }

JWT Claim Validation

// Spring auto-validates these claims: // iss — issuer (if issuer-uri configured) // exp — expiration (always checked) // nbf — not before (if present) // aud — audience (if audiences configured) // Add custom validator: @Bean public JwtDecoder jwtDecoder(JwtProperties props) { var decoder = NimbusJwtDecoder .withJwkSetUri(props.getJwkSetUri()) .build(); decoder.setJwtValidator( JwtValidators.createDefaultWithIssuer( props.getIssuerUri() ) ); return decoder; }

4. Method-Level Security with @PreAuthorize

@RestController @RequestMapping("/api/orders") public class OrderController { // Scope-based: client must have "read" scope → SCOPE_read authority @GetMapping @PreAuthorize("hasAuthority('SCOPE_read')") public List<Order> listOrders() { ... } // Role-based: user must have ROLE_ADMIN (hasRole strips ROLE_ prefix) @DeleteMapping("/{id}") @PreAuthorize("hasRole('ADMIN')") public void deleteOrder(@PathVariable Long id) { ... } // Ownership check: user can only access their own orders // authentication.name = the JWT "sub" claim value @GetMapping("/{id}") @PreAuthorize("hasAuthority('SCOPE_read') and @orderService.isOwner(#id, authentication.name)") public Order getOrder(@PathVariable Long id) { ... } // Multiple authorities (AND): must have both @PostMapping @PreAuthorize("hasAuthority('SCOPE_write') and hasAuthority('SCOPE_orders')") public Order createOrder(@RequestBody CreateOrderRequest req) { ... } // @PostAuthorize runs AFTER method — checks return value @GetMapping("/my-latest") @PostAuthorize("returnObject.userId == authentication.name") public Order getMyLatest() { ... } // Access full JWT in SpEL via authentication.credentials @GetMapping("/tenant") @PreAuthorize("authentication.credentials.claims['tenant_id'] == #tenantId") public List<Order> getTenantOrders(@PathVariable String tenantId) { ... } } // Access JWT programmatically in controller/service @GetMapping("/me") public UserInfo me(@AuthenticationPrincipal Jwt jwt) { String sub = jwt.getSubject(); String email = jwt.getClaimAsString("email"); List<?> roles = jwt.getClaimAsList("roles"); return new UserInfo(sub, email, roles); }
hasRole('ADMIN') vs hasAuthority('ROLE_ADMIN'): hasRole automatically prepends ROLE_. If your JWT claims are in scope format (no ROLE_ prefix), use hasAuthority with SCOPE_ prefix instead.
@EnableMethodSecurity (Spring Security 6+) replaces the deprecated @EnableGlobalMethodSecurity. It enables @PreAuthorize, @PostAuthorize, @PreFilter, @PostFilter, and @Secured on any Spring-managed bean.

6. Opaque Token Introspection vs Self-Contained JWT

Self-Contained JWT

PRO No network call per request — just verify signature locally
PRO Stateless — Resource Server doesn't need to talk to Auth Server
PRO High throughput — JWKS keys cached, crypto is fast
CON Can't revoke a token before expiry — must wait for exp
CON Claims are stale — if roles change, token still has old roles until it expires
spring.security.oauth2.resourceserver.jwt: jwk-set-uri: https://auth.example.com/keys

Opaque Token Introspection

PRO Can revoke tokens immediately — auth server knows the state
PRO Always fresh claims — each request hits the introspection endpoint
CON Network call to auth server on EVERY request — latency hit
CON Auth server becomes a runtime dependency — single point of failure
USE WHEN Short-lived tokens + revocation needed (finance, security-sensitive apps)
spring.security.oauth2.resourceserver.opaquetoken: introspection-uri: https://auth.example.com/introspect client-id: my-resource-server client-secret: ${INTROSPECTION_SECRET}
Best practice: Use short-lived JWTs (15 min) with refresh tokens for most APIs. This balances performance (no per-request introspection call) with security (breach window limited to token lifetime). Revocation becomes less critical when tokens expire quickly.
