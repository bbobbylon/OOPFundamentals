Actuator & Observability

Spring Boot Actuator exposes production-ready endpoints for health checks, metrics, and diagnostics. Essential for Docker, Kubernetes, and cloud deployments.

🩺 What is Spring Boot Actuator — and why does every production app need it?

In production, how do you know the app is healthy, whether the DB pool is exhausted, or what value a config property actually resolved to? Read logs — or hit an Actuator endpoint and get the answer instantly. Spring Boot Actuator adds HTTP endpoints under /actuator that expose operational metadata: health, environment, loaded beans, request mappings, thread dumps, and metrics. Kubernetes and load balancers poll /actuator/health as readiness/liveness probes — 200 UP means route traffic here, anything else means restart or drain the pod. Without it, ops is flying blind.

  • It's your app's instrument panel — health, metrics, env, mappings, loggers, all over HTTP.
  • K8s depends on it. Readiness gates traffic; liveness triggers restarts.
  • Lock it down. Only health/info are public by default; secure the rest behind a role.
  • Extensible. A custom HealthIndicator adds dependency checks (e.g. "is Ping reachable?").

Key endpoints

/health (UP/DOWN + components), /env (effective property values), /beans, /mappings, /metrics/{name} (heap, request counts, pool usage), and /loggers/{name} — read and change a log level at runtime with no redeploy.

What to expose

Only health and info are public by default. Opt others in via management.endpoints.web.exposure.include, then require an ACTUATOR_ADMIN role. Never expose /env publicly — it lists every property (values masked, names not).

Custom health indicators

Implement HealthIndicator: a PingHealthIndicator returns Health.down().withDetail("reason","Ping unreachable") when the IDM is down. It shows up under /health, and K8s stops routing to the pod until it recovers.

CIAM: GET /actuator/health/readiness includes DB, Redis (session store), and Ping checks — if Ping is down, readiness goes DOWN and K8s stops routing new auth requests to that pod while in-session users continue elsewhere. /health/liveness only asks "is the JVM alive?" And flipping com.company.ciam.security to DEBUG via /loggers reveals every JWT validation step without a restart.

1 — Adding Actuator

One dependency unlocks dozens of built-in endpoints:

<!-- pom.xml --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-actuator</artifactId> </dependency> # application.yml — expose specific endpoints (default: only health exposed) management: endpoints: web: exposure: include: health, info, metrics, loggers, env endpoint: health: show-details: when_authorized # always | never | when_authorized server: port: 8081 # best practice: separate port from app (8080) for security

2 — Actuator Endpoints — Click to Explore

GET
/actuator/health
Is the app healthy? Used by load balancers & k8s
HTTP/1.1 200 OK Content-Type: application/json { "status": "UP", "components": { "db": { "status": "UP", "details": { "database": "PostgreSQL", "validationQuery": "isValid()" } }, "diskSpace": { "status": "UP", "details": { "total": 499963174912, "free": 384750227456 } }, "ping": { "status": "UP" } } }
status: UP means the app and all its components are healthy. Kubernetes liveness and readiness probes hit this endpoint.

show-details: always reveals component-level breakdown. when_authorized requires authentication — use for production to avoid leaking DB info.
GET
/actuator/metrics
List all available metrics (JVM, HTTP, custom)
HTTP/1.1 200 OK { "names": [ "jvm.memory.used", "jvm.gc.pause", "http.server.requests", "process.cpu.usage", "hikaricp.connections.active", "spring.data.repository.invocations" ] }
Drill into a metric: /actuator/metrics/http.server.requests

Returns COUNT, SUM, MAX with tags (uri, method, status). Integrates with Micrometer — the metrics facade that ships to Prometheus, Datadog, CloudWatch, etc.
GET
/actuator/info
App version, build info, git commit SHA
HTTP/1.1 200 OK { "app": { "name": "my-spring-app", "version": "1.2.0", "description": "Customer API service" }, "build": { "artifact": "my-spring-app", "time": "2024-06-01T14:30:00Z" }, "git": { "commit": { "id": "a3c2683", "time": "2024-06-01T12:00:00Z" }, "branch": "main" } }
Configure in application.yml under info: for static data. Add spring-boot-maven-plugin build-info goal and git-commit-id-maven-plugin for build/git data automatically injected at build time.
GET
/actuator/loggers
List log levels — change them at runtime
GET /actuator/loggers/com.example.service { "configuredLevel": "INFO", "effectiveLevel": "INFO" } --- Change a log level at runtime (no restart needed) --- POST /actuator/loggers/com.example.service Content-Type: application/json { "configuredLevel": "DEBUG" }
Huge operational win: bump a specific logger to DEBUG in production for 10 minutes to diagnose an issue, then reset to INFO — zero restarts, zero downtime. Requires management.endpoints.web.exposure.include: loggers.
GET
/actuator/env
Active properties and their sources
HTTP/1.1 200 OK { "activeProfiles": ["prod"], "propertySources": [ { "name": "Config resource 'application-prod.yml'", "properties": { "spring.datasource.url": { "value": "jdbc:postgresql://prod-db:5432/mydb", "origin": "URL [file:./application-prod.yml]:3:9" } } } ] }
Shows the effective configuration and which file each property came from. Essential for debugging "why is my app using the wrong config?" mysteries.

Sensitive properties are automatically masked (password, secret, key, token).
POST
/actuator/shutdown
Gracefully shut down the application
HTTP/1.1 200 OK { "message": "Shutting down, bye..." }
Disabled by default for safety. Enable only if needed: management.endpoint.shutdown.enabled: true

Always secure the management port with Spring Security or place it behind an internal network — these endpoints reveal sensitive operational details and (in the case of shutdown) can kill your app.

4 — Securing Actuator Endpoints

# Best practice: separate management port, restrict access management: server: port: 8081 # management on its own port (not exposed to public LB) endpoints: web: exposure: include: health, info, metrics # Lock down with Spring Security if needed on same port: # In SecurityConfig.java: http.requestMatcher(new AntPathRequestMatcher("/actuator/**")) .authorizeHttpRequests(a -> a .requestMatchers("/actuator/health", "/actuator/info").permitAll() .anyRequest().hasRole("ACTUATOR_ADMIN") );
EndpointExpose publicly?Reason
/actuator/healthYesRequired by load balancers and k8s probes
/actuator/infoMaybeOK if you don't expose internal git SHAs/versions
/actuator/metricsNoCan reveal internal performance data to attackers
/actuator/envNoExposes config properties (even if passwords masked)
/actuator/loggersNoAllows changing log levels — operational control
/actuator/shutdownNeverCan terminate your application — disable in prod
